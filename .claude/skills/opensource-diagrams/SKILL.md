# 开源解读:画图与证据表

`docs/06-开源解读流程.md` 只写「什么时候该画图」,这里写「怎么画」。

## 先定图型:看这张图回答什么问题

| 图型 | 回答 | 上限 |
|---|---|---|
| `architecture` | 有几个进程、谁管谁 | 12 个节点 |
| `sequence` | 一次请求经过哪些手 | 30 条消息 |
| `workflow` | 一次决策怎么分叉 | 12 个节点 |
| `lifecycle` | 状态怎么跳 | 12 个节点 |
| `dataflow` | 一块数据的一生 | 12 个节点 |

超上限就拆成 a、b 两张,编号每图从 ① 重起,正文用「图 a 的 ③」指代。

**选型前先问形状**:原来那张 ASCII 图如果是从上往下的流水线、分两路再合一路的菱形,**形状本身就在表达意思**,必须保住。排列方向是硬性的:

- `workflow` 只能左→右推进,泳道是横行
- `sequence` 只能上→下,参与者是竖列
- `architecture` 配 `layout: { mode: "grid" }` 时**行列完全由自己指定**——凡是「形状即语义」的图一律用它

踩过一次:fork-join 用 `workflow` 画成左右两条平行泳道,菱形没了,只能重画。

## 画布大小决定字号

规格里**没有字号旋钮**。渲染器写死:标题 12px、泳道名 11px、消息 9px、备注 7px。页面上看到的字号 = 写死值 ×(显示宽 ÷ 画布宽)。

阅读器给图整篇宽度(1440 屏约 1130px)并限高 930px(`app/globals.css` 的 `.prose.os-prose` 规则),所以显示尺寸 = `min(1130, 930 × 宽高比)`。

- 画布宽 **800 上下**时消息文字约 11px,读着舒服
- 画布宽超过 **1100** 就掉到 8px 以下
- 内容多到画布必须变宽时**拆成两张**,不要硬塞
- 宽高比约 0.9 的竖图缩完宽约 839px,刚好压过正文的 52rem(832px)

## 各图型的硬约束

**sequence**:泳道头固定占 y 72–126,阶段带标签画在 `from − 44` 处,所以**第一条 segment 的 `from` 至少 190**,否则标签被泳道头盖住(showcase 校验不拦这条,踩过两次)。**不支持自己指向自己的消息**(报 span 0px),原地步骤要合并进相邻的跨进程跳转或写进 `note`。时间线可用区间 `160 … 画布高 − 83`,阶段带范围 `72 … 画布高 − 45`。viewBox 宽不超过 1080,设 `column_fit: spread`。

**architecture**:`row`/`col` 必须配 `layout: { mode: "grid" }` 才生效,否则报「must include pos」。格子中心距 = `cellW + gapX`,节点默认 120×60。**带标签的边至少留 70px 净空**(标签压在节点上会判失败),不带标签的边压到 30px 也行。`boundaries` 的 label 长了会撑出框,长说明放卡片。

**workflow v2**:列只是逻辑序号 0–5,像素间距由编译器按内容实测,只能靠缩短标签间接影响。

**lifecycle**:唯一终态放终态带;迁移的 note 会渲染成可见文字。

## 通用写法

- `meta.locale` 用 `zh-CN`;省掉副标题与动画,标题一行
- 节点副标题不超过约 12 个汉字宽;边标签不超过 12 个汉字或 22 个拉丁字符,细节进卡片
- 决策流按阶段分泳道,记账或搬运流按角色分泳道
- 同步与异步只用三个词:同进程同步调用、单向广播、GPU 异步(`.tolist()` 是同步点)
- 新图从 `nano-vllm/diagrams/` 的 v1 模板改起;vLLM 的五张是新范式样例

## 交付链

```bash
# 1. 交付(自带 9 项校验,失败看诊断改)
node ~/.claude/skills/archify/bin/archify.mjs deliver <型> <规格.json> <输出.html> --quality showcase --json
# 2. 导出自包含 SVG(在仓库根目录跑)
node scripts/archify-export.mjs <输出.html> <输出.svg>
```

省掉的步骤:`validate` 只在反复修不好时单独跑(`deliver` 已含);`guide` 选图型没用,自己按「这张图回答什么问题」选;`visual-check` 对嵌页 SVG 无意义。

每种图型的 schema 只在第一次读,用脚本抠需要的字段,别整篇读。

## 校验拦不住的两类

showcase 校验管得了线穿框、标签压标签,管不了这两样:

1. **元素被后画的实心块盖住**——`npm run os:check` 里的文字底板重叠检查能抓一部分;改完直接去 SVG 里量坐标确认(底板矩形 `class="c-mask"` 就是精确包围盒),别靠截图猜
2. **宽高比难看**——只能看

## 证据表(`_NN-evidence.md`)

`npm run os:check` 会把每行的「位置」与「原样引用」拿到 `projects/` 源码上核对,一处未命中即失败。写法要让检查器认得:

- 每行至少写一次文件名,裸 `:12-34` 只沿用同一行前面的文件
- 「原样引用」列只放逐字代码;跨行的按源码顺序拼接即可,空白不计
- 不是代码的轨迹记录写成「干跑输出 `...`」
- 否定式断言(某几行里没有某名字)不用反引号

`scripts/os-check.mjs` 的路径补全只认 `nanovllm/` 前缀,别的项目每行必须写从仓库根开始的完整路径。
