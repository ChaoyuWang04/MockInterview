# 把活派给子 agent 并验收

**现行做法**:

- **派发写死上下文**:子 agent 只有你给它的东西——守则路径、它负责的范围与边界、事实锚(源码快照与 commit、原件路径)、参照样板、别人负责的内容(只能一句话回指)。少一样它就会猜
- **一个 agent 独占一对文件**;共享的底稿、索引、队列由主线程合并,子 agent 交付进自己的交付文件
- **报告只答三问**:改了什么、哪些只能靠猜、自查结果。第二问是守则迭代的输入
- **主线程抽查硬事实**,不信报告;子 agent 推翻你的指令时先自己复核——多半是它对
- **一写一审**:写稿人之外另派一个全新的审稿 agent 直接改稿,只抓事实与图;整本书收尾再派一个只读审稿通读找跨章矛盾
- 一批 3 个并行为宜;瓶颈是主线程的验收能力,不是并发数。中途断连先续作,不重派

**原则**:子 agent 的产出质量上限是你给它的上下文;验收的力气花在它自己查不出的地方——事实与跨篇一致。

**Claude 与 Codex**:派发机制不同,做法相同。
