# 交给 agent 一件多步的活

**现行做法**:写一页任务书,写给维护者看——目标、做到什么算完、证据怎么拿、边界、已知的未知。维护者看过一次就开工,执行步骤由 agent 自己规划、自己验证。不走 brainstorm → spec → plan → 逐步执行的仪式;只有要跨会话或跨 agent 交接时,才把步骤写下来给接手的人。

**原则**:对齐的是意图与验收,不是步骤;模型规划得动的东西写成文档,只多花 token、多一次打断。

**Claude 与 Codex**:相同。用户级不再装流程仪式类 skill(如 superpowers),以免它们在仓库守则之外强插步骤。
