# 注意力基础(Self-Attention · 多头 · 掩码)

> 🔴 重点考点:本篇是当前复习重点,文末「面试考点串联」给出问法对照。

一句话:注意力是一次**由内容决定的加权读取**——每个 token 先说出「我要找什么」,拿它去和所有位置的「我是什么」逐一比对,再按匹配度把这些位置的内容加权取回来。它是 Transformer 里**唯一让不同位置交换信息**的部件,其余组件(FFN、Norm)都在每个位置内部独立干活。

> **类比**:查资料。**Q(query)是你脑子里的检索词**,**K(key)是每本书的书脊标签**,**V(value)是书里的正文**。你拿检索词去扫一遍所有书脊,谁的标签对得上就多抄它几段正文——抄多少由匹配度决定,这就是注意力权重。

## 一、一次加权读取是怎么算出来的

### 三个投影,三个角色

设输入 $X \in \mathbb{R}^{n \times d}$($n$ 个 token,每个 $d$ 维),先用三个独立的线性层把它投影成三份:

$$
Q = XW_Q, \qquad K = XW_K, \qquad V = XW_V
$$

这三个矩阵把同一个 token 的表示,拆成「我要找什么」「我能被怎么找到」「我能提供什么内容」三个角色。然后:

$$
O = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right) V
$$

逐项拆开看:$QK^\top$ 是 $n \times n$ 的匹配分数矩阵,第 $(i,j)$ 项表示「第 $i$ 个 token 该读多少第 $j$ 个」;$\sqrt{d_k}$ 把分数的量级压回可控范围;$M$ 是可选掩码,把不该看见的位置打成 $-\infty$;softmax 逐行归一化成一组和为 1 的读取权重;最后乘 $V$ 就是按权重把内容汇总回来。

**关键在于权重是当场算出来的**:同一个词在不同句子里会得到完全不同的 Q,因而读到完全不同的位置。这是注意力和固定权重的卷积、全连接最本质的差别。

### 为什么 Q 和 K 要用两个投影,不能共用一个

把两次投影合并写开,原始分数是:

$$
s_{ij} = x_i W_Q W_K^\top x_j^\top
$$

中间那块 $W_Q W_K^\top$ 是一个**任意的**双线性矩阵,它能表达非对称关系。**因为匹配本来就是非对称的**:代词「它」需要去找先行词,但先行词并不需要反过来找「它」。

如果强制 $W_Q = W_K = W$,中间就变成 $WW^\top$——**对称且半正定**,模型直接丢掉了表达单向匹配的自由度。

但要分清两件事:**原始分数矩阵对称,不等于注意力权重对称**。softmax 是逐行归一化的:

$$
A_{ij} = \frac{e^{S_{ij}}}{\sum_t e^{S_{it}}}
$$

第 $i$ 行和第 $j$ 行的分母来自不同的求和,所以即便 $S_{ij} = S_{ji}$,也一般有 $A_{ij} \neq A_{ji}$。

共享 Q/K 能省下一个 $d \times d$ 投影,约占注意力四个投影参数的四分之一;但**省不掉 $O(n^2 d)$ 的配对计算**——那部分和投影数量无关。真要折中,可以共享主干再各接一个独立低秩分支,保住一部分非对称性;是否保质得实测。顺带澄清一个高频误答:**标准 RoPE 同时旋转 Q 和 K**,不是只转 K——只有两边都转,内积才只依赖相对位移(见 RoPE 篇)。

### Self 和 Cross 的唯一区别:Q/K/V 从哪来

| | Q 来自 | K/V 来自 | 典型场景 |
|---|---|---|---|
| Self-Attention | 本序列 | 本序列 | Decoder-only 语言模型的每一层 |
| Cross-Attention | 目标序列 | 源序列(编码器输出) | 翻译、VLM 里文本读图像特征 |

公式和实现完全一样,只是喂进去的张量不同。

两个常被追问的维度约束:**Q 和 K 的最后一维必须相同**(否则点积算不了),但 **V 的输出维可以不同**——它只负责被加权求和,不参与匹配。

还有一句要说准:注意力**结构上**让一层之内任意两个可见位置直接交互,不像 RNN 要逐步传递,所以没有距离衰减。但「能直接连上」不等于「一定学得好」——长距离依赖学不学得到,仍取决于训练数据、模型容量和位置编码。

## 二、三个「为什么这么设计」

### 为什么除以 $\sqrt{d_k}$

设 $q_i, k_i$ 各维均值 0、方差 1 且相互独立,那么点积是 $d_k$ 个独立项相加:

$$
\operatorname{Var}(q^\top k) = \operatorname{Var}\left(\sum_{i=1}^{d_k} q_i k_i\right) = d_k
$$

**方差是 $d_k$,标准差就是 $\sqrt{d_k}$**——所以除以 $\sqrt{d_k}$ 才能把分数的典型量级压回 1 附近。除以 $d_k$ 会过头,把标准差压到 $1/\sqrt{d_k}$,softmax 变得过于平坦,每个位置权重都差不多,等于没在做选择。

不缩放会怎样?$d_k = 128$ 时点积的典型量级约 $\pm 11$,softmax 里最大项与次大项差个十几,概率就接近 one-hot。**softmax 一旦饱和,梯度几乎全为 0**,注意力分布就再也调不动了。

三个容易被追问的边界:

- **推理时能不能删掉缩放?** 不能。它是模型定义的一部分,删了注意力分布直接变形;和是否开 KV cache 毫无关系。
- **做过 LayerNorm 是不是就不用缩放了?** 推不出来。LayerNorm 约束的是**投影前**的输入统计,不保证每个头投影后的 Q/K 还是独立单位方差。
- **Q/K 方差本来就不是 1 怎么办?** 那理想缩放里还得含它们的实际方差。工程上不去解析地算,而是用初始化、QK-Norm 或可学习温度把实际尺度压住。
- **有替代方案吗?** 有,QK-Norm、余弦注意力、可学习温度都能控制 logit 尺度(见 注意力配件 篇)。但 T5 的相对位置偏置**不是**缩放的替代品——它解决的是位置关系,不是数值量级。

### 为什么用点积,不用加法网络

$$
s_{ij}^{\text{dot}} = \frac{q_i^\top k_j}{\sqrt{d_k}}, \qquad s_{ij}^{\text{add}} = v_a^\top \tanh(W_q q_i + W_k k_j + b)
$$

上式是点积打分,下式是 Bahdanau 的加法打分——用一个小网络逐对算匹配度。

| 维度 | 点积 | 加法 |
|---|---|---|
| 打分形式 | 双线性相似度 | 带非线性的可学习匹配网络 |
| 额外参数 | 打分本身没有 | 多出 $W_q, W_k, v_a$ |
| 硬件执行 | **一次 GEMM 算完所有配对** | 要物化或分块处理成对中间量 |
| 表达能力 | 受投影后内积结构约束 | 可学更一般的匹配函数 |

点积赢在**能整块打包成矩阵乘**,而矩阵乘正是 GPU 最擅长的事(见 GEMM优化 篇)。**注意两者的配对数都是 $n_q n_k$**,加法注意力并不更省;点积胜出是吞吐、实现成熟度和多头配合的综合结果,不代表任何数据上效果都更好。「不同头能不能混用两种打分?」结构上可以,但会多出实现分支和专用 kernel 成本,收益得靠实验证明。硬件受限时的选型同理:**先测目标硬件上可用的矩阵内核、显存和实际延迟,别只数公式里有几项**。

### 为什么要分成多个头

$$
\operatorname{head}_i = \operatorname{Attention}(XW_i^Q, XW_i^K, XW_i^V), \qquad O = \operatorname{Concat}(\operatorname{head}_1, \dots, \operatorname{head}_h) W_O
$$

每个头在自己的 $d_h = d/h$ 维子空间里独立做一遍注意力,**拼接**后再过一个输出投影融合。

三个必须说准的点:

1. **是拼接,不是平均**。平均会把多个注意力分布糊成一个,多样性当场消失;拼接保留了每个头的完整输出,由 $W_O$ 学怎么融合。
2. **参数量约 $4d^2$,与头数无关**。四个 $d \times d$ 投影(Q/K/V/O),头数只决定怎么把 $d$ 切开,总宽度没变。所以「多头不增加参数量,只改变信息的组织方式」。
3. **缩放除的是 $\sqrt{d_h}$,不是 $\sqrt{d}$**。写错会让注意力过于平滑——这是手撕代码最常见的扣分点。

**头是不是越多越好?不是。** $h$ 变大 $d_h$ 就变小:可能提供更多匹配模式,也可能让单头容量太小、彼此冗余,还会让 kernel 面对更小更碎的矩阵而掉效率。选头数的实际约束是:$d$ 能被 $h$ 整除、$h$ 能被张量并行度整除、目标硬件上有高效 kernel,最后才看消融指标。还要挡住两句常见的过度归因:**多头既不保证输出满秩,也不保证梯度更稳定**——这些取决于投影参数、输入分布、优化器和头间相关性,不是「分了头」就有的结构性保证。

### 实现要点:拆头、合头与数值稳定

手撕注意力最常见的三处扣分,都在这几行里:

```python
def split(t, B, L, h, dh):        # (B,L,d) -> (B,h,L,dh)
    return t.view(B, L, h, dh).transpose(1, 2)   # 必须先 view 再 transpose

scores = q @ k.transpose(-2, -1) / dh ** 0.5     # 除 √d_h,不是 √d
scores = scores.masked_fill(~allowed, float('-inf'))   # mask 在 softmax 之前
out = F.softmax(scores, dim=-1) @ v               # (B,h,L,dh)
out = out.transpose(1, 2).contiguous().view(B, L, d)   # 合头前必须 contiguous
```

1. **顺序不能反**:直接 `view(B, h, L, dh)` 会把序列维和头维搅在一起,数值不报错但语义全错。必须先按 `(B,L,h,dh)` 切,再把 $h$ 转到第 2 维。
2. **合头前要 `.contiguous()`**:transpose 只改了 stride,底层内存还是乱的,直接 `view` 会报错。
3. **手写 softmax 要先减去每行最大值**再取指数——$e^{x}$ 在 $x$ 稍大时就会溢出成 `inf`。减最大值不改变 softmax 结果(分子分母同乘一个常数),却把指数的输入压到 $\le 0$。

## 三、掩码:谁能看见谁

### 必须加在 softmax 之前

掩码要写成**加性偏置**,插在缩放之后、softmax 之前:允许的位置取 $M_{ij} = 0$,屏蔽的位置取 $M_{ij} = -\infty$,这样它的 softmax 概率恰好是 0。

**为什么不能在 softmax 之后把权重置零?** 因为剩下的权重加起来会小于 1,相当于给这一行整体降了增益;要等价就得重新归一化,多一步还更容易写错。而只把最终输出清零更没用——无效位置的 V 已经混进别的位置了。

工程上有两个坑:数值上用 $-\infty$ 要小心,某些 kernel 或 fp16 下会产生 NaN,常改用该 dtype 下足够小又不溢出的有限负数(如 $-10^9$);更要命的是**如果某一行被全部屏蔽**,softmax 分母为 0,整行变 NaN——分块边界和全 padding 样本最容易踩到。

### 两种 mask,管的是两件事

| | Causal Mask | Padding Mask |
|---|---|---|
| 屏蔽什么 | 当前位置之后的所有位置 | 补齐出来的无效 key |
| 依据 | query 与 key 的**位置关系** | 每个样本的**有效长度** |
| 典型 shape | `[1,1,N_q,N_k]` | `[B,1,1,N_k]` |
| 随样本变化 | 否 | 是 |

两者同时存在时按「**任一条件要求屏蔽就屏蔽**」合并,或者直接把两个加性偏置相加。logits 常见 shape 是 `[B,H,N_q,N_k]`,两种 mask 各自广播过去。

另外两个 API 层面的陷阱:**0/1 和 True/False 哪个代表屏蔽没有统一约定**,不同框架语义相反,必须先读接口文档;**下三角也不一定代表保留**,取决于行列分别是 query 还是 key。别照着图形猜。

**训练和增量推理的 mask 也不一样**:训练要构造完整的三角 mask,因为一次喂进整段序列;增量推理时当前 query 只有一个 token,天然只能配上已有的 K/V,不需要显式三角 mask——但 padding 和分块边界仍然要处理对。

### 因果 vs 双向:GPT 和 BERT 的分工

用可见矩阵一眼看清区别(行是 query,列是 key,✅ 表示可读):

| query \ key | $t_1$ | $t_2$ | $t_3$ |
|---|---|---|---|
| **因果** $t_2$ | ✅ | ✅ | ❌ |
| **双向** $t_2$ | ✅ | ✅ | ✅ |

差别不在 Q/K/V 的公式,**只在 softmax 前哪些分数可见**。因果注意力让位置 $i$ 只能读 $j \le i$,于是模型学的是 $p(x_i \mid x_{<i})$,训练目标和逐 token 生成的部署条件完全一致;双向注意力同时用左右上下文,更适合分类、抽取和句向量。

几个高频澄清:

- **BERT 为什么不能直接自回归生成?** 不是「技术上绝对不能」,而是它的 `[MASK]` 预测目标用了右侧信息,与左到右生成的条件不一致。改 mask、改目标再训练,权重照样能用于生成。
- **给 GPT 加双向注意力要改什么?** 得同时改 mask 和训练目标并重新训练。只改推理不改训练,会造成「训练时看得到未来、推理时看不到」的错配。
- **KV cache 是因果 mask 吗?** 不是。**mask 定义可见性,cache 只是复用已经可见的历史 K/V**,一个是建模约束一个是实现优化(见 KVCache 篇)。
- **能从模型输出反推闭源模型用了哪种注意力吗?** 不能。产品表现受数据、训练配方、解码策略和后处理共同影响,反推不出内部结构;**只有官方资料明确披露时才能下结论**。

## 四、复杂度账本:两项,别合并成一项

设序列长 $n$、隐藏维 $d$,注意力的开销分成两块:

| 项 | 来自哪 | 量级 |
|---|---|---|
| 投影项 | Q/K/V/O 四次 $n \times d$ 乘 $d \times d$ | $O(nd^2)$ |
| 序列项 | $QK^\top$ 与 $AV$ 两次 | $O(n^2 d)$ |

**这两项必须分开写。** 常见的错误答法是「注意力是 $O(n^3)$」——那要额外假设 $d$ 与 $n$ 同阶才成立。显存上还要再加一笔:训练时若显式保存注意力矩阵,是 $O(n^2)$ 个元素,这往往比计算更早撞墙。

**什么时候序列项开始主导?** 忽略常数时在 $n \approx d$ 打平;把四个投影和两次注意力矩阵乘的常数算进去,大约在 $n \approx 2d$ 打平。所以 $d = 4096$ 的模型,序列长到 8k 左右两项才相当,32k 时序列项已是投影项的约 4 倍——**「注意力是二次复杂度所以一定是瓶颈」在短序列上并不成立**。

长序列的四条出路,各自改的东西不同,不要混为一谈:

| 路线 | 改了什么 | 复杂度 | 去哪篇看 |
|---|---|---|---|
| FlashAttention | 只改中间矩阵的读写方式 | **仍是 $O(n^2d)$** | FlashAttention 篇 |
| 滑动窗口 | 每个 token 只看最近 $W$ 个 | $O(nWd)$ | SWA 篇 |
| 稀疏注意力 | 动态挑一小撮 token 参与 | 按选中数量算 | 稀疏注意力 篇 |
| 线性注意力 | 去掉 softmax,改用固定大小状态 | $O(nd^2)$,缓存 $O(1)$ | 线性注意力 篇 |

FlashAttention 常被误答成「把注意力变成线性」——它一个 FLOP 都没省,省的是 HBM 读写。

## 五、多头到底学到了什么:观察、消融、剪枝

### 注意力图不是解释

热力图能看出某个头在做近邻、盯分隔符还是跨句指代,**但它只描述了一次读取权重**。后面还有 V 的加权、残差、FFN 和几十层的叠加,权重大不等于对最终输出贡献大。「这个头负责指代消解」这种话,必须靠干预验证,不能靠看图命名。

### 三级证据,强度递增

1. **相关性观察**:统计每个头的平均注意力距离、注意力熵、头间相似度——最便宜,但只是现象。
2. **局部敏感度**:把某个头的输出置零,看 loss 和任务指标掉多少;也可用梯度或 Taylor 近似估计。比看图强,但仍是「删了会怎样」而非「它在做什么」。
3. **因果干预**:激活替换、路径修补——把某个头的激活换成另一个输入下的值,看目标行为是否随之改变。这才能支持功能性结论。

### 剪枝怎么才能真加速

流程是:在校准集上给每个头打分 → 分层或迭代删掉低贡献头 → **微调恢复** → 在多任务、长短上下文上复测。三条常被追问的边界:

- **各层的头重要性不一样**,不能用一个统一阈值一刀切,要逐层消融。
- **参数少了不等于延迟按比例降**。只有剪出规则 shape、kernel 能真的跳过计算并减少访存,才会有端到端收益;剪成不规则形状往往一点没快。
- **合并相似头不能只平均热力图**,得同时处理 Q/K/V 和输出投影四组权重。

至于**为什么训练时需要那么多头、推理却能删掉一批**——训练过程本身会产生冗余,但可删比例随模型、层和任务大幅变化,没有通用比例。
