# SWA(Sliding Window Attention,滑动窗口注意力)

> 🔴 重点考点:本篇是当前复习重点,文末「面试考点串联」给出问法对照。

一句话:**给注意力加一条规矩——每个 token 只准看最近 $W$ 个**。改动小到只是换了张 mask,收益却有两条:序列项计算从 $O(n^2 d)$ 降到 $O(nWd)$,KV cache 从随上下文线性膨胀变成**封顶在 $W$ 条**。代价是窗口外的东西这一层直接看不见,所以现代模型没有纯 SWA,全是「大部分层滑窗、少数层全局」的混合形态。

> **类比**:全注意力是每写一句都翻回第一页重读全书;SWA 是**只看最近两页**。写作的流畅连贯确实大部分只依赖最近两页——但「第三章埋的伏笔」这类远处信息,得靠别的机制兜底。

注意力本身的公式、mask 加在哪一步、复杂度怎么拆成投影项与序列项,见 注意力基础 篇;本篇只盯「把可见范围收窄成一个滑动窗口」这一个旋钮。

## 一、机制:全部改动就是一张 mask

### 窗口 mask:把下三角削成一条斜带

因果注意力里位置 $i$ 能看 $[0, i]$ 的全部历史,SWA 收紧成只看最近 $W$ 个(含自己):

$$
M(i, j) =
\begin{cases}
0, & i - W < j \le i \\
-\infty, & \text{否则}
\end{cases}
$$

这个式子说的是:允许看的位置加 0(分数不受影响),不允许看的位置加 $-\infty$(softmax 之后权重恰好为 0)。**Q/K/V 的投影、缩放、softmax 一个都没改**——SWA 不是一种新注意力,只是给旧注意力换了张可见性表。注意力矩阵于是从完整下三角变成一条宽 $W$ 的斜带。

> 🖼️ 占位:注意力 mask 对比示意——左为因果全注意力的完整下三角,右为 SWA 的宽 W 斜带

### 三笔账:算得少、存得少、decode 不再变慢

| 账目 | 全注意力 | SWA | 为什么 |
|---|---|---|---|
| 序列项计算 | $O(n^2 d)$ | $O(nWd)$ | 每个 query 的配对数从「随 $n$ 涨」变成常数 $W$ |
| 单层 KV cache | 随长度 $S$ 线性涨 | 封顶 $\min(S, W)$ | 窗口外的 K/V 再也不会被读到,可以直接扔 |
| decode 每步注意力 | 随已生成长度变慢 | **常数** | 每步只读 $W$ 条,与上下文多长无关 |

第三行最容易被忽略,工程上却最值钱:全注意力每生成一个 token 都要把整份历史缓存扫一遍,序列越长每步越慢;**窗口固定之后,第 100 个 token 和第 100 万个 token 的单步成本一模一样**。

Mistral 7B 是教科书数字:$W = 4096$,论文报告 32k 序列下缓存降到 $1/8$($32768 / 4096$)而质量不受影响;实现上用**环形缓冲区(rolling buffer)**——第 $i$ 个 token 的 K/V 写进 $i \bmod W$ 号槽位,自然覆盖掉最旧的一条。

有一点要说准:**SWA 省的是「每个位置看多远」,不是「要不要算」**。prefill 仍要对 $n$ 个位置各算一遍窗口内注意力,$O(nWd)$ 是从平方降到线性,不是降到零——长 prompt 下 prefill 依然是成本大头。

### 感受野随深度叠加:传话游戏

单层只看 $W$,但堆起来会累积:第 1 层把 $[i-W,\,i]$ 聚合进位置 $i$ 的表示,第 2 层读位置 $i-W$ 时,顺带拿到了它在第 1 层吸收的更早那 $W$ 个 token。$L$ 层之后:

$$
\text{有效感受野} \approx L \times W
$$

意思是信息每往上一层,就能再往前多跨 $W$ 个位置。Longformer 最早把这条写清楚,Mistral 7B 给了大模型上的数字:$4096 \times 32 \approx 131$k token。

> **类比**:传话游戏。隔着十个人,消息也能传到你耳朵里——**能传到,但会失真**。

这个类比是本篇最该记住的一句。每一层接力都是一次有损压缩:位置 $i$ 的表示是 $W$ 个向量的加权平均,远处 token 的贡献被稀释、又被后面几十层反复重写,传到高层只剩「大意」。所以**理论感受野大,不等于能做精确检索**——「大海捞针」这类要求逐字复现远处片段的任务,纯 SWA 一定挂,因为接力传的是摘要不是原文。

这就是下一节存在的全部理由。

## 二、没人用纯 SWA:局部 + 全局是标准形态

### 各家的比例与窗口

长程信息只能靠接力、接力必失真,标准做法于是是:**大部分层用滑窗(便宜),少数层保留全局注意力(能精确回溯任意位置)**。「局部:全局比例 + 窗口大小」是两个真实的设计旋钮:

| 模型 | 局部:全局 | 窗口 | 层数拆解与备注 |
|---|---|---|---|
| Gemma 2 | 1:1 | 4096 | 起点 |
| Gemma 3 / Gemma 4 | **5:1** | **1024** | 窗口缩到 Gemma 2 的 1/4 |
| GPT-OSS 120B | 1:1 交替 | **128** | 18 滑窗 + 18 全局,配可学习 sink |
| OLMo 3 | 3:1 | — | YaRN 只在全局层用 |
| Step 3.5 Flash | 3:1 | — | 36 滑窗 + 12 全局 |
| Laguna XS.2 | 3:1 | 512 | 逐层 query 头预算 |
| Arcee Trinity Large | 3:1 | — | 45 滑窗 + 15 全局,512k 上下文 |
| MiMo-V2-Flash | 5:1 | **128** | 40 滑窗 + 8 全局,262k 上下文 |

趋势读法:Gemma 2 → Gemma 3 → MiMo,**局部层占比在涨、窗口在缩**——业界一直在试探「局部层到底可以多敷衍」。3:1 是 2026 年最常见的落点;比例背后的路线之争与线性混合的对照见 Hybrid注意力 篇。

收益有公开数字:Gemma 3 报告 32k 上下文下,纯全局方案的 KV cache 显存开销约占 60%,换成 5:1 + 1024 窗口后降到 **15% 以下**,困惑度没有明显退化。

### MiMo-V2-Flash:窗口能压到多小

它的 40 个滑窗层窗口只有 **128**——每个 token 只能看前面 128 个字,单层几乎退化成 n-gram 模型,**全部长程能力压在 8 个全局层上**;而它撑得住 262k 上下文,Agent 类评测也很能打。结论反直觉但好记:**局部层的窗口可以压得比直觉小得多**,因为局部层只需把窗口内的语法与局部语义处理干净,长程定位交给少数全局层就够了。

### 另一条路:全局 token(Longformer 式)

「少数**层**全局」不是唯一解法。Longformer 的做法是「少数 **token** 全局」:窗口注意力之外,再挑几个位置享受双向特权——它看所有人,所有人也看它,而且用一套单独的 Q/K/V 投影。

这样为什么能兼顾感受野与成本:设全局 token 有 $g$ 个,总代价是 $O(n(W + g))$,只要 $g$ 是与 $n$ 无关的常数,**总成本仍然是线性的**;而任意两个 token 之间的最短路径,从「靠接力走 $n/W$ 层」直接缩成 **2 跳**(我 → 全局 token → 你)。代价是这几个位置成了信息瓶颈,所有远程信息都得挤过去。

**现代 decoder-only LLM 为什么不用这一招?** 因为 Longformer 的全局 token 是**按任务人工指定**的(分类挑 `[CLS]`,问答挑问题里的 token),而预训练时根本没有「哪个 token 该当全局」的标签。所以主流换成了挑几个**层**全局:层是固定的,不依赖任务。经典稀疏模式的完整谱系见 稀疏注意力 篇。

## 三、层间分工:位置编码为什么跟着分层

局部/全局分层之后,位置编码也跟着分工,各家高度一致:

| 层类型 | 位置编码 | 需要长度外推吗 |
|---|---|---|
| 局部层(滑窗) | 完整 RoPE | **不需要** |
| 全局层 | NoPE 或 partial RoPE | 需要,YaRN 只在这里用 |

**为什么局部层不需要**:两条理由叠加。一是窗口本身就是位置先验——「只能看前 $W$ 个」这个约束里已经带了粗粒度的位置信息,RoPE 只是锦上添花;二是更硬的一条,**窗口内的相对距离恒 $\le W$,永远落在训练时见过的范围内**。不管上下文总长是 8k 还是 1M,局部层看到的相对位移分布一模一样,**根本不存在长度外推问题,所以不用治**。

**为什么全局层需要**:它要跨几十万 token,相对距离直接冲出训练长度,RoPE 在训练长度之外会失效。三条应对——减弱(partial RoPE)、去掉(NoPE)、补救(YaRN)。

**OLMo 3 是这条规律最干净的公开证据:它的 YaRN 长度外推只在全局层做**。需要救的只有全局层,局部层从来不生病。RoPE、NoPE、YaRN 各自的原理见 RoPE 篇。

## 四、和其他 KV 优化的关系:各砍不同的项

把 KV cache 总量摊开,SWA 砍哪一项一目了然:

$$
\text{KV bytes} = \underbrace{L}_{\text{跨层共享}} \times \underbrace{n_{kv} \times d_h}_{\text{GQA / MLA}} \times 2 \times \underbrace{S}_{\text{SWA 砍这里}} \times \underbrace{b}_{\text{量化}}
$$

这个式子的意思是:四类手段各压一个因子,**互不冲突,可以同时用**。SWA 特殊在它是唯一改变**增长率**的那一项——GQA 把缓存压成 $g/h$、量化压成 $1/2$,但总量仍随序列线性涨;SWA 直接让这一项在 $W$ 处封顶。

混合模型的实际总量因此是两段相加:

$$
\text{KV cache} \propto n_{\text{global}} \times S \;+\; n_{\text{swa}} \times \min(S, W)
$$

前一项是仍在线性增长的全局层,后一项是已经封顶的滑窗层。**上下文一长,总量几乎全由全局层贡献**——这正是把局部:全局推到 5:1 的动机。

| 手段 | 砍哪一项 | 主负责文章 |
|---|---|---|
| GQA / MQA | KV 头数 $n_{kv}$ | KV共享注意力 篇 |
| MLA | 每头的表示维度 | MLA 篇 |
| 跨层 KV 共享 | 层数 $L$ | 注意力配件 篇 |
| **SWA** | **序列长度 $S$,封顶 $W$** | 本篇 |
| KV 量化 | 每元素字节数 $b$ | KVCache量化 篇 |

Gemma 4 的 E2B/E4B 是「三样同时用」的现成例子:SWA 5:1 + GQA + 跨层 KV 共享(报告只公布了共享比例,没有给出拓扑;为什么机制上只能同类型层之间共享,见 注意力配件 篇)。缓存本身的机制与显存账见 KVCache 篇。

## 五、流式场景:滑窗会把 attention sink 挤掉

这是 SWA 最著名的坑,也是高频题。

现象:训好的模型里,大量注意力头习惯把很大一部分权重砸在**开头几个 token** 上,哪怕那只是 `<bos>`。原因是 softmax 权重恒和为 1,每个头**必须**读点什么回来;没什么想读的时候,它需要一个「垃圾桶」位置来倾倒这份配额。

滑窗一开、生成一长,开头那几个 token 最先被挤出缓存——**垃圾桶没了,那份必须花掉的注意力配额被摊到真正的内容 token 上,分布当场变形**。StreamingLLM 给的数字很吓人:Llama-2-13B 只保留最近 1024 个 token 时困惑度飙到 **5158**;把缓存换成「开头 4 个 + 最近 1020 个」,困惑度回到 **5.40**。差别只有 4 个 token。

两级解法,一个补救一个根治:

| 解法 | 改不改模型 | 做法 |
|---|---|---|
| StreamingLLM | 不改 | 推理时永久保留开头约 4 个 sink token + 滑动窗口,可无限长流式生成;比「滑窗 + 每步重算」快 22.2 倍 |
| GPT-OSS | 改 | 训练时就给每个头加一个**可学习的 sink bias**,直接进 softmax 分母,官方发一个垃圾桶 |

sink 的机制细节、它和门控注意力的关系见 注意力配件 篇。这里只需记住结论:**滑窗 + 流式生成,必须配 sink**。

## 六、边界、坑与选型

### 窗口开大开小,换的是什么

$W$ 同时控制三件事:单层能看多远、$L$ 层能传多远($L \times W$)、以及每步的算力与缓存($O(nWd)$、封顶 $W$ 条)。

- **开大**:局部层自己就能覆盖更多依赖,对全局层的依赖变轻;代价是计算与缓存按比例涨,$W$ 大到接近 $n$ 时 SWA 退化回全注意力,一点没省。
- **开小**:省得多,但单层退化成近似 n-gram,**长程能力全被压到少数全局层上**;全局层一旦不够,长文检索先崩。

没有通用最优值。实测顺序是:先定局部:全局比例,再在目标上下文长度上扫 $W$,同时看大海捞针、长文问答、困惑度、KV 显存与端到端吞吐。**只看困惑度会漏掉精确检索的塌陷**,因为困惑度对局部连贯最敏感,而局部连贯恰好是滑窗最擅长的部分。

### 窗口外的信息,四条出路

| 出路 | 能做到什么 | 局限 |
|---|---|---|
| 层间接力 | 把「大意」传到 $L \times W$ 之内 | 多层转述会失真,做不了精确复现 |
| 全局层 | 精确回溯任意历史位置 | 它的缓存仍线性涨,数量要省着给 |
| 常驻 token(sink / 全局 token) | 稳住注意力分布、当远程中转站 | 位置固定,容量极小 |
| 内容动态稀疏 | 按相关性直接命中远处 token | 要多养一个选择器,见 稀疏注意力 篇 |

### 分类要说准:滑窗是静态稀疏,不是稀疏的并列项

高频错答:「滑窗、稀疏、线性是三类方法」。准确说法是——**滑窗本身就是稀疏注意力的一种,属于位置固定的静态稀疏**:mask 在训练前就定死了,与内容无关。它和 DSA 这类内容动态稀疏的分水岭只有一句话:**谁来决定看哪些 token**。

| | 滑动窗口 | 内容动态稀疏 |
|---|---|---|
| 谁决定看哪些 | **位置**(固定 mask) | **内容**(轻量选择器打分选 top-k) |
| 窗口外 / 未选中的 KV | **可以直接扔** | **一条都不能扔**,任何历史都可能被选中 |
| 省下来的是 | 算力 + 显存 | 主要是算力 |

这条差别的工程后果比听起来大:SWA 真能减显存,token 级动态稀疏省的是 FLOPs。去掉 softmax 的线性注意力与 SSM 是另一条坐标轴上的路,见 线性注意力 篇。

### 落地:kernel 与推理引擎

- **kernel 层几乎零成本**:FlashAttention 从 2.3 起提供 `window_size` 参数(取 `(-1, -1)` 表示不开局部),斜带 mask 不必显式物化,分块计算时整块跳过窗口外的 tile。Mistral 7B 报告 16k 序列、$W=4096$ 下相对朴素实现约 2 倍提速。
- **引擎层要多做一层账**:vLLM 与 SGLang 都把滑窗层和全局层登记成**两种不同的缓存**分别管理,混合模型于是有两套缓存池、两套分配策略;滑窗层的块一旦滑出窗口就立刻回收,缓存才真的封顶。vLLM 也留了开关把混合管理关掉、全部当全局层看——省事,但显存收益跟着没了。
- **和前缀复用有冲突**:滑出窗口的块已经被回收,不能再当前缀命中,所以滑窗层的前缀缓存要求「窗口范围内连续命中」而不是「最长公共前缀」;跨请求共享前缀这类优化与滑窗的组合也有条件限制。具体支持随版本与后端变化,见开源解读模块。
