# 数据工程

一句话:数据工程管的是**从原始素材到可训练样本的整条流水线**——预训练语料怎么爬、怎么洗、怎么配,指令与偏好数据怎么设计、怎么标、怎么验收,两条线共用同一套「先定验收、再造数据」的手艺。它值多少?DCLM 的 7B 模型用 2.6T token 训到 MMLU 64%(5-shot),在 53 项理解类任务的均值上与 Llama 3 8B 相当而算力少 6.6 倍——差别不在结构,在一个正例选对了的过滤器。

## 一、一条管线,两条数据线

把数据管线想成**自来水厂**:上游是浑浊的江水,经过沉淀、过滤、消毒,出厂的才是能喝的水。每一环都是漏斗——DCLM 从 240T token 的原始池最后只留下 3.8T,留存率约 1.6%。**好数据是筛出来的,不是捡来的。**

管线的顺序不是随手排的,两条原则定死了它:**便宜的在前,贵的在后**——规则过滤扫一遍文档就能扔掉大头,模型打分要跑一次前向,像机场安检先用金属探测门拦下明显违禁的、开箱细查只对过了门的行李做,反过来做成本要高一个量级;**去重放在过滤之后**——先扔垃圾再去重,待比较的文档少一大截,而两两比较的代价随文档数超线性增长。

两条数据线走同一条脊柱,只是每一环的做法不同:

| 环节 | 预训练语料 | 指令与偏好数据 |
|---|---|---|
| 采集与抽取 | CommonCrawl 快照、代码、论文、书籍 | 真实业务记录、专家标注、可用公开集、合成候选 |
| 过滤 | 启发式规则 + 质量分类器 | 格式检查 + 约束满足 + 答案审阅 |
| 去重 | 文档级 + 子串级近似去重 | 近似重复指令、同义改写扎堆 |
| 去污染 | n-gram 撞评测集 | 按用户/会话/时间隔离,再查改写污染 |
| 配比 | 域权重、温度采样、退火加浓 | 任务/难度/长度/风格的覆盖清单 |
| 交付 | 全局 shuffle 的版本化 token 流 | 版本化样本集 + 冻结的独立评测集 |

**边界**:每参数配多少 token、数据墙、重复 epoch 的收益递减归 ScalingLaws 篇;训练阶段编排、WSD 调度、tokenizer 决策与 loss spike 归 预训练流程 篇;loss mask、灾难性遗忘与超参归 SFT 篇;偏好数据拿去训 RM 与 PPO 归 RLHF与RM 篇;检索语料的切块与索引归 切块与索引 篇。本篇只管数据怎么造出来、怎么验收,不管拿它怎么训。

## 二、数据会怎么坏:四种噪声与它们的症状

样本只通过两条途径影响模型:**训练目标**(它把什么当成要模仿的答案)和**采样权重**(它被看到多少次)。所以诊断噪声要问的不是「这条脏不脏」,而是「它改的是目标,还是权重」。

| 类型与例子 | 机制与表现 | 怎么发现 | 怎么处理 |
|---|---|---|---|
| **错标**:退款日期被标成下单日期 | 改目标。模型忠实模仿错误映射,抽取与事实类输出跟着错 | 对照原文、规则校验、分层人工复核 | 重标或剔除,回查同来源同批次 |
| **分布失配**:训练全是短咨询,线上是多轮纠纷 | 改权重。长尾任务几乎拿不到梯度 | 比任务、领域、长度、标签四类分布,不能只看 token 直方图 | 定向补样、调配比 |
| **行为偏差**:大量正常请求被标成拒答 | 改目标。学出过度拒答和单一文风,「看着礼貌其实有害」 | 把「该答」和「该拒」分组评估 | 修订边界示范,保留合理的困难请求 |
| **重复与污染**:同一 FAQ 反复转载、评测题混进训练 | 改权重(变相加权)并强化记忆,评测分虚高 | 文档与片段去重、隔离评测来源 | 见第四、五节 |

**高 loss 不等于噪声,低 loss 不等于干净。** 正确但困难的样本 loss 天然高;错误标签反过来可能被硬背下来而变成低 loss(神经网络连纯随机标签都能拟合)。所以 loss、模型打分、置信度、模型间分歧、用户互动率都只是**排查线索**,不能当成删样本的判据——判据永远是答案对不对。

### 越洗越差:清洗回归怎么做

「clean data 训完反而变差」是常见事故,先问清洗改了什么。三种可能:误删有效难例(稀有表达、长尾领域、写得别扭但内容正确的材料被规则一刀切);无意改了配比(某条规则对某个域命中率特别高,洗完域权重全变了);改了训练量(样本少了,同样 epoch 数下有效 token 与更新次数一起掉)。

诊断办法是**同预算三方对照**:固定 token 与更新预算,比较原集、清洗集、以及「恢复某一类被删样本」的清洗集,分别看抽检正确率和分组任务成绩,才能定位是哪条规则造成的损失。同一套对照也是回答「清洗到底贡献了多少」的唯一硬证据。前提是每一环都留下留存率、误删样例和规则版本——没有这些,回查无从下手。

### 阈值、专业领域与样本加权

数据量大而质量参差时按成本分层(具体两段式见第三节),但**阈值必须按场景校准**:短回复、方言、高困惑度、低互动在 UGC 场景里都可能是有效数据,照搬别处的阈值等于批量误删。医疗、法律这类专业材料另加一层:核对**来源、时效、适用条件和依据**,关键边界交由对应领域专家复核——文风专业不等于结论正确,而这类数据错一条的代价远高于删一条。

样本加权是双刃剑:**权重要设上限并归一化**,同时监控是否有少量样本占据了过多更新。高权重样本一旦错标,错误会被成比例放大;和均匀权重基线比分组成绩,收益说不清就调回去。

## 三、过滤:先规则,后模型

### 采集与正文抽取

CommonCrawl 是全网爬取快照,约每月一档,几乎所有开源预训练集的网页部分都源于此。每档三种格式:**WARC** 是原始 HTML 加 HTTP 头,**WAT** 是元数据,**WET** 是官方抽好的纯文本。**别直接用 WET**,它把导航栏、菜单、版权声明、cookie 提示一并当成正文;RefinedWeb 与 FineWeb 的共同选择是回到 WARC、用 trafilatura 一类工具重抽正文。WET 相当于整页复印,自己抽取是只剪下正文那一块,光这一步就能明显涨分。网页之外再补专库——代码(按 license 过滤、按文件级规则清洗)、论文、书籍、百科、高质量问答;Dolma 是多源混合的代表,3T token,清洗工具链全套开源。语言识别一般用 fastText 分类器按置信度切分语种,它的输出直接变成后面配比环节的输入。

### 两段式:规则挡大头,模型挑细节

**启发式规则**的判据全是「不用读懂内容就能算出来」的统计量:文档词数落在合理区间、平均词长 3–10、符号与词的比值不过高、重复行与重复段落占比不过高、以 bullet 开头的行不过多、必须命中若干常用停用词(这是「它是自然语言而不是乱码或关键词堆砌」的证据)。外加 URL 黑名单、成人内容词表,以及 PII 遮蔽(邮箱、电话、IP)这类合规工序——隐私问题在这一步处理最便宜。

**模型打分**只跑幸存者,三种主流做法:

- **fastText 质量分类器**:拿「公认的好文本」当正例、随机网页当负例,训一个线性小分类器给每页打分,按分数截断或按分数采样,便宜到能扫全库。
- **教育价值打分**:FineWeb-Edu 的配方是用 LLM 给几十万页标 0–5 的教育价值分,再把标注蒸馏成小分类器扫全库——大模型只出一次卷,批改交给小模型。
- **DCLM 的实证**:一个训练得当的 fastText 过滤器(正例取自指令数据与高赞问答)胜过一堆更花哨的打分方法。结论反直觉但重要——**过滤器不用大,正例选对才是关键**,「什么算好数据」这个定义本身就是最贵的超参。

## 四、去重:回报最高的一步

### 重复的三宗罪

1. **变相加权**。一段文本出现 100 次,梯度权重就是 ×100,而你并没打算这么配比。Lee 等人发现 C4 里有一句 61 词的英文句子重复了六万多次,没人想让模型重点背诵它。
2. **记忆化**。同一篇论文实测,去重后训练的模型**逐字吐出训练数据的频率降到约十分之一**,而且用更少的步数达到同等或更好的困惑度——既缓解隐私风险,又白赚算力。
3. **评测虚高**。重复常常伴随训练与测试重叠,跑分好看、能力没涨,和去污染是一体两面。

### 两级去重

**精确去重**抓逐字节相同的拷贝:URL 去重最便宜放最前,然后是文档或段落的哈希(用 Bloom filter 可以省内存)。**近似去重**抓「改了几个词的转载」,主流是 MinHash-LSH。

先把文档切成 n-gram 集合(常用 5-gram),相似度定义为集合的 Jaccard 相似度;再取 K 个哈希函数、每个取集合的最小哈希值拼成 K 维签名。它成立靠的是 $P[\min_{x\in A} h(x)=\min_{x\in B} h(x)]=J(A,B)$:两个集合「最小哈希值撞上」的概率恰好等于 Jaccard 相似度,所以签名逐位相等的比例就是相似度的无偏估计。类比是两个班各报出学号最小的那个学生,共同学生占比越高,报出同一个人的概率越大——用 K 次「选最小」把变长集合压成定长指纹。

最后是 LSH 分桶:把 K 维签名切成 $b$ 个 band、每个 band $r$ 行($K=br$),任意一个 band 完全相同就落进同一候选桶,只在桶内做精确比对。一对文档成为候选的概率是:

$$
P_{\text{candidate}} = 1 - \left(1 - s^{r}\right)^{b}
$$

$s$ 是真实相似度,这条曲线呈 S 形,拐点约在 $(1/b)^{1/r}$:高于门槛的文档对几乎必被抓住,低于的几乎必被放过。**b 和 r 就是调门槛的两个旋钮**——r 调大、b 调小,门槛右移、曲线更陡,只抓高度相似的对,改写较多的转载会漏;r 调小、b 调大则门槛下移,召回上去了但误判多、桶变大、桶内比对变贵。它把 $O(N^2)$ 的两两比较降成桶内的小范围比较,这才是它能扫万亿 token 的原因。

> 🖼️ 占位:MinHash-LSH 候选概率随 Jaccard 相似度变化的 S 形曲线,叠加两三组 b/r 取值并标出各自拐点

### 粒度的分寸:过粗与过细各自的代价

- **文档级**为主抓整篇转载,**段落或行级**补刀,清掉抽取残留的页眉页脚这类样板文字。只做文档级会漏掉「同一段模板出现在几十万个不同页面里」;逐行狠删则会把正常的重复表达也铲掉,还可能把文章切得语义不连贯。
- **去重不是越狠越好。** FineWeb 的消融里,跨全部 CC 快照做全局去重反而不如**按快照各自独立去重**:全局去重把跨快照反复出现的簇整批删掉,幸存样本向最新一批爬取倾斜,长尾质量更差。注意这个结论与规模和语料构成有关——总量充裕时成立,语料本来就小的场景里别人复现出的是相反结果。

## 五、去污染:分数涨了,能力没涨

- **怎么查**:拿评测集(MMLU、GSM8K 等)的题面与答案对训练集做 n-gram 匹配,常用 10–13 gram,命中就剔除该文档或片段。更严格的还查改写式与翻译式污染:模糊匹配、嵌入相似度、让模型判重。
- **查到怎么办**:追溯到污染进入的那个数据版本,清理后**重新训练或重新评测**。只从榜单里删掉那几道题不算处理,因为模型已经背过了。为什么非查不可?泄题涨的是分数不是能力,榜上多出来的点在真实使用里全要吐回去——背过题库答案的考生模拟考满分,进了没见过题的考场就现原形。
- **指令与偏好数据要多切一刀**:除了文本重叠,还要按**用户、会话、文档来源、时间**隔离训练与评测。同一个用户的两条对话即使字面完全不同,也可能泄露同一个业务事实。
- **MinHash 只判词面重合,不判语义真假**。它抓不出「换了个说法的同一道题」,更抓不出「事实写错了」:前者靠嵌入或模型判重,后者只能靠事实核验。这条纪律在每个阶段都成立,SFT 数据与 RL 的 prompt 池同样要与评测严格去重。

## 六、配比:谁对梯度贡献多少

**样本比例、token 比例、损失权重比例是三件事。** 一条长回答贡献的训练位置可能是短回答的几十倍,所以按样本数配成 1:1,实际梯度贡献可能是 10:1;长短比例要按真实任务的依赖长度和 token 预算来定,不能靠截断答案凑。做配比前先把每个来源的**样本数、有效 token 数、重复率、覆盖到的任务**分别统计出来,再决定按哪个口径配平——「按样本均匀抽」和「按领域均匀抽」也不是一回事。

设领域 $i$ 有 $n_i$ 条样本,常见的一种温度采样定义是:

$$
p_i=\frac{n_i^{1/T}}{\sum_j n_j^{1/T}},\quad T>0
$$

$T=1$ 就是按规模采样,大领域压倒小领域;$T>1$ 把指数压向 0,分布被拉平,小领域相对被抬起来;$T<1$ 反过来更偏向大领域。方向完全取决于公式怎么写——有的写法把 $T$ 放在分子指数上,结论正好相反,所以面试里说这个之前先讲清自己用的定义。

### 均匀、温度、课程:各自在解什么问题

| 策略 | 解决什么 | 代价与坑 |
|---|---|---|
| 按规模采样 | 简单,反映真实数据分布 | 小领域被淹没,长尾能力上不来 |
| 均匀采样 | 保证每个领域都有份 | 小领域被反复重复,容易过拟合 |
| 温度加权 | 在上面两者之间连续调节 | 只调了采样概率,没管长度与损失归一化 |
| 课程 / 退火 | 先覆盖基础,后加难度或加浓高质量数据 | 要和固定配比做同预算对照,否则只是「多训了一会儿」 |

**重要但样本少的任务**单独设最低覆盖,同时补真实样本、限制同一批样本的重复曝光,并盯住独立测试是否开始过拟合。**多语言**不能按原始字符量配平:同样的语义,不同语言分词后的 token 数差别很大,还要单看低资源语言的实际任务表现。**旧领域退化**时先查是错标还是覆盖缺口,再补代表性旧样本或压低新域权重,然后新旧任务一起回归(参数侧的保留机制见 SFT 篇)。

课程学习是有意改变**顺序与难度**,例如先覆盖基本任务、再加入困难且可靠的样本,不是简单按长度排序;均衡采样与课程并不冲突,但阶段性提高难度时必须守住基础覆盖。退火期(学习率衰减段)把数学、代码、教科书式与合成数据上采样,让影响力最大的收尾 token 花在最好的数据上——完整的阶段编排见 预训练流程 篇。

### 怎么搜配比,怎么证明它更好

- **先粗后细**。固定评测集与 token/更新预算,先比较少量候选配比,再在胜出的候选上联调学习率与 LoRA rank。配比和学习率有交互:配比一变最优学习率往往跟着变,所以不能各调各的,要把交互结果记下来。
- **自动化手段**。小模型代理实验(同一配比空间训一批小模型再外推,外推为何合法见 ScalingLaws 篇)、网格或贝叶斯搜索缩小范围;DoReMi 用代理模型相对参考模型的**超额损失**优化域权重,再把平均权重用到更大模型上。目标是超额损失而不是原始 loss——直接追最高原始 loss 会把权重推向不可学习的噪声。代理结论仍要在目标模型上复验。
- **看什么指标**。任务成功率、约束遵循率、拒答边界、**最差子组**成绩,而不只是总 loss;对齐类改动尤其要看拒答边界有没有被配比推歪。

## 七、指令数据:先写验收,再造数据

**先说清模型要学会什么行为、怎么算学会了,再去找数据。** 以客服为例,该覆盖的是正常咨询、信息缺失需要澄清、订单更正、以及超出业务范围该拒绝的请求,而不是把同一句礼貌问候扩写一千遍。落地动作只有两个:列一张按**任务、领域、难度、长度、表达风格**分桶的覆盖清单;冻结一个不参与任何生成与筛选的独立评测集。来源可以是真实业务记录、专家标注、可合法使用的公开集和合成候选,但每一条都要登记**来源、版本与使用范围**——发现一类错误时才能回查整批。

一条合格指令要说清**输入、目标、输出格式和边界**,例如「从下面的工单里提取订单号,以 JSON 输出;没有订单号时反问用户」。边界输入必须配上正确的澄清或拒答示范,否则模型会硬编一个订单号交差。**多样性不是同义改写的条数**:同一个任务写十种问法,任务分布仍然是 1;真正要变的是任务条件、边缘情况和用户意图,防止模型对特定句式过拟合靠的是任务与条件的多样,不是模板轮换。样本按结构化的角色、消息、回答保存,训练时再按基座模板渲染;空 input 是合法的,长度处理不能截掉答案依据(模板与损失边界见 SFT 篇)。

### 六步验收与五个数字

清洗按「**来源登记 → 格式与明显噪声检查 → 精确/近似去重与去污染 → 答案审阅 → 分层抽检 → 版本化交付**」推进,每一步各管一类问题,顺序不能乱。可量化的验收指标有五个:格式合格率、指令约束满足率、分层抽检正确率、重复率、各任务覆盖率;最终判据是**未参与构造的独立下游评测**。

反过来说,困惑度、奖励模型分数、流畅度都不能证明答案正确,也不宜按固定的 top 百分比一刀切放行。分类样本要固定标签语义,抽取样本要明确字段与必要位置,生成样本要定义回答约束与可接受变体——三类任务不能共用同一个自动分数。事实性回答必须对照可靠资料核查实体、数字与引用:模型多次采样答案一致,只说明它一贯这么认为,不说明它对——过滤幻觉样本只能落在这条外部核验上。

清洗后数量不够时,先回头查是不是误删了有效难例,再定向补采或补标,不能靠复制少量精品样本凑数;新增数据要补的是评测暴露出来的缺口,不是总条数。领域数据混入通用指令或旧任务样本时,比例由新任务收益与旧任务掉点共同决定,没有通用的九一开。

### 中文的特殊坑

| 问题 | 怎么发现 | 怎么处理 |
|---|---|---|
| 翻译改了条件、对象或否定关系 | 逐项对照实体、数字、单位、限制条件与预期答案,双语人员抽检 | 修订翻译或重写本地表达;回译只作辅助,译回去流畅不证明语义等价 |
| 繁简、全半角、乱码混杂 | 按来源统计并抽样看 | 修编码和明确的格式噪声;人名、代码、公式里有任务意义的差异要保留 |
| 方言、网络用语、中英混写被当低质删掉 | 按目标用户场景单独抽检 | 有业务需求就保留,并补等义规范表达与对应回答;要分开评估「听得懂用户」和「助手该用什么文风」 |
| 指令含糊或回答自相矛盾 | 检查任务是否可完成、回答是否满足约束且事实一致 | 补上下文、重标或剔除,不因文字流畅就放行 |
| 模板与任务分布单一 | 按覆盖清单的五个维度统计 | 针对缺口补样,比例由验证结果定,没有通用的六四开 |

还有一条常被问反的:中文没有空格**不等于**必须预先分词。是否损失信息要用实际 tokenizer 在样本上测,「中英 token 长度有固定倍数」这种说法不成立。中文资源有限时不要追总条数,先做一小份母语写就、覆盖核心任务的可信种子集,再按第八节的路子扩写与筛查。

## 八、合成与增强:补覆盖,不补事实

合成数据有两种常见形态:**蒸馏式**是强模型出题、改写、扩写,把低质网页重述成干净文风也算;**教科书式**是按主题大纲批量生成课文与习题,让小模型练出超龄表现。用它的时机是**真实数据补不上某个覆盖缺口**,而不是嫌真实数据难收。风险叫**模型坍塌**:反复拿模型输出去训下一代模型,分布的尾部(罕见知识、少数派表达)逐代丢失,输出越来越同质平庸,像复印件的复印件越印越糊。三条缓解:始终保留真实数据锚点、控制合成占比、对生成源做主题与风格的多样性约束。

验收上最容易犯的错是**让同一个生成器给自己打分**——错误会成批继承,而自评发现不了这类相关错误。必须逐批检查三件事:有没有继承同一类错误、长尾有没有丢、是不是只剩一种文风,并用未参与生成与筛选的评测集确认收益。标注预算有限时的标准路径是:先人工审一小份代表性种子,按覆盖缺口生成指令、输入与候选回答,用规则、可核验资料或执行结果筛一遍,去重后再人工分层抽检。Self-Instruct 是「生成候选再过滤」这条路的参考,但生成条数多不等于质量高。

### 数据增强:输入可以变,监督必须仍然成立

增强的前提是**变换后的输入与原监督仍然相容**,而这不等于「标签一概不变」:几何变换要同步移动检测框与分割掩码,mixup 干脆把输入和标签一起混合。

| 模态 | 常见方法与原理 | 必须检查的边界 |
|---|---|---|
| 图像 | 裁剪、翻转、颜色扰动,模拟视角与成像变化 | 裁掉了目标就不能保留原标签;OCR 类任务翻转直接破坏语义 |
| 文本 | 改写、回译、受控实体替换,扩大表达覆盖 | 否定、数字、实体与事实逐项核;替换实体后答案往往也要跟着改 |
| 语音 | 加噪、混响、变速,时频遮挡模拟声学变化 | 保持内容可辨认;时间标注随变速调整,说话人与情感标签未必守恒 |

三条纪律:**先清洗再增强**(复制错误不产生知识)、保留真实样本锚点、强度与合成占比由验证结果决定。跨模态增强(生成图像描述再回译)可以补表达,但要核查描述在图上是否真有依据——裁剪之后还在描述已经不在画面里的物体,就是典型的语义失真。SFT 增强后要复核目标回答是否仍正确;偏好数据还多一步:改写一侧可能改变事实、长度或拒答边界,**原来的排序未必还成立**,要重新判定。

怎么证明增强真的有用:按**原始样本及其衍生族**划分训练与测试,防止副本泄漏;固定训练预算对比「无增强 / 单方法 / 组合」,看独立真实测试、分布外测试和各语言场景子集的成绩;某个子集掉了就按方法、强度、来源逐项消融,撤回有害变换并补回被挤占的覆盖。用重复实验或置信区间区分真收益和波动。

## 九、标注:自动与人工怎么分工,一致不等于标得对

| 方式 | 强在哪 | 弱在哪、适用边界 |
|---|---|---|
| 规则、弱监督或模型构造 | 规模大、版本可追踪,适合结构明确、能自动验证的任务 | 会成批复制规则缺陷与模型幻觉,这类相关错误最容易逃过自评 |
| 人工与专家标注 | 能解释复杂条件、仲裁偏好,发现规则没覆盖的错误 | 成本高、有分歧,疲劳与个人偏好也会引入噪声 |

选择依据是**单位合格样本的成本**加下游效果,而这个成本要把生成、审核、返工和规则维护一起算——只比「生成一条多快」必然得出错误结论。实操总是混合的:机器出候选并做格式、证据、执行结果检查;人工复核分歧样本、高影响样本和边界样本;同时保留一份**分层随机抽检**,因为只复核低分样本会漏掉系统性错误——系统性错误往往分数很高。金融、医疗这类场景按**影响大小与可核验性**分工:稳定字段抽取、格式转换、可核验计算交给自动预标加抽检,需要解释业务规则、有歧义、错了代价大的交给人或专家;不能根据公司名称去推断人家的内部流程。

### 一致性:它是发现歧义的工具,不是正确率

流程是:指南与正反例校准 → 小批试标 → 独立盲标 → 按标签和难度分析分歧 → 专家仲裁并修订指南 → 回查已标的同类数据。标注方和算法方理解不一致时,分歧本身就是指南的缺口,要落到条款和正反例上,而不是口头对齐。两人分类标注常用 Cohen's Kappa:

$$
\kappa=\frac{p_o-p_e}{1-p_e}
$$

$p_o$ 是观察到的一致率,$p_e$ 是按两人各自标签边际分布估计的**偶然一致率**;分子分母都扣掉偶然部分,所以 $\kappa$ 量的是「比瞎猜好出多少」。多人标注要换成适配多人设计的统计量,不能把两人公式直接套给整个团队。

拿到 0.6 不要急着下结论:先看类别是否失衡、样本量够不够、分歧集中在哪两类、指南是不是有歧义,再定向培训、补例、复标;**没有通用及格线,更要紧的是一致高不代表标得对**——大家按同一条错误理解去标,分数会很漂亮。还有三个容易混的词:**交叉验证**是训练/验证划分下的泛化评估,划分时要隔离同用户、同文档的关联样本,但它证明不了标签正确;**交叉校验**是拿原文、独立来源、规则或执行结果去核对标签;**专家审核**覆盖高影响难例,同时也要随机抽普通样本。

开放生成任务没有唯一正确字符串,别硬套一致率:拆成约束满足、连贯、事实适用性、创意几个维度做盲评或成对比较,允许多个合格答案,再看各维度的一致性与偏好分歧落在哪,模型裁判本身也要用人工校准。验收自动数据则要用**未参与规则调优**的代表性审核集,统计正确率、误放率、覆盖率与分组错误,记录人工分歧和返工成本,最后以相同训练预算比较人工、自动、混合三种数据对任务成功率和旧能力的影响。

## 十、行为日志:点击不是偏好

行为日志的价值是它自带**真实任务分布**,代价是它没有标签。第一步是归一化:统一 API 字段、类型、单位与时区,把等义操作映射成同一个动作加参数(比如不同支付入口都归到「发起支付」),但渠道、金额、执行状态这些条件不能丢。抽象粒度是个跷跷板:**过粗**会把「点击、长按、发起意图、执行成功」合并成一件事,丢掉关键条件,模型学不到该在什么条件下做什么;**过细**则样本稀疏,而且规则绑死在当前界面上,界面一改数据就废。判据是围绕「模型需要做的那个决策」保留信息,识别不了的事件宁可原样保留。

### 为什么点击和停留时长不能直接当偏好

隐式反馈里混着三种偏置,它们和「用户更喜欢哪个」无关:

- **位置偏置**:排在前面的天然被点得多。
- **曝光偏置**:没点击很可能是**根本没展示**,不是不喜欢。
- **状态与内容偏置**:停留时长受内容长度、网络、用户当时在干什么影响;停留久也可能是没看懂、在反复找答案。

所以正确做法是:**偏好对必须来自同一请求下条件可比的候选**;把上述条件记录下来,用少量显式偏好或专家审核样本去**校准**这些代理信号,分人群、分场景看偏差和置信度;低置信的降权或干脆不用。SFT 样本同理,只用经规则、事实或执行结果验证过的目标回答,不能把点击最多的答案直接复制成标准答案。会话噪声也要分类而不是一刀切:误触、中断、没有结果的会话标成**不确定**而不是负例;一句「好的」可能是有效确认,也可能是敷衍,取决于后面有没有执行成功。

### 规则更新与收益验证

抽象规则是会改的,改之前要**并行回放**:用新旧两套规则跑同一批历史日志,对比含义差异,确认没有把旧任务的样本改坏,再迁移并回归旧任务;原始日志、抽象结果和规则版本三样都要留档。收益怎么算:先比原始与抽象数据在意图、槽位、执行结果上的正确率;再在**按用户或时间隔离**的测试集上做同预算训练对照;最终看真实任务完成率、错误率和适用的线上对照。离线奖励分涨了不算收益,它很可能只是把代理信号的偏置学得更像了。
