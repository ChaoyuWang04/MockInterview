# 预训练流程全景

> ⚠️ 旧版:本篇写于写作契约确立之前,尚未按新标准审查重写。标准见 docs/05-知识库写作契约.md,样板见「GPU架构与执行模型」。

一句话:预训练从大规模数据构造学习目标,如预测后续词元或恢复被遮词元;开跑前要把数据、模型、资源与恢复方案一起验证,避免把小实验能发现的问题带进昂贵的长时间训练。

## 一、全流程地图

```mermaid
flowchart LR
    A[数据管线<br>采集/清洗/去重/配比] --> B[tokenizer 训练]
    B --> C[架构与超参定型<br>小模型风洞实验]
    C --> D[主训练<br>海量通用数据]
    D --> E[中期/退火<br>高质量数据加浓]
    E --> F[长上下文扩展]
    F --> G[滚动评估] --> D
    G --> H[交付给后训练]
```

数据管线的细节见 数据工程 篇,结构选型从模型结构章总览进入,多卡切分见 并行策略 篇;本篇负责训练阶段之间的交接和开跑前的规划。

### 从原始数据到在线服务,每一步交付什么

| 阶段 | 输入与目标 | 交付前要确认什么 |
|---|---|---|
| 预训练 | 大规模语料,学习语言规律与知识 | 未污染的验证集上是否进步,不同领域是否偏科 |
| 监督微调 | 指令与示范回答,学习按任务要求作答 | 模板是否一致,回答质量与通用能力是否保持;机制见 SFT 篇 |
| 偏好对齐 | 偏好比较或可验证反馈,调整回答行为 | 是否只学会讨好评分器,有无能力回退;机制见 RLHF与RM 篇及 DPO 篇 |
| 部署准备 | 通过评估的权重,选择精度与服务配置 | 精度变化能否接受,目标负载下是否满足延迟与吞吐要求;见 推理加速 篇 |

阶段可以迭代,也可以按需要选择:不是每个系统都必须训练独立奖励模型或运行 PPO。蒸馏本身还要训练学生,不能当成上线时打开的一个推理开关,见 蒸馏 篇。每次交付应保留数据版本、配置和评估结果,这样效果下降时才知道是哪一步引入的。

## 二、tokenizer:最早定、最难改的决定

**BPE/BBPE 原理**:从字节/字符起步,反复把语料里最高频的相邻对合并成新词元,直到词表到达目标大小——像输入法把你常打的词组自动记成短语。字节级(BBPE)保证任何字符都能兜底表示,不会出现 UNK。

**词表大小的三方权衡**:

- 越大 → 同样文本切出的 token 越少(压缩率高、有效上下文更长、推理步数更少)
- 越大 → embedding/lm_head 参数越多(小模型里占比会失衡)
- 多语言/代码覆盖 → 需要更大词表才不至于把中文切成碎字节

衡量指标是 **fertility**(每词平均切几个 token)。趋势很明确:32k(Llama 2)→ 128k(Llama 3/Qwen)→ 256k(Gemma)。tokenizer 一旦定下,中途更换约等于重训,所以它排在流程最前面。

## 三、超参与配置定型:风洞实验

以自回归语言模型为例,预训练可以优化 next-token 交叉熵:

$$
\mathcal{L} = -\sum_t \log p_\theta(x_t \mid x_{<t})
$$

这里用自回归语言建模举例:给定位置 $t$ 之前的文本,提高真实下一个 token 的概率;损失只统计约定的有效位置。

### 掩码语言建模与自回归目标

BERT 的 MLM 隐藏部分词元,用双向上下文恢复原词。例如“他到 [MASK] 办理存款”,右侧“存款”帮助确定目标。多层双向注意力融合局部搭配和远距离信息,预测误差更新上下文表示;标签来自破坏前的原文,无需逐条人工标注。学到的词法、句法与实体关系可供分类、抽取和阅读理解复用,但不保证所有统计知识正确,也不意味着每层严格对应一种语言学功能。

原 BERT 选中约 15% 的 WordPiece 位置作预测目标,其中 80% 换成 `[MASK]`,10% 换成随机词元,10% 保留原词,三类都预测原目标。选中比例不是实际 MASK 比例,混合替换用于减轻训练与微调时的差异。比例过低使单条样本的预测目标少,过高破坏可用上下文;15% 是该论文的设置,不是通用最优值。

MLM 的限制包括只监督选中位置、MASK 在下游通常不出现;不能说其监督比自回归更密或梯度必然更稳定。RoBERTa 使用每次读入重新采样的动态掩码,移除 NSP,并调整数据、训练时长和批量等设置。其消融表明 NSP 并非句子任务的必要保证;整词掩码改变预测难度,不自动消除训练与使用的差异。

自回归只读过去、逐词预测,自然对应从左到右生成;MLM 提供完整输入的双向表示,适合多种理解任务,不能直接当普通逐词生成器使用。两者都能迁移到多种任务,应按输入可见性和目标选择。因果模型的预训练与 SFT 又可以使用同一种交叉熵,数据分布和监督位置的区别见 SFT 篇。

复杂的是**怎么在开跑前就确定超参大概率不炸**。做法是「风洞实验」:在一系列小模型上系统地搜学习率、初始化、batch size,再用规模规律外推到目标尺寸(μP 类方法的核心卖点就是让最优 lr 跨尺寸迁移)。batch size 与 lr 的配套关系、warmup 长度,都在这一步锁定。原则同样是:**贵的决定,便宜地验证**(拟合与外推的方法论见「ScalingLaws」篇)。

选择架构和初始化后,先短跑检查激活、梯度与非有限值,再放大训练。预训练与 SFT 的学习率没有固定数量级差,因为训练起点、数据量、可训练范围与有效 batch 都不同;已有知识要保留时通常更谨慎更新,但 LoRA 和全参不能简单沿用同一倍率。参数量与 token 数应联合按预算比较,不能把 Chinchilla 的结果误写成参数量恒与 token 数平方根成正比。

### 开跑前把资源账算清

先定任务与评估集,再共同选择参数量、训练 token 数和上下文长度。数据量不足时,不能靠无限重复语料补齐预算;总算力固定时,也不是参数越多越好,见 ScalingLaws 篇。

对以参数矩阵乘为主的稠密模型,常用以下粗估:

$$
C\approx 6ND,\qquad T\approx\frac{C}{G F_{\mathrm{eff}}}
$$

$N$ 是参数量,$D$ 是训练 token 总数,$C$ 是总运算量(FLOP);$G$ 是卡数,$F_{\mathrm{eff}}$ 是与模型、精度和并行配置相符的每卡有效运算速率(FLOP/s),$T$ 才是秒数。这个估算没有单独展开长序列注意力、重算、数据等待及故障停机,必须用小规模实测校准。

例如**假设** $N=7\times10^9$、$D=10^{11}$,得到约 $4.2\times10^{21}$ FLOP。若整个集群的有效速率为 $5\times10^{15}$ FLOP/s,则纯训练约 84 万秒,即 9.7 天;保存、验证和停机时间另外预留。这是算例,不是某项目实测。

显存要另算参数、梯度、优化器、激活和临时缓冲,不能由 FLOP 推出。先检查单卡能否放下,再决定分片、模型切分与重算组合,见 显存管理与OOM 篇、ZeRO 篇及 并行策略 篇。

**同样的激活参数量,MoE 和 Dense 也不能直接按相同天数预算。** 两者参与计算的矩阵规模可能接近,但 MoE 还要存更多总参数,并承担路由、专家通信及负载不均的代价。总参数用于估存储,激活参数用于估主要计算,最终吞吐要按真实布局测量;专家机制见 MoE基础 篇。

## 四、多阶段训练与 WSD 调度(现代标配)

现代预训练不是一锅端,而是分阶段换数据配方:

| 阶段 | 数据 | 目的 |
|---|---|---|
| 主训练 | 海量通用网页为主 | 打基础,吃掉绝大部分算力 |
| 中期(mid-training) | 提高质量配比,补数学/代码 | 提质,常伴随上下文加长 |
| 退火(decay/anneal) | 高质量+学术+指令风格数据加浓 | 临门一脚,基准分主要在这里涨 |

学习率调度与阶段划分深度耦合:

- **cosine**:经典,但必须预先定死总步数——中途想多训一段,整条曲线作废;
- **WSD(Warmup–Stable–Decay)**:预热后长期恒定 lr(stable 段),想收尾时随时切一段短促的退火(decay 段)。好处有二:① 不用预先承诺总 token 数,续训友好;② stable 段的任一 checkpoint 都能分叉出一次便宜的退火实验——**测数据配方、拟合 scaling law 的成本大幅下降**(MiniCPM 把这套玩法系统化)。

退火期是数据实验的黄金窗口:不同的高质量配比各退火一份,谁的基准分高就用谁,验证成本只有整训的零头。

## 五、长上下文扩展:放在最后做

注意力对序列长度是平方开销,主训练全程用 128k 跑纯属烧钱。标准做法:主训练用 4k–8k 短序列,**末期**再换长序列继续训——同时把 RoPE base 调大或配 YaRN(原理见「RoPE」篇),数据侧补足真实长文档与合成长依赖任务的配比。这个顺序(先短后长)几乎是全行业共识:长上下文是能力「扩展」,不是从头必需。

## 六、训练稳定性:与 loss spike 作战

万卡 × 数月的训练里,稳定性问题是日常而非意外:

- **loss spike**:先保存异常 batch、数据位置、梯度范数及各卡日志,检查是否由难样本、学习率、溢出或通信错误触发。用相同样本复现,区分一次波动与持续发散;仅在确认数据损坏后跳过该段。已经发散时从最近正常 checkpoint 恢复,修正原因再继续,不能见到尖峰就删数据;
- **监控面板**:loss、梯度范数(异常放大是 spike 前兆)、激活/注意力 logits 幅度;
- **结构性疫苗**:QK-Norm、z-loss 等稳定性组件(见「注意力配件」篇),在架构里预防而不是事后救火;
- **故障恢复**:检查点除权重外,还应按恢复目标保存优化器、调度器、随机状态和数据进度。保存频率依据可接受的重算时间与写盘成本决定,并在正式开跑前做一次恢复演练。

正常收敛不只是一条平滑训练曲线:要在相同有效目标口径下检查训练与验证趋势、分组任务表现和旧能力,同时监控梯度范数、激活及异常批次。梯度裁剪限制过大的范数,不能修好错误数据;bf16 通常不需要 fp16 式 loss scaling,仍需检查非有限值。数据配比消融应固定预算并保存真实结果,没有统一的重复率或代码比例阈值。

## 七、评估:滚动评与防自欺

### loss 异常的复现与恢复

保留异常批次、样本位置、各 rank 日志、学习率、梯度范数和最后健康状态,从同一检查点分别重放异常与正常批次。问题只随样本复现就查数据、标签和长度桶;正常样本也持续失败再查精度、优化器、累积归一化、通信与分片恢复。一次只改变一类因素。

先阻止非有限梯度更新参数。需要回滚时同时恢复权重、优化器、调度器、随机状态与数据进度,修复后重放原触发条件。只恢复权重或直接删除难样本,都不能证明根因已解决。

- **训练中**:滚动跑验证 loss/困惑度 + 一篮子 few-shot 基准(MMLU 类),看斜率而不是绝对值——曲线还在降就别慌;
- **防污染**:评测集必须在数据管线里做过去重剔除(见「数据工程」篇),否则基准分是自我安慰;
- **一个清醒剂**:退火期加浓「考试风格」数据能快速抬基准分,但基座的真实通用性要靠后训练之后的下游表现验证——**基准分好看 ≠ 基座好**。
