# 音频 · 总览

一句话:这是本子领域 **4 篇的导航页**——只回答"我该读哪篇、按什么顺序读",**不讲任何原理**。这四篇不是四个并列话题,而是**一个地基加三个任务**;把地基和任务分开看,边界就自然清楚了。

## 一、一个地基,三个任务

音频这一章的结构和隔壁 01-视觉理解 不同:那边五篇是一条从像素到语言模型的流水线,**这边是一篇地基托着三个方向相反的任务**。

| | 篇 | 方向 | 任务性质 | 核心难点 |
|---|---|---|---|---|
| **地基** | **音频编解码** | —— | —— | 一秒几万个采样点,怎么压成模型吃得下的东西 |
| 任务① | **语音识别** | 音频 → 文本 | **多对一** | 对齐:输入比输出长一两个数量级,且没有逐帧标注 |
| 任务② | **TTS** | 文本 → 音频 | **一对多** | 同一句话有无数种合法读法,逐点回归会学成平均 |
| 任务③ | **音乐生成** | 文本/符号 → 音乐 | 一对多 | 难点从"读法多"转移到**几分钟尺度的结构** |

**中间那一列是本子领域最好用的一把钥匙。** 语音识别和 TTS 是**互为反向的一对**,而它们的难点之所以完全不同,根源就是这条不对称:

- **ASR 是多对一**——一句话不管谁说、快说慢说、什么口音,正确答案只有那一串字。所以它可以用判别式训练,可以用 WER 这种客观指标。
- **TTS 是一对多**——语速、重音、停顿、情绪、音色都有无数种合法取值,**而且它们都不算错**。所以它必须用生成式建模,而且没有客观标准答案,只能靠 MOS。
- **音乐生成也是一对多,但更极端**:连"内容对不对"这个维度都不存在,评测因此最难。

**而这三个任务都得先回答同一个问题:音频到底怎么表示?** 这就是 `音频编解码` 的位置——它是地基,**表征谱系只在它那里讲一次**,另外三篇都从它往下接。所以不管你最后关心哪个任务,**它都该第一个读**。

## 二、四篇各回答什么

| 篇 | 它回答什么 | 一句话定位 |
|---|---|---|
| **音频编解码** | 波形 / 时频谱 / 离散 token 三级台阶各解决什么;神经编解码器的编码器-量化器-解码器三段;RVQ 为什么必须叠层;码率、质量、延迟的三角;音频 token 怎么接进 LLM | 单层码本要 $2^{80}$ 条存不下,**RVQ 把指数问题拆成了线性问题** |
| **语音识别** | CTC / 注意力 seq2seq / RNN-T 三种对齐范式的根本差异;Whisper 的弱监督路线与多任务 token 格式;流式延迟、长音频切分、幻觉、WER 四道上线关 | 难点不在"听清",在**没有逐帧标注怎么训** |
| **TTS** | 两阶段与端到端;声码器为什么最先被啃下来;漏读重复是怎么来的、时长预测器怎么根治;三条建模路线选型;音色克隆与流式 | 一切都从**一对多**发问 |
| **音乐生成** | 符号与波形两条路线;长时结构为什么难;乐理约束的硬软之分;文本配对数据的稀缺;FAD 与主观评测的盲区;版权 | 要在几分钟尺度上同时管住**听感**和**结构** |

## 三、按目标挑一条读法

| 你的目标 | 建议路径 |
|---|---|
| **第一次系统学音频** | 音频编解码(地基)→ 语音识别 → TTS → 音乐生成 |
| **做语音助手 / 实时对话** | 音频编解码(帧率那一节)→ 语音识别(流式与幻觉)→ TTS(首包延迟) |
| **做语音合成 / 数字人** | TTS → 音频编解码(离散 token 那一节)→ 语音识别(只看 WER 评测) |
| **做音乐 / 音效产品** | 音乐生成 → 音频编解码 |
| **只想搞清楚"音频怎么进 LLM"** | 音频编解码 一篇即可,重点在第四节 |
| **准备多模态大模型岗面试** | 音频编解码 → TTS → 语音识别;音乐生成 按岗位取舍 |

## 四、边界速查:这几件事写在哪一篇

四篇互相声明过边界,最容易找错的七处:

| 你要找的 | 在这篇 | 别去这篇找 |
|---|---|---|
| 波形 / STFT / 梅尔谱 / 离散 token 的表征谱系 | **音频编解码** | 另外三篇都只有一句引用,不展开 |
| **声码器**(梅尔谱 → 波形,如 HiFi-GAN) | **TTS** | 容易和下面一行搞混 |
| **神经编解码器**(波形 → 离散 token → 波形,如 EnCodec) | **音频编解码** | 它和声码器都产波形,但**输入不同** |
| 多层 RVQ token 怎么摊平进一维序列(拉平 / 并行 / 延迟 / 分层) | **音频编解码** 第四节 | **不在 音乐生成**——虽然这套是 MusicGen 提出的 |
| 码本坍塌的成因、诊断与缓解 | 根目录 **VAE** | 音频编解码 只说"音频侧同样会坍塌"加一条逐层统计的要求 |
| 离散化的路线之争(VQGAN / FSQ / LFQ) | 02-图像生成 的 **图像Tokenizer** | 音频编解码 只做一句类比 |
| 扩散 / flow matching 的机制本身 | 根目录 **Diffusion**、**FlowMatching** | TTS 与 音乐生成 只讲用在自己这边的代价 |

> **一条贯穿全域的对称**:`语音识别` 讲的"多对一"和 `TTS` 讲的"一对多"是同一枚硬币的两面,两篇开头都点了它。先读懂这条,再读各自的技术细节会快很多。

## 五、真题速查:本子领域暂无真题

**这一条必须说在前面:题库 `questions/` 里没有任何一道题的 `topic` 落在这四篇上。**

| 篇 | 真题数 |
|---|---|
| 音频编解码 / 语音识别 / TTS / 音乐生成 | **各 0 道** |

所以**这四篇的考点表全部是「补充题」**——按正文断言反推出来的问法,不是从真实面试里采到的。两个直接后果:

1. **复习权重要和有真题背书的篇目区别对待。** 隔壁 01-视觉理解 挂着 8 道真题,`VLM结构` 一篇就占 4 道;这里一道都没有。同样是"考点表",证据强度完全不同。
2. **考点表的问法只代表作者的判断。** 它们按契约第九节的四条否决线筛过、也都是"一主一追"的复合句形态,但**没有真题可以校准它们问得准不准**。

题库里唯一和音频沾边的是 `手撕代码` 分类下的 `语音增强/STFT` 与 `语音增强/时频域降噪` 两道编程题。`手撕代码` 整类被排除在文章匹配之外(有测试守护),所以它们不归这四篇承接,只作为背景知识相关。

> 如果之后采到音频真题,按 `docs/02-题库导入流程.md` 入库后,应回到对应专篇重做考点表——**真题优先,补充题让位**。

## 六、小节级索引:想找某一件事,直接翻到哪一节

**音频编解码**

1. 音频长什么样:波形、时频谱、离散 token
2. 神经编解码器:编码器 + 量化器 + 解码器
3. 残差矢量量化:一层码本为什么不够
4. 三角权衡,以及音频 token 接进 LLM

**语音识别**

1. 难在哪:长度差一两个数量级,而且没有逐帧标注
2. 三种对齐范式(CTC / 注意力 seq2seq / RNN-T)
3. Whisper 路线:用弱监督规模换鲁棒性
4. 上线要过的四关(流式 / 长音频切分 / 幻觉 / WER)

**TTS**

1. TTS 难在哪:一对多
2. 两阶段与端到端:从文本到波形的那条链
3. 对齐与时长:漏读和重复是怎么来的
4. 三条路线的选型,以及音色克隆与流式

**音乐生成**

1. 两条路线:写谱子,还是直接出声
2. 长时结构:音乐和语音最不一样的地方
3. 乐理约束:合不合调是另一种性质的约束
4. 文本条件、评测与版权
