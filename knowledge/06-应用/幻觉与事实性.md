# 幻觉与事实性

一句话:幻觉是模型给出**流畅但没有依据**的内容;这篇要说清的是——它其实是两类不同的病,成因散在五层,所以**没有任何单一手段能"解决幻觉"**,只能定义清楚、检测出来、分层压住,压不住就拒答。

## 一、先分两类,否则后面全是糊的

**事实性幻觉**违背外部世界的事实(说某药的适应症里有一条实际没有);**忠实性幻觉**是与**给定的东西**不一致——与题目要求不符、与检索到的材料不符、与工具返回的结果不符。

必须先分开,是因为**这两类的检测方法和缓解手段完全不同**:

| | 事实性幻觉 | 忠实性幻觉 |
|---|---|---|
| 违背的是 | 外部世界的真实情况 | 题目、检索材料或工具结果 |
| 怎么检 | 要找**独立的外部证据**,成本高 | 只需比对**手上已有的材料**,成本低得多 |
| 主要该动谁 | 补数据、上 RAG、接权威数据源核验 | 改 prompt 与约束、压噪声、强制引用 |
| 一个典型形态 | 库里根本没有,模型凭参数知识编 | 材料里写着"仅限 2024 年前签约",答案把这条丢了 |

**这两类会分道扬镳**,而且分道时最危险:检索到的文档本身就是错的或过期的,模型忠实地复述了它——**忠实度满分,事实错**。反过来,模型用参数知识答对了但证据里没有——**忠实度低,事实对**,而它照样附了引用,看起来无懈可击。这正是第七节要求两个指标必须分开报的原因。

### 创造性不是幻觉

写小说编一个不存在的城市,不叫幻觉,因为任务本来就要求虚构。所以任何幻觉治理的第一步不是上技术手段,而是**先划两条线**:

- **允许创造的边界**:哪些字段必须有据可查(人名、剂量、条款号、金额、日期),哪些可以自由发挥(措辞、结构、比喻)
- **什么算"可验证声明"**:能被证据支持或推翻的陈述才进检测范围;"这个方案很有前景"这种判断句既不算对也不算错,硬拿去判会把指标搞成噪声

线没划清,后面所有的检测和指标都是在量一个没定义的东西。

## 二、成因散在五层,这就是它治不好的原因

| 层 | 它怎么制造幻觉 |
|---|---|
| **数据** | 训练语料本身就有错误、互相冲突、或者已经过时 |
| **训练目标** | next-token 优化的是"这句话像不像人话",**不验证真伪**——流畅和正确从来不是同一个目标 |
| **能力边界** | 问题超出模型知识与当前上下文时,它仍然被指令逼着必须答点什么 |
| **检索** | 漏召回、召回噪声、召回了过期文档,或者被检索内容里的提示注入 |
| **解码与对齐** | 对齐过程奖励**自信、顺从、让人满意**的表达,而"我不确定"通常拿不到高分 |

**推论很直接:成因分布在五个不同的层,那就不存在一个层能全包的解法。** 面试里被问"怎么解决幻觉",答"上 RAG"或"做对齐"都是不完整的——正确的形状是第四节那张分层表。

第五层值得单独记一句:**对齐可能让幻觉更难被发现而不是更少**——模型学会了用更笃定的语气说话,人类评审也更容易给自信的答案打高分。

## 三、检测:先拆成原子声明,再逐条找证据

**整段判对错是判不出来的**,因为一段话里通常对错混杂——三句对一句错,你打分打多少都不对。所以标准做法是三步:

1. **拆成原子声明**:每条只陈述一件可验证的事。FActScore 那一路就是这么做的——把长文本拆成一串原子事实,算其中被可靠来源支持的比例
2. **为每条找独立证据**:注意是"独立",不能拿模型自己的另一段输出当证据
3. **判蕴含关系**:证据**是否真的推得出**这条声明。要一并检查引用是否错配、来源之间是否冲突、来源是不是已经过期

辅助工具可以用 NLI 模型、问答一致性、或 LLM-as-judge。但**评审模型自己也会错**,没校准过的 judge 分数不能当结论——偏差类型与校准方法见 RAG评测 篇第六节,本篇不重复。

### 一致性采样:是风险信号,不是事实证明

SelfCheckGPT 那一路的思路很聪明:同一个问题多采样几次,**如果模型真的"知道",几次回答会彼此一致;如果是编的,几次会互相矛盾**。这不需要外部知识库,黑盒模型也能用,所以很实用。

但必须把边界讲清,这是高频追问:**多次答案一致,只说明模型的输出分布稳定,不说明它对。** 模型完全可以**稳定地错**——训练数据里就是这么写的、或者是一个流行的误解,那它每次都会给出同一个错误答案,一致性检查全程亮绿灯。TruthfulQA 报告的正是这类现象:模型会稳定地复述人类常见的错误说法,而且**更大的模型在那个基准上反而更不"真实"**,因为它更好地拟合了训练分布里的错误。

所以一致性只能当**风险排序信号**——把不一致的挑出来优先送检,而不是拿一致当通过。Self-Consistency 那种多数投票同理:它提升的是推理路径的稳健性,不提供任何外部事实校验。

### 三类检测手段的定位

| 手段 | 要什么 | 能答什么 | 不能答什么 |
|---|---|---|---|
| 原子声明 + 证据检索 | 可信知识源 | 事实性与忠实性都能查 | 贵,慢,依赖知识源的覆盖 |
| 一致性采样 | 只要能多次调用 | **哪些地方值得怀疑** | 对不对——稳定的错查不出来 |
| 自我核查(CoVe 那一路) | 只要能多次调用 | 让模型先起草、再规划核查问题、**独立作答**、最后改写 | 仍在模型内部闭环,查不出它系统性不知道的事 |

CoVe 的关键设计是**核查问题要独立回答**,不让它看见原来的草稿——否则模型只会顺着自己已经写下的答案往下圆。

## 四、缓解分层:每层只解决它那一层的事

| 层 | 做什么 | 它解决什么 | 它**不能**解决什么 |
|---|---|---|---|
| 预训练 | 数据来源筛选、去重、时效治理 | 减少源头上的错误与冲突 | 已经训完的模型改不动 |
| SFT / 偏好对齐 | 教会引用、表达不确定、该拒就拒 | **行为**:格式、拒答倾向、要不要标注不确定 | **凭空提供新知识**——它改的是怎么说,不是知道什么 |
| RAG | 查询改写、混合检索、重排、来源过滤、去冲突、强制引用 | 把**外部的、可更新的证据**放到模型面前 | 检索本身会漏、会带噪声、会引错(见第五节) |
| 系统验证 | 数据库查证、计算器、规则校验关键字段 | **确定性地**兜住能被程序判定的部分 | 判不了开放性表述 |
| 拒答与转人工 | 证据不足时明确说没有 | 把无法保证的情况**挡在输出之外** | 拒多了系统就没用了,阈值要按代价定 |

**这张表回答了那道高频追问:SFT、RLHF/DPO 与 RAG 各解决什么。** 一句话版本:**对齐改行为,RAG 给证据,系统验证兜确定性,拒答兜剩下的**。把三者混为一谈——比如指望 DPO 让模型"少胡说"——就会做错方向:它顶多让模型更愿意说"我不确定",不会让它突然知道昨天发布的政策。

**什么该微调、什么该 RAG**,判据是知识的变更频率与是否需要溯源:稳定的领域知识与行为规范可以微调进去;**频繁更新、且答案必须能指回出处的,走 RAG**。两者可以组合,常见形态是微调管"怎么答"、RAG 管"依据什么答"。

## 五、RAG 自己会带来新的幻觉风险

上了 RAG 不等于关掉了幻觉,它只是把风险**换了个位置**:

- **检索噪声**:一条不相关但语气笃定的证据足以把答案带偏
- **过期或错误文档被忠实复述**:忠实度高、事实错——最难查的一类,因为所有指标都显示正常
- **引用错配**:结论对,但挂上去的引用其实不支持它;或者引用编号指向了另一段
- **提示注入**:检索回来的文档里写着"忽略以上要求"。**外部文档必须当作不可信输入**处理,防线见 Prompt优化 篇第八节
- **证据冲突被静默消解**:两版文档说法不同,模型挑了一条讲得斩钉截铁,不告诉你另一条存在

**怎么检查噪声与引用错配**,两个动作最实用:拿**引用精度**(标出来的引用有多少真的支持那句话)单独打一个分,不要和引用召回混在一起报;以及做**加噪对照**——在正确证据里掺入若干条无关块,看答案质量掉多少,这条曲线直接告诉你系统对噪声的耐受度。检索链路本身的手段见 检索优化 篇,整机的证据组织与冲突处理见 RAG系统设计 篇。

## 六、高风险场景:门槛设在声明级,不是回答级

医疗、法律、金融这类场景的差别不在于"更小心",而在于**判定粒度**:

- **证据门槛设在声明级**。整条回答通过不算数——每一条关键声明(剂量、条款号、适用范围、金额、生效时间)都要能指回具体证据,缺一条就不能整段放行
- **三种情况一律不自行作答**:证据不足、来源互相冲突、问题超出授权范围。走拒答或转人工
- **可审计**:记录这次用了哪些检索证据、索引版本、模型版本、prompt 版本。事后复盘时,不能重放的日志等于没有
- **人工复核放在高价值声明上**,不是均匀撒——人名、剂量、金额、日期、法条这几类错了后果最重

Fallback 的完整阶梯、拒答阈值怎么按"错答比误拒贵多少"来校准、垂直领域的数据与权限治理,见 RAG系统设计 篇第四、五节,本篇不重复。

## 七、怎么量:五件事必须分开报

**只看语言相似度(BLEU / ROUGE)是量不出幻觉的**,因为它衡量的是措辞像不像参考答案,和有没有依据无关。至少分开报这五项:

| 量什么 | 回答的问题 |
|---|---|
| 事实正确率 | 说的是不是真的 |
| 忠实度 | 说的能不能从给定材料推出来 |
| 引用支持率 | 拆成引用召回与引用精度两个数 |
| 拒答准确率 | 该拒的拒了没有、不该拒的有没有误拒 |
| 端到端任务风险 | 错误落到业务上有多贵 |

**前两项必须分开**,理由第一节已经给了——它们会分道扬镳,而且分道时正是最危险的时候。这些指标各自怎么定义、评测集怎么建、judge 怎么校准、离线和线上为什么背离,全部见 RAG评测 篇,本篇只负责说清**该量哪几件事、为什么不能合并成一个分**。
