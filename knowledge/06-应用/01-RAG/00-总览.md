# RAG · 总览

一句话:这是本子领域 **6 篇的导航页**——只回答"我该读哪篇、按什么顺序读、我的问题该去哪篇找",**不讲任何机制**。想知道整台机器由哪些模块拼成、模块之间交换什么、钱花在哪一段,那是 RAG系统设计 篇(整机篇)的活;想知道某一条答错该归谁,那是 RAG评测 篇的活。三篇位置不同,别搞混。

## 一、六篇分四组

一条 RAG 链路天然分三段:**离线把库建起来 → 在线把证据捞出来 → 用数字判断该修哪一段**。六篇就按这三段切,外加一条可选的专用索引路线。贯穿全子领域的一句话:**离线决定上限,在线决定这个上限兑现多少,评测决定你该往哪一侧投钱。**

### 离线建库(2 篇)——决定"能不能答"

| 篇 | 它回答什么 |
|---|---|
| **切块与索引** | 从原始文件到索引可查的整条链路:解析与清洗、五种切块策略与块长怎么定、跨块取证、元数据与过滤、代码知识检索、增量更新与一致性。**天花板在这里就定死了,先读它** |
| **Embedding** | 表示本身:向量的语义从哪来、pooling 与归一化、维度与成本账、DPR 与 Contriever 的训练信号差在哪;以及**文档库场景**的 ANN 索引结构与参数(Flat / HNSW / IVF / PQ / OPQ) |

### 在线查询(2 篇)——决定"上限兑现多少"

| 篇 | 它回答什么 |
|---|---|
| 检索优化 | **查询侧一整段**:证据丢在哪一层的诊断表、BM25 在算什么、稀疏与稠密为什么要混怎么融合、查询改写与 HyDE、重排的成本与训练数据、候选整理成上下文、Agent 多轮检索的延迟账 |
| RAG系统设计 | **整机篇**:RAG 的能力边界与和微调的分工、模块之间交什么的契约、生成侧 prompt 与引用、Fallback 四级阶梯与阈值校准、垂直领域治理、延迟与成本怎么分配 |

### 方法论(1 篇)——决定"先修哪一侧"

| 篇 | 它回答什么 |
|---|---|
| RAG评测 | 分层指标(检索 / 生成 / 端到端)各在回答什么、评测集怎么建、三组控制变量实验怎么设计、责任为什么给不出百分比、多路召回怎么算每一路的价值、LLM-as-judge 怎么校准、离线和线上为什么背离。**其余五篇提到指标时一律引到它** |

### 专用路线(1 篇)——贵,而且不是升级版

| 篇 | 它回答什么 |
|---|---|
| GraphRAG | 把实体关系抽成图、按社区层级预写摘要的那条路线:它补的是普通向量 RAG 的哪个洞、图怎么建、Local 与 Global 两种查法差在哪、离线与在线各贵在哪、什么时候明确**不该**用 |

## 二、五条读法:按你的目标挑一条

| 你的目标 | 建议路径 |
|---|---|
| **第一次系统学 RAG** | 切块与索引 → Embedding → 检索优化 → RAG系统设计 → RAG评测,最后按需读 GraphRAG |
| **时间紧,只要接得住面试** | RAG系统设计 → 检索优化 → 切块与索引——真题最密的三篇,吃掉 22 道里的 14 道 |
| **手上系统效果不好,要定位** | RAG评测 → 检索优化,再按结论回到 切块与索引 或 Embedding |
| **要从零搭一套,或者做选型** | RAG系统设计 → 切块与索引 → Embedding → 检索优化 → RAG评测 |
| **归纳类、多跳类问题答不了** | 先把上面前三篇做扎实,再决定要不要付建图那笔钱:GraphRAG |

四条依据,省得你自己再推一遍:

- **第一条路径是数据流顺序,也是出问题时的排查顺序**,推荐默认走它:块切坏了 Embedding 救不回来,召回漏了重排救不回来,这个"上游错误被下游放大"的形状本身就是本子领域最常考的一条主线。
- **唯一的补丁在开头**:RAG系统设计 的前两节(RAG 是什么、模块之间的契约)是全子领域最基础的定义,**先扫一眼当地图**,读完四篇专篇再回来看它的后四节(生成侧、Fallback、垂直领域、成本)。那四节整篇建立在专篇之上,先读只能拿到结论、拿不到依据。
- **第四条路径和第一条只差开头一步**,因为搭系统时先要的是"这台机器由哪几块拼成、各自换掉的代价多大",而不是"块该切多长";学习时反过来,先看清数据怎么流,契约才有意义。
- **GraphRAG 放最后不是因为它难,是因为它是一条专用且昂贵的路线。** 判断该不该建图,前提是先知道普通 RAG 能做到什么、做不到什么——公开评测的结论也是"先把切块、混合检索、重排做扎实",不是"上图就更好"。

## 三、真题速查:22 道题落在哪几篇

题库 `questions/RAG/` 是真题的唯一集合,题目 `topic` 第一段就是文章名,所以对应关系是一一对上的:

| topic 第一段 | 题数 | 这一组主要在问什么 |
|---|---|---|
| 检索优化 | 5 | 技术综述、Retriever 工作机制、BM25、混合检索、Reranker 原理与训练数据 |
| RAG系统设计 | 5 | 原理与工作流、生成与上下文、Fallback、垂直领域治理、模型配置与成本权衡 |
| 切块与索引 | 4 | 知识库构建流程、文本分块、代码知识检索、更新一致性 |
| RAG评测 | 2 | 分层指标、错误归因 |
| Embedding | 2 | 模型选型、向量索引 |
| GraphRAG | 1 | 原理与选型 |
| 知识图谱表示学习 | 1 | TransE、RotatE、GNN 与 GAT 的比较——**计划文章,尚未建文件** |
| 幻觉与事实性 | 1 | 成因、检测与缓解——**计划文章,尚未建文件** |
| 大模型局限 | 1 | 能力边界与系统性解决路径——**计划文章,尚未建文件** |

三条读表须知:

- **前六行的题都能在同名文章的考点表里找到落点**;最后三行的三篇还没建文件,那 3 道题目前只在题库里,读完前六篇不代表这三道也答得上。
- 另有 `questions/Agent/` 里 1 道 `topic` 为 `检索优化` 的题(RAG 与 Agent 集成的延迟与正确率),按 topic 归 检索优化 篇的最后一节,别只在 `RAG` 分类里找。
- **题数少不等于分量轻。** GraphRAG 只挂 1 道题,但它连追问一起横跨建图、两种查法、抽取出错怎么修、更新一致性和适用边界,展开之后就是完整的一篇。**每篇文末各有自己的「面试考点串联」表**,把该篇的真题问法逐条映射到小节,本页不重复。

## 四、边界速查:最容易找错的八处

六篇的分工写死在 `docs/04-知识库地图.md` 里,互相只留一句话引用、不重写。**同一个词在两篇里出现,通常是一篇讲机制、另一篇讲怎么用它**;最容易找错的几处:

| 你要找的 | 在这篇 | 别去这篇找 |
|---|---|---|
| HNSW / IVF / PQ 的结构与参数、FAISS 和向量数据库怎么选 | **Embedding** | 切块与索引 只讲建库链路,索引结构一句话带过 |
| 切多长、overlap 多少、父子块与上下文化块怎么做 | **切块与索引** | Embedding 只说"长文档为什么必须切" |
| 两路结果怎么融合(RRF、归一化加权)、权重怎么切 | **检索优化** | Embedding 只说倒排与向量互补,不讲融合 |
| 候选集怎么去重、压缩、组装成上下文 | **检索优化** | RAG系统设计 从"证据到了模型面前怎么摆"才接手 |
| 证据互相冲突时 prompt 怎么写、引用怎么留 | **RAG系统设计** | 检索优化 到候选整理为止,不管生成侧 |
| Recall@K、忠实度、引用支持率这些指标的定义 | **RAG评测** | 其余五篇提到指标一律引到它,不重复定义 |
| 检索为空或分数全低时怎么兜底、阈值按什么定 | **RAG系统设计** | 检索优化 只讲"降级不能退回凭参数知识硬答"这一条纪律 |
| 实体抽取、社区检测与摘要、Local 与 Global | **GraphRAG** | 其余五篇都不讲图索引 |
