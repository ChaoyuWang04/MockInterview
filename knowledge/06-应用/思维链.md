# 思维链

一句话:思维链(Chain-of-Thought,CoT)就是**把「从问题到答案」中间那几步写出来**——本篇管的是这条推理轨迹本身:它是什么、拿它当训练数据有什么用、收益到哪儿就到头了。

> **边界**:CoT、ToT、GoT、Self-Consistency 之间怎么选、什么时候值得多花十几倍算力,以及 ReAct 的循环怎么组织,见 规划模式 篇(本篇只讲它们的信息流形状差异);SFT 这种训练方式本身见 SFT 篇;过程奖励模型怎么训、怎么用见 RLHF与RM 篇;优势估计与信用分配的机制见 PPO 篇,多轮工具轨迹上的信用分配见 AgenticRL 篇;few-shot 示例怎么选、顺序影响见 Prompt优化 篇;采样温度与解码参数见 解码策略 篇。

## 一、两种用法必须先分开

同一个词「用 CoT」,底下是两件完全不同的事,**分不清这两件事,后面所有讨论都会串**:

| | 提示里给推理示例 | 把步骤做成训练样本 |
|---|---|---|
| 改的是什么 | **只改输入文本**,参数一个都不动 | **改参数**,梯度更新 |
| 怎么做 | 给几条「问题—步骤—答案」示范,或者一句「一步一步想」 | 把「问题—步骤—答案」当作监督数据跑 SFT |
| 成本落在哪 | 每次请求都付示例的 prefill 与更长的输出 | 一次性付标注/生成与训练,推理侧只多付输出长度 |
| 怎么失效 | 换个模板、换个示例顺序就可能掉回去 | 训练分布外的题型不吃;改不动就得重训 |
| 生效范围 | 只在带这段提示的那次请求里 | 模型的默认行为变了,不带提示也倾向写步骤 |

**CoT 描述的是内容形式,SFT 描述的是训练方式,两者不在同一个轴上,不能互相替代。** 所以「CoT 和指令微调是什么关系」这个追问的正确答法是:**它们解决的是不同的毛病**——指令微调解决「听不听话、格式对不对、答不答非所问」,CoT 解决「中间过程写不写出来」。一个只用最终答案做过指令微调的模型,提示里加 CoT 示例照样能写步骤(只是不稳、对格式敏感);一个吃了海量 CoT 样本但没训过指令跟随的模型,照样会答非所问。

现实做法是**合在一起**:指令微调数据集里,推理类任务的回答本身就写成带步骤的形式。这一条数据既是指令微调样本,也是 CoT 样本——**两个词描述的是同一条数据的两个侧面**,不是两套流程。

## 二、训练信号变在哪里

设输入为 $x$、经过校验的步骤文本为 $r$、答案为 $y$,一种常见的训练目标是:

$$
L = -\lambda_r \log p_\theta(r \mid x) - \lambda_y \log p_\theta(y \mid x, r)
$$

人话说就是:**第一项要模型学会「写出这段步骤」,第二项要它学会「在已经写出步骤之后,给出答案」**;$\lambda_r$、$\lambda_y$ 决定这两件事各占多少权重。和只训答案的目标(只剩第二项、条件里也没有 $r$)相比,多出来的东西是——**「怎么从问题走到答案」这段过程本身也被当成了要学的东西**,而不只是最后那个结论。

监督因此变得更具体。一道两步计算题,模型看到的不再只是最后那个数,还有「先取哪些量、怎么变换、再代进哪个式子」。生成时,已经写出的中间结果还会作为上下文被后续 token 读到。

两项都会展开成逐 token 交叉熵,于是马上有一个必须交代的选择:**这些 token 的损失是求和还是平均**。

| 归一化方式 | 一条样本的权重 | 后果 |
|---|---|---|
| 按 token 求和 | 正比于长度 | 一条 800 token 的长链在批梯度里的话语权是 100 token 短链的 **8 倍**,和它对不对无关,只和它长不长有关——模型很容易学成「写得长」而不是「算得对」 |
| 每条先在自身长度上平均,再样本间平均 | 每条等权 | 长链里的**单个** token 权重被稀释,链条关键的那一两步反而学不动 |
| 批内按有效 token 总数归一 | 介于两者之间 | 常见折中,但仍要配长度上限与按长度分层采样,否则批间方差很大 |

所以答这道题不能只说「加权」,要说清**权重是加在样本上还是 token 上**。它和 loss mask 是同一件事的两面:**掩码决定哪些 token 进损失,归一化决定这些 token 各占多重**;掩码怎么写、多轮对话监督到哪一轮,见 SFT 篇。

## 三、三条必须否定的误解

### 「额外的计算空间」不等于改层数、缩短反传路径

**对的那一半**:自回归模型每生成一个 token,做的计算量是固定的(层数固定)。写出中间结果后,这些结果重新进入上下文,下一个 token 的计算可以**建立在它们之上**——等于把「一次前向做不完的串行计算」摊到很多次前向上。理论侧有工作把这件事说死了:固定深度、固定比特精度的 transformer 单次前向能解的问题类很窄(AC⁰),配上 $T$ 步 CoT 之后,可以覆盖规模为 $T$ 的布尔电路能解的问题;实测里置换复合、电路求值这类**天生串行**的任务提升最明显,浅层模型尤其(arXiv:2402.12875)。

**错的那一半**:这是在 **token 维度**上加串行步数,**不是在网络里加层**。模型深度没变、每个 token 的计算图深度没变、反向传播路径也没变短——训练时链更长意味着序列更长,**反传路径是变长不是变短**。梯度消失是残差与归一化位置管的事(见 残差流 篇、Norm位置 篇),CoT 根本不碰它。

### 模仿步骤文本,不等于判断每一步正确

普通 CoT-SFT 的损失是逐 token 交叉熵,**它奖励的是「这个 token 和参考步骤文本一样」**。后果很直接:参考文本里第 3 步是错的,模型就照着学错的那步;参考文本是对的,模型换个说法也说对了,照样被罚。**「这一步对不对」这个信号压根不在损失里**。

要逐步正确性,就得另外拿逐步标签去训过程评审模型或者当过程奖励用——这正是过程监督那条线在做的事:同样的最终答案,**过程监督训出来的模型比结果监督更强**(arXiv:2305.20050)。PRM 怎么训、怎么用、它自己的漏洞在哪,见 RLHF与RM 篇。

### 答案对不等于链条对,链条写出来不等于它真是这么想的

前半句是自动造数据时最常踩的坑:数学题里「两处错误互相抵消」「四选一蒙对了」都会产出**答案正确、过程错误**的样本,拿去训就是在教模型错的推法。所以校验必须**答案和关键步骤一起校验**。

后半句更重,叫**忠实性**:链条只是模型生成的一段文本,**不是它内部计算的日志**。有工作把多选题的选项顺序改一下,把模型引向错误答案,模型照样能写出一段像模像样的解释来支持那个错答案,而且**全程不提自己受过这个改动的影响**;在 BIG-Bench Hard 的 13 个任务上,这种引导最多能让准确率掉 36%(arXiv:2305.04388)。所以**不能拿链条当可解释性证据,更不能当安全审计的依据**。

## 四、泛化:收益是「可能」,风险是「一定」

**收益**:如果步骤展示的是**可复用的规则**(单位先统一、先列方程再解、先算括号),模型有机会把它用到没见过的组合上;同一道题给多种正确解法还能增加多样性,避免只学到一条固定模板。

**风险**都是「不保证」型的,三条要能张口就说:

| 不保证什么 | 因为 |
|---|---|
| 分布外泛化 | 模型可能学到的是这个数据集的**题型模板**,不是规则本身;换领域、换表述,模板就对不上了 |
| 长度外推 | 训练里都是 3 步题,测试给 10 步,模型常在第四五步之后开始漂——链的长度分布本身就是一种分布 |
| 错误不传播 | 链是自回归的,第 2 步错了,后面每一步都在错的前提上继续推,而且**写得同样自信** |

评估因此必须一起看四个数:**最终正确率、过程可靠性、生成长度、耗时**。只看第一个会同时漏掉「答案对但过程烂」和「答案对但多花了 5 倍 token」。数学与程序类可以引入求解器、单元测试做过程校验;其他任务只能靠可靠标注加人工抽检。**不要仅凭答案正确就认定整条链正确。**

## 五、小模型上效果差:四类原因,一条纪律

| 原因 | 症状长什么样 | 怎么改 |
|---|---|---|
| 基础能力不足 | 单步就错(加减法、单位换算) | 先补单步能力,多步是建立在单步之上的,顺序反了没用 |
| 链条太长 | 前两三步对,后面越走越飘 | 换**更短更明确**的分解;按难度递进地喂 |
| 教师步骤难模仿 | 教师跳步、用了小模型没有的知识 | 让教师写得更细更显式;或换风格更朴素的教师 |
| 训练与测试格式不一致 | 训练带步骤、评测直接问答案(或反过来) | 模板逐 token 对齐,把渲染结果打出来比对 |

两条纪律:

1. **必须和「只训最终答案」的基线比。** CoT 数据比纯答案数据贵得多,不比基线就不知道多花的钱买到了什么。
2. **没有通用的参数量门槛。** 「必须超过多少 B 才有 CoT 能力」这种说法不成立——它取决于任务、教师质量、数据量和格式。有工作在 11B 以内的模型上靠针对性特化把多步数学推理明显拉起来,代价是通用能力下降(arXiv:2301.12726);也有工作把 540B 教师的链蒸馏给 T5,GSM8K 从 8.11% 提到 21.99%(arXiv:2212.08410)。两条一起说明:**门槛不是参数量,是「教什么、怎么教、愿意牺牲什么」**。蒸馏本身的机制见 蒸馏 篇。

## 六、自动构造 CoT 数据:流程,以及三条不能破的纪律

流程六步:**选可验证的题 → 一题多采候选 → 校验答案与关键步骤 → 去重去污染保多样 → 少量人工抽检 → 小规模训练对比**。

- **选可验证的题**:数学有标准答案、代码有测试、SQL 能执行。**没有验证手段的任务不适合走自动构造**,因为第三步做不了,后面全是自我安慰。
- **一题多采**:同一道题采 $k$ 条候选(换温度、换提示),既提高「至少有一条对」的概率,也保住多解多样性。
- **校验答案 + 关键步骤**:只校验答案会放过第三节说的「凑对」链。
- **去重、去污染、保多样性**:去重按内容归一化后判等,不能按文本相等;去污染要对着评测集查,防止测试题混进训练;多样性要保住难度分布和解法分布,否则筛完只剩最容易的那批题。手段见 数据工程 篇。
- **人工抽检 + 小规模对比**:自动校验抓得住「答案错」,抓不住「步骤对但表述误导」;先小跑一版和只训答案的基线比,再决定要不要大规模生产。

纪律只有三条,但都是硬的:

1. **生成、验证、训练集划分必须分开。** 用同一个模型既生成又给自己打分,分数高只说明它对自己的输出有信心——相关的错误正好是它发现不了的那一类。
2. **验证器要么是执行类**(求解器、编译器、单元测试)**,要么是独立训练的**。同模型自评只能当粗筛,不能当证据。
3. **评测集在生成之前就冻结隔离**,不能一边生成一边往里加题。

这条流水线和「采样—按硬判据筛—拿筛过的样本做 SFT」是同一件事,采样侧的性质(为什么按硬判据筛不破坏无偏、按分数取 top-k 才破坏)见 拒绝采样 篇。这条路线最早的代表是 STaR:让模型生成能推出正确答案的链,再拿这些链训自己,迭代放大(arXiv:2203.14465)。

## 七、不显式输出 CoT,照样能做 RL

**RL 只要求两样东西:策略产生 action、环境或评分器返回奖励。它从来没要求 action 必须是一段人能读的思维链。** 模型可以直接吐最终答案,也可以把工具调用、环境动作当成轨迹的一部分。

难点在于:**只有终局奖励时,信用分配更难**——几百个 token 的输出,末尾只回来一个标量,分不清是哪一步立的功。五类手段:

| 手段 | 在做什么 |
|---|---|
| 价值基线 | 估「从这里开始的期望回报」,减掉它,只留超出预期的部分 |
| 优势估计 | 把单步奖励与价值差组合成低方差信号(机制见 PPO 篇) |
| 多次采样比较 | 同题采一组,用组内相对好坏代替显式价值网络(见 GRPO 篇) |
| 分步验证器 | 让过程奖励模型或执行器在中途给分,把终局奖励拆成中间奖励(见 RLHF与RM 篇) |
| 子目标奖励 | 人为定义可判定的里程碑:编译通过、检索到证据、单测过了几个 |

多轮工具轨迹上的信用分配是另一个更难的问题,见 AgenticRL 篇。

**R1-Zero 类结果到底说明了什么**,这里三句话必须说准(arXiv:2501.12948):

- **说明**:在可验证任务上、探索足够时,只给结果奖励、不给任何推理示范,模型也能自己长出更长的推理行为——**显式推理示范数据不是必要条件**。
- **不说明「完全没有推理」**:那类模型输出的恰恰是很长的可见推理链,只是这条链是奖励逼出来的,不是抄示范抄出来的。
- **不能推广到所有任务**:结论建立在有自动验证器的任务上;开放式写作、主观任务根本拿不到这种奖励。

**隐藏推理能替代显式链吗?** 能省下输出 token,也少了「链被用户读走、被当成解释」的风险,但代价很实在:**过程不可观察**——过程监督没有可打标签的对象,调试时看不出它在哪一步走岔,安全审计也拿不到可检查的中间产物。所以这是一笔明确的交易:**你是用「链可能不忠实」换「链至少可见」,还是连可见都不要了**。

## 八、信息流的形状:链、链中插动作、树、图

四种东西经常被摆在一起问,但**它们的差别可以只用「信息流长什么形状」讲清楚**:

| | 形状 | 下一步的输入从哪来 | 有没有外部环境介入 |
|---|---|---|---|
| CoT | 一条链 | 上一步是**自己写的文本** | 没有 |
| ReAct | 链,但每步之间插一次动作 | 上一步的**观察来自环境** | 有 |
| ToT | 树 | 同层多个候选,评价器选一个,走错能回溯 | 看实现 |
| GoT | 图 | 多个父节点可以**合并**成一个新节点 | 看实现 |

**怎么选、什么时候值得、成本各差几个量级、评价器为什么是天花板,见 规划模式 篇**,那里有完整的成本模型与选型表;本篇到形状为止。

本篇必须单独补的一句(因为它属于训练侧):**这四种都是测试时的组织方式,一个参数都不更新**。它们和前七节讲的「拿链去训练」不在一个轴上——**训过 CoT 的模型跑 ToT 会更好,但训 CoT 不等于上 ToT**,反过来也一样。

## 九、加了 CoT 反而变差:怎么诊断

先做一件事:**确认下降可复现**。同一套提示、模板、解码参数、精度、测试集版本下再比一次,别让配置变化伪装成 CoT 的效果。然后按「配置 → 数据 → 目标 → 任务适配」往下查,因为配置类原因最便宜也最常见,排到后面就会白重训好几版。

| 原因 | 长什么样 | 怎么确认 |
|---|---|---|
| 解码配置变了 | 温度、停止条件被顺手改过 | 固定解码配置重测(参数见 解码策略 篇) |
| 训推格式不一致 | 训练带思考段,评测模板没带 | 逐 token 比对训练渲染与推理渲染 |
| 链的质量差 | 训练链本身跳步、有错、答案对而过程错 | 抽 50 条人工读;或用独立验证器重跑关键步骤 |
| 长度权重压过正确性 | 输出明显变长,正确率没动 | 换归一化方式重训一版对照(见第二节) |
| 长度失控但不体现在正确率上 | 延迟和成本涨了几倍 | 正确率、token 数、耗时**一起报**,别只报第一个 |
| 任务本身不吃 CoT | 分类、抽取、常识问答,加链原地踏步甚至掉分 | 跑一版直接作答的基线对比 |

最后一行有实证支撑:一份覆盖百余篇论文、20 个数据集、14 个模型的元分析发现,**CoT 的收益主要集中在数学与符号推理类任务**,其他类型收益小得多;在 MMLU 上,除非题目本身含符号运算,直接作答和 CoT 的准确率几乎一样(arXiv:2409.12183)。

由此得到一条决策:**确认是「任务不吃 CoT」之后,正确动作是关掉它,不是把链写得更长**。CoT 不免费,每一步都要真的生成 token,延迟和成本随链长线性涨。
