# Agent · 总览

一句话:这是本子领域 **7 篇的导航页**——只回答"我该读哪篇、按什么顺序读、我的问题该去哪篇找",**不讲任何机制**。想知道一台 Agent 由什么零件组成、怎么转,那是 Agent架构 篇的活;想知道这件事该不该交给 Agent、上线之后怎么兜,那是 Agent选型与治理 篇的活。这三篇各管一层,别搞混。

## 一、七篇分三组

分组依据是**这一篇回答的问题在哪一层**,不是难度:一篇讲整台机器长什么样,四篇各拆一件机制,两篇管机制之外的两个决定。七篇之间不重讲——**任何一件机制只在它的主责篇里展开一次,别篇一律一句话引过去**。所以照顺序读不会读到重复内容,跳着读则会一直被引到别篇。

### 整机图景(1 篇)——本子领域的地基

| 篇 | 它回答什么 |
|---|---|
| **Agent架构** | 这台机器由什么零件组成、怎么转:决策在模型,状态、权限和"停不停"在模型之外;自主度谱系的四档;Skill、Memory、Harness 这三个被叫混的词各是什么;一个 Agent 里几类模型分别怎么选;入口怎么把模糊请求变成结构化状态。**先读它,后面六篇的词汇都在这里定义** |

### 四件机制(4 篇)——一次任务里,四个必须分开回答的问题

顺序就是一步任务本身的顺序:先定下一步做什么,再把动作落下去,再决定状态放哪,最后才轮到要不要拆成多个。

| 篇 | 它回答什么 |
|---|---|
| 规划模式 | **循环怎么组织、怎么停**:ReAct 的三段式、Plan-and-Execute、反思、CoT/ToT/GoT 的取舍,以及让循环一定停得下来的四道闸 |
| 工具调用 | **动作怎么落地、失败怎么兜**:工具 schema 契约、五道校验闸、上千个工具怎么路由、重试与级联超时、三处都不可信的输入 |
| 记忆与上下文 | **状态放哪、预算怎么分**:记忆的四层、上下文装配与超限时的裁剪顺序、向量记忆的召回与治理、时间为什么必须分四种记 |
| 多智能体 | **摆几个 Agent、怎么连线、什么时候是负优化**:相对单 Agent 多付的五笔、四种编排拓扑、结论合并与仲裁、故障接管与共识的边界 |

### 落地与治理(2 篇)——机制之外的两个决定

| 篇 | 它回答什么 |
|---|---|
| Agent框架 | LangChain/LangGraph 与 LlamaIndex 今天各长成什么形状、重叠到了什么程度、给一个项目该按什么依据选;AutoGPT、AutoGen、CrewAI 各自处在什么位置。**只讲选型,不讲任何机制** |
| Agent选型与治理 | 两件事:**该不该交给 Agent**(提示、ICL、微调、RAG、Agent 五条路各补什么,多付哪几笔,止损线画在哪);**交了之后怎么不闯祸**(身份与权限、审批分级、分层监控与故障定位、人也判不准的高风险场景怎么受控) |

## 二、四条读法:按你的目标挑一条

| 你的目标 | 建议路径 |
|---|---|
| **第一次系统学 Agent** | Agent架构 → 规划模式 → 工具调用 → 记忆与上下文 → 多智能体 → Agent框架 → Agent选型与治理 |
| **手上有个项目,先判断该不该上** | Agent选型与治理 的第一、二节 → Agent架构 → 按缺什么回头补机制四篇 → Agent框架 |
| **只准备 Agent 岗面试,时间紧** | Agent架构 → Agent选型与治理 → 记忆与上下文 → 多智能体 → 工具调用 → 规划模式 → 有余力再读 Agent框架 |
| **系统已经上线,要治理与排障** | Agent选型与治理 的第四、五节 → 工具调用 → 多智能体 → 记忆与上下文 |

三条依据,省得你自己再推一遍:

- **Agent架构 排在最前,是因为它定义词汇。** 后面六篇一律不重讲零件与闭环,直接用"编排器""证据层""工具网关""自主度"这些说法;跳过它去读机制篇,会一直在猜这些词指的是哪一格。
- **机制四篇的顺序不能打乱着读。** 四篇互相引用的方向是固定的:规划模式讲"要不要再来一步",工具调用讲"这一步怎么落地",记忆与上下文讲"结果放哪、下一轮装什么",多智能体讲"要不要拆开"。前一篇是后一篇的前提,倒着读会一路撞上转交到别篇的引用。
- **Agent选型与治理 排在最后,是因为它整篇都建立在前面之上。** 它讲权限、监控、止损线时,一律把机制引到专篇("工具层那一层已经写完了,本节不重复");先读它只能拿到结论,拿不到依据。唯一的例外是第二条路径——带着项目来做"上不上"这个决定时,它的第一、二节本来就是入口。

## 三、真题速查:29 道题落在哪几篇

题库 `questions/Agent/` 是真题的唯一集合,`topic` 第一段就是文章名,所以对应关系是一一对上的:

| topic 第一段 | 题数 | 这一组主要在问什么 |
|---|---|---|
| Agent选型与治理 | 6 | 应用技术选型、价值边界与趋势、安全与权限、可观测性、通用与垂直 Agent、高风险决策 |
| 记忆与上下文 | 5 | 分层记忆、向量记忆检索、会话状态管理、对话系统怎么建模时间、上下文预算与降噪 |
| 多智能体 | 5 | 协同机制、冲突检测与仲裁、子 Agent 分工与任务分发、全局状态合并、任务分解与协作 |
| Agent架构 | 5 | 核心组件与闭环、架构谱系与 Workflow 选型、Skill-Memory-Harness、多模型选型、意图澄清 |
| 工具调用 | 4 | Function Calling 与工程集成、工具学习范式、工具选择与路由、容错与重试 |
| 规划模式 | 2 | ReAct、CoT/ToT/GoT |
| Agent框架 | 1 | 开发框架选型 |
| 检索优化 | 1 | RAG 与 Agent 集成的延迟与正确率——**这道落在隔壁 01-RAG 子领域**,不在本子领域 |

读这张表有两件事要说明:

- **题数少不等于内容少。** 规划模式只挂着 2 道题,但这 2 道题的追问横跨 ReAct、Plan-and-Execute、搜索结构与死循环护栏,展开之后是本子领域最长的一篇;Agent框架 反过来,1 道题基本就是它的全部。所以按题数决定读多深会走偏,按第二节的路径读。
- **具体某道题的答案在哪一节,本页不管。** 每篇文末各有自己的「面试考点串联」表,把该篇的真题问法逐条映射到小节,不必回到这里查。

## 四、边界:同一个问法,该敲哪一篇的门

七篇之间划了很多刀,下面这些是最容易走错门的。**每一条都只给门牌号,理由在对应篇里**。

| 你想问的 | 该敲哪一篇 |
|---|---|
| ReAct 循环停不下来怎么办 | 规划模式(四道闸与死循环的三种形状)。Agent架构 只回答"终止判定该不该交给模型" |
| 工具报错了,该重试、换工具还是直接失败 | 工具调用(错误分类与退避)。规划模式 只管"这一步失败要不要改整个方向" |
| Function Calling 和 ReAct 是什么关系 | 两篇给的是同一个答案——正交:协议那一半在 工具调用,循环那一半在 规划模式 |
| 历史太长、工具返回太大,砍哪一段 | 记忆与上下文(预算分档与裁剪顺序) |
| 反思、记忆写回、持续学习差在哪 | Agent架构(三者改的东西与回滚代价的对照)。反思本身为什么常常没用,在 规划模式 |
| 多 Agent 到底值不值 | 多智能体 负责算账(五笔开销、加速比与通信占比),Agent选型与治理 负责给上线前的止损线 |
| 提示注入怎么防 | 工具调用 管三处不可信输入与四条防线;它上面一层的身份、租户、权限与出口管控在 Agent选型与治理 |
| 长期记忆和 RAG 是不是一回事 | Agent架构 给定位(同属证据层的两种来源,但必须分命名空间),记忆场景的召回在 记忆与上下文,文档库那一侧整条链路在 01-RAG |
| Agent 怎么评 | 分三处:Agent架构 讲 Skill/Memory/Harness 的分层验收,Agent选型与治理 讲端到端口径与分层监控,多智能体 讲协作特有的那几个指标 |
| 一个 Agent 里要不要用不止一个模型 | Agent架构(主模型、Memory 模型、多模态模型三类,选型标准完全不同) |
| 端到端指标掉了,按什么顺序往下查 | Agent架构 给按模型类别的四步定位;线上分层监控与 span 级排障在 Agent选型与治理 |
| 该用现成框架还是自己写一个循环 | Agent框架(决策表的第四行) |

## 五、本子领域之外

| 你要找的 | 去哪 |
|---|---|
| 切块、索引、检索、重排、RAG 评测**这整条链路** | 本子领域隔壁的 **01-RAG**(Agent 里的检索只是挂在证据层的一个只读工具) |
| 约束解码怎么保证结构化输出合法、为什么要关掉重复惩罚 | 04-Infra 的 解码策略 篇(工具调用 篇只讲工程层的 schema 与校验) |
| "下一步做什么"是人写死的编排,还是让模型**学**出来的策略 | 03-强化学习章的 AgenticRL 篇——**这里讲系统怎么搭,那里讲怎么训**,是两条轴 |
| TTFT、TPOT、吞吐这些延迟指标怎么定义 | 04-Infra 的 推理服务指标 篇 |
| 长上下文本身怎么训、中间迷失是怎么回事 | 02-预训练与微调 的 长上下文训练 篇 |
| SFT、LoRA、蒸馏这些训练手段本身 | **02-预训练与微调** 章;Agent选型与治理 只讲"该微调还是该检索"这个选择 |
| 系统提示词怎么系统地写和迭代、注入为什么防不住 | 见 Prompt优化 篇(工具调用 篇管三处不可信输入的工程闸,那篇管提示词本身的设计与评估闭环) |
| LangChain、LlamaIndex 某一家的源码实现细节 | **开源解读模块**(`opensource/`);Agent框架 篇只到架构与选型为止 |

两块本子领域会用到、但知识库里**还没有文章**的内容,先在这里挂个号,免得你去搜:

| 你要找的 | 现状 |
|---|---|
| 思维链本身是怎么回事 | `思维链` 是**计划文章,尚未撰写**。眼下 CoT 与 ToT、GoT、Self-Consistency 的取舍在 规划模式 里有一节 |
| 幻觉的成因、检测与缓解 | `幻觉与事实性` 是**计划文章,尚未撰写**。多步链路里怎么不让错误累积,先看 Agent选型与治理 的第二节 |
