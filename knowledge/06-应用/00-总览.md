# 应用 · 总览

一句话:这是本章 **18 篇的导航页**——只回答"我该进哪个子领域、读哪篇、我这个问题该敲哪扇门",**不讲任何机制**。本章讲的是**拿一个已经训好的模型搭出一套能用的系统**;模型本身怎么训、怎么跑得快,一概不在这里,去处见第六节。

本页是 hub,不参与题目 `topic` 匹配,也不挂复习优先级角标——重点标记和考点表都在各篇自己文末。

## 一、本章的形状:两个子领域,加一层公共的提示词

| 块 | 篇数 | 它回答的是哪一类问题 | 入口 |
|---|---|---|---|
| **01-RAG** | 7 篇(1 篇导航 + 6 篇专篇) | 怎么把**正确的证据**找出来、组织好、交到模型面前 | 该子领域的 `00-总览` |
| **02-Agent** | 8 篇(1 篇导航 + 7 篇专篇) | 怎么**决定下一步做什么**,并且真的把它执行掉 | 该子领域的 `00-总览` |
| **章根目录三篇** | Prompt优化 · 思维链 · 幻觉与事实性 | 三件**两侧共用**的事:那段文本本身怎么写与迭代、推理轨迹拿来训练有什么用、以及答案没依据时怎么定义检测缓解 | 直接读 |

**两个子领域的导航页已经把内部写得很细了**——哪篇讲什么、按什么顺序读、哪个问法该敲哪一篇的门,全在那里,**本页一律不重复**。本页只做三件事:把你**送进正确的那个子领域**(第二节)、讲清两者的**交界**(第三节)、划清**本章和别的章**的界(第六节)。

### Prompt优化 为什么摆在章根目录,不进任何子领域

因为提示词是**两个子领域共用的同一层**:RAG 的生成侧 prompt、Agent 的系统提示词与工具说明,写的是同一种东西,踩的也是同一批坑。那一篇讲的是这段文本的工程流水线——人工基线里哪几块必须写、Few-shot 怎么选样和排序、上下文塞不下时按什么顺序删 / 检索 / 压、自动优化的三条路线、评估要几个互相隔离的数据集、模型升级后怎么证明没有回归,以及为什么系统提示词只是一种倾向而不是隔离。

一条边界记住就够:**它改的始终是那段文本,不是权重**。改可训练向量的那一路是 02 章的 提示微调 篇,两篇互为对照,不重写。

## 二、先分诊:我这个问题是 RAG 问题还是 Agent 问题

**一句话判据:难点是「找不到」,还是「做不完」。**

- 证据一次就能取齐,剩下的只是把它组织好、答出来 → **RAG 问题**
- 取什么、取几次、取完还要做什么,得看上一步的结果才知道 → **Agent 问题**

嫌这条太抽象,就用下面四条更好落地的分辨线。任意两条指向同一侧,基本就不会走错门:

| 你问自己 | 偏 RAG | 偏 Agent |
|---|---|---|
| **步数事先知道吗** | 知道:检索一次、生成一次,链路是固定的 | 不知道:模型边走边定,所以才需要终止条件 |
| **系统能不能改变外部世界** | 不能,全程只读 | 能:要写、要调用、要花钱,所以才需要权限与审批 |
| **失败长什么样** | 答错或编了:证据没捞上来,或捞上来没用好 | 流程崩了:停不下来、工具报错没兜住、状态传丢了 |
| **你手上的旋钮是什么** | 切块、索引、召回、重排、阈值 | 规划、工具、记忆、摆几个 Agent |

两处最常见的走错门:

- **"答得不准"默认先当 RAG 问题查。** 端到端答错时,错在证据层的比例远高于错在流程层;但如果链路本来就是多步的,先确认不是某一步的状态没传下去——按模型类别往下定位的顺序在 Agent架构 篇。
- **"接口调不通、参数填错了、超时了"从来不是 RAG 问题**,直接去 工具调用 篇,别在检索链路里翻。

## 三、交界:两者是包含关系,不是二选一

面试里"你觉得该用 RAG 还是用 Agent"是个错位的问法——它们不在同一层。**两个方向分开记**:

| 方向 | 事实 | 所以链路归谁 |
|---|---|---|
| **Agent 里的 RAG** | 检索在 Agent 里就是挂在**证据层上的一个只读工具**:要不要查、查什么、查几次由模型决定 | 这个工具背后的整条链路(切块、索引、召回、重排、评测)**仍然归 01-RAG**,Agent 侧只留一句话引用 |
| **RAG 里的 Agent** | 一条"检索一次、生成一次"的固定链路,做到需要多跳、需要按中间结果改写 query 时,就**长出了 Agent 的形状**:循环、终止条件、逐轮累积的延迟账跟着全来了 | 多轮检索的延迟与正确率那一节**留在 检索优化 篇里算**,不搬进 Agent 子领域 |

一句话记法:**检索是一个动作,Agent 是一圈循环。** 一个动作不需要循环的时候,别去付循环那笔钱——多出来的延迟、token 和不确定性都是实打实的。

四处最容易在交界上找错门的:

| 你想问的 | 敲哪扇门 |
|---|---|
| 长期记忆和 RAG 是不是一回事 | **02-Agent**:定位与命名空间在 Agent架构 篇,记忆场景的召回与治理在 记忆与上下文 篇;文档库那条链路仍在 01-RAG |
| 多跳、多轮检索的延迟与正确率怎么算 | **01-RAG**:检索优化 篇的最后一节(那道真题的文件收在 `questions/Agent/`,但按 topic 归这里) |
| 证据到了模型面前怎么摆、引用怎么留 | **01-RAG**:RAG系统设计 篇;而这段文本本身怎么迭代、怎么证明它变好了,才是 Prompt优化 篇 |
| 这件事该上 RAG 还是上 Agent,要不要干脆去微调 | **02-Agent**:Agent选型与治理 篇把提示、ICL、微调、RAG、Agent 五条路放在一起比,并给止损线 |

## 四、三条读法:按你的目标挑一条

| 你的目标 | 建议路径 |
|---|---|
| **第一次系统学应用层** | 01-RAG 整套(照它导航页的第一条路径)→ Prompt优化 → 02-Agent 整套(同样照它的第一条路径) |
| **只准备其中一个岗** | 直接进对应子领域的导航页,照它第二节里"时间紧"那条路径走;**Prompt优化 两边都要读**,它的考点在两类面试里都出现 |
| **手上有系统要落地或排障** | 先用第二节分诊,再进对应子领域;横跨两侧的系统按"先证据、后流程"的顺序查 |

两条依据,省得你自己再推一遍:

- **先 RAG 后 Agent,不是因为 RAG 更简单。** 是因为 Agent 那一侧默认你已经知道检索是怎么回事:Agent架构 篇讲证据层时,直接把整条检索链路当成一个已知的只读工具带过。反过来读,会在那一节卡住。
- **Prompt优化 夹在中间读最省力。** 读完 RAG 才知道生成侧 prompt 要约束什么(引用、拒答、证据冲突怎么办),带着这些问题再读它;读完它再进 Agent,系统提示词与工具说明那一层就不用从头讲了。

## 五、真题速查:53 道题,分散在三个目录里

本章的真题**不在同一个目录下**,这是本章最容易漏题的地方:

| 题库目录 | 题数 | 归属 |
|---|---|---|
| `questions/RAG/` | 22 | 01-RAG,外加 1 道 topic 为 `幻觉与事实性` 的**归章根目录**;其中 2 道的 topic 指向尚未建文件的计划文章 |
| `questions/Agent/` | 29 | 02-Agent;其中 1 道 topic 为 `检索优化`,**实际归 01-RAG** |
| `questions/SFT/` | 2 | topic 为 `Prompt优化` 与 `思维链`,都归章根目录 |

三条读表须知:

- **按 topic 找题,别按目录名找。** `topic` 第一段就是文章名,目录只是收纳位置;上表那两处错位都由此而来。
- **分篇的题数表在两个子领域各自的导航页里**,具体某道题落到哪一节则在各专篇文末的考点表,本页两者都不重复。
- **计划文章对应的那几道题目前只在题库里**,读完现有文章不代表这几道也答得上;它们的登记见 `docs/04-知识库地图.md`。
