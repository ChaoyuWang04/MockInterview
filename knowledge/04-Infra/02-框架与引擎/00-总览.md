# Infra 框架与引擎 · 总览

一句话:这是本章 **12 篇的导航页**——只回答"我该读哪篇、读它之前该先懂哪篇原理",**不讲任何原理**。本章的分工是**只讲工程与用法**:机制原理一律在 `01-原理` 章(那 30 篇已全部成文),算法在 `03-强化学习` 章,源码细节在开源解读模块。

> **本章所有文章都有时效**。它们对照的是 `projects/` 下的源码快照(约 2026-04)与当时的官方文档,各篇文末与正文都标了口径。框架演进极快,**任何"我记得它是这样"的说法,上线前都该拿自己那个版本核一遍**;第六节列了最容易过时的几处。

## 一、按用途分四组

每组表格的第三列是"先读哪篇原理":本章文章默认你已经懂了那几篇讲的机制,读框架篇时遇到一句话带过的名词,就是去那里补。

### 推理引擎(3 篇)

| 篇 | 它回答什么 | 先读哪篇原理 |
|---|---|---|
| **vLLM** | 一个请求从进来到吐完 token 经历了什么;架构分层、调度器、前缀缓存、CUDA Graph 怎么配 | KVCache · PagedAttention · 连续批处理 · CudaGraph |
| SGLang | 前端语言 + 后端运行时的双重身份;RadixAttention 在引擎里怎么落地、结构化输出怎么做 | RadixAttention · 解码策略(约束解码那一节) |
| 推理引擎对比 | **选型篇**:主流引擎哪些已经趋同、真正的分野在哪几条线上、给定负载该选谁 | 量化 · 推理加速 |

### 训练框架(3 篇)

| 篇 | 它回答什么 | 先读哪篇原理 |
|---|---|---|
| Megatron | Megatron-LM 与 Megatron-Core 的分别;并行度怎么配与那些约束;checkpoint 换并行度的坑 | 并行策略 · ZeRO(DistributedOptimizer 对应的那一档) |
| DeepSpeed | 非侵入式接入;一份 JSON 配置管什么;配置与代码谁优先 | ZeRO · 显存管理与OOM |
| FSDP | PyTorch 原生分片;FSDP1/FSDP2 的分片表示差异;wrap 粒度怎么定 | ZeRO · 并行策略(mesh 那一节) |

### RL 训练框架(5 篇)

先读 **RL框架对比** 建立全局,再按需读单篇:

| 篇 | 它回答什么 | 先读哪篇原理 |
|---|---|---|
| RL框架对比 | **选型篇**:所有 RL 框架都要解决的同一组难题、各家的不同选择、场景决策表 | `03-强化学习` 章的 PPO 与 GRPO(算法本身) |
| verl | 编排型框架:训练与推理引擎一个都不造,造的是把两者接到同一条数据流上的胶水 | 并行策略(两侧分片规则为什么对不上)· 连续批处理 |
| slime | 反抽象路线:只绑 Megatron + SGLang,参数直接透传给上游 | 并行策略(透传的那些并行度各切什么) |
| ROLL | 角色化资源编排:每类活做成一个能单独分卡的角色,用一份资源清单摆到集群 | 并行策略(五维并行的含义) |
| OpenRLHF | 把 RLHF 三阶段打包成开箱即用、可复现的实现;Ray 做角色放置 | ZeRO(它的训练后端只有 ZeRO 一档) |

## 二、RL 框架四家各绑了谁

四篇 RL 框架单篇都建立在本章别的篇目之上:每一家都不自己写训练引擎与生成引擎,只写编排层。**读某一家之前,先把它绑的那两篇读了**,否则单篇里"权重同步""显存腾挪"那些段落没有着力点。

| 框架 | 训练后端(读哪篇) | 生成后端(读哪篇) | 资源编排 |
|---|---|---|---|
| verl | FSDP / FSDP2 / Megatron,另挂多种(FSDP 篇 · Megatron 篇) | vLLM / SGLang / HF 原生 generate(vLLM 篇 · SGLang 篇) | Ray |
| slime | **只有** Megatron(Megatron 篇) | **只有** SGLang,server 模式(SGLang 篇) | Ray |
| ROLL | Megatron-Core 或 FSDP2(Megatron 篇 · FSDP 篇) | vLLM / SGLang(vLLM 篇 · SGLang 篇) | Ray |
| OpenRLHF | **只有** DeepSpeed ZeRO(DeepSpeed 篇) | vLLM(vLLM 篇) | Ray |

四家都用 Ray 做角色放置,但 Ray 在这里**不是**分布式训练框架——切模型的活是训练后端干的;这条分工每篇都会再说一遍,别把它记成"Ray 训模型"。

## 三、三条读法

| 你的目标 | 建议路径 |
|---|---|
| **准备推理岗面试** | vLLM → SGLang → 推理引擎对比(机制原理先读完 `01-原理` 章的推理机制那一组) |
| **准备训练/分布式岗** | Megatron → FSDP → DeepSpeed → NCCL(原理先读 并行策略 与 ZeRO) |

## 五、本章与别处的边界

这一章最容易和别处写重,分工写死如下:

| 你想找的 | 去哪 | 本章的做法 |
|---|---|---|
| 分页、连续批处理、CUDA Graph、KV 量化、投机解码的**机制** | `01-原理` 各专篇 | 一句话引用,不展开 |
| DP/TP/PP/EP/SP/CP、ZeRO、集合通信算子的**原理** | `01-原理/并行策略`、`ZeRO`、`集合通信` | 一句话引用,不展开 |
| 优化手段的**上手顺序与互相影响** | `01-原理/推理加速`(串讲篇) | 不重复编排层内容 |
| PPO / GRPO / DPO 等**算法** | `03-强化学习` 章 | 一句话引用 |
| 某个项目的**源码实现细节** | 开源解读模块(`opensource/`) | 写「具体实现见开源解读模块」 |

反过来,**个体篇不做横向对比,对比篇不讲某一家的内部架构**——这两条是本章内部最容易越界的地方。

## 六、最容易过时的四处

本章里这几段是按写作时的快照写的,引用前先对自己手上的版本核一遍:

| 哪一段 | 在哪 | 为什么容易过时 |
|---|---|---|
| FSDP1 已弃用、FSDP2 的 API 形态 | FSDP 篇第二节 | 按 PyTorch 开发版核实,正式版会继续改 |

## 七、真题速查

题库是全部真题的唯一集合。当前 `topic` 首段直接挂在本章篇目上的真题有五道:

| 题(按题库 topic) | 落在哪 |
|---|---|
| vLLM 的核心加速机制,怎么联合 PagedAttention、连续批处理、CUDA 执行优化与配置调优提高吞吐、控制 TTFT/TPOT | **vLLM 篇**第五、六节;单项机制归 `01-原理` 各专篇 |
| DeepSpeed 提供哪些关键能力,怎么选 ZeRO、卸载和并行组合,训练变慢或通信超时怎么排查 | **DeepSpeed 篇**第三、六节 |
| FSDP 与 DeepSpeed 在架构、显存、通信、卸载、并行组合上怎么比,什么时候优先 FSDP,wrap/prefetch/offload 怎么调 | **FSDP 篇**第三、四节 + DeepSpeed 篇第五节 |
| FSDP 的参数、梯度、优化器状态怎么分片,一次前向、反向、optimizer step 里 AllGather / ReduceScatter / reshard / 预取各发生在哪 | **FSDP 篇**第三、四节(分片原理归 ZeRO 篇) |
| verl 同步 PPO/GRPO 里 prompt batch、`rollout.n`、mini-batch、每卡 micro-batch 与 PPO epoch 怎么换算 | **verl 篇**第六节 |

另有一道「从一个请求过来,到最后吐出 token,在 vLLM 或者 SGLang 里经历了哪些流程」,它的 topic 挂在 `01-原理` 的 连续批处理 篇;本章 vLLM 篇第三节讲的是同一条链路在 vLLM 里的落地,SGLang 篇只讲它不同的那几步,不重复骨架。

其余框架类考点由作者补充,在考点表中统一称为**补充题**。
