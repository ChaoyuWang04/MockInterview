# 解码策略全景

一句话:模型每一步前向只产出**一个词表上的概率分布**,「怎么从这个分布里挑出下一个 token」独立于模型权重,却直接决定生成文本的质量、多样性与风格——同一个模型,换一套解码策略,可以从复读机变成诗人。类比:模型是只负责报出「每个候选词可能性」的参谋,解码策略才是那个拍板的人。

## 一、确定性方法:每次都走同一条路

### 贪心搜索(Greedy)

每步取当前分布的众数:

$$
w_t = \arg\max_{w} P(w \mid w_{<t})
$$

最快、完全可复现,但只顾眼前一步,像下山永远只迈脚下最陡的一步,容易走进局部死胡同。最典型的死胡同是**重复退化**:模型一旦生成过某个短语,该短语再次出现的概率会被上下文抬高,重复又进一步抬高概率——一个自我强化循环,越读越顺嘴,最终输出「我不知道我不知道我不知道……」式的死循环文本。

### 束搜索(Beam Search)

不再只押一条路,而是同时维护 $k$ 条累积对数概率最高的前缀序列,每步把每条前缀各自展开、再全局保留得分最高的 $k$ 条:

$$
\text{score}(w_{1:t}) = \sum_{i=1}^{t} \log P(w_i \mid w_{<i})
$$

在「存在近似标准答案」的封闭任务(机器翻译、摘要、语音识别)里,它确实比贪心更接近全局最优;代价是每步并行推进 $k$ 条序列,算力与显存约为贪心的 $k$ 倍。

但在开放式生成里,beam search 暴露了一个更根本的问题:**高概率 ≠ 好文本**。文本退化论文做过一个著名对比——把人类真实文本逐 token 在模型下的概率画成曲线,它高低起伏,人类经常「说出模型觉得不太可能的词」;而 beam search 输出的概率曲线平滑地贴着高位走。一味追求最大似然,得到的是保守、模板化、兜圈子的文本:最像模型的文本,并不是最像人的文本。这也是随机方法存在的根本理由。

## 二、随机方法:掷骰子,但要把骰子修好

纯随机采样(严格按原分布抽)会踩到长尾:词表几万个 token,尾部每个的概率单看都很低,加起来的总质量却不小,总有几步会抽中不合逻辑的词,一步跑偏、步步跑偏。所以随机方法的全部技术含量在于:**怎么修剪这只骰子**。

### 温度缩放(Temperature)

softmax 前把 logits 除以 $T$:

$$
P(w_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}
$$

这正是统计物理里的玻尔兹曼分布,$T$ 的物理感也完全一致:低温时概率质量向最低能态(最高 logit)凝聚,高温时向全词表弥散。

- $T \to 0$:退化为贪心(argmax);
- $T = 1$:保持模型原分布;
- $T \to \infty$:趋向词表上的均匀分布,输出接近乱码。

注意温度只改变分布的尖锐程度,**不改变 token 之间的相对排序**;它通常与下面的截断方法叠加使用。

### Top-k:固定名额

只保留概率最高的 $k$ 个 token,重新归一化后采样。缺陷在于 $k$ 是死的,而分布形状每一步都在剧烈变化:开放语境(一段故事的开头)里几百个词都说得通,$k=50$ 会错杀大量好候选;强约束语境(「Barack」后面几乎必然是「Obama」)里真正合理的只有一两个,$k=50$ 又强行留下几十个坏候选。像一场招聘不看来了什么人,一律录取前 50 名。

### Top-p / Nucleus:自适应的最小核

改为按概率从高到低累加,取累积质量刚达到 $p$ 的最小集合:

$$
V_p = \min \Big\{ V' \subseteq V \;:\; \sum_{w \in V'} P(w) \ge p \Big\}
$$

候选集大小随分布形状自适应伸缩:尖锐时「核」里可能只剩一两个词,平坦时可容纳几百个。它与上文的退化分析出自同一篇论文,此后多年是事实上的默认策略。

弱点在高温:温度把长尾抬起来之后,凑满固定的累积质量 $p$ 就必须纳入大量低质 token,top-p 在 $T > 1$ 时明显失稳。

### Min-p:以榜首为锚的动态门槛

设当前分布的最高概率为 $p_{\max}$,只保留满足

$$
P(w) \ge p_{\text{min}} \cdot p_{\max}
$$

的 token($p_{\text{min}}$ 常取 0.05–0.1,即「至少得有榜首 5%–10% 的人气才配上场」)。门槛跟着模型的信心走:模型笃定时 $p_{\max}$ 高、门槛水涨船高,候选自动收紧;模型犹豫时门槛随之放低,候选自然放宽。由于门槛是相对比例而非绝对累积质量,高温摊平分布时它的候选集扩张得远比 top-p 克制——min-p 论文(ICLR 2025)在温度拉到 2–3 的区间仍能同时保住创造性与连贯性,已被开源社区广泛采纳,是截断家族里最新的主流选项。

三者对比记忆:top-k 固定名额,top-p 凑满选票,min-p 锚定榜首的相对门槛。

### Typical Sampling

按「token 的信息量是否接近整个分布的熵」筛选候选,理论出发点是人类语言的均匀信息密度假说;思想优雅,实践中远不如上面几位常用,一句带过。

## 三、组合、顺序与惩罚项

### 参数叠加的顺序

真实推理栈里这些参数串成流水线。HF transformers 的顺序是:重复惩罚 → 温度 → top-k → top-p / min-p 截断 → 采样。顺序是有语义的:先升温再截断,top-p 要在被摊平的分布上凑累积质量,候选集显著变大;先截断再升温,则高温只在安全集合内部摊平。不同框架的默认顺序并不一致且往往可配置(llama.cpp 甚至默认把温度放在整条截断链之后),**跨框架迁移同一组采样参数时必须核对采样链**——这是「参数相同、效果不同」的常见来源。

### 重复惩罚家族

**Repetition penalty**(乘除式):对已出现过的 token 的 logit,正数除以 $\theta$、负数乘以 $\theta$($\theta > 1$),整体往下压:

$$
z_i' = \begin{cases} z_i / \theta, & z_i > 0 \\ z_i \cdot \theta, & z_i \le 0 \end{cases} \qquad i \in \text{已生成集合}
$$

**Presence / frequency penalty**(加减式,OpenAI API 风格):直接在 logit 上做减法,presence 对「出现过」一次性扣分,frequency 按出现次数 $c_i$ 线性加罚:

$$
z_i' = z_i - \alpha_{\text{presence}} \cdot \mathbb{1}[c_i > 0] - \alpha_{\text{freq}} \cdot c_i
$$

副作用必须记住:惩罚是无差别的,分不清「病态复读」与「正常复用」。代码里反复出现的变量名与关键字、JSON 里重复的键名、必要的专有名词、中文里的「的/是」这类高频功能词都会被一起压——惩罚开大后的典型症状是变量名越写越歪、格式逐渐崩坏。所以代码与结构化输出场景一般关掉或调到极小,宁可靠低温防重复。

## 四、进阶解码:改目标,而不只是修剪分布

### Contrastive Decoding(对比解码)

同时跑一大一小两个模型(expert 与 amateur),对候选 token 用两者的对数概率之差打分,在 expert 的高概率候选内选差值最大者。直觉:重复、空话、跑题这类退化模式,小模型犯得比大模型更凶;两者相减,等于把「小模型也会」的通用毛病减掉,放大「大模型懂而小模型不懂」的那部分信号。零训练成本,开放式生成质量显著超过 nucleus sampling;代价是推理时要同时养两个模型。顺带一提,它限定候选范围的 plausibility 约束($p \ge \alpha \cdot p_{\max}$)与后来 min-p 的门槛形式完全同款。

### 约束解码(Structured / Constrained Decoding)

当输出必须严格符合 JSON schema、正则或语法时:把约束编译成有限状态机(FSM),每步只放行「当前状态下合法」的 token,其余 logit 置 $-\infty$ 后再采样,格式合法率 100%,额外开销极小。工程实现(压缩 FSM、跳跃解码)见 rollout引擎篇的 SGLang 部分。

### 投机解码(Speculative Decoding)

小模型快速起草若干 token,大模型一次前向并行验证,配合拒绝采样保证输出分布**与大模型逐 token 采样严格一致**——它不改分布、只提速度,严格说是推理加速技术而非采样策略,展开见推理加速篇。放在这里是为了面试中的一个关键辨析:温度、截断、惩罚都在改分布,投机解码不改。

## 五、场景配方表

| 场景 | 推荐配置 | 为什么 |
| --- | --- | --- |
| 代码 / 数学 / 事实问答 | $T$ 0–0.3 或 greedy,关重复惩罚 | 错一个 token 就全盘错,要确定性 |
| RL rollout(反例!) | $T \approx 1.0$、top-p 0.95–1.0 | 组内多样性就是优势信号来源,低温同质化等于自制零梯度组,见 GRPO 篇 |
| 创意写作 / 闲聊 | top-p 0.9 + $T$ 0.7–0.9;想更放开可用 min-p 0.05–0.1 配更高温 | 在多样性与连贯之间找平衡 |
| Agent / 工具调用 | 低温 + 约束解码 | 参数错一个字调用就失败,格式必须有硬保证 |
| 评测 / 复现实验 | greedy 或固定随机种子 | 可复现;注意并行推理的浮点非结合性仍可能带来微小抖动 |

## 六、与训练的联动

- **RLHF 之后分布变尖**:对齐训练把概率质量压向少数「高分回答」,模型校准变差(预训练模型的 token 概率与真实频率大致对齐,RLHF 后不再,GPT-4 技术报告展示过这条校准曲线的塌陷)。后果:同样的 $T=1$,对齐后的模型表现得像预训练模型的低温档,所以 chat 模型的默认温度普遍设在 0.6–0.9 而非 1.0。
- **推理模型的默认温度有讲究**:长思考链对重复退化极其敏感,greedy 一旦在链条中段进入循环就出不来,所以官方推荐往往不是 0(如 DeepSeek-R1 官方建议 $T$ 0.5–0.7 配 top-p 0.95,并明确提醒不要用贪心)。

## 七、一步解码的完整流水线

```mermaid
flowchart LR
    A[模型前向: 词表 logits] --> B[惩罚项修正]
    B --> C[温度缩放 z/T]
    C --> D[截断: top-k / top-p / min-p 或 FSM 掩码]
    D --> E[softmax 重新归一化]
    E --> F[按分布随机抽样]
    F --> G[新 token 拼回上下文]
    G --> A
```

每生成一个 token 走一遍全流程;截断与采样各步的开销相对模型前向都可忽略,因此采样与贪心是同一量级、共享同一条 KV cache 路径,只有 beam search 因并行维护 $k$ 条序列(连带 $k$ 份 KV cache)才有成倍开销。

## 八、面试考点串联

对齐题库「解码策略/综述」一题的高频追问:

1. $T \to 0$ / $T \to \infty$ 各退化成什么 → 贪心 / 词表均匀分布(乱码)——「温度缩放」
2. beam search 为何在开放式生成里不自然 → 人类文本并不总走高概率路径,最大似然给出保守模板文 →「束搜索」
3. top-k vs top-p vs min-p 一句话 → 固定名额 / 凑满累积质量 / 锚定榜首的相对门槛;高温稳定性 min-p > top-p > top-k →「随机方法」
4. 重复惩罚的副作用 → 无差别惩罚会伤代码变量名等正常复用 →「惩罚项」
5. 哪些方法改分布、哪些不改 → 温度/截断/惩罚都改分布;投机解码严格不改 →「进阶解码」
6. 采样对推理效率的影响 → 与贪心同量级、共享 KV cache;beam 才有 $k$ 倍开销 →「流水线」
