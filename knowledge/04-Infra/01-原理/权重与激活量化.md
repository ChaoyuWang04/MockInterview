# 权重与激活量化

> 🔴 重点考点:本篇直接对应真实面经高频问法,文末「面试考点串联」给出问法对照。

一句话:量化的公式谁都会写,真正的难题只有一个——**激活里有一小撮通道的数值大得离谱,而它们恰好长在矩阵乘唯一不能细分 scale 的那一维上**。本篇讲的这一串经典算法,全部是在回答同一个问题:拿这撮离群值怎么办。(scale/zero-point、对称与非对称、粒度定义、PTQ 与 QAT、W4A16 与 W8A8 这两个记号本身,见 量化 篇,本篇默认读者已经看过,不重讲。)

## 一、拦路虎:激活离群值

### 现象:固定的几个通道,幅度高出两个数量级

Transformer 训到一定规模后,激活矩阵里会稳定出现**少数几个幅度极大的通道**(outlier channels)。SmoothQuant 的测量是这些离群值比大多数激活值大约 **100 倍**,LLM.int8() 在自己的口径下报告的是**最高 20 倍**。类比:一个班平均身高 1.7 米,混进几个 3 米的巨人——尺码表要罩住巨人,普通人就全挤进一两个档里,分辨率全浪费在没人的区间。

> 🖼️ 占位:激活矩阵热力图,横轴 hidden 通道、纵轴 token,大部分区域数值平缓,少数几列呈刺眼的亮色竖条纹

有三个性质是后面所有算法能成立的前提:

- **极其稀疏**。LLM.int8() 在 6.7B 尺度上测到:每条序列约有 15 万个离群值,但它们只集中在整个 transformer 的 **6 个特征维度**上,约占全部维度的 0.1%。
- **沿通道固定、沿 token 稳定**。SmoothQuant 的原话是:同一个 token 内跨通道的方差很大,而同一个通道跨 token 的方差很小——一旦某个通道出现离群值,它在所有 token 上都会出现。**离群是通道的属性,不是 token 的属性**,所以可以离线一次性处理掉。
- **不是噪声,是功能部件**。LLM.int8() 把那几个离群维度置零,top-1 softmax 概率质量掉 20% 以上、困惑度恶化 600–1000%;随机去掉同样数量的普通维度只掉 0.1%。所以不能简单裁掉。

### 成因:两条线索,尚无统一定论

老实说学界还没有一个被公认的单一解释,目前有两条互补的线索:

1. **注意力想做「什么都不干」**。有些 head 学到的行为是"这一层对这个 token 不做更新",要让 softmax 输出逼近精确的 0,就得把 softmax 的输入越推越大;训练中这个推力持续放大,溢出到网络别处就成了离群值。对应论文用 clipped softmax 与 gated attention 两个改动在预训练期抑制它,改完后 BERT/OPT/ViT 能直接做全 INT8 激活量化。
2. **massive activations**。少数**固定的**特征维度上出现极端大值(可达其他值的 $10^5$ 倍),数值几乎与输入无关、像一个常数偏置,且集中在句首 token 与分隔符 token 上,并导致注意力概率往这些 token 上聚集(与 attention sink 相关)。要注意:该论文明确指出 massive activations 与 LLM.int8() 说的 outlier features **不是同一个现象**,两者不要混为一谈。

### 为什么规模越大越明显

LLM.int8() 做过一个相变(phase shift)分析:模型从 6B 涨到 6.7B 的这一小段里,**受离群值影响的层从 65% 跳到 100%,受影响的序列维度从 35% 跳到 75%**,之后离群幅度的中位数快速上升。但同一篇论文有个更值得记住的补充观察:如果横轴换成**困惑度**而不是参数量,这个"突变"就变成了一条平滑的指数曲线——**驱动离群值涌现的更像是模型质量本身,而不是参数量这个数字**。面试里这句话比"越大越明显"值钱得多。

## 二、为什么 per-channel 救不了激活

这一节是全篇的数学起点,也是面试最爱问的一环。记线性层 $Y = XW$,激活 $X$ 的形状是 $T \times C_i$(T 个 token、$C_i$ 个输入通道),权重 $W$ 的形状是 $C_i \times C_o$。

> 记号提醒:这里为了让 $Y = XW$ 写起来顺,把 $W$ 记成 $C_i \times C_o$;量化 篇按 PyTorch 的存储惯例记成 $out \times in$。两者只差一个转置,**「沿输出通道」在两篇里指的是同一维**,别被 shape 的写法绕进去。

展开写,输出的每一个数都要沿着**输入通道维 $c$ 求和**:$Y_{t,o} = \sum_c X_{t,c} W_{c,o}$。而上一节说了,离群值恰恰长在 $c$ 这一维上。

**"求和维上的 scale 提不出点积"这条约束的完整推导见 量化 篇**,这里只取结论、接着往下推:scale 若只依赖 $t$(激活 per-token)或只依赖 $o$(权重 per-output-channel),它与求和下标无关,能整个提到求和号外面——整数矩阵乘照常一口气算完,最后拿"行 scale × 列 scale"的外积把结果一次性缩放回来,这正是 LLM.int8() 说的 vector-wise 量化。

但若 scale 依赖 $c$(激活 per-channel):

$$
Y_{t,o} = \sum_{c} s_c\, \tilde{X}_{t,c}\, W_{c,o}
$$

$s_c$ 卡在求和号**里面**,每一项乘的系数都不一样,提不出来。要做只有两条路:在累加之前对每个乘积单独缩放(整数累加器直接作废,tensor core 用不上),或者把 $C_i$ 拆成很多段分别 GEMM 再拼(退化成一堆小矩阵乘)。SmoothQuant 把这条约束总结成一句话:**缩放只能沿矩阵乘的外侧维度做**(激活的 token 维、权重的输出通道维)。

| 张量 | 这个粒度可行吗 | 原因 |
| --- | --- | --- |
| 激活 per-token | ✅ | token 维是外侧维,scale 能提出求和 |
| 激活 per-channel | ❌ | 通道维是归约维,scale 卡在求和里 |
| 权重 per-output-channel | ✅ | 输出通道维是外侧维 |
| 权重 per-group(沿归约维每 128 个一组) | ✅ weight-only 下天然可行;整数激活下要专门的 kernel | W4A16 本来就要在片上把权重反量化回 fp16 再累加,分组 scale 顺手乘掉;而整数 GEMM 想用分组 scale,就得按组切断累加、分段拼部分和,要 kernel 专门设计(W4A8 这类方案就是这么做的) |

**结论:离群值偏偏长在唯一不能细分 scale 的那一维上。** 这就是激活量化全部困难的来源,也直接导出四条出路——本篇后面几节就是这四条路:

| 出路 | 做法 | 代表算法 | 代价 |
| --- | --- | --- | --- |
| 绕开 | 把离群通道单独拎出来用高精度算 | LLM.int8() | 混合精度 kernel 复杂,常常不加速 |
| 搬走 | 把这一维的动态范围转嫁给权重 | SmoothQuant | 权重变难量化,$\alpha$ 有最优区间 |
| 摊平 | 正交变换把离群值打散到所有通道 | QuaRot / SpinQuant | 部分变换必须在线做,改推理图 |
| 躲开 | 干脆不量化激活,只压权重 | GPTQ / AWQ | 拿不到低位宽 tensor core 的算力翻倍 |

## 三、绕开与搬走:LLM.int8() 与 SmoothQuant

### LLM.int8():把巨人请出去单算

思路最直白:既然离群通道只占约 0.1%,那就**按通道把它们抽出来走 fp16**,其余 99.9% 走 int8 vector-wise 量化(激活按行一个 scale、权重按列一个 scale),两路矩阵乘的结果再加回来。判定标准是个硬阈值:幅度 ≥ 6.0 的特征维度算离群——论文测出来只要按这个阈值分解,困惑度就不再退化。**为什么说它"装得下但不加速"**:论文自己给的数据是,小于 6.7B 的模型上,量化本身的开销会让推理**比 fp16 更慢**;只有到 175B 那种量级的大矩阵乘,才能跑到约 2 倍于 fp16。原因很实在——在线找离群列、把矩阵切成两路、两种数据类型各跑一次 GEMM 再合并,这些访存与 kernel 启动开销吃掉了低位宽省下的时间。**它证明了百亿模型可以 8 bit 近乎无损,解决的是"装得下",不是"跑得快"。**

### SmoothQuant:两人抬担子,一头太沉就往另一头挪

观察:激活难量化(有巨人),权重好量化(分布规整、精度还有富余)。那就做一个**数学等价的难度迁移**:

$$
Y = XW = \left(X\,\mathrm{diag}(s)^{-1}\right)\left(\mathrm{diag}(s)\,W\right) = \hat{X}\hat{W}
$$

意思是:$\mathrm{diag}(s)^{-1}\mathrm{diag}(s) = I$,浮点意义下输出**一个数都不变**;$s$ 只是把每个通道的"量纲"从激活那头挪到权重那头。迁移多少由 $\alpha$ 控制:

$$
s_j = \frac{\max|X_j|^{\alpha}}{\max|W_j|^{\,1-\alpha}}
$$

意思是:$\alpha = 0$ 时完全不迁移,$\alpha = 1$ 时把激活的动态范围整个甩给权重。论文默认 $\alpha = 0.5$;激活更难量化的模型往上调,例如 GLM-130B 用 0.75,LLaMA 系列在 0.6–0.9 之间。**$\alpha$ 太小激活仍然难量化,太大就轮到权重崩——中间那段论文称为 sweet spot,这是必须点破的一条:难度只是搬了家,没有被消灭。**

**scale 怎么做到零开销**:$X$ 通常是前面某个 LayerNorm 或线性层的输出,把 $1/s$ 按输出通道折进那一层的权重与偏置里,离线做完,推理时不多一次 kernel、不多一次读写——这就是"offline migration"这个词的真正含义。校准也很轻:512 条 Pile 随机句子,一次性标定 smoothing factor 与静态量化的步长。收益是权重激活双 int8、整条 GEMM 走 int8 tensor core,论文报到最高 1.56 倍加速、2 倍显存节省。

## 四、躲开:GPTQ 与 AWQ 两条权重侧路线

W4A16 干脆不碰激活。既然离群值只在激活里,不量化激活就没有这个问题——代价是算力不变(仍是 fp16 累加),只赚访存。

### GPTQ:切歪的蛋糕,后面的刀补回来

目标写出来就懂:逐层最小化量化前后的**输出**差,而不是权重本身的差。

$$
\hat{W} = \arg\min_{\hat{W}} \left\lVert WX - \hat{W}X \right\rVert_2^2
$$

意思是:只要这一层的输出对得上,权重自己偏了多少无所谓。这一步把"全局不可解"的问题切成一层一层的小二次问题。

这个二次型的 Hessian 是 $H = 2XX^{\top}$,由校准集的激活统计出来——**它衡量的是每个权重对输出的敏感度**,$[H^{-1}]_{jj}$ 越小说明这一列越敏感。算法一次量化一列,把这一列造成的误差**分摊给右边还没量化的列**:

$$
E_{:,j} = \frac{W_{:,j} - Q_{:,j}}{[H^{-1}]_{jj}}, \qquad W_{:,j:} \leftarrow W_{:,j:} - E_{:,j}\,[H^{-1}]_{j,\,j:}
$$

意思是:先把第 $j$ 列的量化误差除以该列的敏感度归一项,再按 $H^{-1}$ 第 $j$ 行的系数分配给右边所有还没动的列。类比:切蛋糕,每切一刀量一下歪了多少,后面的刀主动调整角度把总误差补回来;Hessian 告诉你哪几刀切歪最伤。

GPTQ 相对前身 OBQ 的**三个工程近似**,是高频追问:

1. **统一列序**:OBQ 每一行按各自的贪心顺序挑下一个权重量化;GPTQ 发现在大矩阵上任意一个固定顺序效果几乎一样,于是所有行共用同一列序,$H^{-1}$ 全行复用,复杂度从 $O(d_{\text{row}}d_{\text{col}}^3)$ 降到 $O(\max\{d_{\text{row}}d_{\text{col}}^2,\ d_{\text{col}}^3\})$。
2. **128 列延迟批更新**:逐列更新整个矩阵是纯访存操作、算术强度极低,GPU 完全喂不饱。改成每次只在 128 列的块内做局部更新,块处理完再对右边一次性批量更新。
3. **Cholesky 稳数值**:反复用高斯消元求 $H^{-1}$ 的各行,在大模型上会累积误差直到 $H$ 失去正定性、算法崩掉。改成一次 Cholesky 分解预先取出所有需要的行,再配 1% 的对角阻尼。

成果:175B 模型约 4 个 GPU 小时量到 3–4 bit,单卡可跑,论文报高端卡上约 3.25 倍加速。校准集是 128 条来自 C4 的 2048-token 片段。

### AWQ:保护干活最多的那 1%

观察:一个权重通道重不重要,**看的不是权重自己多大,而是对应的激活多大**——激活幅度大的通道被频繁重度使用。按激活幅度挑出约 1% 的"显著通道",只把这 1% 留成 fp16,int3 的困惑度就能救回大半。但混合精度存储硬件不友好(kernel 要同时处理两种数据类型),所以 AWQ 改用**等价缩放**来保护:显著通道的权重先乘 $s>1$ 再量化,激活侧除以 $s$ 抵消。

$$
\mathbf{s} = \mathbf{s}_X^{\alpha}, \qquad \alpha^{\star} = \arg\min_{\alpha \in [0,1]} \mathcal{L}\!\left(\mathbf{s}_X^{\alpha}\right)
$$

意思是:$\mathbf{s}_X$ 是各输入通道激活幅度的**平均值**,整个方法只有 $\alpha$ 一个标量超参,在 $[0,1]$ 上网格搜索(论文用 20 个格点),目标是最小化该层量化后的输出重构误差。$\alpha=0$ 退化成不缩放,$\alpha=1$ 完全按激活幅度缩放。为什么乘个 $s$ 就能降误差:量化步长由整组的最大值决定,单独放大一个通道时整组的步长几乎不变,而这个通道在网格里的**相对**分辨率提高了,相对误差近似降到 $1/s$。类比:车间里 1% 的老师傅干了大半产量,防护装备优先配给他们。

**与 GPTQ 的本质差异**(这是必考的对比题):

| | GPTQ | AWQ |
| --- | --- | --- |
| 动不动权重分布 | **动**:误差补偿会改写还没量化的权重值 | **不动**:只做可逆的逐通道缩放,权重的相对结构不变 |
| 用到的统计量 | 二阶($H = 2XX^\top$),要做回归式拟合 | 一阶(各通道激活幅度的均值) |
| 对校准集的依赖 | 强 | 弱 |
| 数据效率 | 需要约 192 条序列 | 16 条即可达到同等困惑度 |
| 换校准分布(PubMed↔Enron) | 困惑度涨 2.3–4.9 | 只涨 0.5–0.6 |

所以 AWQ 在指令模型、多模态模型上泛化更稳。两者并不互斥——工程上常见"先用 AWQ 搜出缩放,再用 RTN 或 GPTQ 落地量化"的组合。

## 五、摊平:旋转与 Hadamard 变换

直觉一句话:**离群值集中在少数固定通道,说明坐标系选得不好。换个坐标系,让每个新通道都是所有旧通道的均匀混合,巨人就被摊薄到全班身上了。**

$$
Y = XW = (XQ)\left(Q^{\top}W\right)
$$

意思是:取正交矩阵 $Q$($QQ^{\top}=I$),浮点下输出完全不变;但 $XQ$ 的每一列都是 $X$ 各列的线性组合,一个孤立的大值被摊成 $C$ 份,单通道峰值按 $1/\sqrt{C}$ 的量级下降。Hadamard 矩阵是这里的理想选择:元素全是 $\pm 1$、混合最均匀,而且有 $O(C\log C)$ 的快速变换。

> 🖼️ 占位:旋转前后的单通道幅度分布对比,左图有几根刺眼的尖峰,右图变成平缓的一片

**QuaRot**:用**随机化 Hadamard 矩阵**($\tilde{H} = H\,\mathrm{diag}(s)$,$s$ 是随机的 $\pm 1$),靠"计算不变性"把全局旋转离线吸收进权重(输入侧权重前乘、输出侧权重后乘),这部分推理时零开销。有两处必须**在线**做:FFN 下投影之前的 Hadamard,以及 attention 里 Q/K 的 head-wise Hadamard(因为 RoPE 让全局旋转穿不过去),用快速 Hadamard kernel 实现。结果是权重、激活、KV cache **全部 4 bit,一个高精度通道都不留**:LLaMA2-70B 上 WikiText-2 困惑度最多涨 0.47、保住 99% 零样本性能,prefill 最高 3.33 倍加速(batch 64、序列 2048),decode 期显存省 3.89 倍。权重那一步默认仍然调用 GPTQ,激活在线 round-to-nearest;6/8 bit 下连校准集都不用。

**SpinQuant**:发现不同的随机旋转效果差得很远——零样本推理最多差 13 个点。既然如此就**把旋转矩阵学出来**:冻结网络权重,用 Cayley SGD 在 Stiefel 流形上优化旋转(保证优化过程中始终正交),800 条 WikiText-2 样本、100 步迭代(消融显示降到 128 条几乎不掉点)。学到的残差流旋转与逐 head 旋转可以直接融进权重、不改推理图;另一个变体再叠上在线 Hadamard,约 8% 延迟开销换极端 4-bit 激活下的精度。W4A4KV4 上 LLaMA-2 7B 与全精度的零样本差距缩到 2.9 个点,比 QuaRot 又缩了约 30%。

一句评价:**旋转是目前把 4-bit 激活做到可用的主线**,代价是要么改推理图插在线变换,要么依赖专门的 kernel 支持。它和权重侧算法不是竞争关系——旋转负责把激活变得可量化,权重那一步照样调 GPTQ。

## 六、五连对比与阶段选型

| 算法 | 量化对象 | 核心一招 | 典型位宽 | 特点 |
| --- | --- | --- | --- | --- |
| LLM.int8() | 权重 + 激活 | 离群通道抽出走 fp16 | W8A8 混合 | 开山之作,近乎无损;小模型上反而更慢 |
| SmoothQuant | 权重 + 激活 | 逐通道把难度从激活迁到权重 | W8A8 | 全 int8 GEMM,scale 折进前层零开销 |
| GPTQ | 仅权重 | Hessian 加权的逐列误差补偿 | W4 / W3 | 精度好、量化快;对校准集较敏感 |
| AWQ | 仅权重 | 按激活幅度缩放保护显著通道 | W4 | 不动权重分布,泛化稳、数据效率高 |
| QuaRot / SpinQuant | 权重 + 激活 + KV | 正交/Hadamard 旋转摊平离群 | W4A4KV4 | 唯一把激活压到 4 bit 的路线;需在线变换 |

**W8A8 与 W4A16 分别用在哪个阶段**,是把上表接到系统上的关键一问:

| | prefill / 大 batch | decode / 小 batch |
| --- | --- | --- |
| bound | 计算受限 | 访存受限 |
| 真正想要的 | 低位宽 tensor core 的算力翻倍 | 权重搬运量下降 |
| 对应方案 | **W8A8**:SmoothQuant、FP8 | **W4A16**:GPTQ、AWQ |
| 换一个为什么不划算 | W4A16 算力不变,还多一步反量化,prefill 上可能是负收益 | W8A8 只把权重搬运减半,4 bit 减 4 倍更值;而且激活量化要多一趟在线统计 |

根子在于:decode 每生成一个 token 都要把**全部权重**从显存搬一遍,权重位宽直接决定时间,W4A16 的提速上限接近 4 倍;而 prefill 的权重搬运被整个 batch 摊薄,瓶颈在算力,必须**两边都低位宽**才能进 int8/fp8 tensor core。另外三点只给结论,展开各有专篇:

- 量化之后 bound 究竟迁不迁移,要按 weight-only 和 W8A8 分开算,定量分析见 Roofline与Bound分析 篇;
- int4 权重的反量化**必须和 GEMM 融合**在同一个 kernel 里,否则先反量化写回显存再读进来访存量反而涨,细节见 GEMM优化 篇与 访存与算子优化 篇;
- PD 分离部署下两段本可以各用各的最优方案,但它们共享同一份权重 checkpoint,想各用一套就得各存一份权重,这笔显存要单独算(部署形态见 PD分离 篇)。

## 七、校准集:几百条样本决定成败

**它们拿校准集干什么**:所有这些 PTQ 算法都要用几百条样本跑一遍前向,收集每一层输入激活的统计量。要的东西不一样,依赖强度也就不一样——SmoothQuant 要每通道的最大值(一阶),AWQ 要每通道的平均幅度(一阶),GPTQ 要 $XX^{\top}$(二阶)。

| 方法 | 校准集用量 | 数据来源 |
| --- | --- | --- |
| GPTQ | 128 条 × 2048 token | C4(通用网页语料) |
| SmoothQuant | 512 条随机句子 | Pile |
| AWQ | 16 条即可达到 GPTQ 用 192 条的效果 | Pile |
| SpinQuant(学旋转) | 800 条、100 步迭代;降到 128 条几乎不掉点 | WikiText-2 |

量级都是**几百条、几十万 token**,几分钟到几小时就跑完——校准集的成本从来不是问题,**选得对不对才是**。三个典型的翻车方式:

1. **序列太短**:统计不到长上下文才出现的激活范围,部署到长请求上 scale 直接不够用;
2. **领域太单一**:二阶方法会把 Hessian 拟合到那个领域上。AWQ 论文的对照实验很直观——把校准分布换成另一个领域(PubMed↔Enron),GPTQ 困惑度涨 2.3–4.9,AWQ 只涨 0.5–0.6;
3. **拿评测集当校准集**:这是数据泄漏,量化后的评测分数不可信。

**过拟合校准集的风险有多真实**:有一篇专门做系统实验的工作(Williams & Aletras)对多种 PTQ 与剪枝方法横扫了不同校准数据、任务与模型,结论是校准数据对压缩后模型下游表现的影响**明显大于**此前文献暗示的程度——不少论文报告的"对校准集鲁棒",在更广的任务集上并不成立。所以实操建议就一句:**校准集要贴近真实部署分布,但必须与评测集严格分开**;方法越依赖二阶统计(GPTQ 系,以及内部调用 GPTQ 的旋转方案),这条越要紧。

## 八、权重 / 激活 / KV cache 能不能一起量化

| 组合 | 能否叠加 | 说明 |
| --- | --- | --- |
| 权重 + 激活 | 能,而且本来就是同一套方法在做 | 两者共用一条 GEMM,必须同时低位宽才吃得到低精度 tensor core |
| 权重 + KV cache | 能,而且最常见 | 作用在不同算子上(线性层 vs attention),误差路径基本独立 |
| 激活 + KV cache | 能 | 旋转类方法就是把两者一起处理的 |
| 三者全上 | 能,但这是最激进的档位 | W4A4KV4 目前只有旋转路线做到可用 |

**顺序有讲究**:先做等价变换(SmoothQuant 的缩放、QuaRot/SpinQuant 的旋转),再做权重量化(GPTQ / RTN)——变换会改变权重的分布,量化必须落在最终分布上。**误差怎么累积**:每加一处量化,就是往前向里多注入一个扰动,而层与层之间是**乘性传播**——后一层会放大前一层的偏差,所以不要指望各处的损失能互相抵消,也不要指望它们能线性相加。可靠的做法只有一个:**每加一处量化就跑一遍你真正关心的下游任务**,看掉几个点。困惑度在这里尤其会骗人,它是平均指标,而量化误差集中伤害的是低频与关键 token,在数学、代码、长链推理这类"错一步全错"的任务上掉点常常远大于困惑度暗示的水平。**按收益来源搭配,三档典型组合**:

- **W4A16 + KV fp8**:单卡跑大模型 + 长上下文。权重压 4 倍解决 decode 的带宽瓶颈,KV 压一半解决上下文长度,两者收益来源不同,基本可以叠加;
- **W8A8(或 FP8)+ KV fp8**:高并发服务,prefill 吃算力、decode 吃带宽,两头都照顾;
- **W4A4KV4**:端侧与极限压缩,需要旋转类方法配专门 kernel。

KV cache 侧的具体机制——K 与 V 的分布差异、算子怎么改、静态量化参数怎么取、fp8 与 int8 怎么选——全部见 KVCache量化 篇,本篇只给到"能不能叠加"这层结论;量化模型上再做低秩微调(QLoRA 那条线)见 LoRA 篇。
