# Infra · 总览

一句话:这是本章 **51 篇、三个子目录的章级导航页**——只回答"我该进哪个子目录、这道题该敲哪扇门",**不讲任何原理**。本章讲的是**让一个模型跑起来、跑得快、跑得省**:GPU 怎么执行、瓶颈在哪、每个机制省的是什么(01-原理),框架里怎么配、怎么选(02-框架与引擎),以及那些不属于大模型、但面试一定会顺着简历问的传统系统题(03-通用系统)。

本页是 hub,不参与题目 `topic` 匹配,也不挂考点表——考点表在各篇自己文末。

## 一、本章的形状:三个子目录

| 子目录 | 篇数 | 它回答的是哪一类问题 | 入口 |
|---|---|---|---|
| **01-原理** | 30 篇 + 1 篇导航 | **为什么**:硬件地基、分析方法、kernel 优化、推理机制、量化、分布式——每个机制省的是什么、代价是什么 | 该子目录的 `00-总览` |
| **02-框架与引擎** | 12 篇 + 1 篇导航 | **怎么用**:vLLM / SGLang / Megatron / DeepSpeed / FSDP / NCCL 与四家 RL 框架的架构、配置与选型 | 该子目录的 `00-总览` |
| **03-通用系统** | 9 篇 + 1 篇导航 | **不属于大模型、但面试会问**:并发、分布式锁、缓存、网络、负载均衡、数仓、推荐系统、归一化、机器人 | 该子目录的 `00-总览` |

**三个子目录的导航页已经把内部写得很细了**——哪篇讲什么、按什么顺序读、哪道题落哪一节,全在那里,**本页一律不重复**。本页只做三件事:把你**送进正确的子目录**(第二节)、讲清子目录之间的**交界**(第三节)、划清**本章和别的章**的界(第六节)。

## 二、先分诊:这道题问的是原理、用法,还是别的

**一句话判据:问"为什么 / 省的是什么 / 瓶颈在哪"→ 01-原理;问"怎么配 / 怎么选 / 某个框架里怎么做"→ 02-框架与引擎;换成传统后端也成立 → 03-通用系统。**

嫌这条太抽象,就用下面三条更好落地的分辨线:

| 你问自己 | 偏 01-原理 | 偏 02-框架与引擎 | 偏 03-通用系统 |
|---|---|---|---|
| **答案会不会随框架版本变** | 不会:由物理与算法决定 | 会:半年一变,各篇都标了时效口径 | 不会,但会随业务场景变 |
| **题干有没有点名某个项目** | 通常没有 | 有:vLLM、Megatron、verl 直接出现在题干里 | 没有,或点的是 Redis、Spark、Nav2 这类非大模型项目 |
| **把"大模型"换成传统服务还成不成立** | 不成立 | 不成立 | 成立 |

两处最常见的走错门:

- **"框架名 + 机制名"的题**,如"vLLM 的 PagedAttention 是怎么回事":机制去 01-原理 的 PagedAttention 篇,02 的 vLLM 篇只讲它在引擎里怎么配、和别的看家本领怎么搭。02 每篇导航表的第三列就是它的前置原理篇。
- **"推理慢怎么办"这类整机题**:先去 01-原理 的 推理加速 篇(串讲篇)把手段的顺序排出来,再回具体机制篇;别一上来翻框架配置。

三道自测,拿到题先过一遍:

| 题 | 敲哪扇门 | 为什么 |
|---|---|---|
| "FlashAttention 为什么快?" | 01-原理 的 FlashAttention 篇 | 问的是机制,答案不随框架版本变 |
| "vLLM 的 `gpu_memory_utilization` 该开多大?" | 02-框架与引擎 的 vLLM 篇 | 题干点名了项目,问的是配置 |
| "Redis 分布式锁怎么续租、Redlock 靠不靠谱?" | 03-通用系统 的 分布式系统 篇 | 换成传统后端照样成立 |

## 三、交界:三个子目录之间,以及和别章之间

| 交界 | 分工 |
|---|---|
| **01-原理 ↔ 02-框架与引擎** | 机制归 01,配置与架构归 02;02 的每篇都以"先读哪篇原理"开头,01 的每篇都不点名框架版本 |
| **03-通用系统 ↔ 01-原理** | 负载均衡(实例**之间**怎么分)↔ 连续批处理(实例**之内**怎么排队);网络性能(单机内核协议栈)↔ GPU互联与组网(NVLink / RDMA);并发控制(CPU 线程)↔ CUDA流与异步执行(GPU stream) |
| **02-框架与引擎 ↔ 03-强化学习** | 02 的四家 RL 框架讲**系统怎么搭**——两个引擎怎么共卡、权重怎么同步;PPO / GRPO 算法本身归 03 章 |
| **01-原理 ↔ 01-模型结构** | MoE并行与DeepEP 讲 MoE 怎么切到多卡,MoE 是什么归 01 章;KVCache量化 讲 KV 怎么压位宽,GQA / MLA 怎么压头数归 01 章 |

一句话记法:**01 讲机器,02 讲工具,03 讲机器之外的系统。**

### 跨子目录最容易问串的五对名字

同一件事在两个子目录里各有一篇,分工写死,答题时先想清楚面试官问的是哪一半:

| 容易混的一对 | 01-原理 那一半 | 02 或 03 那一半 |
|---|---|---|
| PagedAttention 与 vLLM 的 KV 管理 | PagedAttention 篇:分页为什么消灭碎片、怎么共享 | vLLM 篇:block size、前缀缓存、抢占在引擎里怎么配 |
| ZeRO 与 DeepSpeed / FSDP | ZeRO 篇:三个 Stage 各切什么、通信为什么涨 | DeepSpeed 篇与 FSDP 篇:同一思路的两个实现怎么接入、怎么选档 |
| 集合通信 与 NCCL | 集合通信 篇:AllReduce 语义、Ring vs Tree、算法带宽 | NCCL 篇:拓扑探测、环境变量、nccl-tests 怎么读 |
| 并行策略 与 Megatron 的并行配置 | 并行策略 篇:DP/TP/PP/EP/SP/CP 各切什么、通信量 | Megatron 篇:并行度参数怎么配、哪些约束框架不替你查 |
| 连续批处理 与 负载均衡 | 连续批处理 篇:一台实例内按 step 调度、chunked prefill | 负载均衡 篇(03):实例之间按成本向量分发、准入与熔断 |

## 四、四条读法:按你的目标挑一条

| 你的目标 | 建议路径 |
|---|---|
| **第一次系统学 Infra** | 01-原理 导航页的第一条路径(六组按依赖顺序)→ 02-框架与引擎 导航页里对应岗位那条 → 03-通用系统 按简历经历挑 |
| **只准备推理岗** | 01-原理 导航页"只准备推理岗"那条 → 02 的 vLLM → SGLang → 推理引擎对比 → 03 的 负载均衡 |
| **只准备训练 / 分布式岗** | 01-原理 导航页"训练 / 分布式岗"那条 → 02 的 Megatron → FSDP → DeepSpeed → NCCL |
| **RL / 后训练岗** | 先读 03-强化学习 章的算法 → 02 的 RL框架对比 → verl / slime / ROLL / OpenRLHF 按需 |

后端、推荐、机器人方向不在上表里:直接进 03-通用系统 的导航页,它的第四节按岗位分了三条路。

**先 01 后 02 不是因为 01 更简单**,而是 02 的每一篇都默认你已经知道那几个机制是什么:vLLM 篇讲调度器时把 PagedAttention 与连续批处理当成已知名词带过,反过来读会在第一节就卡住。

## 五、真题分布:142 道,分散在三个目录里

本章的真题**不在同一个目录下**,这是本章最容易漏题的地方:

| 题库目录 | 落到本章的题数 | 归属 |
|---|---|---|
| `questions/AI Infra/` | 135(该目录共 146 道) | 116 道 → 01-原理;16 道 → 03-通用系统;3 道 → 02-框架与引擎。**另有 11 道 topic 挂在别章**(卷积与池化、稀疏注意力、Softmax优化、Agent 侧等),按 topic 找 |
| `questions/SFT/` | 6 | 解码策略(2 道)、ZeRO、显存管理与OOM、量化、DeepSpeed |
| `questions/RL/` | 1 | verl 的批次换算 |

三条读表须知:

- **按 topic 找题,别按目录名找。** `topic` 第一段就是文章名,目录只是收纳位置;上表的错位都由此而来。
- **分篇对应在各子目录的导航页里**:01-原理 导航页第三节按九组题对应到篇,02 导航页第七节列了 5 道,03 导航页第五节列了 16 道;具体落到哪一节在各专篇文末的考点表。本页三者都不重复。
- **04 章之外的题不要往这里找**:题干问 GQA 为什么省 KV 是 01-模型结构 的题,问 LoRA 显存是 02 章 的题——即使它们出现在 `AI Infra` 目录里。

## 七、本章写作的三条纪律

改本章任何一篇之前先看这三条,它们是 `docs/04-知识库地图.md` 里写死的分工:

1. **串讲篇与导航页不许写成技术综述**:01 的 推理加速 篇只讲手段之间怎么组合、按什么顺序上,各级 `00-总览` 只做目录导航;单项机制一律一句话引到专篇。
2. **02 的个体篇不做横向对比,对比篇不讲某一家的内部架构**:vLLM 篇不比 SGLang,推理引擎对比 篇不讲 vLLM 的调度器怎么写。
3. **03 里同一个系统按角度切开就不重写**:Redis 分三篇、归一化 与 Norm位置 分两章、推荐系统 与 推荐模型 分两章,边界在各自导航页与 04 地图里。

> 本篇是导航页,不设「面试考点串联」——考点在各专篇文末。
