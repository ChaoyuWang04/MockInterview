# 通用系统 · 总览

一句话:这是本目录 **9 篇的导航页**——只回答"我该读哪篇、这道题该敲哪扇门",**不讲任何原理**。本目录收的是**不属于大模型、但面试会问**的传统后端与 ML 基础题:简历上写过数据链路、推荐、服务端或机器人,面试官几乎一定往这里挖。

本页是 hub,不参与题目 `topic` 匹配,也不挂考点表——考点表在各篇自己文末。

## 二、Redis 被三篇切开:先看你的问题是哪一角

同一个 Redis,三篇各管一个角度,**互不重写**。拿到题先判断它问的是下面哪一行:

| 问题在问 | 敲哪扇门 | 典型问法 |
|---|---|---|
| **数据结构与底层编码** | 缓存系统 篇 | 逻辑类型和编码是什么关系、listpack / skiplist / dict 什么时候切换、MGET 为什么快、Cluster slot 与 hash tag |
| **线程模型** | 并发控制 篇第五节 | 核心命令为什么串行、"mostly single threaded"而不是纯单线程、I/O 线程与后台任务、慢命令为什么阻塞全局 |
| **拿它做分布式锁** | 分布式系统 篇 | `SET NX PX`、Lua 原子释放、续租、Redlock 与 fencing token |

一道题跨了两行(如"Redis 单线程为什么还能做锁"),按两行分别去对应篇取答案,别在一篇里找全。

> 三篇分工的完整原文在 `docs/04-知识库地图.md` 的 04-Infra 一节;要改任何一篇的边界,先改那里,再回来改本页。

## 三、最容易走错门的五对名字

| 容易混的一对 | 分工 |

| 并发控制 与 分布式系统 | 前者只讲单机多线程,后者只讲跨进程跨机器;GPU 侧归 CUDA流与异步执行 篇 |

## 四、三条读法:按你要面的岗挑一条

| 你的目标 | 建议路径 |
|---|---|
| **后端 / 平台岗** | 并发控制 → 缓存系统 → 分布式系统 → 网络性能 → 负载均衡(第二节的 Redis 三角先看一遍,免得答串) |
| **推荐 / 数据岗** | 数据系统 → 推荐系统 → 02 章 推荐模型 与 特征工程 → 归一化 只看第四节的选型 |
| **具身 / 机器人岗** | 机器人系统 → 03 章 强化学习基础 → 05 章 世界模型范式 → 动作条件与交互 |

**只准备大模型岗**的话,本目录只需读两处:负载均衡 篇(它讲的就是 LLM 服务实例间的分发)和 网络性能 篇第六节;其余按简历上有没有对应经历决定。

两条依据,省得你自己再推一遍:

- **后端岗先读 并发控制 再读 分布式系统**,因为后者讲锁的正确性时默认你已经知道单机互斥保证的是什么;反过来读会在 fencing token 那一节卡住。
- **推荐岗把 数据系统 放在最前**,因为 推荐系统 篇讲的实验与评估默认特征和样本已经正确生产出来;JOIN 膨胀、数据倾斜正是样本表出问题的常见来源。
