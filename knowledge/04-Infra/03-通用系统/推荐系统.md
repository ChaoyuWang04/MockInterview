# 推荐系统

一句话:推荐系统真正的工程难题不是模型有多强,而是**在几十毫秒里从千万到十亿量级的库中挑出几十条**——所以它必然是一条召回 → 粗排 → 精排 → 重排的漏斗。本篇只讲系统与实验这一侧:分层为什么非分不可、延迟预算怎么排、负采样把概率改坏了怎么修、改动怎么用线上实验验收。模型这一层(FM/DCN、DIN 序列建模、双塔的结构与负采样)见 推荐模型 篇。

## 一、为什么必须分层:单条候选的算力预算随候选数反比缩

召回 → 粗排 → 精排 → 重排这四层不是历史包袱,是被一条算术逼出来的:

$$
\text{单条候选可用算力} \approx \frac{\text{该段延迟预算} \times \text{单机可用算力}}{\text{该段候选数}}
$$

人话:分子是几乎固定的(延迟预算由产品定,算力由采购定),所以**候选数每降一个数量级,单条候选就能多花一个数量级的算力**。把精排那套「用户特征 × 物品特征全交叉 + 上千条行为序列」拿去跑全库,成本要高六到八个数量级,任何机器都接不住;反过来,只用双塔内积去决定最终展示顺序,又白白浪费了候选已经很少这个便宜条件。分层的本质就是**把算力花在候选已经足够少、每一分算力回报最高的地方**。

| 阶段 | 候选规模 | 单条候选大致能做什么 | 模型形态 | 真正的优化目标 | 最怕的错误 |
|---|---|---|---|---|---|
| 召回 | 全库 $10^7$–$10^9$ → 几千 | 一次向量内积或一次倒排查表 | 双塔 ANN、倒排、图游走、规则、热门 | 召回率、覆盖、新内容进入速度 | **漏召回**——后面再强的排序也救不回来 |
| 粗排 | 几千 → 几百 | 一次小 MLP,特征只能是预计算好的 | 轻量双塔、向量化内积、小 DNN | **与精排的一致性**,而不是 CTR 本身 | 把精排本来会选的候选提前砍掉 |
| 精排 | 几百 → 几十 | 完整特征交叉 + 行为序列 | 多目标交叉模型、序列模型 | 点击/时长/转化的准确预估 | 分数或相对次序错 |
| 重排 | 几十 → 展示位 | 在候选**之间**做组合级搜索 | 打散、MMR、序列生成、业务规则 | 整个列表的收益:多样性、疲劳、安全、频控 | 每条单看都最优,整页很难看 |

两点容易被忽略:**粗排的目标不是预测点击,是尽量不冤枉精排会喜欢的候选**——它的验收指标应该是「粗排 Top-N 与精排 Top-N 的重合度」,而不是粗排自己的 AUC;**重排是唯一一个不独立给候选打分的阶段**,前三层都假设候选之间互不影响,只有重排真正在优化列表整体。表里的量级是业界常见范围,不是固定常数:具体候选数、每层保留比例和毫秒预算都要靠压测和线上实验定。

### 什么时候能合并粗排,什么时候该扩大候选集

粗排的净价值 = **它省下的精排成本 − 它砍错候选造成的损失**。所以精排轻到一定程度(蒸馏成小模型、物品侧表示预计算、量化与算子融合都做过了),前者会小于后者,这时**合并粗排**是对的。判据要靠数,不能靠感觉:把粗排短路掉、让召回候选直接进精排跑一版离线重放,看两件事——端到端延迟还在不在预算内,以及最终 Top-N 列表变了多少。如果 Top-N 几乎不变,说明粗排一直在做无用功,拆掉还能少一层维护和一处口径不一致。

**扩大候选集**的前提正相反:漏斗统计要证明瓶颈在覆盖,而不是在排序。做法是逐层统计「最终被点击的物品是在哪一层被淘汰的」——如果大量正反馈物品根本没进召回,那是召回率的问题,加大精排候选没用,该补召回源或改索引;如果正反馈物品都进了候选却排不上去,那是排序的问题,扩候选只是白烧算力。一个便宜的验证:把候选数翻倍跑实验,看精排 Top-N 的构成变了多少,变化很小就说明扩不动了。

## 二、多路召回:分数不可比,配额是最后一道闸

多路召回是为了覆盖:向量召回抓语义相似,倒排抓关键词,协同过滤抓行为共现,还有关注、地理、热门、新内容、探索这些补充路。合并时的第一个坑是**各路分数根本不在一个尺度上**——余弦相似度在 $[-1,1]$、热度分是一个计数、规则优先级是序数,直接放一起排等于随机加权。三条常见处理,代价各不相同:

| 做法 | 怎么做 | 代价 |
|---|---|---|
| 分位数归一化 | 把每路分数映射成它在该路历史分布里的分位 | 最稳,但只保留路内次序,强度信息全丢 |
| 交给统一粗排 | 不校准分数,各路分数只作为粗排的输入特征之一,由粗排给出唯一可比的分 | 工业上最常见;但粗排本身要有足够的训练数据覆盖每一路 |
| 逐路概率校准 | 用 isotonic 之类把每路分数映射成「该候选被精排选中」或「被点击」的概率 | 校准后真的可比,但每路都要独立维护一个校准器和校准集 |

第二个坑是**配额**。如果合并后按分数直接截断,候选量天生大的热门路和向量路会把长尾路、新内容路、探索路挤成零——而这几路恰恰是打破曝光闭环的唯一来源。所以每路要给配额:可以按该路近期的贡献(进入精排 Top-N 的比例、最终曝光后的正反馈率)滚动调整,但**每路必须有一个不为零的下限**,否则一条新路冷启动失败一次就永远起不来,变成自我实现的失败。合并时对同一物品去重,但**保留召回来源做审计**——出问题时要能回答「这条是哪来的」。不过**训练排序模型时要慎用「召回来源」这个特征**:它携带的信息是「旧系统觉得它好」,不是「用户觉得它好」,模型学会它就等于把历史分发偏置固化下来;做归因和审计可以,进模型要有消融证明。

## 三、延迟预算:先按段分配,再按固定次序调

先量**端到端 P99**(不是均值,均值会把长尾藏起来),再拆到各段:多路召回、特征拉取、粗排、精排、重排、序列化与网络。最容易被低估的一段是**特征拉取**——几十上百个特征要打多次 KV 存储,它常常比模型前向还贵。

超预算时按这个次序调,理由是**副作用递增**:

1. **先测,不先调。** 拿分段耗时的 P99 定位瓶颈段。凭直觉去优化「感觉最重」的精排,十次有六次调错段。
2. **砍不改变候选集合的成本。** 特征拉取合并批量与加缓存、多路召回改并发、去掉重复计算的特征、模型前向做算子融合与低精度。这一步**完全不损精度**,应该榨干了再往下走。
3. **砍精排的单条成本,而不是候选数。** 蒸馏成小模型、物品侧表示预计算、行为序列截断或改成两级检索(见 推荐模型 篇的 SIM)。精度有损但可控。
4. **砍候选数,从漏斗里「淘汰后指标掉得最少」的那层开始。** 通常是粗排入口,而不是召回入口——砍召回砍掉的是覆盖,是不可恢复的损失。
5. **最后砍召回路数**,按历史贡献率从低到高砍,并保住探索路和新内容路的下限配额。
6. **超时降级要当一等公民设计**,而不是事故时临时想。每段设独立超时,超时就返回该段的部分结果而不是让整个请求失败:精排超时退回粗排分,粗排超时退回召回分,全挂了退到热门加多样性的兜底列表。降级路径要定期演练,没演练过的降级在事故当天基本用不上。

## 四、双塔召回的工程流程

结论先摆:全库有千万到十亿个物品,不可能每次请求都把用户和每个物品拼起来跑一遍模型;于是把打分函数强行拆成 $s(u,i)=\langle f(u),g(i)\rangle$ 这种可分离形式,$g(i)$ 与请求无关就能离线全量算好写进索引,线上只剩一次用户塔前向加一次近邻检索。代价是**两侧在打分前不能交互**,「某个用户特征恰好和某个物品特征搭配」这类细粒度组合它天生表达不了,这就是双塔的天花板,不是调参能补的。塔的结构约束、点积与余弦的取舍、四种负样本来源、批内负采样的修正、以及多兴趣向量与蒸馏这些缓解手段,全部见 推荐模型 篇;本节只讲把它落成一条线上链路要做哪些事。

| 步骤 | 做什么 | 这一步最容易出的事故 |
|---|---|---|
| 定正样本 | 按业务目标选点击/完播/成交,训练与验证**按时间切分** | 随机切分导致未来信息泄漏,离线指标虚高 |
| 选特征 | 用户塔只能用**请求时刻真拿得到**的特征;物品塔特征必须可离线批算 | 用户塔用了只有离线才算得出的统计量,上线即崩 |
| 造负样本 | 四种来源按比例混合(见 推荐模型 篇) | 只用曝光未点击,等于把召回训成了粗排 |
| 训练与离线验收 | Recall@K、覆盖率,并按人群、新老用户、新物品切片看 | 只看训练损失或全局 Recall,新物品全军覆没看不出来 |
| 批量建库 | 全库过一遍物品塔出向量,写进 ANN 索引 | 索引版本与模型版本不对齐 |
| 线上服务 | 一次用户塔前向 + ANN 取 Top-K,与其他路合并去重 | 训练与服务的特征口径不一致(见 特征工程 篇) |
| 更新与回滚 | 新物品增量写入,周期性全量重建;模型换代双索引灰度 | 没有回滚方案,一次坏模型污染整个索引 |

**索引版本与模型版本必须绑在一起**,因为向量空间是模型定义的:换了模型,库里的老向量和新模型算出的查询向量就不在同一个空间,检索结果退化成近似随机——而且**不会报任何错**,这是这条链路最典型的静默故障。做法是索引带模型版本号、查询侧校验版本,换代时双写双查再灰度切换。ANN 索引本身的结构与参数(HNSW/IVF/PQ 怎么选、召回率与延迟怎么权衡)见 Embedding 篇。

### 十亿级物品库的瓶颈会转到哪

| 瓶颈 | 具体表现 | 常见做法 |
|---|---|---|
| 索引内存 | $10^9$ 条 × 128 维 × fp32 已经约 512 GB,单机放不下 | 降维、标量量化或乘积量化压缩、水平分片 |
| 构建与更新 | 全量重建按小时甚至天计,新物品等不起 | 增量索引 + 周期全量重建的双层结构 |
| 分片路由与归并 | 每片各取 Top-K 再归并,分片越多**尾延迟越被最慢那片决定** | 控制分片数、对齐副本、设分片级超时并接受部分结果 |
| 召回率随规模下滑 | 索引参数不变,库变大后 Top-K 命中真值的比例会掉 | 在真实向量分布上重调参数,盯「ANN 召回率对延迟」的曲线 |
| 过滤条件 | 地域、下架、黑名单等过滤会把 Top-K 打空 | 按属性分区建索引,或超采后过滤,别指望纯后过滤 |

调这几项时记住一条:**脱离向量维度、索引类型、目标召回率、硬件和并发去承诺 QPS 或延迟,都是空的**。

### 冷启动:向量算得出来,不等于推得出去

**新物品**的 ID embedding 是随机初始化的,物品塔算出的向量没有意义。抓手是让物品塔尽量少依赖 ID:内容特征(标题、图文编码)、类目、作者,以及「作者历史表现」这类可迁移的先验;训练时可以随机把一部分物品的 ID embedding 置零,强迫模型学会只靠内容也能给出合理向量。但**光有向量不够,还得有曝光通道**——给新内容单独一路召回和保底配额,在探索槽位里投放,拿到最初几百次反馈之后才谈得上正常排序。**新用户**零行为时只能用经授权的上下文(设备、地域、时段、来源)、显式兴趣选择,再叠一层热门加多样性保底,有少量反馈后转成上下文 bandit 做受控探索。验收不能看大盘——大盘被老物品和老用户主导,冷启动做好做坏都淹没在噪声里;该看的是**新内容在 N 天内拿到首次正反馈的比例、新内容的曝光占比、以及新用户的次日/七日留存**。

## 五、负采样带来的概率偏移与校准

**先把两件不同的事分开。** 推荐模型 篇里的批内负采样修正,治的是**召回**对比损失里「热门物品被当负例的次数天然更多」,它改的是**候选分布**,受益的是排序质量。本节讲的是**排序/CTR 预估**里对负样本做下采样,它改的是**类先验**,受益的是**概率值本身**。一个在召回的 softmax 分母里做,一个在 CTR 的二分类输出上做,机制和修法都不一样,面试里混为一谈是常见失分点。

### 偏移从哪来

CTR 任务里点击常常只占千分之几到百分之几,负样本多到训练成本不划算,所以工程上正样本全留、负样本按概率 $w$ 随机丢。这一刀只动了训练集的正负比例,没动「给定特征时用户点不点」,可交叉熵训出来的模型拟合的恰恰是**训练集上的后验**:

$$
p' = \frac{p}{p + w(1-p)}
$$

人话:$p$ 是线上真实点击概率,$w$ 是负样本保留率,$p'$ 是模型在采样后数据上学到的概率。分母里只有负样本那一项被 $w$ 缩小了,所以 $p'$ 必然大于等于 $p$,$w$ 越小放大得越狠。真实 CTR 1%、只留 10% 负样本时,训练集里正样本占比升到约 9.2%——**模型没做错任何事,是我们改了题目**。

### 推理时怎么还原

$$
p = \frac{w\,p'}{1 - p' + w\,p'}
$$

人话:线上拿到模型输出的 $p'$,代进这个式子就还原成真实 CTR。$w=1$(不采样)时它退化成 $p=p'$,可以当作一个随手的自检。

换成对数几率更好记:真实几率等于采样后几率乘 $w$,取对数就是

$$
\operatorname{logit}(p) = \operatorname{logit}(p') + \log w
$$

人话:修正项 $\log w$ 是一个**与特征无关的常数**,所以整条打分曲线只是整体平移,任何两个候选的相对次序都不变,AUC 一点不动——**排序没坏,坏的只是概率值**。$w=0.1$ 时加的是 $\log 0.1 \approx -2.30$,是加一个负数把分数压回去,不是乘一个比例。更一般地,正样本保留率 $a_1$、负样本保留率 $a_0$ 时修正项是 $\log(a_0/a_1)$。这里最容易错的,是把「负样本采样率」「采样后的正负比」和「loss 权重」混成同一个数。

三条前提必须说清:保留概率要**只由标签决定、与特征无关**,若按活跃度、曝光位置或难度非均匀采样,一个全局 $w$ 就不够;模型本身要拟合得动,欠拟合的输出平移一个常数也救不回来;只有下游真要用概率值时才必须修——纯排序场景无所谓,**广告不行**,竞价里 eCPM 等于出价乘 pCTR,预估偏高 20% 就是多花 20% 的钱。

### 另一条路:训练时重加权,以及权重系数怎么定

不在推理端修,也可以在训练端把损失改回原分布:每条被保留的样本乘 $1/a_y$,正样本全留就是权重 1,负样本保留率 $w$ 就是权重 $1/w$。这样样本虽然少了,期望损失仍对应原始数据分布,模型直接输出真实 CTR。

**权重系数不是超参数,它由采样机制唯一确定。** $a_y$ 就是你实际执行的保留率,查采样代码或统计采样前后的条数即可,不能为了 AUC 更好看去调它——调了就等于又引入一次未知的先验偏移。真正需要判断的是另外三件事:非均匀采样时必须**在采样当时记录每条样本的入样概率**,做逐样本的逆 propensity 加权,事后估的 propensity 不可靠;$w$ 越小、负样本权重 $1/w$ 越大,少数几条样本会主导梯度,**训练方差变大、收敛变抖**,所以重加权和推理端平移并不是等价的两条路——平移只改一个输出常数、不动训练动态,通常应该先试它;如果有人真在「调」权重,那多半是在做代价敏感学习(故意让漏召的代价高于误召),那是另一个目标,和采样修正混在一起以后概率就再也解释不清了。

odds 平移只处理「已知采样造成的先验变化」,模型误差、时间漂移和流量结构变化留下的残差,要在一份**独立、接近线上分布**的校准集上拟合 Platt scaling 或 isotonic regression;温度缩放、可靠性图与 ECE 的具体机制见 分类损失 篇。**不能拿训练集本身拟合校准器**——那等于用做过的卷子估自己的水平。

### 校准做没做对,怎么验

| 看什么 | 怎么看 | 通过的样子 |
|---|---|---|
| 整体偏不偏 | 预测均值 ÷ 实际点击率(广告侧常叫 PCOC 或 calibration ratio) | 接近 1;大于 1 说明还偏高 |
| 概率准不准 | LogLoss / Brier score,校准前后对比 | 校准后应显著改善 |
| 分段准不准 | **可靠性图**:按预测概率分箱,横轴取箱内预测均值、纵轴取箱内真实点击率 | 点贴着对角线;整体压在对角线下方 = 过度自信 |
| 压成一个数 | ECE,按箱内样本量加权的绝对差 | 只在同一分箱口径下横比才有意义 |
| 分群是否都准 | 按人群、展示位置、流量来源、时段**分别**画可靠性图 | 大盘校准而某个位置严重偏是常态 |
| 有没有伤排序 | AUC / GAUC | 单调变换不该改变它;变了说明校准器过拟合 |

最关键的一条:**验证必须在原始的、未采样的分布上做**。在采样后的集合上量出「校准良好」,恰恰说明你根本没修。

## 六、在线 A/B 实验:分流、指标、显著性、发布

线上日志已经被旧策略筛过一遍,直接在日志上换个特征权重再算指标,评的是「旧策略选出来的候选上换权重会怎样」,不是「新权重上线后会怎样」。所以特征权重、模型版本这类改动**只能靠随机实验定论**。DID、倾向评分、IPS 这些反事实方法可以在无法随机化时补充,但依赖无未观测混杂、倾向得分有重叠这些更强的假设,不会自动获得 A/B 的因果可信度。

### 随机分流:用户级还是请求级

| | 用户级(按 user_id 或设备哈希分桶) | 请求级(每次请求独立随机) |
|---|---|---|
| 体验 | 一致,同一用户始终一种策略 | 同一用户在两种策略间反复横跳 |
| 能测到什么 | 能测到**累积效应**:留存、兴趣变化、模型学习效应 | 只能测即时反应 |
| 主要偏差 | 分桶不均衡、用户间方差大,需要更多流量和更长时间 | 两组用户组成完全相同、方差小跑得快,但**会串味**:实验组的推荐改变了用户的历史序列、疲劳度和画像,这些状态又流进对照组的请求,把真实差异冲淡 |
| 什么时候用 | 默认选它,尤其涉及留存和长期指标时 | 只适合「当次请求内即时可判、且不改变用户状态」的改动,比如渲染耗时、纯展示样式 |

还有一条比选哪种更容易翻车:**随机单位和分析单位必须一致**。按用户随机却按曝光算方差,是最常见的假显著来源——同一用户的多条曝光高度相关,当成独立样本会把方差算小好几倍。修法是按用户聚合成一个指标再比,或者对比率型指标用 delta method、bootstrap 估方差。

### 指标要分层,主要指标只能有一个

| 层 | 例子 | 作用 |
|---|---|---|
| 主要指标(唯一) | 搜索成功率、人均有效时长、转化率 | 决定上不上线,**实验开始前就写死** |
| 护栏指标 | P99 延迟、退出率、投诉率、内容多样性、供给侧曝光集中度 | 不求涨,只求不显著变坏;破一条就否决 |
| 诊断指标 | 各路召回贡献、漏斗各层通过率、模型分数分布 | 出问题时解释为什么,不参与决策 |

主要指标唯一的理由很实际:指标一多,总有一个会显著(多重比较),然后人会挑那个去讲故事;确实要看多个就先做 Bonferroni 或 FDR 校正,并写进实验开始前的方案里。显著性侧另记三条。先定 **MDE(最小可检测效果)**,由业务回答「涨多少才值得为这套复杂度买单」,再反推流量和时长,不能拿跑出来的数字倒填。样本量大致与 $(\sigma/\text{MDE})^2$ 成正比——**要检测的效果小一半,流量得大四倍**,这解释了为什么千分之一量级的收益极难做显著。最后是**不许偷看**:每天瞄一眼、显著了就停,实际的假阳性率远高于 5%;要么时长定死,要么用序贯检验。推荐场景还要**至少跑满一个完整周**,行为有很强的周内周期。

### 长期影响:短期涨不等于真的好

**新奇效应**是改动本身的新鲜感带来的短期虚涨,几天到两周回落;识别方法是看**逐日效果曲线是不是在收敛**,而不是只看累计均值,也可以只用「实验开始若干天后才进来的新用户」这一子集重算效果。**学习效应**方向相反:用户要适应,模型更要适应——新策略改变了曝光分布,而模型是拿旧分布的日志训的,要等几个训练周期才追上,所以**只跑三天就下结论,可能把一个好策略杀掉**。真正的慢变量(留存、供给生态)只能靠 **holdback**:留一小撮流量长期保持旧策略几周到几个月,代价是这部分用户的体验会落后,比例要控制。

### 实验互相影响怎么隔离

- **分层正交**:把流量切成若干「层」,同一层内的实验互斥(一个用户在这层只进一个实验),不同层之间正交重叠。**改同一个模块的实验必须放同一层**(比如都改精排分),改互不相干模块的可以跨层。核心思想是用「层」把「会不会打架」表达成配置,而不是靠人去记。
- **先验证分流本身**:上线前跑 A/A 实验确认无偏;跑中盯 **SRM(样本比例不匹配)**,两组流量比例偏离设计值就说明分流或日志有问题,此时任何结论都不可信,先修分流再谈指标。
- **确实存在交互时**,显式做 2×2 全因子实验把交互项估出来,或者干脆串行跑,别硬凑并行。
- **网络与市场干扰**:社交传播、商家供给、广告预算是共享的,实验组多花的就是对照组少花的,用户级 A/B 的「个体处理不影响他人」假设不成立。这时按地域、城市或时间片(switchback)分流,代价是样本单位从用户降成簇,可用样本骤减。

### 收益很小该不该上线,以及怎么安全发布

默认**不上**,判据不是 p 值而是三笔账:一、**和 MDE 比,不是和 0 比**——显著只说明效果不是 0,流量够大时 0.02% 也能显著,那不是发现,是样本量;二、**算净收益**,收益减去延迟成本、算力成本和长期维护成本,一个涨 0.1% CTR 却让精排多花 8 ms 的模型很可能净负,因为延迟本身会伤全站转化;三、**看置信区间下界**而不只是点估计,区间下界贴着 0 就意味着「很可能几乎没用」。两类例外要单独立项说清楚:**复利型改动**(特征平台、样本质量、基础设施)本身收益小但为后续改动铺路;**护栏型改动**(降延迟、降成本、提多样性)主指标持平即可上。

安全发布的顺序是:离线验证 → 小流量(比例以「能发现严重回归」为准)→ 按计划放量 → 全量 → 长期 holdback 监控。每一步都要配预设的自动回滚阈值、版本化的模型与索引,以及**演练过的**回滚路径。

## 七、离线指标和线上 A/B 为什么总对不上

| 背离的来源 | 具体是怎么发生的 |
|---|---|
| 评的根本不是同一件事 | 离线在**固定候选集**上算 AUC 或 Recall@K;线上是新模型自己去选候选。模型一换候选就变,离线从没测过那批新候选 |
| 样本被旧策略筛过 | 日志里只有旧系统曝光过的物品;新模型推出来的、旧系统从没曝光过的物品没有标签,离线只能当它不存在,于是系统性低估 |
| 口径不一致 | 离线用完整特征,线上有特征缺失、超时降级和缓存陈旧;全局 AUC 跨用户比分数而线上只在一次请求内排序(GAUC 的动机见 推荐模型 篇) |
| 只测了一层 | 召回 Recall@K 涨了,但涨出来的候选粗排和精排根本不选,端到端等于没动 |
| 忽略系统效应 | 延迟、多样性、疲劳、供给生态这些离线指标里没有的东西,上线后会反噬 |
| 分布漂移 | 离线用的是历史某段数据,线上的流量结构、内容供给和竞争环境都变了 |

大前提是**摆正分工**:离线的职责是挡掉明显变差的,不是证明变好,最终决策一律以线上实验为准。在这个前提下,对齐有四条做法,按性价比排:

1. **端到端重放,而不是单层打分。** 召回的改动要接到**真实的粗排与精排**上离线重放,报「最终 Top-N 列表变了多少」,而不是只报召回层的 Recall。
2. **常留探索流量。** 持续留一小撮随机或探索流量产出**无偏日志**,专供离线评估和纠曝光偏差。这是最有效也最常被跳过的一条——没有无偏数据,离线评估的天花板就被钉死了。
3. **用反事实估计补。** IPS、加权重要性采样、doubly robust 都能在日志上估「新策略大概能拿多少收益」,但必须同时报有效样本量:权重方差一大,估计就不可信。
4. **建离线—线上的历史对照。** 把过去 N 次实验的「离线涨幅对线上涨幅」画成散点,拟合出你这个系统的换算关系和噪声带。**离线指标的价值不在绝对值,而在它和线上的相关性稳不稳**;相关性差的离线指标应该淘汰,而不是继续用。
