## 题目

为什么要用后训练的小模型替换商业大模型?什么条件下这个替换才成立,又要付出哪些代价?

## 要点

- 动机不只是省钱:延迟、数据合规、可控性和版本稳定同样是理由
- 成立条件是任务窄且分布稳定,评测能覆盖真实分布
- 小模型换的是"这个任务上够用",不是通用能力
- 代价是自己承担数据、训练、评测和迭代的全部工程
- 判据要包含长尾错误率与失败代价,不能只看平均指标

## 答案

**动机通常被简化成"省钱",但真正推动替换的往往是另外几条。** 按重要性排:

| 动机 | 说明 |
|---|---|
| 单位成本 | 高频调用场景下,推理成本随量线性增长,小模型可能低一到两个量级 |
| 延迟 | 自部署小模型能进本地网络,省掉跨公网往返 |
| 数据合规 | 数据不出内网是很多行业的硬约束,和成本无关 |
| 可控性 | 商业模型会静默升级,行为漂移不可控;自有权重版本可冻结 |

**替换成立的条件**很窄,三条必须同时满足:

1. **任务窄且分布稳定**。抽取、分类、格式化、固定域问答这类任务,输入分布可枚举;开放对话和长链推理不适用。
2. **有足够的领域数据**。可以用商业模型蒸馏出训练数据,但要过质量门禁,见 [模型蒸馏方法](050-模型蒸馏方法.md)。
3. **评测能覆盖真实分布**,包括长尾。这条最常被低估——评测集只覆盖常见情况,上线后长尾一片崩。

**换来的是"这个任务上够用",不是通用能力。** 小模型在目标任务上打平甚至超过大模型是常见的,但一旦输入超出训练分布,退化会非常陡峭,而且往往是**静默**的——它会给出格式正确但内容错误的答案,比直接报错更危险。所以必须配置分布外检测或置信度阈值,低置信时回退到大模型。

**代价是工程责任的转移**:数据构造、训练、评测、监控、随业务变化的迭代,全部由自己承担。商业 API 的隐性价值是"别人替你持续升级"。决策时要把这份长期投入算进总成本,而不是只比单次调用价格。

判据上,除了平均指标,必须看**长尾错误率**和**单次失败的代价**。高频低风险任务适合替换;低频高风险任务省下的成本可能远小于一次错误的损失。

## 知识点

单位成本与延迟、数据合规约束、版本可冻结、分布内够用与分布外陡降、静默退化、置信度回退、长期迭代成本。

蒸馏数据的构造与质量见 [数据蒸馏概念边界](073-数据蒸馏概念边界.md);结构化任务为何 SFT 就够见 [结构化抽取任务](102-结构化抽取任务.md)。
