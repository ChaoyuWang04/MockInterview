## 题目

针对多轮对话任务,如何系统设计监督微调(SFT)的数据格式、上下文组织方式、模型输入结构及训练策略,以有效建模对话历史、保持上下文一致性并生成连贯响应?请结合典型应用场景说明关键设计考量。

## 要点

- 保存结构化角色与消息边界,训练和推理使用一致模板
- 因果注意力只看当前位置及之前,标签掩码单独控制回答监督
- 截断要保留当前请求及其必要依据,避免跨会话泄漏
- 用多轮评测检验事实记忆、指代、意图切换与矛盾

## 答案

**把对话按角色和时间顺序组织成因果序列,用历史作条件、用高质量 assistant 回复作监督。** 连贯性来自正确的上下文与示范,并不是把整段对话设为双向可见。

```text
输入顺序: user1 → assistant1 → user2 → assistant2
目标掩码:   0          1          0          1
```

先保存结构化消息,再用模型的聊天模板渲染角色和结束标记;工具调用与结果也要保留正确边界。每个 token 只能注意到自身及更早的位置,不能看到未来回答。标签可监督所有 assistant 轮次,或只监督末轮;提示词、padding 不计直接损失,细节见 [损失掩码](014-sft-损失掩码.md)。

### 历史很长怎么办

按 token 预算保留 system、当前请求和它依赖的历史;优先按完整轮次截断,早期关键事实可摘要或检索补回。若删掉了回答所需证据,就重写目标或丢弃样本。打包不同会话时隔离注意力,仅加分隔符不够。

客服要保留订单与澄清条件,角色扮演要保留身份和状态,代码助手要保留被修改的代码版本;窗口大小取决于实际依赖长度,没有通用覆盖比例。

### 来源追问补充

- **效率**:按长度分桶、打包短样本,并分别评估截断前后效果,避免只追求吞吐。
- **一致性评估**:设置跨轮指代、早期事实召回、条件更新和自相矛盾用例,结合任务成功率与人工审阅;单轮平均分不足以判断。
- **意图漂移**:加入更正需求、换话题和歧义澄清的示范,让模型在保留有效事实的同时更新当前目标。扰动历史后必须确认答案仍成立,不能把错误响应当正例做 SFT。
