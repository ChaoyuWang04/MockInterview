## 题目

在大模型训练或微调中,batch size 过小或过大分别会造成哪些影响?如何结合梯度稳定性、收敛速度、泛化能力和硬件资源,合理选择批量大小及梯度累积策略?

## 要点

- 区分微批、数据并行副本数、累积步数与有效token
- 独立采样时大batch降低梯度估计方差,收益会递减
- 累积省激活峰值,不会自动增加硬件并行效率
- 学习率缩放是有条件近似,最终看同预算任务成绩

## 答案

**batch 大小同时改变梯度估计与执行效率,最优值要结合有效 token、更新次数和实测吞吐选择。** 等长等大小微批、数据并行副本数为 $D$、累积 $K$ 次时,$B_{\mathrm{eff}}=B_{\mathrm{micro}}DK$;张量/流水线并行的卡数不能再乘进去。变长 SFT 还要统计每步被监督的 token。

### 过小与过大

独立同分布采样下,平均梯度的方差约随 $1/B$ 降低;相关、重复或错标数据不满足理想条件。小有效批容易波动,小微批可能使计算/通信效率低;大有效批超过有用规模后,新增样本的优化收益递减,相同 token 预算内更新次数也变少。小批噪声有时有助泛化,但“大批一定尖锐、小批一定更好”不是定律。

直接增大微批通常增加激活峰值,改善并行利用直到饱和。固定模型的梯度张量大小不因 batch 增大而增加,普通数据并行每次同步通信量也不按 batch 线性增长。

### 梯度累积的边界

显存只能放一条时,可多次前后向后统一更新。累积需按整个有效批的监督 token 正确归一化,最后不足 $K$ 次也要处理;裁剪、优化器和调度器应跟随实际更新。它以更多串行微步换低激活峰值,不会像真实大微批一样提高矩阵并行度。BatchNorm 的批统计、跨样本对比损失、dropout与浮点顺序可能使两者不完全等价,累积也不自动扩大跨样本负例池。

### 如何选与调

先找满足最长样本峰值且吞吐合适的微批,再比较有效批与学习率的少量组合。线性缩放源于小步SGD下若干次更新的近似,Adam等设置及大幅改批时不能机械套用。观察梯度、独立验证、达到目标所需 token 和时间,大批退化时重调更新预算、学习率、配比和正则,或减小有效批。

LoRA 节约可训练状态,可能容纳更大微批,但激活仍受长度影响。显存不足还可按瓶颈用重算、混合精度或[ZeRO 分片](013-zero-分片与选型.md),没有所有模型通用的最佳 batch。
