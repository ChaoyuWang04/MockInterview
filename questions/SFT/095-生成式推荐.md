## 题目

请以公开方法说明生成式推荐如何表示物品、训练和解码，并比较它与传统召回/排序的取舍。进一步分析大目录、推理延迟、发展方向，以及完全无行为数据的新用户冷启动方案。

## 要点

- 区分原始物品 ID、语义 ID 和自然语言，不生成不存在的物品
- 说明 MLE 与点击/长期价值不一致、曝光偏差和自回归延迟
- 大目录采用检索—生成级联、受限解码与可映射目录
- 冷启动区分零交互和少量交互，平衡探索、体验、隐私与公平
- 用推荐指标和线上预算评测，不虚构公开方法收益

## 答案

**生成式推荐把推荐改成“按用户状态生成下一物品标识”，但仍须保证标识合法、候选可查、目标与业务一致。**以公开的 TIGER 为例，物品内容经残差量化得到多级 semantic ID，再用 Transformer 根据交互 ID 序列生成下一物品。共享语义码有助迁移，但不保证冷启动成功。

推理用前缀树或 token mask 限定真实目录；大目录先经 ANN/规则召回，再受限生成或重排。缓存、批处理和蒸馏可降延迟，但须实测。传统系统易分阶段优化；生成式方法能统一序列目标，却有自回归延迟和目录维护成本。

训练应校正曝光/位置偏差，加入困难负样本和多目标；DPO 只适用于可靠的成对偏好。多模态或 Diffusion 方案仍须证明合法率、延迟和增量收益。

零交互时用经授权的上下文、内容语义、主动选择和“热门+多样性”保底；少量反馈后用上下文 bandit 更新兴趣并限制打扰。模型可生成兴趣描述再检索真实物品，不能幻想 item ID。RAG 可取实时内容，Agent 可澄清偏好，但不能替代召回排序。评测看 Recall/NDCG、合法率、长尾、多样性、新用户留存、延迟、隐私和公平。

## 知识点

生成式推荐、semantic ID、受限解码、检索—生成级联、曝光偏差、冷启动、上下文 bandit。

- 一手依据：[TIGER: Transformer Index for GEnerative Recommenders](https://arxiv.org/abs/2305.05065)
