## 题目

请以一个公开方法为例,讲清生成式推荐模型如何表示用户和物品、怎样训练与解码,并比较它与传统召回/排序系统的取舍。大商品库、冷启动和推理延迟应怎样处理?

## 要点

- 区分原始物品 ID、语义 ID 与文本 token
- 生成目标必须映射回有效商品目录
- 评估既看推荐准确率,也看覆盖、多样性、合法率和延迟
- 大目录常需约束解码或检索-生成级联
- 不把公开论文结果写成个人或闭源项目经验

## 答案

**生成式推荐把推荐目标改写成“根据用户历史生成下一物品的离散标识”,但仍要解决目录约束、检索效率和业务评估。** 以公开的 TIGER 为例,先用物品内容表示和残差量化得到多级 semantic ID,再把用户交互历史表示成 semantic ID 序列,用 Encoder-Decoder Transformer 训练下一物品 ID 的自回归生成。semantic ID 让内容相似物品共享部分码,比完全独立的原始 ID 更容易迁移到少交互物品;它仍不保证冷启动成功,因为内容质量、码冲突和用户反馈都可能限制效果。

推理时不能让模型随意产生不存在的码。可用前缀树、合法 token mask 或候选目录约束 beam search,再把有效 semantic ID 映射回物品。百亿级商品库不宜直接枚举全目录,常用 ANN/规则先召回候选,对候选建立受限解码空间,或让生成模型产出粗粒度语义簇后再精排。缓存用户状态、批处理、较短 ID 和蒸馏可以降低延迟,实际收益取决于硬件、并发和召回率要求。

传统系统通常把召回、粗排、精排拆开,模块易独立优化;生成式方法能统一序列目标并利用语义表示,但自回归解码更慢,目录更新和合法性更难。落地可采用级联:传统召回保证覆盖,生成模型负责候选扩展或重排,精排继续优化业务目标。

评测至少包含 Recall@K、NDCG@K、目录合法率、长尾覆盖、多样性、新物品切片、延迟和业务指标。语言生成质量不能替代推荐准确率,单篇论文的离线或线上收益也不能当作模型固有收益。

## 知识点

生成式推荐的闭环包括物品离散化、序列目标、受限解码、目录映射、召回/排序评测与线上预算。
