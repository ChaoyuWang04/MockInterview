## 题目

请系统性地阐述大语言模型从预训练、后训练(包括监督微调、对齐优化如 RLHF 等)到最终推理部署的完整技术流程,说明各阶段的核心目标、关键技术、典型方法及其在实际应用中的挑战与优化方向。

## 要点

- 预训练、SFT、偏好对齐与部署的目标和数据不同
- 训练侧处理数据质量、资源与稳定性,部署侧平衡质量、延迟和吞吐
- 评测贯穿各阶段,关注对齐后的通用能力退化
- 能说明数据配比与课程、奖励模型问题及分页 KV 缓存的基本作用

## 答案

**先用预训练获得基础能力,再用 SFT 学示范回答、偏好对齐学习取舍,最后把模型做成可稳定服务的系统。** 各阶段都要留独立评测,不能只看训练损失。

| 阶段 | 怎么做、为什么 | 主要挑战 |
|---|---|---|
| 预训练 | 清洗、去重并混合语料,做下一 token 预测;用分布式训练承载参数与计算 | 数据污染、算力预算、数值不稳定 |
| SFT | 将指令与回答渲染为对话,用示范回答监督;可全参或参数高效微调 | 模板和掩码错误、数据偏科、遗忘 |
| 偏好对齐 | RLHF 可训练奖励模型并优化策略;DPO 直接学习偏好对 | 偏好噪声、奖励投机、通用能力下降 |
| 推理部署 | 用 KV cache 复用历史计算,结合量化、批处理与并行 | 显存容量、排队延迟、输出质量 |

量化降低存储与部分计算开销,蒸馏把教师行为传给小模型,两者都要重新评估质量。

### 来源追问补充

- **数据配比与课程**:按任务需求、质量和去重后数量确定采样比例,用小规模消融比较;课程学习可以逐步加入长序列或难样本,但要保留基础分布,并验证顺序是否真有收益。
- **奖励模型为何不稳、DPO 改了什么**:偏好噪声、分布偏移及策略利用奖励漏洞都会影响训练;DPO 去掉显式奖励模型与在线 RL 环节,仍依赖偏好质量,详见 [后训练流程](011-后训练流程.md)。
- **延迟与吞吐**:批量变大通常提高吞吐,也可能增加排队时间,应在延迟目标下测负载。PagedAttention 用块表映射离散 KV 块并按需分配,减少显存浪费,机制见 [FlashAttention 与 PagedAttention](../AI%20Infra/057-fa与pagedattention原理.md)。

### 开跑前与训练中

按任务和预算选择架构、tokenizer 与规模,检查初始化后的激活和梯度,用短跑比较优化器、学习率、有效 batch 及精度后再扩大规模。预训练与 SFT 学习率没有固定数量级差:起点、训练量和可训练范围都不同,LoRA 与全参也不能直接套同一比例。

loss spike 先保存异常批次并复现,检查数据/长度、学习率、溢出和分布式错误,不能直接删数据。收敛既看有效目标上的验证 loss,也看任务指标和旧能力,见[损失异常诊断](054-训练loss-异常诊断.md)。

### 数据筛选与推理并行

SFT 先查格式、答案正确、重复与评测污染,再分层抽检和验证,不只按模型评分放行,见[数据集构建](027-sft-数据集构建.md)。实际配比应报告真实来源、预算和消融,不编企业经验。

大模型推理时 TP 切层内运算,PP 切层,DP 用独立副本承载更多请求;先让权重、KV 和缓冲放下,再按互联、并发及延迟约束比较组合。TP 不一定在单机,PP 也不一定跨机,见[并行方式全景](../AI%20Infra/091-并行方式全景.md)。

预训练、指令微调、偏好对齐、数据配比、课程学习、吞吐与延迟。
