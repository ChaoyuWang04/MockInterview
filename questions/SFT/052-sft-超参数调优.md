## 题目

在监督微调(SFT)时,如何系统调整学习率、批量大小、训练轮数等关键超参数?请说明影响机制、典型调试策略、与 LoRA 的关联及对收敛、泛化和过拟合风险的影响。

## 要点

- 先校验数据与监督链路,再比较超参数
- 学习率、有效batch与训练量相互影响
- 全参与LoRA的参数化和状态成本不同
- 选择依据是独立任务效果和旧能力,不能只看loss

## 答案

**先固定任务验收与数据基线,再做有限的分阶段搜索,比套一组“标准参数”可靠。** 先检查模板、标签、截断和 EOS,确认小样本能学到目标,再放大训练。

### 关键参数如何作用

学习率控制更新尺度,太大可能破坏已有能力或发散,太小则预算内学不充分;预热与衰减按实际更新或 token 计划安排。有效 batch 影响梯度噪声和每份数据对应的更新次数,微批决定激活峰值与执行效率。训练轮数决定重复曝光,是否该早停应结合验证趋势、任务指标和旧能力,不能固定三轮或见一次波动就停。

LoRA 还要选择 rank、alpha、目标层和 dropout。rank 改容量,alpha 改增量缩放,它们与学习率有交互,不能把 alpha/r 当所有实现中独立等价的“有效学习率”。全参允许更新更多权重、状态占用更大,LoRA 常可腾出微批空间,但长度和激活仍是限制。具体见[LoRA 超参数](031-lora-超参数调优.md)与[batch 权衡](079-batch-size-训练权衡.md)。

### 有限预算的搜索

固定数据版本、训练预算和新旧评测,先筛学习率稳定区间,再比较少量有效 batch 与训练量,最后检查 LoRA 容量及正则。候选之间保留可比的 token/更新口径,先用短跑淘汰明显发散方案,对优胜者做完整验证。已有日志的梯度范数、更新量、训练/验证趋势和输出抽检能发现明显配置问题;若完全不增加试验成本,只能排除部分错误,不能证明当前参数最优。

### loss 与效果矛盾怎么办

验证交叉熵衡量参考答案 token 的概率,任务指标可能关注事实、格式或完整生成,两者并不一致。先排查模板、解码、评价脚本与数据污染,再按任务和长度分组检查,看是否只学会高频短答或文风,遗漏关键推理。按真实验收指标选检查点,修正数据与评价目标。震荡还需区分正常批次噪声与持续发散,按[loss 诊断](054-训练loss-异常诊断.md)保存样本、查梯度和数值,再做针对性调整。
