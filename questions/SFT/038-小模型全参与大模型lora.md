## 题目

在相同任务下,对比小规模模型进行全量监督微调(SFT)与大规模模型采用 LoRA 等参数高效微调方法的效果差异,系统分析模型容量、微调策略(如全量微调 vs. 适配器式微调)及其协同效应对最终性能的影响,并结合实际场景说明各自的优劣与适用条件。

## 要点

- 基座能力与可更新范围共同决定可学到什么,不能只按模型参数量排序
- 大模型 LoRA 少存梯度和优化器状态,但基座权重与激活仍大
- 推理成本取决于完整模型及服务条件,合并不会把大模型变小
- 用相同数据、任务评测及明确预算比较,同时评估保留能力
- LoRA 不佳先排查数据与训练,再比较扩大适配范围、变体及全参基线

## 答案

**没有“大模型 LoRA 必赢”或“小模型必须全参”的规模分界。** 大基座可能已有任务所需知识,少量增量就能改变输出方式;小模型全参虽能更新所有权重,仍受其表示能力与预训练基础限制。反过来,大模型若需要改变的方向超出当前低秩更新范围,小模型全参也可能在特定任务上更好。

### 把效果与成本放在同一张表里

| 比较点 | 小模型全参 | 大模型 LoRA |
|---|---|---|
| 更新范围 | 所有原权重可更新,适配自由度大 | 受目标层与秩约束,可利用较强基座能力 |
| 训练资源 | 全部参数需梯度与优化器状态 | 可训练状态少,但更大的基座与激活仍需显存 |
| 部署成本 | 若能力足够,较易满足显存和延迟限制 | 合并后仍是大基座,推理成本不会因只训小增量而消失 |
| 能力保留 | 全参更新也需防过拟合与遗忘 | 冻结保留了原权重,不保证启用增量后不遗忘 |

两者都用相同训练/测试拆分,分别调好超参数,记录训练预算和峰值显存;效果比较目标任务与原有能力。部署时控制精度、硬件、输入长度和并发,实测延迟与吞吐。大模型 LoRA 未必比小模型全参省总显存或训练时间。

例如端侧分类或格式抽取,若小模型已达质量要求,全参后的紧凑部署可能更合适;复杂问答若依赖大基座已有能力,且服务预算允许,LoRA 值得优先试验。这里只是选型条件,不是已有项目成绩;数据条数或模型参数量都没有统一拐点。

### LoRA 不佳与全参的边界

先查数据、模板、损失掩码及优化设置,再比较扩大目标层、调整 r 与缩放。DoRA 分别学习幅度和方向,AdaLoRA 按重要性动态分配低秩预算;它们改变更新方式或预算分配,都有训练成本,不保证必然提升。

若排除上述问题后,PEFT 在允许预算内持续欠拟合,而全参基线带来足够的验证收益,大模型也可考虑全参。需要同时承受资源开销和能力退化风险,不能因模型大就认定低秩容量足够。

### 合并与保留分支

部署前计算 $W'=W_0+(\alpha/r)BA$,可省去独立分支;矩阵形状与基座规模不变。保留增量便于多任务共享基座和切换,但多一次分支计算,批处理效果需实测。每个任务都另存完整合并模型会重复保存基座;量化模型合并还须处理反量化及再量化误差,重新评测。

基座能力、更新容量、训练显存账本、部署约束、DoRA、AdaLoRA。
