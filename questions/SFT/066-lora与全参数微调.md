## 题目

请详细介绍 LoRA(Low-Rank Adaptation)的技术原理,系统对比其与全参数微调(Full Fine-tuning)在计算资源消耗、训练效率、模型性能与部署适用性上的差异,并结合实际应用场景说明两者的适用条件与选择策略。

## 要点

- 同一基座下比较更新空间、训练账本与真实速度
- LoRA 仍计算基座前向与输入梯度,不能承诺固定加速倍数
- 性能差距取决于任务所需更新、数据与优化,没有必用全参的领域名单
- 明确多适配器切换、加权合并和先 LoRA 后全参的不同含义

## 答案

**LoRA 用受限的更新空间换取更少的训练状态和任务副本。** 它冻结 $W_0$,训练 $W'=W_0+(\alpha/r)BA$;全参微调直接更新原模型所有权重。低秩假设针对任务增量,并不要求基座本身低秩。

| 维度 | LoRA | 全参数微调 |
|---|---|---|
| 更新能力 | 受目标矩阵及秩限制 | 可调整全部原权重 |
| 显存 | 基座加少量可训练状态,另有激活 | 所有参数的梯度和优化器状态 |
| 训练速度 | 省基座权重梯度及状态更新,仍需主干计算 | 更多权重梯度和状态更新 |
| 任务副本 | 可仅保存 A/B 与配置,依赖匹配基座 | 通常保存完整微调模型 |
| 推理 | 合并后保持原矩阵形状 | 同架构、同精度下基础计算规模相近 |

LoRA 的分支有额外前向计算,冻结主干仍为较早适配器传播梯度;实际速度受激活、反量化、核函数和通信影响,不能承诺快2–10倍。参数及多卡显存推导见 [参数量估算](055-lora-参数量估算.md)。

### 效果差距与选择

当任务需要的更新超出当前秩或未适配模块,数据充分且优化正确时,全参可能更好;LoRA 在小数据下也可能因约束而泛化更好。垂直领域标签、r=64或样本量都不是“必须全参”的判据。先排除坏数据与训练错误,比较更大r、更多目标层,再以全参为对照,同时评测目标质量、遗忘与成本。

秩和学习率的诊断见 [超参数调优](031-lora-超参数调优.md);AdaLoRA 按重要性分配秩,DoRA 分离幅度与方向,都应作为受控候选。QLoRA 主要缓解基座存储瓶颈,不保证提升能力。Adapter/软提示的比较见 [原理与秩选择](002-lora-原理与秩选择.md)和[LoRA 与 Prompt Tuning](020-lora与prompt-tuning.md)。

### 切换、合并与衔接

单任务可预先合并 $W'=W_0+sBA$,去掉分支;多任务保留共享基座,按请求切换匹配的适配器,需考虑加载、批处理和额外算子开销。合并应核对基座版本、缩放与目标层,量化时另验再量化误差。

多个适配器可尝试 $W_0+\sum_i c_is_iB_iA_i$,但任务可能干扰,组合秩可能增长;分别平均 A 和 B 不等于平均增量。先 LoRA 后全参时,可合并所得有效权重再解冻并重新配置优化器和学习率;这只是训练衔接,不保证胜过同预算直接全参。适配器可插拔也不意味着能跨不同基座无条件迁移。
