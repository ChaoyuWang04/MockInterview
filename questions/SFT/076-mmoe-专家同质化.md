## 题目

在多任务学习中，MMoE模型常出现专家网络同质化现象（即多个专家网络输出或功能趋向一致），请深入分析该现象的成因，并列举至少两种有效的缓解策略，说明其作用机制。

## 要点

- 输出相似与门控集中是两种可同时出现的现象
- MMoE原本就有任务独立门控
- 多样性约束与共享/私有结构分别针对不同问题
- 诊断包含表示、门控、梯度和消融

## 答案

**专家输出趋同是同质化,门控长期集中到少数专家是路由塌缩;二者相关但不能混为一谈。** 标准 MMoE 已有每任务独立门控,通常把所有专家的输出做稠密加权,不是天然的 top-k 稀疏计算。

同质化可能来自相同结构和相似梯度使专家学到重复函数、任务确实需要相同特征,或早期门控偏好使部分专家更新不足。梯度冲突只是可能因素,不能仅凭专家相似就断定发生了负迁移。

### 缓解与检测

| 方法 | 作用机制 | 边界 |
|---|---|---|
| 专家多样性约束 | 对归一化输出的相关性平方加小惩罚,减少重复表示 | 直接压原始内积可能靠缩小范数或反向取巧;过强正交会破坏有益共享 |
| 调节门控使用 | 监控平均门控质量,适当熵正则、门控噪声或专家 Dropout,让弱专家获得训练机会 | 稠密 MMoE 的“均衡”主要是梯度/贡献均衡;均匀使用不保证输出不同 |
| 共享与私有专家 | 保留共享能力,给冲突任务独立容量,例如 PLE | 更多参数和成本,需消融确认收益 |

若平均门控分布为 $\bar g_j$,最小化 $\sum_j\bar g_j\log\bar g_j$ 会鼓励总体使用更均匀;它不等于要求每个样本都均匀混合。应联合查看任务/样本级门控熵、专家输出相似度或 CKA、各专家梯度范数,再移除单个专家测试指标是否变化。只看门控直方图不能判断功能是否重复。

### MMoE 与 LLM MoE

二者都有专家和门控。MMoE 的门控按任务选择共享表示;常见 LLM 稀疏 MoE 按 token 选择少数 FFN 专家,还涉及容量、通信和实际计算负载。任务专用与共享的平衡可通过门控输入、共享/私有专家数量及损失权重调整,具体结构见 [MMoE、PLE 与 ESMM](042-mmoe-ple-esmm.md)。
