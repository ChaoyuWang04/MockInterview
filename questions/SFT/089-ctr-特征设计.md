## 题目

在构建点击率（CTR）预估模型时，通常会使用哪些类型的特征？请举例说明用户、物品和上下文特征的具体应用。

## 要点

- 每类给出具体特征,说明表示什么
- 历史统计严格使用请求发生前的数据
- 区别类别embedding与连续值变换
- 手机场景示例作为设计候选,不冒充内部事实

## 答案

**CTR 特征应描述“谁在什么条件下看到什么”,用用户、物品和上下文三类信息共同估计点击概率。** 所有特征必须在预测时可得,历史统计尤其不能包含当前点击或未来反馈。

| 类型 | 例子 | 提供的信号 |
|---|---|---|
| 用户 | 最近点击类目、过去活跃频次、长短期行为表示 | 当前兴趣、兴趣稳定性与使用习惯 |
| 物品 | ID/类目、标题图片表示、价格与上架时长 | 身份、内容、价值和新鲜度 |
| 上下文 | 请求时段、入口/页面、设备与网络状态 | 本次访问目的及使用条件 |

还可加入平滑后的历史 CTR、用户价格偏好与当前价格的交叉、用户历史与候选内容相似度。历史 CTR 要限定过去时间窗并平滑小样本统计;目标编码的防泄漏见 [目标编码与独热编码](060-目标编码与独热编码.md)。页面位置可能携带展示策略偏差,需确保训练与线上使用位置的方式一致。

### 稀疏 ID 与冷启动

高基数 ID 可用 embedding 查表、频次门槛与未知桶、哈希或共享属性表示,在容量与碰撞之间取舍;不能把任意整数 ID 当作有大小关系的连续数。连续量可做对数变换、标准化或分桶,选择依赖长尾程度和模型,见 [数值特征缩放](074-数值特征缩放.md)。

新用户缺少行为时,用可靠的当前上下文、已有偏好与总体先验回退,同时保留缺失标记;新物品可依赖内容、类目和供给属性。需单独评估新用户/新物品切片,不能拿老用户平均表现替代冷启动验证。

### 手机场景的候选设计

以手机应用商店、浏览器或负一屏为例,可比较入口、请求时段、系统版本、网络类型及当前页面主题等上下文,观察同一候选在不同访问目的下的点击变化。这是待验证的设计方案,不是已知 OPPO 内部实现。逐项做消融,同时检查线上可用率、延迟、漂移和训练服务一致性,避免仅因有字段就全部加入。
