## 题目

请系统阐述大语言模型在预训练之后的后训练(Post-training)完整流程,详细说明监督微调(SFT)、奖励建模(Reward Modeling)和基于人类反馈的强化学习对齐(如 PPO)等关键阶段的目标、数据形式、技术实现及其在模型对齐中的作用。

## 要点

- 区分示范学习、偏好建模与基于奖励的策略优化
- 讲清三个阶段的数据、训练对象与依赖关系
- PPO 用优势估计和裁剪控制更新,RLHF 常另加对参考策略的 KL 约束
- 回答为何不能只增加 SFT 轮次,以及稳定性、DPO 与 reward hacking
- 说明这是典型流程,对齐税仍需评测和缓解

## 答案

**典型流程是先用示范教模型回答,再把人类偏好训练成评分信号,最后用评分改进生成策略。** SFT 本身属于后训练。这是 InstructGPT 式路线,并非所有后训练都必须经过三个阶段。

| 阶段 | 数据与目标 | 怎么训练 |
|---|---|---|
| SFT | 指令与示范回答,学习遵循指令 | 对回答 token 做交叉熵训练,可全参或 LoRA |
| RM | 同一 prompt 的优选/劣选回答,学习相对偏好 | 模型输出标量,用成对损失提高优选回答的相对分数 |
| PPO 对齐 | prompt 与策略新生成的回答,提高期望奖励 | 冻结 RM 打分,critic 估计价值,用优势指导策略更新 |

RM 通常从已有语言模型初始化并加评分头。RL 的策略通常从 SFT 模型起步;critic 是预测回报的基线,不等于判定人类偏好的 RM。PPO 裁剪新旧策略的概率比以限制单次更新,RLHF 再用对固定参考策略的 KL 惩罚约束累计偏移;实际 token 级优势可用 GAE 估计,不是都简化为一个终局分数减常数。

### 为什么继续 SFT 不够

多训示范仍在优化“复现这个答案”,没有引入“两个回答谁更好”的新监督。偏好优化可把安全、准确和风格等比较信号纳入目标,但 SFT 并不存在“永远无法超过标注者”的定理,RL 也不保证输出必然更好。

### 稳定性、替代路线与闭环

- **PPO 不稳:**先查偏好标注、RM 过拟合及奖励尺度,再检查优势估计、学习率、裁剪和 KL。DPO 直接用偏好对更新策略,省去显式 RM、critic 和在线采样,但仍会受坏数据及过优化影响。
- **奖励被钻空子:**查看真实任务效果与 RM 分数是否背离;用独立评测、长度/格式去偏、当前策略的新偏好数据、KL 约束及早停共同缓解,不能承诺彻底杜绝。
- **迭代与对齐税:**用新反馈更新数据和评分器,选通过人评及通用能力评测的版本。对齐可能牺牲部分原有能力;混入预训练目标或保留数据可缓解,RLHF 本身不会自动消除这种代价。

### 数据构建与其他路线

SFT 数据要覆盖业务任务、难度和拒答边界,检查答案正确性、去重与模板,按来源拆分留出集。数量不足时先定位覆盖缺口,可引入公开或合成数据并复核,不能用固定数量或配比替代质量评估。偏好数据对同一问题采多个回答,盲化候选来源、随机交换次序、统一标注标准;复核分歧并防长度/格式偏置,按 prompt 分组避免泄漏。

拒绝采样可用 RM 或规则筛选候选,再用胜者做 SFT;仅在推理时挑选 best-of-N 不更新权重。DPO 直接利用偏好对,适合已有离线反馈的场景;PPO 可在当前策略上持续采样、利用外部奖励,更适合需要在线探索且评分可靠的情形,没有“效果上限必高”或“必须RLHF”的通则。IPO 用有限分差目标减少过优化倾向,细节见 [DPO 数据与调参](033-dpo-数据与调参.md)。

SFT 和偏好阶段按验证收益决定顺序及规模,不能按统一比例分配;基础任务未学好先补示范,偏好区分不足再补对照。公开/自建选择、采样标注与比例调整见 [SFT 与 DPO 数据衔接](049-sft与dpo-数据衔接.md)。

### 常见落地边界

- **为什么 RM 常用成对排序:**不同标注者对“7 分还是 8 分”的尺度很难统一,在同一 prompt 下选 A 还是 B 更容易校准。代价是只能学到相对偏好,仍会受顺序、长度和标注群体偏差影响。
- **RL 数据少会不会过拟合:**会。PPO 每轮虽可重新采样,但 prompt、RM 和任务分布都可能很窄。要同时留出 prompt、人评切片和通用能力集,观察 RM 分数上涨是否伴随真实质量或分布外能力下降。
- **能否减少人工标注:**可用规则验证器、AI 反馈、用户行为或合成偏好扩量,但先定义它们代表什么目标,抽样做人审并检查偏差。没有可靠人工偏好时,不能把自动分数直接叫“人类反馈”。
- **RLHF 能否消除幻觉:**不能保证。事实核验奖励、引用检查和领域评测可降低特定错误,却也可能被策略钻规则漏洞;上线仍需检索、校验与拒答机制。
- **工程成本怎么降:**先用 DPO 等离线方法建立基线;必须在线探索时再上 PPO/GRPO。共享底座、参数分片和高吞吐 rollout 能降成本,但算法选择应由反馈形态决定,不能只按显存多少决定。
