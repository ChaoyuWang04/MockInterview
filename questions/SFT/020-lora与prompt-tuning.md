## 题目

请系统比较 LoRA 与 Prompt Tuning 两种参数高效微调方法的技术原理、参数更新机制、资源消耗、迁移性能、优缺点及其典型适用场景,并分析二者在实际应用中对模型性能与训练效率的权衡。

## 要点

- LoRA 学低秩权重增量,Prompt Tuning 只学输入端连续提示向量
- 两者冻结基座,仍需要通过基座反向传播训练信号
- 比较参数存储、合并能力、前缀带来的推理开销与基座依赖
- 回答 100 个任务的成本、秩选择和混合方案,不编固定性能结论

## 答案

**LoRA 改变网络内部的线性变换,Prompt Tuning 通过可学习的输入向量引导同一个冻结模型。** 后者的 soft prompt 是连续参数,不同于手写文字提示,也不同于在各层提供前缀状态的 Prefix-tuning。

| 维度 | LoRA | Prompt Tuning |
|---|---|---|
| 更新位置 | 选定矩阵的增量 $sBA$ | 输入端 $m$ 个提示向量 |
| 参数量 | 所有目标层合计 $N_L=\sum_j r_j(d_j+k_j)$ | $md$,d 为嵌入维度 |
| 训练资源 | 少存梯度和优化器状态,仍需基座计算 | 任务参数通常更少,仍需反传到提示向量 |
| 推理 | 可并入原矩阵;保留分支便于切换 | 保留额外提示位置,有注意力与状态开销 |
| 适配空间 | 调整多个中间层,容量受目标层和秩控制 | 只从输入端调节,效果更依赖基座和任务 |

两者都适合共享基座的多任务部署,也都依赖匹配的基座和 tokenizer,不能保证直接跨模型迁移。Prompt Tuning 原论文在特定 T5 实验中发现规模增大可缩小与全参微调的差距,不等于任何任务上都优于或弱于 LoRA。普通仅收文字的黑盒 API 不提供软提示参数与梯度接口,不能直接完成标准 Prompt Tuning。

### 原题追问

- **100 个任务怎么比?** 若一个参数存 b 字节,共享基座之外分别保存 $100bN_L$ 和 $100bmd$ 字节。举例,m=20、d=4096、b=2 时,100 份软提示约 16.4 MB。若把每份 LoRA 都合并成完整模型则不再享有这份共享存储收益;保留分支时要计实际运行开销,软提示则增加上下文开销,吞吐应按同一负载测量。
- **r 怎么选?** 在相同目标层和数据下比较候选秩,记录缩放与学习率,用效果和资源一起选择;没有通用最优值。
- **能否混合?** 可以同时训练软提示与 LoRA,或按任务分别加载。它扩大可调空间,也增加参数与调参成本;须与两个单独方案作对照,不能预设叠加就更好。
