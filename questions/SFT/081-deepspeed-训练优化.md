## 题目

DeepSpeed 在大模型训练中提供哪些关键能力?它怎样缓解显存瓶颈,如何选择 ZeRO、卸载和并行组合,又该怎样排查训练变慢或通信超时?

## 要点

- 按模型状态、激活和通信开销区分优化手段
- ZeRO 分片、CPU/NVMe 卸载都存在代价,省显存不等于加速
- 区分并行算法可以组合与具体框架支持的组合
- 用实测峰值、吞吐与最先出错的进程定位问题

## 答案

**DeepSpeed 把分布式训练中的显存管理、梯度处理和优化器更新封装进训练引擎。选功能时先问“哪部分放不下、哪一步最慢”,不用一开始就把所有开关打开。**

| 能力 | 解决什么 | 需要付出的代价 |
|---|---|---|
| ZeRO 分片 | 减少各数据并行副本重复保存的模型状态 | 高阶段需要更频繁地取回参数;三阶段原理见 [ZeRO 分片与选型](013-zero-分片与选型.md) |
| CPU 卸载、ZeRO-Infinity | 用主机内存或 NVMe 扩大可用存储 | CPU 更新、PCIe 搬运和磁盘读写可能拖慢 GPU |
| 激活重算、梯度累积 | 分别减少保留的激活、降低单次微批大小 | 增加计算,或增加一次更新前的前反向次数 |
| 混合精度、融合计算、通信重叠 | 减少数据量与调度开销,隐藏部分通信等待 | 依赖数值范围、算子支持和可用于重叠的计算窗口 |
| TP、PP、专家等并行能力 | 把计算或模型结构分给多卡 | 有通信、流水线空闲及接入限制;原理见 [并行方式全景](../AI%20Infra/091-并行方式全景.md) |

### ZeRO-2、ZeRO-3和卸载怎么选

ZeRO-2 能在目标序列长度、微批和峰值缓冲下装得下,就先测它;它省去了 ZeRO-3 取参数的部分通信,**可能更快,但不是必然**。ZeRO-3 省出的空间如果能换来更合适的微批、减少重算,总吞吐也可能反超。

原始 ZeRO-Offload 主要把优化器状态和更新移到 CPU;ZeRO-Infinity 在 ZeRO-3 基础上利用 GPU、CPU、NVMe 多级存储,用预取与分块搬运缓解等待。NVMe 负责存储,不执行优化器计算。当每步必须搬的数据很多、计算窗口很短、磁盘或 PCIe 带宽不足时,预取也藏不住开销。

优化顺序是先量出 GPU 计算、CPU 更新、搬运与磁盘等待各占多少,再调分块、缓冲、预取、主机内存和设备带宽。固定内存有利于异步搬运,但不能无限分配;缓冲越大也越吃内存。

### 和 Megatron、PP、FSDP怎么比较

ZeRO 管模型状态如何保存,TP/PP 管计算如何切开,不是只能二选一。决定 TP/PP/DP 时先保证每卡能装下,再把频繁通信尽量放在快互联内,测不同组合的吞吐和气泡;没有通用的参数量分界线。

**组合还要看实现。按本地 2026-04 DeepSpeed 源码快照,其流水线引擎不支持 ZeRO-2/3。** 所以不能把“ZeRO-3 + PP”直接作为该引擎的配置建议。对支持某种组合的实现,更多微批可能摊薄气泡,却也影响激活峰值和调度成本;具体账本见并行方式全景。

FSDP 与 ZeRO 有相近的状态分片思路,实际选择还要比较卸载能力、保存恢复、生态集成与实测性能。跨卡带宽弱、参数反复聚合很多时,ZeRO-3 可能更慢;TP 也有频繁通信,不能因此就认定换 TP 必然提速。

### 通信超时怎样排查

先找所有进程中**最早的异常**:可能是一张卡先 OOM、数据读取卡住,其他卡才在集合通信中超时。再检查各进程是否进入相同顺序的通信、张量形状是否一致,以及保存模型等操作是否要求全部进程参与。应用侧没有异常后,用最小多卡通信测试排查网卡选择、链路、驱动与共享内存。调大超时只适用于已确认的慢操作,不能修复缺席的进程或不匹配的通信。
