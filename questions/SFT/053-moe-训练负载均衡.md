## 题目

MoE 训练时,少数专家承担大量 token、其他专家很少被选中,会有什么影响?可以从损失函数、路由机制和容量管理上怎样改善?

## 要点

- 热门专家形成计算与通信热点,冷门专家训练不足
- 解释辅助均衡损失为什么能改变后续路由
- 容量上限、噪声探索与偏置调节解决不同问题
- 同时检查模型质量、负载和耗时,避免只追求均匀

## 答案

**负载不均会让一部分专家忙不过来、另一部分学不到东西。** 同步训练常要等最慢的设备;有容量上限时,热门专家还会出现 token 溢出。冷门专家长期缺少更新,总参数很多却没被有效利用。热门专家的权重不会因被调用更多次就自动变大,增长的主要是待处理 token、激活与通信缓冲。

### 辅助损失怎样起作用

以 Top-1 的 Switch 形式为例:

$$
L_{\text{balance}}=\alpha N\sum_{i=1}^{N} f_iP_i
$$

$N$ 是专家数,$f_i$ 是本批实际分给专家 $i$ 的 token 比例,$P_i$ 是路由器对该专家的平均概率,$\alpha$ 控制均衡项的力度。实际计数不反传,梯度经过概率 $P_i$:专家越忙,继续给它高概率的代价越大。主任务损失仍负责判断“哪个专家有助于答对”,两者一起训练。

$\alpha$ 太小压不住热点,太大可能为平均分配而牺牲匹配质量。应联合看各层专家负载、溢出比例、验证损失与吞吐,不能只把负载直方图调平。不同公式的归一化不同,系数不能直接照搬。

### 其他手段解决什么

| 方法 | 改了哪一步 | 边界 |
|---|---|---|
| 路由噪声 | 扰动分数,给冷门专家探索机会 | 不保证严格均衡,噪声太大也会损害选择 |
| 专家容量 | 对单个专家接收的 token 数设上限 | 超额 token 怎样丢弃、旁路或改派取决于实现;不能免费保留质量 |
| 动态负载偏置 | 过载专家降选择分数,闲置专家升分数 | 偏置更新速度与统计窗口需调节;选中后仍可用原始分数加权 |
| Expert Choice | 每个专家从 token 中挑固定数量 | 专家工作量更可控,但每个 token 被多少专家选中会变化 |
| Sinkhorn 类分配 | 先把软分配调整得更均衡 | 后续硬 Top-K 不自动保证最终每个专家 token 数相同 |

按本地 2026-04 Megatron-LM 快照,其 Sinkhorn 路径是在软归一化后按 token 取 Top-K,因此需要继续测硬路由的实际负载。DeepSeek 的辅助损失自由均衡采用动态偏置;“没有这项均衡损失”也不意味着任何模型都完全不使用其他辅助项。

### 相关真题追问

**Top-1 和 Top-K 有什么取舍?** Top-1 每个 token 只算一个路由专家,计算和分发更少;更大的 K 增加专家组合与计算量,不保证更均衡或质量必然更好。

**已经严重倾斜了怎么处理?** 先排除计数错误、数据偏科和路由数值异常,检查死专家是否仍有学习机会,再调整均衡系数、偏置或探索。必要时回退到较早的健康检查点;直接重置专家会丢掉已学能力,不能当作无代价修复。

**通信与推理热点怎么办?** 按实测拓扑减少重复跨节点搬运,用独立计算重叠通信;推理可比较热点专家副本与放置调整,但都增加资源或管理成本。训练均衡不能保证线上均衡,详见 MoE并行与DeepEP 篇。

**细粒度与共享专家为什么有用,MoE什么时候更划算?** 更小的专家给出更灵活的组合,共享专家承担通用模式、减少路由专家重复学习;这不直接保证负载均衡。在需要较大模型容量、显存与互联充足且能形成合适批量时,MoE 较可能用较少激活计算达到目标质量;小批低时延或互联薄弱时,Dense 可能更合适。结构与成本详见 MoE基础 篇。
