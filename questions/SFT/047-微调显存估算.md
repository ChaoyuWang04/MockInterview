## 题目

大模型微调的显存主要花在哪些地方?请结合参数量、精度、batch size 和序列长度给出估算方法,说明全参改成 LoRA 后哪些占用会变,以及 OOM 时怎样排查。

## 要点

- 分清参数、梯度、优化器状态、激活与临时缓冲
- 给每项写明精度和字节数,避免重复计算主权重
- LoRA 减少可训练状态,冻结基座及反向激活仍要存
- 根据实际峰值选择重算、分片或卸载

## 答案

**先算模型状态的固定账,再补激活、临时缓冲和运行时开销。参数量能估出第一部分,不能单独决定训练总显存。**

设全参模型有 $P$ 个参数,采用 16 位参数和梯度、FP32 主权重与 Adam 两份状态,不做分片和卸载:

| 项目 | 字节数 | 为什么需要 |
|---|---|---|
| 训练参数 | $2P$ | 用于前向、反向计算 |
| 参数梯度 | $2P$ | 保存当前更新信号 |
| FP32 主权重 | $4P$ | 用高精度累积较小的参数更新 |
| Adam 一阶、二阶状态 | $4P+4P$ | 分别跟踪梯度和梯度平方的滑动平均 |

这些合计 $16P$ **字节**,不含激活等。假设 $P=7\times10^9$,就是 112 GB,约 104.3 GiB。若梯度累积用 FP32、没有独立主权重,或优化器状态采用其他精度,要逐项重算。纯 FP32 参数、梯度加两份 FP32 Adam 状态也恰好是 $16P$,但组成不同。

### batch和序列长度怎样影响显存

这里看的是**一次前反向的微批大小**,不是累积多步后的全局 batch。激活包括各层反向要用的中间张量;粗略包含随 $bshL$ 增长的部分。普通注意力若显式保存注意力矩阵,还可能有随 $ba s^2L$ 增长的部分。$b,s,h,L,a$ 分别是微批、序列长度、隐藏维、层数和头数;具体常数取决于模型与实现。

FlashAttention 避免保存完整注意力矩阵,重算减少长期保存的激活。因此不能把所有实现的激活都套成同一个平方公式,也不能承诺一个固定的“每条样本占几 GB”。总量还要考虑 logits、算子工作区、通信缓冲以及分配器和其他 CUDA 占用,最好在目标长度下测一次完整更新的峰值。

### 换成LoRA后怎么算

设冻结基座参数量为 $P_f$,LoRA 可训练参数量为 $P_t$。仍按上表的混合精度假设,模型状态约为:

$$
M_{\text{状态}}\approx2P_f+16P_t\quad\text{字节}
$$

基座保留 16 位权重,只有可训练部分需要梯度、主权重与 Adam 状态。例:冻结 7B 基座、另有 10M 可训练参数,这部分约 14.16 GB。**这不是总训练占用。** 反向仍需经过模型,激活不会按可训练参数比例一起消失。QLoRA 可继续压缩基座存储,但要另计量化元数据和计算临时区;方法原理见 LoRA 篇。

### 显存还不够怎么办

| 手段 | 主要省哪项 | 代价或边界 |
|---|---|---|
| 减微批、用梯度累积维持更新规模 | 激活峰值 | 多次前反向,要正确归一化有效 token 的损失 |
| 激活重算 | 保存的激活 | 反向重做部分前向;激活占大头时更有价值 |
| ZeRO-1/2/3 | 依次分片优化器状态、再梯度、再参数 | 通信与临时聚合开销;详细账本见 [ZeRO 选型](013-zero-分片与选型.md) |
| LoRA | 可训练状态 | 限制更新空间,任务效果需验证 |
| CPU/NVMe 卸载 | 移走部分状态 | 保留全参训练能力,但可能受主机更新与搬运速度限制 |

选 LoRA 还是卸载先看任务能否接受受限更新,再看训练吞吐预算;两者也可能组合。OOM 时先定位发生在加载、前向、反向还是首次优化器更新,对照最长序列、微批和活张量峰值。`reserved` 大于 `allocated` 只说明分配器持有更多内存,**差值不等于碎片**;再看快照和外部占用。不要把缓存清空当成减少活张量的办法。
