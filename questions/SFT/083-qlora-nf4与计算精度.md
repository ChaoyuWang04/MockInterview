## 题目

QLoRA 为何将 NF4(NormalFloat 4-bit)存储与较高精度计算结合?请从数值分布、存储开销、硬件兼容性和微调稳定性解释其设计,并比较 BF16 与 FP16 计算、双重量化及分块大小的取舍。

## 要点

- 订正来源前提:原论文计算精度为 BF16,NF4 是 NormalFloat
- NF4 是非均匀码本,不能承诺对任意分布保持信息熵
- 双重量化压缩缩放常数,不是4-bit加16-bit计算
- 按相同模型与任务实测格式误差,区分裸权重和训练总显存

## 答案

**NF4 负责省存储,BF16/FP16 负责执行计算,两者分工不同。** 原论文使用 BF16 计算,并非必须“NF4+FP16”;NF4 的名称是 NormalFloat,不是归一化浮点。冻结基座采用低位码本,训练时反量化所需权重,用较高精度完成矩阵乘并把梯度传给 LoRA 参数。

### NF4、双重量化与块大小

NF4 用16个非均匀取值近似标准正态分布,零附近更密、尾部更疏。权重按块缩放后映射到码本;“适合近似正态权重”不等于任何层都正态,也不保证无损或保留全部信息熵。INT4 的均匀网格、FP4 的浮点网格与 NF4 如何比较,要固定块大小、缩放和权重分布,看重构误差及下游质量,不存在统一的15%或20%优势。

双重量化是把第一轮量化的缩放常数再次量化。每64个权重配一个FP32常数时,元数据为0.5 bit/权重;原论文进一步量化常数约省0.37 bit/权重。块更小通常更能适应局部分布和异常值,却增加元数据与处理开销;块更大更省元数据,但可能被异常值拉大范围。64是配方选择,不是普适最优值。

### 为什么不直接换 INT8、FP8 或 FP16

INT8/FP8 每权重的编码位数约为4-bit的两倍,可能换得更小误差或更便利的计算路径;当显存允许、质量或硬件支持更重要时值得比较。NF4 通常通过反量化使用硬件支持的高精度矩阵乘,不能假设 GPU 原生直接计算 NF4,也不能承诺固定反量化延迟。

BF16 与 FP32 指数范围相近,较不易溢出;FP16 有更细的尾数但范围较窄,训练可能需要损失缩放。两者谁更合适取决于硬件和数值行为,不是 FP16 精度全面更高。A/B 的存储精度、计算精度和优化器状态精度也应分别声明。

### 怎样验证效果

在相同数据、目标层、秩和预算下比较高精度 LoRA 与 QLoRA,先测量化基座掉点,再测微调收益、保留能力和峰值显存。原论文部分任务接近16-bit微调的结果不能当作固定精度差;Guanaco 的某项99.3%成绩也不是相对 LoRA 的精度保留率。分页优化器管理内存峰值,不会修复量化误差;65B单卡48GB需论文具体配置,不能仅由裸4-bit权重推出。
