## 题目

请总结对大模型进行微调时的关键建议,涵盖数据准备、任务设计、训练策略、超参数选择、参数高效方法、显存优化、评估机制和避免灾难性遗忘等方面。结合实际案例说明这些因素如何影响微调效果。

## 要点

- 先确定业务验收及新旧任务基线,再调训练配置
- 数据内容、聊天模板和损失位置先用小样本验证
- 按瓶颈选择全参、LoRA、量化、重算与分片
- 当前任务泛化差与旧任务退化要分别评估,两者可以同时发生

## 答案

**关键是任务与数据对齐,并用独立评测证明每次训练调整有效。** 只报告 loss 下降或照搬一套超参数,都不能说明微调成功。

### 实施顺序

1. **定义验收**:明确任务边界、格式、正确性和可接受的旧能力掉点,固定新旧验证集,记录基座结果。
2. **检查数据链路**:清洗与分层采样后,解码训练样本核对角色、截断、标签和 EOS。先验证少量样本能学到目标,再扩大训练。
3. **比较训练配置**:从可复现基线出发,分别试学习率、有效 batch、训练量和可训练范围。batch 不是越大越好,梯度累积也要结合更新次数和吞吐评估。
4. **定位资源瓶颈**:优化器状态重可考虑 PEFT/ZeRO,激活重可比较重算、序列长度和微批;量化减少基座存储,仍需核验效果。
5. **保存与验收**:保留数据版本、模板、配置和检查点,同时看下游指标与新旧验证,再决定早停和回滚。

### LoRA、全参与 QLoRA 怎么选

LoRA 适合训练状态受限、需要保存多份任务增量的情况;全参允许更充分调整,但成本和遗忘风险要实测。秩从预算允许的小范围比较,当新任务欠拟合且其他瓶颈已排除时再扩大,没有固定的最佳 r 或 alpha/r 比例;原理见[LoRA](002-lora-原理与秩选择.md)。

QLoRA 冻结以 4-bit 存储的基座,计算时使用较高精度表示并训练 LoRA。应比较原基座、量化基座与微调模型在关键任务上的差异;若量化误差或数值敏感性带来无法接受的退化,考虑更高精度。不能按固定任务名单判定 4-bit 必可用或必不可用。

### 效果下降如何复盘

低质数据再多也应先抽样找错误类型、修订或筛查,同时保留有效难例,详见[数据质量与噪声](037-数据质量与噪声.md)。通用能力掉点先排除模板、评测和量化变化,再查领域配比与更新强度,比较回放和正则,见[遗忘对策](028-灾难性遗忘与对策.md)。

**过拟合看新任务训练集与验证集的差距,遗忘看固定旧任务相对训练前的退步**,两者可同时出现。假设标题生成只会复读促销话术,可检查重复样本并补非促销场景,在同预算下比较新任务泛化和旧能力;这是设计示例,实际面试应补自己的真实基线、改动与结果。

### 调参复盘与阶段选择

loss 震荡先检查异常样本、有效标签、学习率及梯度范数,区分正常批次波动、数值溢出和持续发散,按[loss 异常诊断](054-训练loss-异常诊断.md)定位后再改配置。不要照搬固定分位长度截断、数据比例或“alpha=2r”;截断必须保留任务依据,rank、alpha 和学习率的联合选择见[LoRA 超参数](031-lora-超参数调优.md)。

混入通用指令或原始文本时分开定义目标和监督范围,用新旧验证集调权,配比见[多源数据](077-多源数据配比.md)。SFT 已满足目标可以结束训练;需要进一步改善偏好取舍时再比较 RLHF/DPO,见[预训练与 SFT](029-预训练与sft.md)。真实复盘要交代数据与配置版本、对照预算和测量结果,不能把参考示例写成本人的实施经验。

监督微调、实验基线、有效 batch、量化、过拟合、遗忘评估。

## 追问

- LoRA 的 rank 一般怎么选,什么场景需要调大?
- 如果微调后模型在通用任务上下降明显,怎么排查和解决?
- QLoRA 的 4-bit 量化对模型效果影响大吗,什么情况下不建议用?
- 如果数据质量不高但量大,应该怎么处理?
- LoRA 和全量微调分别适合哪些场景?
- 如何判断微调后的模型是过拟合还是知识遗忘?

- 训练 loss 震荡或无法收敛时如何排查?
- SFT 与预训练或通用数据的混合比例如何设置?
- rank 与 alpha 怎么联合选择,是否有固定经验公式?
- SFT 与 RLHF 有何关系,什么时候只做 SFT 就够了?
