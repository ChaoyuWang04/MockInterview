## 题目

什么是多模态 RAG？请以界面截图问答为例，说明图像解析、知识库、跨模态检索和生成怎样组成完整系统，以及它相对文本 RAG 多了哪些难点。

## 要点

- 图像、文字、位置和文档出处要形成可追踪的统一记录
- 可分别检索 OCR 文本、视觉向量和结构化组件，再融合结果
- 生成模型需要看到与问题相关的区域和证据，而不是整库素材
- 重点评估定位、跨模态对齐、引用支持、延迟与权限

## 答案

**多模态 RAG 把可检索证据从纯文本扩展到图片、表格、音频或视频，并让生成模型同时使用这些证据。** 对界面截图，输入通常是截图加用户问题，输出是组件识别、功能解释或操作指引，并附对应区域和文档来源。

```mermaid
flowchart LR
  A[截图与问题] --> B[OCR 检测与版面解析]
  B --> C[组件 文本 位置记录]
  C --> D[文本与视觉索引]
  D --> E[跨模态召回与重排]
  E --> F[VLM 基于证据回答]
```

离线时，把产品文档、组件说明、历史截图和操作规则拆成可追踪单元，保存原图区域、OCR 文本、组件类型、页面版本和权限。可以用文本 Embedding 检索说明文档，用视觉或图文联合 Embedding 检索相似区域，也可以按组件名、页面版本做结构化过滤。

在线时先识别截图中的文字、控件和空间关系，再根据问题选择文本检索、图像检索或两者并行。不同检索分数不能直接相加，可用排名融合或 Reranker 统一排序。最后只把相关区域、OCR 结果和说明文档交给 VLM，并要求回答引用具体组件与来源。

它比文本 RAG 多出三类难点：OCR 或检测错误会污染后续检索；不同模态必须对齐到同一个对象；高分辨率图片和视频会迅速消耗上下文与算力。评测因此要分开看组件定位、OCR、检索命中、跨模态对应、答案正确与引用支持。界面更新后还要让旧截图和旧说明按版本失效。

## 知识点

OCR、版面解析、视觉语言模型、跨模态 Embedding、区域级检索、分数融合、版本化和证据引用。


## 追问

- 高分辨率长截图怎样减少视觉 token 和延迟？
- 界面版本变化后怎样避免引用过期组件说明？
