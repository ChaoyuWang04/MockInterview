## 题目

moe 这里的并行方式可以怎么并行?并行起来的必备条件是啥?

## 要点

- 先说清"不重叠等于串行等通信":四步是一条纯串行依赖链
- 和 DP 梯度同步的本质区别:MoE 里没有第三件事可干
- 三个条件:拆 batch(前提)+ dispatch–GEMM + combine–GEMM
- 理想值 $\max(t_{\text{comm}}, t_{\text{gemm}})$,差距就是重叠质量的度量
- 隐藏条件:重叠期间通信要少占算力

## 答案

### 不重叠 = 串行等通信

MoE 这一层的四步是一条**纯串行的数据依赖链**:dispatch 没到齐就没法算,GEMM 没算完就没得寄回。不做任何处理时

$$
t_{\text{layer}} \;=\; t_{\text{dispatch}} + t_{\text{gemm}} + t_{\text{combine}}
$$

三段首尾相接,**两趟通信全裸露在关键路径上**。

这里和 DP 的梯度 all-reduce 有个本质区别:反向传播是逐层产出梯度的,通信天然有**别的层**的计算可以盖;而 MoE 的 dispatch 和紧随其后的 GEMM 之间**没有第三件事可干**。想重叠,只能人为再造一股独立的工作流——这就是"拆 batch"这个条件的来源。

### 三个必备条件

1. **拆 batch(前提)**:把一批请求切成两个 micro-batch,让它们错开一拍。DeepSeek-V3 的 prefill 用的就是双 micro-batch 交替,decode 侧则把 attention 拆成两步、凑成一条五阶段流水线
2. **dispatch–GEMM 重叠**:A 批在飞的时候算 B 批
3. **combine–GEMM 重叠**:A 批的结果在回程的时候算 B 批

```python
# 单批次是 dispatch → gemm → combine 三段串行;拆成两个 micro-batch 后:
ha = dispatch_start(a)
for layer in moe_layers:
    hb = dispatch_start(b)           # b 在飞 —— 同时算 a
    ya = grouped_gemm(wait(ha))
    ca = combine_start(ya)           # a 在回程 —— 同时算 b
    yb = grouped_gemm(wait(hb))
    cb = combine_start(yb)
    a, b = wait(ca), wait(cb)
    ha = dispatch_start(a)           # 下一层的 a 提前出发
```

三条都做到,理想情况下这一层的耗时从"三段相加"变成 $\max(t_{\text{comm}},\ t_{\text{gemm}})$——通信被完全藏进计算里(或反过来),谁长听谁的。真实系统达不到这个理想值,**但差距有多大,就是重叠做得好不好的度量**。

### 一个常被漏掉的隐藏条件

**重叠期间通信要少占算力。** 通信 kernel 也占 SM,如果它吃掉三成 SM,"重叠"换来的收益要先扣掉这三成。这正是 DeepEP 给高吞吐 kernel 划 SM 配额、给 decode 走"不占 SM 的 hook 式重叠"的价值所在。

## 知识点

四步串行依赖链、与 DP 梯度通信的区别、拆 micro-batch 是前提、两处重叠、理想值 $\max$ 式、通信占 SM 的隐藏成本。
