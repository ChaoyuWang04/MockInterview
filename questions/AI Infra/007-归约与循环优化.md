## 题目

warp reduce、循环展开、减少分支、ping-pong 双缓冲这几个优化手段分别为什么能提速?各自的代价是什么?

## 要点

- warp reduce 靠 shuffle 直接读同 warp 别的线程的寄存器,省掉 shared 与 block 级同步
- block 级归约是两级结构
- 循环展开的三层收益,以及寄存器溢出这个代价
- 减少分支的真实含义是别让 if 在 warp 内部劈叉
- 双缓冲提供的是「同一线程内部的重叠」,不依赖 occupancy

## 答案

| 技巧 | 为什么有效 | 代价 |
|---|---|---|
| **warp reduce** | shuffle 指令直接读同 warp 另一线程的寄存器,归约免走 shared、免 `__syncthreads()` | 只在 warp 内有效,跨 warp 还要第二级 |
| **循环展开** | 省循环开销 + 提高指令级并行 + 给编译器优化空间 | 寄存器用量上升,过头会 spill 到 local memory |
| **减少分支** | 同 warp 走不同分支时两条路径**串行执行、时间相加** | 有时要重排数据,或拆成两个 kernel |
| **ping-pong 双缓冲** | 一块 buffer 正在被算,另一块同时在被填,把访存延迟藏进计算 | shared 用量翻倍,occupancy 减半 |

### warp reduce

```cuda
__inline__ __device__ float warpReduceSum(float v) {
    #pragma unroll
    for (int off = 16; off > 0; off >>= 1)
        v += __shfl_down_sync(0xffffffff, v, off);  // 直接读 lane+off 的寄存器
    return v;   // 结果落在 lane 0
}
```

省掉的是:5 轮 shared 读写、5 次 block 级同步、以及那块 shared 空间本身(空间省下来又能提 occupancy)。标准的 block 级归约是**两级**:每个 warp 先内部 shuffle 归约 → 各 warp 的 lane 0 把结果写进 shared(只需 32 个 float)→ 第一个 warp 再 shuffle 归约一次。Volta 之后必须用带 `_sync` 后缀的版本并传 mask(通常 `0xffffffff`),否则会读到未定义值。

### 循环展开的三层收益

1. **省掉循环开销**——每轮的比较、自增、跳转指令没了,循环体越短占比越高
2. **提高指令级并行(ILP)**——展开后相邻几轮互不依赖,可以同时在流水线里跑;对访存尤其重要,能一口气发出多条 load 让延迟互相重叠
3. **给编译器更多空间**——地址计算变常量偏移,累加器常驻寄存器,还能把多次访存合并成向量化访存

所以只有**循环次数在编译期已知的小循环**才值得全展开。

### 减少分支

关键**不是**不能写 if,而是别让 if 在一个 warp 内部劈叉:

```cuda
if (threadIdx.x % 2 == 0)        { do_a(); } else { do_b(); }  // 坏:耗时 = 两分支之和
if ((threadIdx.x / 32) % 2 == 0) { do_a(); } else { do_b(); }  // 好:分支发生在 warp 之间
```

### ping-pong 双缓冲

朴素 tiling 循环是串行的:搬第 k 块 → 同步 → 算第 k 块 → 搬第 k+1 块……搬数的几百个周期里计算单元完全闲着。双缓冲提供的是**同一个线程内部的重叠**——访存指令发出后不立刻等结果,先去计算。它**不依赖 occupancy**,这正是高性能 GEMM(每线程占资源多、驻留 warp 极少)必须用它的原因。Ampere 起有 `cp.async`,数据可从 HBM 直进 shared 不过寄存器;Hopper 进一步用 TMA 做批量异步搬运。
