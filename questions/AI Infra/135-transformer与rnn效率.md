## 题目

从实际计算实现角度比较 Transformer 与 RNN 的计算效率、内存占用、训练并行性、推理延迟和硬件利用率，并说明这些差异怎样影响大规模训练与部署。

## 要点

- 不能只用 $O(n)$ 与 $O(n^2)$ 判断实际速度
- Transformer 训练可并行所有位置，RNN 有沿时间步的依赖
- 区分训练激活、注意力中间量和推理状态
- 长序列、流式推理和硬件特性决定选型

## 答案

**Transformer 单层可能做更多计算，却常在训练时更快，因为所有 token 能组成大矩阵并行计算；RNN 必须沿时间步逐步更新隐藏状态，关键路径更长。**

| 维度 | Transformer | RNN |
|---|---|---|
| 单层计算 | 约 $O(nd^2+n^2d)$ | 约 $O(nd^2)$ |
| 训练并行 | token 位置可并行，适合 GPU/TPU | 时间步有依赖，难全部并行 |
| 长序列内存 | 普通注意力中间量可达 $O(n^2)$；激活也随层数增长 | 通常保存每步状态用于反向，仍随序列增长 |
| 自回归推理 | KV Cache 随长度增长，每个新 token 仍读取历史 K/V | 每步更新固定大小状态，流式延迟稳定 |

因此在中等长度、大 batch 训练中，Transformer 更容易把硬件吃满并扩展到多卡。长序列下，注意力平方计算会成为瓶颈，可用 FlashAttention降低中间量 IO，用滑窗/稀疏注意力改变可见范围；KV Cache 只是推理项，不能算进训练显存。

RNN适合严格流式、低延迟、状态很小的任务，但固定状态也可能压缩掉很早的信息。Mamba、RWKV等结构尝试同时获得可并行训练与递归式推理状态，不过它们不是传统RNN的简单同义词。部署时应按上下文长度、质量目标、设备矩阵算力、内存和批量实测，不能把RNN说成“无限上下文”，也不能说用了KV Cache后Transformer每步是 $O(1)$。
