## 题目

什么是动态量化?什么是静态量化?两者的优点和缺点分别是什么?

## 要点

- 先钉住讨论对象:这组概念说的是**激活的 scale 什么时候确定**,权重的 scale 永远离线算好,不参与这个分类
- 动态 = 推理时按当前这批激活现算;静态 = 离线用校准集统计好、固定写进模型
- 动态精度高但每层多扫一遍激活;静态零运行时开销但怕分布漂移
- 动态的开销不在算力而在访存,通常要和前一个算子融合掉才划算
- W8A8 主流配方是"权重 per-channel 静态 + 激活 per-token 动态"

## 答案

先说清讨论的是什么:**这组概念说的是激活的 scale 什么时候确定**。权重训完就固定,scale 永远离线算好,不进这个分类。

| | 动态量化 | 静态量化 |
|---|---|---|
| scale 何时定 | 推理时按当前这批激活现算(一次 absmax 归约) | 离线用校准集统计好,固定写进模型 |
| 典型粒度 | per-token(天然适配) | per-tensor |
| 精度 | 更高,永远贴合当前输入的分布 | 取决于校准集覆盖得好不好,分布一漂就崩 |
| 运行时开销 | 每层多扫一遍激活求 max,再做一次乘除 | **零** |
| 工程友好度 | scale 是随数据产生的张量,分页/CUDA Graph 下要额外处理 | scale 是模型级常量,天然友好 |
| 适合 | 通用服务、输入分布不可控 | 输入分布稳定、极致压延迟 |

**动态的代价要说到点子上**:开销不在算力,而在**又扫了一遍激活**。对本来就访存受限的算子,这一趟归约通常要和前一个算子融合掉才划算——单起一个规约 kernel 就是白搭一趟 HBM 往返。

**静态的风险也要说准**:它赌的是"线上分布和校准集一致"。scale 定小了截断误差爆,定大了档位全浪费在没数据的区间,而且一旦线上分布漂移(换任务、换语言、上长上下文),没有任何自我纠正的机会。

实践中的分工:

- **激活量化**:W8A8 的主流配方是「权重 per-channel 静态 + 激活 per-token 动态」,精度与可实现性兼顾
- **KV cache**:反过来,vLLM / SGLang / TensorRT-LLM 三家全走静态——因为静态 scale 是模型级常量,分页管理器、CUDA Graph、跨实例 KV 传输对它全都无感

## 知识点

激活 scale 的定时、absmax 归约的访存代价、算子融合、校准集依赖与分布漂移、静态 scale 作为模型级常量的工程优势。
