## 题目

TTFT、TPOT、ITL 分别是什么?TPOT 和 ITL 的关系是什么?

## 要点

- 三个指标的定义要对着一条请求的时间线钉死
- TPOT 的分母减 1 是因为首 token 已计入 TTFT
- 关系一句话:**ITL 是分布,TPOT 是这个分布的均值**
- 什么时候用哪个:看整体用 TPOT,排查抖动看 ITL 的 P99
- 能补一句口径坑:不同工具对 ITL 的定义不一致

## 答案

### 定义

| 指标 | 全称 | 定义 | 测的是什么体验 |
|---|---|---|---|
| **TTFT** | Time To First Token | 请求到达服务端 → 吐出第一个 token | 「点了发送后多久有反应」 |
| **ITL** | Inter-Token Latency | 相邻两个输出 token 之间的间隔,每生成一个就产生一个测量值 | 「流式输出卡不卡顿」 |
| **TPOT** | Time Per Output Token | 除首 token 外的平均每 token 时间 | 「整体读起来有多快」 |
| **E2E** | 端到端延迟 | 请求到达 → 最后一个 token 返回 | 非流式接口的唯一体感 |

对着时间线读就不会记混:**排队 + 调度 + prefill = TTFT**;之后每一步 decode 的实测间隔 = 一个 ITL(共 $N-1$ 个);这些 ITL 的平均 = TPOT;全程 = E2E。

### TPOT 和 ITL 的关系

**ITL 是分布,TPOT 是这个分布的汇总统计。**

$$
\text{TPOT} = \frac{\text{E2E} - \text{TTFT}}{N_{\text{out}} - 1} = \operatorname{mean}(\text{ITL}_1, \dots, \text{ITL}_{N_{\text{out}}-1})
$$

把首 token 之后的总时间除以剩下的 token 数就是平均每 token 花的时间;**分母减 1 是因为第一个 token 已经算进 TTFT,不能重复计**。

什么时候用哪个:

- **看整体体验、做容量规划、算 E2E** → 用 TPOT。它是一个数,能进公式、能横向比较。
- **排查抖动、定位卡顿** → 必须看 **ITL 的 P99**。均值会骗人:200 个 token 里 199 个间隔 20 ms、有一个卡了 2 秒(被抢占重算),TPOT 只从 20 ms 涨到 30 ms 看着还行,用户却实实在在看到停顿两秒。

一句话记法:**TPOT 告诉你「平均多快」,ITL 的尾部告诉你「会不会卡」**,线上告警两个都要有。

### 一个口径坑

不同工具定义不一致:NVIDIA GenAI-Perf 直接把 ITL 定义成平均间隔、等同于 TPOT;vLLM 的指标里逐次间隔直方图和每请求 TPOT 直方图都有;Sarathi-Serve 用的是第三个词 TBT。**标准答法**:概念上 ITL 是逐次测量、TPOT 是它的均值,但工程上有工具把 ITL 当均值用,看报告前先确认口径。

## 知识点

TTFT / ITL / TPOT / E2E 的定义,$\text{E2E} \approx \text{TTFT} + \text{TPOT} \times (\text{输出长度} - 1)$,P99 优先于均值。
