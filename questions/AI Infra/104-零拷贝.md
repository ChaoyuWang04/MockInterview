## 题目

什么是零拷贝?

## 要点

- 答之前先把"朴素路径上到底有几次拷贝"数清楚,否则"零"没有参照
- 两条硬件路径 GPUDirect P2P / RDMA,各消掉其中哪几步
- pageable → pinned 那次拷贝最容易被漏,而且它还会让异步失效
- 最该记住的坑:前提不满足时**不报错,只变慢**
- 排查从查拓扑开始,不是从看代码开始

## 答案

### 先数清朴素路径上有几次拷贝

一份数据从本机显存发到对端显存:

1. **显存 → 主机内存**(D2H)
2. **pageable → pinned 暂存区**:主机内存默认可被 OS 换出,而 DMA 引擎只能操作 page-locked 内存,驱动会先把数据 memcpy 进一块内部 pinned 缓冲再 DMA
3. **用户态 → 内核态**(走 TCP 的话)
4. 网卡发出

对端再反着来一遍。所谓零拷贝,就是用硬件路径把中间这几步消掉。

### 两条路径各消掉哪几步

| 机制 | 消掉哪几步 | 前提条件 |
|---|---|---|
| **GPUDirect P2P** | 1、2 —— 卡间直传,不落主机内存 | NVLink 域内直接可用;**只有 PCIe 时两张卡必须挂在同一个 root complex 下**,跨 CPU socket 的路径官方标注为可能极慢甚至不可靠;IOMMU 需 passthrough |
| **GPUDirect RDMA** | 1、2、3 —— 网卡直读显存 | 网卡与 GPU **同一 root complex**(最好同一颗 PCIe switch);显存必须是设备内存并**注册**给网卡、按 64 KB 对齐;驱动与网卡固件支持 |

第 2 步值得单独说,它最常被忽略:**用 pageable 主机内存做中转,不只多一次 CPU memcpy,还会让异步失效**——异步拷贝 API 遇到 pageable 指针时实际是同步执行的,你以为在重叠,其实在串行。所以凡是走主机内存的中转 buffer,一律要 pinned。

### 最该记住的坑:静默退化

**前提不满足时,程序不会报错,只会变慢。**

- P2P 不可用时,peer 拷贝自动改走"经系统内存中转"的备用路径——功能正常,**带宽掉一个数量级**
- GPUDirect RDMA 不可用时,通信库通常退回"先 D2H 到主机 pinned buffer 再发",同样只是慢

所以线上遇到"带宽只有预期的几分之一",第一件事**不是看代码,是查拓扑**:`nvidia-smi topo -m` 打出的矩阵里,两个设备之间标的是 `NV#`(NVLink)、`PIX`(同一颗 PCIe switch)、`NODE`(同 NUMA、过 root complex)还是 `SYS`(跨 socket)——后两种就是退化路径。

## 知识点

四步朴素路径、P2P 与 RDMA 各消掉哪几步、pageable 会让异步失效、注册与 64 KB 对齐、静默退化、先查拓扑再看代码。
