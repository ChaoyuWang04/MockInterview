## 题目

GPU 的内存模型是什么?写 kernel 时能显式编程的存储有哪些?L1 和 L2 cache 的命中率怎么提升?

## 要点

- 能默写内存层级表:容量、延迟、作用域、能否编程四列
- 明确区分「能显式编程」(寄存器 + shared memory)与「只能间接影响」(L1/L2/HBM)
- 说清 shared memory 为什么是 tiling 的地基
- 提高命中率的四条手段要能说出机制,不能只报菜名
- 点出 GPU 的 cache 定位与 CPU 不同:主要用来提高带宽利用率

## 答案

### 一、内存层级(A100 量级,不同代际有出入)

| 存储 | 容量量级 | 访问延迟 | 作用域 | 能否显式编程 |
|---|---|---|---|---|
| 寄存器 | 每 SM 256 KB | ~1 周期 | 单线程私有 | 间接(靠编译器,可控总用量) |
| **Shared Memory** | 每 SM 最多 ~164 KB | ~20–30 周期 | **block 内共享** | ✅ **完全显式,由你分配和读写** |
| L1 Cache | 与 shared 共用同一块 SRAM | ~30 周期 | 单 SM | ❌ 只能间接影响 |
| L2 Cache | 40–50 MB | ~200 周期 | **全 GPU 共享** | ❌ 只能间接影响(有 persisting 提示) |
| HBM 显存 | 40–80 GB | **~400–600 周期** | 全 GPU | ❌ 只能优化访问方式 |

### 二、能显式编程的只有两个

**寄存器(通过控制变量数量)+ Shared Memory(完全手工管理)**。L1/L2 是硬件自动管理的缓存,你只能通过**改变访问模式**去间接提高命中率。

shared memory 之所以关键:它是**唯一由你掌控、且比显存快一个数量级**的存储。所有 tiling 的本质都是同一件事——把一块数据从 HBM 搬进 shared,让 block 内线程反复复用它,**把「多次慢访问」变成「一次慢访问 + 多次快访问」**。

### 三、提高 L1 / L2 命中率的四条

1. **合并访存(coalescing)**:让同一个 warp 的 32 个线程访问**连续地址**,硬件会合并成少数几个宽事务;地址跳着走会退化成 32 次独立访问
2. **提高数据复用**:tiling + shared memory,减少对同一份数据的重复读取
3. **缩小工作集**:让热点数据能装进 L2(40 MB 量级)。这也是算子融合能提速的原因之一——**融合后中间结果不落显存,直接留在片上**
4. **调整数据布局**:按实际访问顺序排布(如 NCHW 换 NHWC),让相邻线程读到相邻地址

> 注意:GPU 的 cache 主要是**用来提高带宽利用率**的,不像 CPU 那样指望它把数据长期留住。GPU 掩盖延迟主要靠「线程多」,不靠「缓存大」。

## 知识点

内存层级(寄存器 / shared / L1 / L2 / HBM)、shared memory 与 tiling、合并访存、数据复用、工作集与 L2 容量、GPU cache 与 CPU cache 的定位差异。
