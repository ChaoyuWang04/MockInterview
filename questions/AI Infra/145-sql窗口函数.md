## 题目

请系统阐述SQL中窗口函数（Window Function）的定义、语法结构及其核心组成部分（如PARTITION BY、ORDER BY、窗口帧等），详细说明常用函数（ROW_NUMBER、RANK、DENSE_RANK、SUM() OVER、AVG() OVER等）的功能与区别，并结合实际场景举例说明其在数据分析、排名计算、累计聚合、移动平均等典型应用中的使用方法与优化技巧。

## 要点

- 窗口函数在保留原行的同时访问同一窗口内的其他行
- `PARTITION BY` 分组，`ORDER BY` 定顺序，frame 定当前行能看到的范围
- `ROW_NUMBER` 不并列，`RANK` 并列后跳号，`DENSE_RANK` 并列后不跳号
- `ROWS` 按物理行计数，`RANGE` 按排序值和同值 peer 处理
- 性能重点是分区倾斜、排序/shuffle、输入裁剪和窗口复用

## 答案

**窗口函数与 GROUP BY 的最大区别是：它算完以后不把多行压成一行。** 每条输入行仍在，只是多出排名、累计值、前一行值等列。

### 语法的三个部件

```sql
function(...) OVER (
  PARTITION BY 分组列
  ORDER BY 排序列
  ROWS BETWEEN 帧起点 AND 帧终点
)
```

- `PARTITION BY`：把行分成互不影响的组；省略时整张结果集是一个分区。
- `ORDER BY`：定义组内先后，排名、累计和 `LAG/LEAD` 通常依赖它。
- 窗口帧：在当前分区内进一步限定参与计算的行。

### 三个排名函数

假设分数是 100、90、90、80：

| 函数 | 结果 | 含义 |
|---|---|---|
| `ROW_NUMBER()` | 1、2、3、4 | 每行唯一编号，并列也强行分开 |
| `RANK()` | 1、2、2、4 | 并列同名次，后面跳号 |
| `DENSE_RANK()` | 1、2、2、3 | 并列同名次，后面不跳号 |

若业务要求“每组最新一条”，应使用 `ROW_NUMBER()` 并给出能打破并列的稳定排序键，例如 `ORDER BY update_time DESC, id DESC`。

### 累计和移动窗口

```sql
SELECT user_id, dt, amount,
       SUM(amount) OVER (
         PARTITION BY user_id ORDER BY dt
         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_sum,
       AVG(amount) OVER (
         PARTITION BY user_id ORDER BY dt
         ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
       ) AS avg_7_rows
FROM orders;
```

这里是“最近 7 行”，不一定等于“最近 7 天”。若一天可能多行，需要先按天聚合，或使用目标数据库支持的时间范围帧。

`ROWS` 按行的位置计数；`RANGE` 按排序值处理，并会把相同排序值的 peer 一起纳入。默认 frame 也因数据库和是否有 `ORDER BY` 而异，关键查询最好显式写出来。

环比/同比通常用 `LAG`：先得到同粒度的月度或年度指标，再取上一期值。若原表缺月，应先补日历，否则“上一行”不一定是“上个月”。

### 性能怎么优化

1. JOIN、过滤和聚合先减少输入列与行，再做窗口排序。
2. 检查 `PARTITION BY` 是否严重倾斜；一个超大分区仍会成为瓶颈。
3. 多个函数若分区、排序和 frame 相同，尽量复用同一个 window specification。
4. 避免没有必要的全局窗口；省略 `PARTITION BY` 可能要求全局排序。
5. 单机数据库的索引能否减少排序取决于执行器；Spark/Flink 等分布式系统还要考虑 shuffle 和分区布局。

流式 SQL 还要额外定义时间属性、watermark、迟到数据和状态保留时间。无界累计窗口会让状态持续增长，不能照搬离线 SQL。
