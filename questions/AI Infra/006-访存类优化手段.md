## 题目

算子的访存类优化手段有哪些?shared memory、合并访存、bank conflict 分别在解决什么问题,怎么做?

## 要点

- shared memory tiling 的本质:把「多次慢访问」变成「一次慢访问 + 多次快访问」
- 合并访存的机制是硬件搬运粒度(扇区 32 B / 缓存行 128 B),不合并会浪费搬来的字节
- bank conflict 只发生在「同 warp 访问同一 bank 的不同地址」,读同一地址是广播不冲突
- padding 与 swizzle 两种解法及各自适用场景
- 每条手段都要说出代价

## 答案

### 一、shared memory tiling:所有分块的本质

把一块数据从 HBM 搬进片上,让 block 内线程反复复用。一个 $T \times T$ 的块载入一次后,块内每个元素平均被复用 $T$ 次,**HBM 读取量大致按 $1/T$ 下降**。

标准写法永远是三段式:**协同载入 → `__syncthreads()` → 计算**。同步不能省,因为载入是所有线程分工完成的,你读的格子可能是别的线程刚写进去的。代价:shared 与 L1 共用同一块 SRAM(每 SM 约 164 KB),**你用掉的每一 KB 都在挤压能驻留的 block 数**。

### 二、合并访存:别浪费已经搬来的字节

GPU 访存的最小粒度不是一个 float,而是**扇区(32 B)/ 缓存行(128 B)**。硬件把同一个 warp 的 32 次请求合并成尽可能少的宽事务。

| 访问模式 | 后果 |
|---|---|
| 32 线程读连续 32 个 float | 128 B、4 个扇区,**搬来的每个字节都被用上** |
| 跨步 2 | 只用到 128 B 却横跨 256 B,**一半带宽白扔** |
| 完全散乱 | 32 次事务搬 1024 B 只用了 128 B,**利用率掉到 1/8** |

```cuda
float good = A[row * N + threadIdx.x];   // 相邻线程 → 相邻地址
float bad  = A[threadIdx.x * N + col];   // 相邻线程隔 N 个元素 → 32 个不同扇区
```

三个配套手段:**地址按 128 B 对齐**;**向量化访存**(打包成 `float4` 一次读,访存指令数降到 1/4,要求 16 B 对齐);**改布局**(卷积 NCHW→NHWC)。躲不开跨步访问(如转置)时的标准套路是:**用连续方式读进 shared,在 shared 里做跨步访问**。

### 三、bank conflict:shared memory 的唯一陷阱

shared 被切成 32 个 bank、每个宽 4 字节:$\text{bank} = (\text{字节地址}/4) \bmod 32$。**同一个 warp 内多个线程访问同一 bank 的不同地址**时硬件只能排队,N 路冲突就慢 N 倍,最坏 32 倍。重要例外:**多个线程读同一个地址不算冲突**,硬件会广播。

```cuda
__shared__ float tile[32][32];  // 坏:列访问 bank=tx,32 路冲突
__shared__ float tile[32][33];  // 好:行长与 32 互质,bank=(i+tx)%32,各占一个
```

原理是**让行长和 bank 数互质**,每往下一行 bank 编号错开 1。代价只是每行浪费 4 字节。padding 会打乱地址对齐,对需要 128-bit 向量化读写 shared 的高性能 kernel 不友好;这时改用 **swizzle**——把列号按行号做异或置换,同样错开 bank,但不浪费一个字节、也不破坏对齐。
