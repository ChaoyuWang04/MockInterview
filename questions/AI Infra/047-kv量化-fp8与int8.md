## 题目

vLLM 和 SGLang 现在对 KV cache 也做 fp8 量化,它们是怎么量化的?既然有了 fp8,为什么还要做 int8,两种量化方式有什么差异?

## 要点

- 三家引擎全是**静态**、粒度多为 per-tensor 或每层,vLLM 不给校准时 scale 直接取 1.0
- fp8 敢取 scale=1.0 是因为 E4M3 自带 ±448 量程,bf16 的 K/V 通常远在范围内
- 核心差异在档位排布:fp8 相对误差不随幅度衰减,int8 的量程完全由 scale 决定
- int8 的优势只在"分布被 scale 罩得住"的那一段,代价是要细粒度 + 离群处理
- 还有硬件因素:原生 bf16↔fp8 转换指令是 Ada / Hopper 起才有的

## 答案

### 三家引擎怎么做

| 引擎 | 格式 | scale 怎么来 | 粒度 |
|---|---|---|---|
| vLLM | fp8_e4m3 / fp8_e5m2 | 不校准全取 **1.0**;或 warmup 时用一批 token 估一次;或离线校准 | per-tensor,或 per-head(仅 FlashAttention 后端) |
| SGLang | fp8_e4m3 / fp8_e5m2(fp4_e2m1 实验中) | 校准参数文件,或 checkpoint 自带的每层 K/V scale | per-tensor / 每层 |
| TensorRT-LLM | INT8 / FP8 / NVFP4 | 离线 PTQ 校准(常见 512 条校准样本) | per-tensor |

**三家都是静态。** vLLM 那个"warmup 时估一次"看着像动态,其实是一次性算完就冻结,本质仍是静态。

**为什么敢默认 scale = 1.0**:E4M3 能表示到 ±448,而 bf16 的 K/V 通常远在这个范围之内——不是偷懒,是"这个格式的量程本来就够"。此时写是一条格式转换指令、读是反过来一条,连乘法都没有。

### 两种方式的差异

| | int8 | fp8 E4M3 |
|---|---|---|
| 档位怎么排 | 均匀,256 档等间距 | 指数 + 3 位尾数,每个二进制区间 8 档 |
| 量程 | **完全由 scale 决定** | ±448 自带 |
| 相对误差 | 量程顶端约 0.4%,到量程 1/100 处涨到约 40% | **全程约 3%–6%,与幅度无关** |
| 对 scale 的敏感度 | 极高 | 低 |
| 工程复杂度 | 高一个档次(细粒度 + 离群处理) | 接近零 |

### 有了 fp8 为什么还做 int8

两条真实理由:

1. **精度上限**。同样 8 bit,int8 在**量程顶端**的相对误差(约 0.4%)远好于 fp8 的 3%–6%。只要把粒度切细、把组内动态范围压窄,让绝大多数值都待在量程顶端附近,int8 是能比 fp8 更准的——这正是学术线的 int8/int4 KV 方案在做的事
2. **硬件**。原生 bf16↔fp8 转换指令与 fp8 张量核是 Ada / Hopper 起才有的;在更早的卡上 fp8 的收益要打折,而 int8 的存储与转换路径是现成的

代价也很清楚:**int8 位宽和 fp8 一样,工程复杂度却高一个档次**——组要切小、离群要单独处理,而这两件事在分页与 CUDA Graph 下都要付钱。**这才是 fp8 在 Hopper 之后成为默认答案的真正原因,不是"fp8 精度更高"。**

## 知识点

三家引擎的静态口径、scale=1.0 的成立条件、均匀档位与浮点档位的相对误差曲线、int8 的精度优势区间、fp8 原生转换指令的硬件门槛。
