## 题目

挑一个你熟悉的算子,详细说说你是怎么做优化的?都用了哪些性能优化手段?并分析它的计算量和访存量。

## 要点

- 这是开放经验题,考的是**方法论的完整度**,不是手段清单的长度
- 必须以「算账 → 判 bound → 选手段」为骨架,而不是背优化清单
- 每个手段都要说「为什么这条对这个算子有效」
- 主动给数字、主动说代价、主动说没做什么
- 复测口径要交代清楚

## 答案

> 这里给的是**答题框架**,具体经历要用自己真实做过的算子来填。

### 一、讲的顺序(五段式)

1. **选算子 + 说清 shape 与场景**(训练还是推理、prefill 还是 decode、典型 batch/seqlen)
2. **先算账**:FLOPs、理论最小访存字节、算术强度,和目标卡的拐点比 → **定 bound**
3. **说 baseline 与 profiler 观察**:基线耗时多少、SM/DRAM Throughput 各是多少、warp stall 主因是什么
4. **按 bound 上手段**,逐条说「为什么这条对这个算子有效」
5. **给数字 + 说代价**:提升多少倍、occupancy 变化、精度有没有动、可维护性代价

### 二、选什么算子好讲

| 算子 | 好讲在哪 |
|---|---|
| RMSNorm / LayerNorm | 归约 + elementwise,能讲整行进 shared、warp reduce、单趟 Welford、和残差融合 |
| Softmax | online softmax、两趟变一趟、数值稳定性 |
| GEMM | 三层分块、双缓冲、Tensor Core、tile/wave quantization,深度足够 |
| Attention | FlashAttention 的分块 + online softmax,能一路讲到 IO-awareness |

### 三、手段清单按类归并(别平铺直叙)

- **访存类**:合并访存、向量化访存、shared memory tiling、消 bank conflict、改数据布局
- **并行类**:block/thread 切块、grid-stride loop、warp reduce
- **流水类**:ping-pong 双缓冲 / 多级流水、`cp.async`
- **指令类**:循环展开、减少 warp 内分支
- **跨 kernel**:算子融合,消掉中间张量的落盘

### 四、计算量 / 访存量怎么现场算

**FLOPs** = 数乘加次数 × 2;**访存量** = 数清「有几个张量必须读、几个必须写」× 元素数 × 每元素字节数,取**理论最小值**;两者一除得算术强度,和拐点比即得 bound。手推的是理想下限,真实值以 profiler 的 DRAM 计数器为准。

### 五、三条加分

- 主动说**代价**:shared/寄存器占用上升、occupancy 下降、可维护性变差
- 主动说**没做什么、为什么不做**(比如判定是计算受限,所以没去做融合)
- 给出**复测口径**:warmup 之后用 CUDA event 计时、取中位数、**端到端复测**而不是只看微基准

## 知识点

优化方法论骨架(算账 → 判 bound → 选手段 → 复测)、手段的分类归并、FLOPs 与访存量的现场估算、代价意识与复测口径。

## 追问

- 你判的 bound 和 profiler 给的一致吗?不一致会是什么原因?
- 这个优化在真实模型里端到端提升了多少?为什么和微基准不一样?
- 如果换一个 shape,这套参数还成立吗?
- 有没有哪个手段做了之后反而变慢?
