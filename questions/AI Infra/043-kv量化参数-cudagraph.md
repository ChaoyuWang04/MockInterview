## 题目

在 CUDA Graph 下能获取 KV cache 的量化参数吗?怎么获取?

## 要点

- 图冻结的是**地址和形状**、不是内容,且图里不能有任何 host 参与
- 三条硬约束:scale 不能当标量参数传、张量必须预分配地址固定、不许 d2h 同步
- 静态 scale 天生图友好,和 KV cache 本身"变内容不变地址"是同一个道理
- 动态 scale 也能进图,前提是"规约 → 写固定地址 → kernel 按指针读"全程不回 host
- 三种典型破图写法,前两种静默出错、第三种直接捕获失败

## 答案

**能,但写法被约束死。** 图冻结的是**地址和形状**、不是内容,且图里不能有任何 host 参与。套到 scale 上得到三条硬约束:

| 约束 | 对 scale 意味着什么 |
|---|---|
| kernel 参数按值冻结 | scale **不能当标量参数传**——捕获时那个数会被永久录进图 |
| 张量地址按值冻结 | 存 scale 的张量必须**预分配、地址固定**,每步只能原地写内容 |
| 不允许 host 同步 | 规约结果**不能回 host**,也不能据此在 Python 里走 if |

### 由约束直接推出做法

- **静态 scale 什么都不用做**:它是一块常驻的、地址固定的、内容永不改变的小张量,kernel 按指针读。这和 KV cache 本身"变内容不变地址"是同一个道理
- **动态 scale 必须全程留在设备上**:规约 kernel 把结果写进那块预分配的固定地址张量,attention kernel 按**指针**去读,host 从头到尾不知道 scale 是多少。规约 kernel 自己的形状只由 batch 决定,而 batch 正是分档变量,所以它能被一起捕获

### 三种典型破图写法

1. 求出 absmax 后 `.item()` 成 Python float 再传给 kernel → **捕获期那一个值被永久冻结**,此后每步都在用第一批数据的 scale(**静默出错**,最难查)
2. 每步重新分配一个 scale 张量 → 图里录的是老地址,规约写到新地址,attention 读到陈旧内容(**静默出错**)
3. 依赖设备端数值的 host 分支(如 `if scale > thresh`)→ **捕获直接报错**

### 面试直答

静态 scale 天生图友好;动态 scale 能进图,前提是"**规约 → 写固定地址 → kernel 按指针读**"这条链上一次 host 都不回——这和投机解码里"接受了几个"必须留在设备上是同一套手法。vLLM 那个 warmup 时估一次 scale 的选项,本质就是**把动态压成静态**,从此没有图的问题。

## 知识点

CUDA Graph 冻结地址与形状、标量参数按值冻结、预分配固定地址张量、设备端闭环、d2h 同步与破图、把动态压成静态的降级手法。
