## 题目

在 LLaDA 一类扩散语言模型上引入量化,为什么可能同时损失精度和生成速度?应怎样设计校准、量化粒度、敏感模块保护和端到端验收?

## 要点

- 扩散语言模型存在迭代去 mask、双向注意力和动态 mask 比例,分布不是固定的一步 decode
- 前一步量化误差会改变置信度与后续解 mask 决策,并在迭代中累积
- 校准必须覆盖不同时间步、mask 比例、长度和任务,不能只抓一批静态激活
- 低位宽只有配套 kernel 并减少端到端时间才算加速

## 答案

**不能直接把自回归 LLM 的一批校准样本和 W4A4 配方原样套给 LLaDA。** 扩散语言模型从大面积 mask 的序列开始,反复预测、选择一部分位置去 mask,并使用双向注意力。早期与晚期、已确定与仍被 mask 的 token 激活分布不同;某一步的量化误差还可能改变置信度排序,进而改变下一步解哪些位置,所以误差会沿迭代轨迹放大。

可按以下顺序设计:

1. 先建立 FP16/BF16 基线,按时间步、mask 比例、序列长度和任务采集激活,让校准集覆盖完整生成轨迹。
2. 从权重 8 bit 或 weight-only 开始,逐层做敏感度消融;对 attention 的 Q/K/V、softmax 附近、输出头和异常值通道比较保留高精度、旋转/平滑与更细粒度 scale。
3. 激活量化要同时看 token 与 channel 差异;静态 scale 覆盖不了时再用动态或分阶段 scale,但要计算在线统计成本。
4. 每降一次位宽就比较每步 logits/置信度、最终任务质量、迭代步数和生成轨迹翻转,不能只看困惑度或权重重构误差。

速度必须单独验收。若量化、解包或反量化是独立 kernel,或目标硬件没有相应低位宽矩阵算子,模型虽变小却可能更慢。最终比较显存、每次去噪耗时、总迭代数和端到端 tokens/s,并确认质量门槛没有靠增加采样步数补回来。

## 知识点

LLaDA、扩散语言模型、动态 masking、迭代误差累积、时间步校准、混合精度。

- 依据:[Large Language Diffusion Models](https://arxiv.org/abs/2502.09992)、[DLLMQuant](https://arxiv.org/abs/2508.14090)。
