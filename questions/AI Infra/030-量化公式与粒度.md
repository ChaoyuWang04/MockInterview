## 题目

量化的公式是什么?per-tensor、per-channel、per-group、per-block、per-head、per-token 分别是怎么做量化的,量化参数的 shape 是什么?DeepSeek-V3 采用细粒度 block scaling 有什么收益与代价?

## 要点

- 量化 / 反量化两式,scale 是档距、zero-point 是码表的平移量
- 误差两个来源(舍入与截断)是跷跷板关系,定 scale 就是在两者之间选
- 对称 vs 非对称:$z=0$ 与否,scale 公式不同
- 粒度决定"多少个数共用一组 $(s,z)$",要能背出每种粒度的 scale shape
- per-block 要明确块沿哪些维度切,不能只说“更细粒度”
- 权重 per-channel 是 `[out]` 不是 `[in]`;沿求和维切 scale 需要分段累加或专用 block kernel

## 答案

### 公式

$$
q = \mathrm{clamp}\Bigl(\mathrm{round}\bigl(x / s\bigr) + z,\ q_{\min},\ q_{\max}\Bigr), \qquad \hat{x} = s\,(q - z)
$$

左式量化:除以档距、取整、加平移量,超出表示范围的**截断**到端点;右式反量化。$\hat{x} \neq x$,差值就是量化误差,来源有二且是跷跷板:**舍入误差**最大半个档距($s$ 越小越小),**截断误差**是超范围的值被拍到端点($s$ 越小罩得越窄、被拍扁的越多)。

| | 对称量化 | 非对称量化 |
|---|---|---|
| zero-point | $z = 0$ | $z \neq 0$,平移码表对准数据实际范围 |
| scale | $s = \max\lvert x \rvert / (2^{b-1}-1)$ | $s = (x_{\max}-x_{\min}) / (2^{b}-1)$ |
| 适合 | 零均值、大致对称的分布(权重) | 单边分布(如 ReLU 后的激活) |

### 粒度与 shape

记权重 $W \in \mathbb{R}^{out \times in}$,激活把 batch 与序列拉平 $X \in \mathbb{R}^{T \times in}$($T = B \times S$):

| 粒度 | 一组 scale 覆盖什么 | scale shape | 谁在用 |
|---|---|---|---|
| per-tensor | 整个张量 | `[1]` | 激活静态量化、KV cache 默认 |
| per-channel | $W$ 的一行(沿**输出通道**) | `[out]`(广播成 `[out, 1]`) | 权重 |
| per-group | $W$ 一行里连续 $G$=128 个 | `[out, in/G]` | int4 权重标配 |
| per-block | $W$ 的二维小块,如 $B_o\times B_i$ | `[ceil(out/B_o), ceil(in/B_i)]` | FP8 权重、细粒度缩放 |
| per-token | $X$ 的一行,即一个 token 的整条隐藏向量 | `[T]`,即 `[B, S, 1]` | 激活 |
| per-head | 一个 head 的 K 或 V | `[KV 头数]` 量级(动态再多一维 batch) | KV cache |

一句话记忆:**权重的 per-channel 是"每个输出神经元一张表",激活的 per-token 是"每个 token 一张表"——两者都不沿求和维切。**

**per-channel 到底是哪一维**是最容易答错的一问:$W$ 是 `[out, in]` 时 scale 是 `[out]`,不是 `[in]`。理由不是习惯,是可提取性——沿 $in$ 切就等于沿求和维切,scale 提不出求和号。

元数据开销能直接算,这是拿分细节:int4 + per-group($G$=128)+ fp16 scale,

$$
\text{有效位宽} = 4 + \frac{16}{128} = 4.125\ \text{bit/权重}
$$

配上同粒度的 zero-point 约 4.25 bit,所以 int4 模型的实际体积总比「参数量 × 0.5 字节」大一点。

### DeepSeek-V3 的细粒度 FP8 缩放

以官方 FP8 权重格式为例,权重按 `128×128` block 保存 scale；运行时激活可按“每 token、每 128 个通道”动态缩放。比 per-tensor 或整行共用 scale 更细时,局部异常值只影响所在块,其他块仍能利用更多有效码点,因此更容易控制低动态范围格式的量化误差。代价是 scale 元数据、在线统计与访存增加,而且 GEMM kernel 必须按相同块边界正确装载和累加；没有匹配 kernel 时,精度收益未必能转化成端到端速度收益。
