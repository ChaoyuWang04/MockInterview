## 题目

Agent 在高并发下频繁调用多个外部工具，怎样从召回、生成、工具执行、缓存、调度和容错层面降低端到端延迟，同时保证结果质量与稳定性？

## 要点

- 先用链路追踪找到关键路径，分别测检索、模型生成、工具排队与执行时间
- 只并行没有依赖的工作；有依赖时按 DAG 分层执行
- 缓存键必须包含租户、权限、工具版本和参数，失效策略服从数据语义
- 慢工具要异步化，并以超时、幂等重试、熔断和降级控制尾延迟
- 流式输出只改善感知延迟；量化要单测工具选择和参数生成能力

## 答案

**先把 Agent 链路画成依赖图，再优化真正的关键路径。** 不能把所有工具一股脑并发：只有互不依赖、没有副作用的调用才能安全并行。

```mermaid
flowchart LR
    A[请求] --> B[检索与规划]
    B --> C[独立工具并行]
    C --> D[依赖工具分层执行]
    D --> E[模型汇总]
    E --> F[流式返回]
```

### 各阶段怎么做

| 阶段 | 主要手段 | 必须守住的边界 |
|---|---|---|
| 召回 | embedding 预计算、ANN 参数预算、多路召回并行、语义缓存 | 根据置信度和剩余延迟预算调召回深度，不能只追求快 |
| 生成 | KV cache、连续批处理、合适的量化、短输出约束 | 流式返回降低等待感，不减少模型总计算 |
| 工具 | 连接池、异步 I/O、批量 API、请求合并 | 写操作和非幂等操作不能盲目合并或重试 |
| 调度 | 按 deadline 排队、限制在途请求、背压 | 高并发时先保护关键请求，避免队列无限增长 |

长工具链先删除无价值调用，再把依赖图分层；每层内并行，层间顺序执行。工具特别慢时，主流程保存执行状态并异步等待，界面返回进度；若任务允许，也可先返回部分结果。

### 缓存与失败怎么处理

缓存键至少包含**租户/权限、规范化参数、工具版本和数据版本**。稳定数据可设较长 TTL；实时数据用短 TTL 或由变更事件主动失效。TTL 没有通用值，要用陈旧结果的业务代价来定。

把工具分成“完成任务必需”和“可选增强”。必需工具失败就终止或明确返回失败；可选工具超时可跳过、用可信旧缓存或降级。只对幂等错误做有限重试，并配合超时、熔断和全链路 deadline。

INT4 是否可用不能只看困惑度，要比较量化前后**工具选择正确率、参数结构正确率、任务成功率和尾延迟**。若能力下降，回退到 INT8/混合精度或只量化不敏感层。
