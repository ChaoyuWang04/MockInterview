## 题目

推测的 token 校验时,会触发 d2h 的同步,怎么避免这个同步点对推理流水线的影响?

## 要点

- 先说清危害:队列被抽干 + 之后要重新灌满,量级几十到几百微秒,而 decode 一步才几毫秒
- 核心思路:**让「接受了几个」这件事 host 永远不需要知道**
- 五条手段:验证在 kernel 里做、下一轮输入在 GPU 上组装、seq_lens 设备端张量化、形状定长化、随机数留在 device
- 形状定长化还顺带保住了 CUDA Graph,丢掉的是双份收益
- 有些同步必须保留(EOS / 流式返回),用异步 event + 滞后一步轮询

## 答案

### 问题长什么样

朴素实现:验证 kernel 算完 → 把「接受了几个」拷回 host → CPU 用 `if` 判断 → 组装下一轮输入 → 再发 kernel。这个拷贝是 **d2h 同步点**:CPU 必须停下来等 GPU 把这一轮算完,队列随即被抽干,下一批 kernel 还没提交。每轮在 timeline 上留一个 gap,量级几十到几百微秒,而 decode 一步总共才几毫秒到十几毫秒——**几轮下来就吃掉大半加速比**。

### 解法:把整条链留在 GPU 上

1. **验证在 kernel 里做**:比较 draft token 与 target 采样结果、生成 accept mask、前缀和求接受长度,全在 device 上,结果写进一个 device tensor,不回 host
2. **下一轮输入也在 GPU 上组装**:用 gather / scatter 按设备端的接受长度挑出「最后一个被确认的 token」,直接写进下一轮输入缓冲区,CPU 只管无脑发同一串 kernel
3. **序列长度做成 device tensor**:attention kernel 自己去读 `seq_lens`,而不是靠 host 传标量参数进来——这是解耦的关键
4. **形状定长化**:每轮固定按 $k+1$ 个位置算,被拒绝的位置照算不误(反正算力闲着),**用「算点废的」换掉动态 shape**
5. **随机数留在 device**:采样用的 uniform 数在 GPU 上生成,别为了接受-拒绝判定专门回一趟 host

第 4 条尤其重要:CUDA Graph 要求每轮的 kernel 序列、参数、地址固定不变,只要有一个 host 分支依赖 GPU 结果,整轮就录不成图,decode 的 launch 开销也省不掉——**这里丢的是双份收益**。

### 什么同步必须保留

**判断请求是否结束(EOS / 达到 max_tokens)、把 token 流式返回给用户**,这些 host 最终必须知道。做法是**异步 event + 滞后一步轮询**:这一轮的结果等下一轮 kernel 已经发出去之后再取回,GPU 队列始终有活干,代价只是「结束判定慢一轮」——多生成一轮被丢弃,远比每轮停一次划算。

## 知识点

d2h 同步的双份代价、设备端标量替代 host 分支、定长 shape 换动态 shape、CUDA Graph 对固定序列的要求、滞后一步的异步回读。
