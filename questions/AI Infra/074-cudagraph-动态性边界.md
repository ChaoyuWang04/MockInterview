## 题目

CUDA Graph 时可以有动态性吗?重放之间哪些东西能变、哪些不能?

## 要点

- 一条总纲:**内容可变,地址和形状不可变**
- KV cache 一直在写 → 能生效,变的是内容不是地址
- 图里**不能**有同步点,后果分「捕获失败」与「静默算错」两类
- 有限动态性的三条逃生口,都不推翻形状固定这条底线

## 答案

| 项目 | 重放之间能不能变 | 为什么 |
|---|---|---|
| 张量里的**数值内容** | ✅ 能 | 图记的是地址,kernel 运行时读到的是当下内容 |
| **KV cache 的内容** | ✅ 能 | 同上,decode 每步往 KV 里写新 token 没问题 |
| 有效序列长度、block 表 | ✅ 能(间接) | 放设备端张量当参数传,形状不变只变数值 |
| 输入张量的**地址** | ❌ 不能 | 按值录进图,只能 `copy_` 原地写回同一块 |
| 张量**形状** | ❌ 不能 | grid/block 尺寸、指针偏移全被冻结 |
| kernel 启动配置、标量参数 | ❌ 不能(除非显式 update) | 捕获期按值记录 |
| host 侧 if / `.item()` / `print` | ❌ 不能 | 图里根本没有 host 参与 |

**「kvcache 一直在变还能生效吗?」——能,而且这正是设计目标。** 变的是内容不是地址;只要预分配好、原地写,图完全无感。

**「图里能有同步点吗?」——不能。** 捕获期间任何依赖 host 的操作都非法:`cudaDeviceSynchronize`、不带 Async 的 `cudaMemcpy`、`.item()` / `.cpu()`、根据 GPU 上的数在 host 侧走 if、输出形状取决于数据的算子(`nonzero`、`x[mask]`)。后果分两类:要么**捕获直接报错**,要么更糟——捕获那一次的判断结果**被当成常数录进图**,此后每次重放都按陈旧结果走,**静默算错**。所以上图前的必修课是先把隐式同步清干净。

需要有限动态性时官方给了三条逃生口,但都不改变形状固定这条底线:重录后用 `cudaGraphExecUpdate` 做整图更新(拓扑不变就不必重新实例化)、按参数组合缓存多张图、以及条件节点(IF / WHILE / SWITCH,把分支判断放到设备端做)。

## 知识点

按值冻结、内容与地址的区分、隐式同步清单、静默出错模式、图更新与条件节点。
