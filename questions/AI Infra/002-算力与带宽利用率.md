## 题目

什么是算力利用率?什么是带宽利用率?这两个数怎么做理论计算?

## 要点

- 两个利用率是同一个模子:实测 / 峰值
- 分子靠算法手推(FLOPs、访存字节),分母查数据表,只需要一个实测量:kernel 耗时
- 能走完一个完整数值例子
- 分母要和 kernel 实际用的计算单元对齐(稠密/稀疏、Tensor Core/CUDA Core、fp16/fp32)
- 两个利用率一定一高一低;都低说明瓶颈是第三种东西
- 训练侧的专用口径 MFU

## 答案

### 一、定义

$$
\text{算力利用率} = \frac{\text{FLOPs} / t}{P_{\text{peak}}} \qquad\qquad \text{带宽利用率} = \frac{\text{Bytes} / t}{BW_{\text{peak}}}
$$

分子是「实测算力 / 实测带宽」= 总浮点运算数(或总访存字节)÷ 耗时,分母是官方峰值。**分子靠算法手推、分母查数据表,全程只需要一个实测量:kernel 耗时。**

### 二、走一遍完整数值

A800 上跑 fp16 方阵 GEMM,$M=N=K=4096$,实测耗时 0.5 ms:

| 步骤 | 计算 | 结果 |
|---|---|---|
| FLOPs | $2 \times 4096^3$ | 137.4 GFLOP |
| 访存字节 | $3 \times 4096^2 \times 2$ B | 100.7 MB |
| 实测算力 | 137.4 G / 0.5 ms | 275 TFLOP/s |
| 实测带宽 | 100.7 M / 0.5 ms | 201 GB/s |
| **算力利用率** | 275 / 312 | **88%** |
| **带宽利用率** | 201 / 2039 | **10%** |

结论自己跳出来:算力接近打满、带宽几乎闲着 → **计算受限,再优化访存也没用**。

### 三、三条实操注意

1. **分母要和 kernel 实际用的单元对齐**。稠密 / 稀疏差 2 倍,Tensor Core / CUDA Core 差一个数量级,fp16 / fp32 又差一档。拿 fp16 Tensor Core 的峰值去除一个跑在 CUDA Core 上的 fp32 kernel,结果毫无意义
2. **分子的访存字节用理论最小值**,算的是理想下限。真实搬运量只多不少(重复读、未合并访存、写回),所以手推的带宽利用率是**下界**,真机计数器给的才是实际值
3. **两个利用率一定一高一低**,这是天然的交叉验证。如果算出来两个都低,说明瓶颈既不是算力也不是带宽,而是 occupancy 不足、同步等待或 kernel launch 开销

训练侧另有专用口径 **MFU(Model FLOPs Utilization)**:只统计前反向「必要的」浮点运算,不算重计算重复做的那部分;把重复的也算进去的叫 HFU,恒 ≥ MFU。

算力利用率、带宽利用率、峰值口径对齐、理论访存下界、MFU 与 HFU。
