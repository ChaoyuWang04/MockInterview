## 题目

GPU资源有限时，怎样让低延迟在线推理和高吞吐微调任务混部？请说明隔离、优先级、批处理、抢占、MIG/MPS选择和收益评估。

## 要点

- 在线推理优先保护SLO，训练只消费可回收余量
- 用硬隔离保证下限，用软调度提高剩余资源利用率
- 抢占只能发生在可恢复边界，并计入保存、恢复和缓存重建成本
- MIG偏硬隔离，MPS偏共享；可用能力受GPU与软件栈限制
- 用goodput、尾延迟、训练吞吐、抢占代价和碎片率共同验收

## 答案

**核心策略是“推理有保底，微调吃余量”。** 推理对P99敏感，微调更看长期吞吐；两者完全公平排队会让训练step阻塞在线请求。

```mermaid
flowchart LR
    A[推理流量预测] --> B[保留推理容量]
    B --> C[空闲容量给微调]
    C --> D{SLO将违约?}
    D -- 是 --> E[停止入新训练step或安全抢占]
    D -- 否 --> C
```

### 分配与调度

- **硬保底**：给在线服务预留显存、计算份额和副本，设置 admission control，先防止 OOM 和队列失控。
- **弹性余量**：微调按 step 或 checkpoint 边界运行；推理流量上升时先停止下一个训练 step，再考虑保存状态后抢占。
- **各自批处理**：推理用连续批处理并限制等待窗口；微调调大 micro-batch 或梯度累积追求吞吐，不能共用同一延迟目标。
- **权重与数据**：推理权重常驻；训练状态按需加载。频繁换入优化器状态通常会抵消混部收益。

MIG把支持的GPU切成较强隔离的实例，故障和显存干扰小，但切分粒度固定、闲置份额不易借用；MPS让多个CUDA进程共享GPU，利用更灵活，但显存、缓存和调度干扰更明显。是否可用及隔离能力取决于GPU型号、驱动和容器栈。

流量突增时，只有预测的P99或排队时间将越过SLO，且抢占收益大于保存/恢复成本，才抢占微调；否则先限流、扩副本或降低在线batch。验收同时看 **SLO内完成的goodput、P99、训练样本/秒、GPU有效时间、OOM、抢占恢复时间和资源碎片率**，不能只看GPU利用率。
