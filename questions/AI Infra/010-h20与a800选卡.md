## 题目

跑一个大模型,大 shape 下 GEMM 占大头。已知 H20 的带宽是 A800 的两倍、算力是 A800 的一半,理论预期这个模型在哪张卡上跑得更快?为什么?

## 要点

- 不能背参数表,必须走「算强度 → 算拐点 → 定位 → 算时间」四步
- 大 shape GEMM 的强度远超两张卡的拐点,都是计算受限
- 计算受限时时间只由算力决定,带宽项被 min 顶住用不出来
- 能主动给出反转场景(decode 阶段结论相反)
- 结论的真正含义:「哪张卡快」是算子的属性,不是卡的属性

## 答案

### 第一步:写下参数与拐点

| | A800 | H20 | 对比 |
|---|---|---|---|
| HBM 带宽 | 2.0 TB/s | 4.0 TB/s | H20 = 2× |
| FP16 稠密算力 | 312 TFLOPS | 148 TFLOPS | H20 ≈ 0.47× |
| 拐点 = 算力/带宽 | **153** FLOP/Byte | **37** FLOP/Byte | |

### 第二步:算算子强度

大 shape GEMM,取 $n=4096$ 的方阵,强度 $= n/3 = 1365$ FLOP/Byte。

### 第三步:定位

$1365 \gg 153 > 37$ —— 在**两张卡上都落在水平段,都是计算受限**。而且不是勉强越过拐点,是超出 A800 拐点近 9 倍,余量极大。

### 第四步:算时间

计算受限时 $t = \text{FLOPs} / P_{\text{peak}}$,**和带宽无关**:

- A800:$137.4\text{ GFLOP} / 312\text{ TFLOPS} = 0.44$ ms
- H20:$137.4\text{ GFLOP} / 148\text{ TFLOPS} = 0.93$ ms

**答:A800 更快,约 2.1 倍**(正好是算力比的倒数)。

### 为什么带宽翻倍一点忙都帮不上

回到 $\min(P_{\text{peak}},\ BW \times I)$:H20 这一侧 $BW \times I = 4.0\text{ TB/s} \times 1365 = 5.5$ PFLOP/s,而 $P_{\text{peak}}$ 只有 148 TFLOPS。**min 取的是算力那一项,带宽项再翻十倍,min 值也纹丝不动**——H20 的带宽优势整个被顶在屋顶下面用不出来。

### 换个场景结论就反转

同样两张卡跑 decode:batch 小、矩阵退化成 GEMV,fp16 下强度 ≈ batch 大小。取 batch=32,强度 32 —— **低于 H20 的拐点 37,更远低于 A800 的 153,两张卡都变成访存受限**。此时 $t = \text{Bytes} / BW$,13B 的 fp16 模型权重 26 GB、每生成一个 token 要完整读一遍:

- A800:26 GB / 2.0 TB/s = 13 ms/token
- H20:26 GB / 4.0 TB/s = 6.5 ms/token → **H20 快 2 倍**

**这道题真正想考的是:「哪张卡更快」不是卡的属性,是「算子落在屋顶哪一段」的属性。** 这也解释了 H20 这类「砍算力、保带宽」的卡为什么专为推理 decode 而生。

## 知识点

拐点比较、min 结构下带宽项被顶住、计算受限与访存受限下时间公式的差别、prefill 与 decode 的选卡偏好。

## 追问

- 如果这个模型 prefill 和 decode 各占一半时间,该怎么选卡?
- batch 开到多大,H20 在 decode 上的优势会消失?
- 量化到 int8 之后,这道题的答案会变吗?
- 实际上还要看什么参数才敢下结论?(显存容量、互联带宽、单卡功耗)
