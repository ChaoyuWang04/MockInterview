## 题目

量化和反量化通常占多少推理时间,应该怎样准确测量?如果转换开销很大,工程上怎样通过融合、scale 策略、数据布局和硬件选型加速?

## 要点

- 没有脱离位宽、shape、batch、硬件和 kernel 的固定耗时比例
- 分清离线权重量化、在线激活量化、KV 写侧量化与读侧反量化
- 反量化结果不应落回 HBM,应在 GEMM/attention 取数路径中片上完成
- 端到端质量、吞吐和延迟同时验收,不能只看模型体积

## 答案

**量化/反量化没有通用的固定占比,必须对目标 shape 和 kernel 做时间线测量。** 离线权重量化不在请求关键路径;动态激活量化每轮要统计 scale;KV 在写入时量化一次、后续每个 decode step 都会读取并反量化;weight-only 则每次 GEMM 取权重时解包和反量化。

测量时先固定 batch、序列长度、dtype 和并发,分别记录转换 kernel、低精度 GEMM/attention 以及端到端 TTFT、TPOT。还要比较“低位宽搬运省下的时间”是否大于 scale 统计、打包、解包和转换成本。只报 profiler 中一个 kernel 的百分比会受异步执行和重叠误导,需要同步边界正确的基准与整条请求复测。

最关键的优化是**不物化高精度中间张量**。权重反量化应融合进 GEMM 的 prologue,KV 反量化应在 attention 读取后于 shared memory 或寄存器完成;否则低位宽读入后又把 FP16 写回 HBM,流量可能比不量化更大。其次可选择离线静态 scale 或更粗粒度减少在线规约,让 scale 与打包布局满足向量化和 Tensor Core 对齐,复用已统计的参数,并使用硬件原生支持的 FP8/FP4/INT8/INT4 路径。

如果目标设备没有对应 kernel,提高位宽或只量化权重可能比强上 W4A4 更快。最终选择以“质量达标下的端到端吞吐、尾延迟和显存”决定。

## 知识点

动态与静态量化、融合反量化、GEMM prologue、KV Cache、片上转换、端到端 profiling。
