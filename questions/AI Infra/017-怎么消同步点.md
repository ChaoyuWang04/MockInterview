## 题目

怎么消同步点?

## 要点

- 手段一:用 event 表达跨流依赖,代替全局 sync,让 GPU 侧排队而 host 不停
- 手段二:干掉隐式同步,能列出 PyTorch 里的主要来源与改法
- 核心思路一句话:别把 GPU 上的数拉回 host 做判断
- 手段三:分块流水,把大传输切小,重叠上限是 max(传输, 计算)
- 知道边界:launch 开销问题靠消同步点解决不了

## 答案

### 一、用 event 表达依赖,代替全局 sync

CUDA event 是**插在流里的一个标记**。关键是 `cudaStreamWaitEvent`——它让**另一条流在 GPU 侧等**,而 **host 立刻返回继续下发**,队列深度得以保持。

```cuda
cudaStreamCreateWithFlags(&s1, cudaStreamNonBlocking);   // 别用默认流
cudaStreamCreateWithFlags(&s2, cudaStreamNonBlocking);

cudaMemcpyAsync(d_a, h_a, n, cudaMemcpyHostToDevice, s1); // h_a 必须是 pinned
kernel_a<<<g, b, 0, s1>>>(d_a);
cudaEventRecord(done, s1);            // 流 1 上打一个「这里算完了」的标记

cudaStreamWaitEvent(s2, done, 0);     // 流 2 在 GPU 侧等这个点;host 不停
kernel_b<<<g, b, 0, s2>>>(d_a, d_c);

cudaStreamSynchronize(s2);            // 只在真正要用结果时才等
```

### 二、干掉隐式同步

最难查的同步点都是**你没写 sync 但它偷偷同步了**的:

| 会同步的写法 | 为什么 | 改法 |
|---|---|---|
| `.item()` / `.cpu()` / `.tolist()` / `float(t)` | D2H 取值,必须等 GPU 算完 | 在 GPU 上累加,循环外取一次 |
| `print(tensor)`、`assert t.sum() > 0` | 打印和断言都要读到实际数值 | 只在调试期开,或按 N 步采样 |
| `if t > 0:` 这类 host 侧分支 | 控制流依赖 GPU 上的数 | 改成 `torch.where` / 掩码,在 GPU 上做 |
| `torch.nonzero(t)`、`x[mask]`、`torch.unique` | **输出形状取决于数据**,必须把 size 拉回 host 才能分配输出 | 固定形状 + 掩码,或接受这次同步 |
| 不带 Async 的 `cudaMemcpy`;源张量非 pinned 的 `non_blocking=True` | DMA 不能直接搬 | 换 pinned 内存 + 异步拷贝 |
| 热循环里 `torch.tensor(标量, device='cuda')` | 每次都触发一次 H2D | 循环外建好张量复用 |

核心思路只有一条:**别把 GPU 上的数拉回 host 做判断**。要么把判断挪到 GPU 上,要么**延后**——日志、指标这类不影响计算的东西,攒到几十步之后一次性取回。

排查工具:`torch.cuda.set_sync_debug_mode("warn")` 会在触发同步时报警,`"error"` 直接抛异常(官方说明它覆盖不全,不含分布式等)。

### 三、分块流水,把大传输切成小块

多流 + event 只是搭好框架,真正让传输「藏进」计算的是**分块**:把一次大传输切成 N 块,第 k 块传完就立刻开算,同时开始传第 k+1 块。

传输和计算各占 4 个时间片、切成 4 块后,总耗时从 **8 片降到 5 片**,只剩首尾两次填 / 排空流水线的空转。块越多首尾占比越小,但块太小时每块跑不满硬件、launch 开销反而占主导。重叠的天花板很清楚:**总时间 = max(总传输时间, 总计算时间)**。

> 另一类问题——小算子太多、CPU 下发根本跟不上——**靠消同步点解决不了**,那是把整段固定序列打包成一次提交的活(CUDA Graph)。
