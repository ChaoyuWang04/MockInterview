## 题目

讲下你熟悉的并行方式?解释下常用的并行方式的原理,dp、tp、pp、ep、sp、cp 等等。

## 要点

- 先说明各自切什么,再按显存、通信和框架支持选择组合
- TP 的核心不是"能切",而是"怎么切通信最少"——列切进、行切出
- SP 与 CP 别混:一个切激活存储、复用 TP 组,一个切注意力计算本身
- EP 不凭空多一维,它是把 DP 维在 MoE 层重新解释
- 说明 DP/TP/PP 的主要通信与选型,定量计算另见通信专题

## 答案

一句话:**一张卡装不下模型、也算不动数据时,就把模型和数据沿不同维度切开分给多张卡**。

| 策略 | 切什么 | 每卡持有 | 原理一句话 |
|---|---|---|---|
| **DP** 数据并行 | 数据 batch | 完整模型副本 | 各算各的前反向,梯度 all-reduce 取平均。显存全冗余是它的死穴 |
| **TP** 张量并行 | 单层内的矩阵 | 每层权重的 $1/t$ | MLP 先列切再行切、注意力按头切,一个块末尾只对一次账 |
| **PP** 流水线并行 | 模型的层 | 一部分层(stage) | micro-batch 依次流过,前向传边界激活,反向传其梯度 |
| **EP** 专家并行 | MoE 的专家 | 一部分专家 | token 寄给专家所在的卡,算完再寄回,每层两次 all-to-all |
| **SP** 序列并行 | TP 域内的序列 | 一段 token | 把 LN/Dropout 那段冗余激活按序列切给 TP 组内各卡 |
| **CP** 上下文并行 | 整条序列 | 一段 token | 注意力计算本身分布式化,K/V 沿环逐跳传(Ring Attention) |

### TP 为什么是"列切进、行切出"

MLP 是两个矩阵乘夹一个非线性。第一个权重按**列**切:

$$
A = [A_1, A_2] \ \Rightarrow\ Y = [\mathrm{GeLU}(XA_1),\ \mathrm{GeLU}(XA_2)]
$$

每卡拿到的已经是完整的一个列块,GeLU 逐元素作用,**各算各的不用对账**。若按行切则 $XA = X_1A_1 + X_2A_2$,得先跨卡求和才能过 GeLU——非线性不满足"和的函数 = 函数的和"。第二个权重顺势按**行**切,每卡出一个部分和,末尾一次 all-reduce 收口。注意力同构:按头切,输出投影行切。

### 三对容易混的

- **SP vs CP**:SP **不要新卡**,复用 TP 组,切的只是 LN/Dropout 区域那份"每卡一份全量"的冗余激活,通信量与纯 TP 持平(all-reduce 本就等于 reduce-scatter + all-gather,SP 把两步拆开放到 TP 区两侧);CP 是序列长到单卡放不下时,把**注意力计算**也切开。
- **EP vs DP**:EP 不凭空多一维,是把 attention 侧的 DP 维**在 MoE 层重新解释**成 EP 维——同一批卡,进 attention 时按 DP、进 MoE 层时按 EP。
- **ZeRO vs 模型并行**:ZeRO 切的是参数/梯度/优化器状态的**存储**,计算上仍是 DP。

### 平台来源补充:代价与组合

**DP** 易扩展数据吞吐,代价是普通 DDP 复制模型状态;梯度通常分桶同步并与反向重叠,不是一定等反向结束后才发一次通信。**TP** 可拆开单层,但频繁的层内集合通信容易进入关键路径,应优先放在高速互联组。**PP** 只在段边界点对点通信,但要面对阶段负载不均和灌入、排空的空转。

单节点放不下时,先估参数、优化器状态和激活峰值:比较状态分片或 TP,需要进一步分层才加入 PP,剩余资源再扩 DP。纯三维布局满足 $N=tpd$,全局样本 batch 为 $B=bmd$（$b$ 为每个微批样本数,$m$ 为累积微批数）。并行度受形状整除、互联和微批效率约束,不存在只按模型参数量决定的通用配置。

**ZeRO-3 与 PP 的区别:**前者把数据并行副本里的训练状态分片,执行某层时取回所需参数;后者让不同阶段常驻并计算不同层。两者都能省显存,通信与调度代价不同,组合还取决于框架支持。

**GPipe 与 PipeDream 的区别:**GPipe 在一个批次内先完成所有微批前向,再做反向并同步更新。原始 PipeDream 用流水化的前后向交替及异步更新提高利用率,需要保存权重版本。同步的 1F1B 则仍可在批次末统一更新,不能把“1F1B”直接等同于原始 PipeDream。增大微批数量、平衡各段或交错调度能减少空转;微批太小会降低算子效率,同步 1F1B 本身也不保证消除 bubble。
