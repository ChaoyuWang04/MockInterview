## 题目

对 KV cache 做动态量化的动机是什么?量化时 KV cache 的 dtype 怎么选,为什么?

## 要点

- 动机分两层:为什么量化 KV(容量与带宽),为什么选动态(不依赖校准集、不怕漂移)
- KV 量化的收益是"用精度换容量,再用容量换吞吐"
- dtype 首选 fp8 E4M3:相对误差不随幅度衰减,scale 只要量级对
- int8 均匀档位,"罩住最大值"和"分辨小值"是零和,必须更细粒度 + 离群处理
- E5M2 是"连 scale 都懒得给"的兜底,int4/fp4 要付元数据与 kernel 复杂度

## 答案

### 动机

**为什么压 KV**:KV cache 是推理系统里唯一随负载线性膨胀的显存项,也是 decode 里唯一随负载增长的带宽项(权重那部分和 batch 无关)。位宽减半 → 同显存装 2× 的 token → 并发或上下文翻倍 → 权重读取被摊得更薄,**吞吐的大头在最后这一层**。

**为什么选动态**:scale 每步现算,永远贴着当前数据,不依赖校准集、不怕线上分布漂移(长上下文、换任务时静态 scale 最容易失手)。代价是三笔开销:多一遍规约、每读一块 KV 多读一份散点的 scale、以及若把 scale 读回 host 就是一个 d2h 同步点。

### dtype 怎么选

| | int8 | fp8 E4M3 | fp8 E5M2 |
|---|---|---|---|
| 档位怎么排 | 均匀,256 档等间距 | 指数 + 3 位尾数,每个二进制区间 8 档 | 指数 + 2 位尾数,每区间 4 档 |
| 量程 | 完全由 scale 决定 | **±448 自带** | **±57344 自带** |
| 相对误差 | 量程顶端约 0.4%,到量程 1/100 处涨到约 40% | **全程约 3%–6%,与幅度无关** | 全程约 6%–12% |
| 对 scale 的敏感度 | **极高** | 低 | 极低 |

(量程按 OCP 规范;AMD 的 fnuz 变体 E4M3 上限是 ±240。)

结论与理由:

- **首选 fp8 E4M3**。相对精度不随幅度衰减,scale 只要"量级对"就行;而 Ada / Hopper 起 bf16↔fp8 有原生转换指令,在寄存器里做,不占访存也几乎不占算力。**位宽减半的收益直接落袋,代价接近零**
- **为什么是 E4M3 不是 E5M2**:KV 是前向激活、分布集中,不需要 5 位指数那么宽的量程,选 E4M3 换回一位尾数;E5M2 的位置是"连 scale 都懒得给"的兜底
- **int8 要付什么**:均匀档位意味着"罩住最大值"和"分辨小值"零和,组里混进一个离群值其余全挤进头几档。所以 int8 KV 要么把组切小、要么把离群单独拎出来——位宽和 fp8 一样,**工程复杂度却高一个档次**
- **int4 / fp4 要付什么**:元数据反噬(per-token 分组下 int4 的元数据占比就到 6.2%)、必须做离群处理、以及 4 bit 解包与非对齐访问的 kernel 复杂度

## 知识点

KV 量化的容量与带宽动机、动态 scale 的三笔开销、int8 与 fp8 的档位/量程/相对误差对比、E4M3 与 E5M2 的分工、低位宽的元数据反噬。
