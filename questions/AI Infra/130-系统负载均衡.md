## 题目

在大模型训练、推理和高并发服务中，如何设计负载均衡策略，兼顾资源利用率、延迟、稳定性与异构硬件？请同时说明缓存、异步队列、限流降级和慢节点处理的作用与权衡。

## 要点

- 负载不能只数请求，要估 token、显存、执行时间和设备能力
- 在线推理按 SLO 调度，训练按同步边界处理慢节点
- 缓存、队列、限流、熔断分别解决不同问题
- 异构与共卡场景要有隔离、可抢占点和恢复成本

## 答案

**负载均衡不是把请求平均分，而是让每台设备承担接近其能力的工作量，同时守住延迟和显存边界。**

推理请求的成本随输入、输出上限、模型和 KV Cache 占用变化。调度器应按 token 预算和可用显存组批，把相近长度或相同模型的请求放在一起；队列接近 SLO 时优先短请求或高优先级请求，并通过限流、降级或扩容控制排队。batch 上限不能写死，要由“权重 + KV + 工作区 + 安全余量”估算，再在 P99 约束下压测。

训练是同步系统，最慢 rank 会拖住所有人。应监控每步耗时、通信和数据加载，发现 straggler 后先隔离故障节点或降低其任务量；能否抢占取决于 checkpoint 和恢复成本。异构 GPU 不能只按卡数分配，应按实测吞吐或预计完成时间加权。

通用服务中，缓存减少重复计算，异步队列削峰并解耦，熔断阻止慢下游耗尽线程，限流保护容量。缓存一致性要按数据语义选择 TTL、版本号或主动失效；队列积压先停止继续放大、降级非核心任务，再扩消费者并检查下游。MIG/MPS的可用能力和隔离程度取决于 GPU、驱动与部署栈；训练和在线推理共卡容易产生抖动，应优先资源隔离。

## 知识点

加权负载、token budget、动态批处理、背压、限流、熔断、straggler、异构调度。


## 追问

- 动态批处理中如何设置 batch size 上限以避免 OOM，同时保证延迟 SLA？
- 异构环境下如何处理不同 GPU 的显存碎片问题？
- 当某个节点出现慢节点时，如何快速检测并熔断？
- 如果缓存和数据库出现数据不一致，你的处理策略是什么？
- 异步队列如果堆积严重，如何快速恢复？
- 实际业务的最高 QPS 和瓶颈是怎样测出来的？
