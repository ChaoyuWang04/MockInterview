## 题目

在意图识别或工具调用中，如何综合提示词、JSON Mode/Structured Outputs、JSON Schema 或 grammar 约束和后处理，使模型稳定输出指定 JSON？请比较其保证范围、成本、适用场景和生产兜底。

## 要点

- 区分提示软约束、生成时硬约束、生成后语法/schema/业务校验
- JSON 合法、schema 通过、语义正确和操作获授权是四件事
- 说明流式校验、复杂 schema、Unicode、修复和重试的边界
- 用通过率、字段准确率、重试率和尾延迟评测

## 答案

**可靠方案是“明确契约→约束生成→分层校验→显式失败”，不能靠一句“只输出 JSON”。**

1. **提示层：**写清字段、类型、枚举、必填项和边界示例，成本低，但模型仍可能加代码围栏、漏字段或输出错类型。
2. **生成层：**JSON Mode 通常只保证 JSON 语法；支持范围内的 Structured Outputs 或 grammar 解码会按当前解析状态屏蔽非法 token，可进一步约束 schema。复杂引用、深层条件和字符串语义是否支持要按引擎实测，不能承诺业务正确。
3. **校验层：**依次做 UTF-8/转义处理、JSON 解析、schema 校验、字段间约束、ID/权限校验。只对无歧义的围栏和空白做安全清洗；关键字段不能猜值或静默补默认值。
4. **失败层：**把精确错误交给模型有限重试；受副作用影响的请求用幂等键，仍失败就返回结构化错误或转人工。流式输出用增量解析器维护字符串、括号和 schema 状态，对象闭合后再做业务校验。

选择依据是 schema 支持、输出长度、吞吐和风险；语法需强保证时用约束解码，所有生产方案仍保留服务端校验。分别统计 schema 通过率、字段语义准确率、重试率、额外 token 和 P99 延迟。

## 知识点

JSON Mode、Structured Outputs、JSON Schema、grammar/constrained decoding、增量解析、语义校验、幂等重试。

- 流式输出如何实时校验 JSON，并处理非法 Unicode？
- JSON 嵌套很深或 schema 动态变化时如何处理？
- 多工具场景如何切换 schema，并防止上游格式错误级联？
