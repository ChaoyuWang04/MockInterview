## 题目

在大模型应用中，如何通过规范化输入输出数据格式提高生成结果的稳定性与一致性？请说明提示工程、schema约束、约束解码、后处理和工程兜底的设计与适用场景。

## 要点

- 提示明确字段、类型、必填项和示例，减少歧义
- schema校验只能发现错误，约束解码可在生成时禁止非法token
- 解析、语法校验、语义校验、修复和失败兜底要分层
- 同时评估格式正确率、语义正确率、重试率与延迟

## 答案

**稳定的结构化输出要形成闭环：先把要求说清楚，生成时限制语法，生成后校验语义，失败时明确重试或返回错误。**

1. **提示层。** 给出字段名、类型、可选值、必填规则和一两个边界示例；删掉无关上下文，避免同一字段有两种说法。
2. **生成层。** 优先使用框架支持的 Function Calling 或 JSON Schema；要求更强时用 grammar/constrained decoding，根据解析状态只允许能继续形成合法结构的token。`temperature=0`只能降低采样随机性，不能保证跨硬件、并行内核和版本逐位一致。
3. **校验层。** 先解析JSON，再校验schema，最后检查业务约束，例如日期范围、ID是否存在、字段之间是否矛盾。schema合法不代表语义正确。
4. **失败处理。** 可把具体校验错误反馈给模型做有限次数修复；高风险字段不能静默补默认值，应返回明确错误或转人工。重试要有上限和幂等键。

流式JSON可用增量解析器维护括号、字符串和当前schema状态，提前发现不可能完成的前缀；真正的业务校验通常等字段或对象闭合后进行。评估时分别报告schema通过率、字段准确率、重试率、额外token和P99延迟，不能只看“格式错误率”。
