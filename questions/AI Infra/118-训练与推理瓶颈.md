## 题目

大模型训练与推理各有哪些计算、显存、通信、数据和调度瓶颈？请从算法、系统、并行和硬件协同说明优化方法、可复用部分与正确的调优顺序。

## 要点

- 训练关注整个前反向和优化器，推理要分prefill与decode，目标不同
- 显存要拆参数、梯度、优化器、激活和KV；通信要拆DP、TP、PP、EP
- 混合精度、FlashAttention可跨阶段复用，ZeRO和KV调度等有明确阶段边界
- 梯度累积解决micro-batch显存，不减少总计算，也不自动提升利用率
- 先定位层级和bound，再优化并用端到端指标复测

## 答案

**训练追求“每步更快、能装下、能扩展”，推理追求“在SLO内服务更多请求”。** 先区分阶段和瓶颈，避免拿训练方案直接套推理。

| 阶段/瓶颈 | 典型信号 | 常用手段 |
|---|---|---|
| 训练计算 | GEMM/attention kernel占满时间 | BF16/FP16、FlashAttention、融合kernel、编译优化 |
| 训练显存 | 参数/梯度/优化器或激活OOM | ZeRO/FSDP、激活重计算、合适micro-batch；梯度累积维持有效batch |
| 训练通信 | NCCL暴露、GPU等待 | 调整DP/TP/PP/EP并行域、bucket、通信计算重叠和拓扑映射 |
| 输入与CPU | GPU时间线有空洞 | 并行预处理、pinned memory、异步拷贝、减少Python小算子 |
| 推理prefill | 长prompt使TTFT升高 | FlashAttention、chunked prefill、prompt/前缀复用、必要时序列并行 |
| 推理decode | TPOT高、带宽或KV受限 | 权重量化、KV cache/GQA、连续批处理、投机解码 |
| 推理容量/调度 | KV碎片、排队、长尾 | PagedAttention、token预算、抢占、PD分离和admission control |

### 可复用与不可混淆

混合精度、算子融合、FlashAttention、profiling方法可跨训练和推理复用。ZeRO/FSDP主要分片训练状态；推理的KV cache、连续批处理和请求调度解决另一组问题。量化可跨阶段使用，但训练中的低精度数值稳定与部署PTQ不是同一流程。

长上下文训练的主要压力是注意力计算和激活；长上下文推理还会积累KV。FlashAttention减少IO和中间存储，不减少稠密attention FLOPs。MoE还会增加router负载不均与all-to-all通信，需要专家并行和容量/路由共同调。

正确顺序是：固定真实shape和质量门槛 → 测端到端并分层trace → 判计算、带宽、显存、通信或调度bound → 只改一个主变量 → 复测P99/goodput或每step时间。ROI来自当前最大瓶颈，不来自某项技术的宣传倍数。
