## 题目

开 cudagraph 为啥会相对更容易 oom?

## 要点

- 三个原因叠加,不是单一原因
- 档位越多,常驻的中间张量越多
- 图池里的中间张量**不释放**,峰值由最大档位决定
- 第三条最容易漏:图池吃掉的显存,KV cache 就用不上了
- 对策三条:调小最大捕获 batch、减档位、多图共享同一个池

## 答案

### 三个原因叠在一起

1. **每个档位一张图**。按 batch 分档捕获,档位越多要常驻的中间张量越多。
2. **图池里的中间张量不释放**。常规 eager 下,一层算完中间结果就还给 allocator 复用;在图里它们必须常驻,因为**地址被冻结了**。峰值由**最大档位**的激活量决定——即使线上绝大多数请求 batch 很小,这块显存也一直占着。
3. **图池占的显存,KV cache 就用不上了**。推理引擎通常把「剩余显存」全部划给 KV cache;图池吃掉一块,能装的 KV 就少一块 → **最大并发数下降**,或者启动时直接 OOM。

第三条是最容易漏答、也是线上最常撞到的一条:表面现象往往不是「捕获时 OOM」,而是「开了图之后可跑的并发变少、长上下文请求被拒」。

### 对策

| 对策 | 代价 |
|---|---|
| 调小最大捕获 batch | 超过档位的大 batch 回退 eager,那部分请求失去图收益 |
| 减少档位数量 | padding 到最近档的浪费变大 |
| 多图共享同一个池 | 需保证共享图之间重放不互相踩 |

顺序上先做第三条(几乎无损),再权衡前两条;判断标准是看图池省下来的显存换成 KV cache 能多撑多少并发。

## 知识点

分档数量与显存的线性关系、图池中间张量常驻、图池与 KV cache 争夺剩余显存、最大捕获 batch 的调参。
