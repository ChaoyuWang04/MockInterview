## 题目

在 PD 分离场景下,讲述下有哪些涉及 KV cache 的操作或者算子?

## 要点

- 按时间顺序给出完整七步,别只答「传一下」
- P 侧要先 gather 成连续 buffer 才传得快,否则是几千次小块散拷
- **D 侧必须重建块表**(最容易答漏的一步)
- 传的是「数据 + 逻辑顺序」,不是指针
- 释放有先后:P 侧确认传完才能放

## 答案

按时间顺序,一条请求的 KV 要过七道:

| # | 阶段 | 具体做什么 | 算子 / 机制 |
|---|---|---|---|
| 1 | P 侧写入 | attention 算完当前层的 K/V 后,按槽位映射**散写**进分页显存的物理块 | cache 写入 kernel |
| 2 | P 侧导出 | 分页布局是打散的,直接发出去是几千次小块散拷、带宽吃不满 → 先在显存里 **gather 成连续 buffer** | 布局转换 kernel;该 buffer 通常直接就是 RDMA 注册区 |
| 3 | 传输 | 连续 buffer → 对端 buffer,机内走 NVLink / P2P,跨机走 RDMA | 传输通道 |
| 4 | D 侧接收 | 数据落进预先注册好的显存 / 内存区 | 单边 RDMA WRITE 或 READ |
| 5 | D 侧建表 | **申请物理块 → scatter 回分页布局 → 重建块表** | 块管理器 |
| 6 | D 侧读取 | 每个 decode step 按块表把散落的块 gather 起来算 attention,并 append 当前 token 的新 KV | paged attention kernel |
| 7 | 释放 | P 侧确认传完才能释放块;D 侧请求结束后归还 | 引用计数 / 块回收 |

### 第 5 步是最容易答漏的

**块表必须重建,不能照搬。** 分页显存里「逻辑块 i → 物理块号」的映射是每个实例私有的,P 侧的第 3 个物理块在 D 侧可能是第 917 个。所以跨实例传的是**数据 + 逻辑顺序**,不是指针或物理块号。

### 两条容易被追问的配套

- **为什么要先 gather**:分页把 KV 打散成一堆 16 token 的小块,直接按块发送会退化成大量小消息,握手与描述符开销占满带宽;先在显存里拼成一段连续 buffer,才能让 NVLink / RDMA 跑到标称带宽。
- **接收侧要提前备好落地**:D 侧的注册 buffer 与物理块必须在数据到达前分配好,否则 P 传不出去、块被占住,反过来把 P 拖慢——这就是 PD 分离里的反压。

## 知识点

槽位映射散写、gather / scatter 布局转换、单边 RDMA 与内存预注册、块表重建、引用计数回收、反压。
