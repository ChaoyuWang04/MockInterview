## 题目

请系统性地列举并解释常见的 Linux 系统网络性能调优手段，涵盖内核参数配置、连接处理与管理、缓冲区设置、IO 模型选择等方面的具体方法，并结合高吞吐、低延迟服务（如大规模模型推理部署）的场景，说明其优化原理与实际应用。

## 要点

- 先用指标确认瓶颈在连接、队列、带宽、CPU 还是应用
- 解释监听队列、socket 缓冲区、拥塞控制各解决什么
- 区分 epoll、SO_REUSEPORT、中断亲和性三种不同机制
- 所有参数都按负载实测，不照抄固定 sysctl 数值

## 答案

**网络调优的核心不是把参数调大，而是先找出包在哪一层排队或被丢弃，再改对应的一层。**

| 现象 | 重点检查 | 常见手段 |
|---|---|---|
| 建连失败、SYN 丢失 | 监听队列、连接速率 | 调整 backlog，扩容监听实例，检查 SYN flood 与防护策略 |
| 吞吐上不去 | socket 缓冲、拥塞窗口、丢包 | 根据带宽时延积设置缓冲上限，选择适合网络的拥塞控制 |
| 连接很多、CPU 忙 | 阻塞线程、系统调用次数 | 非阻塞 socket + epoll，批量收发，减少拷贝和唤醒 |
| 单核被打满 | accept 竞争、中断集中 | SO_REUSEPORT 分摊连接；RSS/RPS 与 IRQ 亲和性分摊收包 |

这些手段职责不同：epoll 管“哪些连接就绪”，SO_REUSEPORT 把新连接分给多个监听 socket，中断亲和性决定网卡收包由哪些 CPU 处理，它们并不互相绑定。`tcp_tw_recycle` 已被 Linux 移除；`tcp_tw_reuse` 也要结合内核版本和连接方向判断，不能当万能开关。

上线前记录基线：吞吐、RTT、重传、丢包、队列长度、软中断 CPU、内存和业务 P99。每次只改一组参数，再用同一负载复测。若 GPU 推理已经饱和，网络优化仍可降低排队和尾延迟，但不会提高模型算力上限；此时应先优化批处理、模型或扩 GPU。

## 知识点

listen backlog、socket buffer、epoll、SO_REUSEPORT、拥塞控制、RSS/RPS、IRQ affinity、基线压测。
