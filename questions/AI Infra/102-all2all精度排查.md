## 题目

自研的 all-to-all 实现替换掉默认通信路径后,跑模型时出现精度问题,你会怎么查精度问题?

## 要点

- 先二分掉范围,别一上来盯着 kernel 看
- 有一条现成的正确性基线:AllGather + ReduceScatter 那条完全规则的路径
- MoE 这条链上可疑点就那么几个,每个都有对应的验法
- 必须先把随机性固定住,否则分不清"错了"和"不确定"
- 最后要能区分"真 bug"和"浮点不结合导致的末位差异"

## 答案

### 第一步:先把范围二分掉

1. **换回基线**:把自研 all-to-all 换成 AllGather + ReduceScatter 那条路径——它完全规则、形状静态、不用交换计数表,最不容易错。换回去就好 → 问题在通信实现;还是不对 → 别在通信上耗时间
2. **单卡对照**:EP=1 跑一遍,和多卡逐层比中间张量,**差异从哪一层开始放大就锁到哪一层**
3. **固定随机性**:关掉采样走 greedy、固定 batch 组成与 padding,否则你分不清"错了"和"只是不确定"

### 第二步:按 MoE 这条链逐个排

| 可疑点 | 怎么验 |
|---|---|
| **排列没逆回来** | dispatch 前做过一次按专家 id 的 argsort + gather,combine 后必须精确逆置。把专家换成恒等映射,输出应与输入逐元素相等 |
| **门控权重加错位置** | 加权求和在 combine **之后**、按每个 token 自己那 $k$ 份权重相加。令所有权重恒为 $1/k$ 再和单卡比,能把"权重错"和"数据错"分开 |
| **计数表 / split sizes 对不上** | 收发条数不匹配时往往**不报错**,只是读到脏数据。逐 rank 打印发送条数与接收条数,两边总和必须相等 |
| **token 被丢了** | capacity 封顶下超出的 token 走残差旁路,**推理侧丢 token 会直接改变输出**。统计实际参与专家计算的 token 数是否等于 $Tk$ |
| **低精度档位** | FP8 dispatch 送的是马上进低精度 GEMM 的输入,combine 送的是要进残差流的输出(官方配 BF16)。把两段都提到 BF16 试一次,能定位是不是精度档的问题 |

### 第三步:区分"真错了"和"只是不一样"

浮点加法不满足结合律,**规约顺序一变结果就有末位差异**——换了通信实现必然改变求和顺序,所以"和基线不完全 bitwise 相等"本身不是 bug。

判据是看**误差随层数是发散还是稳定**:稳定在 $10^{-3}$ 量级、不随层数放大 → 数值噪声;某一层突然跳几个数量级 → 真 bug。定量上用**相对误差 + 下游指标**(困惑度或一个小评测集)双看,别只盯单点最大差。

## 知识点

换回规则基线做二分、单卡逐层对照、恒等专家验排列、等权重验门控、计数表守恒、精度档二分、浮点不结合与误差发散判据。
