## 题目

draft KV cache 和 target KV cache 是共享的吗?如果推测的 token 没被接受,draft 和 target 的 KV cache 分别怎么处理?

## 要点

- 不共享:两个独立模型,层数、KV 头数、head_dim 与语义都对不上,只共享 token 序列
- KV 是**追加写**的,写完不再改 —— 所以「撤销」只需移动长度指针,不用擦数据
- target 与 draft 的回退位置不同,要分开说
- target 补出的那个新 token 还没进过 draft,下一轮由 draft 的第一次前向补上
- 分页管理下回退基本不触发块的分配释放

## 答案

### 共享吗:不共享

draft 和 target 是**两个独立模型**——层数、KV 头数、head_dim 全不一样,KV 张量形状根本对不上,更不用说语义(每层 K/V 是各自模型学出来的表示)。所以**两边各自维护一套 KV cache,只有 token 序列是共享的**。

MTP / EAGLE / Medusa 这类「寄生在 target 上」的方案略有不同:它们复用 target 的隐藏状态,但 draft 头自己那部分仍有独立的小 cache。

### 拒绝之后怎么处理

关键认知:**KV cache 是追加写的,每个位置写完就不再改**。所以「撤销」不需要真的擦除,只要**把序列长度指针往回移**——下一轮写新 token 时直接覆盖那片区域。这是回滚几乎零成本的根本原因。

| | 验证前写到哪 | 接受 $j$ 个之后 | 怎么回滚 |
|---|---|---|---|
| **target** | 一次前向把 $k+1$ 个位置的 K/V 全写进去了 | 只有前 $j+1$ 个有效 | 长度指针置为 $\text{base}+j+1$,后面几个位置变成待覆盖的垃圾,不用清 |
| **draft** | 自回归 $k$ 步,写了 $k$ 个位置 | 只有到分叉点为止有效 | 指针退回分叉点;target 补出的新 token 还没进过 draft,**下一轮 draft 的第一次前向把它喂进去**,顺带补上它的 KV |

两个工程细节:**分页管理下**回滚就是把块内偏移减回去,一轮退几个 token 通常连一个块都退不满,所以**基本不触发块的分配与释放**;**树形草稿**(多分支候选)一次验证多条路径,未被接受的分支写进去的 K/V 全部作废,同样是移指针,复杂度主要在树注意力的 mask 上。

## 知识点

两套独立 KV、追加写语义、长度指针回退、分页下的块内偏移回退、树形草稿的分支作废。
