## 题目

多个子 Agent 并行产出局部结论后,全局状态怎样合并?要处理哪些一致性问题,合并结果又如何保证可复现?

## 要点

- 先定状态模型:合并的是结构化事实,不是自然语言段落
- 每条结论必须带来源、时间和置信度,否则无法合并只能拼接
- 写入用追加式事件日志加投影,天然幂等且可重放
- 冲突分三类:重复、矛盾、时序错位,处理方式各不相同
- 主管做裁决而不是求平均,证据强度不等于出现次数

## 答案

**合并的前提是有一个结构化的状态模型。** 如果子 Agent 交回来的是自然语言段落,那就只能拼接不能合并——主管无从判断两段话说的是不是同一件事。所以先定 schema:实体、断言、证据引用,以及每条结论必带的三个字段——**来源、观测时间、置信度**。

**写入协议**用追加式:子 Agent 不直接改全局状态,而是向事件日志追加带 ID 的结论,全局状态由日志投影得到。好处是三条:重复提交天然幂等(按 ID 去重)、任何时刻可重放复现、出错能回溯到具体是哪个子 Agent 的哪次调用。

**冲突分三类,处理方式不同:**

| 类型 | 表现 | 处理 |
|---|---|---|
| 重复 | 多个子 Agent 报同一事实 | 按实体+断言归一去重,合并证据列表 |
| 矛盾 | 结论相反 | 交主管裁决,依据证据强度与来源可靠性 |
| 时序错位 | 结论基于不同时刻的观测 | 按观测时间而非返回时间排序,晚到的旧观测不覆盖新结论 |

时序这条最容易漏:子 Agent 返回有先后,但它们观测的是不同时刻的系统状态。用返回顺序覆盖会让旧数据盖掉新数据,必须以**观测时间戳**为准。

**裁决不是求平均。** 三个子 Agent 说 A、一个说 B,不代表 A 对——它们可能查的是同一份被污染的数据源。主管应当按证据强度和来源独立性裁决,并且把"存在分歧"这件事本身保留在状态里,而不是抹平后只给一个结论。仲裁策略的完整比较见 [多智能体冲突](017-多智能体冲突.md)。

边界:合并逻辑要有确定性——同一组输入必须得到同一个全局状态,否则整个系统不可测试。所以裁决规则应尽量写成规则而非交给模型自由发挥,模型只在规则覆盖不到时介入。

## 知识点

结构化状态 schema、来源/时间/置信度三元、事件日志与投影、幂等写入、观测时间与返回时间、证据独立性、确定性合并。

任务怎样分发见 [子 Agent 分工与任务分发](027-子agent分工与任务分发.md);会话状态的存储与一致性见 [会话状态管理](019-会话状态管理.md)。
