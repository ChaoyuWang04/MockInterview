## 题目

在 Agent 中集成 RAG 时，哪些检索、上下文和工具编排问题会影响响应延迟与结果正确率？请分析成因、性能与精度权衡、可扩展性，并提出可验证的优化方案。

## 要点

- 先区分知识缺失、漏召、错排、上下文污染和生成未用证据
- 稀疏/稠密召回、过滤、重排分别解决不同问题
- Agent 每一步的检索、模型和工具时延沿实际路径累积
- 缓存、并行和降级必须服从权限、新鲜度与任务风险
- 检索指标、回答忠实度和端到端任务成功率分层评测

## 答案

**先用可追踪评测集确定证据在哪一层丢失，再优化对应环节；接入 Agent 后还要把每次检索放进全链路 deadline。**

先从真实请求标注支持答案的文档块。知识库没有正确内容时先补数据；正确块未进候选集时检查查询改写、切块、Embedding/索引版本、权限和元数据过滤；已召回但排序差时再调混合召回、RRF或重排；证据已送入仍答错，则排查冲突、压缩丢条件和生成器是否忠于证据。HyDE可能帮助跨表达检索，也可能放大错误前提，必须与原查询和关键词召回对照。

延迟主要来自在线编码、ANN搜索与过滤、重排、上下文生成、工具RPC和多轮循环；HNSW建图主要是写入/离线成本。各阶段通常沿路径相加，Agent重复调用会反复累积。可缓存带租户、权限、模型和数据版本的结果，并行无依赖步骤，限制检索/推理步数；低置信度时改问澄清问题、返回有依据的部分结果或明确拒答，不能默认相信参数知识。

离线分别看 Recall@K、MRR/nDCG、引用支持率和忠实度；线上看任务成功率、P95/P99、成本、缓存陈旧率与降级率。Top-K、阈值和量化参数都应在相同预算下实测。

## 知识点

分层诊断、Query Rewrite、Hybrid Search、RRF、Reranker、证据忠实度、Agent deadline、可版本化缓存。
