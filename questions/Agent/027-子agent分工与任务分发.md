## 题目

主管-子 Agent 架构里,子 Agent 按什么维度分类?它们是静态注册还是运行时动态创建?任务又按什么机制分发?

## 要点

- 分类维度决定了工具集与权限边界,按数据源或职能切最稳
- 静态注册可审计、可预热;动态派生灵活但难以限权和复现
- 分发机制三种:定向路由、广播、竞标,代价依次上升
- 主管只做编排与裁决,不亲自执行,否则上下文会爆
- 必须设并发上限、超时和终止条件,否则子 Agent 会无限派生

## 答案

**先把"分几类"和"怎么创建"分开——前者是权限设计,后者是运行时机制。**

**分类维度**决定每个子 Agent 拿到哪些工具和什么权限。实践中按**数据源或职能**切最稳定:比如日志检索、指标查询、配置变更审查、代码归因,各自一类。按"任务难度"或"业务模块"切则容易随需求漂移。分类的直接产出是一张表:每类的工具白名单、可访问的数据范围、是否允许写操作。

**创建方式**是明确的取舍:

| 方式 | 优点 | 代价 |
|---|---|---|
| 静态注册 | 权限可审计、可预热、行为可复现 | 覆盖不到没预料的任务类型 |
| 运行时派生 | 灵活,能按任务临时组合工具 | 难限权、难复现,容易失控派生 |

多数生产系统用**静态注册的类型 + 运行时实例化**:类型和权限是固定的,主管只决定起几个、传什么参数。这样既保留并发弹性,又不让权限边界变成动态的。

**分发机制**按代价递增:

1. **定向路由**:主管按规则或分类模型直接指派。最省 token,要求主管能判断任务类型。
2. **广播**:同一任务发给多个子 Agent,取最优或投票。适合归因这类"不知道答案在哪"的场景,成本成倍。
3. **竞标**:子 Agent 先报置信度或能力匹配度,主管再选。多一轮交互,适合子 Agent 异构且能力差异大时。

三条工程约束必须说到:主管**只做编排与裁决,不亲自执行**,否则所有原始数据都进主管上下文,很快超预算;必须设**并发上限、单任务超时和最大派生深度**,否则子 Agent 会互相派生直到失控;每个子 Agent 的产出要带**来源与置信度**,否则后面无法合并,见 [子 Agent 全局状态合并](028-子agent状态合并.md)。

多智能体的一般收益条件与协同机制见 [多智能体协同](016-多智能体协同.md),本题不重复。

## 知识点

职能切分与工具白名单、静态注册与运行时实例化、定向路由/广播/竞标、主管上下文预算、派生深度与并发上限。
