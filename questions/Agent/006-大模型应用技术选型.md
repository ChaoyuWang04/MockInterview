## 题目

请比较提示工程、上下文学习、微调、RAG 和 Agent 的原理、能力边界、成本与适用场景，并说明如何结合具体大模型产品的功能和用户体验做技术选型与改进。

## 要点

- 说明五种方法并非同层互斥，可组合使用
- 从任务行为、知识时效、多步行动、可追溯性、延迟与成本选型
- 产品分析区分公开能力、推测架构和真实用户价值
- 对具体产品能力标明 2026-09 时效

## 答案

**先判断缺的是行为、示例、知识还是行动能力，再选最小可行组合**。提示工程用指令和格式约束已有能力；上下文学习（ICL）用少量示例临时适配；微调改变稳定的行为、风格或领域能力，但不适合保存频繁更新的事实；RAG 在回答时注入可更新、可引用的证据；Agent 只在任务需要多步决策、工具和外部动作时增加控制循环。

选型可按四问推进：知识是否常变？是否必须引用来源？是否存在动态分支和副作用动作？延迟、数据、维护预算是多少？例如司机政策答疑可用 RAG，订单异常若需查单、改派和转人工，可用受控工作流加工具调用；实时定价本身通常是专用预测与优化系统，不能简单归为“微调大模型”。

以讯飞星火/星辰平台为例（截至 2026-09）：官方文档公开了联网搜索、代码生成、知识库，以及由大模型、代码、决策、知识库等节点组成的工作流。由此只能确认它在产品层组合了检索和 Agent 式编排，不能反推出内部模型结构。它的产品价值是让不写代码的用户也能搭建垂直问答或业务流程；改进时应重点补来源与时间提示、工具权限解释、步骤追踪、失败恢复和发布前评测。C 端看任务成功率与等待时间，B 端还要看租户隔离、来源审计、更新成本和人工兜底。
