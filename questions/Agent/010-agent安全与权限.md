## 题目

在真实业务中部署 AI Agent 时，如何从算法机制和系统架构两层防止隐私泄露与越权操作？请说明权限控制、敏感信息过滤与脱敏、调用审计和日志监控的设计原理与实施要点。

## 要点

- 安全判断不能只靠 LLM，模型外必须有强制策略边界
- 用户、工具和数据三层鉴权，凭证短期化且权限最小化
- 输入、检索、工具参数和输出均做敏感信息检测
- 全链路审计要可追踪，也要避免日志二次泄密
- 能回答提示注入、长链路权限回收和体验取舍

## 答案

**核心原则是：模型可以提出动作，可信执行层才有权批准动作。** 算法层负责识别风险，系统层负责强制执行；即使模型被提示注入，越权请求也不能穿过策略边界。

算法层对输入、RAG 片段、工具参数和最终输出分别检测。身份证、手机号等用规则，姓名、地址等用实体识别或分类模型；LLM 只能辅助判断上下文，不能作为唯一防线。敏感字段按用途做掩码、删除或令牌化，并保留数据来源和敏感级别。

系统层先认证用户，再按用户、工具、数据行或字段逐级授权。工具通过可信注册表暴露，执行器使用带作用域和有效期的临时凭证；转账、删除、对外发送等动作进入预提交状态，由用户确认。第三方内容一律视为数据，不能改写系统指令；同时限制网络出口和可调用工具，并在输出端做 DLP 检查。

每次请求用 trace ID 串联模型、检索和工具。日志记录身份、策略结论、工具名、耗时和脱敏摘要，不直接保存密钥、完整参数或私密上下文。长任务按步骤签发能力令牌，可随时撤销；低风险请求静默放行，高风险请求再升级认证或确认，以减少不必要打断。
