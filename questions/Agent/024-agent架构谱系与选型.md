## 题目

你了解哪些常见的 Agent 架构?它们的分界在哪里?什么条件下应该选择 Workflow 型而不是让模型自主规划?

## 要点

- 分界是"下一步做什么"由谁决定:人写的控制流,还是模型
- 谱系按自主度递增:固定 Workflow、Plan-and-Execute、ReAct、多 Agent
- 自主度越高,能力上限越高,可预测性和可调试性越差
- 选 Workflow 的条件是流程已知且稳定、要求可审计、错误代价高
- 现实系统多是分层混合,不是单选

## 答案

**这些架构的真正分界只有一条:"下一步做什么"由人写的控制流决定,还是由模型决定。** 按模型自主度从低到高:

| 架构 | 谁决定下一步 | 适合什么 |
|---|---|---|
| 固定 Workflow | 人写的编排图 | 流程已知稳定、要可审计、错误代价高 |
| Plan-and-Execute | 模型先出计划,再按计划执行 | 任务可提前拆解,步骤间依赖清晰 |
| ReAct | 模型每步根据观察决定下一步 | 路径依赖中间结果,无法预先规划 |
| 多 Agent | 主管分派,子 Agent 各自决策 | 子任务异构、可并行、需要不同工具集 |

自主度是一条明确的取舍轴:越往下能力上限越高,可预测性、可调试性和成本可控性越差。ReAct 能处理没预料到的分支,但也可能在错误路径上循环;多 Agent 能并行,但引入了状态合并和冲突。

**选 Workflow 的条件**很具体,满足其一就该优先考虑:

1. 流程本身已经确定且稳定,变化频率低于迭代提示词的成本
2. 需要逐步可审计——金融、医疗、风控场景常是硬要求
3. 单步错误代价高,必须在固定位置插入人工确认或规则校验
4. 延迟和成本有硬预算,不能接受模型多轮试探

反过来,当长尾分支多到规则覆盖不划算、且失败可自动检测时,固定编排就成了瓶颈,该往上走——继续演进到用 RL 训练策略的条件见 [Workflow 编排与 Agentic RL](../RL/028-workflow编排与agenticrl.md)。

实际系统很少是单选:高风险环节保留确定性编排和人工确认,把自主决策放在探索空间大、失败可回滚的环节。谈架构选型时应该给出这条分界线画在哪里,而不是宣称某种架构更先进。
