## 题目

从零设计一个具备自主决策和工具使用能力的 AI Agent。说明感知、规划、记忆、工具调用、执行反馈等核心组件的职责、数据流与技术选择，并解释它们如何协同完成复杂任务。

## 要点

- LLM 是决策组件，编排器和策略层才控制真实执行
- 规划、状态、记忆、检索、工具和验证职责分离
- 给出从输入到结束、失败恢复和人工确认的完整闭环
- 说明 ReAct、预先规划、RAG 和多 Agent 的选择条件
- 区分运行时反思、记忆写回与模型训练

## 答案

**可落地的 Agent 是“模型决策 + 外部状态机 + 受控执行器”，不能让 LLM 直接支配真实系统。** 感知层把文本、图像和环境事件转成结构化输入；编排器维护目标、任务状态、预算和 deadline；规划器对简单任务直接选择动作，对依赖明确的复杂任务先生成任务图，环境变化后再局部规划。

工作记忆保存当前步骤和中间结果，长期记忆保存有来源、版本、权限和有效期的稳定信息；RAG 按需取回外部知识，不把一次模型“反思”直接写成事实。工具网关用强类型契约完成选择、参数校验、鉴权和执行，结果以结构化 Observation 返回。验证器检查任务是否完成，高风险或不可逆动作停在预提交状态等待确认。

完整闭环是：输入解析→读取状态/检索→计划→策略校验→工具执行→验证→更新状态→继续或结束。瞬时且幂等的工具错误可限次退避重试，其他错误换工具、重规划或转人工。ReAct 适合结果会改变下一步的任务；Plan-and-Solve 适合依赖较稳定、可预先分解的任务。多 Agent 只在并行或专业分工收益明显时采用。评测看成功率、步骤/重复率、错误恢复、延迟、成本和人工接管；轨迹经验证后才能用于后续提示或训练。

## 知识点

Agent 控制平面、状态机、规划、记忆、RAG、工具契约、Observation、验证器、人机协同。

## 追问

相关真题追问：

- 工具失败、返回异常或格式错误时，怎样重试、降级和恢复？
- 长期记忆如何与 RAG 结合并控制膨胀？
- ReAct 与 Plan-and-Solve 各适合什么任务？
- Agent 与 RAG 各解决什么问题，如何组合？
- 多 Agent 何时值得使用，通信和任务分解怎样设计？
- 如何评估 Agent，并理解反思、记忆写回与持续学习的区别？
