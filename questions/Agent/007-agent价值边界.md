## 题目

请分析大模型 Agent 的核心价值、局限和适用条件，并结合 RAG、固定 Workflow 与多 Agent 说明工程权衡、典型场景和发展趋势。

## 要点

- 价值来自多步决策、工具使用和环境反馈，不是“更像人”
- 区分 Agent、RAG 与固定 Workflow，并说明可组合关系
- 覆盖错误累积、延迟成本、状态、安全、可控性和评测
- 趋势结论说明依据，不把预测或内部案例写成事实

## 答案

**Agent 的价值是在目标不确定、步骤需随环境变化时，动态选择工具和下一步；如果路径稳定，固定 Workflow 往往更可靠、更便宜。**RAG 负责取回有来源的知识，Agent 负责任务控制，二者可以组合，没有“谁是增强版”的关系。

适合 Agent 的任务通常同时具备三点：需要多步分解，必须读取或改变外部系统，且分支不能在开发时完全枚举。例如数据分析可根据中间结果改写查询；客服若只是政策问答，用 RAG 即可，涉及查订单、退款和转人工时才需要受控工具流程。

局限来自长链路：一次错误会改变后续状态，多轮调用增加 token、延迟和失败面；工具输出与网页内容可能提示注入，副作用动作还涉及授权和审计。生产系统应使用显式状态、schema 与业务校验、最大步数和预算、幂等与补偿、低置信转人工，并按任务完成率、错误恢复率、工具成功率、P95/P99 延迟、成本和安全事件评测。模型生成的思维链不等于可信解释。

所谓“单工具→多步规划→多 Agent”可作为能力层次，不是统一历史版本。可预期的方向是更强的工作流约束、验证器、可观测性和人机协作；多 Agent 只有在角色拥有不同权限、信息或并行任务时才可能值得，不能把角色数量当智能程度。

## 知识点

Agent 价值边界、Workflow、RAG、错误累积、工具安全、终止条件、端到端评测。
