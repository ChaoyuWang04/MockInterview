## 题目

通用 Agent 与垂直 Agent 的技术边界在哪里?垂直 Agent 的核心竞争力来自哪些可以被验证的东西?

## 要点

- 分界不在领域词表,在环境是否封闭、成功是否可判定
- 通用 Agent 赌的是基座泛化,垂直 Agent 赌的是环境与评测的确定性
- 竞争力要落到可验证的四项:工具深度、私有数据、领域评测集、失败兜底
- 基座每次升级都会吃掉一部分只靠提示词堆出来的垂直优势
- 判据是"换个更强基座后还剩什么",不是当前效果好不好

## 答案

**分界不在于领域词汇,而在于环境是否封闭、成功是否可判定。** 垂直 Agent 面对的工具集有限、状态空间可枚举、结果通常能程序化校验;通用 Agent 面对开放环境,连"做完了没有"都难判定。这条差别决定了后面所有工程选择。

由此推出两者赌的东西不同:通用 Agent 赌基座模型的泛化能力,随基座升级而水涨船高;垂直 Agent 赌的是环境和评测的确定性——正因为封闭,才能把工具做深、把失败模式穷举、把评测做成可回归的集合。

谈"核心竞争力"必须落到可验证的东西上,否则只是话术。真正立得住的有四项:

1. **工具深度**:不是接了多少 API,而是把领域动作封装到什么粒度、错误语义是否可区分、失败能否自动重试或降级
2. **私有数据与反馈闭环**:线上真实轨迹带来的数据是不可复制的;有没有形成"失败 → 标注 → 回流训练/规则"的闭环
3. **领域评测集**:覆盖真实分布和长尾的、可回归运行的评测,是垂直 Agent 最硬的资产,也最难被抄
4. **失败兜底**:在这个领域里做错的代价是什么,系统如何检测、拦截、回滚、交人

反过来,**只靠提示词工程和流程编排堆出来的优势最脆弱**——基座每升一代就会吃掉一部分。评估一个垂直 Agent 的护城河,判据应当是"把基座换成更强的模型之后还剩下什么",而不是当前效果比通用产品好多少。

边界:这个划分是连续谱不是二分。很多产品是"通用底座 + 垂直工具与评测",竞争力来自后两者;讨论时应说清哪一层是自己做的。

## 知识点

封闭环境与可判定性、工具粒度与错误语义、数据反馈闭环、领域评测集、基座升级的侵蚀效应、护城河判据。
