## 题目

Agent 调用外部工具遇到超时、错误响应、空结果或业务失败时，如何向模型反馈、决定重试或切换工具、设置重试上限，并通过熔断、降级和用户澄清保证任务连续性？

## 要点

- 执行层先分类和清洗错误，再给模型可操作的结构化反馈
- 仅对瞬时且幂等的失败做有预算的退避重试
- 重试、切换、降级、澄清和终止由状态机明确编排
- 熔断、隔离、限流和重试预算防止故障放大
- 记录可观测指标，用受控数据改进策略

## 答案

**先由执行层判断错误语义和风险，再让 Agent 规划；不要把原始堆栈、不可信工具文本或固定“重试三次”直接交给模型。**

工具返回统一结构：错误类别、可否重试、状态码、Retry-After、数据新鲜度和安全摘要。超时、限流、短暂5xx可在剩余 deadline 内指数退避并加 jitter；只有幂等调用或带幂等键的副作用操作才能自动重试。认证失败应修复凭证或升级处理，NOT_FOUND可能是有效业务结果，不能一律换工具。

状态机可按“调用→重试→备用工具→降级→澄清/终止”前进。备用工具必须语义等价且权限足够；非核心能力失败可用可信旧缓存、裁剪功能或返回部分结果，核心事实或高风险操作失败则明确失败。用户意图有歧义、空结果可能由条件不足造成，或降级会明显改变结果时，才发起具体澄清。

高并发下配置每跳超时、全链路 deadline、重试预算、隔离舱、限流和熔断，避免下游故障变成重试风暴。重试次数、退避、熔断阈值没有通用值，应按成功率、P99、成本和业务损失实测。长期改进来自聚合后的可靠性数据和人工审核，不能把单次失败日志直接写成长期事实。

## 知识点

结构化错误、幂等键、指数退避、jitter、Retry-After、deadline、熔断、隔离舱、功能降级。
