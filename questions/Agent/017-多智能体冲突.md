## 题目

多 Agent 系统中，某个 Agent 误判并与其他 Agent 的策略冲突时，如何检测、缓解和解决冲突？请比较通信协议、共识、优先级调度和监督仲裁等方案的实现与适用场景。

## 要点

- 区分存活故障、状态冲突、资源冲突和语义策略冲突
- 心跳只能检测存活，语义冲突还需约束和证据校验
- 协调按预防、协商、仲裁、补偿和人工逐级升级
- 准确说明 Raft 与 BFT 的故障边界
- 不可逆动作、实时安全系统和吞吐取舍有明确边界

## 答案

**先定义冲突类型，再选协调机制；共识协议只能统一状态顺序，不能判断哪个策略语义上正确。** 心跳和租约检测 Agent 是否存活，版本号和 compare-and-set 检测并发写冲突；资源预留表发现重复占用；计划提交前用业务不变量、约束求解器或独立验证器检查目标、动作与安全规则是否相容。

协调可分层处理。第一层用状态所有权、租约、幂等键和权限隔离预防冲突；第二层按任务优先级、deadline 或竞价协商资源；第三层把双方的证据、版本和代价提交给仲裁器。已执行的可逆动作通过补偿事务恢复，不可逆动作必须在提交前审批，不能指望分布式快照自动回滚外部世界。

中心仲裁容易治理但有单点和排队瓶颈；去中心化扩展性更好，却需明确网络分区与故障假设。Raft 处理崩溃故障，不处理拜占庭节点；需要抗任意恶意行为时才考虑 BFT 类协议，并接受更高通信成本。自动驾驶多车协同等实时安全控制应由确定性、安全认证的控制协议负责，LLM 可提供受约束建议，不能进入毫秒级安全闭环。

评测时固定任务负载，比较冲突发现率、误报率、仲裁时延、回滚/补偿成功率、吞吐、通信量和故障下任务成功率。
