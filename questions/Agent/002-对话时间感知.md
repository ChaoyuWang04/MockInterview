## 题目

对话系统如何建模时间信息?请区分当前时间、事件时间、相对时间和知识新鲜度,说明跨会话记忆、RAG 检索、确定性时间工具及评测方法。

## 要点

- token 顺序位置不等于现实日历时间
- 相对时间先归一化为带时区的结构化时间
- 长期记忆记录发生时间、写入时间、有效期和来源
- 检索既看语义相关性,也做时间过滤和新鲜度排序
- 日期算术和时区换算优先交给确定性工具

## 答案

**时间感知至少包含四件事:知道系统当前时间,解析用户说的事件时间,维护跨会话事件顺序,以及判断知识是否过期。** RoPE 或位置编码只表示 token 在序列中的顺序,不会自动知道“今天”、时区、节假日或现实中的现在。

输入层先保存请求时间、用户时区和会话 ID。时间解析器把“上周五”“三天后”归一化成区间或时间戳,同时保留原文和不确定性;“今天”必须绑定该轮请求时刻。长期记忆中的事件至少记录 event_time、created_at、updated_at、valid_from/to 和来源,使“上周说的方案”能先按实体与语义召回,再按时间窗口、会话关系和版本过滤。被后续信息推翻的记忆应失效或保留版本,不能只覆盖文本而丢掉历史。

RAG 中可把时间条件写入查询和元数据过滤,对新闻、价格、制度等内容按新鲜度排序,并把文档日期展示给模型。语义相似度高不代表时间正确,因此要检查未来信息泄漏、过期文档和冲突版本。日期加减、时区换算、交易截止时间等确定性问题应调用日历或时间工具,模型负责解析意图和解释结果。

评测要拆开:时间表达归一化准确率、事件先后/持续时间推理、跨轮指代、跨会话召回、检索时间过滤、过期答案率和端到端任务成功率。测试集要固定“系统当前时间”,覆盖时区、闰年、模糊表达与知识更新。索引的存储开销取决于字段、分片和压缩,不能写成固定百分比。

## 知识点

对话时间感知由时间解析、结构化记忆、时间约束检索、确定性工具和专项评测共同完成。
