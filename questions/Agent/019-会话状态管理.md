## 题目

多轮对话或 Agent 系统如何管理会话状态？请说明存储、动态更新、长度截断、生命周期，以及分布式高并发下的一致性和性能设计。

## 要点

- 消息原文、任务状态、上下文视图和长期记忆分开存
- 按语义优先级压缩，而不是机械删除最早消息
- 明确会话创建、活跃、挂起、归档和过期生命周期
- 通过版本号、CAS、幂等和顺序键处理并发写入
- 用负载模型、P95/P99 和一致性故障验证方案

## 答案

**会话状态要有唯一事实源，模型上下文只是按本轮预算生成的读取视图。** 原始消息和工具事件追加写入持久库；Redis 等缓存保存活跃会话的近期状态；任务检查点、实体、摘要和审计信息分别结构化存储。

每轮先读取系统约束、当前目标、未完成步骤和必要工具结果，再按 token 预算加入近期原文、滚动摘要与检索到的长期记忆。超限时优先压缩已完成片段，保留未决约束和 source 指针；摘要失败仍能回查原文。中间工具输出应标明步骤、版本和可信状态，未经校验的结果不能污染最终事实。

分布式场景可按 session_id 路由，但粘性会话不能代替一致性。写入携带 turn_id、幂等键和版本号，用 CAS/事务拒绝乱序覆盖；需要“读己之写”时读主副本或带版本读取，不能假设任意副本都最新。异步持久化只用于允许短暂不一致的数据，关键检查点须先落盘再确认。

生命周期至少包括创建、活跃、挂起、恢复、归档和删除，并定义 TTL、故障恢复和隐私策略。压测应说明请求分布、对话长度与读写比例，报告吞吐、P95/P99、冲突重试率和数据丢失/陈旧读。

## 知识点

会话状态、追加日志、上下文视图、CAS、幂等写入、读己之写、检查点、生命周期。
