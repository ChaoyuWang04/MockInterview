## 题目

Agent 为什么常用向量数据库检索长期记忆？请说明 Embedding 模型、记忆切块、索引、过滤、时间因素和重排序如何设计，并解释向量检索的适用边界。

## 要点

- 向量库擅长语义近邻，但不是完整记忆系统
- 模型和切块由真实 query-memory 任务评测决定
- ANN、元数据过滤、混合召回和重排各负其责
- 时间衰减、Top-K 和阈值没有跨场景通用值
- 版本、来源、租户隔离、删除和冲突治理不可缺少

## 答案

**向量数据库适合从大量非结构化历史中找语义相近片段，但它只是检索索引。** 当前任务状态、权限和稳定画像宜放关系库或 KV；原始对话进入可审计存储；向量库保存可检索表示和原文指针。

Embedding 先按目标语言、领域、长度、吞吐和真实 query-memory 对评测，通用模型不足时再用人工复核的正负例微调。切块应围绕完整事件、对话轮次或事实，过小会失去语境，过大则降低定位精度；每块附带用户、会话、时间、生效区间、来源、权限和版本。

百万级检索可按规模、更新频率、过滤能力、内存和召回目标选择 HNSW、IVF-PQ 或磁盘索引。查询时先做租户/权限等硬过滤，再并行稠密与 BM25 召回，用 RRF 或校准分数融合，最后对有限候选重排。稳定偏好不能因时间久就自动衰减；实时事件才强调新鲜度。Top-K、0.7 阈值、固定 chunk 长度和“毫秒级”都不是通用结论。

离线看 Recall@K、MRR/nDCG、冲突与过期率，线上看记忆使用后的任务成功率、纠错率、尾延迟和成本；同时支持更正、删除、索引重建与回滚。
