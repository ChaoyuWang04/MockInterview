## 题目

用 PPO 或 GRPO 对大模型做强化学习微调后，为什么可能在非训练分布（OOD）任务上退化？请区分灾难性遗忘与奖励过优化，给出至少三类缓解手段，并说明怎样选择训练比例、KL 强度和评测指标。

## 要点

- 窄训练分布、代理奖励偏差和更新过强是不同问题
- 用基座能力与独立偏好评测区分遗忘和奖励过优化
- KL、保留数据、扩展覆盖、独立评委和早停各管一层
- GRPO 免 critic 不等于 OOD 泛化更好
- 拒绝采样与 PPO 的成本、探索和筛选偏差不同

## 答案

**OOD 退化通常不是单一算法故障，而是训练分布、奖励代理和更新幅度共同作用。** prompt 或奖励覆盖过窄时，策略会把容量集中到高频模式；代理 RM 偏爱长度、格式或迎合时，在线优化会放大漏洞；学习率、epoch 或 KL 设置不当又会让模型快速远离基座。旧能力所需数据长期不出现，还会发生灾难性遗忘。

区分两类问题要同时看两条轴。若通用语言损失、基座基准和未参与奖励设计的旧任务普遍下降，更像遗忘；若训练 RM 分继续升高，但人评、独立验证器或真实业务指标下降，并伴随长度、格式等捷径，更像奖励过优化。两者可以同时发生，所以要保留基座、SFT 和各 RL 检查点，在相同模板与解码参数下按任务、难度、长度和分布切片比较。

常用缓解手段有：

1. **限制漂移**：加入相对 reference 的 KL、减小学习率或更新 epoch、按实测 KL 和独立指标早停。KL 太大时策略几乎冻结、奖励学不上去；太小时容易漂移和钻奖励漏洞。应先统一按 token/序列及 KL 方向的口径，再围绕目标行为区间调系数。
2. **保留旧能力**：在 RL 目标旁混入高质量 SFT 或预训练保留数据的交叉熵损失，也可冻结部分参数或用较小可训练子空间。这里重放的是保留数据；直接长期复用旧 PPO rollout 会产生策略陈旧，不能混为一谈。
3. **扩大覆盖并改进奖励**：增加领域、难度和对抗 prompt，校准多个奖励分量，用独立评委、人类抽检和留出集选择检查点。单靠训练中的同一个 RM 分不能证明泛化。

RL:SFT 比例没有通用常数。先让各损失按 token 和有效样本正确归一化，再根据梯度尺度、关键旧任务掉点与目标任务增益做小范围扫描；旧能力先掉就提高保留项或降低 RL 强度，目标学不动则反向调整。这个比例是控制器，不是行业固定配方。

GRPO 去掉 critic，可能降低工程复杂度；组内相对奖励也能减弱 prompt 间奖励尺度差异。但它仍使用同一训练分布和奖励，组大小不是 OOD 泛化机制，因此不能断言比 PPO 更抗退化。拒绝采样是生成多个候选、筛选后再 SFT，流程简单稳定，却受候选覆盖与筛选器偏差限制；PPO 能在线改变采样分布、继续探索高奖励行为，但成本更高，也更容易放大奖励漏洞。选择时应比较同预算下的独立评测，而不是默认某一路线保留 reference 分布。

上线监控至少包含训练奖励、独立奖励/人评、reference KL、熵、回答长度和多样性，以及固定的域内、OOD、安全和拒答切片；用回归阈值、趋势告警和检查点回滚判断是否退化。
