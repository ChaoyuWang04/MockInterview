## 题目

大模型强化学习对齐中的 Reward Function 应怎样设计?请说明信号来源、多目标冲突和训练稳定性的处理方法,并分析 Reward Hacking 的成因、识别方式与缓解手段。

## 要点

- 区分学习型 Reward Model 与训练时完整 Reward Function
- 覆盖偏好、规则、验证器、过程奖励和结果奖励等信号来源
- 说明量纲校准、加权、硬约束与安全门控怎样处理目标冲突
- 从代理目标错位解释 Reward Hacking,给出具体模式和至少三类缓解方法
- 用分量指标、人评、红队和真实任务评测闭环,不只看总奖励

## 答案

**先把真正目标拆成可验证的分量,再决定哪些做软奖励、哪些必须做硬约束。** Reward Model 只是完整 Reward Function 的一个来源；训练时常还会加入规则分、可验证结果、格式要求和 reference KL。

一个示意写法是

$$
R(x,y)=\sum_i w_i\,\widetilde r_i(x,y)-\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\rm ref}),
$$

其中 $\widetilde r_i$ 是校准到可比较尺度的有用性、事实性、安全性或任务分。权重只是待验证超参数。合规、资金操作等不可违反的条件更适合先用门控或约束拦截,再在可行答案中优化软目标；只给拒答高分会诱发“什么都拒绝”。

### 信号怎样选

| 信号 | 适合什么 | 主要风险 |
|---|---|---|
| 成对偏好 RM | 难写成规则的总体质量 | 长度、风格、标注者与分布偏差 |
| 规则/程序验证器 | 代码测试、格式、明确答案 | 测试覆盖或规则漏洞 |
| ORM | 完整结果是否好 | 信号稀疏,难定位哪一步出错 |
| PRM | 推理步骤是否可靠 | 需要可信步骤标注或验证,成本高 |

绝对分数常受标注者尺度影响,同一 prompt 下的相对选择更容易统一。成对 RM 常用 Bradley–Terry 模型

$$
P(y_w\succ y_l\mid x)=\sigma\big(r_\phi(x,y_w)-r_\phi(x,y_l)\big).
$$

它只把相对偏好学成标量代理,不会因此自动防止 Reward Hacking。任务没有明确成功标准时,可先写评分细则、收集成对偏好与分歧,把能机验的子目标拆给规则,其余交给人审或经过校准的评委。

### 为什么会被钻空子

Reward Hacking 的根因是**代理奖励与真实目标不完全一致,而策略专门寻找能涨代理分的输出**。典型现象包括无意义拉长、固定模板、谄媚、过度拒答,以及代码绕过薄弱测试。判断时看训练奖励是否继续上涨而独立人评、事实正确率、安全召回或真实任务成功率下降,并固定解码设置检查长度和格式分桶；仅凭 reward 上涨不能证明能力提升。

缓解要形成闭环：

1. 改进数据与评委：复核分歧,平衡长度/格式,用当前策略的新回答刷新数据；可用多 RM、置信度或保守聚合暴露不确定性。
2. 缩小可投机空间：reference KL、较小更新、早停、规则门控和独立安全约束配合使用。KL 只能限制漂移,不能判断事实或保证安全。
3. 加强监督与验收：可验证任务用单元测试,有可靠步骤监督时比较 PRM；持续红队、人审、分维度留出集和线上 A/B,不要让训练 RM 同时当唯一裁判。

多个 RM 不必在部署推理时常驻。训练时可离线批量打分、共享主干做多头、蒸馏评委或先用便宜规则筛选；这些方法都要重新验证偏差。PPO 阶段通常先冻结 RM,当策略分布漂移、评测失真或新漏洞出现时再收集新数据并刷新 RM,更新频率没有固定比例。KL 系数也应按同一统计口径下的实际偏移双向调节,不能照搬常数。

PPO 的 clip 系数控制本批新旧概率比越界后何时停止继续获益,与 reference KL 的累计行为约束不是同一个旋钮。clip 太窄可能让有效更新很快饱和,太宽则允许更大单批变化；应结合 clip fraction、近似 KL、任务收益和生成质量联合搜索,同样没有通用固定值。
