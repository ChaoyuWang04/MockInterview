## 题目

用固定 Workflow 编排的 Agent 有哪些固有局限?满足什么条件才值得转向 Agentic RL 去训练策略,又要付出哪些代价?

## 要点

- Workflow 把决策写死在编排里,改进只能靠人改图和改提示词
- 逐步局部最优不等于整体最优,且没有跨步的信用分配
- 失败轨迹在 Workflow 里只是日志,在 RL 里是训练信号
- 转向的前置条件是可自动验证的奖励加可复现的环境,缺一不可
- 代价集中在 rollout 基础设施、奖励设计和可回滚性上

## 答案

**Workflow 的本质是把"下一步做什么"固化成人写的控制流;Agentic RL 把这一步变成可学习的策略,用任务最终结果反过来调整它。** 两者的分界不在能力强弱,而在决策由谁决定。

Workflow 的局限来自这个固化本身:

1. **分支靠枚举**。没预料到的情况走不到正确分支,只能持续追加规则,长尾永远补不完。
2. **没有跨步信用分配**。每个节点各自调好提示词,不代表整条链路最优;哪一步拖累了结果,编排层看不出来。
3. **失败不产生改进**。失败轨迹只是日志,要靠人读、人归因、人改。
4. **上限被基座和提示词锁死**。同一个模型换编排的收益会很快见顶。

值得转 RL 的条件要同时满足,少一条都会失败:

- **结果可自动验证**。有程序化判据(单测、schema、检索命中、环境终态)才谈得上奖励;只能靠人评的任务先别上 RL。
- **环境可复现、可并发**。初始状态能重置、外部副作用可沙箱化,否则 rollout 既不可比也不安全。
- **失败模式足够多样**,多到规则覆盖不划算——这是收益来源。
- **已有可用的 Workflow 版本**。它正好用来产出冷启动数据和基线,见 [冷启动数据质量](031-冷启动数据质量.md)。

代价也要说清楚:rollout 系统要提供沙箱、超时、权限与环境版本隔离;奖励一旦有缝就会被钻,见 [过程奖励与 Hack 诊断](032-过程奖励hack.md);训练稳定性、可解释性和线上回滚都比改一份编排难得多。

现实里两者常是**分层**而非二选一:高风险、强合规的环节保留确定性编排和人工确认,把 RL 用在真正需要探索的决策点上。
