## 题目

PPO 与 GRPO 在大模型强化学习中为什么会出现训练不稳、样本效率低和奖励偏差？请说明 DAPO、Dr. GRPO、GSPO 等已核实改进各自解决的问题，并给出 PPO、GRPO、DPO 及 GRPO 变体的选择方法。

## 要点

- 分开分析 PPO 的 critic 问题与 GRPO 的组采样问题
- 只使用有一手来源的 DAPO、Dr. GRPO、GSPO 名称
- DeepSeek-R1 的可核实做法不与后来的变体混写
- 方法选择取决于反馈形式、在线探索需要和实际故障
- reward hacking 要有可观测诊断与独立兜底

## 答案

**PPO 的主要风险来自在线数据、奖励噪声、critic/GAE 误差和多轮复用后的策略陈旧；GRPO 去掉 critic，却新增了组采样成本与组内统计偏差。** GRPO 中全对、全错的组没有学习信号，离群奖励会改变整组尺度，终局奖励让长回答的信用分配困难；两者都可能迎合奖励漏洞，也都不能靠裁剪自动消除 reward hacking。

| 改进 | 针对问题 | 核心做法与边界 |
|---|---|---|
| DAPO | 零梯度组、探索受限、长度与超长回答 | 动态补采有效组、提高正向裁剪上界、token 级损失与超长奖励塑形；它是一组配套设计，不是任意 GRPO 都默认具备 |
| Dr. GRPO | 难题权重和回答长度引入的偏差 | 分析组奖励标准差归一化与按回答长度归一化的偏置，并在其目标中去除这些缩放；需同步检查梯度尺度 |
| GSPO | token 级概率比在长序列和分布式训练中的高方差 | 用序列级重要性比率和裁剪约束整条回答；它改变了更新粒度，不等于免费提升所有任务 |

不存在只凭名字选择的“稳定版”或“自适应版”。先看监控：零方差组多时改 prompt 难度或用动态采样；长度持续漂移时检查长度归一化和奖励；token 级概率比尖峰、长序列不稳时评估 GSPO；奖励本身不可靠时，先修奖励和评测，换策略目标不能补上错误监督。

DeepSeek-R1 报告采用 GRPO 家族以免训练同规模 critic，R1-Zero 主要使用可验证的准确性与格式奖励。能说清的稳定来源是组内基线、裁剪更新和规则奖励；不能把后来的 DAPO 技巧、动态温度或课程学习反向归因给 R1。GRPO 相比 PPO 更适合结果可验证、同题可多采样且 critic 成本高的任务；若需要细粒度价值估计、组内经常同分或生成极贵，PPO 仍可能更合适。

PPO 与 DPO 的选择先看数据：有高质量固定偏好对、无需在线探索时，DPO 省去 rollout、RM 与 critic 的在线耦合；能在线获得可靠奖励、需要超越现有偏好对覆盖时，PPO/GRPO 可以直接探索，但成本和不稳定性更高。PPO 仍被广泛使用，是因为它能直接优化不可微的序列级、多目标奖励，并持续从当前策略的新回答中学习，工程监控和分布式实现也较成熟。DPO 也会受偏好噪声、数据覆盖和 reference 选择影响，不是“小数据必胜”。

奖励过优化的典型证据是训练奖励继续上升，而人评、独立验证器或真实任务指标掉头，同时长度、格式、拒答率或单一措辞异常变化。诊断时画代理奖励与独立指标随 KL/训练步的曲线，按长度、任务和难度切片，做对抗提示与奖励消融。缓解手段包括 reference KL、减小更新与早停、多个独立评委、刷新当前策略上的偏好数据、修补规则漏洞、保留人工抽检与回滚点。只监控同一个奖励模型无法证明问题已解决。
