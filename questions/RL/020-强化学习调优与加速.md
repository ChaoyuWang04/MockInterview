## 题目

强化学习训练应怎样调学习率、探索强度和 batch，并在不改变算法语义的前提下提高吞吐、降低显存？请结合 RLHF 的 PPO 阶段说明 actor/critic 学习率、梯度累积、熵正则和分布式 rollout 的取舍。

## 要点

- 先查正确性与奖励，再调算法稳定性和系统吞吐
- actor/critic 学习率没有固定倍数关系
- 探索方法随算法与动作空间变化，不能混用
- 微批和梯度累积可保留有效 batch，但不降低总计算量
- PPO rollout 只能有限复用，不能直接套长期 replay

## 答案

**调优顺序应是正确性、算法稳定性、显存，再到硬件利用率。** 先用小规模样例核对奖励、终止、mask、优势、旧策略概率和 loss 归一化；这些错了，提高吞吐只会更快地训坏。随后建立固定评测与监控，逐项改变学习率、batch、裁剪、KL 和探索强度，最后用性能分析定位生成、打分、训练还是通信瓶颈。

学习率常配 warmup 和衰减，但区间取决于模型、优化器、有效 batch 与奖励尺度。RLHF 中 actor 优化策略目标，critic 回归回报，二者损失尺度、初始化、更新次数和是否共享骨干都不同，所以“critic 必须比 actor 小一个数量级”不是通用规则。分别观察策略 KL/entropy、value loss、解释方差和梯度范数做扫描；critic 欠拟合时提高其容量、更新次数或学习率，策略漂移过快则先降低 actor 更新强度。

探索策略也不能混写：离散价值算法可用 $\epsilon$-greedy，连续控制常加动作噪声，随机策略用熵奖励，语言模型更多通过采样温度、top-p 与熵/KL 约束调节候选多样性。熵系数太大时策略长期随机、奖励难提升；太小时过早塌缩、rollout 同质。可根据目标熵、候选多样性和 reward/KL 曲线分段衰减或自适应调整，而不是固定单调日程。

batch 大通常让梯度更稳、矩阵计算更饱满，却增加驻留数据和单轮延迟；batch 小更新更频繁、噪声更大。显存受限时，先减每卡 micro-batch 并用梯度累积保留 optimizer 的有效 batch，再考虑混合精度、激活重计算、参数/优化器分片、卸载、序列打包与按 token 动态组批。累积不能减少总前反向计算，微批过小还会降低吞吐；rollout 侧则重点控制生成并发、最大 token 和 KV cache。

并行策略要匹配瓶颈：环境或推理并行解决采集慢，数据并行适合能放下副本时扩吞吐，大模型再用张量/流水线/参数分片。生成与训练解耦能覆盖空泡，但异步过强会产生策略陈旧，必须记录生成数据的策略版本并限制滞后。PPO 只在少量 epoch 内复用当前 rollout；经验回放和优先回放主要属于可校正的 off-policy 算法，不能直接当 PPO 加速插件。

每次优化都看端到端 samples/tokens per second、各阶段利用率和通信占比，同时守住 reward、独立任务指标、KL、熵、clip fraction 与 value 误差。只有吞吐提高且这些训练口径一致，才算有效加速；不存在脱离硬件和序列长度的固定加速倍数。
