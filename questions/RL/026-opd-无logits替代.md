## 题目

On-Policy Distillation 依赖教师在学生轨迹上给出逐 token 分布。如果教师是只返回文本、至多返回少量 top-k logprob 的商业 API,还能不能做标准 OPD?有哪些替代方案,各自损失了什么?

## 要点

- 标准 OPD 的监督信号是教师在学生前缀上的**完整词表分布**,API 给不了
- top-k logprob 只能做截断 KL,偏差随 k 变小、分布变平而增大
- 只有文本时退化为学生采样 + 教师改写的序列级蒸馏,丢掉逐 token 密集信号
- 教师与学生 tokenizer 不同则根本无法逐 token 对齐,这是硬约束
- 替代方案的收敛目标已不是最小化 KL,不要仍称其为 OPD

## 答案

**不能做标准 OPD。** 标准 OPD 每一步都要教师在学生已生成的前缀上给出**归一化的全词表分布**,再对学生分布算逐 token KL;商业 API 返回的是采样文本,或最多每步几个 top-k logprob,缺的正是这份分布。

按教师能返回的信息量,替代方案是一个阶梯:

| 教师能给 | 可行做法 | 丢了什么 |
|---|---|---|
| top-k logprob | 在 top-k 上算截断 KL,余下质量归入"其他"桶 | 长尾信息;k 小或分布平坦时偏差显著 |
| 仅文本 | 学生先采样,教师在学生前缀上改写/纠错,再做 SFT | 逐 token 密集信号,退化为序列级 |
| 仅偏好或打分 | 组成偏好对做 DPO,或当 RLAIF 的奖励 | 监督退化成序列级标量 |
| 标准答案 | 转 RLVR,用可验证奖励 | 不再依赖教师分布,但只适用可验证任务 |

这些方案都保住了 OPD 最本质的那一半——**样本来自学生自己的分布**,因此仍能缓解 exposure bias;丢掉的是另一半:教师逐 token 的密集反馈。所以它们是"on-policy 的蒸馏",但目标函数已不是 KL 最小化,答题时不宜继续叫标准 OPD。

有两个前提必须先确认,否则上面全不成立:

1. **tokenizer 是否一致。** 教师与学生分词不同时,token 边界对不上,逐 token KL 无从定义;只能退到序列级方案,或先做 token 对齐映射(有损)。
2. **返回的 logprob 是哪个分布的。** 若 API 在采样温度、top-p 截断之后才给 logprob,它已不是教师的原始分布;拿它当蒸馏目标会把解码超参一起学进去,需要还原到温度 1 的未截断分布或明确接受这层偏差。
