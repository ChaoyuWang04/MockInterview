## 题目

交易系统里 Python 与 C++ 怎样互相调用?几种方式的边界在哪?数据怎样传递才不会成为瓶颈?

## 要点

- 先分清需求:Python 调 C++、C++ 回调 Python、还是跨进程
- GIL 是核心约束:C++ 长耗时段要显式释放,回调 Python 要重新获取
- 数据靠缓冲协议做零拷贝,逐元素转换是常见的性能灾难
- 传指针必须约定内存布局、连续性和对象生命周期
- 延迟极敏感的链路通常拆进程,不做同进程绑定

## 答案

**先分清是哪种需求**,选型完全不同:

| 需求 | 常用方案 | 适用条件 |
|---|---|---|
| Python 调 C++ | pybind11 / nanobind | 已有 C++ 库要暴露给 Python,类型映射最省事 |
| 加速已有 Python | Cython | 热点是 Python 循环,想渐进改造而非重写 |
| 只有 C 接口 | ctypes / cffi | 只有动态库和头文件,不想编译扩展 |
| 极低延迟 | 进程分离 + 共享内存 | 主链路用 C++,Python 只做研究与监控 |

**GIL 是绕不开的约束。** C++ 侧执行耗时计算时必须显式释放 GIL,否则其他 Python 线程全被阻塞;反过来,C++ 线程要回调 Python 时必须先获取 GIL。行情回调这种"C++ 线程主动调 Python"的场景最容易踩坑——GIL 的获取本身既是延迟来源,也是抖动来源。

**数据传递要走缓冲协议,不能逐元素转换。** NumPy 数组通过 buffer protocol 可以让 C++ 直接拿到底层指针,做到零拷贝;把一个大数组逐元素转成 `std::vector` 是最常见的性能灾难。传指针时必须确认三件事:内存布局(行主序还是列主序)、是否连续、以及**生命周期**——C++ 侧持有指针期间,Python 侧对象不能被回收。

架构上的经验:延迟极敏感的链路(行情解析、下单)通常**不做同进程绑定**,而是由独立的 C++ 进程负责,Python 通过共享内存或消息队列取数据。这样 GC 停顿和 GIL 完全不进入热路径,代价是多一层序列化和进程边界。

边界:互操作层是 bug 高发区——异常跨语言边界的传播、引用计数、多线程下的对象生命周期都容易出错。要有明确的所有权约定和专门的边界测试,不能只测两侧各自的逻辑。
