## 题目

从原始 Transformer 出发，现代大模型在注意力、位置编码、FFN、归一化、MoE 与状态空间模型方向有哪些代表性演进？请按组件说明各自解决的问题，并解释选型时为什么要区分公开架构事实、算法结构与系统实现优化。

## 要点

- 架构演进围绕质量、训练稳定性、长上下文、缓存、计算和通信权衡
- MQA/GQA/MLA 改 KV 表示，SwiGLU 改 FFN，RMSNorm/Pre-LN 改训练动力学
- MoE 扩大总容量，稀疏/线性注意力与 SSM 处理长序列成本
- FlashAttention 是精确实现优化；闭源模型未公开细节不能补猜

## 答案

**现代大模型没有抛弃 Transformer，而是在各组件上分别压缩缓存、改善训练、扩大容量并降低长序列成本。** 可以按问题而不是按模型名字来梳理：

| 组件 | 代表方向 | 主要目标与边界 |
|---|---|---|
| 注意力表示 | MHA → MQA/GQA；MLA | 共享或压缩 K/V，降低解码缓存与带宽；质量和实现需验证 |
| 位置 | 绝对/正弦 → RoPE、ALiBi | 更直接表达相对距离；能算更长位置不等于质量自然外推 |
| FFN | ReLU/GELU → SwiGLU | 用门控乘性交互增强逐 token 变换，需重新核算中间宽度 |
| 归一化 | Post-LN → 常见 Pre-LN；LN → RMSNorm | 改善深层梯度与简化尺度归一，但没有跨模型绝对优劣 |
| 容量 | Dense → 稀疏 MoE | 总专家容量与每 token 专家计算部分解耦，代价是路由和通信 |
| 长序列 | 稀疏/线性注意力、SSM、混合架构 | 减少全局两两交互成本，同时承担检索或近似能力的取舍 |

原始 Transformer 给出多头注意力、FFN、残差与 Post-LN 的骨架。公开的 LLaMA 报告采用 Pre-Norm、RMSNorm、SwiGLU 和 RoPE；DeepSeek-V2 公开了 MLA 与 DeepSeekMoE；Mamba 是选择性状态空间模型，并非线性注意力。RWKV 可用线性注意力和递归两种视角描述，也不应与 Mamba 合成同一种结构。

还要分清模型结构与内核：FlashAttention 保持标准 softmax attention 的结果，通过分块和在线归一化减少内存读写，理论配对计算仍为二次；它可以和 MHA/GQA 等结构组合。训练算法也不等于模型骨架，PPO、GRPO 等后训练方法不会取代注意力、FFN 这些前向结构。

实际选型先固定任务：长文档需要看精确检索与缓存，在线服务看延迟、吞吐和硬件支持，训练看稳定性与通信。SSM、稀疏注意力和 MoE 可以组成混合架构，但组合会叠加内核、路由和评测复杂度，并非方向越多越好。Encoder-only、Decoder-only 的任务分工见 [语言模型架构选型](002-语言模型架构选型.md)，RoPE 与 ALiBi 的外推边界见 [位置编码方法](013-位置编码方法.md)。Tokenizer、训练数据构成、昇腾等芯片适配和应用许可是独立选型轴，不能从一张架构表推出来。开源报告只能说明对应版本；GPT-4 等闭源模型未披露的层数、专家数、注意力形式、数据比例和训练成本都不应推测成确定事实，也不能用不同币种、硬件和统计口径直接比较成本。

## 知识点

按“组件—瓶颈—代价”理解架构演进，比记模型清单可靠。结构、训练算法、内核和服务系统属于不同层次，公开版本事实也不能外推到整个模型家族。
