# 真实面经双写流程

触发:**用户发来真实面经**(面试里真被问出口的题)。深维平台的练习题截图不走这里,走 [02-题库导入流程.md](02-题库导入流程.md)。

分不清就看这一条:**面经 = 有人在真实面试里被问过**。这是 🔴 重点考点 标记的唯一依据,也是这份手册存在的理由。

## 为什么要写两处

题库和知识库是同一批知识的两个视角,面经进来时**两边都要写**,漏一边就断了:

| | 题库 `questions/` | 知识库 `knowledge/` |
|---|---|---|
| 形态 | 一道题一个文件,零散 | 一个知识点一篇,按 topic 汇总 |
| 面经落成什么 | **真题原文 + 参考答案** | **考点表里的一行**(问法 → 本文哪一节) |
| 什么时候用 | 刷题时逐题过 | 复习时成体系地过,顺带验收文章写透没有 |

**先做知识库那一腿**:定位到哪篇文章,才知道题库那边 `topic` 第一段该写什么(两者靠文章名匹配)。

## 第 0 步:识别哪些是真实面经

面经帖里混着复习心得、个人总结、"我觉得还会问 X" 这类猜测,**只提取面试官真的问出口的问题**。

- 一句话里塞了好几个追问的,拆成**主问 + 追问**(对应题库的 `## 追问` 分区、知识库考点表的复合问法)
- 顺手记下**公司**与轮次(有就记,没有就算了)
- 截图糊了、读不出内容 → 如实说读不出,**不猜**(铁律 4)

**识别完先存档**:把这批原话**逐字追加**到 [references/面经原题.md](references/面经原题.md),再动手改任何文件。原话的口气就是信息——错别字、不规范写法一律照录,订正留到入题库时再做。截图本身不进仓库,这份存档就是唯一原件。

## 第 1 步:知识库侧

**定位文章**:按考点找到对应文章名,`find knowledge -name "<文章名>.md"`(只认文章名,不认所在章节)。然后按文章状态分三种走法:

| 文章状态 | 动作 |
|---|---|
| 已成文 | 更新考点表 → 加 🔴 |
| ⚠️ 旧版 | 一样更新考点表 → 加 🔴(两种标记可共存),**同时**把该篇在 `01-TASK.md` 提到最前 |
| 🚧 占位 / 没这篇 | **不当场写整篇**。把该篇提到 `01-TASK.md` 最前,任务行后面附上面经原问法;🔴 等文章真写出来再加(占位稿挂 🔴 只会让页面同时显示灰框和重角标,误导) |

### 更新考点表:替换或合并,不是并列

**这是这条流程最容易做错的一步。** 看到表里已有近义问法就再加一行,结果一篇文章三行问同一件事——不要这样。

1. 先扫一遍现有表,判断新题和哪一行**问的是同一件事**
2. **同一件事** → 用面经原问法**替换掉**那一行。真题问法优先于自拟问法
3. **面经问得更深、或多了一个追问** → 合并成「一主一追」的复合句,不新起一行
4. **确实是全新考点** → 新增一行,并回填「本文哪一节」。**填不出小节 = 文章没覆盖这个点**,要回正文补内容,不能只加表格行
5. 面经问法**照抄原话的口气**,别改写成书面语(四条否决线见 [05-知识库写作契约.md](05-知识库写作契约.md) 第九节)

表下那行来源注脚跟着改:

| 表的构成 | 注脚 |
|---|---|
| 全是面经原题 | 不加注脚 |
| 混了面经与自拟 | `> 本表混有面经原题与自拟题;自拟题按写作契约第九节的出题标准补出。` |
| 全是自拟(本流程之外) | `> 本表按出题标准自拟,非面经原题。` |

最后在 H1 下面加 `> 🔴 重点考点:本篇直接对应真实面经高频问法,文末「面试考点串联」给出问法对照。`(已有就别重复加)

## 第 2 步:题库侧

机制沿用 [02-题库导入流程.md](02-题库导入流程.md)(`npm run topics` 看树 → 跳过/合并/新建三选一 → 六分区 → 汇总表),差异只有这几条:

- **标记真题**:`tags` 必须加 `面经`;`company` 填公司,不知道就留空,但 `面经` 标签照加
- **撞车时真题优先**:和已有的平台练习题同考点时,**不要直接跳过**——用面经的原问法改写题干,原问法放进 `## 追问`。真题问法比练习题问法值钱
- **面经通常没有标准答案** → AI 撰写,`tags` 加 `待校对`(02 的既有约定)
- **`topic` 第一段必须对齐第 1 步定位到的知识库文章名**,别另造近义词
- **不要碰 `mastered` / `highfreq`**,那两个字段是页面点击写回的

分类文件夹沿用 02 的映射表(量化、KVCache 这类落 `AI Infra`);文件夹不存在就按那张表的名字新建,不要另造名字。

## 第 3 步:验证与汇报

```bash
npm test          # 全库可解析 + topic/summary 合规 + 文章名唯一
npm run kb:lint   # 写作契约检查
```

汇总表分两段贴出来:

```
【知识库】
文章          | 动作                  | 说明
量化          | 替换 2 行 + 新增 1 行   | 已有 🔴
KVCache量化   | 新增 1 行              | 补加 🔴
显存管理与OOM  | 未动(占位)            | 已提到 01-TASK 最前

【题库】
# | 分类/topic            | 判定      | 说明
1 | AI Infra/量化/粒度     | 新建 001  | 面经·字节
2 | AI Infra/KVCache量化   | 并入 002  | 同考点,题干换成面经原问法
```

一个 commit 覆盖两边:`feat(面经): 知识库 N 篇考点更新 + 题库 +新建X 合并Y`。

## 常见坑

- **纯增量**:考点表加行不删行,一篇里三行问同一件事(见第 1 步的替换规则)
- **只写一边**:更新了知识库忘了题库,或反过来。这条流程的全部意义就是两边同步
- **一批面经命中多篇占位稿**:`01-TASK.md` 的优先级按**面经出现频次**排,不是按顺手
- **改文章名会断题目 `topic` 的匹配**(铁律 6),重命名前全库 grep
