# 真实面经双写流程

触发:**用户发来真实面经**(面试里真被问出口的题)。深维平台的练习题截图不走这里,走 [02-题库导入流程.md](02-题库导入流程.md)。

分不清就看这一条:**面经 = 有人在真实面试里被问过**。这是 🔴 重点考点 标记的唯一依据,也是这份手册存在的理由。

## 为什么要写两处

题库和知识库是同一批知识的两个视角,面经进来时**两边都要写**,漏一边就断了:

| | 题库 `questions/` | 知识库 `knowledge/` |
|---|---|---|
| 形态 | 一道题一个文件,零散 | 一个知识点一篇,按 topic 汇总 |
| 面经落成什么 | **真题原文 + 参考答案** | **考点表里的一行**(问法 → 本文哪一节) |
| 什么时候用 | 刷题时逐题过 | 复习时成体系地过,顺带验收文章写透没有 |

**先做知识库那一腿**:定位到哪篇文章,才知道题库那边 `topic` 第一段该写什么(两者靠文章名匹配)。

两边的承接关系长期保存在 [面经考点映射](references/面经考点映射.md):**原题位置 → 题库文件 → 主负责文章 → 覆盖状态与正文小节**。`01-TASK.md` 只保留待办与映射引用,完成后删任务,不删原件和映射。整个流程由负责人执行,页面的 topic 链接不会自动补写文章。

## 第 0 步:识别哪些是真实面经

面经帖里混着复习心得、个人总结、"我觉得还会问 X" 这类猜测,**只提取面试官真的问出口的问题**。

- 一句话里塞了好几个追问的,拆成**主问 + 追问**(对应题库的 `## 追问` 分区、知识库考点表的复合问法)
- 顺手记下**公司**与轮次(有就记,没有就算了)
- 截图糊了、读不出内容 → 如实说读不出,**不猜**(铁律 4)

**识别完先存档**:把这批原话**逐字追加**到 [references/面经原题.md](references/面经原题.md),再动手改任何文件。原话的口气就是信息——错别字、不规范写法一律照录,订正留到入题库时再做。截图本身不进仓库,这份存档就是唯一原件。

每批分配不重复的批次编号 `B001`、`B002`……,每条原题用「批次 + 组号 + 题号」定位,例如 `B001-G01-Q09`。沿用原截图的组序、题序;无编号的原文可加整理编号,须说明是整理元数据。每题前放固定锚点(如 `<a id="b001-g01-q09"></a>`),收到日期、公司与轮次有依据才填。**已有编号与锚点不能因后来插题而重排**,追加补录另用新批次,疑似转录错误另附注记。

## 第 1 步:知识库侧

**定位文章并登记映射**:按考点查文章全名(可用 `rg --files knowledge` 查文件清单),不按面经批次的章节名限制归属。先读原题的主问与全部追问,每个独立考点登记一行;同篇的「一主一追」可以共用一行。复合题跨篇时拆行,各有主负责文章。相同考点来自多条原题时保留各自来源行,可以关联同一道题库题和同一个正文小节。

映射列为:原题位置、考点摘录、题库文件、主负责文章、覆盖状态、正文小节。未入题库的先标「待入库」,归属暂不明确的标「待定」并列任务,不能漏行。**不能只把整批面经挂在一个章节下面就算登记完**。定位后按文章状态处理:

| 文章状态 | 动作 |
|---|---|
| 已成文 | 更新正文与考点表 → 加 🔴 → 逐题核对并回填映射的小节和「已覆盖」;仍缺内容标「待补」并留任务 |
| ⚠️ 旧版 | 一样更新正文与考点表 → 加 🔴(两种标记可共存),同时把重写任务提前并引用映射原题编号;未核对的行保留「待核对」,不能因有正文就标已覆盖 |
| 🚧 占位 / 没这篇 | **不当场写整篇**。映射登记「待写」与计划文章全名;把撰写任务提前并引用映射原题编号,后续写作者从映射回到原问法。🔴 等文章真写出来再加 |

任务按原件出现频次排序(一条原题拆成多行只计一次,不按题库拆题数放大频次)。调整分组队列时,把命中的文章从原分组移出,更新剩余篇数,避免重复任务。入库收尾前为每个「待写/待补/待核对/待定」事项留下可追踪的任务;允许一个任务按文章或批次汇总多行。

### 更新考点表:替换或合并,不是并列

**这是这条流程最容易做错的一步。** 看到表里已有近义问法就再加一行,结果一篇文章三行问同一件事——不要这样。

1. 先扫一遍现有表,判断新题和哪一行**问的是同一件事**
2. **同一件事** → 用面经原问法**替换掉**那一行。真题问法优先于自拟问法
3. **面经问得更深、或多了一个追问** → 合并成「一主一追」的复合句,不新起一行
4. **确实是全新考点** → 新增一行,并回填「本文哪一节」。**填不出小节 = 文章没覆盖这个点**,要回正文补内容,不能只加表格行
5. 面经问法**保留原话的口气**,别改写成书面语;自拟补题才用 [05-知识库写作契约.md](05-知识库写作契约.md) 第九节的四条否决线筛选。真实面经即使问公式、数字或项目细节也不能因此删掉,原件始终原样保留

表下那行来源注脚跟着改:

| 表的构成 | 注脚 |
|---|---|
| 全是面经原题 | 不加注脚 |
| 混了面经与自拟 | `> 本表混有面经原题与自拟题;自拟题按写作契约第九节的出题标准补出。` |
| 全是自拟(本流程之外) | `> 本表按出题标准自拟,非面经原题。` |

最后在 H1 下面加 `> 🔴 重点考点:本篇直接对应真实面经高频问法,文末「面试考点串联」给出问法对照。`(已有就别重复加)

## 第 2 步:题库侧

机制沿用 [02-题库导入流程.md](02-题库导入流程.md)(`npm run topics` 看树 → 跳过/合并/新建三选一 → 六分区 → 汇总表),差异只有这几条:

- **标记真题**:`tags` 必须加 `面经`;`company` 填公司,不知道就留空,但 `面经` 标签照加
- **撞车时真题优先**:和已有的平台练习题同考点时,**不要直接跳过**——用面经原问法更新题干,有价值的旧问法或新追问并入 `## 追问`。同一道题已收录时可复用文件,但新来源仍登记映射
- **面经通常没有标准答案** → AI 撰写,`tags` 加 `待校对`(02 的既有约定)
- **`topic` 第一段必须对齐第 1 步定位到的知识库文章名**,别另造近义词
- **回填映射中的题库文件**:用仓库内的真实路径。同一复合原题涉及多个独立文章时按考点拆题,使每道新题的 `topic` 与主负责文章一致。历史合题暂未拆开的,在映射标「待核对」并记录归属疑点,不能用不存在的文件凑齐
- **标签不能代替原件**:`面经` 标记整道题,其中 AI 补的追问、答案、计算题设定不自动成为真题。映射的考点摘录必须能回到原件确认;找不到来源的只登记待核对,不编原题编号
- **不要碰 `mastered` / `highfreq`**,那两个字段是页面点击写回的

分类文件夹沿用 02 的映射表(量化、KVCache 这类落 `AI Infra`);文件夹不存在就按那张表的名字新建,不要另造名字。

## 第 3 步:验证与汇报

先人工完成三向核对:

1. **原件 → 映射**:每条真题的主问和独立追问都有去向。暂时无法归类或回答的也要登记待处理,不能因为已有一行就漏掉剩余追问。
2. **题库 → 映射**:本批新增/合并/复用的题都能回到真实来源,`topic` 与主负责文章一致。检查的是原件支持的问法,不要求 AI 补充追问冒充面经。
3. **映射 → 正文或任务**:「已覆盖」的正文小节确实存在、内容和考点表答得上原题;其余状态有对应任务和缺口说明。原题链接、题库路径、文章名称逐项核对。文章尚未成文不妨碍本批入库完成,但未处理事项必须明确保留。

三向核对后更新 [来源与批次地图](references/来源与批次地图.md):登记本批实际原图位置、P/B 批次关系、批次说明、长期映射和当前状态。真实面经没有老师平台材料时可以只有 B 批次;同时有老师页面时必须同时保留 B 原题与 P 参考材料。

新批次若改变了既有的来源说明,同步更新相关任务和章节地图,不再保留「该章没有面经」这样的过期结论。批次标题也不是文章归属的限制。

```bash
npm test          # 全库可解析 + topic/summary 合规 + 文章名唯一
npm run kb:lint   # 写作契约检查
```

两个命令只检查格式与现有程序行为,**不会验证真题来源与逐题覆盖**。脚本提示须打开原文判断。汇总表必须给出每个考点的去向(批量时可以链接本批映射表,并单独列出全部待处理项):

```
原题编号 | 考点 | 题库文件与新建/合并/复用判定 | 主负责文章 | 已覆盖的小节 / 待写任务与缺口
```

一个 commit 包含本批原件、映射、题库、知识库及任务更新:`feat(面经): 知识库 N 篇考点更新 + 题库 +新建X 合并Y`。后续撰写或重写文章时,必须再执行写作契约第九节的**写前检索、写后验收**,不能只看入库时的旧状态。

## 常见坑

- **纯增量**:考点表加行不删行,一篇里三行问同一件事(见第 1 步的替换规则)
- **只写一边**:更新了知识库忘了题库,或反过来。这条流程的全部意义就是两边同步
- **一批面经命中多篇占位稿**:`01-TASK.md` 的优先级按**面经出现频次**排,不是按顺手
- **只留在任务队列**:任务完成会删除,真题来源和文章对应关系必须留在映射表
- **只核对表格不读正文**:已覆盖要求正文能回答原题的主问与追问,不是有标题、有链接或有 🔴 就算
- **改文章名会断题目 `topic` 的匹配**(铁律 6),重命名前全库 grep
