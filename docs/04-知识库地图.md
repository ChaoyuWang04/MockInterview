## 结构约定(2026-08 重构)

- **顺序**:文件夹用 `NN-` 数字前缀控制顺序,页面显示时剥掉前缀;目录内 `00-总览.md` 自然排第一
- **层级**:支持任意层嵌套(如 `05-多模态/03-视频生成/视频VAE.md`)
- **与题库的联动**:题目 frontmatter `topic` 第一段 → **按文章名全库匹配**(不再要求同名分类文件夹),因为分章已不与题库分类一一对应
- **文章名全局唯一**(各章的 `00-总览` 除外,它们是 hub 页不参与匹配),有测试守护
- **只有写完的文章才建文件**:知识库里每一篇都是成文稿,没有「占位」「旧稿」之分。还没动笔的文章登记在下面的计划表里,不提前建空文件

新增文章:按文章名反查题库 topic → 回读真题、追问和已有答案,核实事实并列出本篇必答考点 → 写正文与考点表 → 逐题验收覆盖情况 → `npm test` 与 `npm run kb:lint`。
**写作契约(语言/公式/图表/mermaid 规模/代码/真实性/怎么出考点题)见 [05-知识库写作契约.md](05-知识库写作契约.md)**,标杆样板是 `04-Infra/01-原理/GPU架构与执行模型.md`;架构类参考 [references/frontier-llm-architecture-handbook-2026.md](references/frontier-llm-architecture-handbook-2026.md)。

## 章节地图

### 01-模型结构

总览 · 注意力基础 · Transformer整体架构 · KV共享注意力(MHA/MQA/GQA)· MLA · 稀疏注意力 · 线性注意力 · SWA · Hybrid注意力 · 注意力配件 · RoPE · MoE基础 · MoE路由 · Norm位置 · FFN与激活 · 残差流 · MTP · Tokenizer · 新架构追踪 · **RNN与门控循环网络** · **卷积与池化** · **序列模型**

> **`MagiAttention` 已于 2026-09 迁至 `04-Infra/01-原理`**(与 `并行策略` 为邻)。它不改注意力的数学——一个 mask 不删、一个维度不压,结果与全注意力逐位一致,省的是跨卡通信与负载不均;归类上属于上下文并行基建,不是注意力变体。

> 新出现的注意力变体各开一篇;还不够成篇的先记进「新架构追踪」。

**`新架构追踪` 是本章的串讲篇**,分工照 04-Infra 的 `推理加速` 写死:**只讲演进主线与手段之间的关系**——谁接替谁、谁只是并行分支不构成替代、谁根本不是新机制(如 FlashAttention 是实现优化),单项机制一律一句话引到专篇;末尾接「当季新出、尚未单独成篇」的追踪表,成熟一条就升格为独立文章。**不许写成技术综述**,那会把本章十几篇专篇各抄一段。

**`注意力基础` 与 `注意力配件` 的分工写死**:`注意力基础` 负责标准注意力本身——QKV 投影与公式、$\sqrt{d_k}$、点积与加法打分、多头拆分与头数、掩码(causal/padding/双向)、复杂度账本、注意力头分析与剪枝;`注意力配件` 只负责不改变注意力复杂度的周边件——QK-Norm、门控、attention sink、跨层 KV 共享、逐层注意力预算。手撕注意力类真题的 topic 一律挂 `注意力基础`。

**本章末三篇的分工写死**:`Transformer整体架构` 串起完整数据流与组件边界(一次前向、层内零件、三种架构、可学习参数、训推两条路、整机算力账);`RNN与门控循环网络` 讲递归与门控机制;`卷积与池化` 讲 CNN 基础算子、参数共享与下采样;`序列模型` 是**横向对比篇**,只把三者摆在一起比依赖路径、训练并行、推理状态与归纳偏置,**任何一边的机制都不重讲**,一律引到上面三篇。Mamba / RWKV 的谱系归 `线性注意力`,本章各篇只给一句定位。

### 02-预训练与微调

总览 · 预训练流程 · ScalingLaws · 数据工程 · 优化器 · SFT · LoRA · 蒸馏 · 长上下文训练 · 泛化与正则化 · 损失函数 · 分类损失 · 回归损失 · **Softmax优化**(计划)· 对比学习 · 特征工程 · 推荐模型 · 参数初始化 · 拒绝采样 · 提示微调 · 域泛化 · **多任务学习** · **集成学习**

`蒸馏` 负责响应/特征/关系蒸馏、任务适配,并澄清教师生成数据与数据集浓缩的区别。

**损失函数三篇的分工写死**:`损失函数` 是总览篇,只讲按任务选目标、损失与评测指标的关系、各族一句话定位和数值稳定的通用原则,单族机制一律引到专篇;`分类损失` 负责交叉熵的梯度与概率解释、二分类为何不用 MSE、标签平滑的损失视角、Focal、类别不平衡与概率校准;`回归损失` 负责 MSE/MAE/Huber 的形状梯度与噪声假设、按目标选型,以及从 MSE 出发的逐层反传。手写实现一律留给题库的手撕代码题。标签平滑另有一条:正则视角归 `泛化与正则化`,损失视角归 `分类损失`,两边不重写。

`提示微调` 负责 Prompt/Prefix/P-Tuning 的注入位置、可训练参数量、RoPE 下前缀给不给位置、以及 KV 缓存怎么处理;PEFT 的横向选型与多任务存储账归 `LoRA` 篇,两边不重写。`拒绝采样` 负责把三件同名的事分开——经典拒绝采样(严格无偏)、按分数筛答案的 best-of-N(不无偏)、重要性采样(不丢样本但权重方差爆炸);投机解码算法仍归 `投机解码` 篇。

`多任务学习` 负责损失配比、梯度冲突与多任务专家结构;多个损失怎么加权的总览级结论仍归 `损失函数` 篇第五节,MMoE/PLE 那种按任务共享专家与 LLM 按 token 稀疏激活的 MoE 不是一回事,后者归 `MoE基础` 与 `MoE路由`。`集成学习` 负责 Bagging、Boosting、Stacking 及树模型机制;通用特征处理与目标编码泄漏另由 `特征工程` 负责。

计划文章 **`Softmax优化`** 负责**大词表下输出层的近似与加速**:分层 Softmax、自适应 Softmax、采样 Softmax 与 NCE 各修了什么、训练时能用而推理时不能用的那几种、以及词表并行。**与邻篇的分工写死**——词表大小的参数账与 logits 显存账归 01 章 `Tokenizer`,交叉熵本身的性质与融合算子归 `分类损失`,InfoNCE 与负采样机制归 `对比学习`,词表并行的通信账归 04-Infra 的 `并行策略`;本篇只讲这些近似方案各自省掉了什么、代价是什么。

计划文章 `NLP基础` 负责分词、命名实体识别、句法分析、机器翻译和问答等基础任务。计划文章 `模型可解释性` 负责树模型的不纯度减少(MDI)、Gain/Cover/Frequency、排列重要性与 SHAP 各自的含义、偏差、计算成本和解释边界;`集成学习` 只讲树本身怎么长,不讲怎么解释它。

**Redis 被三篇按角度切开,分工写死**:**数据结构与底层编码**(逻辑类型 vs 编码、listpack/skiplist/dict、MGET、Cluster slot 与 hash tag)归 `缓存系统`;**线程模型**(核心命令为什么串行、`mostly single threaded` 而非纯单线程、I/O 线程与后台任务、慢命令阻塞)归 `并发控制`;**拿它做分布式锁**(`SET NX PX`、Lua/`DELEX` 原子释放、续租、Redlock 与 fencing token)归 `分布式系统`。三边不重写。另一条:`并发控制` 只讲单机多线程,`分布式系统` 只讲跨进程跨机器;GPU 侧的 stream/event 归 `CUDA流与异步执行`,训练侧的集合通信归 `集合通信`、`并行策略`。

**`归一化` 与 `Norm位置` 的分工写死**:BN 的原理与 $\gamma,\beta$、小 batch 失效与替代谱系(GN/SyncBN/FrozenBN/GhostBN)、IN 的定位、GN 组数、**CV 任务选型**归 `归一化`;五种 Norm 的计算轴对照、**为什么 Transformer 选 LN 不选 BN**、BN 的 padding 与 masked statistics、**RMSNorm 全套**、Pre/Post/Sandwich 位置归 `Norm位置`。两边都不重写。

**`推荐系统` 与 `推荐模型` 的分工写死**:双塔的结构约束、点积与余弦、四种负样本来源、批内负采样的 $\log p_j$ 修正、多兴趣与蒸馏等缓解、序列建模归 02 章的 `推荐模型`;`推荐系统` 只讲**系统与实验侧**——召回排序分层与算力预算、多路召回配额与分数校准、延迟预算调整次序、**排序侧负样本下采样导致的 CTR 概率偏移与还原**、在线 A/B 实验、离线与线上背离。**注意区分两种「负采样修正」**:`推荐模型` 讲的是召回里批内负采样的 $\log p_j$,`推荐系统` 讲的是排序里下采样后的先验还原,不是一回事。

### 05-多模态

**根目录(共用范式与跨子领域)**:总览 · VAE · Diffusion · FlowMatching · DiT · **多模态训练** · **多模态推理系统** · **多模态RAG**
**子领域**(每个含 00-总览):01-视觉理解(VLM结构 + 视觉编码器/任意分辨率/**图像预处理**/**视觉分割与SAM**)· 02-图像生成(SD架构/条件控制/图像编辑/图像Tokenizer)· 03-视频生成(视频扩散架构/时空注意力/视频VAE/长视频一致性)· 04-音频(语音识别/TTS/音频编解码/音乐生成)· 05-3D生成(NeRF/3DGS/多视角扩散/网格生成)· 06-世界模型(世界模型范式/视频世界模型/动作条件与交互)

**`多模态训练` 与 `VLM结构` 的分工写死**:「为什么必须分阶段」「连接器为何是唯一随机初始化的模块」「全解冻为什么训崩」这些**结构侧**论证归 `VLM结构`;`多模态训练` 只讲**训练侧**——图文数据治理、四种对齐目标各解决什么与何时叠加、代表模型的阶段为何互不相同、怎么用归因实验决定动哪一层、视觉 token 膨胀与样本长度方差带来的训练瓶颈、分层评测。CLIP 的对比机制与 ViT 本身归 `视觉编码器`,InfoNCE 与负样本工程归 02 章的 `对比学习`,两边都不重写。

**`多模态推理系统` 的边界**:只讲弱 VLM 与强文本模型级联这一条链路——分工、结构化中间表示、动态路由、定向复查、缓存与分层评测。工具 schema 与校验闸归 `工具调用`,多 Agent 连线归 `多智能体`,连续批处理与 P95/P99 指标定义归 04-Infra 对应篇,本篇只讲它们在这条链路上怎么用。

**`图像预处理` 与邻篇的分工**:本篇只管**颜色与噪声**——灰度转换与色彩标准、四类噪声模型、五种经典降噪及保边代价、下游任务验证。分辨率、缩放与切图策略归 `任意分辨率与高分辨率`,像素变 token 之后归 `视觉编码器`。

**`视觉分割与SAM` 的边界**:分割任务谱系(语义/实例/全景与可提示分割的任务定义之别)、SAM 三段结构与不对称设计、稀疏与稠密提示、歧义多掩码与 IoU 头、数据引擎三阶段、类别无关的能力边界,以及视频(SAM 2 流式记忆)与 3D 扩展的定位。ViT/MAE/CLIP 的骨干机制归 `视觉编码器`,分辨率与切图归 `任意分辨率与高分辨率`。**注意重名**:02 章 `泛化与正则化` 里的 SAM 是 Sharpness-Aware Minimization,与本篇无关,两边各自标清楚。

**`多模态RAG` 与 `多模态推理系统` 的分工写死**:`多模态RAG` 讲**材料怎么进库、怎么被检索出来**——文档解析与版面分析、图文块与 caption 绑定、三条检索路线(转文字/统一图文嵌入/页面截图)、模态鸿沟、引用定位与分模态评测;`多模态推理系统` 讲**一次请求里两个模型怎么协同推理**——级联分工、结构化中间表示、动态路由、定向复查、验证器。通用检索链路归 `检索优化`,通用切块与索引归 `切块与索引`,通用检索指标归 `Embedding`,三边都不重写。

**`04-音频` 四篇的分工写死**(本子领域的结构是**一个地基 + 三个任务**,不是四个并列话题):**音频表征谱系(波形 / STFT / 梅尔谱 / 离散 token)只在 `音频编解码` 讲一次**,它是地基;其余三篇只说一句「谱系见该篇」,不展开。

- **声码器(mel → 波形,如 HiFi-GAN)归 `TTS`;神经编解码器(波形 → 离散 token → 波形,如 EnCodec)归 `音频编解码`**——两者都产波形但输入不同,不切开必然重写
- **多层 RVQ token 摊平进一维序列(拉平 / 并行 / 延迟 / 分层预测)归 `音频编解码` 第四节,不归 `音乐生成`**——尽管这套排布是 MusicGen 提出的,`音乐生成` 只能一句话引过去
- `语音识别` 独占 CTC / 注意力 seq2seq / RNN-T 三范式与 Whisper 弱监督路线;`TTS` 独占一对多难题、时长与韵律、音色克隆;`音乐生成` 独占符号与波形两条路线、长时结构、乐理约束、FAD 与主观评测、版权
- 码本坍塌的成因与缓解归 `VAE`,离散化路线之争归 `图像Tokenizer`,扩散/流匹配机制归 `Diffusion`/`FlowMatching`,条件注入机制归 `条件控制`,音频侧一律只讲自己这边的代价

> **本子领域题库零真题**,四篇考点表全部是补充题。若之后采到音频真题,入库后须回对应专篇重做考点表,真题优先、补充题让位。

**`05-3D生成` 的分工写死**:**3D 表示谱系(体素/点云/网格/隐式场)与体渲染方程只在 `NeRF` 讲一次**,它是本子领域的地基篇,邻篇一律一句话引过去。

- **`NeRF ↔ 3DGS` 的横向对比判给 `3DGS`**,因为 3DGS 整篇是针对 NeRF 定义的;`NeRF` 只在「局限」留一句「渲染速度后来被 3DGS 拿回去了,见 3DGS 篇」,不展开对比
- `NeRF` 独占隐式辐射场、位置编码与谱偏差、分层采样、Instant-NGP/Mip-NeRF 等加速谱系;`3DGS` 独占高斯参数化(含协方差为何拆成缩放+旋转)、可微光栅化五步、自适应密度控制、浮空物与存储代价
- `多视角扩散` 独占**数据稀缺这条立论**、SDS、Janus 问题、视角条件化与跨视角注意力、优化式 vs 前馈式;底层 3D 表示只点名不讲机制
- **`多视角扩散` 与 `长视频一致性` 管的是两件事**:前者是**同一时刻不同机位**的空间一致性(约束硬,由相机参数唯一确定),后者是**同一东西不同时刻**的时间一致性(约束软,没有客观答案);两边只做一句对照,不互相展开
- 提网格、拓扑与 UV、材质归 `网格生成`;扩散机制归 `Diffusion`;条件注入机制归 `条件控制`

> **本子领域题库零真题**,四篇考点表全部是补充题。规矩同 `04-音频`:采到真题后回专篇重做考点表。

**`06-世界模型` 的分工写死**:**「什么是世界模型、表征+动力学+奖励三块、隐空间 rollout、想象中训练、与 model-based RL 的关系」这套概念框架只在 `世界模型范式` 讲一次**,它是本子领域的地基篇。

- **动作空间的表示、条件注入到哪一层、离散 vs 连续、交互延迟与误差累积,整条判给 `动作条件与交互`**;`世界模型范式` 与 `视频世界模型` 都只说一句「动作作为条件进入」,一律不展开(两篇原本都写着「动作注入」,已切开)
- `视频世界模型` 独占**把视频生成模型当可交互环境**这件事:因果性与实时性两条硬约束、Genie 的潜在动作(无标注学可控性)与 GameNGen 的实时模拟、**可回访一致性**、帧率预算与 NFE
- **`视频世界模型` 与 `长视频一致性` 管的是两件事**:后者是单向长视频的**缓慢漂移**(观众看不到正确答案),前者是可交互环境里的**可回访一致性**(玩家可随时转身对质,是离散的对错判定)。只做一句对照
- 经典 RL 谱系(MDP、DQN、actor-critic、探索)归 `强化学习基础`;扩散机制归 `Diffusion`;视频骨干归 `视频扩散架构`

> **本子领域题库零真题**,考点表全部是补充题。规矩同 `04-音频`、`05-3D生成`。

**`VAE` 与 `图像Tokenizer` 的分工写死**:向量量化、straight-through 梯度、承诺损失与**码本坍塌的成因、诊断与缓解**归 `VAE`(VQ-VAE 是 VAE 家族成员,机制与连续 VAE 同源);`图像Tokenizer` 只讲面向图像生成的 tokenizer 谱系与选型——离散与连续之争、VQGAN/FSQ/LFQ 等路线差异、码本设计如何配合下游生成模型,机制一句话引过去,两边不重写。

### 06-应用

**根目录(两个子领域共用)**:总览 · **Prompt优化** · **思维链** · **幻觉与事实性**
**子领域**:**01-RAG**:总览/检索优化/Embedding/切块与索引/RAG评测/**RAG系统设计**/**GraphRAG** · **02-Agent**:总览/规划模式/工具调用/记忆与上下文/多智能体/**Agent框架**/**Agent架构**/**Agent选型与治理**

**`思维链` 的边界**:只讲推理轨迹本身——两种用法(提示给示例 vs 做成 SFT 样本)的分野、训练信号与 token 归一化、三条必须否定的误解(计算空间不等于改层数、模仿步骤不等于每步正确、答案对不等于链对且链不一定忠实)、泛化边界、小模型失效原因、自动造数据流程、无显式 CoT 时的 RL 信用分配。**CoT/ToT/GoT/Self-Consistency 的选型与成本归 `规划模式`**,本篇只给信息流形状对照。

**`幻觉与事实性` 的边界**:幻觉的定义与两类分野(事实性 vs 忠实性)、五层成因、检测方法(原子声明、一致性采样为何不是事实证明、自我核查)、分层缓解各解决什么、RAG 自身引入的新风险、高风险场景的声明级证据门槛。**指标定义与 judge 校准归 `RAG评测`,Fallback 阶梯与垂直领域治理归 `RAG系统设计`**,本篇只说该量哪几件事、为什么不能合并成一个分。

**RAG 七篇的分工写死**:`切块与索引` 管离线建库(解析清洗、切块策略、元数据、代码检索、增量更新与一致性);`Embedding` 管表示本身与文档库场景的 ANN 索引结构;`检索优化` 管查询侧(BM25、混合检索与融合、查询改写、重排、候选整理);`RAG系统设计` 是**整机篇**——模块契约、生成侧 prompt 与引用、Fallback 主负责、垂直领域治理、成本配置;`RAG评测` 是**方法论篇**——分层指标、错误归因与对照实验,其余各篇的指标定义一律引到它;`GraphRAG` 只讲图索引这一条路线的机制与成本边界;`00-总览` 纯目录导航。**候选集怎么整理成上下文归 `检索优化`,证据到了生成侧怎么组织归 `RAG系统设计`,两边不重写。**
