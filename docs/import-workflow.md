# 截图批量导入协作流程

目标:快速把老师平台的题搬进本地题库,**不建重复题**,每批秒级验证。

## 分工

**你(用户)**:攒截图 → 一条消息发一批(建议 ≤15 张)。不用做任何说明;截图默认带答案,没答案的题 AI 会自行识别并处理。

**AI**:按下面流程处理整批,结束给出汇总表。

## AI 的每批流程

1. `npm run topics` —— 打印主题树(分类 → topic 段 → summary + 文件名),这是唯一需要预读的索引,不读题目正文
2. 逐张读图,在树上定位考点;只对命中的 1-3 个候选文件读原文
3. 三种判定:

| 判定 | 条件 | 动作 |
|---|---|---|
| **跳过** | 考点和问法都与已有题相同 | 不建题;出题公司不同时在已有题 `company` 追加(如 `字节、美团`) |
| **合并** | 同考点、不同问法/角度 | 并入已有题:题干融合、答案补角度、新问法进「追问」;**超过长度红线就拆新叶子而不是硬塞** |
| **新建** | 树上无此考点 | 按 `_template.md` 新建,定好 topic 叶子 |

4. 截图无答案的题:AI 直接撰写参考答案,tags 加 `待校对`(页面可见,复核后删)
5. 验证 = `npm test`(全库可解析 + topic/summary 合规,秒级)。**不开浏览器、不跑 build**;仅当用到从未用过的语法(如新类型 mermaid 图)才抽查渲染
6. 一批一个 commit:`feat(题库): 批次N +新建X 合并Y 跳过Z`
7. 汇总表(事后可查、git 可回滚):

```
# | 分类/topic        | 判定           | 说明
1 | RL/GRPO/KL散度    | 新建 003       | 树上无此考点
2 | RL/PPO/clip机制   | 并入 002       | 同考点换问法,进追问
3 | SFT/解码策略/综述  | 跳过           | 与 001 重复,company 追加美团
4 | RL/GRPO/优势估计   | 新建 004(待校对) | 截图无答案,AI 撰写
```

## 判定尺度(备忘)

- 「同考点」看 topic 叶子会不会重名,不看措辞;先信 summary,拿不准才读原文
- 合并以**已有题为主体**,新截图内容做增量;答案始终保持 ≤ 约 500 字
- 所有判定 AI 直接执行,不逐条确认;你事后扫汇总表,不同意的指出来,git 历史随时可回滚
