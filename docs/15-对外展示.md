# 对外展示

定位:`site/` 是 Orrery 的**输出**环节——维护者的个人主页,也是对外展示面。它独立构建、独立部署,和根目录的阅读站互不影响。主页的风格与内容结构正在重构(见 01-TASK),本手册只管它现在怎么维护。

## 一、它是什么

| 项 | 现状 |
|---|---|
| 技术栈 | Next.js 16(App Router)+ pnpm + next-intl 中英双语;博客由 Hugo 单独构建后挂在 `/blog` |
| 线上地址 | <https://chaoyuwang.vercel.app>,Vercel 部署 |
| 个人信息与卡片 | `site/src/i18n/messages/{en,zh}/` 下的 `personal.json`、`collections.json`,**中英成对改** |
| 站点配置 | `site/src/data/site.ts` |
| 博客 | Hugo 源在 `site/hugo-blog/`,构建脚本 `site/scripts/build-hugo.mjs` |
| 静态资源 | `site/public/`;引用路径大小写必须与文件一致,`check:assets` 会查 |

## 二、与根目录隔离

- `site/` 有自己的 `package.json` 与 `pnpm-lock.yaml`,**不和根目录共用依赖**;在根目录用 `npm run site:dev`、`npm run site:build` 转发,或直接 `pnpm --dir site <命令>`
- 根目录的 `tsconfig`、ESLint、Vitest 都排除 `site/`,`npm test` 不管它
- 模板来源:基于 zhengzangw 的 `nextjs-portfolio-blog-research`,`site/THIRD_PARTY_NOTICES.md` 保留原作者声明

## 三、改动与发布

1. **内容改动**(自我介绍、项目卡片、论文与 PR 的描述):这是以维护者身份对外说话,措辞交维护者过目再推送
2. **代码与样式修复**:照常施工,按下面验证后提交
3. 推送到 `main` 即触发 Vercel 部署;Vercel 项目的 Root Directory 是 `site`,Ignored Build Step 是 `git diff --quiet HEAD^ HEAD -- .`——只有 `site/` 变了才构建,每日内容提交不会连带重建主页

**不进公开仓库的**:简历原件、未公开的个人材料。仓库是公开的,`site/` 下的一切都等于已经发布。

## 四、验证

```bash
pnpm --dir site install
pnpm --dir site lint
pnpm --dir site check:assets
pnpm --dir site build
```

再用 `pnpm --dir site dev` 在浏览器里看首页中英两版与手机宽度;动了博客就看 `/blog`。部署后打开线上地址确认。

## 五、项目包装

给一个新项目起名、写 README 与主页卡片,暂按 `site/docs/new-project-playbook.md` 的起名方法(从别的学科借一个词做隐喻);其中的文件命名约定、仓库改名格式与 banner 风格已过时,在 `paradigms/_待评估.md` 里等随主页重构一并更新。
