# 日常维护

## 日常习惯

- **内容即数据**:`questions/` `knowledge/` `opensource/` `leetcode/` 里的一切(含笔记、掌握状态、高频标记)都是纯文本,勤 `git commit`,历史就是你的学习记录
- 备份 = 推到私有远端仓库,或直接拷贝整个项目文件夹;换电脑 `git clone` + `npm install` 即恢复
- `projects/` 下的源码仓**不被 git 追踪**(体积大且各有自己的 .git),换电脑要重新 clone

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面显示红色错误卡片 | 卡片上写着文件名和原因(frontmatter 语法错 / 缺「题目」「答案」分区),照着改文件 |
| 新分类/新题不显示 | 文件(夹)名以 `_` 或 `.` 开头会被忽略;确认是 `.md` 结尾,然后刷新 |
| 答案里的小标题变成了分区 | 正文用了顶层 `## `,改成 `###` 及以下 |
| 改了内容页面没变 | 内容改动本来就免重启;若确实没变,`leet-restart`。改了**代码**必须 `leet-rebuild` |
| 端口 3000 被占 | `leet-status` 看是不是自己的服务;确认是别的进程用 `lsof -ti:3000 -sTCP:LISTEN` 定位。换端口:`LEETPREP_PORT=3002 leet-start` |
| 构建报找不到已删除的路由 | 路由类型缓存残留:`rm -rf .next .next-prod` 后重建 |
| Mermaid 图显示失败 | 页面会显示原始代码和错误信息,按提示修语法 |
| 知识库文章打不开 | 文章名必须全局唯一;确认路径各段都存在(白名单校验会挡住任何不匹配) |

服务启停、端口分工、为什么脱离终端 → [07-常驻服务](07-常驻服务.md)。

## 测试

```bash
npm test        # 秒级,五个文件全跑
```

| 测试文件 | 守护什么 |
|---|---|
| `tests/questions.test.ts` | 解析/定点写回逻辑(mastered、highfreq、Note),含路径穿越校验 |
| `tests/samples.test.ts` | 真实题库回归:任何解析失败或 topic/summary 不合规的题会带文件名报错 |
| `tests/knowledge.test.ts` | 知识库树:文章非空、**文章名全局唯一**、章节顺序、嵌套路径、状态标记 |
| `tests/opensource.test.ts` | 解读页非空 + `NN-` 序号前缀 |
| `tests/leetcode.test.ts` | 清单结构(17 组 100 题)、补充题合并、高频标记合法性、排序规则 |

## 依赖升级

```bash
npm outdated                      # 查看可升级项
npm update                        # 小版本升级
npm test && leet-rebuild          # 升级后验证并重建常驻服务
```

大版本升级(next 16、react 20 等)建议单独开分支验证。
