# 模拟面试系统

第六个模块,与题库/知识库/开源解读/LeetCode 平级。内容在 `interview/`,页面 `/interview`。

**一句话**:拿你自己的简历 + 真题 + 知识库,由大模型扮演面试官口头出题、追问、按要点判分。

## 一、跑起来

三个进程,缺一个就降级但不崩:

| 进程 | 起法 | 没起会怎样 |
|---|---|---|
| Next.js | `npm run dev`(:3001)或 `leet-start`(:3000) | 页面打不开 |
| 语音服务 | `bash scripts/voice-start.sh`(:8700) | 页面正常,语音模式自动禁用,可以打字面试 |
| LLM | 云端 DeepSeek,无需本地进程 | 判卷报 502 |

配置全在 `interview­prep/.env.local`(被 `.gitignore` 排除,不进仓库):

```bash
INTERVIEW_LLM_BASE_URL=https://api.deepseek.com/v1
INTERVIEW_LLM_MODEL=deepseek-v4-flash
INTERVIEW_LLM_API_KEY=sk-...
INTERVIEW_VOICE_URL=http://127.0.0.1:8700
DASHSCOPE_HOST=https://ws-xxxx.cn-beijing.maas.aliyuncs.com   # 云端 STT 用
DASHSCOPE_API_KEY=sk-ws-...
```

> **百炼的工作空间级 key(`sk-ws-` 开头)必须配套 workspace 主机名**,用通用的 `dashscope.aliyuncs.com` 一律 401。主机名在百炼控制台的「API Host」那行。

## 二、四个模型,各管一段

| 环节 | 模型 | 在哪 | 换它改哪 |
|---|---|---|---|
| **判卷 / 追问** | `deepseek-v4-flash` | 云端 | `.env.local` 的 `INTERVIEW_LLM_*` |
| **朗读题目** | Qwen3-TTS VoiceDesign 1.7B(4.2G) | 本地 MLX | `voice-server.py` 的 `TTS_MODELS` |
| **转写回答** | Whisper large-v3-turbo(1.5G) | 本地 MLX | 同上 `STT_MODELS`,页面上可切 |
| **简历画像** | 同判卷模型 | 云端 | `INTERVIEW_LLM_PREP_*` 可单独指向别的 |

模型文件在 **`~/.mlx-models/`**(仓库外,git 不追踪,共约 7.3 G)。缺了用:

```bash
bash scripts/ms-fetch.sh mlx-community/<仓库名>
```

**走 ModelScope 不走 HuggingFace**:实测 HF 跨境 200 KB/s、ModelScope 17.6 MB/s,同样的仓库快 80 倍。

当前装了(合计 7.3 G):

| 模型 | 大小 | 用途 |
|---|---|---|
| `Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16` | 4.2G | TTS,**用文字描述音色** |
| `whisper-large-v3-turbo-asr-fp16` | 1.5G | 默认 STT |
| `Fun-ASR-Nano-2512` | 1.6G | 备选 STT,最快但术语差一档 |

> 预设音色那版(CustomVoice,9 个固定音色)已弃用删除 —— 那些音色带口音。

## 三、内容从哪来

```
interview/
  resumes/01-agent-rl.md   简历(可多份,开场选)
  resumes/02-infra.md
  profiles/*.json          画像,与简历同名,LLM 生成
```

出题的语料是**只读**的题库与知识库 —— 本系统对 `questions/` 和 `knowledge/` **一个字节都不写**。想标 mastered/highfreq 去刷题页点。

| | 提供什么 |
|---|---|
| `questions/**` | `## 题目`=主问 · `## 要点`=判分依据 · `## 答案`=判卷标准 · `## 追问`=**人工写好的追问池** |
| `knowledge/**` | 「面试考点串联」表:问法 → 本文哪一节 |

看当前池子有多大:

```bash
npm run interview:index
```

**知识库每写完一篇(删掉 `🚧 占位` + 补考点表),池子自动变大**,不用改代码。

## 四、抽题:两道硬闸挡幻觉

「简历里没有多模态,却被问多模态」这件事是**代码挡的,不是嘱咐模型别问**。

```
第一级 · 章节门禁(人工定,写在简历 frontmatter 的 `章节:`)
    候选 = 全部题目 ∩ {文章有正文} ∩ {章节在册}

第二级 · 加权采样(纯函数,零 LLM)
    w = 亲和度(0→剔除 1→1.0 2→2.0 3→3.0)
      × highfreq?2 × 面经?1.5 × mastered?0.2
      × 已问过?0.05 × 同篇刚问过?0.3
```

**`章节:` 由人写,不由 LLM 推断。** 你漏写一个章节最多少考几道题;LLM 多推一个章节就是问你完全没做过的东西。

**亲和度 0 = 永不出题,只能你手改 `profiles/*.json` 加进去**,画像脚本只会给 2 和 3。

改了简历重跑画像:

```bash
npm run interview:profile     # 简历 hash 没变会自动跳过
```

另外整体排除两类:`questions/手撕代码/`(口头面试念不了代码)、各章 `00-总览.md`(hub 页,剥掉 `NN-` 前缀后全叫「总览」会撞名)。

## 五、上下文:只追加,不修改

DeepSeek 的缓存命中价是未命中价的 **1/30**,前提是**消息一旦写下就永不改动**。所以整场对话是严格追加的:

```
[system]     面试官人格 + 评分标准 + 输出格式 + 面经口气   ← 整场不变
[user]       简历全文
[user]       第 N 题判分材料(要点/答案/追问池/考点表)      ← 追加后不再动
[assistant]  题干
[user]       我的回答
[assistant]  判卷 JSON
   ⋮
```

实测 4 题会话 8664 token,**未命中只占 16%**,一场 30 轮约 ¥0.06–0.12。

> ⚠️ **改 `context.ts` 时的红线**:任何让「已写下的消息内容发生变化」的改动,都会让缓存从那一条起全部失效,而且**不报错、不变慢,只是悄悄贵 30 倍**。`tests/interview.test.ts` 里有一条用例专门守它(逐条比对前后两次组装的消息数组),别删。

## 六、两档模式

共用同一个评分内核,差别只在反馈时机:

| | 面试档 | 过题档 |
|---|---|---|
| 反馈 | 全程不给答案 | 一题一结算:命中哪些要点 / 标准答案 / 去看哪篇 |
| 节奏 | 追问无上限,模型决定何时换题、何时收尾 | 一题一结算,答完就换 |

**参考答案在面试档里到不了浏览器** —— API 响应里一个字都不带,打开 devtools 也偷看不到。这是结构保证,不是提示词自觉。

### 一轮长什么样

```
题目自动念出来(主问读预渲染缓存,0 延迟)
   ↓ 按空格
录音
   ↓ 再按空格
自动转写 → 自动提交 → 判卷 → 下一问自动念出来
```

全程不用点第二下。空格键在文本框里打字时不拦截。

### 谁决定面试怎么走

**出题权在代码,追问权在模型。** 抽到哪道题由加权采样决定(纯函数、可复现);抽到之后:

| | 谁定 |
|---|---|
| 追问几轮 | 模型,**没有上限** |
| 什么时候换题 | 模型(`next: nextq`) |
| 整场什么时候结束 | 模型(`next: end`),你也可以随时点「结束并复盘」 |
| 能问什么 | 参考答案 / 考点表 / **他自己的简历**,三者之外不许问 |

模型每轮还会写一条 `note`(私下备注,候选人看不到),复盘时用得上。

### 会话记录与复盘

结束时把整场发去生成复盘,连同逐轮记录落盘到 `interview/sessions/YYYY-MM-DD-HHMM-<简历>.md`。

复盘走 `post` 阶段、**思考全开**(一场一次,你在读报告,慢一点无所谓),结构固定:
整体 → 答得好的 → 答错或没答到的(你说的 / 问题在哪 / 正确的是 / 去看哪篇)→ 下一步。
提示词里把语言要求写死了:「说人话,不要『候选人展现了较强的…』这种腔调」。

会话文件是 markdown、进 git —— 和题库知识库同构,可以 grep、可以 diff。

## 七、语音

页面开场的「语音」面板控制:音色描述 / 语速 / 音量 / 稳定度 / STT 后端。**语音模式默认开**。

当前默认(改这里:`components/interview/useVoice.ts` 的 `DEFAULT_VOICE_CONFIG`,
以及 `voice-server.py` 顶部的 `DEFAULT_*`,两处要一致):

| 项 | 值 |
|---|---|
| 音色描述 | 三十多岁的男性,标准普通话,播音腔,吐字清楚,语气平静克制不带感情,像在严肃地问问题 |
| 语速 / 音量 / 稳定度 | 1.2× / 120% / 0.1 |
| STT | `whisper-turbo` |

下面还有个 **STT 对照台**:用你自己的声音录一句,三个后端并排比。这是选型工具,不属于面试流程。

### 主问预渲染

```bash
npm run interview:tts      # 94 道题干 → interview/cache/tts/*.mp3
```

94 道合计 9 分钟音频、**4.3 MB**(mp3 64k),渲染约 6 分钟。命中缓存的主问播放延迟是 **0**;追问是新文本,必然现场生成(约 2 秒)。

**换音色/语速/读音映射之后要重跑** —— 缓存 key 包含全部影响音频的参数,旧的不会被误用,但新参数下是空的。缓存目录不进 git。

### 几条实测出来的约束

**热词必须精准,不能全域灌入。** 三个后端行为不同:

| | 溢出时 |
|---|---|
| Whisper turbo | 448 token 上下文,**从前面截断**——相关词放最后能救 |
| Fun-ASR Nano | 两种顺序都退化,救不了 |
| Qwen3-ASR(云端) | 灌 400 词无影响 |

三家都**不报错、不涨延迟,只是悄悄变差**。知识库里的英文 token 去重有 3633 个,全灌必然溢出。热词由 `expandHotwords()` 从当前题目自动提取,并展开大小写/分词变体(`DeepEP` → `DeepEP` / `deepep` / `Deep EP` —— 给多个落点才认得出)。

**长句会让 TTS 生成跑飞,所以要切句。** 实测 41 字的题干出了 14.7 秒音频、只念了头一秒就是大段静音;同样内容切成 17 字的短句完全正常。所以合成前按标点切段(上限 24 字),没有标点可切的长句硬切(优先在空格处断),逐段生成、掐掉各段尾部静音再拼接。

**切分只降低概率,消不掉。** 生成是随机采样,所以输出侧还有自检:静音占比 >40% 或时长远超文本应有长度就重来,最多 3 次。全库 94 个音频靠这两条做到 0 异常。

**读音修正只做「规范大小写」,不要插空格。** TTS 模型已经学会按大写字母切词、把连续大写逐字母读,所以 `DeepEP` 就够了;拆成 `Deep E P` 反而把句子打碎让生成更不稳(同一句从 5.6s 拖到 8.2s)。唯一需要真改写的是**数字当介词用**:`all2all` 会被念成「all 二 all」,必须换成 `all to all`。映射表在 `voice-server.py` 的 `PRONUNCIATION`,听着别扭就加一条,加完重跑预渲染。

**本地 STT 的内存与音频长度无关,但耗时会涨。** Whisper 按 30 秒窗口处理,60s/180s/300s 音频内存恒定 6.2 GB,耗时分别是 2.9s / 6.0s / 15.0s。没有时长上限,但五分钟的回答要等 15 秒 —— 那种长度用云端更划算(90 秒实测 2.3 秒,且不占本地内存)。

**语速不是模型参数。** Qwen3-TTS 的 `speed` 源码里写着 `not directly supported yet`,传了没用。真正的变速在输出侧用 ffmpeg 的 `atempo` 做(变速不变调)。

**音色描述每次生成会抖。** 温度默认 0.1(模型原默认 0.9 抖得厉害),页面上有「音色稳定度」滑杆。要完全锁死音色得用 Base 版做 3 秒音频克隆。

## 八、验证

```bash
npm test                      # 93 项,秒级,不联网 —— 日常改完跑这个
npm run interview:live        # 7 项,真打 DeepSeek,要联网
bash scripts/voice-audit.sh   # 9 项,逐个控件端到端,要两个服务都在跑
npm run interview:index       # 打印候选池规模 + 生成全域热词表
npm run interview:tts         # 预渲染主问(可重入,已存在的跳过)
npm run interview:profile     # 重跑简历画像(简历没变会跳过)
```

`voice-audit.sh` 存在的理由:语音链路有三跳(浏览器 → Next.js 代理 → voice-server),**中间任何一跳漏传参数都不报错**。已经踩过三次:代理漏传 `instruct`(音色描述改了不生效)、漏传 `normalize`(读音修正开关是死的)、漏传 `X-Spoken`(「实际念的是」永远空白)。改语音链路后跑一遍。

## 九、排障

| 现象 | 原因 |
|---|---|
| 页面显示「语音服务未启动」 | `bash scripts/voice-start.sh` |
| 云端 STT 超时,本地正常 | **进程继承了 HTTP_PROXY**。必须用 `voice-start.sh` 启动,它会显式清掉代理变量 |
| 判卷 502 | `.env.local` 的 key 或余额;`curl https://api.deepseek.com/user/balance -H "Authorization: Bearer $KEY"` |
| 整个语音服务失去响应 | 失控生成。已加 token 上限 + 自检重试;若复现看日志里的「生成异常,重试」 |
| 某道题念一半就静音 | 长句跑飞。已加切句 + 自检重试;若复现把那句加进 `PRONUNCIATION` 或缩短题干 |
| 主问也要现场合成(慢) | 缓存没命中。改过音色/语速/读音映射后要重跑 `npm run interview:tts` |
| 转写把术语听错 | 先确认热词是否精准(不是越多越好);再在对照台换个后端试 |
| 音色描述改了没变化 | 跑 `scripts/voice-audit.sh`,大概率又是某一跳漏传 |

`voice-server.py` 里两个重活端点**必须是 `def` 不能是 `async def`** —— 模型推理是同步阻塞的,写成 `async def` 会占着事件循环,一个慢请求让整个服务失去响应。
