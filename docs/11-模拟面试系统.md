# 模拟面试系统

模拟面试是六个功能模块之一。它只读题库与知识库,使用简历或指定文章组织问题,由模型追问和判卷,最后把会话与复盘写入 `interview/sessions/`。

本文件只解释产品行为和数据流。服务安装、密钥、模型、启动与排障见 [08-常驻服务.md](08-常驻服务.md);验证命令见 [09-日常维护.md](09-日常维护.md);未完成事项只写在 [01-TASK.md](01-TASK.md)。

## 一、入口与使用方式

| 入口 | 用途 |
|---|---|
| `/interview` | 选择简历和模式,开始通用模拟面试 |
| `/interview/kb/<文章名>` | 读完一篇知识库文章后只考这一篇 |
| `/interview/sessions` | 按日期查看通用面试和单篇自测复盘 |
| `/interview/sessions/<id>` | 查看单场复盘与逐轮记录 |

通用面试支持文字和语音。语音服务不可用时页面自动退化为文字模式,不会阻塞判卷。

## 二、数据与模型分工

```text
interview/
  resumes/*.md       简历,开场时选择
  profiles/*.json    简历画像,由脚本生成
  sessions/*.md      已完成会话和复盘
  cache/tts/          主问题干音频缓存,不进 git
```

题库与知识库在整个面试过程中只读:

| 数据 | 用途 |
|---|---|
| 题目 `## 题目` | 主问原文,保留真题口气 |
| 题目 `## 要点` | 逐项判分依据 |
| 题目 `## 答案` | 模型参考答案,面试档不下发浏览器 |
| 题目 `## 追问` | 优先使用的人工追问池 |
| 知识库考点表 | 补充题库尚未覆盖的可问点 |
| 简历与画像 | 章节门禁、项目深挖和章内亲和度 |

四类模型能力各自独立:云端模型负责判卷、追问与简历画像;本地 TTS 朗读题目;云端或本地 STT 转写回答。具体实现和切换位置由 08 维护。

## 三、通用候选池

候选池由代码构建,不让模型自由发明问题:

1. 读取正式题库,排除不适合口头回答的 `手撕代码`。
2. 用题目 `topic` 第一段匹配知识库文章名;匹配不到的题不进入通用面试。
3. 题库题已经覆盖某篇文章时,该文章的考点行只作判卷参考,不再重复出题。
4. 没有题库题覆盖的文章,只有在不是占位稿且存在考点表时,考点行才进入候选池。
5. 各章 `00-总览.md` 是导航页,不参与文章名匹配和出题。

实时查看题量、排除项、匹配缺口、文章状态和各章候选分布:

```bash
npm run interview:index
```

这些数字会随题库和知识库变化,不在长期手册中保存快照。

## 四、抽题门禁与权重

通用面试使用两级门禁:

```text
简历 frontmatter 的章节范围
  → 画像给出的章内 topic 亲和度
  → 先选章节
  → 再在章内选题
```

先选章节再选题,可以避免内容较多的章节仅凭候选数量压过其他章节。章内权重还会考虑高频、已掌握、已经问过和刚问过同篇文章等因素。

简历中的章节既可以等权,也可以给出比例:

```yaml
章节: [03-强化学习, 04-Infra]
章节: {03-强化学习: 4, 04-Infra: 2}
```

章节由人明确填写,不由模型推断。画像只在允许的章节内给 topic 亲和度;亲和度为 0 的方向永不出题。修改简历后运行 `npm run interview:profile` 重建画像。

## 五、上下文与判卷边界

整场上下文只追加、不改写已经发送的消息。每次换题时追加当前题目的判分材料,随后追加题干、回答和判卷结果。这既保证会话可复查,也保护模型前缀缓存。

必须保持以下边界:

- 出题和阶段切换由代码控制;模型只能在当前材料范围内判卷和追问。
- 面试档的参考答案不下发浏览器,前端也不能作为要点真源。
- 保存会话时由服务端按题目 id 重新查要点和答案,不能信任客户端回传的判分材料。
- 判卷成功前不把本轮写入上下文,失败重试不会重复插入同一问答。
- 模型 JSON 解析失败时允许一次纠正重试;纠正消息只属于该次请求,不能写回永久上下文。
- 阶段 id 与题库 id 使用不同前缀,统一通过 id 转换函数处理,不能直接截固定字符。

这些约束由 `tests/interview.test.ts` 守护。

## 六、通用面试的两档模式

| | 面试档 | 过题档 |
|---|---|---|
| 目标 | 练项目表达、决策与技术追问 | 快速练技术细节 |
| 流程 | 开场 → 项目深挖 → 技术延伸 → 广度补充 | 直接从候选池出题 |
| 反馈 | 全程不展示答案,结束后统一复盘 | 每题展示命中要点、答案和关联文章 |
| 节奏 | 阶段上限由代码控制,阶段内追问由模型决定 | 一题结算后换题 |

### 面试档四阶段

| 阶段 | 出题材料 | 判分依据 |
|---|---|---|
| 开场 | 固定自我介绍问题 | 不判分 |
| 项目深挖 | 简历原文与画像中的项目 | 背景、角色、关键决策、权衡、量化结果 |
| 技术延伸 | 当前项目关联 topic 下的候选题 | 题目要点或知识库原文 |
| 广度补充 | 两级加权候选池 | 对应题目的判分材料 |

项目顺序由会话种子打乱,模型再根据本场自我介绍选择要深挖的项目。代码负责限制重复项目、重复追问和阶段轮次;模型可以提前结束阶段,但不能突破上限。

技术延伸如果没有匹配材料就跳过,不能退回全池伪装成项目相关问题。用户选择跳过时也要把 `(跳过)` 追加进上下文,避免模型再次询问同类内容。

## 七、单篇过题

知识库文章页的“考一遍这篇”只在文章不是占位稿,且存在题库题或考点表时显示。

单篇池与通用候选池不同:

- 不读取简历章节和画像亲和度。
- 收集该文章关联的全部题库题。
- 同时收集该文章考点表的全部问法,即使文章已经有题库题。
- 题库题使用人工维护的 `## 要点` 判分。
- 考点行按“本文哪一节”定位原文,由模型从原文现抽 3–5 条要点后判分。
- 小节定位失败时回落整篇文章,不猜测不存在的答案。

因此不能直接筛选通用 `corpus.candidates`;单篇池由 `lib/interview/kbdrill.ts` 独立组装。

## 八、语音交互

开场页的语音设置默认收起,配置保存在浏览器 `localStorage`。可调整音色、语速、音量、稳定度和 STT 后端;保存的后端不可用时自动回落到第一个可用选项。

主问题干是固定真题原文,可以运行 `npm run interview:tts` 预渲染;追问由模型现场生成,只能实时合成。缓存键包含文本和全部语音参数,更换音色、语速或读音规则后必须重新预渲染。

本题术语会自动生成精准热词。全域热词只提供给云端 STT,不要向本地 Whisper 灌入过长词表。录音临时文件、模型安装、代理清理、长音频切分和语音排障统一见 08。

## 九、会话与复盘

结束时把逐轮记录和模型复盘写入:

```text
interview/sessions/YYYY-MM-DD-HHMM-<简历>.md
```

会话文件由程序整体生成,因此可以安全序列化自己的 frontmatter;题目文件仍必须遵守定点写回规则。frontmatter 保存主题、简历、模式、时间、轮次、命中和覆盖范围。单篇自测额外保存文章范围。

复盘正文包含整体表现、答得好的地方、问题与正确答案、关联文章和下一步。没有 frontmatter 的旧会话继续使用回落解析,无需迁移。
