# 材料解读流程

定位:把一份**冻结的公开材料**写成一篇能独立读懂、真正帮助记忆与迁移的中文长文。材料可以是 PDF、网页,也可以是视频的字幕转录——**载体不是判据**。

**和 06 的边界**:本模块的输入是**冻结的材料**,过期靠版本核验;[06-开源解读流程](06-开源解读流程.md) 的输入是**活的代码仓**,过期靠基准 commit 与 `os:check`。两边的事实锚、产出形态与正文纪律都不同,不要互相套用。**时间轴不同是设计如此,不是矛盾**:本模块讲那份材料**当年写了什么**,06 讲那个项目**现在是什么样**,同一个项目两边说法不一致完全正常(PagedAttention 论文里没有自动前缀缓存,今天的 vLLM 默认开启)。**不要为了对齐而改动任何一边**;需要跨代际对照时,由本模块在文中说明「论文之后发生了什么」并给官方证据。

两边共用的只有文风。会真造成返工的那几条(加粗紧贴标点、半角波浪号)由 [09-日常维护](09-日常维护.md) 的「踩过的雷」守着,`npm test` 会拦。

## 两个库:按重要程度分,不按载体或出品方分

| | 报告解读 `/reports` | 日常研读 `/readings` |
|---|---|---|
| 定位 | **必看**。要精读、要能复述、要能迁移到自己的项目 | **关注**。扫方向、筛未来可能的方向 |
| 默认归属 | [`readings/_机构名单.md`](../readings/_机构名单.md) 里的机构主导(企业、知名新兴实验室、知名高校与研究组);顶会顶刊正式录用 | 其余一切过了准入的材料 |
| 原件 | `papers/<公司>/` | `readings/_src/<方向>/` |
| 解读 | `reports/<公司>/` | `readings/<方向>/` |
| 目录键 | **公司**(方向只在索引里) | **方向**(机构只在索引里,做卡片条幅) |
| 索引 | `reports/index.md` | `readings/index.md` |
| `release-date` | 模型首次对外可用日 | 原件首次公开日 |
| 状态命令 | `npm run reports:status` | `npm run readings:status` |

除上表这几行之外,**两个库共用本手册的全部内容**——开始写之前、长文写作契约、六条硬约束、标杆、子 agent 协作、人工验收,一字不分岔。

**出品方只是重要程度的代理指标,不是规则。** 名单内机构的材料基本都是必看的,所以拿它当默认值;FlashAttention 出自斯坦福的实验室却是工业界的日常,正是这条的典型。但可以覆盖:名单外小 lab 的论文认为必看就进报告解读,大厂的边角材料只想关注就进日常研读。**边界靠名单收敛,不靠改规则**:判了名单外的机构值得必看,就在名单里加一行。

## 准入:三道闸门,不设内容闸门

| 闸门 | 要求 | 卡在这里的例子 |
|---|---|---|
| 一 · 有原件 | 总得有能读的东西 | `Wan 2.7`:没有报告也没有博客,架构溯源到 Wan 2.1 |
| 二 · 不重复 | 内容不能已经在库里 | `GLM-5.2`:model card 指回已收录的 GLM-5,新机制 IndexShare 已按 `IndexCache` 单收 |
| 三 · 可信度 | 下面三条至少满足一条 | — |

闸门三的三条:① 有官方开源实现仓库,第三方复现不算;② 主导机构是企业实验室、知名新兴 lab 或知名研究组,看第一作者所属与通讯机构;③ 顶会顶刊正式录用(CVPR / ICCV / ECCV / NeurIPS / ICML / ICLR / SIGGRAPH / ACL / EMNLP;数学、金融等非计算机学科按该学科公认的顶刊,如经济学的 QJE)。**一条都不满足就默认不收**,单独列出并写明差在哪一条,由维护者拍板。

**综述免闸门三。** 新领域的综述往往出自小机构——大厂还没来得及出,等它出了那个方向也就不新了。闸门一与闸门二对综述照旧。综述的写法另有一套,见第四节。

**桌面的年份前缀就是入库决定。** 维护者主动下载、要收的材料,会在桌面文件名前加年份(如 `2025-OneRec Technical Report.pdf`)。带前缀的**免闸门三,也不再问收不收**,核实只决定进哪个库、哪个方向;闸门二照旧,已在库的跳过。没有前缀的一律不收。库内文件名去掉这个前缀。alphaXiv 热榜来源不受这条影响,仍按本节末的热度线准入。

**不设内容闸门。** 综述、立场文、路线图、benchmark、规模定律、纯算法一律可收,全模态都收。学科上收**泛计算机**:数学、金融等也收(如日常研读的「金融市场与量化」)。重要与否由维护者判断,不由材料的形态判断。**「这份材料没公开做法」不是拒收理由,而是解读里要写清的结论**——`Hy3` 与 `Mistral Large 3` 的 model card 只给架构规格加部署配方,没有训练数据、算力、超参与消融,这本身就是读者要知道的事实。**已收录的原件不因后续规则变化而移除。**

## 三种原件形态,同一套契约

同一个流程、同一页、同一套写作契约,只有事实锚不同。不为此新增目录、标签、元数据或第二套规则。

| 形态 | 典型来源 | 事实锚 | 原件落盘 |
|---|---|---|---|
| **PDF** | 技术报告、论文 | `(PDF p. 12)` | `.pdf`,默认不追踪 |
| **网页** | 官方博客、recipe 页、实验记录、model card | 「原文 2.4 节」 | 无文件,只在索引里登记 URL |
| **转录文本** | 视频与发布会的字幕、播客转录 | **短引原话** | `.srt` / `.vtt` / `.md`,**追踪** |

- **网页与转录文本的页头「本文依据」必须写明 URL 与访问日期。** 网页会原地改动不留版本号,视频会被重传、剪辑或下架,URL 加日期是唯一的溯源线索
- **网页原件必须跟着链接读**:它把大量背景摊在链接里——评判框架可能定义在伴随博客中,benchmark 只给一个名字。做法见第三节第 8 条
- **转录文本解读的是字幕文件本身**,模态只有文字和图片:字幕全文,加上必要时从画面里取的图。**时间轴一律忽略**,不写进解读也不当事实锚;要追溯就短引原话,让读者能在字幕里搜到

## 一、目录与网页

```text
papers/<公司>/<报告>.pdf          # 报告解读的原件,默认不被 git 追踪
reports/<公司>/<报告>.md          # 报告解读的正文,必须被 git 追踪

readings/_src/<方向>/<材料>.pdf   # 日常研读的原件,默认不被 git 追踪
readings/<方向>/<材料>.md         # 日常研读的正文,必须被 git 追踪
```

**两库共用的命名规则:**

- 原件与解读在两边使用完全相同的目录名与文件名,如 `DeepSeek-V4.pdf` 与 `DeepSeek-V4.md`
- 文件名只保留稳定的模型、项目或材料名。正式名称自带的代际或版本号(如 `DeepSeek-V3.2`、`Hunyuan3D-2.0`)必须保留;不要再把日期、arXiv 修订号、完整论文副标题或冗余版本后缀塞进路径,这些信息写在解读正文里
- 原件默认不追踪的是 PDF,确需保存时 `git add -f` 单篇加入。**字幕与转录文本例外,一律追踪**——视频会下架,那份文本可能是唯一的存世记录
- **同一篇材料只能在一个库里。** 两边都登记会让读者不知道该读哪篇,测试守这条

**报告解读专属(目录键 = 公司):**

- 公司目录按**模型或项目的主要归属方**确定。高校与多家公司联合署名时,不额外创建“联合”“高校”或重复公司目录;合作关系在解读正文中说明。若归属确实无法判断,先核对论文首页、官方发布页和项目仓库,不要凭作者邮箱猜
- **同一系列优先放进同一个目录,此时可以打破公司归属**(如 FlashAttention 1/2/3/4 虽然后续代际换了署名机构,仍放在一起),便于对照阅读;归属变化写在解读正文里

**日常研读专属(目录键 = 方向):**

- 方向目录名与 `readings/index.md` 里的 `## ` 标题**逐字一致**,不做 slug 映射;测试守双向一致(有目录必有 `## `,反之亦然)
- 方向名两个库共用**同一套词表**,这样同一方向下的论文与基模报告可以对照读。但**建 `## ` 标题的时机不同**:`reports/index.md` 有条目才建(空标题会被 `npm test` 拦);`readings/index.md` 的 `## ` 同时是目录契约,可以先建后填。**新方向先在用得上的那一侧建,另一侧等第一条进来再建**
- 方向名里有顿号和空格(如 `图像、视频与 3D 生成`),脚本与文档里引用这类路径**一律加引号**
- 机构不建目录,只作为索引里的一列,在卡片上显示成条幅

**页面与元数据(两库共用):**

- **需要保留原件图表时**,图片下载到 `public/reports/<slug>/` 或 `public/readings/<slug>/`,正文用 `![图注](/reports/<slug>/文件名.png)` 这样的站内绝对路径引用,图注注明引自原文哪张图。实测该路径不与动态路由冲突(静态文件优先),且 Tailwind preflight 会把图约束在容器宽度内、窄屏不溢出。**加完图必须 `leet-restart`**,否则常驻服务上只有图裂开(原因见 [08-常驻服务](08-常驻服务.md))。**能改写成 markdown 表格或 Mermaid 的一律改写**:原件里以图片形式呈现的表格必须转成原生表格,否则数字无法搜索、窄屏也读不了
- **解读里点名为关键证据的原文 figure,写稿时就要出现在该处。** 能改成表或 Mermaid 的仍改写;否则拷贝原图,或按 [06-开源解读流程](06-开源解读流程.md)「轨道 B」画一张更直白、更好对比的讲解 SVG。文件落 `public/readings/<slug>/` 或 `public/reports/<slug>/`,alt 写一句完整的话,加完 `leet-restart`。不支撑叙事的图不配、不占位。通读点名再加仍可以。**图在前,字配合。** 图放在它所解释的那段文字前面;结构、对比和趋势以图为准,正文不要再复述柱高、分档或连线,只补图上读不出的判断、边界和「我们如何解释」。**训练数据的样本模式**(文档打包与跨样本掩码、FIM 这类原文给出的格式、两种 SFT 模板)按同一条出现在该处;示意须标明不是语料原文,报告没公开的样本不编造。
- Markdown 是网页数据源。一级标题 `# ...` 是索引页显示的标题;以下正文正常使用 `##`、`###`
- 每篇已发布文章必须把唯一的 `<!-- release-date: YYYY-MM-DD -->` 放在一级标题后的第一个非空行。日期必须是真实存在的公历日期;缺失、重复、格式错误或日期非法都必须让测试与构建带文件名失败。该注释是文章内唯一的元数据,不计入正文;它只用于在卡片上显示首发日,页面顺序由索引决定
- **两个库的 `release-date` 语义不同**,这是唯一一处写作层面的分岔:

  | 库 | 记的是 | 取值 |
  |---|---|---|
  | 报告解读 | **模型首次对外可用日** | 官方 Web、App、API 或权重中**最早**发生的事件。一篇覆盖模型家族的文章取该家族的首发日;覆盖后续具名 checkpoint 的取该 checkpoint 自己的。若对象从未对外可用、文章只讲公开技术,才改用该技术首次官方公开日 |
  | 日常研读 | **原件首次公开日** | arXiv v1 提交日 / 会议正式发布日 / 博客发表日 / 视频发布日,取**最早**。修订版(v2、v3)不回写 |

- 首发日是不变事件。后续 API 上线、权重开放、论文上传或修订、PDF 换版、本站改稿和 git 提交都不得回写该日期
- 取证两条口径(踩过的雷见 [09-日常维护](09-日常维护.md)):**Hugging Face 仓库的 `createdAt` 不是首发日**,权重仓库提前建好、发布当天才解禁,要用权重佐证就看文件提交时间;**官方发布日志与官方博客不一致时取日志**,即最早的官方公开事件,不取传播最广的那次官宣
- 两个库中以下划线或点开头的目录与文件都不会出现在网页,可用于未完成草稿;正式发布时再改成普通文件名
- 主页「📄 报告解读」进入 `/reports`,「🔖 日常研读」进入 `/readings`;每张卡片进入一篇完整长文,文章页右上角显示「方向 · 机构」

**一份材料只对应一篇解读。** 不要另建“算法篇”“训练篇”“infra 篇”,也不建立重复的元数据、代际表或关键词数据库。算法、架构、训练 recipe、infra 和关键词都在同一篇文章里形成一条完整叙事。

索引怎么排、状态怎么推导、告警看什么,全在第八节;先做哪一批只写在 `01-TASK.md`。

## 二、分流:从桌面到两个库

两个来源,后三步共用:**来源一**是维护者主动扫桌面,**来源二**是每日自动扫 alphaXiv 热榜(见本节末)。四步:扫描 → 核实 → 归档 → 排队。前后两步是机械的,中间两步靠判断。

### 1. 扫描

```bash
npm run papers:scan                 # 默认只扫 ~/Desktop 顶层
npm run papers:scan -- --dir <路径>  # 一次性处理某个目录
```

**年份前缀就是提名**(规则见上面「准入」)。载体不限:PDF、字幕、转录文本、markdown 带了前缀都收;说明书、账单、论坛存档和没打前缀的论文一律不收。

脚本**只采集,不判断**:

1. **按前缀分**:没有年份前缀的直接归 C,不读内容
2. **去重**:比对 `reports/index.md`、`readings/index.md`、`readings/_判定档案.md` 三张表,命中就跳过。**少了这一步,每轮扫描都会把同一批材料重新问一遍**
3. **提取**:arXiv 编号、正文里的仓库链接、页数;顺带标出综述与转录文本,它们的写法不同
4. **出报告**(临时文件,不入库),分三档:

| 档 | 含义 | 下一步 |
|---|---|---|
| A | 待入库(带年份前缀) | 核实后定去向并归档 |
| B | 已在库或已判定 | 跳过,不再问 |
| C | 无年份前缀,不收 | 原地不动 |

A 档不预判进哪个库,建议名已去掉年份前缀。

### 2. 核实

逐条联网核 arXiv、主导机构、开源仓库与录用情况,定下进哪个库(名单内机构默认报告解读,名单外默认日常研读)、哪个方向、哪个公司目录,写好「一句话」,由维护者在报告上确认。**这一步不自动化——归属与方向靠人判断。** 需要新方向时,先在对应索引建好 `## ` 标题和空表头,归档器不会擅自新建。

### 3. 归档

按勾选结果**移动**文件(不是复制),并同步登记:

| 去向 | 动作 |
|---|---|
| 报告解读 | 移进 `papers/<公司>/`,在 `reports/index.md` 对应方向登记一行 |
| 日常研读 | 移进 `readings/_src/<方向>/`,在 `readings/index.md` 对应方向登记一行 |
| 不收 | 移进废纸篓,在 `readings/_判定档案.md` 记一行**带理由** |
| 不是材料 | 原地不动 |

**归档器只做移动,绝不删除**——判错了能从废纸篓捞回来。`_判定档案.md` 不是黑名单,规则变了可以重新捞出来。

### 4. 排队

索引里已登记、正文还不存在的行就是待解读队列。**不另建任务清单**,两份清单必然失同步;`01-TASK.md` 只写「这一批做哪几篇」。

### 来源二:alphaXiv 热榜(每日云端定时任务)

alphaXiv 首页 Trending 是社区票选的新论文榜,大厂与知名高校的新工作基本都在上面。每天由 Claude Code 云端定时任务(routine)跑一遍下面的流水线,**关机也照常执行**,做完直接 commit 并 push 到 `main`。任务提示词、模型与触发时间在 <https://claude.ai/code/routines> 管理,本节是它的规则来源。

**准入**(脚本判):首发 7 天内,**任意一次**每日扫描时 `public_total_votes`(网页点赞按钮上的数)≥ 30;只收计算机方向(`Computer Science` / `cs.*` / `stat.ML`);7 天内始终没到 30 的不收。票数要攒两三天,所以不看「当天」而看 7 天窗口,每篇只在第一次达标的那天被记一次。**达标即入库,不设人工拍板**:真正值得犹豫的材料到不了 7 天 30 票,这条热度线就是这个来源的闸门三。

**分流**(脚本初判,核实后终判,看**第一作者所属**,不看 alphaXiv 的机构标签——它有时为空或不全):

| 情况 | 去向 |
|---|---|
| 主导机构在 [`readings/_机构名单.md`](../readings/_机构名单.md) 里 | `A · 名单内`:报告解读,目录键 = 名单那一行的目录名 |
| 名单外 | `B · 名单外`:日常研读,方向从 `readings/index.md` 现有的 `## ` 里选 |
| 已在两个库或判定档案里 | `D · 已在库`:跳过,去向指向那篇 |
| 不是计算机研究,或取不到原件 | `不收`:去向写 `不收:理由` |

**每日流水线:**

1. `git pull`,然后 `npm run papers:feed -- --write`:拉热榜(公开接口 `api.alphaxiv.org/papers/v3/feed`,不用登录),把新达标的论文追加进 [`readings/_alphaxiv-扫描记录.md`](../readings/_alphaxiv-扫描记录.md),判定与去向先填初判
2. **核实**:用 alphaXiv MCP(`answer_pdf_queries`、`find_researchers`、`get_paper_content`)或直接读 arXiv 首页,确认第一作者机构与首发日;把扫描记录的判定与去向改成终判
3. **归档**:从 arXiv 取 PDF 放进 `papers/<公司>/` 或 `readings/_src/<方向>/`(非 arXiv 的按第三节去官方渠道取),在对应索引登记一行。**PDF 不进 git**,本机用 `npm run papers:pull -- --apply` 按扫描记录补下载
4. **解读**:从两个索引里「来自扫描记录、还没正文」的行中按票数从高到低取,**每次运行最多 3 篇**,余下的留在队列里下次优先。**一写一审**,每篇两个子 agent:
   - **写稿人**按第三到第六节写,对照第六节的标杆
   - **审稿人**是一个全新的子 agent,拿原件与稿件,**直接改稿**。只抓三件事:表述是否与原件相符(数字、页码、结论、有无编造)、每张配图是否承载了有效信息(不承载就删或换)、该可视化的地方是否做到了最优(原件关键 figure 有没有配上、能不能改成更直白的表或讲解图)。**不抠措辞与细枝末节**——一篇解读的配图就那几张,审稿的力气花在图与事实上
   - 审完即以正式文件名发布(第五节第 5 条的公开审阅),主会话只做调度、登记与提交
5. `npm test` 与 `npm run build` 全绿后 commit 并 push;不绿不推,写进当日清单
6. **当日清单**就是这次运行的最终回复:今天发布了哪几篇、队列还剩几篇、有什么失败。不另建清单文件

**本机自动同步。** 本机的 Claude Code 与 Codex 会话启动时,钩子跑 `scripts/sync-latest.sh`:`git fetch`,GitHub 上有新提交就只做快进合并(`--ff-only`),按扫描记录补下载 PDF,新配图触发 `leet-restart`,再把云端最近一次日报的篇目作为简报交给 agent。本机有未推送的提交、或未提交的改动与云端改了同一文件时,git 会拒绝合并,脚本只报告、不动任何东西。脚本开头还会列出内容目录里改了没提交的文件(按目录计数、最早改于几天前),提醒按 AGENTS.md 的「一批一推」收尾;它只提醒,不替任何一条线提交

脚本只采集与初判,不下载、不登记、不移动;热榜接口没有官方文档,字段一变脚本会直接报错退出而不是静默漏抓,届时改用 alphaXiv MCP 的 `discover_papers`(`prioritize: popular`)按方向词检索顶上。

## 三、开始写之前

1. 确认拿到的是目标报告的完整 PDF,记录封面上的正式标题、版本或发布日期
2. 去模型的官方发布页、官方仓库或官方新闻核对上述实际首发日,写入 `release-date`;论文页只能在没有更直接官方记时作为备选证据。已有正式报告在新规则上线前必须一次性全部回填,不允许部分文章无日期继续发布
3. **动笔前必须查版本**:去官方论文页、官方仓库或发布页检查是否有更新修订。若官方版比本地 PDF 新,先用官方原件替换稳定路径下的旧文件,再重新核对标题、版本、日期、页数和文件完整性;旧版报告地图与页码不得沿用。若因研究需要刻意保留旧版,必须在文章开头明说依据版本及原因
4. 同时做文本提取与逐页视觉检查。文本提取用于搜索,页面渲染用于核对公式、表格、图注、上下标和版式;不能只信 OCR 或抽取文本
5. 先画“报告地图”:按原报告章节列出全部技术主张、关键数字、图表和实验结论,给每项记下 PDF 页码
6. 标出三个层次:**报告明确写了什么**、**我们如何解释它**、**哪些是外部资料补充**。三者不能混成作者原话
7. 遇到论文身份、外部项目或版本现状不确定时,查官方论文页、项目仓库或官方文档;没有证据就保留不确定性,不猜
8. **原件是网页时,必须跟着正文里的链接读一遍**,见下方专条

只有完成报告地图后才开始写正文。这样可以避免文章只追着摘要写,漏掉附录、训练细节或 infra 约束。

### 原件是网页时,这几步换个做法

| 步骤 | PDF 原件 | 网页原件 |
|---|---|---|
| 1 完整性 | 确认 PDF 完整、记页数 | 确认正文抓全(整页文本 + 逐张图),记下页面标注的发布日与你的访问日期 |
| 3 版本 | 查 arXiv 是否有更新修订 | 网页会**原地改动且不留版本号**。记录访问日期即为版本;若正文提到"完整技术报告待发布",必须在开头写明本文依据的是当前博客版 |
| 4 双读 | 文本提取 + 逐页渲染 | 整页文本 + **逐张读图**。网页常把表格做成图片,纯文本抓取会静默丢掉整张表的数字 |
| 5 报告地图 | 每项记 PDF 页码 | 每项记**原文小节名** |

**第 8 条:链接跟进(网页原件的核心动作)**

网页原件的背景是**摊在链接里**的,不跟进就只能抄结论。动笔前把正文里的链接分成三类,按类处理:

- **伴随篇/前作**:同一作者定义框架、方法或术语的另一篇。**优先级最高**——正文的核心主张往往靠它才成立(判据、分级、评分口径都可能在那边)。必须读完并把定义讲清楚
- **评测与数据集**:每个 benchmark 至少要让读者知道"它测什么、为什么选它",不能只出现一个名字
- **方法与引用来源**:逐个打开核实真实标题,不照抄编号(踩过的雷见 [09-日常维护](09-日常维护.md))

链接取来的一切都是**外部补充**,必须与原文结论清楚分开,不得冒充原文内容。跟进后仍拿不到的,如实写"链接指向的材料尚未公开"。

## 四、长文写作契约

目标不是把 PDF 翻译一遍,而是让读者读完后能够回答三个问题:

1. 它到底做了什么,整个系统如何连起来?
2. 为什么要这样设计,它解决了旧方案的哪个具体矛盾?
3. 哪些思想可以迁移到自己的模型训练、推理或基础设施项目?

写作必须满足:

- **极其简单直白**:短句优先;术语首次出现先说人话,再给正式定义;能用一个小例子讲清就不要先堆符号
- **先全景、后细节、再回到全景**:开头给读者一张模型与训练全貌图;每个设计讲完后说明它接在系统哪里、影响谁
- **完整覆盖但不机械复述**:算法、模型架构、数据、训练 recipe、推理、并行与通信、算子/系统优化、评测和已知限制,报告写到什么就覆盖什么;报告没写的明确说没写
- **每个重点都讲原因**:按“旧问题 → 新设计 → 工作机制 → 收益 → 代价/适用边界”展开,不能只列名词和结论
- **保留可迁移启发**:每个核心设计末尾回答“对自己的项目有什么用”;区分可直接复用的技巧与依赖特定规模/硬件的做法
- **图表服务于理解**:优先自己重画简洁 Mermaid 流程图;被点名为关键证据的原文 figure 按第一节配图条出现在该处,不只写页码。直接引用时注明 PDF 页码,**网页原件注明引自原文哪张图**,不把装饰图当内容。引用前必须真的打开图看过,不靠文件名或图注猜内容
- **数字可追溯**:参数量、token 数、训练成本、吞吐、精度变化等数字紧跟 `(PDF p. N)`;**网页原件没有页码,改标原文小节名**(如「原文 2.4 节」)。**但先确认页面是否真有编号**:不少研究博客(如 Transformer Circuits Thread)正文标题不带任何编号,页首目录卡也是运行时生成,这种页一律给小节名,不得沿用「X.Y 节」这种编号写法——读者按编号找不到位置,等于没有锚。不要凭印象补数字;只在图里出现的数字,注明读自哪张图
- **外部补充可辨认**:外部资料只用于补背景或交叉核验,给出链接并明确标成补充,不能冒充报告内容
- **跨篇引用一律纯文本,不写站内链接**:写「见 MixGRPO 一篇」,不要把篇名包成 Markdown 链接、把 `../Tencent/MixGRPO.md` 塞进括号——页面路由不带 `.md`,这种链接点开就是 404;而且**必须写准确篇名**(即文件名去掉 `.md`,如 `HunyuanVideo-1.5` 而不是 `Hunyuan Video 1.5`),只有全名能靠 grep 审计出断链。与 [05-知识库写作契约](05-知识库写作契约.md) 第八节、[06-开源解读流程](06-开源解读流程.md) 的反向链接口径同一条规则。指向外部材料的链接照常给,不受此限
- **中文标点用全角**(`,` `:` `;` `()` `「」`),与已发布各篇一致;代码块、公式与链接内部照原样不动。子 agent 默认会写半角,提示词里要写死这一条
- **中文引号一律用 `「」`**,不用弯引号 `“”`:全库 213/232 篇如此,与上一条同属全角标点要求
- **只写材料本身的技术内容,不写我们的采集过程**:正文里不出现「上一轮调查给出」「索引里登记的那行」「`pdfinfo` 读出 `Pages: N`」「HTTP 403 抓取失败」「MD5 / 字节数校验」这类措辞——那是维护者的工作台账,读者要的是这份报告讲了什么。版本核验与首发日取证**只在文末「资料与阅读边界」留结论与来源**,一句话讲清依据,不叙述操作过程;确实没拿到的证据写「未能核实」即可,不要交代用了哪个工具、返回什么状态码
- **不要用检索手段当论据**:「某词在全文出现 0 次」「全文检索 `MoE` 零命中」是我们核对的方法,不是材料的内容。要表达"报告没写",直接说**它给了什么、没给什么**,能给页码就给页码(「架构一节只有一段话,没有专家池与路由(PDF p.3)」),不要摆词频
- **不要向读者交代本文的写作计划**:「本文不假装复原一条训练流水线」「本文跟着这个重心走」「本文刻意不复述」这类句子删掉。需要限定范围时,直接写限定后的内容,或者用一句事实句带过(「逐个 benchmark 的表格报告已给清楚,下面只讲读表要知道的三件事」)
- **关键词在文中解释**:默认读者第一次接触这些概念。术语首次出现时先说人话,再给中文名、英文全称和缩写;开头几次不要只丢缩写。若开篇术语密集,先放一小段必要的读前背景,但不要让词汇表抢走正文篇幅。文末可用一小节串联关键词;不另建只列名词、不讲关系的索引实体

文章通常会自然包含:一句话结论、阅读路线、全景架构、逐项核心设计、数据与训练 recipe、infra/推理、实验怎么证明、限制与未公开信息、可迁移启发、关键词回看和参考资料。**这只是覆盖清单,不是已冻结模板**;章节顺序应服从该报告自己的叙事。技术论文没有模型全貌和训练 recipe,那几项自然换成这项技术要解决的问题、以及它怎么支撑基模训练或推理;原件没写的照旧不补。

### 原件是综述时,写法换一套

综述不是「问题 → 方案 → 实验」,它是**一张地图**。套常规契约会得到一份目录复述,没有价值。四件事要答清,顺序即叙事:

1. **这张地图切了几刀**:分类轴是什么、判据是什么、为什么这么切。**轴本身才是这篇综述的主要贡献**,比它收了多少篇重要得多
2. **每一区里有什么**:各类的代表工作;哪些结论已经收敛成共识,哪些还在打架
3. **作者的判断**:他们认为哪里最欠缺、有哪些反复出现的失败模式。这一层要与「他们综述到的事实」明确分开,和常规契约的三层事实是同一条纪律
4. **这张地图指向哪些值得单独读**:挑出几篇,说明为什么是这几篇

**第 4 条同时是一个机制,不只是一节内容。** 挑出来的那几篇直接登记进 `readings/index.md` 成 ⬜ 未解读行,「一句话」里写明 arXiv 编号与「来自 <综述名>」;原件等真要动笔时再取——这和网页原件「没有文件、只靠索引登记」是同一套。**综述因此是下一批的入口,不是一篇读完就完的文章。**

正文里不写待办,队列在索引里。综述在库里不另设标记或分类,就是普通一行。

### 标杆文风的六条硬约束

1. **先讲矛盾,再上名词**:先让读者知道旧方法卡在哪,再引入新设计;不从摘要复读或缩写清单开场
2. **一段只推进一个意思**:短句、短段落优先,用“因为”把结论和原因接起来;类比要帮助建模,但不能当作论文证据
3. **复杂设计都走完一条因果链**:旧问题 → 新设计 → 工作机制 → 收益 → 代价/边界 → 可迁移启发。不要只讲“它是什么”
4. **公式也要像正文一样可读**:行内公式只用 `$...$`,独立公式用 `$$...$$`;当前渲染链不支持 `\(...\)`,禁止使用。公式前先说它要算什么,公式后解释符号和操作;上下标太多时,先定义中间量或拆成两步,不为了照抄原式牺牲阅读
5. **图要说清真实性边界**:自己重画的图必须注明根据哪个 PDF 图/页面,并区分“机制示意”与“实测时间/数据”。Mermaid 的节点、时间轴和箭头都要人工核对,能渲染不等于含义正确
6. **读完必须留下判断,不只留下摘要**:明确哪些结论被实验支持,哪些只是作者观察,哪些实现细节没有公开;最后把可迁移的设计原则串回整个系统

## 五、从原件到发布

1. **投递**:PDF 放进 `papers/<公司>/`,确认公司和报告名,并在 `reports/index.md` 对应方向登记一行「报告 | 公司 | 一句话」,放到宏观到微观的位置上。**网页原件**只需确认 URL、公司和报告名并登记,`papers/` 下不留文件
2. **版本核验**:按第二节搜索官方最新版;发现更新先替换原件并重新确认完整性,再进入后续流程。**网页原件**改为记录访问日期,并确认是否有"完整报告待发布"之类的声明
3. **通读**:提取文本、渲染页面,完成报告地图和页码证据。**网页原件**做整页文本 + 逐张读图,并按第三节第 8 条完成链接跟进,证据落到小节名
4. **组织**:找到贯穿全文的主要矛盾,决定文章叙事,列出必须讲清的核心设计
5. **撰写**:默认在各自库里写下划线开头的未发布稿(`reports/<公司>/_<报告>.md` 或 `readings/<方向>/_<材料>.md`);若需要直接检验真实网页渲染,也可使用正式文件名公开审阅。一边写一边回查 PDF,不靠二手摘要。被点名为关键证据的 figure 按第一节配图条当场配上,图在所解释文字之前
6. **自审**:逐项检查覆盖、事实层次、数字页码、图表含义、限制和可迁移启发
7. **验收**:主会话按第七节逐篇验收,通过即发布;维护者通读是抽查,指出难懂、缺失或不够有启发的地方时,按内容问题重写,不做表面润色
8. **发布**:隐藏审阅的稿件在验收通过后去掉文件名前的 `_`;公开审阅的稿件则保持正式文件名。确认索引那一行的材料名与目录键和文件一致(`npm test` 会守),然后运行验证。**一批写完整批提交并推送一次**,推送之后这批才算发布:云端流水线与其他机器只读 GitHub

## 六、已验收标杆与子 agent 协作

现行写作标杆分两路,不要混用:

```text
基模训练 / 模型报告
  papers/DeepSeek/DeepSeek-V2.pdf
  reports/DeepSeek/DeepSeek-V2.md

其他基模相关技术
  papers/DeepSeek/DeepSeekMoE.pdf
  reports/DeepSeek/DeepSeekMoE.md
```

DeepSeek-V2 是模型报告的篇幅、开头和叙事标杆;DeepSeekMoE 是技术篇的因果链、关键 figure 与图文配合标杆。都要学「如何让陌生技术变得可理解」,不得机械复制标题、篇幅、类比或章节顺序。

**翻新已发布稿。** 对照上面对应标杆收一版,不另起炉灶。开头「本文依据」只写最终那一版原件(标题、编号、日期、页数),不写换版过程、v1/v2 对照、决策或中间思考;换版若必须留痕,只在文末「资料与阅读边界」用一两句。按配图条补关键 figure(图在前、字配合)。能删的复述、过程台账、过长版本史一律删。

可以让多个子 agent 并行撰写,但协作边界必须清楚:

- 一个子 agent 只拥有一份原件(一份 PDF、一个 URL 或一份字幕文件)和对应的一篇 Markdown;禁止多个 agent 同时改同一篇解读
- 任务开始前必须完整阅读本流程,并按体裁读对应标杆(模型报告读 DeepSeek-V2,其他基模技术读 DeepSeekMoE),再完成自己报告的章节地图与页码证据
- 任务中必须给出精确的原件路径与解读路径,不让 agent 自行发明目录、拆文章或新建元数据实体
- 子 agent 交付时要列出:已覆盖的报告部分、重要数字的页码(网页原件给小节名)、外部补充、未公开/无法核实的缺口、测试与网页渲染结果。**网页原件另须列出跟进了哪些链接、各取到什么背景**
- 一批至多 3 篇并行:单篇要吃完整份原件,瓶颈是主会话逐页对照的验收能力,不是并发数
- 并行完成不等于自动验收。主会话逐篇对照原件、检查网页,通过即发布;维护者事后抽查

**不派给子 agent 的一类原件:超长画布的网页打印件。** 这类文件整份只有一「页」、高度可达十万 pt(`Ultra-Scale-Playbook` 就是单页 1133 × 102047 pt、20 万字符),后果是:`pdftotext` 一次吐出全文而无任何位置锚点,逐页视觉检查也无从下手——渲染成图会得到一张几十米长、缩到看不清的图。**必须由主维护者亲自处理**,子 agent 拿到它只会退化成「读一遍纯文本抄摘要」。

**但正确的做法不是去裁切打印件,而是回到线上原页面。**(实做 `Ultra-Scale-Playbook` 后修正的结论)打印件是网页的派生物,回到源头能一次性解决全部困难:

- **结构**:直接按 DOM 的 `h2`/`h3` 切段取文,得到干净的小节边界,而打印件里侧边栏目录会和正文交错;
- **公式**:`pdftotext` 会把公式整段吞掉——正文里凡是「given by the following formula」后面都是空的;线上页把公式放在专门元素里(该书是 `d-math`),能直接取到 LaTeX 源码;
- **图表**:图是独立资源,可以单独打开、按需放大。**若图是 SVG,先试着抓它内部的文本节点**,取不到再截图;
- **读图的可靠姿势**:把浏览器视口宽度设成与截图尺寸一致(该书是 800),图片才会按原始分辨率呈现;视口设得比图大反而会被整体缩放,字就糊了。图片文档里 `zoom` 的区域裁切用不了,别在那上面浪费时间。

打印件此时只剩一个用途:**当作某个时间点的冻结快照,用来发现线上版被原地改过什么**。本次即靠它发现该书的小节标题与附录在 2025-02 之后被改动过。

## 七、验收与验证

人工验收逐项回答:

- 原报告的每个主要贡献、关键实验和重要限制是否都能在文章中找到
- 架构、算法、训练 recipe 和 infra 是否讲清“为什么”,而非只给摘要
- 每个精确数字和报告图表是否能回到正确页码(网页原件回到正确小节或正确的那张图)
- 正文点名为关键证据的原文 figure,是否已在该处出现(表 / Mermaid / 原图 / 讲解 SVG)
- 网页原件:正文里的关键链接是否都跟进过,取回的背景是否与原文结论清楚分开
- 推断和外部补充是否与报告原文清楚分开
- 不看 PDF 的读者是否能沿文章独立复述整体设计,并说出至少几条可迁移启发
- 有没有为了显得完整而补写报告未公开的实现

子 agent 交来的稿子,主会话另守四条——这是它自己最查不出的地方:

- **取证细节自己重跑**:子 agent 报的精确证据(提交号、时间戳、页码)在主会话复现一遍;复现不了的,退回能复现的证据,并在文中写明它是上界还是下界
- **图逐格读**:行列、分格、图例与颜色逐一对原图,不看整体印象
- **编号类引用逐条对原页**:定理、命题、推论、表号、图号,各自落在哪一页
- **登记行与派单里的一句话是待核假设**:会议标注、机构、编号、「论文主张」都以原件为准,转引式的尤其要核

代码验证:

```bash
npm test
npm run build  # 隔离写入 .next-check,只验证、不部署
```

状态命令按改动的库跑一条:`npm run reports:status` 或 `npm run readings:status`。

验证通过后,纯 Markdown 正文刷新即可;若新增了 `public/reports/` 或 `public/readings/` 配图,运行 `leet-restart`;只有同时改了页面代码、配置或依赖才运行 `leet-rebuild`。不要把普通 `npm run build` 当作发布命令。

真实网页还要人工检查:

- 页面能从 `/reports/<公司>/<报告>` 或 `/readings/<方向>/<材料>` 打开,目录卡片与标题正确
- 索引按方向分组,组内卡片顺序与索引行序一致;每张卡片显示条幅与经证据核对的实际首发日;修订日或本站更新日不得出现在卡片上
- Mermaid 已生成 SVG 且没有 `.mermaid-error`;图中的箭头、分支和标签与正文含义一致
- KaTeX 公式没有溢出、上下跳动或暴露 LaTeX 命令;复杂上下标在窄屏仍可阅读
- 页面正文不应露出原始 Markdown 标记,尤其检查 `**术语**` 后紧接中文时是否把星号原样显示
- 至少抽查桌面与窄屏下的开头、最长公式、最宽表格和最复杂图

自动测试对两个库同样守护:日期位置与唯一性、真实日历日校验、缺失或非法日期拒绝、索引与已发布文章一一对应、页面顺序等于索引行序、每个方向的已发布卡片按首发日从新到旧(同日按 slug 升序);并要证明修订日出现在正文时不会被当成首发日。另有两条只属于某一库:报告解读的索引公司列必须等于目录名,日常研读的方向目录必须与索引的 `## ` 双向一致。还要守**同一篇材料不能同时出现在两个库**。这些结构检查不能证明解读或首发日证据正确;发布前仍必须保留官方来源核对、逐页人工核对与真实网页验收。

## 八、库存与解读状态

两个库各有一份索引,是各自库存与页面顺序的**唯一记录**:

| 库 | 索引 | 每行的三列 |
|---|---|---|
| 报告解读 | [`reports/index.md`](../reports/index.md) | 报告 \| **公司**(= 目录名) \| 一句话 |
| 日常研读 | [`readings/index.md`](../readings/index.md) | 材料 \| **机构**(纯元数据) \| 一句话 |

两边规则一致:按技术方向分 `## `,行序即页面顺序;每个方向的已发布行按首发日从新到旧,同日按材料名字面值升序;未解读排在已发布后面。**状态不手写,由文件推导**:正文存在为 ✅ 已发布,`_<材料>.md` 存在为 🚧 施工中,否则 ⬜ 未解读。用 `npm run reports:status` / `npm run readings:status` 现场打印,它们列三类告警:已发布文章没登记、登记的目录键与实际目录不一致、原件目录里有文件但索引没有行。

两个库共用同一套方向词表,但建标题的时机不同:报告解读有条目才建(空标题 `npm test` 会拦),日常研读可以先建后填。报告解读不为方向建目录;日常研读的方向就是目录,加方向等于建目录。具体先做哪一批只写在 [01-TASK](01-TASK.md)。

**网页原件在原件目录下没有文件,只能靠索引登记**,所以录入时务必在「一句话」里注明原件是网页并留下 URL 线索。转录文本原件同理,要留视频来源的 URL 线索。

**判过不收的材料记在 [`readings/_判定档案.md`](../readings/_判定档案.md)**,一行一条带理由,唯一用途是让分流的去重步骤跳过它们。规则变了可以重新捞出来,它不是永久黑名单。

**两个索引页可切换「按方向」与「按时间」。** 按方向就是上面的行序;按时间把全部卡片按首发日距今分成三天内、七天内、一个月内、六个月内、六个月以外五段,段内按扫描记录里**达标当天的票数**从高到低,没有票数的(热榜接入前的老文章、手动收的材料)排在后面,再按首发日从新到旧。这个视图是为了看新文章,不为老文章的顺序做额外照顾。视图偏好只存在浏览器本地,不进 URL。

**已读标记**存在 `reports/_已读.md` 与 `readings/_已读.md`,每行 `- <目录>/<材料>`;卡片右下角勾选时只增删那一行,不碰索引与正文。

**执笔记录**存在 `reports/_执笔记录.md` 与 `readings/_执笔记录.md`:每篇由哪个 Agent 后端写成、之后被谁大改过,以及是否已按现行标杆重写(阅读器隐藏)。新写或整篇重写一篇后更新该行,成批的实质修改记进「大改」栏;「待重审重写」的篇目按现行标杆重写并验收后,状态改为「现行」。
