# 运行服务:Web、开发与语音

## 一句话

日常用**生产模式常驻**在 `localhost:3000`(`leet-start` 启停);开发调试用 `npm run dev` 跑在 `localhost:3001`。两者**构建目录、端口、进程全部分离**,可以同时开着互不干扰。服务**完全脱离终端**,关窗口/退出 Terminal 都不受影响。

## 终端命令(已装进 ~/.zshrc)

| 命令 | 作用 |
|---|---|
| `leet-start` | 启动常驻服务(没有生产构建时自动先构建);已在运行则原样返回 |
| `leet-stop` | 停止;PID 文件丢失时会兜底清理端口上的残留进程 |
| `leet-restart` | 重启 |
| `leet-status` | 运行状态 · PID · 内存 · CPU · 访问地址 |
| `leet-rebuild` | **改过代码后**重新构建并重启 |
| `leet-logs` | 跟踪日志(`.leet/server.log`) |
| `leet-open` | 浏览器打开 |

换端口:`LEETPREP_PORT=3002 leet-start`。实现在 `scripts/leet-server.sh`,`~/.zshrc` 只是 source 它——改脚本立即生效,不用再动 zshrc。

## 什么时候需要重新构建

| 改动 | 是否需要 `leet-rebuild` |
|---|---|
| 加题、改题、写笔记、标高频、标已掌握 | **不需要**,刷新页面即见 |
| 新增/修改知识库文章、开源解读 | **不需要** |
| 改 `app/` `components/` `lib/` 等代码、装新依赖 | 需要 |

原因:所有页面都是 `export const dynamic = 'force-dynamic'`,每次请求实时读磁盘上的 markdown。

## 语音与云端判卷服务

模拟面试页面即使没有语音服务也能使用文字模式。完整语音需要单独启动本地服务:

```bash
bash scripts/voice-start.sh    # 前台运行:http://127.0.0.1:8700
```

首次使用先建立仓库外模型所需的 Python 环境:

```bash
uv venv --python 3.12 .venv-voice
VIRTUAL_ENV=.venv-voice uv pip install mlx-audio soundfile fastapi uvicorn python-multipart
```

模型保存在 `~/.mlx-models/`,不进 git。缺失时使用项目脚本下载:

```bash
bash scripts/ms-fetch.sh mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16
bash scripts/ms-fetch.sh mlx-community/whisper-large-v3-turbo-asr-fp16
```

配置放在 `.env.local`,不要提交密钥:

```bash
INTERVIEW_LLM_BASE_URL=https://api.deepseek.com/v1
INTERVIEW_LLM_MODEL=<model>
INTERVIEW_LLM_API_KEY=<key>
INTERVIEW_VOICE_URL=http://127.0.0.1:8700
DASHSCOPE_HOST=<workspace-api-host>
DASHSCOPE_API_KEY=<workspace-key>
```

百炼工作空间级 key 必须配套控制台给出的工作空间主机名。`voice-start.sh` 会读取 `.env.local` 并清除代理环境变量;不要绕过脚本直接启动,否则云端 STT 可能表现为无报错超时。

维护命令:

```bash
npm run interview:index       # 查看实时候选池;正常模式会同步全域热词
npm run interview:profile     # 简历变化后重建画像
npm run interview:tts         # 音色、语速或读音规则变化后重建主问缓存
bash scripts/voice-audit.sh   # 修改语音链路后做端到端检查
npm run interview:live        # 真实调用判卷模型,需要联网和有效密钥
```

语音服务的同步模型推理端点必须保持普通 `def`,不能改成阻塞事件循环的 `async def`。用户录音只临时写入 `/tmp/interview-stt-*`,正常请求结束和下次启动时都会清理;`interview/cache/tts/` 则是有意保留、但不进 git 的题干缓存。

常见语音问题:

| 现象 | 处理 |
|---|---|
| 页面显示语音服务未启动 | 运行 `bash scripts/voice-start.sh` |
| 云端 STT 超时、本地正常 | 确认通过 `voice-start.sh` 启动,让代理变量被清除 |
| 判卷返回 502 | 检查 `.env.local` 的模型地址、密钥和余额 |
| 主问仍现场合成 | 参数变化后重新运行 `npm run interview:tts` |
| 转写术语不准 | 先在页面对照 STT 后端,再检查本题热词;不要盲目扩大全域词表 |
| 音色设置不生效 | 运行 `bash scripts/voice-audit.sh`,检查三跳参数是否完整传递 |

模拟面试的产品行为、出题和判卷机制见 [11-模拟面试系统.md](11-模拟面试系统.md)。

## 后台运行机制

`scripts/leet-daemon.py` 使用 double-fork 与 `setsid` 将生产服务放进独立会话,所以关闭终端不会停止服务。不要用普通的 `nohup cmd &` 替代这层机制;状态、PID 和日志统一通过 `leet-status`、`leet-logs` 查看。

## 为什么 dev 和 prod 要分开构建目录

`npm run dev` 会持续改写构建目录,如果和生产共用 `.next`,常驻服务的产物会被冲掉,再次启动时报
`TypeError: routesManifest.dataRoutes is not iterable`(本项目踩过)。

现在 `next.config.ts` 用 `distDir: process.env.NEXT_DIST_DIR || '.next'`:

- 生产:`NEXT_DIST_DIR=.next-prod`(`npm run build` / `npm run start` 已内置)
- 开发:默认 `.next`

两个目录都在 `.gitignore` 里。

## 本机路径约束

真实项目路径是 `~/1Project/interviewprep`;服务和开发工具都应指向这里。不要通过 `~/Desktop` 下的软链接启动后台进程,macOS 的 TCC 权限会先检查受保护的 Desktop 目录。项目没有配置开机自启,重启电脑后重新运行 `leet-start` 即可。
