### 老师答案准确摘要

> 以下内容是老师页面的结构化参考摘要，不代表事实已经核实。

- **核心结论：**把 Function Calling 描述为推理期注入工具 schema、由模型选择工具、宿主执行后回填结果的显式编排；把 Toolformer 描述为通过自监督构造工具调用样本并继续训练，让模型学会何时生成 API 调用。
- **比较维度：**训练阶段；推理阶段；工具扩展成本；可控性与错误处理；实时数据能力；高德地图选型。
- **选型建议：**实时、频繁变更且需审计的地图工具优先 Function Calling；稳定且高频的固定能力才考虑训练式工具使用，生产系统可混合。

### 事实校正提醒

- Toolformer 并不是把工具结果完全内化进参数；它仍会生成调用标记并依赖外部工具执行，因此“无外部依赖、延迟极低”不成立。
- Function Calling 的工具使用能力通常也来自指令微调或对齐训练，不能笼统称为无需专门训练的零样本能力。
- 工具变更是否必须完整重训取决于实现，可用提示、适配器或增量训练；行业采用率等结论需有版本和来源。

### 原图核对元数据

### 老师答案准确摘要

> 以下内容是老师页面的结构化参考摘要，不代表事实已经核实。

- **核心结论：**按生成前 schema/提示、生成时 CFG/FSM 约束解码、生成后解析/schema/业务校验与有限重试构建分层防线。
- **权衡：**软提示成本低但不保证格式；约束解码保证受支持语法但有引擎与延迟成本；后处理负责发现和有限修复，仍需降级。
- **部署建议：**地图等高可靠工具参数应组合约束解码、语义校验、幂等重试和明确失败。

- 约束解码对推理速度的影响有多大，如何优化？

### 事实校正提醒

- Schema-guided 生成通常是约束解码的一种实现关系，不宜当作互斥大类。
- 正则表达式不能可靠解析任意嵌套 JSON；修复必须限定范围，关键字段禁止静默猜值。
- 重试时把 temperature 从0.3提高到0.7通常会降低结构稳定性，不应作为通用方案；“5%—15%延迟”也必须按引擎、schema和模型实测。
- 应明确区分语法合法、schema 合法和业务语义正确。
