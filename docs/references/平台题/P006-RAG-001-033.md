RAG检索优化可分为检索前、检索中、检索后三个阶段，核心方法是让“找得更准"和”用得更精"。
一、查询扩展（检索前）
原理：原始查询往往信息不足或表述歧义，通过LLM生成同义改写、子问题分解或假设文档（HyDE）来丰富检索素材。
常用手段：
• HyDE：让LLM先写个"理想答案"，拿这个假设文档去检索
• 伪相关反馈：首轮检索Top-K结果中的高频词，反馈扩展查询
• 多视角改写：生成3-5种不同表述同时检索，取并集
适用：用户问题模糊、专业术语不一致的场景
二、混合检索＋重排序（检索中）
技术
原理
作用
混合检索
向量相似度+BM25关键词检索，用RRF或线性加权融合
解决向量对关键词不敏感、长尾实体召回差的问题
重排序（Re-ranking）
用Cross-Encoder对粗排Top-K做精细打分
弥补Bi-Encoder语义粗粒度的缺陷
关键点：两阶段架构——Bi-Encoder快速召回千级候选，Cross-Encoder精排Top-100，兼顾效率和效果。
三、上下文压缩与动态检索（检索后）
•上下文压缩：用LLM或专用小模型过滤冗余段落，只保留与问题相关的句子，解决“中间丢失“和长上下文噪声
• 动态检索粒度：根据问题类型自适应选择块大小—事实性问题用小粒度（256 token），总结类用大粒度（1024 token）或整文档
四、迭代与反馈优化
• 迭代检索：LLM发现当前上下文不足时，生成新查询继续检索（Self-RAG、IRCOT）
• 用户反馈闭环：收集点赞/点踩数据，微调Embedding或重排序模型
选型建议：中小项目优先做混合检索+重排序（投入产出比最高）；长文档场景必上上下文压缩；复杂多跳问答再考虑迭代检索。
