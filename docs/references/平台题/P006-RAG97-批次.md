## 事实校正口径

- Top-K、chunk 大小、overlap、向量维度、索引规模分界和延迟都必须绑定数据、模型、硬件与 SLO，不能写成通用配方。
- Reranker 只能重排已经召回的候选，不能找回召回阶段遗漏的证据。
- 稀疏与稠密检索的原始分数通常不在同一尺度，融合前需要按名次融合或校准。
- RAG 提供外部证据条件，但不能保证事实正确、引用正确或消除幻觉。
- FAISS 是索引库；向量数据库或托管服务还负责持久化、分片、过滤、权限和运维，不能把产品层级混为一谈。
- HNSW、IVF 等 ANN 索引没有脱离数据分布和参数的统一复杂度或规模选型结论。
- GraphRAG、LangChain 与 LlamaIndex 等快速演进项目，正式写作时须查当前官方资料；平台答案只作为问题线索。
- 医疗、法律等高风险 RAG 必须覆盖权威来源、版本/法域、权限、审计、拒答和人工复核，不能只写“接知识库即可”。
