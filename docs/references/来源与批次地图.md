# 来源与批次地图

这里是截图、平台材料和真实面经的**批次级总入口**。它回答三个问题：原始材料在哪里、处理结果记在哪里、某一批现在进行到哪一步。

本文只登记文件职责与批次状态，不复制逐题内容。逐题查老师材料与知识库去向看 [写作参考索引](写作参考索引.md)，逐题查真实面经去向看 [面经考点映射](面经考点映射.md)。执行新批次前分别阅读 [题库采集与导入流程](../02-题库导入流程.md) 和 [面经双写流程](../10-面经双写流程.md)。

## 文件职责

| 要找的内容 | 固定位置 | 是否进 Git | 维护要求 |
|---|---|---|---|
| 原始长截图 | `inbox/<批次>/` | 否，`.gitignore` 忽略整个目录 | 原图是 OCR、公式、表格、标签和页面追问的校核依据；批次表必须记录实际目录、数量与缺图 |
| 真实面经的逐字题干 | [面经原题.md](面经原题.md) | 是 | 使用稳定的 `Bxxx` 编号；保留原话，不润色、不合并 |
| 老师平台的题干、KEY POINTS、答案与页面追问 | `平台题/Pxxx-*.md` | 是 | 使用稳定的 `Pxxx-Qxxx` 编号；老师答案是参考材料，不冒充面经原话或已核实事实 |
| 一批材料的范围、异常、去重与验收结论 | `平台题/Pxxx-批次.md` | 是 | 每批一份；记录原图范围、来源性质、新建/合并/复用结果和未完成事项 |
| 最终可刷题目 | `questions/<分类>/`；LeetCode 标准题进 `leetcode/` | 是 | 按实际考点归类，不按截图文件夹名硬分；保留来源回链 |
| 真实面经到题库、知识库的逐题关系 | [面经考点映射.md](面经考点映射.md) | 是 | 原题、题库、主负责文章、正文覆盖或待办必须能三向核对 |
| 平台材料到题库、知识库的逐题关系 | [写作参考索引.md](写作参考索引.md) | 是 | 文章作者写前回读完整来源，写后填写正文小节和覆盖状态 |
| 知识库文章规划与缺口 | [知识库地图](../04-知识库地图.md) 与 [任务队列](../01-TASK.md) | 是 | 地图长期保留文章规划；任务队列只保留未完成事项，完成后删除任务行 |
| OCR、聚类候选、审阅 JSON 等中间产物 | 系统临时目录 | 否 | 只用于提速，不是正式来源，可以被清理 |

## 来源怎样分流

```text
原始截图或用户原文
        │
        ├─ 仅确认是平台整理题 ─→ P 批次材料 ─→ 写作参考索引
        │
        └─ 用户确认题干来自真实面试
                    ├─→ B 批次逐字原题 ─→ 面经考点映射
                    └─→ 有老师页面时，同时保留 P 批次参考材料

两条路径最后都落到题库，并映射到已有知识库正文或明确的待写任务。
```

- 公司标签、难度标签和老师答案不能证明一道题是真实面经。来源未确认时按平台整理题处理，不加 `面经` 或 🔴。
- 截图分类名只表示采集入口。最终题库分类、topic 和主负责文章由题目实际考点决定。
- 同一题可以在题库层去重，但 B/P 来源记录不能因合并而删除。

## 新批次完成时必须更新

1. 分配不重复的 `Pxxx`；若题干被用户确认来自真实面试，再分配不重复的 `Bxxx`。
2. 在本表新增一行，填写**当前实际存在**的原图目录、图片数量、缺图和来源性质。
3. 链接批次说明；真实面经再链接 B 原件与面经映射，平台材料链接写作参考索引。
4. 只有逐图核对、全库去重、题库落地、知识库映射和验证都完成后，才把状态改成“已完成”。未成文文章可以标为待写，但必须有映射和任务。
5. 原图目录移动或批次状态变化时同步改本表与对应批次说明。不要把批次明细塞回 `00-START.md`，也不要把长期记录只留在完成后会删除的 `01-TASK.md`。
