# 题库采集与导入协作流程(执行手册)

目标:快速把老师平台(深维LLM)的题搬进本地题库,**不建重复题**,每批秒级验证。
本手册自足:全新会话无需任何历史上下文,按此文档即可完成整个流程。

> **先分清来源**:这份手册只管**平台练习题**。如果用户发来的是**真实面经**(面试里真被问出口的题),走 [10-面经双写流程.md](10-面经双写流程.md)——那条流程要同时更新知识库的考点表并加 🔴,不是只入题库。

## 分工

**截图输入**:用户发来截图,或提供 `inbox/2-SFT-258/`、`inbox/3-RL-124/` 这类单层批次目录。目录可带用于排序的数字前缀,名称保留采集分类和本批截止题号,不再套日期子目录。原图只在本地保留,不复制进来源文档目录、不提交 git;准确路径、数量与批次状态登记在 [来源与批次地图](references/来源与批次地图.md)。没有答案时 AI 自行识别并处理。

**电脑采集**:用户授权后,AI 操作已登录的老师平台,读取当前可访问的题目与答案,再按下面流程入库。不要求用户逐页截图。

**当前授权与审阅**:[03 中的标杆](03-题目写作规范.md) 已于 2026-09-03 获用户认可;同日用户批准 [P002 / SFT-258](references/平台题/P002-SFT258-批次.md) 按三名 agent 并行批量导入,事后审阅、不逐题审批。2026-09-04 用户又批准 [P003 / RL-124](references/平台题/P003-RL124-批次.md) 和 P004 / PT-327 沿用同一流程。PT 只是截图批次前缀,不代表题目都属于预训练;P004 必须按实际知识分类。SFT 前三题的 [P001 试跑](references/平台题/P001-核验与入库.md) 仍待用户审阅并保留 `待校对`,不再作为批量前置门槛。

## 电脑采集:先留材料,再翻题

以下页面操作由用户于 **2026-09-03** 说明,页面变化时重新确认:

- 点「显示答案」展开老师的答案;优先读取文字,公式、图表和读取不完整的部分用截图核对。
- 页面底部绿色「已掌握」按钮用于进入下一题,**同时涉及老师平台的掌握状态**。本次用户已授权由 AI 使用它翻题;不能把这项授权当成本地题库已掌握的依据。新建本地题仍是 `mastered: false`,合并时保留本地既有状态。
- 每天解锁额度是**全平台合计 80 道**,不是每个分类各 80 道。分类总题数与当前可访问题数分别记录,不要求一次采完分类总数;额度用尽或进入锁定页时记下进度。

每题按顺序执行:

1. 记录分类、当前题序/总数、题干、标签、公司及页面地址;只记录页面上有依据的信息,不采集账户水印或个人 Note。
2. 展开答案,核对题干、要点、答案、知识点与追问是否读取完整。读不清的公式标待核对,不猜。
3. 在 `docs/references/平台题/` 保存本批来源材料:分配稳定的批次/题目编号,记录采集日期、来源类型、老师题干与答案,便于后续写作回查。**平台整理题不因带公司标签就自动变成已确认面经**;真实面经仍走 10。
4. 材料保存成功后再点「已掌握」,读取新页面确认题目确实变化。页面地址可能不变,题序也可能重排,不能把 URL 或题序当作唯一标识;结合题干、分类与已采记录判重。
5. 同题循环、答案缺失、锁定或加载异常时保留本题与最后成功位置,核实后继续;每批结束核对已保存条数与实际看过的题目,中断后按记录恢复。

采集完成只表示来源材料已留存,还必须完成下面的去重、写作与知识库承接。每题在 [写作参考索引](references/写作参考索引.md) 登记“来源题干及老师答案 → 题库文件 → 主负责文章 → 正文小节与覆盖状态”,复用已有题也不能漏记。后续文章作者须从索引回读原稿,不能只把材料放进文件夹就算会被使用。

## 冷启动清单(新会话第一批前做一次)

3. 处理完首张截图后自查一遍格式再继续,避免整批带病

「RAG与AGENT」类截图的边界:检索/向量/重排/知识库类 → `RAG`;工具调用/规划/记忆/多智能体类 → `Agent`。

**分区映射**(截图版块 → md 六分区):

| 截图版块 | md 分区 |
|---|---|
| 题干大字 | `## 题目` |
| KEY POINTS | `## 要点` |
| REFERENCE ANSWER | `## 答案` |
| KNOWLEDGE POINT | `## 知识点` |
| 追问题目 | `## 追问` |
| NOTE | 不搬运(那是老师平台上的个人笔记区) |

**元数据**:题干下方第一行 chips 是难度与标签;灰色 chip 是出题公司 → `company`。难度按语义对译为 简单/中等/困难,拿不准就留空(可选字段);tags 保留有用的页面标签并订正术语写法,原始标签另存来源材料;截图里的水印(ID:xxxx、时间)一律忽略。frontmatter 各字段照 `_template.md` 写全(含显式的 `mastered: false`)。

**答案处理原则**:按 [03 的答案写作契约](03-题目写作规范.md) 组织。保留正确且与本题有关的技术内容,核实疑点并补条件,用自己的话解释;不把老师答案视为免校对的标准答案。公式用 KaTeX 重排(块级 `$$` 独占一行),表格重排成 GFM 表格。

## 每批流程

1. 对整个来源批次一次提取题干、老师答案、要点与追问,底稿供后续各轮复用。长截图可先统一 OCR,用于全文检索、聚类和查重;OCR 不是正式转写,题干、公式、表格、页内题号、标签、公司和全部追问仍须逐张回看原图。单层目录先清点文件,分别记录稳定来源编号、来源图号/路径与截图可见的平台题号;缺图保留原编号,不把图号当平台题号,也不预设一图一题。续图、重复图、缺答案及不可读内容单列
2. 协调者运行 `npm run topics`,先对照全库(含不同分类)及本批来源统一去重,每轮开工前复核新增目标。在树上定位考点,对命中的 1–3 个候选文件读原文;主题树负责找候选,答案内容决定是否重复
3. 三种判定:

| 判定 | 条件 | 动作 |
|---|---|---|
| **复用(不新建)** | 考点和问法都与已有题相同 | 保留新来源,检查老师答案是否提供有效补充;有补充则合并,否则复用。出题公司不同时在已有题 `company` 追加(如 `字节、美团`) |
| **合并** | 同考点、不同问法/角度 | 并入已有题:题干融合、答案补角度、新问法进「追问」;公司不同时同样在 `company` 追加;**超过长度红线就拆新叶子而不是硬塞** |
| **新建** | 树上无此考点 | 按 `questions/_template.md` 新建;文件名 = 分类内下一个可用序号 + 简称(如 `003-grpo-kl.md`);定好 `topic` 叶子与 `summary` |

4. 按**目标题文件与知识库文章的唯一负责人**分组,登记“来源 → 目标题文件 → 主负责文章 → 负责人”;同一文件只由一人写入,多组共同命中的文章交给指定负责人集中补充。每个 worker 默认约 10 题,简单且独立的题可到 15 题;每轮汇总约 30 条来源,根据去重后的目标分组,不按连续图号硬分
5. AI 新写或实质改写的答案均加 `待校对`,包括参考老师答案重写的题;规则见 03。合并时保留用户的 `mastered`、`highfreq` 与 `Note`
6. **知识库增补**:对每道新建/合并/复用的题,拿 topic 第一段**全库查同名文章**(`rg --files knowledge` 查文章名——匹配只认文章名、不认所在章节),若存在,检查该题考点是否已被文章覆盖;**未覆盖的点补进文章对应小节**(保持原文结构,增量要简洁,并视情况更新「面试考点串联」);文章不存在时**不要自动创建**(整篇文章只在用户点名时撰写)。平台题在 [写作参考索引](references/写作参考索引.md) 回填实际正文小节与覆盖状态;真实面经更新面经映射。无文章时在 04 登记计划名称,映射标「待写」;该题仍可正常刷题,但对应文章创建前暂不进入模拟面试候选池。现有文章仍缺内容则标「待补」。缺口连同来源编号留在 01 任务队列。不能只补考点表不补正文,也不能将平台题标成自拟或加 🔴。汇总表「说明」列注明:知识库已覆盖 / 已补充 / 无文章
7. 验证 = worker 逐题按 03 自检,协调者每轮汇总后集中运行一次 `npm test` 与 `npm run kb:lint`。内容修改不跑 build;用户事后审阅,新语法或疑似渲染问题按需抽查。这里的验证要求不限制前面的浏览器采集
8. 汇总表(事后可查、git 可回滚):列明来源编号、图号与平台题号,以及下列判定和知识库承接状态;异常单列并继续处理其他题。
9. 更新 [来源与批次地图](references/来源与批次地图.md):新批次新增一行,已有批次更新实际原图目录、来源性质、批次说明、长期映射和完成状态。真实面经还必须填写对应 B 批次,不能只登记 P 批次。
10. 每轮集中一个 commit:`feat(题库): +新建X 合并Y 复用Z`

```
# | 分类/topic        | 判定           | 说明
1 | RL/GRPO/KL散度    | 新建 003       | 树上无此考点
2 | RL/PPO/clip机制   | 并入 002       | 同考点换问法,进追问
3 | SFT/解码策略/综述  | 复用 001       | 新来源保留,company 追加美团
4 | RL/GRPO/优势估计   | 新建 004(待校对) | 截图无答案,AI 撰写
```

## 判定尺度(备忘)

- 「同考点」看实际考查内容,不只看措辞或 topic 名字。summary 用于筛候选,复用/合并前读候选题原文;同属 PPO 但考查不同机制的题可以分开
- **topic 第一段的粒度 = 知识库文章粒度**(一个可独立成文的知识点,如 GRPO、GQA、RoPE):定 topic 前先查 `docs/04-知识库地图.md` 的文章词表,能对齐已有词条就对齐,不要另造近义词(如已有 `RoPE` 就别写 `旋转位置编码`)
- 合并以**已有题为主体**,新截图内容做增量;答案始终保持 ≤ 约 500 字
- 所有判定 AI 直接执行,不逐条确认;用户事后扫汇总表,不同意的指出,git 历史随时可回滚
- 截图模糊/整体空白、缺图、缺答案或内容串题时:在异常清单保留来源编号、问题及待处理项,继续其他题;读不出的部分不猜测编造
