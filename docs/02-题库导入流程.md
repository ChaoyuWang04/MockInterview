# 真题入库流程

目标:把真题录入 `questions/`,完成读取、去重、答案整理、知识库承接与验证。截图、网页采集和用户提供文本都走这一条流程;它们只是输入方式,不产生不同题目类型。

本文件只负责端到端编排。题目字段、六分区和答案质量的唯一标准在 [03-题目写作规范.md](03-题目写作规范.md),这里不重复维护另一套写作要求。

## 一、唯一数据模型

- `questions/<分类>/<序号>-<简称>.md` 是题目的唯一实体。
- 进入题库的每一道题都必须带 `真题` 标签;不再使用其他名称或来源编号区分真假。
- `待校对` 只表示答案尚未人工核验,与题目是否真实无关。
- 本地 `inbox/` 只作当轮核对的临时工作区,验收后可清理;它不属于项目数据模型,也不建立长期批次编号、来源映射或重复原题档案。
- 题目内容的技术分类由实际考点决定,不能按截图目录名机械归类。

## 二、输入与读取

输入可以是用户文字、截图目录,也可以是用户授权后在已登录页面中读取的题目。

1. 先清点本批题目,确认题干、标签、公司、答案、知识点与追问是否完整。
2. 截图可先做 OCR 以便搜索,但 OCR 只是草稿;数字、公式、表格、题号和追问必须逐张回看原图。
3. 看不清或没有答案就如实保留缺口,不猜;需要 AI 补写答案时添加 `待校对`。
4. 页面上的掌握状态不能写成本地 `mastered: true`;新题默认 `mastered: false`。
5. 输入中出现 LeetCode 标准题时按 [07-LeetCode清单.md](07-LeetCode清单.md) 校准题号与 slug;非标准题、复合题和手写实现题仍进入真题库。

## 三、先去重再写入

1. 运行 `npm run topics`,按题干、summary、topic 和答案范围搜索全库。
2. 读取最接近的 1–3 道已有题,按实际考点判断:

| 判定 | 条件 | 动作 |
|---|---|---|
| 复用 | 考点和问法已经存在 | 不新建;只补充确有价值的角度或公司信息 |
| 合并 | 同一考点的不同问法或追问 | 并入已有题;超出长度红线则拆成更细的 topic |
| 新建 | 全库没有这个考点 | 使用 `questions/_template.md`,取分类内下一个序号 |

3. 合并时保留原有 `mastered`、`highfreq` 和 `Note`;AI 新写或实质改写答案时保留 `待校对`。

## 四、按题目规范写入

使用 `questions/_template.md`,并逐项执行 03 的字段、六分区、长度、答案质量和 `待校对` 约定。老师答案、旧答案和 AI 草稿都只是参考;真题身份不等于答案已经通过校对。

## 五、知识库同步

对每道新建、合并或复用的题,读取 `topic` 第一段并全库查同名知识库文章:

- 文章存在:确认正文已经回答该考点;没有则补正文和「面试考点串联」。
- 文章不存在:在 `docs/04-知识库地图.md` 登记计划文章名,不为了建立链接而创建空壳文章。
- 题库真题优先进入考点表;作者为了教学连贯额外补出的问法标为「补充题」。
- `🔴 重点考点` 只表示复习优先级,不再表示真实性等级。

## 六、验收

逐题检查:

- 题目带 `真题`;答案待核验时带 `待校对`。
- 没有重复题,topic 第一段与知识库文章名或计划名称一致。
- 主问和已有追问都有答案去向,公式和表格已回看原图。
- 知识库正文与考点表已同步,或计划文章已登记。

最后运行:

```bash
npm test
npm run kb:lint
```

一次导入作为一个逻辑提交;汇报新建、合并、复用、知识库补充和仍待校对的数量即可,不分配额外批次编号。
