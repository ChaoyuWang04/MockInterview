# 日常维护

## 日常习惯

- **内容即数据**:`questions/` `knowledge/` `opensource/` `reports/` `leetcode/` 里的一切(含笔记、掌握状态、高频标记)都是纯文本,勤 `git commit`,历史就是你的学习记录
- 备份 = 推到私有远端仓库,或直接拷贝整个项目文件夹;换电脑 `git clone` + `npm install` 即恢复
- `projects/` 下的源码仓**不被 git 追踪**(体积大且各有自己的 .git),换电脑要重新 clone
- `papers/` 下的 PDF 原件默认不追踪;需要随仓保存某一份时用 `git add -f` 显式加入

## 常见问题

| 现象 | 原因与处理 |
|---|---|
| 页面显示红色错误卡片 | 卡片上写着文件名和原因(frontmatter 语法错 / 缺「题目」「答案」分区),照着改文件 |
| 新分类/新题不显示 | 文件(夹)名以 `_` 或 `.` 开头会被忽略;确认是 `.md` 结尾,然后刷新 |
| 答案里的小标题变成了分区 | 正文用了顶层 `## `,改成 `###` 及以下 |
| 改了内容页面没变 | 内容改动本来就免重启;若确实没变,`leet-restart`。改了**代码**必须 `leet-rebuild` |
| Mermaid 图显示失败 | 页面会显示原始代码和错误信息,按提示修语法 |
| 知识库文章打不开 | 文章名必须全局唯一;确认路径各段都存在(白名单校验会挡住任何不匹配) |

端口、构建缓存、Web 与语音服务问题统一见 [08-常驻服务](08-常驻服务.md);模拟面试的功能行为见 [11-模拟面试系统](11-模拟面试系统.md)。

## 踩过的雷

| 雷 | 处理 |
|---|---|
| 下载的 PDF 被截断,`file` 照样报 `application/pdf` | 下载后一律 `pdfinfo` 验一遍,读得出 `Pages:` 才算数 |
| 拿 HuggingFace 仓库 `createdAt` 当模型首发日 | 那是预置时间,实测早数天到数周;看文件提交时间。口径见 [10-基模报告流程](10-基模报告流程.md) |
| 官方发布日志与官方博客差几天 | 取最早的官方公开事件,不取传播最广的那次官宣 |
| 照抄第三方清单里的 arXiv 编号 | 逐个打 arXiv API 核实;已抓到过张冠李戴、以及根本不在 arXiv 上的 |
| `**` 紧贴标点,页面把星号原样显示 | CommonMark flanking 规则所致。**引号不是原因,标点才是**,两种形状会失效:①闭合 `**` 夹在标点和文字之间(`……的区别:**前者`);②开启 `**` 夹在文字和标点之间(`因为**「包一层」……`)。修法:句末标点(,。:;、!?)挪到加粗外面;成对的右括号/右引号**不能**挪出去(会留下没闭合的左半边),改在 `**` 那侧补一个空格。参考标杆写法 `用 **压缩稀疏注意力(CSA)** 把细节先压缩`。**`npm test` 查不出这个**,只有真实页面算数:打开页面跑 `document.body.innerText.includes('**')` |
| 用 grep 统计正文出现次数 | 中文正文用全角括号,且 `grep -c` 数的是行不是次;先看一眼原文格式再定模式 |
| 批量替换踩到子串 | 先用占位符保护长词(如文件名),再替换短词,最后回填 |

## 按变更类型验证

| 改动 | 必跑 | 按需追加 |
|---|---|---|
| 真题、答案、标签 | `npm test` | 同步修改知识库时运行 `npm run kb:lint` |
| 知识库文章或地图 | `npm test`、`npm run kb:lint` | 人工逐题核对真题覆盖 |
| 开源解读 | `npm test` | 人工核对真实源码和外部链接 |
| 报告解读 | `npm test`、`npm run build` | 核对官方首发日与公司内新到旧顺序;人工逐页核对 PDF 原文、图表、数字和页码引用 |
| LeetCode 清单 | `npm test` | 从官方数据同步时复核题目总数 |
| README、手册和引用 | `npm test` | 人工从 00 的入口走一遍 |
| 模拟面试逻辑 | `npm test` | `npm run interview:live` |
| 语音链路 | `npm test` | `bash scripts/voice-audit.sh` |
| 页面、API、依赖 | `npm test`、`npm run build` | 日常服务需要更新时运行 `leet-rebuild` |

自动检查只验证结构和可执行约束,不能替代答案事实核验、原图复查、源码核对和人工阅读。

## 测试

```bash
npm test        # 本地自动检查;默认不调用外部模型
```

| 测试文件 | 守护什么 |
|---|---|
| `tests/questions.test.ts` | 解析/定点写回逻辑(mastered、highfreq、Note),含路径穿越校验 |
| `tests/samples.test.ts` | 真实题库回归:任何解析失败或 topic/summary 不合规的题会带文件名报错 |
| `tests/knowledge.test.ts` | 知识库树:文章非空、**文章名全局唯一**、章节顺序、嵌套路径、状态标记 |
| `tests/opensource.test.ts` | 解读页非空 + `NN-` 序号前缀 |
| `tests/reports.test.ts` | 公司/报告扫描、一级标题、首发日元数据与排序、长文读取和路径穿越校验 |
| `tests/leetcode.test.ts` | 清单结构(17 组 100 题)、补充题合并、高频标记合法性、排序规则 |
| `tests/interview.test.ts` | 模拟面试:抽题门禁(章节/亲和度)、上下文 append-only、TTS 缓存 key、与 .mjs 脚本的防漂移 |
| `tests/docs.test.ts` | 活动文档链接、入口口径、手册地图和已废弃静态说明 |

> `tests/interview-live.test.ts` 默认跳过(要联网打 DeepSeek),用 `npm run interview:live` 单跑。
> 语音链路另有 `bash scripts/voice-audit.sh`,逐个控件端到端验证,需要 Web 和语音服务都在跑。模型安装与密钥配置见 08。

## 依赖升级

```bash
npm outdated                      # 查看可升级项
npm update                        # 小版本升级
npm test && leet-rebuild          # 升级后验证并重建常驻服务
```

大版本升级(next 16、react 20 等)建议单独开分支验证。
