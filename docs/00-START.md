# 从这里开始

接手这个项目,先读完这一页。**这里只有守则和地图,没有细节**——细节一律在对应手册里,按下面的地图去找。

## 一、这是什么

一套**本地、单人、离线**的大模型面试准备系统。**markdown 文件即数据库**:所有内容都是纯文本,git 可追溯,不依赖任何数据库或云服务。

五个模块,各有一个入口:

| 模块 | 内容在哪 | 页面 |
|---|---|---|
| 题库 | `questions/<分类>/<序号>-<简称>.md` | `/` → `/<分类>` |
| 知识库 | `knowledge/NN-章节/[NN-子领域/]文章.md` | `/kb` |
| 开源解读 | `opensource/<主题>/<项目>/NN-*.md`(源码仓在 `projects/`,git 不追踪) | `/opensource` |
| LeetCode | `leetcode/hot100.md` + `extra.md` + `notes/` | `/leetcode` |
| 服务运维 | `scripts/leet-*.sh` | 终端 `leet-start` |

## 二、七条铁律

1. **markdown 是唯一真源**。页面只读文件、写回文件;不引入数据库,不把内容藏进代码。
2. **写回必须定点替换**。改题目的 `mastered`/`highfreq`/Note 时,只改那一行/那一节,**禁止**用 gray-matter 之类整体重新序列化 frontmatter——会毁掉手写格式与行内注释。
3. **题目正文的 `## ` 只属于六分区**(题目/要点/答案/知识点/追问/Note),内部小标题一律 `###` 及以下。
4. **不编造**。论文编号拿不准就联网核实;项目实现拿不准就去 `projects/` 下看;图片读不出内容就说读不出,不猜。
5. **验证只跑 `npm test`**(秒级)。改了 `app/` `components/` `lib/` 才需要重建常驻服务;只改 markdown 内容刷新页面即可。
6. **改名就要改引用**。文件名是这个系统的连接键(题目 `topic` ↔ 知识库文章名、跨篇引用、题库分类名)。重命名前先全库 `grep` 一遍,把引用一起改;这条踩过两次坑。
7. **用户明确排除的功能不要加**:刷题计划、待复习队列、搜索、网页内题目编辑器、URL 位置参数。

## 四、维护这些文档的规矩

- **每份手册只讲一件事**,保持简洁;`00-START` 永远只有守则和地图,细节不许往这里堆
- 更新时**不是只做增量**:发现过时或错误的内容要**删掉**,避免下一个人被误导
- 流程有变(新增模块、改了约定)→ 先更新对应手册,再回来更新本页地图
- 文件名格式:`NN-中文名.md`,编号按工作流顺序;新增手册接着往后编

## 五、第一次上手

```bash
npm install     # 首次
leet-start      # 启动常驻服务 → http://localhost:3000
npm test        # 秒级全量验证
npm run kb:lint # 知识库写作契约检查
```

开发调试用 `npm run dev`(端口 **3001**,与常驻服务互不干扰)。
