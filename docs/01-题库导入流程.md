# 截图批量导入协作流程(执行手册)

目标:快速把老师平台(深维LLM)的题搬进本地题库,**不建重复题**,每批秒级验证。
本手册自足:全新会话无需任何历史上下文,按此文档即可完成整个流程。

## 分工

**用户**:攒截图 → 一条消息发一批(建议 ≤15 张)。不用做任何说明;截图默认带答案,没答案的题 AI 自行识别并处理。

**AI**:按下面流程处理整批,结束给出汇总表。

## 冷启动清单(新会话第一批前做一次)

1. 读 [02-题目写作规范.md](02-题目写作规范.md)(文件格式、六分区、长度红线)
2. `npm run topics` 打印主题树,建立去重索引
3. 处理完首张截图后自查一遍格式再继续,避免整批带病

## 截图 → 本地字段映射

**分类映射**(老师平台的分类角标/面包屑 → 本地 `questions/` 文件夹名,**不要新造文件夹名**)。目前 `questions/` 下只有 4 个文件夹(Agent / RAG / SFT / 手撕代码),其余 4 个在遇到第一道题时按下表的名字新建:

| 平台叫法 | 本地文件夹 |
|---|---|
| RAG(RAG与AGENT 中偏检索的) | `RAG` |
| Agent | `Agent` |
| SFT / 大模型训练与微调 | `SFT` |
| RL / 强化学习 | `RL` |
| 多模态 | `多模态` |
| 预训练 | `预训练` |
| AI Infra | `AI Infra` |
| 手撕代码 | `手撕代码` |

「RAG与AGENT」类截图的边界:检索/向量/重排/知识库类 → `RAG`;工具调用/规划/记忆/多智能体类 → `Agent`。

**分区映射**(截图版块 → md 六分区):

| 截图版块 | md 分区 |
|---|---|
| 题干大字 | `## 题目` |
| KEY POINTS | `## 要点` |
| REFERENCE ANSWER | `## 答案` |
| KNOWLEDGE POINT | `## 知识点` |
| 追问题目 | `## 追问` |
| NOTE | 不搬运(那是老师平台上的个人笔记区) |

**元数据**:题干下方第一行 chips 是难度与标签;灰色 chip 是出题公司 → `company`。难度按语义对译为 简单/中等/困难,拿不准就留空(可选字段);tags 照抄截图 chips 原文;截图里的水印(ID:xxxx、时间)一律忽略。frontmatter 各字段照 `_template.md` 写全(含显式的 `mastered: false`)。

**答案处理原则**:技术内容完整保留,但**用自己的话重写**,不逐字照抄平台文本;公式用 KaTeX 重排(块级 `$$` 独占一行),表格重排成 GFM 表格。

## 每批流程

1. `npm run topics` —— 唯一需要预读的索引,不读题目正文
2. 逐张读图,在树上定位考点;只对命中的 1-3 个候选文件读原文
3. 三种判定:

| 判定 | 条件 | 动作 |
|---|---|---|
| **跳过** | 考点和问法都与已有题相同 | 不建题;出题公司不同时在已有题 `company` 追加(如 `字节、美团`) |
| **合并** | 同考点、不同问法/角度 | 并入已有题:题干融合、答案补角度、新问法进「追问」;公司不同时同样在 `company` 追加;**超过长度红线就拆新叶子而不是硬塞** |
| **新建** | 树上无此考点 | 按 `questions/_template.md` 新建;文件名 = 分类内下一个可用序号 + 简称(如 `003-grpo-kl.md`);定好 `topic` 叶子与 `summary` |

4. 截图无答案的题:AI 直接撰写参考答案,tags 加 `待校对`(页面可见,用户复核后删)
5. **知识库增补**:对每道新建/合并的题,拿 topic 第一段**全库查同名文章**(`find knowledge -name "<topic第一段>.md"`——匹配只认文章名、不认所在章节),若存在,检查该题考点是否已被文章覆盖;**未覆盖的点补进文章对应小节**(保持原文结构,增量要简洁,并视情况更新「面试考点串联」);文章不存在时**不要自动创建**(整篇文章只在用户点名时撰写)。汇总表「说明」列注明:知识库已覆盖 / 已补充 / 无文章
6. 验证 = `npm test`(全库可解析 + topic/summary 合规 + 知识库文章非空,秒级)。**不开浏览器、不跑 build**;仅当用到从未用过的语法(如新类型 mermaid 图)才抽查渲染
7. 一批一个 commit:`feat(题库): +新建X 合并Y 跳过Z`
8. 汇总表(事后可查、git 可回滚):

```
# | 分类/topic        | 判定           | 说明
1 | RL/GRPO/KL散度    | 新建 003       | 树上无此考点
2 | RL/PPO/clip机制   | 并入 002       | 同考点换问法,进追问
3 | SFT/解码策略/综述  | 跳过           | 与 001 重复,company 追加美团
4 | RL/GRPO/优势估计   | 新建 004(待校对) | 截图无答案,AI 撰写
```

## 判定尺度(备忘)

- 「同考点」看 topic 叶子会不会重名,不看措辞;先信 summary,拿不准才读原文
- **topic 第一段的粒度 = 知识库文章粒度**(一个可独立成文的知识点,如 GRPO、GQA、RoPE):定 topic 前先查 `docs/03-知识库地图.md` 的文章词表,能对齐已有词条就对齐,不要另造近义词(如已有 `RoPE` 就别写 `旋转位置编码`)
- 合并以**已有题为主体**,新截图内容做增量;答案始终保持 ≤ 约 500 字
- 所有判定 AI 直接执行,不逐条确认;用户事后扫汇总表,不同意的指出,git 历史随时可回滚
- 截图模糊/整体空白读不出内容时:跳过该张并在汇总表标注「图不可读」,不要猜测编造
