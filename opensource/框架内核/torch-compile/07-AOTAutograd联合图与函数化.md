# AOTAutograd:联合图与函数化

这一页回答一件事:Dynamo 只交来一张前向图,反向怎么也在编译期进图;原地修改、视图别名与 DTensor 这类张量子类又怎么处理,才能让编译后的函数在 autograd 眼里和原函数一模一样。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

Dynamo 交来的是一张 torch 函数级别的前向图(02 章),里面没有反向。eager 下的反向是 autograd 引擎在运行时按前向记下的链一个节点一个节点调出来的,编译器在编译前向时根本看不见它。训练里反向的算量通常不比前向少,这一半不进图,编译最多只加速一半。

想把反向也抓下来,马上撞上两件 eager 天天在做、编译器最怕的事。

**原地修改与别名。** 模型里到处是 x.mul_(2) 这类原地运算,还有 view、transpose、切片这类和原张量共享存储的视图。对编译器来说,一张图里只要有「写」,它就得先弄清楚谁和谁共享存储、写之前谁读过,才敢重排与融合;弄不清就只能保守,弄错了结果就错。更麻烦的是这些写和别名有一部分是用户看得见的:函数改了传进来的参数,函数返回了参数的一个视图,调用者之后还会接着改它。

**张量子类。** DTensor 这类张量子类在 Python 里重写了算子的分发,后端只认识普通张量。

还有一层约束压在上面:编译后的函数必须对 autograd 表现得和原函数一样。输出的梯度链要对,被原地改过的参数版本号要对,返回的视图改了要能反映回原张量。DDP、FSDP 这类框架在反向里挂着 hook 等梯度就绪,反向如果变成一整块黑盒,hook 的时机也会变。

所以这一章的问题是:**怎么在编译期把反向也抓成图,抓出来的图里没有原地修改与别名、只有普通张量,而调用者看到的一切行为不变。**

## 二、解法

最天然的直觉是:反向本来就是 autograd 引擎按前向留下的链,逐个调用各算子的求导公式。那就在假张量上把前向跑一遍,紧接着当场调一次求梯度的接口,把引擎发出的每一个算子都录下来。前向和反向于是落进同一张图,这张图叫联合图。知识库 TorchCompile 篇讲过这一步为什么能让反向也被融合,这里只讲它怎么保住 eager 的语义。

![AOTAutograd 在一次编译、一次前向、一次反向里各做什么:编译期先把 Dynamo 交来的前向图函数化后跑一遍只收集元数据,再把原输入与 tangent 一起喂给前向加求梯度接口录成联合图,原地修改改成返回新值、子类拆成普通张量,切分后前向图当场交给 Inductor、反向图默认首次反向才编;运行期前向先整理重复与互为视图的参数,再进入一个 autograd.Function,里面拆子类、调编译好的前向、装回子类,出来后在尾声里把被改的输入写回、别名输出按视图链重放;反向默认仍由 eager 引擎驱动,整个编译区域是一个节点,先对齐梯度步长与 DTensor 放置再调编译好的反向,区域外的梯度累加与 DDP、FSDP 的 hook 要等整个区域反向跑完才轮到;另一条路 Compiled Autograd 在反向开始时遍历整张 autograd 图,把各区域的反向图、hook 与梯度累加一起抓成一张图再交给 torch.compile](/opensource/torch-compile/07a-joint-graph-and-runtime-wrappers.svg)

**先跑一遍只看不录。** 真正录图之前,AOTAutograd 先在假张量上把函数化之后的前向跑一遍,什么图也不录,只为回答几个问题:哪些输入被改了,改的是数值、还是形状与步长;哪些输出和输入或中间结果共享存储;哪些是张量子类;有多少带副作用的算子要串起来。这一遍还顺带判断要不要反向:没有一个输出需要梯度、也没有需要梯度的输入被改,就只编一张推理图,不录联合图。在不求梯度的上下文里调用,走的就是这条路。

**再跑一遍录联合图。** 联合图的输入是两组:原来的输入,加上每个需要梯度的输出对应的一个 tangent,也就是反向时从上游传回来的梯度。录制时先跑前向,再用这些 tangent 调一次求梯度接口;前向和引擎发出的每个 ATen 算子都记成节点,求梯度那一段录下的节点标成反向,其余标成前向。录的是穿过 autograd、函数化与子类这几层分发之后的最底层算子,不再是 Dynamo 那张 torch 函数级别的图。之后这张图被切成前向图与反向图,各存什么、重算什么由 08 章讲。

**函数化:把「改」变成「返回新值」。** 录制时每个张量都套上一层函数化包装。原地算子被改派到它的非原地版本,算出的新值记到这块存储的待更新列表上;视图记住自己是怎么从底座切出来的。之后再用到同一块存储的另一个别名时,先把待更新的值应用到底座,再按记下的切法重新切一遍,读到的就是改过的值。录完之后的图里一个原地算子都没有,AOTAutograd 在结尾专门断言这一点。图从此是纯函数,编译器可以随意重排、融合、复用缓冲。

**被改的输入交给图外写回。** 图不能改输入,就让它把被改输入的新值当作额外的输出返回。运行时分两种写回:输入不需要梯度、只改数值(比如归一化层的统计量缓冲),Inductor 会打开一个开关把这次拷回留在图的末尾,由后端去写;其余情况在图跑完之后由包装层逐个拷回,只改了形状与步长的就按新值把元数据改回去。被改的输入如果需要梯度,它的新值也会拿到一个 tangent 参与反向,梯度才能从写回处流回原输入。

**别名输出在图外重放。** 输出如果是某个输入或中间结果的视图,编译好的前向照样把它算出来,但不给它 tangent、不进反向;包装层拿到之后,从真输入或图多返回的那个中间底座上,按录下来的视图链重新切一遍再交给用户。这样返回的视图有正确的梯度链,用户改它也会反映到底座上。

**参数重复与互为视图单独处理。** 同一个张量被传进来两次,录图时会被当成一个,梯度也会被算重,所以先去重;两个不同的输入共享存储、其中一个又被改了,就把它们合并成一个共同的底座作为图的输入,在图里按原来的切法重新切出两个视图。

**张量子类拆成普通张量。** DTensor 这类子类声明了「怎么拆」:拆出里面的普通张量(DTensor 是本地分片),加上一份不可变的元数据。录图时把普通张量现场装回子类再调用,子类自己的分发逻辑被一路追进去,DTensor 发出的通信也作为算子进图;出图之前再拆开。于是后端看到的只有普通张量。运行时由一层包装负责入口处拆、出口处装。

**最后打包成一个 autograd.Function。** 编译好的前向与反向被装进一个自定义的 autograd 函数:它的前向调编译好的前向图并保存反向要用的张量,反向调编译好的反向图。外面再包上前面说的写回、重放、去重几层。在 eager 的 autograd 图里,整个编译区域就是这一个节点;用户调反向时,驱动一切的仍是 eager 的引擎。

**为什么实际不吃亏。** 函数化、元数据收集、联合图都只在编译时做一次。运行时的那几层包装在编译时就生成成直线代码,下标全部提前算好;函数没有改输入、没有别名输出、没有子类时,对应的那几层直接省掉,前向就是一次调用。

**另一条路:Compiled Autograd。** AOTAutograd 的反向是按编译区域各录各的,而且是借求梯度接口录的,看不见由引擎统一调度的 hook,也录不到把梯度累加进参数的那一步。断图把前向切成几段,反向也跟着切成几段,中间夹着 eager;DDP、FSDP 挂在参数上的 hook,本该在某个梯度一就绪就触发,官方文档也承认它可能被推迟到整个编译区域的反向跑完之后。Compiled Autograd 换了个时机:不在编译前向时抓,而是在反向真正开始时,由 C++ 遍历整张 autograd 图,给每个节点算一个缓存键(节点类型加上非张量的属性,张量与尺寸抬成图的输入);未命中就在假张量上把整张反向抓成一张 FX 图,各编译区域的反向图原样拷进来,hook 与梯度累加成为图里的节点,再按 eager 的时机把它们挪回该在的位置,最后把整张图交给 torch.compile 再编一遍。它只在编译函数的调用期间生效,所以反向要在编译函数里面调。

## 三、代价

**编译期要多跑两遍 Python。** 除了 Dynamo 自己的一遍,AOTAutograd 还要在假张量上跑一遍收集元数据,再跑一遍录联合图,两遍都带着函数化与子类的分发。反向图的生成本身也在这里付账;只是交给 Inductor 生成代码默认推迟到第一次反向(01 章)。

**tangent 的样子是猜的。** 联合图在编译期就要知道反向传进来的梯度长什么样,可它要到运行时才出现。当前默认猜它和对应输出的形状、步长一样;运行时对不上,反向入口先按猜的步长新建一块再拷一份,每步都付。子类更贵:DTensor 的梯度放置方式和编译时猜的不同,就要在反向入口做一次重分布,也就是一次集合通信;该是子类的地方来了普通张量,直接报错。

**反向的上下文在编译时就定死了。** eager 的反向是动态的,可以在外面套一层自动混合精度再调;编译好的反向在录图时就决定了是否在混合精度下运行。默认假设反向和前向处在同一个混合精度上下文里,而官方的混合精度建议恰恰是反向不要放在里面;两者不一致时,官方文档自己写的是可能静默出错。

**不支持对编译区域再求二阶导。** 要求保留梯度图、再对梯度求导的写法,走到编译好的反向时直接报错。

**反向会复用激活的显存。** 前向保存下来、又不和任何输入输出共享存储的张量,反向会把它们的缓冲拿来复用。代价是编译好的反向不许保留计算图:要做第二次反向、或要对梯度再求导而保留计算图,都会在反向入口报错,除非关掉这项复用。

**需要梯度的输入被原地改,每次都多一次拷贝。** 这种写回留不进图,只能在图外拷回:多一个 kernel,新值还要多占一份显存直到拷完。

**Compiled Autograd 把反向的账再付一遍。** 第一次反向要把整张反向图重新过一遍 Dynamo、AOTAutograd 与 Inductor;之后每次反向即使命中缓存,C++ 也要把整张 autograd 图的节点逐个走一遍算键。开着它时 autograd 的多线程执行被关掉;默认尺寸先当静态,某个尺寸一变就按动态重编;图里出现假张量模拟不了的张量类型就直接报错。

## 四、和同类大厂框架不一样的地方

01 章已经比过 JAX 的抓图方式、分支、缓存键与形状。这里比的是反向从哪来、原地修改谁负责。对照对象是 JAX 与 TensorFlow 的 tf.function,两者都在大规模训练里用。

| | torch.compile 的 AOTAutograd | JAX 的求导加即时编译 | tf.function 里的 GradientTape |
|---|---|---|---|
| 反向从哪来 | 编译期在假张量上调一次求梯度接口,把引擎发出的算子录成联合图,再切成前、反两张 | 求导是函数变换,输入一个函数、返回算梯度的新函数;把即时编译套在它外面,整个求梯度函数一起编 | 在函数里用 GradientTape 求梯度,官方训练步骤示例把求梯度与参数更新整个写进 tf.function |
| 原地修改 | 用户照常写,编译期函数化成返回新值,运行时再写回 | 数组不可变;更新语法返回新数组,即时编译里原值不再被用到时编译器把它就地做 | 可变状态只能是 tf.Variable,用它的赋值方法改;这类有副作用的算子作为图的一部分每次调用都执行 |

一句话:JAX 从语言层面不给原地修改与副作用留位置,反向只是又一次函数变换,编译器天然拿到纯函数,求导与即时编译还能任意嵌套,二阶导照样编;torch.compile 接受 eager 的全部写法,于是要在编译期补一套函数化,在运行时补几层包装,把 eager 的行为一样一样还原回去。

## 五、调参与观测

这一章的参数分三处:`torch._functorch.config` 与 `torch._dynamo.config` 里的全局配置,在之后发生的编译里生效,已经编好的不受影响;编译入口的 `backend`;日志环境变量,要在导入 torch 之前设好。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `torch._functorch.config.backward_pass_autocast` | 全局配置,或用 `config.patch` 只作用于某次编译 | `"same_as_forward"` | `"off"`:假设反向不在 autocast 里;也可给一组 autocast 参数 | 编译与 eager 的 loss 曲线对照 |
| `torch._functorch.config.donated_buffer` | 全局配置 | 开源构建为 `True` | `False`:反向不复用激活缓冲,允许 `retain_graph=True`,反向峰值显存略高 | 报错信息里点名这个开关 |
| `torch._functorch.config.guess_tangent_strides_as_outputs` | 全局配置 | 开源构建为 `True` | `False`:tangent 只按内存格式猜,非该格式的梯度到来时转一次 | profiler 里反向开头的拷贝 kernel |
| `torch._functorch.config.view_replay_for_aliased_outputs` | 全局配置 | 开源构建为 `True` | `False`:别名输出改走 autograd 自带的视图重放,不行再退到 `as_strided`,后者的反向较慢;配置注释说多数模型感觉不到差别 | — |
| `torch._functorch.config.debug_assert` | 全局配置 | `False` | `True`:运行时多查一遍 requires_grad 等编译期假设,排查精度问题时开 | 断言报错 |
| `backend` | `torch.compile` | `"inductor"` | `"aot_eager"`:只跑 Dynamo 与 AOTAutograd,图用 eager 执行;用来判断错在 AOTAutograd 还是 Inductor | 与 `"eager"`、`"inductor"` 三者对照 |
| `torch._dynamo.config.compiled_autograd` | 全局配置,在调用编译函数前设 | `False` | `True`:编译函数调用期间触发的反向整张抓图再编译 | `TORCH_LOGS=compiled_autograd` |
| `torch._dynamo.config.compiled_autograd_kwargs_override` | 全局配置 | `{}` | 给 Compiled Autograd 那次编译单独改参数,目前只支持 `fullgraph` | — |
| `torch._dynamo.config.optimize_ddp` | 全局配置 | `True`(按 DDP 分桶切图) | `"python_reducer"`:换 Python 版 reducer,配合 Compiled Autograd 让通信进反向图(15 章) | `TORCH_LOGS=ddp_graphs` |

**观测三处。** 看图:`TORCH_LOGS=aot_graphs` 打出切分后的前向与反向图,前向图多出来的输出就是被改输入的新值与别名底座;`TORCH_LOGS=aot_joint_graph` 打出切分前的联合图;`TORCH_LOGS=+aot` 打 AOTAutograd 的调试日志。tlparse 报告里同样有这几份图与前向元数据。Compiled Autograd:`TORCH_LOGS=compiled_autograd` 打出每张反向图与重编原因,`compiled_autograd_verbose` 再加上 autograd 节点到图节点的对应,会拖慢运行;`torch._dynamo.utils.counters["compiled_autograd"]["captures"]` 数抓了几次。

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 混合精度训练,按官方建议只把前向与 loss 放进 autocast | `torch._functorch.config.backward_pass_autocast = "off"` | 让编译后的反向与 eager 的精度一致,不额外花什么 |
| 反向里挂了 hook(FSDP、DDP、自定义梯度处理),想让 hook 与梯度累加也进图 | `torch._dynamo.config.compiled_autograd = True`,把前向、loss 与 `backward()` 写进同一个编译函数 | 多一次整张反向的编译,每步多一遍 C++ 遍历 autograd 图 |
| 同一次前向要做多次反向(多个 loss 分开反传、需要 `retain_graph=True`) | `torch._functorch.config.donated_buffer = False` | 用反向峰值显存换能多次反向 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 报 `torch.compile with aot_autograd does not currently support double backward` | 是不是对梯度再求导(梯度惩罚、二阶优化) | 把需要二阶导的那段用 `torch.compiler.disable` 隔出编译区域;这种写法往往先撞上下一行的报错 |
| 报 `compiled with non-empty donated buffers` | 反向是不是带了 `retain_graph=True` 或 `create_graph=True` | 设 `donated_buffer = False`,或改成每次前向只反向一次 |
| 报 `Expected a DTensor tangent but got a plain Tensor` | 编译函数返回了多个要梯度的输出,是否只对其中一部分调了反向 | 按报错提示对不需要梯度的输出调 `.detach()` |
| 开 autocast 后编译版的 loss 与 eager 对不上 | 反向是不是在 autocast 外调的 | 设 `backward_pass_autocast = "off"` |
| 编译后 DDP 或 FSDP 的反向通信全挤到最后,和计算不重叠 | `TORCH_LOGS=aot_graphs` 看反向是否一整块、hook 是否只能在区域外触发 | 保持 `optimize_ddp` 默认的分桶切图,或开 Compiled Autograd(15 章) |
| 反向 profiler 里每步开头多出一批拷贝 kernel | 梯度的步长是否和前向输出不同,或需要梯度的输入被原地改 | 让输出与梯度保持同样布局;把对需要梯度输入的原地修改改成非原地 |
| 设了 `TORCH_LOGS=aot_joint_graphs` 后导入 torch 就报 `Invalid log settings` | 名字拼写 | 注册的名字是单数 `aot_joint_graph` |

## 六、常见误区

**「编译了前向,反向就整张编成了一张图。」** 文档里「反向也提前抓出来、交给编译器」的说法听起来就是这样。实际上每个编译区域各自打包成 autograd 引擎里的一个节点,反向仍由 eager 引擎逐个节点驱动;断图几次,反向就是几段编译好的反向加上中间的 eager,参数的梯度累加与 hook 都在节点外面。要一整张反向图,得开 Compiled Autograd。

**「反向在 autocast 外面调,编译后的反向自然也在外面跑。」** eager 下确实如此,反向的精度看调用那一刻的上下文。编译后的反向在录图时就定了,默认按前向所在的上下文录;官方文档把这列为 torch.compile 与 eager 的语义差异,说错了会静默出错。按官方混合精度建议写代码的人,恰恰要把 `backward_pass_autocast` 改成 `"off"`。

**「函数化会把原地修改抹掉,参数和缓冲就不会被改了。」** 函数化只是让图里没有原地算子,改动一个不少:被改的输入要么在图的末尾写回,要么在图跑完后由包装层写回。反过来,原地修改也不会让编译断图或报错,03 章说的副作用表管 Python 对象,张量的原地修改全在这一章处理。

**「开了 Compiled Autograd,哪里调 `backward()` 都会被编译。」** 开关的名字像全局生效。实际上它只在编译函数被调用的那段时间里挂上,`loss.backward()` 写在编译函数外面,走的还是普通的 AOTAutograd 反向;要么把反向写进编译函数,要么用内部的 `torch._dynamo.compiled_autograd._enable(torch.compile)` 把训练步包起来;源码注释推荐优先用开关。

**「DTensor 进了编译,图里还是 DTensor。」** 调试时打印图的人常这么以为。图里只有本地分片与集合通信,DTensor 在入口被拆开、出口被装回。梯度的放置方式在编译时就猜好了,运行时来的梯度放置不同会触发一次重分布,多出来的通信出现在反向的开头,在图里找不到。

**「`retain_graph=True` 在编译后照样能用。」** eager 下它只是让计算图多活一会儿。编译后的反向默认会复用前向保存的激活缓冲,这些缓冲只能用一次,所以带着 `retain_graph=True`(以及隐含它的 `create_graph=True`)的那次反向在入口就报错,不用等到第二次。报错信息里给了关掉复用的开关名,代价是反向显存高一些;前向保存的张量全都和输入输出共享存储、没有可复用的缓冲时,不会报。

**「日志名照文档抄就行。」** 官方可观测性页与排障页都写着 `aot_joint_graphs`,而代码里注册的是 `aot_joint_graph`。设错名字不是没输出,而是导入 torch 时就抛 `Invalid log settings`。
