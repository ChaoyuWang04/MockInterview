# Python 语义建模与副作用

这一页回答一件事:抓图只抓得住张量运算,函数里那些改列表、改字典、改对象属性、改全局变量的 Python 代码,编译之后怎么保证每次调用照样生效。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

编译产物是「抓一次、跑很多次」的:抓图只在第一次调用时做,之后每次调用直接跑改写后的字节码(01 章)。可模型代码从来不只有张量运算。往缓存列表里追加一个结果、给统计字典加一、让模块上的步数加一、改一个全局开关、在闭包里改外层变量,这些都是 Python 层面的副作用,FX 图里根本表达不了。

于是有两种直接的骨折方式。**抓图时真的去改**,那这些修改只在编译那一次发生,后面每一次调用都悄悄少做一遍;抓图还可能中途推倒重来(断图时会从头再抓,05 章),真改了的对象就被改了两遍。**抓图时干脆不管**,结果一样:编译后的函数少了这些行为。两种情况都不报错,结果和 eager 不一致,而且往往要跑很多步之后,从某个统计量或缓存里才看出来。

还有一层更底的问题:抓图时碰到的每一个 Python 值,都要当场决定它「在图里是什么」。张量要变成图里的节点,整数可能被当成常量折进去,列表要记住里面每一项各是什么,函数要决定是钻进去接着抓、整个作为一个节点放进图、还是抓不了只能断图。判断错了,要么图是错的,要么平白多出断图。

所以这一章的问题是:**怎么在不真执行的前提下,把 Python 对象的状态和修改模拟准,并让这些修改在每一次调用里都兑现。**

## 二、解法

最天然的直觉是记账:抓图时不碰真对象,只在一个替身上改,顺手在账本上记一笔「这个对象被改过」;等编译好的图跑完,再照账本把改动写回真对象。torch.compile 就是这么做的,账本叫副作用表,替身叫追踪对象。

![抓图与每次调用的分工:左边是示例函数的四行代码,抓图期间只执行 1 次,张量运算记进 FX 图,改已有列表和改对象属性只改追踪对象并登记进副作用表,真对象不动,表里记的是每个对象的最终状态而不是操作流水;右边是每次调用都执行的改写后字节码,依次调用编译图、新建逃逸出去的新对象、还原返回值,最后按副作用表把最终状态一次性写回真对象](/opensource/torch-compile/03a-trace-once-write-back-every-call.svg)

**每个值换成一个追踪对象。** 抓图时,局部变量和栈上的每个值都被包成一个追踪对象,按 Python 类型分成 250 多个类:张量、常量、列表、字典、集合、用户自定义对象、nn 模块、各种函数、上下文管理器、高阶算子等。追踪对象回答两件事:这个值在图里是什么(张量是图节点,可折叠的常量当场算掉,容器记住每一项的追踪对象),以及它支持哪些操作、每个操作怎么模拟。一个 Python 对象在一次抓图里只对应一个追踪对象,两个名字指向同一个列表,改其中一个,另一个也看得见。

**追踪对象带着来源。** 从函数外面来的值(参数、全局变量、模块属性,以及它们的元素和属性)记着「从进入函数时的哪里能取到它」,比如「第 1 个参数的第 0 个元素」。来源有两个用处:一是变成 guard,决定这份编译结果下次还能不能用(04 章);二是写回时能准确找到那一个真对象,别名关系不会断。在函数里新建的对象没有来源。

**修改只落在替身上。** 往已有列表里追加,改的是追踪对象里那份条目清单,真列表不动,副作用表把这个列表标成「改过」;给对象设属性,表里按对象、按属性名记下最新的值,保留第一次写入的先后。函数里新建、又没流出函数的对象,抓完时直接从表里清掉,不产生任何写回。

**函数调用走三条路之一。** torch 的算子和张量方法直接成为图里的节点;普通 Python 函数默认钻进去继续抓,和外层共用同一张副作用表;标准库里少数模块、numpy 与 pandas 这类第三方库、被显式禁用的函数,调用处就断图。优先级是「强制内联名单」高于「跳过名单」高于「默认内联」。标准库里一批用 C 写的函数钻不进去,就用预先写好的 Python 等价实现(polyfill)顶替,这样也能内联进来。

**图跑完之后写回。** 改写后的字节码在调用编译图之后依次做:为逃逸出去的新对象重新建一份;把返回值还原出来(有来源的直接取原对象,张量从图输出里取,常量直接装入,其余按追踪对象重建一个新的 Python 对象);最后把副作用表里的改动一次性写到真对象上。列表整体切片替换,字典只更新新增和改过的键值,属性逐个设值,闭包变量、全局变量直接存回,迭代器往前推到该到的位置,随机数生成器恢复状态。所有写入集中放在最末尾,免得前面的写入影响后面对象的还原。

**写回的是最终状态,不是操作流水。** 追加 10 次,写回时是一次切片替换,不是 10 次追加。绝大多数场景里这两者等价;真正依赖中间顺序的情况(比如限长队列,追加顺序决定挤掉哪一项)会被识别出来,直接断图,不会静默写错。

**为什么实际不吃亏。** 写回是几行 Python 字节码,只在确实有副作用时生成;没有副作用、返回值全是张量的函数走一条快路径,图跑完直接解包返回。抓图期间的模拟只在编译时付一次。

## 三、代价

**每次调用都要付写回的钱,而且按容器大小计。** 列表改了一项,写回时整张列表切片替换;字典平时只写改过的键,但只要删过键,就先清空再把全部键值重写一遍。在函数里维护一个很长的 Python 列表,或者一个每步都删键的字典,每一步的写回都会跟着变长,这部分开销不在图里,profiler 里看起来像 CPU 侧的空转。

**建模是一项永远做不完的活。** 前端最大的一块代码就在这里:追踪类约 2.5 MB,C 函数的 polyfill 15 个模块。Python 每种没被建模的类型、每个钻不进去的 C 函数,都意味着断图或退回到兜底的「用户自定义对象」类,后者能做的操作有限,也是抓图出意外最常见的来源。

**有几类副作用写回不了,只能断图。** 高阶算子(条件分支、激活重计算等)的子图里改外层对象;限长队列;在编译区域里定义的类,它的实例又流出了区域;要重建的生成器里带修改。这些都是一次断图,结果仍然正确,但图碎了(05 章)。

**打印和日志默认断图。** 它们的效果就是副作用,又没法记成「最终状态」。可以登记成「挪到图跑完再执行」,代价是它不再按原位置执行,打印语句之后又被改过的对象,打出来可能是改过的样子;而且参数只能是张量、常量和格式串。

**激活重计算下 eager 和编译天然不一致。** eager 的激活重计算在反向里重跑前向,会把前向里的 Python 副作用再做一遍;编译后没法在反向里重放 Python 修改,默认遇到就断图,要么接受这处差异。

**绕过前端的逃生口会让账本失明。** 把函数标成「整个进图、前端不钻进去」,前端就看不到里面的副作用,也不做安全检查;里面改了外部对象,编译后不会写回,官方文档自己说这会导致难查的静默错误。

## 四、和同类大厂框架不一样的地方

对照对象是 TensorFlow 的 tf.function 和 JAX 的即时编译,三者都是「追踪一次、之后重放编译结果」,分歧在 Python 副作用由谁负责。

| | torch.compile | TensorFlow 的 tf.function | JAX 的即时编译 |
|---|---|---|---|
| 对函数的要求 | 接受带副作用的普通 Python | 官方建议不要依赖 Python 副作用,只拿来调试追踪过程 | 要求纯函数:输入全走参数,结果全走返回值 |
| 追加列表、改全局这类副作用什么时候发生 | 每次调用,在编译图跑完之后写回 | 只在某组输入第一次调用、也就是追踪时发生,之后重放图不再执行这段 Python | 只在第一次追踪时执行一次,之后的调用不再重复 |
| 状态放哪 | 普通 Python 对象、模块属性都行 | 放进 tf.Variable,用它的赋值方法改 | 显式作为参数传进、作为返回值传出 |
| 读到的全局变量在两次调用之间变了 | 读过的全局变量进了 guard,变了就重编(04 章) | 仍用追踪时的值,也不会因此重新追踪 | 可能静默沿用第一次捕获的值 |
| 想每步打印一个值 | 默认断图;登记后挪到图跑完再打印 | 用 tf.print,它每次执行都会打印 | Python 的打印只在追踪时出现 |

一句话:TensorFlow 和 JAX 把「别写副作用」的责任交给用户,换来追踪器简单、语义可预测;torch.compile 自己记账把 Python 语义补齐,换来的是这 2.5 MB 的建模代码,以及每次调用末尾那段写回。

## 五、调参与观测

这一章的开关都在 Python 里,改全局配置或调用装饰器,要在第一次调用编译函数之前设好。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `torch._dynamo.config.side_effect_replay_policy` | 全局配置,编译过程中不能改 | `"info"` | `"warn"`:有副作用就发警告并列出来源;`"error"`:直接报错;`"silent"`:连日志也不记 | 警告里列出的对象来源 |
| `torch._dynamo.config.replay_side_effects` | 全局配置 | `True` | `False`:不再写回 Python 对象的修改,只有导出需要;普通训练推理关掉就是错结果 | — |
| `torch._dynamo.config.reorderable_logging_functions` | 全局配置,往集合里加函数 | 空集合 | 登记的打印或日志函数不再断图,挪到图跑完后执行;只接受张量、常量和格式串参数,不能带关键字参数 | `TORCH_LOGS=graph_breaks` 里对应断图消失 |
| `torch._dynamo.config.ignore_logging_functions` | 同上 | 空集合 | 登记的函数在编译区域里整个变成空操作,不执行也不断图 | 同上 |
| `torch._dynamo.config.dont_skip_tracing` | 全局配置 | `False` | `True`:无视大部分跳过名单,硬钻进去抓;抓图更完整,也更容易撞上建模不到的东西 | 断图原因里的 skip reason 变化 |
| `torch._dynamo.config.skip_fwd_side_effects_in_bwd_under_checkpoint` | 全局配置 | `False` | `True`:激活重计算里的前向副作用不再断图,反向不重放,接受和 eager 的差异 | 断图类型 `HOP: Unsafe side effect` 消失 |
| `torch._dynamo.config.allow_unspec_int_on_nn_module` | 全局配置 | `False` | `True`:模块上的整数属性不再当常量钉死,改它不再触发重编 | `TORCH_LOGS=recompiles` |
| `torch.compiler.substitute_in_graph` | 装饰器,给一个 C 函数注册 Python 等价实现 | — | 抓图时用这份实现内联,eager 下仍调原函数 | 那处断图消失 |
| `torch.compiler.disable` | 装饰器 | — | 被标的函数不编译,调用处断图 | `TORCH_LOGS=graph_breaks` |
| `torch.compiler.allow_in_graph` / `torch.compiler.nonstrict_trace` | 装饰器 | — | 前端不钻进去,整个作为一个调用进图;里面的 Python 副作用不会被记账 | — |

**观测三处。** 生成了哪些写回:`TORCH_LOGS=side_effects` 逐条打出每个被写回的对象、它的来源和在用户代码里改它的那几行栈,同样的内容也进 tlparse 报告。某个值被建模成了什么:`TORCH_LOGS=dynamo` 打出每条字节码执行时栈上的追踪对象类型,官方文档的排障建议是先看它有没有被当成兜底的用户自定义对象。为什么断图:`TORCH_LOGS=graph_breaks` 里,被跳过的函数会写明模块、函数名和跳过的原因。

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 上线前审一遍模型里的 Python 副作用 | 排查期设 `side_effect_replay_policy = "warn"` 并开 `TORCH_LOGS=side_effects`,逐条确认后改回默认 | 多几条警告和日志,换来确认每一处写回都是有意的 |
| 模型里散落着打印张量的调试语句,不想因此断图 | `torch._dynamo.config.reorderable_logging_functions.add(print)`;纯日志不需要的,把对应方法加进 `ignore_logging_functions` | 用「打印挪到图后、只看得到最终参数」换一张完整的图 |
| 用了激活重计算,前向里有计数这类无害副作用 | `skip_fwd_side_effects_in_bwd_under_checkpoint = True` | 用反向不重放这点差异,换掉每层一次的断图 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 编译后某个 Python 列表、计数或缓存和 eager 对不上 | `TORCH_LOGS=side_effects` 里有没有这个对象 | 没有:看修改是不是发生在被 `disable`、`allow_in_graph` 或 `nonstrict_trace` 标过的函数里,把修改移到编译区域里或区域外 |
| 断图原因是 `Attempted to call function marked as skipped` | 日志里的 skip reason:在跳过名单里,还是 C 函数找不到源码 | 自家的纯函数被跳过就检查所在文件;C 函数用 `substitute_in_graph` 注册等价实现 |
| 断图原因是 `HOP: Unsafe side effect` | 是不是在激活重计算或条件分支的子图里改了外层对象 | 把修改挪出子图;能接受差异再开 `skip_fwd_side_effects_in_bwd_under_checkpoint` |
| 断图原因是 `Side effect on existing deque with limited maxlen` | 是否对函数外传进来的限长队列做了修改 | 改用不限长的队列或列表,在编译区域外再截断 |
| 报 `Reconstruct user defined class without a source` | 类是不是定义在被编译的函数里,实例又被返回或存到了外面 | 把类定义挪到模块顶层 |
| 每一步都重编,原因指向模块上的某个整数属性 | 这个整数是不是在前向里被改、又参与了计算或分支 | 改成张量,或开 `allow_unspec_int_on_nn_module` |

## 六、常见误区

**「副作用会在编译后原样重放一遍。」** 这个说法来自「记下来再重放」的直觉。实际写回的是每个对象的最终状态:列表是一次切片替换,字典是一次批量更新,属性是一次设值。所以自定义列表或字典子类里重写的追加、赋值方法,在写回时不会被调用,写回特意绕开了它们,只调内置容器自己的方法。

**「打印放在函数中间,编译后打印的就是那一刻的值。」** 默认情况下打印会断图,那一刻的值确实是对的,但图碎了。登记成可挪动之后,打印被挪到图跑完再执行;如果打印之后又改了被打印的对象,打出来的可能是改过的样子。配置项的注释自己就写明了这个限制。

**「tf.function 和 JAX 的经验在这里也成立:Python 副作用只在第一次调用时发生。」** 从那两个框架迁过来的人常这么以为,于是专门把计数挪出编译函数,或者改成张量来维持状态。在 torch.compile 里没必要,副作用每次调用都会写回;真正要注意的是另一件事:模块属性和全局变量里的整数,一旦参与了计算或分支判断,就被钉成常量进 guard,前向里改它会让下一次调用重编(04 章)。

**「被跳过的函数只是它自己不编译,不影响调用它的函数。」** 跳过发生在调用那一刻:外层函数抓到这里就断图,前后成两张图,被跳过的函数按 eager 执行,它里面再调用的函数仍会被尝试编译。所以一个被跳过的小工具函数放在热循环里,代价是把整段图切开。

**「`allow_in_graph` 能把任何抓不进的函数塞进图。」** 它确实能让前端不钻进去,但同时跳过了前端的所有安全检查,包括副作用记账。函数里改了外部对象,编译后不会写回。官方文档把它称作容易误伤自己的工具,普通用户要把函数整个当黑盒,应该注册成自定义算子(14 章)。

**「副作用表也管张量的原地修改。」** 不管。`x.add_(1)` 这类原地运算是张量操作,进的是 FX 图,由 AOTAutograd 的函数化处理(07 章);副作用表只管 Python 对象本身的修改。两套机制分工,排查张量值不对时不要去 `side_effects` 日志里找。
