# vLLM 13|量化

同一份量化 checkpoint 放在不同代的卡上,会落到完全不同的矩阵乘 kernel;vLLM 怎么用一个方法名把 30 种量化格式收进同一个接口,让每一层自己决定权重怎么建、怎么载、走哪个 kernel,以及为什么省显存一定成、省时间却不一定。

说法都在源码基准 `94f4170df3`(tag `v0.30.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

量化要省的是三笔账。权重决定装不装得下:70B 的模型按 BF16 存是 140 GB,一张 80 GB 的卡先被权重撑爆,KV 一块都分不到。权重也决定 decode 的带宽:每出一个 token 都要把全部权重读一遍,小批 decode 的 TPOT 跟着权重字节数走。激活决定 prefill 的算力:张量核的吞吐看两边输入的精度,只有权重和激活都是低精度,矩阵乘才真的变快。KV 决定并发,它怎么折成块数见 03 章。

显存这一头最直白,**模型起不来,或者起来了并发很低**。更隐蔽的是另一头:**量化了反而更慢**。量化格式不是一种:各家工具的打包顺序、缩放因子的粒度、哪些层不量化都不一样;卡也不是一种:A100 没有 FP8 张量核,H100 没有 FP4 张量核。同一份 FP8 checkpoint 放到 A100 上,只能把权重读进来现场还原成 BF16 再算;一层 AWQ 权重的形状不合专用 kernel,就掉进通用路径,一批超过 256 个 token 时每次调用都先把整块权重还原成 FP16 再乘,比不量化还多一遍活。服务照常起来,区别只在启动日志的某一行。

## 二、解法:一个方法名收口,每层自己决定建、载、算

最天然的直觉是把量化做成一个开关,打开就把权重换成低精度。可一份量化权重不只有「几 bit」这一个属性。AWQ 把 8 个 4 bit 数塞进一个 32 位整数,顺序是 0、4、1、5、2、6、3、7;GPTQ 沿输入维按自然顺序打包;compressed-tensors 允许同一个模型里不同层用不同方案;gpt-oss 的 MXFP4 只压了专家,注意力和其余线性层仍是 BF16。约定读错一处,读进来的就是乱码。所以 vLLM 用一个**方法名**说清「这份权重是谁、按什么约定压的」,再往下分四级分派:

![同一份量化 checkpoint 在 A100、H100、B200 上落到哪族 kernel:最上面一条是启动时的分派链,方法名找到配置类,配置类给每一层一个量化方法,方法按格式查本平台的 kernel 候选表,第一个自报能跑的胜出;下面 3 行是 FP8 块量化、NVFP4、INT4 权重 3 种 checkpoint,每格画出权重与激活各以几 bit 进矩阵乘。FP8 块量化在 A100 上落到 Marlin、只压权重,在 H100 与 B200 上走 DeepGEMM;NVFP4 在 A100 与 H100 上都落到 Marlin、激活仍是 16 bit,只有 B200 上走 FlashInfer 的 FP4 张量核;INT4 权重本来就只压权重,H100 上是 Machete,A100 与 B200 上是 Marlin](/opensource/vllm-lite/13a-checkpoint-to-kernel.svg)

**第一级,方法名到配置类。** 30 个方法名由 20 个配置类承接:AWQ 的 3 个别名归一个类,GPTQ 的 3 个别名归一个类,在线量化的总名和它的 5 个简写归同一个类。不指定方法时,读模型配置里的量化段;各配置类按一张写死的先后表挨个「认领」,GPTQ 排最前,MXFP4 这类导入代价大的排在末尾;认出来的和用户给的名字对不上,启动就报错。认出来之后再过两道闸:卡的算力版本低于这个类声明的下限,或者模型精度不在它允许的激活精度里,都直接报错。

**第二级,配置类到每层的方法。** 模型构造时,每个线性层、每组 MoE 专家、每个注意力层都问一次配置类「我这层怎么办」。答案可以是不量化(checkpoint 里跳过的层)、一个线性层方法、一个专家方法,或者给注意力层用的 KV 缩放因子方法。所以一个模型里可以同时有 FP8 层、BF16 层和 4 bit 专家;已量化 checkpoint 里没被压的那些层,还能再叠一层在线量化。

**第三级,每个方法管三件事。** 建权重:按 checkpoint 的打包精度和缩放因子形状声明参数,加载器照原样拷字节。加载完再整理:把权重改成选中的 kernel 要的排法,AWQ 的乱序在这里改回自然顺序,Marlin 与 Machete 在这里预打包,缩放因子在这里换布局。前向:调 kernel。在线量化反过来,权重先建在不占显存的元设备上,加载完一层就地压一层,峰值显存不会先摊开整份 BF16 权重。

**第四级,kernel 候选表。** 线性层按格式分 9 张表:FP8 按张量或通道、FP8 块量化、FP8 只压权重、INT8、整数权重的混合精度、NVFP4、MXFP4、MXFP6、MXFP8,每张表里每个平台一串按性能排好的 kernel。每个 kernel 自报两件事:这张卡能不能跑,这一层的形状与粒度能不能做。启动时挨个问,第一个两样都答「能」的胜出。思路和注意力后端的选法一样(06 章),只是按格式分表。专家层的 kernel 由专家方法按格式另查一套表(11 章)。

**激活的量化还要一步现算,编译期把它并掉。** W8A8 与 W4A4 在每次矩阵乘前都要把激活现场压成低精度。编译期有 3 个与量化相关的融合 pass:RMSNorm 加量化、SiLU 乘法加量化、注意力输出加量化,机制见 08 章。默认优化级别下,RMSNorm 加量化在 RMSNorm 或 FP8 量化的手写算子开着时打开,SiLU 加量化再多一个条件:模型是 NVFP4 也开;块量化 FP8 模型会自动打开 FP8 量化的手写算子,于是两项都开。注意力输出加量化在所有优化级别下都关。

为什么这样实际不吃亏:分派全在启动时做,每层只选一次,前向时就是一次直接调用;checkpoint 原样拷进来,不必先转成统一格式;接一种新格式等于写一个配置类加一个方法类,接一个新 kernel 等于在某张表里插一个位置;一个都选不中时,每个 kernel 被拒的原因会全部列进报错。

## 三、代价

**能跑不等于快。** 候选表只问「能不能」,只压权重的降级也算能。FP8 块量化在 A100 和 L40S 上都落到 Marlin:权重以 8 bit 读进来,激活保持 BF16,张量核按 BF16 算;NVFP4 在 Hopper 上同理只剩 4 bit 权重。显存和 decode 读权重的带宽省下来了,prefill 的算力没省,还多一步还原。选中了谁只在启动日志里打一行 info。

**形状不合的层单独掉队。** 候选是按层问的,一层不收就只有这一层降级。AWQ 某层 Marlin 不收时退回未优化的 AWQ 路径:一批不足 256 个 token 用专用 kernel,超过 256 就每次把整块权重还原成 FP16 再做普通矩阵乘;专家层不收时退到通用的整数权重专家 kernel。两处都只警告一次。

**兜底是模拟。** NVFP4 表的末尾是一份「先还原成 BF16 再乘」的模拟实现,前面都不行就用它,只打一行警告;AMD 卡上的 NVFP4 线性层只有这一个选项。

**KV 的缩放因子只能从 checkpoint 来。** 整层一个标量的 FP8 KV,缩放因子取自 checkpoint;缺了就按 1.0,超出 FP8 表示范围的值直接截断,只留一行警告。运行时现算缩放因子的那条路已经删掉;想要现算,只能换成每个 token 每个头一个缩放因子的那几种精度,而它们只有 Triton 后端收。KV 精度一变,注意力后端可能换人、块大小可能跟着变,见 06 章。

**格式在收窄。** 分组 GPTQ 的激活重排不再支持,这种 checkpoint 直接起不来;2 个方法名已标弃用,要显式放行才能用;bitsandbytes 与 GGUF 已经搬出仓库,要另装插件,它们的权重加载见 17 章。

## 四、和 SGLang、TensorRT-LLM 比:卡上没有对口的低精度张量核时谁来兜底

对照对象是 SGLang(基准 826d5170ae)与 TensorRT-LLM(基准 59f5c47f2e)。三家都要把 checkpoint 里的低精度权重接到矩阵乘上,分歧在 kernel 由谁选、手里只有 BF16 权重时管不管,以及卡上没有对口的张量核时退不退。

| 必须有人做的事 | vLLM | SGLang | TensorRT-LLM |
|---|---|---|---|
| 认出 checkpoint 的格式 | 读模型配置里的量化段,各配置类按写死的先后认领;命令行给的名字对不上就报错 | 同样先检测;命令行名字对不上时查一张兼容表,表外报错 | 读 Model Optimizer 导出的量化配置;手填的算法与之冲突就报错 |
| 手里只有 BF16 权重 | 加载时逐层现压:FP8 三种粒度、MXFP8、MXFP4;专家另有 INT8 与 NVFP4 | 加载时现压 FP8;另有只转专家的在线 NVFP4 | 文档只给离线用 Model Optimizer 出 checkpoint 这一条路;加载时现压只出现在视觉生成那一支 |
| 线性层的矩阵乘 kernel 谁来定 | 每种格式每个平台一张候选表,kernel 自报能不能跑,取第一个;可按 kernel 族名过滤,也可拉黑单个 kernel | 块 FP8 与 NVFP4 各一个命令行开关,自动挡按卡选,手动点名的跑不了就报错 | 配方到线性层方法类是一条条件链,一种配方对一个方法类 |
| 卡上没有对口的张量核 | 自动退到 Marlin 只压权重:FP8 在 Ampere 上、块量化 FP8 在 Ada 上,NVFP4 在 Ampere 与 Hopper 上 | 同样有 Marlin 兜底:FP8 在 SM80–SM88 上自动开 Marlin,NVFP4 在 SM80–SM90 上默认走 Marlin | 硬件表直接标不支持:Ampere 没有 FP8 权重,Hopper 没有 NVFP4;只压权重的 NVFP4 是单独一种配方,不是自动退路 |
| KV 的缩放因子从哪来 | 只从 checkpoint,缺了按 1.0;另有每 token 每头现算的几种精度 | checkpoint 或一份外部 JSON,缺了按 1.0 | FP8 KV 可对没声明的 checkpoint 手动打开;NVFP4 KV 必须离线出好 |

vLLM 的取舍是「能起来优先」:只要有一个 kernel 能跑就起服务,代价是降级不报错,要靠读日志才知道。TensorRT-LLM 走另一头,配方和卡对不上就不支持;SGLang 两头都有,自动挡会降级,手动点名的后端跑不了就报错。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。`--kernel-config` 与 `--quantization-config` 都收 JSON,也收点号写法。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--quantization`(`-q`)· 量化方法名 | 启动 | 不设:读 checkpoint 的量化段自动认 | 已量化 checkpoint 上给了对不上的名字:启动报错;BF16 checkpoint 上给 `fp8` 或 `fp8_per_tensor`、`fp8_per_block`、`fp8_per_channel`、`mxfp8`、`mxfp4`:加载时逐层现压,权重字节数减半或更少,没有校准 | 在线量化打 `Quantized N layers of types:`;报错 `does not match the quantization method specified` |
| `--quantization-config` · 在线量化的细粒度配置 | 启动 | 不设 | `linear`、`moe` 各自指定权重与激活精度,`ignore` 跳过层,`targets` 按层名指定(与前两项互斥);已量化 checkpoint 上只作用于它没压的层,命中已量化层直接报错 | 报错 `Cannot apply requested online quantization` |
| `--allow-deprecated-quantization` · 放行弃用方法 | 启动 | 关 | 开:`fbgemm_fp8`、`fp_quant` 能起,打一行弃用警告;关着用它们直接报错 | 报错 `is deprecated` |
| `--dtype` · 模型与激活精度 | 启动 | `auto` | 必须在方法允许的激活精度里:`mxfp4` 与 `modelopt_mxfp8` 只收 BF16,AWQ、GPTQ、`fp8` 收 FP16 与 BF16;不在就启动报错 | 报错 `is not supported for quantization method` |
| `--linear-backend` · 线性层 kernel 族 | 启动 | `auto` | 点名一族(`cutlass`、`marlin`、`machete`、`deep_gemm`、`flashinfer_cutlass` 等,除 `auto` 外 20 个取值):某类层没有这一族的 kernel 就警告后自动选;有但这张卡跑不了就启动报错 | 警告 `has no kernel for this linear layer type`;报错 `Failed to find a kernel that can implement` |
| `--kernel-config` 里的 `linear_backend_per_quant` · 按方案分别点名 | 启动 | 不设 | 键是方案名(`fp8_w8a8`、`fp8_block_w8a8`、`int8_w8a8`、`mixed_precision`、`nvfp4_w4a4`、`nvfp4_w4a16`、`w8a16_fp8`、`mxfp4`、`mxfp6`、`mxfp8`),压过 `--linear-backend` | `Applied linear backend override for` |
| `--moe-backend` · 专家 kernel 族 | 启动 | `auto` | 见 11 章 | 见 11 章 |
| `--kv-cache-dtype` · KV 用什么精度存 | 启动 | `auto`:跟模型精度;checkpoint 声明了 FP8 KV(ModelOpt 或 llm-compressor 导出)时就是 `fp8` | 18 个取值。`fp8`(即 `fp8_e4m3`)、`fp8_e5m2`:每层一个标量缩放因子;`int8_per_token_head` 等 3 种:每 token 每头现算,只有 Triton 后端收;`nvfp4`:每 16 个值一个 FP8 缩放因子,只有 SM10x 上的 FlashInfer 收;`turboquant_*` 4 种:K、V 分别 3–8 bit,有自己的注意力后端 | `Using fp8 data type to store kv cache`;缺缩放因子时警告 `Using KV cache scaling factor 1.0 for fp8_e4m3` |
| `--kv-cache-dtype-skip-layers` · 哪些层的 KV 不量化 | 启动 | 空;选 TurboQuant 时稠密模型自动加上首尾各 2 层 | 写层号或 `sliding_window`:这些层保持模型精度,页大小补齐到与量化层一致 | — |
| `-cc.pass_config.fuse_norm_quant`、`fuse_act_quant`、`fuse_attn_quant` · 量化融合 | 启动 | 前两项:`-O1` 起按条件开(见第二节);`fuse_attn_quant`:各级都关 | 打开注意力加量化融合会让分段图改成整图(08 章) | 日志 `Enabled custom fusions:` |
| `VLLM_DISABLED_KERNELS` · 拉黑 kernel | 环境变量 | 空 | 逗号分隔的 kernel 类名,选择时直接跳过,排在它后面的补上 | 报错原因里写 `disabled by environment variable` |
| `VLLM_USE_DEEP_GEMM` · 块 FP8 用不用 DeepGEMM | 环境变量 | 1 | 设 0:Hopper 与 Blackwell 上块 FP8 改走 CUTLASS 块量化 | `Selected … for Fp8LinearMethod` 那一行 |
| `VLLM_BLOCKSCALE_FP8_GEMM_FLASHINFER` · Hopper 上块 FP8 小批走 FlashInfer | 环境变量 | 1 | 设 0:不再按批大小在 FlashInfer 与 DeepGEMM 之间切,全用 DeepGEMM | 同上 |
| `VLLM_MARLIN_INPUT_DTYPE` · Marlin 的激活也压 | 环境变量 | 不设(激活 BF16) | `int8`:Marlin 变 W4A8 整数;`fp8`:只在 SM89 与 SM12x 上允许,别的卡直接报错 | 报错 `Marlin W4A8-FP8 only support SM89 or SM12x` |

**怎么看。** 一是方法有没有认对:报错 `Quantization method specified in the model config (X) does not match` 说明命令行名字和 checkpoint 冲突;compressed-tensors 模型在 `VLLM_LOGGING_LEVEL=DEBUG` 下每层打 `Using scheme: … for …`。二是 kernel 落到了谁,每种格式各有一行 info:FP8 是 `Selected CutlassFP8ScaledMMLinearKernel for Fp8LinearMethod` 这种,整数权重是 `Using MacheteLinearKernel for mixed-precision linear` 以及 `Using … for AutoGPTQLinearMethod`、`Using … for AutoAWQMarlinLinearMethod`,NVFP4、MXFP4、MXFP8 是 `Using … for NVFP4 GEMM` 这种。看到 `Marlin` 而 checkpoint 是 W8A8 或 W4A4,就是降级成了只压权重。三是降级警告:`Falling back to unoptimized AWQ kernels`、`Falling back to Moe WNA16 kernels`、`NVFP4 linear falling back to the slow and unoptimized emulation backend`。四是 KV:`Using KV cache scaling factor 1.0 for fp8_e4m3` 说明 checkpoint 没带缩放因子;`Checkpoint does not provide a q scaling factor` 说明 Q 的缩放因子借用了 K 的。

**卡代 × 方案 → 走哪族 kernel。** 线性层,假定 FlashInfer 与 DeepGEMM 都装着;标了「只压权重」的格子就是 W8A8 或 W4A4 的 checkpoint 被降级。

| 卡代 | FP8 按张量或通道(W8A8) | FP8 块量化 | INT4 权重(GPTQ、AWQ) | NVFP4(W4A4) |
|---|---|---|---|---|
| A100、A10(SM8x,不含 SM89) | Marlin,只压权重 | Marlin,只压权重 | Marlin | Marlin,只压权重 |
| L40S、RTX 4090(SM89) | CUTLASS(要 CUDA 12.4 以上) | Marlin,只压权重 | Marlin | Marlin,只压权重 |
| H100、H200(SM90) | CUTLASS | 小批 FlashInfer、大批 DeepGEMM;不可用时 CUTLASS 块量化 | Machete | Marlin,只压权重 |
| B200、GB200(SM10x) | CUTLASS;激活按整张量静态量化时 FlashInfer 在前 | DeepGEMM;不可用时 CUTLASS 块量化 | Marlin | FlashInfer CuTe-DSL,其次 FlashInfer CUTLASS |
| RTX 5090、RTX PRO 6000(SM12x) | CUTLASS;激活按整张量静态量化时 FlashInfer 在前 | DeepGEMM 或 CUTLASS 块量化 | Marlin | FlashInfer CUTLASS |

compressed-tensors 的 FP8 在 SM89 以下的卡上直接换成只压权重的方案,落点通常也是 Marlin(装了 Humming 时是 Humming)。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| H100 上跑官方出的 FP8 块量化 checkpoint | `vllm serve Qwen/Qwen3-32B-FP8` | 什么都不加:方法与粒度从 checkpoint 认,块 FP8 走 DeepGEMM;多写 `--quantization` 只会多一个对不上的机会;换到 A100 上会静默落到 Marlin,要确认那行 `Selected …` |
| H100 上只有 BF16 权重,显存吃紧,要立刻起服务 | `vllm serve <模型> --quantization fp8_per_channel` | 权重按输出通道一个缩放因子、激活每 token 现算,走 CUTLASS 的 W8A8;用权重减半换没有校准的精度损失,离群值多的模型先在自己的数据上测 |
| 长上下文把 KV 先吃满,checkpoint 带了 K、V 缩放因子 | `vllm serve <模型> --kv-cache-dtype fp8 --kv-cache-dtype-skip-layers sliding_window` | 全注意力层的 KV 字节数减半,容量怎么折算见 03 章;滑窗层对量化更敏感,留在原精度;注意力后端可能换人(06 章),启动后看有没有 `scaling factor 1.0` 警告 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动报 `does not match the quantization method specified in the quantization argument` | checkpoint 是不是已经量化过 | 去掉 `--quantization`,让它自己认 |
| 启动报 `is not supported for the current GPU. Minimum capability` | 这个方法类的算力下限 | 换方案,或换卡 |
| 启动报 `GPTQ group activation ordering (desc_act=True) is no longer supported` | checkpoint 的 `desc_act` 与分组 | 换静态重排或不重排的 checkpoint |
| 启动报 `Unknown quantization method: bitsandbytes` | 插件装没装 | 装 `vllm-bnb-plugin`;GGUF 同理要装 `vllm-gguf-plugin` |
| 启动报 `Failed to find a kernel that can implement the … linear layer. Reasons:` | 原因列表;是否点名了 `--linear-backend` 或设了 `VLLM_DISABLED_KERNELS` | 去掉点名或拉黑,回到自动选 |
| 量化后显存降了,吞吐没涨甚至掉了 | 选中 kernel 那一行是不是 `Marlin` 或 `Emulation` | 卡代不对就换方案(A100 用 INT4 权重比 FP8 更合适);装齐 FlashInfer 与 DeepGEMM |
| 日志 `Falling back to unoptimized AWQ kernels` | 哪几层、形状是多少 | 这些层每次大批都整块还原;换 GPTQ 或 compressed-tensors 格式的同一模型 |
| 开 FP8 KV 后答案变差 | 有没有 `Using KV cache scaling factor 1.0` | 换带 K、V 缩放因子的 checkpoint;敏感层用 `--kv-cache-dtype-skip-layers` 留原精度 |
| 开 FP8 KV 后吞吐反而掉 | 注意力后端那行日志变没变 | 见 06 章 |
| 开批不变模式后量化模型变慢 | 选中的 kernel 变没变 | 批不变模式下 FP8 与 AWQ 的 Marlin 被禁用,FP8 非 CUTLASS 的层每次把整块权重还原成 BF16 再乘,NVFP4 被强制走 CUTLASS 或模拟(14 章);这是换确定性的代价 |

## 六、常见误区

- **以为方法名写 `awq_marlin` 或 `gptq_marlin` 就等于用 Marlin kernel。** 名字里带着 kernel,很容易这么读。这个基准里 AWQ 与 GPTQ 各自的 3 个名字落到同一个配置类,kernel 另从候选表里选:H100 上 4 bit 权重先轮到 Machete,只有 Machete 不收才是 Marlin;形状不合的 AWQ 层会退到未优化路径。看 `Using … for mixed-precision linear` 那一行,别看方法名。
- **以为 A100 上 `--quantization fp8` 能吃到 FP8 张量核。** 教程只说「FP8 省一半显存、更快」。A100 没有 FP8 张量核,自动落到 Marlin 只压权重,矩阵乘仍按 BF16 算;L40S 有 FP8 张量核,可块量化 FP8 在它上面同样落到 Marlin,因为 DeepGEMM 与 CUTLASS 块量化都从 Hopper 起步。省的只是显存和 decode 的读权重带宽。
- **以为 FP8 KV 会自己校准缩放因子。** 旧版有现算的开关,网上教程还在教;官方 KV 量化文档写「三种方法」却只列了两种。这个基准全仓库已经没有现算那条路,checkpoint 不带缩放因子就按 1.0,日志只一行警告。缩放因子要靠 llm-compressor 或 Model Optimizer 离线标定进 checkpoint。
- **以为 `--kv-cache-dtype auto` 就是跟模型一样的 BF16。** checkpoint 声明了 FP8 KV(ModelOpt 的 `kv_cache_quant_algo` 或 llm-compressor 的 `kv_cache_scheme`)时,`auto` 解析成 `fp8`;想要 BF16 KV 必须显式写 `bfloat16`。
- **以为 README 硬件表里列着的格式装好 vLLM 就能用。** 那张表还有 bitsandbytes、GGUF、DeepSpeedFP 三行。前两个已经搬到树外插件,不装插件直接报 `Unknown quantization method`;DeepSpeedFP 全仓库只剩那张表里的一行,代码已经没有。文档与代码冲突时以代码为准。
- **以为 `--linear-backend` 点名失败会自动退回。** 自动选择的「不行换下一个」给人这种印象。实际分两种:这类层根本没有该族的 kernel,警告一次后自动选;有该族的 kernel 但这张卡跑不了,候选只剩它,启动直接报错。在线量化文档举的 `--linear-backend flashinfer` 不在可选值里,照抄起不来,要写 `flashinfer_cutlass` 这类完整名字。
- **以为给已量化的 checkpoint 加 `--quantization-config` 会把整模型换成新精度。** 它只作用于 checkpoint 没压的层,比如只量化了专家的 MXFP4 模型,可以给稠密线性层再叠一层 MXFP8;规则命中已量化的层直接报错,不会覆盖。
- **以为 gpt-oss 这类 MXFP4 checkpoint 整个模型都是 4 bit。** 只有专家是 MXFP4,注意力和其余线性层仍是 BF16,算显存时按这个算;而且它只收 BF16 激活,`--dtype half` 起不来。
