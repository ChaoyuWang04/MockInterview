# vLLM 09|推测解码

decode 每出一个 token 都要把全部权重读一遍;vLLM 怎么让 13 个推测方法名共用一条「先猜、目标一次验完」的路,以及为什么换一种猜法会连带换掉这一步走的执行器。

说法都在源码基准 `94f4170df3`(tag `v0.30.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

小批 decode 时,一步的时长几乎全花在读权重上。一个 8B 参数的 BF16 模型每步要从显存读约 16 GB 权重,这一步给 1 条请求算还是给 32 条算,读的都是这 16 GB。TPOT 于是贴着一条由模型体积和显存带宽定死的下限,批再小也压不下去。让同一次读权重多产出几个 token,是推测解码的出发点,原理在知识库里讲过。

vLLM 的麻烦在「谁来猜」。配置里认 13 个方法名:在已有 token 里查表的、挂在目标隐状态上的草稿头、模型自带的 MTP 层、一次出整块的块草稿、另一个完整的小模型。它们的草稿从哪来、在 CPU 还是 GPU 上出、每步多跑几次前向、要不要自己的 KV,各不相同。坏的指标有两个。一是访存瓶颈下 TPOT 仍然下不去:选了草稿要在 CPU 上出的猜法,GPU 每步都停下来等 CPU 查表。二是接受率低时反而变慢:每条请求每步固定验 1 加 K 个位置、草稿器固定跑一遍,256 条并发、每步猜 3 个时一步要算 1024 个 token;平均接受长度只有 1.2 时,真正变成输出的只有 307 个。

## 二、解法:猜法各管各的,验证只有一处

最天然的直觉:谁来猜都行,只要猜出来的都交给同一个验证器、按同一条规则收。vLLM 的每一步是固定的三段:目标模型给每条请求算 1 加 K 个位置(上一步采出的那个 token,加上一步留下的 K 个草稿),拒绝采样决定收下几个,草稿器紧接着为下一步再猜 K 个。不同猜法只在第三段不一样:

![同一条时间轴上的四行,每行从目标前向画到下一步目标前向开始,每步猜 3 个:EAGLE、EAGLE3、MTP 在验证之后跑 3 次草稿前向,第 1 次照搬目标批的形状,留在 Model Runner V2 且异步开;DFlash 与 DSpark 只跑 1 次草稿前向就出整块;独立草稿模型跑 3 次完整小模型前向并退回 V1;n-gram 与 suffix 要等采样结果拷回 CPU 查表、排好下一步,这段时间 GPU 空等,退回 V1 且异步关](/opensource/vllm-lite/09a-draft-paths-per-step.svg)

**模型外查表。** n-gram 在这条请求的上下文(prompt 加已生成的部分)里找与结尾重合最长的片段,把它后面的 K 个 token 抄过来当草稿。suffix 还查过去请求的输出,按出现频率估每个候选的概率,每条请求每步猜几个由匹配长度现定,K 只是上限。两者零参数、零前向,但要拿整段 token 历史去查;默认实现在 CPU 上,采样结果得先拷回来。另有一版 n-gram 把查表搬到了 GPU 上。

**挂在目标上的草稿头。** EAGLE 吃目标最后一层的隐状态,EAGLE3 把几层中间隐状态拼起来吃;MTP 是模型自带的预测层,权重就在目标检查点里,不指定路径时直接读目标自己。这一族的第一次草稿前向照搬目标这一步的批形状和注意力元数据,之后每次每条请求只喂 1 个 token,一共跑 K 次。模型带几层 MTP 就按层依次各跑一次;只带 1 层却要猜 3 个,就是同一层连跑 3 次。DFlash 与 DSpark 是块草稿:每条请求喂一个真 token 和一串掩码位,一次前向出整块,不再逐个追。

**独立草稿模型。** 另一个同词表的小模型,每次都是一个完整模型的前向,不吃目标的隐状态,自己的每一层都占 KV。词表不同时可以打开交集映射,只在两边都有的 token 上猜。

**验证只有一处。** 默认是标准拒绝采样。草稿默认贪心取最大的那个,草稿分布退化成一个点,判据就变成「以目标给这个 token 的概率收下」;被拒时从目标分布里扣掉草稿那一份再采一个,K 个全收时再从目标分布白送一个。温度为 0 的请求直接和目标的 argmax 逐位比。草稿采样只看温度,不看 top-k 与 top-p;源码注释写明这只拉低接受率,不改验证之后的分布。另两种验证要显式选:块验证把整块草稿联合起来判,只有 Model Runner V2 实现了;合成验证按给定的每位接受率掷骰子,完全不看目标,是压测用的,输出不再是目标模型的分布。

**每步猜几个。** 全局一个 K。可以另给一张按「这一步排上了几条请求」分段的表,并发高时把 K 降到 0,即这一步不猜;DSpark 带置信度头时还能开自适应验证,按每条请求每个位置的存活概率,在一个启动时剖析出来的全局预算里挑出要验的位置。没有按实测接受率自动关掉推测的机制,也没有按请求开关推测的字段。

为什么实际不吃亏:验证就是一次普通的混批前向,调度器照常把 1 加 K 个位置记成 token 数(02 章),注意力后端把这种短查询仍按 decode 处理(06 章)。Model Runner V2 下草稿的值一直留在 GPU 上,调度器只拿到个数(07 章);只有批里有结构化输出请求时才拷回 CPU 做文法检查(14 章)。收下 j 个草稿,这一步就产出 j 加 1 个 token,读权重的那一次被它们分摊。

## 三、代价

**每步多算 1 加 K 倍的位置。** 纯 decode 的一步从每条 1 个 token 变成 1 加 K 个:1024 条并发、猜 3 个就是 4096 个 token;猜 7 个时是 8192 个,正好吃满 H100 在线服务默认的一步总额(02 章)。块草稿和独立草稿模型还要在总额里给草稿器自己的输入再扣几个槽位。批一大,decode 从等显存变成等算力,被拒的位置就是实打实白算。

**草稿器占显存。** 草稿层和目标层登记在同一份配置里,KV 从同一个块池里分,池里能放的目标 token 相应变少;每条请求还按 K 多留几个 KV 槽位给草稿器往前写,DFlash 多留 K 加 1 个。草稿改成按概率采样时要缓存整份草稿分布:1024 条 × 3 个位置 × 151936 词 × 2 字节,约 890 MiB。EAGLE 一族开着前缀缓存时,命中的最后一块要重算,给草稿头补出隐状态(04 章)。

**猜法决定走哪套执行器。** 两版 n-gram、suffix、独立草稿模型、Medusa、MLP 草稿器、自定义类这 7 种,以及 EAGLE 的并行起草,Model Runner V2 都还没做,整台服务退回 V1;其中草稿在 CPU 上出的几种还会关掉异步调度(07 章)。块验证只在 V2 上有,退回 V1 时照标准拒绝采样跑,不报错。DSpark 和自适应验证反过来只有 V2 做了,强制用 V1 就起不来。

**有几种组合不能开。** 水印要求草稿按概率采、用标准验证,而且猜法只能是 EAGLE、EAGLE3、MTP、DSpark;返回采样分布的回放不收推测解码;为 KV 共享省 prefill 的那个开关不收 EAGLE 一族,因为草稿头要每个 prompt 位置都正确的 logits;按请求数分段的 K 表碰上数据并行会被自动撤掉,因为各副本选出不同的 K 会让集合通信对不上;自适应验证要整图 CUDA graph,不收 LoRA 与流水线并行。开着异步的推测解码还会自动关掉 cascade 注意力。

## 四、和 SGLang、TensorRT-LLM 比:换一种猜法,执行路径跟不跟着换

对照对象是 SGLang(基准 826d5170ae)与 TensorRT-LLM(基准 59f5c47f2e)。三家都有查表、草稿头、独立小模型、块草稿几类猜法,分歧在换一种猜法时 CPU 与 GPU 的重叠保不保得住,以及验证和猜几个由谁定。

| 必须有人做的事 | vLLM | SGLang | TensorRT-LLM |
|---|---|---|---|
| 查表类猜法在哪查 | CPU 版要等 token 拷回,退回 V1 并关异步;GPU 版保住异步,仍走 V1 | 语料树在主机上查,CUDA 上照样留在重叠路径,只有 CPU 设备才关 | n-gram 池在 CPU 上,关重叠并告警;另有一种 GPU 上的后缀自动机在目标前向里查,不关 |
| 独立草稿模型怎么接 | 退回 V1,异步照开 | 沿用 EAGLE 那套重叠 worker 的验证路径 | 和目标装进同一个引擎,留在重叠路径 |
| 候选长什么形状 | 一条链 | 每步留多个分支时是一棵树 | 默认一条链,可选动态树 |
| 验证默认怎么判 | 标准拒绝采样;草稿默认贪心,判据退化成目标给的概率 | 只看目标概率;标准拒绝采样要显式打开,且只收单分支 | 批里有非贪心请求时默认逐位精确匹配;拒绝采样是原型开关 |
| 每步猜几个随负载变 | 按本步请求数查一张静态表;DSpark 另可按置信度逐请求少验 | 按观测到的接受长度在阶梯上升降,只有两代 EAGLE 能开 | 按批大小查表或给并发上限;另有滚动接受率门禁,打穿就永久关 |

vLLM 的取舍是先把 EAGLE 一族和块草稿在新执行器上做完,其余猜法留在旧执行器里,由配置自动切过去;同一份启动参数只改一个方法名,背后的执行器和异步都可能跟着换。SGLang 让内建猜法在 GPU 上一律留在重叠路径里,TensorRT-LLM 按「能不能装进目标那一个引擎」划线,装不进的查表就关重叠。

**怎么看。** 一是稳态日志:每 10 秒一行 `SpecDecoding metrics: Mean acceptance length: …, Accepted throughput: …, Drafted throughput: …, Accepted: … tokens, Drafted: … tokens, Per-position acceptance rate: …, Avg Draft acceptance rate: …%`。平均接受长度 = 1 + 收下的草稿数 ÷ 验证次数,已含白送的那 1 个,范围 1 到 K+1;每位接受率的第 i 项是「前 i 个草稿全收」的比例,只降不升,它在哪一位掉到很低,K 就该截在哪。二是 `/metrics`:`vllm:spec_decode_num_drafts`、`vllm:spec_decode_num_draft_tokens`、`vllm:spec_decode_num_accepted_tokens`,以及带 `position` 标签的 `vllm:spec_decode_num_accepted_tokens_per_pos`,导出时都带 `_total` 后缀;接受长度用 `1 + rate(accepted) / rate(drafts)` 算。结构化输出请求里被文法判为无效的草稿不计入草稿数。三是启动日志:有没有 `Model Runner V2 does not yet support`、有没有 `Async scheduling not supported with … speculative decoding and will be disabled`。

| 场景 | 怎么起 | 拿什么换什么 |

| 开了推测,TPOT 没降反升 | `Mean acceptance length` 与当时的并发 | 接受长度贴近 1 就换猜法或减 K;只在高并发时变慢就加分段 K 表,高并发段填 0 |
| 开了推测后整体吞吐掉了一截 | 启动日志有没有退回 V1、异步被关的告警 | 换成 V2 做了的猜法:EAGLE 一族、MTP、块草稿;查表类至少用 `ngram_gpu` |

| 启动报 `VllmConfig does not have enough slots to schedule a token` 或告警 `max_num_scheduled_tokens is set to` | 一步总额够不够草稿器的输入槽位 | 调大 `--max-num-batched-tokens`,或减 K |

## 六、常见误区

- **以为 K 越大越快。** 官方文档的例子写 5,suffix 那页还建议 16 或 32,大家就照着往大了设。每条请求每步固定验 1 加 K 个位置,草稿头还要多跑几次前向,而第 i 位要前 i 个全中才算数,越往后收下的越少;看 `Per-position acceptance rate` 在哪一位掉下去,K 就截在哪。
- **以为 suffix 不设 K 就是 32。** suffix 的文档写默认 32。代码里不设时取树深上限 24,并打一行告警;要 32 得显式写。
- **以为照文档的例子就能跑 MLP 草稿器。** 文档有完整例子,方法选型表还标着「中到高收益」。基准上模型注册表里这一行被注释掉了,注释写着等 V1 支持再打开,V1 的草稿器分支里也没有它;它又在 V2 的不支持名单里,两头都接不住。
- **看到 MTP 那条「同一层重复前向」的告警,就以为多层 MTP 也在重用一层。** 这条告警只看 K 是否大于 1,不看模型带几层;带多层 MTP 的模型在 V2 上走按层依次调用的那条路,K 不超过层数时每层各跑一次。只有 1 层却设 K 大于 1,告警说的才是实情。
- **以为块验证在哪都生效。** 配置里 `block` 和 `standard` 并列,看不出限制。它只在 V2 的验证器里实现;n-gram、suffix、独立草稿模型会让整台服务退回 V1,V1 的验证器只认合成验证,其余一律按标准拒绝采样,不报错也不告警。
- **把合成验证当成更快的验证方式。** 名字里只说「合成」,压测报告里接受长度又很好看。它按配置的接受率掷骰子决定收不收,目标给什么分布都不看;上线就等于改了模型输出。
- **以为草稿也得带上请求的 top-p、top-k,否则结果会偏。** 直觉是两边分布要一致才能「无损」。验证那一步用的是施加过采样参数的目标分布,草稿只用温度采,源码注释写明这只影响接受率;要提接受率该换猜法或改成按概率采草稿,而不是给草稿补参数。
- **以为 EAGLE 开并行起草会更快。** 文档写它「只兼容 EAGLE 与草稿模型方法」,看着像个普通加速开关。它要草稿头专门按并行起草训过,而且 V2 不支持,打开就整台退回 V1;DFlash 与 DSpark 本来就是一次出整块,不用管它。
