# vllm-lite 解读底稿(常驻)

项目级常驻文件,下划线开头,阅读器不显示,git 追踪,不随发布删除。本解读是按 `docs/06-开源解读流程.md` 新标准重写的精简版 vLLM;长版 `opensource/推理服务/vllm/` 是讲稿转录的历史例外,原样保留,两份互不修改。长版底稿只当「去哪儿找」的线索用,**继承来的任何事实都要在本基准上重核,不得照抄**。

## 一、基准与核对方式

- 官方仓库 <https://github.com/vllm-project/vllm>,本地镜像 `projects/推理服务/vllm/`,分支 `main`
- **基准 commit**:`94f4170df37fe29d68bd2f7e5a496501b78d55ae`(提交时间 2026-09-22),核对日期 2026-09-23;最近的发布 tag `v0.30.0`(另有 `proto-v*` 系列 tag,与主发布线无关,取 tag 时用 `git tag --sort=-creatordate | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$'`)
- 长版基准 `08426d51ef` 到本基准之间有 689 个提交。**长版的行号和默认值不能直接引用。**
- **基准快照**:`/tmp/vllm-base`,导出命令 `git -C projects/推理服务/vllm archive 94f4170df37fe29d68bd2f7e5a496501b78d55ae vllm csrc rust docs README.md pyproject.toml setup.py examples | tar -x -C /tmp/vllm-base`。未导出 `tests/`、`benchmarks/`、`tools/`、`.buildkite/`,要读就用 `git show <基准>:<路径>`。`/tmp` 重启会清,没了就重导
- 读代码一律读快照,不读 `projects/`(`os:check` 会把它快进到上游最新)
- **zsh 陷阱**:`git show $B:rust/...` 里的 `:r` 会被 zsh 当成变量修饰符吃掉,变成 `…ust/…`。一律写成 `"${B}:路径"`
- 目录名 `vllm-lite` 与源码仓目录名 `vllm` 不同,`scripts/os-check.mjs` 里有一张别名表把它指到 `projects/推理服务/vllm`

## 二、一句话核心

vLLM 把「KV 分页 + 不分阶段的 token 级调度 + 块哈希前缀缓存 + CPU/GPU 异步重叠 + 编译与 CUDA graph」做成一套推理服务栈,再用统一的 KV connector 接口把 PD 分离、KV 分层存储和外部缓存挂进来。代码花在哪:`vllm/` 下 Python 源码 37 MB,模型实现与模型层(`model_executor/` 加 `models/`)占 49%,引擎骨架 `v1/` 占 18%(注意力后端 2.2 MB、worker 1.7 MB 最大)。
