# LMCache 解读底稿(常驻)

跨会话状态载体,阅读器不显示。拆解方法与写法以 `docs/06-开源解读流程.md` 为准,本文件只记这个项目的事实与进度。

**这个项目和推理引擎解读不一样的三处**,动笔前先读:

1. **这不是又一个推理引擎。** 引擎内部的调度、分页 KV、前缀树归 vLLM / SGLang 自己的解读。本项目只写缓存层怎么插、怎么存、怎么搬、怎么观测。
2. **推荐路径是多进程守护,不是进程内库。** 官方文档把 in-process 标成 deprecated / Legacy,`lmcache server` 才是主干。进程内 `LMCacheEngine` + `storage_backend/` 还在,只作对照,不按对等章节展开。
3. **PD 分离不是 LMCache 自己传 KV。** 官方 `docs/source/mp/disaggregated_prefill.rst` 写明:当前请求的 P→D 交给引擎侧 NIXL 连接器,LMCache 负责跨请求复用;两者用组合连接器拼在一起。不要写成「LMCache 替代了 PD 传输」。

### 对照用的同领域仓库

第四段对照对象是同类 KV 层 **Mooncake**(月之暗面 Kimi)和 **FlexKV**(腾讯云 TACO),都是大厂大规模在用。vLLM / SGLang 是宿主引擎,连接器怎么插归 02,不进第四节对等列。HiCache 是 SGLang 引擎内三层,不是对等产品。两家本站都尚未成稿,断言只核 README / 官方文档能站住的定位,不写内部实现,核不动就不写。NIXL 只写本项目怎么插,不重写传输库。

## 二、一句话核心

LMCache 是推理引擎旁边的 **KV 缓存层**:把本该只活在 GPU 里的 KV 变成可以跨请求、跨进程、跨机器复用的块。推荐部署是独立进程 `lmcache server`,和引擎没有共命运。8009 KB 源码里,分层存储与 L2 适配约占四分之一,多进程服务与传输约占七分之一,引擎插拔与 GPU 搬运约占七分之一,其余是索引、编排、观测和 CLI。
