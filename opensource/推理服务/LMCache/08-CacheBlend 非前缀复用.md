# CacheBlend 非前缀复用

这一页回答一件事:可复用段落不在 prompt 开头时,怎么命中、怎么转位置、缺口谁补。说法都在源码基准 `0cf5efc7`(tag `v0.5.5`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

前缀缓存只认「从头开始一模一样」。RAG、多文档、把几段材料换顺序再问,可复用的段落往往在中间。热层里明明有过同一段,查找却从第一块就开始 miss。坏的是 **TTFT**:整段 prompt 回到全量 prefill。

真问题不是「块切得不够细」,而是:**命中不能绑在前缀树上;位置变了的 KV 也不能直接拼回去。**

## 二、解法

先换引擎类型,把非前缀模块装进独立缓存服务。默认类型不装它。传输还得让缓存服务自己看得见引擎那块显存(默认那条,或两条都装);只开「引擎自己搬」时启动直接拒绝,不会装上一半再降级。

装上之后,查找变成一条统一请求。一条腿仍报连续前缀盖了多少 token;另一条用存块时登记的指纹,在整段 query 的任意偏移上探测。命中可以不在开头。前缀已经盖住的块不进稀疏腿。两腿都进热层之后才给结果;没有可取回的段,这次请求到此结束。

取回不是把块对块粘上。服务按 token 把命中段散进引擎的分页 KV:位置没变的原样写;位置变了的先转 RoPE 再写。半截槽位、和引擎自己要补算的 token 共用一个块时,也按 token 写。散失败是整次失败,引擎改全量重算,不会留下半截 KV。

缺口——没命中的 token、块与块的接缝、分段前缀留下的洞——由引擎前向补算。进程内遗留路径还会在指定层上,按新旧 K 的差挑一小段重算,再用注意力输出拼回去。推荐的多进程路径不走那套进程内搅拌器;边界补算仍发生,只是发生在引擎侧,服务负责散和转位置。

![未开非前缀引擎类型时请求停在普通前缀查找;已开时才进入非前缀模块,先统一查找命中非前缀块,再把块散进分页 KV 并在位置变化时转 RoPE,缺口由引擎补算,没有从默认路径指向非前缀模块的箭头](/opensource/LMCache/08a-cacheblend-lookup-scatter.svg)

存的时候仍走缓存服务自己搬的那条存请求,额外异步登记指纹。指纹登记失败只打日志,不让这次存储失败。协调器地址配了且事件上报开着,才多一条舰队目录匹配;否则只在本机表里找。

官方文档把进程内那套搅拌开关标成遗留,和这一页的推荐入口不是同一条装配。

## 三、代价

**默认不开。** 引擎类型默认是普通前缀。忘了改类型,RAG 段落再熟也走前缀 miss。

**热层两项仍必填。** 容量和驱逐没有默认,见 01 章。非前缀模块吃同一份热层;指纹表再占一份主机内存。

**多一趟统一查找和一次按 token 的散。** 短 prompt、几乎没有重复段落时,指纹探测和转 RoPE 可能比省下的计算还显眼。

**位置编码要先登记。** 取回前引擎要把 RoPE 状态交给服务。没登记直接取回,服务报错,不会瞎转。

**散是全有或全无。** 引擎分多轮才把块表撑满时,这一轮一个命中都盖不到就推迟;盖到一部分却盖不全,这次失败,整段改重算。

**舰队匹配另有门。** 只配协调器地址、关掉事件上报,日志警告后仍只做本机匹配,不是跨机指纹自动亮。

## 四、和同类大厂框架不一样的地方

同类仍是引擎外面的 KV 层。这一列只拿 Mooncake、FlexKV 来衬托非前缀这件事。HiCache 是引擎内前缀缓存,不进对等列。

| 维度 | Mooncake | FlexKV | LMCache |
|---|---|---|---|
| 首先解决哪件事 | 预填充和译码拆开之后,KV 怎么交接、怎么进池 | 显存不够时把容量伸到主机内存、盘和远端 | 下次同一段文本再来,少做一遍预填充 |
| 不在前缀上的重复段落 | 公开材料不把这件事当招牌 | 公开材料不把这件事当招牌 | 指纹命中任意偏移;位置变了转 RoPE 再写入分页 KV |
| 缺口谁补 | | | 引擎补算没命中的 token 和接缝;不是服务把块直接粘成一条 |

另两列只核公开定位。核不动非前缀复用的内部实现,不写那一行的细节。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。独立缓存服务改引擎类型和传输模式;热层容量和驱逐见 01 章、04 章。传输模式的三种取值见 07 章,不要只改引擎类型、把传输留成「只开引擎自己搬」。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--engine-type` · 要不要装非前缀模块 | 缓存启动 | `default` | `blend`:组合器才挂非前缀模块 | 启动日志;未开时统一查找根本没有 |
| `--supported-transfer-mode` · 谁搬砖 | 缓存启动 | `lmcache_driven` | 非前缀类型要求 `lmcache_driven` 或 `auto`;`engine_driven` 启动 `ValueError` | 日志 `Supported transfer mode:`;启动报错 |
| `--l1-size-gb` / `--eviction-policy` · 热层 | 缓存启动 | 无,必填(01 章) | 非前缀命中同样住这份热层 | 探活口 `/status` |
| `--chunk-size` · 每块多少 token | 缓存启动 | `256` | 指纹窗口跟这块大小走;短于一块的尾巴设计上打不中 | `/status` 的 `chunk_size` |
| `--enable-segmented-prefix` · 前缀中间 L2 失败时是否留洞后块 | 缓存启动 | 关 | 打开:洞后的块当纯加载、洞由引擎补;关掉:从前缀缺口截断。循环状态登记强制关 | 查找结束事件里的分段前缀命中 token |
| `--enable-dedup-content` · 同一段文本不同前缀是否只登记一次指纹 | 缓存启动 | 关 | 打开:内容已在表里就不再登记;关掉:各前缀各登一次 | 指纹登记计数 |
| `--coordinator-url` · 协调器 | 缓存启动 | 空 | 空则本机匹配 | 无舰队客户端 |
| `--coordinator-event-reporting` · 是否把缓存事件送给协调器 | 缓存启动 | 关 | 有地址但不上报:警告后仍本机匹配;两边都开才问舰队目录 | 日志警告;指标 `lmcache_blend.coordinator_matches` |
| `--coordinator-blend-timeout` · 舰队匹配预算与 HTTP 超时 | 缓存启动 | `1.0` 秒 | 调大:等目录更久;必须是大于 0 的有限数 | `lmcache_blend.coordinator_match_timeouts` |
| `--coordinator-blend-match-concurrency` · 同时在飞的目录查询 | 缓存启动 | `8` | 必须 ≥ 1 | 超时与匹配计数 |
| `enable_blending` · 进程内遗留搅拌 | 进程内配置 / 环境 | 关 | 打开要按层搬运,并配检查层与重算比例;推荐独立服务不要靠它 | 断言失败或走进程内搅拌器 |

**怎么看。** 探活口 `/status` 里非前缀模块会报已登记 RoPE 的实例、正在进行的统一查找个数。命中看 `lmcache_blend.lookup_hit_tokens` 对 `lmcache_blend.lookup_requested_tokens`(按块对齐,块尾巴进不了分子分母)。指纹命中与过期块看 `lookup_fingerprint_hits` / `lookup_stale_chunks`。取回看 `retrieve_requests`、`scatter_shifted_chunks`(转了 RoPE 的块)、`retrieve_noops`(按原因分类的空散)。没有 GPU 上下文时 `lookup_no_gpu_context_errors` 会加。不要用引擎那行「外部前缀命中率」当非前缀成绩:前缀全 miss 时那一行仍是 0,指纹命中走另一组指标。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。热层两项必填仍见 01 章。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机 RAG / 多文档,段落不共享前缀 | `lmcache server --l1-size-gb 20 --eviction-policy LRU --engine-type blend`;引擎连本机请求口,传输保持默认 | 用指纹命中换中间段落的 prefill;代价是统一查找和转 RoPE,短请求可能不划算 |
| 同机多引擎副本共用热层,仍要非前缀 | 服务只起一份,同样 `--engine-type blend`;不要把传输改成只开引擎驱动 | 用一份热层加一份指纹表换重复段落;代价是热层按并集估,启动门禁比默认类型严 |
| 多机还想用邻居的指纹目录 | 上套再加 `--coordinator-url` 和 `--coordinator-event-reporting`;超时默认 1 秒 | 用舰队目录换本机表没有的段落;代价是不上报事件就仍只本地匹配,多一轮 HTTP |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 服务起不来,报非前缀引擎与传输不配 | 传输是不是只开了引擎驱动 | 改成缓存服务自己搬,或两条都装 |
| RAG 仍全量 prefill | 引擎类型是不是还停在默认 | 改成非前缀类型并重启服务 |
| 查找有指纹、取回报错 | 有没有先登记 RoPE | 引擎要在取回前发登记 |
| 命中段在,KV 却半截错 | 这一轮块表是否只盖住部分命中 | 散失败会整次重算,不要当静默成功 |
| 配了协调器仍只有本机命中 | 事件上报开了没有 | 只给地址不够 |
| `/status` 没有非前缀字段 | 是不是走了默认引擎类型 | 未开根本不装该模块 |
| 把进程内搅拌环境变量当推荐开关 | 是不是还在引擎进程里开遗留项 | 改独立服务的引擎类型;遗留页不对等展开 |

## 六、常见误区

- **以为非前缀复用是把命中块直接拼成一条 KV。** 因为听起来像「段落复用」。位置变了必须转 RoPE;缺口必须补算。当成零开销粘贴,生成会漂。
- **以为开一个布尔开关就行。** 推荐路径上它是另一种引擎类型,而且拒绝只开引擎驱动传输。当成普通开关,得到的是启动失败。
- **以为默认类型已经在做任意偏移匹配。** 默认组合器不挂非前缀模块。前缀查找全 miss 时,不会自动去翻指纹表。
- **以为进程内搅拌比例就是独立服务的默认。** 那组检查层、重算比例、分隔符是遗留路径的环境变量。独立服务这一页不靠它们装配模块。
- **以为配了协调器就会跨机指纹命中。** 目录是事件流堆起来的。不上报事件,客户端是空的,匹配仍本机。
- **以为外部前缀命中率为 0 就等于 CacheBlend 没干活。** 非前缀命中本来就不进那一行。看混合指标里的命中 token 和转位置块数。
