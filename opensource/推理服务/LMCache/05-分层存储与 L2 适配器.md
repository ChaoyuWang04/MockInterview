# 分层存储与 L2 适配器

这一页回答一件事:热层放不下或下次不在本机时,块怎么异步落到可插拔冷层,而查找入口不换。说法都在源码基准 `0cf5efc7`(tag `v0.5.5`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

引擎侧前缀缓存只活在当前 GPU、当前进程。换一条请求、换一个引擎进程、换一台机器,同一段长上下文都得再算一遍;**TTFT 回到全量 prefill**。

热层能挡住「下一步 decode 够得着」,挡不住「这份块还要活过这次作业」。热层满了,上一章那条环只丢掉、不下沉——不接冷层,长系统提示、多轮、同机多副本共享时,卡还在忙,命中却掉光。把盘、对象存储、别人的分布式池直接塞进查找路径,每换一种介质就换一套键算法,排障会变成「到底是没命中还是插件没装上」。

真问题不是「要不要第二层」,而是:**热层写完之后异步落下去,插件只换后面那一截,查找还是同一套。**

## 二、解法

热层写完成才唤醒落盘环。默认每个已配的冷层插件都收下同一批键,写完不删热层;也可以改成热层只当缓冲,冷层写成功立刻清热层。没配插件时这条环空转,数据只活在热层。

读的时候查找模块先问热层。未命中的键交给预取环:先在各插件上查并锁,再按策略挑谁把块搬回热层。默认多个插件都有时取下标最小的那个;同时在飞的预取默认最多 8 个。默认搬回热层后当临时块,读完可以清;另有一种策略会把预取块留在热层。

插件按启动时重复给出的规格现装,类型名对不上或依赖没装会在启动时报。工厂只换后面的读写实现:本机文件与块设备、远端对象与键值库、以及可以挂上 Mooncake Store 的那一种。查找键、分块、哈希仍是前面的章,不因换盘而换入口。

进程内那套分层存储官方标成遗留,和推荐路径不是同一份代码,不对等展开。

![热层写完才异步落冷层：查找模块先问热层，未命中交给预取；写完成唤醒落盘环，工厂按类型现装插件，未配冷层则虚线跳过](/opensource/LMCache/05a-l1-to-l2-async.svg)

为什么不吃亏:推理线程只跟热层打交道;落盘和预取在独立服务的后台环上跑。换介质是换插件,不是换查找。热层驱逐仍然只丢掉——冷层靠「写完再拷」,不是赶人时顺手泄下去。

冷层另有一条配额环,和热层那条不是同一件事。热层按盐值分名单时不传盐,水位一到会在后台炸掉;冷层这条环会按盐值看占用,对照配额。没登记配额的盐有效上限是 0,下一轮会整桶清掉,等于白名单。配额是软的:超了不拒写,大约 1 秒后的下一圈再赶。

## 三、代价

**冷层不是默认就有。** 启动不写插件规格,只有热层。引擎重启、换机之后,热层没了就得重算。

**落盘是异步的。** 热层写成功不等于冷层已经有。立刻杀进程,刚写入的块可能还在飞。默认还不删热层,两份各占一份容量。

**预取默认当临时块。** 下次同前缀再来,热层里未必还留着,又要问冷层。想留在热层要另选预取策略。

**按盐值隔离必须配配额。** 没登记的盐下一圈会被清光。热层那条环仍然不能选按盐值分名单。

**插件依赖是启动期的。** 类型名未注册、第三方库没装、必填字段缺,拒绝启动,不会运行时再降级成「只有热层」。

**进程内遗留路径不共用这份冷层。** 从嵌进引擎改成独立服务,旧进程里的盘缓存不会出现在新服务里。

## 四、和同类大厂框架不一样的地方

同类是「引擎外面的第二层 KV」。对照只放 Mooncake(月之暗面 Kimi 线上用)和 FlexKV(腾讯云)。vLLM、SGLang、HiCache、传输库、存储后端不进对等列。

| 维度 | Mooncake | FlexKV | LMCache |
|---|---|---|---|
| 第二层首先解决哪件事 | 自己就是集群里的那口池,预填充到译码要靠它搬 | 显存不够时把容量伸到主机、盘和远端 | 热层写完异步落到可插拔冷层,换请求、换进程、换机器还能命中 |
| 插件换什么 | 池本身就是产品 | 公开材料强调容量延伸的后端 | 只换冷层读写;查找、分块、哈希不换 |
| 满了怎么腾 | 池自己的分层与淘汰 | 往下层伸 | 热层环只丢掉;冷层另开水位或按盐值配额环 |
| 和 Mooncake 的关系 | 自己就是那口池 | 远端可挂 Mooncake 的存储 | 冷层适配器之一可以挂 Mooncake Store,不是本章主体 |

重心在 LMCache 这一列。Mooncake 与 FlexKV 只核公开说过的定位,实现细节留给它们自己的页面。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。冷层插件和落盘、预取策略都在缓存服务进程上;热层必填项见第 01、04 章,改完必须整份服务重拉。配额接口是运行时,改了大约 1 秒后的下一圈驱逐才生效。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--l2-adapter` · 一条冷层插件规格,JSON,可重复 | 启动 | 空列表,没有冷层 | 每加一条就多一个插件,顺序即下标;缺 `type` 或 JSON 非法则启动失败 | 启动报错;探活 `/status` 里存储状态 |
| JSON 里的 `type` · 插件类型名 | 启动,写在 `--l2-adapter` 里 | 无,必填 | 未注册或依赖没装:启动失败。内置包括 `fs`、`fs_native`、`raw_block`、`s3`、`valkey`、`mooncake_store` 等 | 启动日志 |
| `fs` 的 `base_path` · 文件冷层目录 | 同上 | 无,必填(非空字符串) | 目录写满则落盘失败,热层仍在 | 盘占用;落盘失败日志 |
| JSON 的 `shared` · 是否多实例共享同一存储域 | 同上 | `false` | `true`:协调器按类型名认池,同类型全舰队只应有一个池 | 协调器侧放置 |
| JSON 的 `eviction` · 打开该插件的冷层驱逐 | 同上 | 缺省则该插件不赶 | 要 `eviction_policy`:`LRU` / `IsolatedLRU` / `noop`;水位默认 `0.8`,比例默认 `0.2`。`LRU` 还要求插件报得出总容量,否则跳过装配 | `/status` 里冷层驱逐控制器;日志 `L2 usage … above watermark` |
| `--l2-store-policy` · 写完热层后往哪拷、要不要清热层 | 启动 | `default` | `default`:所有插件都写,不删热层;`skip_l1`:都写,成功后删热层(热层当缓冲) | 热层占用是否在落盘后下降 |
| `--l2-prefetch-policy` · 多插件都命中时谁搬回来、搬回热层是否留下 | 启动 | `default` | `default`:下标最小的插件搬,热层当临时;`retain`:同样选下标最小,但留在热层 | 热层命中是否在预取后稳住 |
| `--l2-prefetch-max-in-flight` · 同时在飞的预取个数 | 启动 | `8` | 调大:冷层并行升,热层瞬时写入升;调小:长 miss 排队 | 预取积压 |
| `--periodic-notifier-interval-ms` · 周期唤醒间隔 | 启动 | `5` | 影响后台事件心跳,不是冷层容量 | 启动参数本身 |
| 探活口 `PUT /quota/{cache_salt}` · 给某个盐登记配额,吉字节 | 运行时 | 没登记则有效上限 0 | 软限制:不拒写,下一圈按盐值赶;`_default` 表示空盐 | `GET /quota`;日志 `cache_salt=… over quota` |

**怎么看。** 先确认缓存服务还在,热层两项必填已经有(第 01、04 章)。探活 `/status` 看存储与冷层驱逐(策略、水位、占用、盐值桶个数;不展开每个盐)。指标 `lmcache_mp.l2_usage_bytes` 按插件类型名打点。配额用 `GET /quota`。落盘跟不上时,热层占用贴水位而冷层占用不涨。`IsolatedLRU` 却从未 `PUT` 过配额,下一圈会把未登记的盐清光。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。热层必填仍要带上。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机在线,系统提示跨请求复用,冷层用本机盘 | `lmcache server --l1-size-gb 20 --eviction-policy LRU --l2-adapter '{"type":"fs","base_path":"/mnt/nvme/l2"}'` | 用盘上的第二份换引擎重启后少做 prefill;代价是多一份盘占用,默认热层也不删 |
| 热层只当写缓冲,冷层才是正本 | 同上,加 `--l2-store-policy skip_l1 --eviction-policy noop` | 用关掉热层赶块、写完即清热层换名单开销;代价是读必须预取,预取默认还不把块留在热层,跨请求热命中要再加 `--l2-prefetch-policy retain` |
| 多租户按盐值隔离容量 | `--l2-adapter` 的 JSON 里加 `"eviction":{"eviction_policy":"IsolatedLRU"}`,再 `PUT /quota/<盐>` | 用白名单配额换租户互挤;代价是没登记的盐下一圈被清光,热层策略仍须是 `LRU` 不能跟冷层一样选 `IsolatedLRU` |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 起不来,JSON 报错或未知类型 | `--l2-adapter` 是不是对象、有没有 `type` | 补字段;依赖没装要先装,不会降级 |
| 服务很健康,换进程命中全没 | 有没有配 `--l2-adapter`;落盘是否已完成 | 没插件就只有热层;刚写入可能还在飞 |
| 冷层有块,热层命中仍掉 | 预取策略是不是 `default`(临时块) | 跨请求要留热层就改 `retain` |
| 选了 `IsolatedLRU` 数据第二天没了 | 该盐有没有配额 | 没登记等于上限 0;先 `PUT /quota` |
| 热层选了 `IsolatedLRU` 水位一到崩 | 是不是热层环(第 04 章) | 热层改回 `LRU`;按盐值只给冷层 |
| 配了 `LRU` 冷层却从不赶 | 插件有没有报总容量 | 没容量会跳过装配;看启动告警 |
| 从进程内改独立服务,盘上旧文件不命中 | 是不是两套存储代码 | 遗留路径不共用;不要指望自动迁 |

## 六、常见误区

- **以为热层一赶就会写到冷层。** 因为分层听起来像「满了往下挤」。热层环只丢掉;冷层靠写完成之后的那条拷贝环。没配插件时,赶掉就是没了。
- **以为配了盘,查找就改成「先盘后内存」。** 查找入口不变,先热层,未命中才预取。插件只换后面。
- **以为默认预取会把冷块养在热层里。** 默认当临时块。系统提示天天复用却看着命中不稳,先看是不是每次预取完又清了。
- **以为 `IsolatedLRU` 在热层、冷层是同一个开关。** 启动器两边都能填这个词,热层环不传盐,水位触发会炸;冷层环会传盐,但没配额等于清空。
- **以为配额会在写入时拒绝。** 软限制,超了先写下,下一圈再赶。看写入成功就以为容量还够,会误判。
- **以为 Mooncake 列是在讲 Mooncake 自己怎么分层。** 本仓只是冷层可以挂它的 Store。池内部怎么淘汰,等 Mooncake 自己的解读。
- **以为进程内磁盘缓存和独立服务的文件插件是同一份。** 官方把进程内存储标成遗留。换部署等于换账本。
