# SERDE 与 CacheGen

这一页回答一件事:块进冷层之前能不能换形状,以及那种有损压缩在推荐路径上有没有落地。说法都在源码基准 `0cf5efc7`(tag `v0.5.5`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

热层里的块按引擎那份精度躺着。落到盘或远端时若原样搬,坏的是 **TTFT**:带宽和落盘时间把命中省下的 prefill 吃回去。

长系统提示、多轮、冷层在对象存储或跨机池上时,这份账最明显。插件只换后面的读写,不负责把字节变瘦或锁上——第 05 章那条落盘环照样把满精度送出去。把加密当成默认、把量化当成无损,排障时会把精度损失和「没配变换」搅在一起。

真问题不是「冷层会不会存」,而是:**进某一个插件之前,要不要按这个插件自己的规格做变换;没写规格就当这层不存在。**

## 二、解法

变换挂在单条冷层插件上,不是挂在整份服务上。启动时插件规格里可以带一份变换子字典;存储管理器造好插件之后,有子字典才包一层包装器。控制器仍看见普通插件:查找、上锁不进变换;写入先变再交给里面的插件,读回先解开再进热层。另一条插件可以完全不带这份字典。

省略子字典时,包装器不会装、线程池不会起、也不多占一份临时缓冲。官方口径是:省略则如同不存在。

内置几种变换按名字进工厂:一种按元素做有损量化;一种按预设压 KV 张量;一种在落盘前做带认证的加密,密钥按盐派生。量化不是无损。加密不是默认开。工厂里没注册的名字启动失败,不会静默改成原样落盘。

有一种按头维度非对称编码的实现,以及一套只产出字节流的编码层,当前没有挂进推荐路径的工厂名单,正文不当成可抄的开关。

CacheGen 是另一条线。多进程文档写明:推荐路径上尚未实现。进程内遗留存储里仍有一份编解码,和本章的适配器包装器不是同一条调用链。不要把论文或遗留路径画进独立服务的热路径。

![热层块进冷层：一条插件可先做可选变换再落盘，另一条插件不经过变换盒；CacheGen 标成未实现或遗留，没有实线进入推荐路径](/opensource/LMCache/09a-serde-before-l2.svg)

为什么不吃亏:推理线程仍只跟热层打交道;变换在独立服务里、包在某一个插件外面。盘和远端可以各用各的规格,不必为了加密把本机文件也加密一遍。

## 三、代价

**变换是按插件选择加入的。** 不写子字典,冷层仍按满精度走,带宽和盘占用不会自己变小。

**有损量化会丢掉精度。** 读回热层的不是原来那份浮点。把量化当成压缩开关打开,坏的是生成质量,不是「存得更慢一点」。

**加密只罩冷层。** 热层仍是明文。主密钥在服务进程里,能读这份密钥的人仍能解开所有盐派生出来的数据,不是租户之间的隔离。

**一批里一步失败,整批算失败。** 变、存、载、解任何一步出错,不会只成功一半。失败的键会清掉。

**多一份临时缓冲和一组工作线程。** 线程数默认 1。纯 Python 的变换加线程帮不上;会放 GIL 的算子才值得加。

**CacheGen 在推荐路径上不能当功能用。** 按多进程文档去配,配不出一条已实现的调用链。

## 四、和同类大厂框架不一样的地方

同类仍是引擎外的 KV 层。对等列只有 Mooncake(Kimi 线上)与 FlexKV(腾讯云)。传输库不进表。另两列有没有压缩、加密,本页核不动就不写那一格。

| 维度 | Mooncake | FlexKV | LMCache |
|---|---|---|---|
| 首先解决哪件事 | 预填充和译码拆开之后,KV 怎么在集群里搬、怎么进分布式池 | 引擎显存不够时,怎么把容量伸到主机内存、盘和远端 | 进某一个冷层插件之前,要不要把块变瘦或锁上 |
| 变换挂在哪 | 自己就是那口池 | 容量往下层伸 | 包在单条插件外面;另一条可以不包 |
| 省略时像什么 | 池本身仍在 | 下层仍在 | 和没这层变换一样:不多分配、不多线程 |
| CacheGen 这类有损流式压缩 | 本页不写实现 | 本页不写实现 | 多进程文档标明尚未实现;进程内遗留另有一份,不对等展开 |

重心在 LMCache 这一列。另两列只核公开说过的定位。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。变换写在第 05 章那条 `--l2-adapter` JSON 的 `serde` 子字典里,改的是缓存服务进程;热层必填项仍见第 01、04 章。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--l2-adapter` JSON 里的 `serde` · 本条插件的变换规格 | 启动,嵌在 `--l2-adapter` 里 | 省略则本条不变换 | 有子字典才包包装器;必须是对象且含 `type` | 探活 `/status` 里该插件是否带 `serde_wrapped` |
| `serde.type` · 工厂注册名 | 同上 | 无,必填(写了 `serde` 时) | 未注册则启动失败。本基准注册了 `fp8`、`turboquant`、`aesgcm` | 启动报错 `Unknown serde type` |
| `fp8` 的 `fp8_dtype` · 量化到哪种 8-bit 浮点 | 同上 | `float8_e4m3fn`;也可 `float8_e5m2` | 有损;元素字节大约减半(相对 16-bit) | 生成质量;冷层占用 |
| `fp8` / `turboquant` / `aesgcm` 的 `max_workers` · 变换线程池 | 同上 | `1` | 调大:会放 GIL 的算子并行升,CPU 升;纯 Python 几乎无益 | 线程名 |
| `turboquant` 的 `preset` · 压缩预设 | 同上 | `turboquant_k8v4` | 另有 `turboquant_4bit_nc`、`turboquant_k3v4_nc`、`turboquant_3bit_nc`;都是有损 | 冷层占用;质量 |
| `turboquant` 的 `head_dim` / `block_size` | 同上 | `128` / `16` | 须与模型头维、分块对上,对不上会编解码失败 | 落盘/预取失败日志 |
| `turboquant` 的 `skip_first_layers` / `skip_last_layers` | 同上 | `2` / `2` | 头尾若干层原样存放,中间层按预设压 | 冷层占用 |
| `aesgcm` 的 `key_provider` | 同上 | `hkdf`;`keyring` 尚未实现 | 不是 `hkdf` 则启动失败 | 启动报错 |
| `aesgcm` 的 `master_key_path` | 同上 | 无,`hkdf` 时必填 | 启动时读一次;空路径拒绝启动。主密钥不写入冷层 | 缺文件则 `OSError` |
| `aesgcm` 的 `aes_bits` | 同上 | `128`;可为 `256` | 只影响密钥长度,不改变「热层仍明文」 | 启动参数本身 |

**怎么看。** 先确认第 05 章的插件已经起来。探活 `/status` 里被包过的插件会多一个 `serde_wrapped: true`;没写 `serde` 的插件没有这个字段,不要当成坏了。未知 `type` 在启动期抛错,不会先空转再降级。量化打开后先看生成是否发糊,再看冷层占用;加密打开后热层占用不会变小。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。热层必填和第 05 章的 `--l2-adapter` 仍要带上。`serde.type` 只使用工厂里注册过的名。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 本机盘做冷层,带宽和盘占用要紧,能接受有损 | `lmcache server --l1-size-gb 20 --eviction-policy LRU --l2-adapter '{"type":"fs","base_path":"/mnt/nvme/l2","serde":{"type":"fp8"}}'` | 用大约一半的冷层字节换精度;热层仍是原精度 |
| 远端对象存储,只要落盘加密,本机文件不加密 | 两条 `--l2-adapter`:一条 `fs` 不带 `serde`;一条 `s3` 的 JSON 里 `"serde":{"type":"aesgcm","key_provider":"hkdf","master_key_path":"/etc/lmcache/keys/master"}` | 用冷层密文换主密钥与进程内明文;不是租户隔离 |
| 更狠的有损压缩,冷层仍是本机盘 | 同一条 `fs` 插件改 `"serde":{"type":"turboquant","preset":"turboquant_k8v4"}` | 用更小的冷层换更多质量损失;头尾默认各留 2 层不压 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 起不来,报未知变换类型 | `serde.type` 是不是 `fp8` / `turboquant` / `aesgcm` | 不要写 CacheGen 的名字;工厂没注册就不会装 |
| 起不来,报缺少主密钥路径 | `aesgcm` 有没有 `master_key_path` | `hkdf` 没有默认文件 |
| 服务很健康,盘占用仍按满精度涨 | 该条 `--l2-adapter` 有没有 `serde` | 省略则不变换;不要去改另一条没包的插件 |
| 打开量化后回答发糊 | 是不是把有损当成无损 | 先关掉量化对照质量,再考虑换预设 |
| 配了加密,热层 dump 仍能读出 KV | 加密是否只包冷层 | 预期如此;热层明文 |
| 按文档去找 CacheGen 开关,独立服务没有 | 是不是在看多进程文档里的 coming soon | 推荐路径未实现;不要去进程内遗留里抄调用链 |

## 六、常见误区

- **以为 CacheGen 已经在独立服务里落地。** 因为文档目录里有这一页。那一页写的是尚未实现;进程内遗留里的编解码不会被适配器包装器调用。
- **以为加密默认开。** 因为「落盘」听起来应当锁上。省略 `serde` 就是原样字节;加密要写 `aesgcm` 和主密钥路径。
- **以为 8-bit 量化是无损压缩。** 因为体积正好大约减半。代码按元素有损转换,读回来精度已经丢了。
- **以为变换是整份服务一份。** 因为冷层插件可以有多条。包装器按条包;一条量化、一条不包,是合法组合。
- **以为没写子字典也会起变换线程。** 官方写明省略则如同不存在。去数线程却数到变换池,先看是不是其实写了子字典。
- **以为编码层里的非对称方案可以当 `serde.type` 填。** 那份代码没有注册进工厂。填了就是未知类型,启动失败。
- **以为查找也会走变换。** 包装器把查找直接交给里面的插件,不经过序列化线程。
