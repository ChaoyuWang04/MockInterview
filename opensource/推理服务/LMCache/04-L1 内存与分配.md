# L1 内存与分配

这一页回答一件事:热块放在哪一块 GPU 能快速碰到的区域,这块区域满了或碎了时谁被赶走。说法都在源码基准 `0cf5efc7`(tag `v0.5.5`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

引擎下一步 decode 要的是已经算过的 KV 块。这些块若还散在普通可换页的主机堆里,或者热层根本没预留够,GPU 每次都要等一次慢拷贝;**TTFT 和 decode 间隔一起抖**。

两种坏法最常见。一种是热层开小了:命中刚攒起来就被挤掉,长上下文、多轮、同机多副本共享时,卡还在忙,命中率却掉回全量 prefill。另一种是总容量看着够,空闲却碎成许多不够长的洞:新块切不进去,引擎侧拷贝线程堵在「内存不够」,推理被拖住。

真问题不是「主机内存有没有」,而是:**要有一块 GPU 能直接碰到的连续热区,并且满了能按规矩腾位置,而不是把碎片留给下一次写入。**

## 二、解法

先钉住一块主机内存当热层。默认不一次钉满上限:先钉一块能开工的,后台按 64 兆字节一块往上钉,每凑满约 1 吉字节才把地址空间往外扩。平台钉不住时,启动会自动关掉这种懒增长,改成一次钉满。对齐默认 4 千字节。

对象账和切空位是两件事。账上先给键占写锁,再向空闲表要一整批同样大小的块;切不到,这一批全部标失败并回滚,不会留下半截。空闲表从左往右找第一块够大的洞,释放时相邻的洞并回去。读的时候加读锁;读锁或写锁还在的键,后台不许赶。写锁默认 600 秒过期,读锁默认 300 秒。

热层介质三选一,互斥:钉住的主机内存、GDS 板、Device-DAX。开 GDS 就关掉钉住内存;开 Device-DAX 就关掉纯 CPU 热层。点对点要的是一整块可登记内存,跟后两种形状合不来——谁去协调邻居是后面的章,这里只记热层形状这一条。

赶块是另一条后台环,每秒看一次占用比。不到水位就空转;到了,按策略挑最旧的,丢掉大约两成已分配。丢掉就是丢掉,不在这条环上泄到冷层。热层这条环不带盐值:按盐值分名单的那一种要盐值才能挑人,热层环直接传空,水位一到会在后台线程里炸掉。热层当真当缓存时用全局最旧;什么都不赶是给「热层只当写缓冲、冷层写完自己清」用的。

![热层是一块钉住的板:引擎 GPU 拷进独立服务里三选一的热层,空闲表按对齐做首次适配;对象账先占锁再切空位;驱逐环每秒看占用,水位不到则虚线空转,到了才丢掉约两成已分配](/opensource/LMCache/04a-l1-slab-eviction.svg)

为什么不吃亏:GPU 碰到的是钉住的连续区,不是随用随 malloc 的碎页;驱逐在独立进程的后台环上跑,不跟推理抢同一条 Python 线程。懒增长让启动不必先把上限一次钉满,但水位用的分母是已经提交的堆,不是配置上限。

## 三、代价

**热层大小和驱逐策略没有默认值。** 少一项启动器直接拒绝。开小了命中被赶走,开大了和引擎抢主机内存。

**水位用的是当前堆,不是配置上限。** 懒增长还没钉满时,分母偏小,会提前开始赶块;把探活里的占用当成「离上限还很远」会误判。

**切空位是整批成败。** 总空闲够、最大洞不够,新键全部失败。锁还在的键赶不走,表面上有容量,写入仍失败。

**GDS 板和 Device-DAX 跟钉住内存互斥。** 后两种不是一整块可登记内存。Device-DAX 还要求关掉懒增长,共享内存名也要空。

**什么都不赶时,满了就写不进。** 它不为你腾位置;只有上游保证热层只是短暂缓冲时才合理。

## 四、和同类大厂框架不一样的地方

同类是「引擎外面的 KV 热层」。对列是 Mooncake(Kimi 线上)与 FlexKV(腾讯云)。vLLM、SGLang、HiCache 不进对等列。

| 维度 | Mooncake | FlexKV | LMCache |
|---|---|---|---|
| 热数据默认在哪 | 集群里的分布式池,主机内存和盘分层 | 本机主机内存,下面再接盘和远端 | 本机独立进程里一块钉住的热层,冷层另接 |
| 满了怎么腾 | 池自己的分层与淘汰 | 往下层伸容量 | 后台水位环按策略丢掉热块,不在这里泄冷层 |
| GPU 怎么碰到热区 | 走它自己的传输引擎 | 公开材料强调容量延伸 | 钉住内存给 DMA;也可整层换成 GDS 板或 Device-DAX |
| 和点对点的形状 | 自己就是那口池 | 公开材料不把整段登记当招牌 | 只有钉住的那一整块能登记;GDS 与 Device-DAX 直接拒绝点对点 |

重心在 LMCache 这一列。Mooncake 与 FlexKV 只核公开定位,实现细节留给它们自己的解读。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。热层大小、介质和驱逐策略都在缓存服务进程上,改完必须整份服务重拉,引擎连器跟着重启才看得到新容量。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--l1-size-gb` · 热层上限,吉字节 | 启动 | 无,必填 | 调大:能留的热块多,主机内存被占;调小:更早被赶,TTFT 回到全量 prefill。GDS 开着时这一项改成板的大小 | 探活 `/status`;指标 `lmcache_mp.l1_memory_usage_bytes` |
| `--eviction-policy` · 满了怎么赶 | 启动 | 无,必填;`LRU` / `IsolatedLRU` / `noop` | `LRU`:热层环能跑的全局最旧;`IsolatedLRU`:要盐值,热层环不传盐,水位触发会在后台抛错;`noop`:不赶,满了写不进 | `/status` 里驱逐控制器的 `eviction_policy` |
| `--eviction-trigger-watermark` · 触发水位 | 启动 | `0.8` | 调低:更早赶,命中更容易掉;调高:更晚赶,更容易切空位失败 | 日志 `L1 memory usage … above watermark` |
| `--eviction-ratio` · 一次丢掉多少已分配 | 启动 | `0.2` | 调大:一次腾得空,可能误伤热块;调小:可能连续多轮都腾不够 | 同上;指标 `lmcache_mp.l1_usage_ratio` |
| `--l1-use-lazy` · 要不要后台慢慢钉 | 启动 | 开 | `--no-l1-use-lazy`:启动一次钉满,共享内存传输才可能启用。Device-DAX 必须关懒增长 | 启动日志 `use lazy memory allocator` |
| `--l1-init-size-gb` · 懒增长一开始钉多少 | 启动 | `20` | 实际取值不超过 `--l1-size-gb`。开太小:早期水位分母小,提前赶 | 日志 `LazyMemoryAllocator: Expanded …` |
| `--l1-align-bytes` · 切块对齐 | 启动 | `4096` | 必须是正的二的幂;GDS 直通也要 4 千字节 | 启动参数本身 |
| `--l1-write-ttl-seconds` · 写锁多久过期 | 启动 | `600` | 调短:卡住的写入更快腾;调长:坏写入占着不让赶 | 对象账行为;锁过期后键可删 |
| `--l1-read-ttl-seconds` · 读锁多久过期 | 启动 | `300` | 调短:取回卡住时更快可赶;调长:热块更难被误赶 | 同上 |
| `--gds-l1-path` · 把热层换成 GDS 板 | 启动 | 关 | 钉住内存关掉; `--l1-size-gb` 变成板大小;点对点启动失败 | 日志 `GDS L1 tier enabled` |
| `--gds-l1-backend` · 哪一种 GDS | 启动 | `auto` | `cufile` / `hipfile` / `ugds` / `phx`;`auto` 在 CUDA 上选 cuFile、ROCm 上选 hipFile | 启动日志 |
| `--gds-l1-use-direct-io` · 板文件是否直通 | 启动 | 开 | 关了可能丢掉 DMA 快路径 | 启动参数 |
| `--l1-devdax-path` · 热层换成 Device-DAX | 启动 | 关 | 必须 `--no-l1-use-lazy` 且 `--shm-name ""`;点对点启动失败 | 日志 `Device-DAX L1 tier enabled` |

**怎么看。** 先看缓存服务还在。探活 `/status` 里有存储状态和驱逐控制器(策略名、水位、比例、线程是否活着)。指标口上的 `lmcache_mp.l1_memory_usage_bytes` 和 `lmcache_mp.l1_usage_ratio` 是当前占用,懒增长时分母是已提交的堆。打开额外日志后,驱逐环会按间隔打 `L1 memory usage: x/y GiB`。写入失败先看是水位没赶,还是空闲表没有够大的洞,还是键还锁着。`POST /cache/clear` 清的是热层里没锁的对象,锁着的会留下。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机在线,长上下文或多轮 | `lmcache server --l1-size-gb 32 --eviction-policy LRU` | 用一块钉住的热层换少做 prefill;代价是 32 吉字节主机内存,短请求上多一趟本机往返 |
| 要 DMA 直通盘、热层换成板 | `lmcache server --l1-size-gb 20 --eviction-policy LRU --gds-l1-path /mnt/nvme/l1` | 用 GDS 板换钉住内存;代价是点对点起不来,也没有主机侧那一整块可登记区 |
| 热层只当写冷层前的缓冲 | `--l1-size-gb 8 --eviction-policy noop`,并确认冷层写完会清热层 | 用关掉赶块换少维护名单;代价是清不及时就写不进 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 起不来,缺热层大小或驱逐策略 | 启动命令两项必填都有没有 | 补上,没有默认值 |
| 起得来但命中很快掉光 | `/status` 占用是不是长期贴着水位;策略是不是 `noop` | 加大 `--l1-size-gb`,或不要用 `noop` 当缓存 |
| 占用远低于上限却报内存不够 | 空闲是否碎了;懒增长堆是不是还很小 | 看 `l1_usage_ratio` 的分母;考虑清一次或等后台钉完 |
| 打开点对点直接退出 | 是不是开了 `--gds-l1-path` 或 `--l1-devdax-path` | 热层改回钉住内存;点对点协调本身看后面的章 |
| Device-DAX 起不来 | 有没有 `--no-l1-use-lazy` 和空的 `--shm-name` | 两项都要,不是运行时再降级 |
| 选了 `IsolatedLRU` 后水位一到服务异常 | 热层环有没有把盐值传进去 | 热层改回 `LRU`;按盐值隔离是冷层配额那条路 |
| 指标里占用不涨、写入全失败 | 驱逐线程 `thread_alive`;键是不是一直锁着 | 看 TTL;锁过期前后台赶不走 |

## 六、常见误区

- **以为示例里的 20 吉字节是热层默认值。** 那是文档示例,也是懒增长的初始钉住大小,不是 `--l1-size-gb` 的默认。少写这一项,启动器拒绝。
- **以为水位 0.8 是相对配置上限。** 分母是空闲表当前的堆。懒增长还没钉满时,20 吉字节的上限也可能在只钉了初始那段时就开始赶。
- **以为热层一赶就会写到冷层。** 热层这条环只丢掉。冷层怎么接是下一章;把驱逐目的地当成下沉,会在冷层空着时误以为数据还在。
- **以为总空闲够就一定写得进。** 空闲表要连续且对齐。碎洞加锁着的键,容量数字好看,新块仍然失败。
- **以为 GDS 板是钉住内存下面再加一层。** 三选一。开了板,钉住内存那条分配器根本不会建。
- **以为点对点只是多一个广告地址。** 热层必须是一整块可登记内存。板和 Device-DAX 在推荐入口直接拒绝,不是运行时降级。
- **以为 `noop` 表示「永不丢数据」。** 它表示「后台不赶」。满了就写不进;数据还在不在,取决于有没有别人把热层清掉。
- **以为热层选 `IsolatedLRU` 就能按租户赶。** 启动器允许这个取值,但热层驱逐环调用时不传盐值,实现里盐值为空直接抛错。按盐值分名单是给带配额的冷层环用的。
