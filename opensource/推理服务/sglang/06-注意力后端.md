# SGLang 06|注意力后端

attention 为什么没有一份能通吃所有硬件和模型的 kernel、抽象层该切在哪、MLA 为什么要另起接口,vLLM 解读的「注意力后端」一章已经讲透。这一页只说 SGLang 遇到的问题、它的解法、代价、以及和 vLLM 不一样的地方。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、核心问题

kernel 多不是问题,vLLM 那边也一样多。SGLang 这边真正坏的是:**选中之后没有第二次机会**。

命令行上有 24 个后端名字(注册表里 23 个,另外 2 个是指向已有后端的废弃别名)。每个名字背后是一组硬约束——这张卡行不行、模型是普通多头注意力还是把 KV 压成一个向量的那类、KV 用什么精度、页多大、开没开推测解码、要不要逐 token 可复现。这些约束没有一个地方统一声明,而整个选择只在启动时做一次,之后运行期再没有任何接口能换。

选错的后果分三档,难受程度正好倒过来:

- **起不来。** 卡代不对、模型结构不对、和推测解码冲突,启动时直接抛错。这一档最好,因为它说话。
- **起来了,但别的东西被悄悄改了。** 要求整页搬运的后端会把页大小改写成 32、64 或 128,前缀命中因此退到页边界(03 章);精度不匹配时后端本身被静默换成另一个。两者都只打一行日志。
- **起来了,什么都没改,就是慢。** Hopper 上手动指定某个后端会比默认慢,因为这个基准上它有一处已知的 kernel 回归;开了 FP8 KV 但后端不做融合反量化,槽数翻倍、TPOT 反而变长(12 章)。

后两档不报错,所以排障时最容易被跳过。

## 二、解法:一次性的名字解析

最天然的直觉:每个后端一个类,类里同时有 prefill 和 decode 两套 kernel;启动时按卡、模型结构、页大小、推测解码挑一个,之后不再换。SGLang 就是这么做的,而且比这更彻底——**整条选择链处理的自始至终只是字符串**,决策树吐出一个名字,一串修正函数可能把它改成另一个名字,直到最后一步才拿名字去字典里换一个类。

![从启动参数到运行时真正被调用的那个后端实例,一共四道工序:三个入口字段进来,空的就走决策树吐一个名字,名字接着串行经过五道修正(改写页大小、精度不匹配换后端、只会 decode 的补一个 prefill 侧、平台缺指令集退回软件实现、确定性模式限定名字),每道修正只打一行日志不报错,最后名字进工厂函数才做唯一一次断言;产物是一层套一层的结构,最外层是混合与稀疏模型的包装层,中间是 prefill 与 decode 不同时才有的分发器,里面才是两个真正的后端实例](/opensource/sglang/06a-name-to-backend.svg)

**入口有三个**:一个底,两个分阶段覆盖。覆盖为空就继承底;两个覆盖填了同一个名字,就直接把它当成底。

**没指定时走一棵决策树**,不是优先级表。树按卡代与 CUDA 版本、模型是不是把 KV 压成一个向量的那类、推测解码的草稿宽度与页大小、模型有没有 attention sink 分叉,落到一个名字上就返回。没有候选列表,也就没有「下一个」。开确定性推理时换另一棵树,并把可选的名字限定在一小撮里。个别模型在这棵树之前就把名字定死,压根不走树。

**选出来的名字要过一串修正**:要求整页搬运的后端改写页大小;KV 精度不匹配的静默换一个后端;只会 decode 的自动补一个 prefill 侧;平台缺指令集的退回软件实现;确定性模式再限定一次,不在允许集里的连前缀缓存一起关掉。这几道是串行的,后一道看到的是前一道改过的值,每道只打一行日志。

**最后名字才变成实例。** 这一步的工厂函数当场断言卡代、模型结构、和推测解码冲不冲突,不满足就抛错。**这是整条路上唯一一次校验,而且发生在构造时,不在选择时**——所以「这个组合行不行」这个问题,在启动完成之前没有任何地方能回答。

两阶段的名字不同就再套一层分发器:decode 与空转交给 decode 那个,推测解码的 verify 按一个开关决定归哪边(默认归 prefill 侧),其余交给 prefill 那个。混合模型与稀疏模型在这之外还要再包一层:线性层、短卷积层、稀疏层走自己的 kernel,选出来的全注意力后端只是这层包装的一个成员。纯状态空间模型连这套都不走,直接用自己的后端。

**基类只有两件事。** 一是把每一层的调用按这一步的模式转到 decode 那套 kernel 还是 extend 那套。二是每次前向开头把这批请求在槽位表里的行整理成 kernel 要的形状——后端之间差别最大的其实是这个,不是 kernel 本身:有的要一张按页折算过的页表,有的要一条拼平的槽号列表加一份前缀和,还要按序列长度和 SM 数当场算每条请求的 KV 切几份并行。

CUDA graph 把第二件事劈成两半:能录进图的静态形状 GPU 操作一半,读主机值、分配动态形状的另一半。启动时按最大批和最大上下文把所有缓冲一次买断,之后每步重放只刷新图外那一半。这个两半的契约是当前基类的正式接口,旧的那对「捕获时调这个、重放时调那个」的方法已经从基类删掉了;图外那半本身也能被录成一张小图,但那是个默认关着的开关。

为什么实际不吃亏:选择只在启动时做一次,运行时零开销;元数据整理的形状和后端无关,换后端不用动调度器;每一道改写都有日志,理论上不会不知道自己在跑什么。

## 三、代价

- **没有能力矩阵,答案散在 9 个修正函数和 4 个处理器里。** 一个组合行不行,要么启动抛错,要么被改写后打一行日志,有的直到构造那一刻才知道。想在起服务之前先问一句「这套参数能不能跑」,没有地方可问。
- **页大小被改写就丢了 token 级命中。** 走整页 kernel 的 MLA 后端把页钉到 64,前缀命中从此只到 64 的倍数(03 章)。
- **确定性模式一路砍。** 可选后端先砍到 6 个,DeepSeek 一类的模型再砍到 4 个,剩下那 2 个能用但要把前缀缓存整个关掉。
- **后端私有缓冲吃显存,而且是启动时一次买断的。** Triton 后端的中间结果缓冲是最大 token 数乘头数乘最大份数乘 V 维、fp32;MLA 模型在某一代 AMD 卡上份数会按 SM 数算到 512、缓冲涨到约 4 GB,所以代码里硬钉在 256。FlashInfer 的工作区默认 384 MB,几个模型系列 512 MB,确定性模式 2 GB。就绪时显存比自己算的少 1–4 GB,多半是这两项。
- **有的后端关功能。** 两个纯软件后端关掉 CUDA graph,其中一个还不支持推测解码;某个 AMD 后端在上下文超过 8192 时把显存比例乘 0.85。
- **prefill 与 decode 用两个后端是实验功能。** 启动时除了那行选中日志,还会再打一行 warning 说这个特性不稳定。

## 四、和 vLLM 不一样的七处

![两边都必须做的三件事各占一行:第一行是拿到一组待选的 kernel,vLLM 是一张按硬件与精度当场算出的优先级表因此有好几个候选框,SGLang 是一棵决策树只吐一个框;第二行是判断能不能跑当前的卡与模型,vLLM 每个后端自带一个准入校验方法并在循环里被逐个调用,SGLang 这一格是空的虚线框因为全树没有这样的方法;第三行是跑不了时怎么办,vLLM 淘汰当前候选并有一条回到第一行的箭头形成闭环、原因只打在 debug 级,SGLang 只有被改写成另一个名字或构造时抛错两条出口、没有回头箭头](/opensource/sglang/06b-vllm-diff-selection.svg)

1. **怎么选。** vLLM 是候选优先级表加逐个准入校验,不行就试下一个,淘汰原因打 debug 日志。SGLang 是一棵决策树返回一个名字,没有候选循环,后端身上也没有「我能不能跑」这类方法;显式指定就是它,不行要么抛错要么被改写。
2. **prefill 和 decode 可以是两个后端。** vLLM 一个后端两个阶段都管。SGLang 有三个字段,不同时套一层分发器按模式转发,推测解码的 verify 归哪边另有一个开关。
3. **元数据谁整理。** vLLM 的构造器是独立对象,每步把调度输出翻译成 kernel 参数。SGLang 由后端自己在每次前向开头整理,CUDA graph 下拆成图外刷新和图内录制两段,基类给了默认实现。
4. **页大小谁说了算。** vLLM 一直是 16。SGLang 默认 1,后端要求就改成 32、64 或 128,只打一行日志(03 章)。
5. **混合模型怎么接。** vLLM 的状态空间类住在另一个枚举里,连参与选择的资格都没有。SGLang 把它们做成包装层套在选出的全注意力后端外面,线性层的 kernel 由另一族参数单独定,而且在某些 Blackwell 卡上还反过来限定外面那个全注意力后端只能是 3 个之一。
6. **稀疏注意力是一等后端。** vLLM 的稀疏 MLA 变体登记在同一张注册表里,但由模型层钦定、不参与优先级竞争。SGLang 这边它是一个正常的后端名,内部再按卡代和 KV 精度选 prefill 与 decode 两个子实现——换一下 KV 精度就换了一整套 kernel。
7. **草稿模型另有一套。** 推测解码的草稿模型只允许 7 个后端,不在名单里就退回一个默认值并打警告;目标模型不受影响。vLLM 的草稿模型和目标模型走同一套选择。

两边的参数名都在下一节。

## 五、调参与观测

**参数在哪调。** 这一页的参数全是启动参数,改了要重启;后端内部的阈值是环境变量,也要重启。运行时没有能换后端的接口,`/set_internal_state` 只放行 5 个和这里无关的字段。`/server_info` 返回的是解析完成之后的值,所以 `attention_backend`、`prefill_attention_backend`、`decode_attention_backend`、`page_size` 这四项读回来就是实际生效值,不用去对启动命令。

| 参数 · 一句话说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |

| `torch_native` | MHA | 模拟 | 是 | 是 | 否 | 否 | 否 |
| `flex_attention` | MHA | 模拟 | 否 | 是 | 否 | 否 | 否 |
| `hpc_ops` | MHA | 强制 64 | 是 | 否 | 否 | 否 | 否 |
| `aiter` | MHA | 任意 | 是 | 否 | 是 | 是 | 否 |
| `flashinfer` | MLA | 1 | 否 | 是 | 是 | 否 | 否 |
| `flashmla` | MLA | 强制 64 | 是 | 是 | 是 | 否 | 否 |

再补三条矩阵之外的:草稿宽度大于 1 且页大于 1 时,只有 `flashinfer`、`fa3`、`triton` 能跑;混合线性模型的全注意力层在 SM120 上只能是 `triton`、`trtllm_mha`、`flashinfer`,其他 Blackwell 上只能是 `triton`、`trtllm_mha`、`fa4`,昇腾上只能是 `ascend`;确定性推理只允许 `ascend`、`fa3`、`fa4`、`flashinfer`、`triton`、`intel_xpu`,其中后两者会被关掉前缀缓存,DeepSeek 一类的吸收式 MLA 模型更是只剩前 4 个。

**典型配置。** 三套起点,组合是按参数语义推的,不是实测最优。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| H100 / H200 上跑 Llama、Qwen 这类 MHA 模型,长 prompt 多、要 token 级前缀命中 | 三个后端字段都不给,页也不给(默认落到 `fa3` 加页 1) | 拿 kernel 性能换命中率:页为 1 时前缀能命中到单个 token,但整页搬运的 kernel 一个也用不上 |
| B200 上跑 DeepSeek V3 这类 MLA 模型,吞吐优先 | `--attention-backend trtllm_mla --page-size 64 --kv-cache-dtype fp8_e4m3` | 拿命中率换吞吐与显存:命中只到 64 的倍数,换来整页 kernel 和一半的 KV 占用 |
| 要逐 token 可复现(RL 打分、回归对拍) | `--enable-deterministic-inference --attention-backend fa3` | 拿吞吐换可复现:split 按固定 tile、allreduce 走树形且通道数被钉死;把 `fa3` 换成允许集里的另外两个名字,前缀缓存会被一起关掉 |

**怎么看。** 启动日志里找三类行。**选择行**:`Use X backend by default`,确定性模式下是 `Falling back to 'X' for deterministic inference`;没有选择行说明是手动指定的。**改写行**:页大小、精度回退、稀疏子后端、草稿后端退回、`Cuda graph is disabled because of using torch native attention backend`。**限制行**:`radix cache is not compatible with X attention backend for deterministic inference`。跑起来之后,`/server_info` 里那四个字段才是最终答案。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动抛 backend 相关的 ValueError 或断言失败 | 卡代与模型结构是否匹配 | 对上面的矩阵换一个名字 |
| DeepSeek 的 `cached_tokens` 总是 64 的倍数 | 有没有页大小改写那行日志 | 03 章;要 token 级命中就换 `fa3` 或 `flashinfer` |
| 开 FP8 KV 之后反而更慢 | 矩阵的 FP8 列;`fa3` 是不是被换成了 `triton` | 换成 `fp8_e4m3`;或换 `trtllm_mla`、`flashmla` |
| Hopper 上 decode 比预期慢 | 是不是手动指定了 `flashinfer` | 换回 `fa3` |
| 草稿宽度大于 1 时启动抛错 | 页是不是大于 1、后端是不是那 3 个之外 | 页设 1,或换 `flashinfer`、`fa3`、`triton` |
| 混合线性模型在 Blackwell 上断言失败 | 全注意力后端在不在允许集里 | SM120 用 `triton`、`trtllm_mha`、`flashinfer`;其他 Blackwell 用 `triton`、`trtllm_mha`、`fa4` |
| 确定性模式下命中率归零 | 后端是不是不在 radix 允许集里 | 换 `fa3`、`fa4`、`triton`、`ascend` |
| Triton 长上下文 decode 慢 | `--triton-attention-num-kv-splits` 还是 8 | 调到 16–32,或打开 `--enable-lean-attention` |
| CUDA graph 没生效 | 是不是 `torch_native` 或 `flex_attention` | 换后端 |
| 就绪时显存比自己算的少 1–4 GB | Triton 中间缓冲、FlashInfer 工作区 | 调小 `--triton-attention-num-kv-splits`;注意确定性模式的工作区是 2 GB |
| 草稿模型跑的后端和目标模型不一样 | 草稿只允许 7 个 | 看那行退回警告,接受它或把目标后端也换成名单里的 |

## 六、常见误区

- **以为像 vLLM 一样有候选链,指定的后端不行会自动换下一个。** 人们是从 vLLM 的日志里习惯了「被淘汰的候选」这回事。SGLang 显式指定就是它:不匹配要么启动抛错,要么被静默改成另一个并打一行日志,没有「下一个候选」,后端身上也没有一个能问「你能不能跑」的方法。
- **以为 `--attention-backend` 决定了所有注意力层的 kernel。** 名字确实像。但线性层另有 `--linear-attn-backend` 一族四个参数,稀疏注意力另有两个子后端参数,多模态编码器另有 `--mm-attention-backend`;混合与稀疏模型是在选出的后端外面包一层,包装层自己不算注意力后端。
- **以为文档说的「Blackwell 默认 `trtllm_mha`」总成立。** 文档只写了主线。草稿宽度大于 1、页大于 1、K 与 V 行宽不等(走 `fa4`)、SM120(走 `flashinfer`)都不走它。
- **以为 Hopper 上 `flashinfer` 比 `fa3` 快。** 早期版本的默认确实是它。这个基准上 Hopper 的 MHA 默认是 `fa3`,源码注释写明原因是 FlashInfer 0.6.1 在 Hopper attention kernel 上的一处性能回归,修好之前不换回去。
- **以为 `--decode-attention-backend` 只影响 decode。** 推测解码的 verify 和草稿默认走 prefill 侧,要 `--speculative-attention-mode decode` 才走 decode 侧;CUDA graph 也只默认捕 decode 侧。
- **调 `--triton-attention-reduce-in-fp32` 想修 fp16 溢出。** 参数还在,帮助文本也还在。这个基准上全树只有参数定义和字段顺序表提到它,没有任何 kernel 读。
- **以为 `--triton-attention-num-kv-splits` 是实际切几份。** 它是上限。实际份数按序列长和 SM 数当场算;确定性模式下改成按 256 的 tile 整除;AMD 上默认值是 16 不是 8;MLA 模型还会按 SM 数往上抬,某一代卡上抬到 512 会让 fp32 缓冲涨到约 4 GB,所以被硬钉在 256。
- **以为文档矩阵里的名字都能填给 `--attention-backend`。** 文档的 MLA 表里有 Cutlass MLA、MHA 表里有 Dual Chunk FlashAttention,这个基准的注册表和命令行取值里都没有这两个。反过来,`nsa` 是 `dsa` 的废弃别名、`compressed` 是 `dsv4` 的废弃别名,选了会打弃用警告然后走到同一个实现。
- **以为 Ampere 不能用 `fa3`。** MHA 模型可以,工厂函数明确放行 SM80;MLA 模型不行,断言只认 SM90。只是决策树在 Ampere 上不会自动选它。
- **以为确定性模式只改采样。** 它换掉默认后端、把可选后端限到 6 个、DeepSeek 一类只剩 4 个,在剩下那 2 个上还要关掉前缀缓存,顺带把 FlashInfer 工作区抬到 2 GB、Triton 的 split 改成固定 tile。
- **以为稀疏注意力模型要手动指定后端。** 按模型结构自动。但它的两个子后端是由 `--kv-cache-dtype` 决定的,而这个模型的 `auto` 在 SM100 及以上会自动变成 `fp8_e4m3`——也就是说什么都不写也可能换了一整套 kernel,日志里那行 `Set DSA backends` 最常被略过。
