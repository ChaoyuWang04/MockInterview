# SGLang 16|模型加载与权重缓存

磁盘上的 checkpoint 和 kernel 要的张量为什么对不上、注册表为什么要惰性、加载器怎么分工、safetensors 快在哪,vLLM 解读的「模型生态与权重加载」一章已经讲透。这一页只说 SGLang 在启动时把权重弄进显存的路子、多副本怎么少读盘、以及它和 vLLM 不一样的地方。RL 训练里的权重同步与显存让出在 17 章。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、核心问题

权重是 10–1000 GB 的文件,每次启动都要读盘、按 TP 切片、做量化后处理,再抓 CUDA graph。坏掉的指标是启动时间:官方文档给的量级是分钟级。它在 3 种场景下会被放大:

- 一台机器 8 个 rank 读同一份文件。网络文件系统上每个 rank 各读一遍,总流量是 8 份 checkpoint,页缓存里还各存一份。
- 同一张卡上跑 2 个引擎进程(比如 RL 里训练侧和推理侧各起一个),权重在显存里放 2 份,直接 OOM。
- 换权重要重启。重启等于重新探测显存、重建 KV 池、重抓图,分钟级的事情重来一遍。

## 二、解法:读一次,大家共用

最天然的直觉是「谁先读到就分给别人」,SGLang 按距离远近做了 3 层:

- **同一台机器的多个 rank** 共用 OS 页缓存。开了预取之后每个 rank 只负责预热 1/N 的文件,后台线程顺序读,读盘总量从 N 份降到 1 份,后面的 mmap 全在内存里命中。
- **同一张卡的多个进程** 共用一个权重缓存守护进程。守护进程把读盘、切片、量化后处理全做完,把每个张量导出成 CUDA IPC 句柄;引擎在 meta 设备上建一个空壳模型,把每个参数直接指向守护进程的显存,零拷贝。独立启动的守护进程活得比引擎久,引擎重启只剩一次句柄交换。
- **跨机器的新实例** 用 R-Fork:新实例不读盘,从一个正在跑的实例经 NCCL 或 TransferEngine 走 GPU 到 GPU 直传,rank 对 rank。

实际不吃亏的原因:页缓存是 OS 白送的;IPC 映射不多占一字节显存;GPU 网络比任何磁盘都快。

## 三、代价

守护进程只放行 2 种权重形态:不量化,和分块 FP8。其他量化方法的后处理会改张量形状或塞 Python 侧元数据,零拷贝映射会得到错的数,所以直接报错拒绝。引擎的参数指着别人的显存,守护进程一死指针就悬空,引擎每 5 秒查一次守护进程存活,发现死了就把自己 SIGKILL。所有在线换权重接口在缓存模式下一律拒绝。R-Fork 要求种子实例与新实例的并行策略完全一样。注册表不惰性,启动时把 238 个模型文件逐个导入,每次启动都付这笔。

## 四、和 vLLM 不一样的七处

1. **注册表是急切的。** vLLM 表里存字符串,子进程探测元信息,再按文件哈希缓存。SGLang 把 `models/` 目录下 238 个文件逐个导入,215 个文件声明了 `EntryClass`,登记出 276 个架构名,没有子进程也没有缓存。找不到原生实现时退到 Transformers 实现,打一行警告。外部包通过 `SGLANG_EXTERNAL_MODEL_PACKAGE` 覆盖同名架构。
2. **加载器不只由 load_format 决定。** vLLM 15 个格式名落到 7 个类。SGLang 枚举里 22 个值,命令行只开放 18 个,落到 15 个类加 1 个私有插槽;3 个枚举值(jax、rdma、local_cached)没有任何加载器。量化方法也会改类:auto-round-int8 换成 Inc 加载器,modelopt 系列换成 ModelOpt 加载器,`--load-format` 写什么都不管用。量化检测本身在 12 章。
3. **网络盘预取要手动开。** vLLM 自动检测网络文件系统并预热。SGLang 要 `--weight-loader-prefetch-checkpoints`,开了之后多线程读默认关掉,免得预取线程和读线程抢 I/O。
4. **预分片有两种。** sharded_state 是离线脚本产出,每个 rank 读自己那份。presharded 是第一次正常加载并量化后自动落盘到 `model_path/presharded/` 下按并行与量化配置命名的子目录,第二次直接读,跳过重新量化;目录要在共享文件系统上。
5. **R-Fork 是内建加载器。** vLLM 解读里权重从别的实例来只有外部库代理一条。SGLang 的 remote_instance 有 nccl、transfer_engine 两种自家后端,ModelExpress 是第三种;后者没有可用种子时自动退回读盘并把自己登记为种子。
6. **启动重叠。** `--startup-weight-load-mode overlap` 在抓 CUDA graph 的同时预热 checkpoint 文件,抓完再提交真权重。只支持 Llama、Qwen2、Qwen3 三个架构和 fp16、bf16 两种精度。vLLM 解读里没有这一项。
7. **热重载只走默认加载器。** `/update_weights_from_disk` 换路径原地重读,失败自动回滚重读原权重,默认顺手清前缀树,可选重抓图。守护进程模式下直接拒绝。vLLM 的分层热重载是为量化模型省显存,SGLang 这条路没有分层。

## 五、调参与观测

**参数在哪调。** 启动参数决定走哪个加载器和读盘方式(`--load-format`、`--model-loader-extra-config` 传 JSON、`--weight-loader-*` 一组、`--weight-cache-*` 一组、`--remote-instance-weight-loader-*` 一组),改了要重启。环境变量(`SGLANG_` 前缀)管文件顺序、跳过哪些模型文件、守护进程的 socket 路径,也要重启。运行时只有两个入口:`/update_weights_from_disk` 原地换权重;`/model_info` 读回 `model_path`、`load_format`、`weight_version`、`architectures`(`/get_model_info` 与 `/server_info` 已标弃用)。独立守护进程用 `python -m sglang.srt.weight_cache.daemon` 加同一套服务参数启动。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--load-format` · 用哪个加载器 | 启动 | auto:safetensors 优先,退回 .bin;.gguf、Mistral 原生、s3 路径自动改 | dummy:不读盘,填随机数,只测性能。sharded_state、presharded:每 rank 只读自己那份,启动变快。fastsafetensors:GPU Direct Storage 直读显存 | `Load weight end` 行的 `elapsed`;`/model_info` 的 `load_format` |
| `--model-loader-extra-config` · 给加载器的 JSON | 启动 | {} | `enable_multithread_load`(默认 true)、`num_threads`(默认 8):本地 NVMe 提到 16 读盘变快;网络盘反而互相抢 | `Loading safetensors checkpoint shards` 进度条 |
| `--weight-loader-prefetch-checkpoints` · 各 rank 分摊预热页缓存 | 启动 | 关 | 网络盘:读盘总量从 N 份降到 1 份,启动变快;开了默认关多线程;本地盘没有效果 | debug 日志 `prefetching checkpoint files into page cache finished in` |
| `--weight-loader-prefetch-num-threads` · 每 rank 预热线程数 | 启动 | 4 | 网络盘带宽没跑满时调高 | 同上 |
| `--weight-loader-disable-mmap` · 整文件读进内存 | 启动 | 关 | mmap 慢的文件系统上变快;主机内存峰值多一个分片 | `Load weight end` 行的 `elapsed` |
| `--weight-loader-drop-cache-after-load` · 读完一个分片就丢页缓存 | 启动 | 关 | 主机内存被页缓存挤满时开;代价是下次重启不再命中页缓存 | 主机内存占用 |
| `SGLANG_SORT_WEIGHT_FILES` · 文件顺序与多 rank 错开 | 环境变量 | 0(只排序) | -1 保持原序;k 大于 0 时各 rank 错开 k 个文件起读,多 rank 并发读盘更均匀 | 多 rank 时的进度条是否同步 |
| `--weight-cache-mode` · off、daemon、client | 启动 | off | client 加独立守护进程:重启只做句柄交换,秒级。daemon:引擎自己拉守护进程,与引擎同死,首次启动反而更慢。开了之后所有 update_weights 接口拒绝,CPU 备份被禁 | `[IpcModelLoader] Fetched N tensors from daemon ... in Xs` |
| `--weight-cache-socket` · 守护进程 socket 路径 | 启动 | 按 GPU UUID 从模板生成 | socket 文件不存在时 client 模式退回读盘;存在但连不上直接报错 | 警告 `falling back to disk load` |
| `--weight-cache-timeout` · 等守护进程就绪的秒数 | 启动 | 1800 | 大模型读盘慢时调高 | `did not become ready within` |
| `--remote-instance-weight-loader-backend` · R-Fork 后端 | 启动 | nccl | 配 `--load-format remote_instance` 与种子 ip、port;nccl 还要一组端口。参数不全静默退回 auto | 警告 `Fallback load_format to 'auto'` |
| `--startup-weight-load-mode` · 抓图时预热文件 | 启动 | serial | overlap:启动总时间缩短;只 3 个架构 | overlap 下 `Load weight end` 行不再打印 |
| `SGLANG_DISABLED_MODEL_ARCHS` · 跳过哪些模型文件 | 环境变量 | 空 | 少导入文件,启动省时;写文件名不带 .py | 就绪前是否还出现该架构的 import 警告 |
| `--model-impl` · sglang、transformers、auto | 启动 | auto | 无原生实现时退到 Transformers 实现,吞吐低 | 警告 `has no SGLang implementation, falling back to Transformers` |
| `--delete-ckpt-after-loading` · 就绪后删 checkpoint | 启动 | 关 | 省磁盘;之后 `/update_weights_from_disk` 没东西可读 | 就绪后目录消失 |
| `/update_weights_from_disk` · 原地换权重 | 运行时 | `flush_cache` 为 true | 不重启;只走默认加载器;失败回滚 | 日志 `Update engine weights online from disk begin`;`/model_info` 的 `weight_version` |

**怎么看。** 启动日志两行夹住整个加载:`Load weight begin. avail mem=` 和 `Load weight end. elapsed=… type=… avail mem=… mem usage=…`,`elapsed` 包括建模型、读盘、切片和量化后处理,不只是读盘;`mem usage` 是权重实际占的显存。中间 `Using model weights format ['*.safetensors']` 说明选中了哪类文件,rank 0 的 `Loading safetensors checkpoint shards` 进度条看读盘速度,`Loading from presharded checkpoint at` 说明走了预分片,`Detected Mistral native format` 说明格式被自动改了。守护进程侧看 `Model loaded from disk in Xs`、`Exported N tensors as IPC handles. Ready to serve`,配不上时打 `Config mismatch: {...}` 并列出差异字段。

| 症状 | 先查 | 然后 |
|---|---|---|
| 本地 NVMe 上启动慢,进度条慢 | `num_threads` | 提到 16;反复重启同一配置改 presharded |
| 网络盘上多 rank 启动慢 | 预取开没开 | 开预取;主机内存不够再开 drop cache |
| 开了 daemon 模式重启没变快 | 守护进程是不是引擎拉的 | 改独立启动加 client |
| `Config mismatch` 后走了读盘 | 差异字段:dtype、量化、TP、revision、torch 版本 | 对齐参数或重启守护进程 |
| `not verified for CUDA IPC zero-copy` | 量化方法不在白名单 | 关掉缓存 |
| 引擎突然被杀,日志 `Weight cache daemon ... died` | 守护进程先死了 | 先起守护进程再起引擎 |
| `/update_weights_from_disk` 报 `not supported while the weight cache is active` | 缓存模式 | 关缓存后重启 |
| 日志 `Fallback load_format to 'auto'` | R-Fork 的 ip、port、端口组不全 | 补齐 |
| 吞吐明显低于同尺寸模型 | 有没有 `falling back to Transformers` 警告 | 用原生架构名或外部模型包 |
| 换权重后答案变差 | 请求里 `flush_cache` 是否设了 false | 保持默认 true |
| 主机内存被吃光 | 页缓存 | 开 drop cache |
| 启动报 `Unknown load_format` | 用了 jax、rdma、local_cached | 换格式 |

## 六、常见误区

- **load_format 决定加载器。** 人们这么以为是因为参数名就叫这个。实际上量化方法优先:auto-round-int8 和 modelopt 系列会换成自己的加载器,日志里那行 `Using ModelOptModelLoader` 常被略过,然后奇怪为什么 `--model-loader-extra-config` 不生效。
- **开 daemon 模式重启会快。** 名字里有守护进程,人们以为它常驻。实际上引擎拉起的守护进程是引擎的子进程,引擎退它也退,第一次启动还多一次读盘加握手。想要秒级重启必须独立启动守护进程,引擎用 client。
- **多线程越多读盘越快。** 本地盘上成立。网络盘上线程互相抢带宽,预取一开系统就把多线程关了,你再显式写 `enable_multithread_load` 等于把它抢回来,更慢。
- **守护进程能让两个引擎各放一份权重。** 恰恰相反,它是让两个引擎共用同一份。代价是谁都不能改:在线换权重接口全拒绝,CPU 备份被禁,量化只放行分块 FP8。
- **R-Fork 是权重同步。** 它只在启动那一刻从种子实例拉一次,之后两边各走各的。种子实例后来换了权重,新实例不会跟着变。
- **注册表和 vLLM 一样惰性。** 代码是从 vLLM 改来的,人们以为机制也一样。实际上启动时 238 个文件全导入,某个模型文件缺依赖只打警告跳过,该架构就「不支持」;先看就绪前的 `Ignore import error when loading` 警告。
- **`Load weight end` 的 elapsed 是读盘时间。** 它包括建模型、切片和量化后处理,在线量化的模型里后处理可能占大头。overlap 模式下这行根本不打印。
- **npcache 能加速 safetensors。** 它只支持 .bin,safetensors 走它直接断言失败。
- **presharded 要先跑离线脚本。** 那是 sharded_state。presharded 第一次自己落盘,但 `model_path` 只读(比如 HF 缓存挂载)时必须在 extra config 里给 `presharded_path`。
- **删了 checkpoint 还能热重载。** `--delete-ckpt-after-loading` 就绪后把 `model_path` 目录删了,之后 `/update_weights_from_disk` 读同一路径必然失败。
