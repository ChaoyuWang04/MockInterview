# SGLang 04|RadixAttention:前缀缓存

前缀为什么能复用、块哈希怎么做前缀缓存、命中边界落进块内部时为什么要复制,vLLM 解读的「PagedAttention 与 KV Cache 管理」与前缀缓存一章已经讲透。这一页只说 SGLang 遇到的问题、它的解法、代价、以及和 vLLM 不一样的地方。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、核心问题

系统提示词、上一轮对话、agent 每一步带的工具说明、同一个 prompt 的 64 条 rollout,每来一条请求都从头算一遍 prefill。5000 个 token 的 prefill 在一张卡上是 50–500 毫秒,多轮对话每一轮都付一次。

这些负载共享的形状有三个特点:分叉点落在任意一个 token 上;主干(系统提示词、工具说明)比枝叶重要,显存紧张时它们必须最后被丢;同一批里常有 10–100 条同源请求,prompt 只该算一次。块哈希满足不了第一条,也没有「谁是谁的主干」这种结构。

## 二、解法:一棵前缀树

把所有请求的 token 序列合成一棵树。没有分叉的一段压成一个节点,节点的键是这段 token,值是它们的格子号(03 章)。

- **新请求从根往下走**,走到哪分叉就从哪开始算。走到节点中间分叉,就把节点从那里劈成两半,劈开只改树,不动 KV。命中到单个 token,但全命中也留最后 1 个 token 给这次前向,因为要拿它算 logits。
- **在跑的请求给路径上的节点加锁**,锁着的节点不会被丢。请求结束时它的路径留在树上,变成可丢的缓存。
- **显存不够时从叶子开始丢**,默认丢最久没用的(还有 7 种策略可选)。叶子先丢意味着主干最后丢:系统提示词是所有分支的根,永远最后走。
- **调度器按命中长度排队**:等待队列里谁命中得多谁先进批,同源的请求连着进,一次 prefill 就把树长好,后面的全命中。同一批里 10–100 条同 prompt 的请求,用一棵模拟树先查重,prompt 只算一次。
- **树能延伸到内存和硬盘**(05 章),显存里的节点被丢之前先备份一份。

## 三、代价

- **树只在一个进程里。** 哈希可以跨进程算出同样的指纹,树不行。PD 分离的 decode 端默认不开树,多副本靠网关另建一棵近似树来路由。
- **匹配是 CPU 的活。** 按命中长度排队要每轮把整个等待队列逐条走一遍树,等待队列超过 128 条时 SGLang 自动退回先来先服务,日志不提示。
- **地址表 2 GB**(03 章),这是树能在任意 token 劈开的前提。
- **后端钉页后命中退到页边界。** FlashMLA 这类程序把页改成 64,命中只能到 64 的倍数。
- **并发拉满时树被驱逐空,命中率归零。** 树只用空闲显存,在跑的请求越多,留给缓存的越少。
- **上一轮的回答比 prompt 先被丢。** 结束时整段路径插进树里,回答那一段是叶子,下一轮来之前它可能已经没了。

## 四、和 vLLM 不一样的六处

1. **指纹对树。** vLLM 每 16 个 token 算一个哈希,查表 O(1),哈希能跨进程复现。SGLang 用树,分叉在任意 token,劈开不复制,但只在本进程内。
2. **谁先进批。** vLLM 按到达顺序。SGLang 默认按命中长度排,同源的请求挨着进;队列超过 128 条时退回到达顺序。
3. **丢谁。** vLLM 把有哈希的块排成 LRU 队列,队首先丢。SGLang 只丢叶子,从叶子往上按策略挑,主干天然最后丢。
4. **同一批里的同源请求。** vLLM 刻意不去重,一个哈希可以对应多块。SGLang 用模拟树在批内查重,prompt 只算一次。
5. **换权重之后。** SGLang 给 RL 留了开关,权重更新后整棵树清空,旧 KV 一个不留。
6. **树的形态。** SGLang 默认用统一树,一棵树里按层型分成全注意力、滑动窗口、Mamba 几个组件,每个组件自己的驱逐链;树核可以换成 Rust 实现。
