## 一、SGLang 是什么

**SGLang** 是 LMSYS 主导、RadixArk 团队维护的大语言模型与多模态模型服务框架。它的出发点和多数推理引擎不一样:它把一次 LLM 应用看成一段**程序**而不是一次调用。多轮对话、few-shot、树状搜索、agent 循环,每一步都在往同一段前缀后面追加内容,而朴素的引擎把每次调用当成互不相干的请求,前缀反复重算,约束解码一次只能吐一个 token。SGLang 为此做了一门前端语言(用 Python 装饰器写含控制流、约束、多模态的 LLM 程序,也是名字里「Language」的来源)和一个运行时 SRT(SGLang Runtime),运行时里的两项设计,radix 树前缀缓存和压缩状态机,就是从「程序多次调用共享前缀」这个出发点长出来的。今天绝大部分代码在运行时里,前端语言只剩很小一块。

运行时面对的矛盾和所有推理引擎相同:显存与算力有限、请求潮汐波动,却要把百亿到万亿参数的模型以高吞吐、低延迟服务给成千上万个并发请求。SGLang 的回答是把**缓存**当成主线:前缀缓存用 radix 树管理,命中到 token;调度器按缓存命中排序;缓存从显存扩到主机内存和分布式存储;多副本时连路由也按缓存内容决定。围绕这条主线,再加上 CPU 与 GPU 的错批重叠、大规模 MoE 的一整套部署方案,以及注意力后端、推测解码、PD 分离、量化、多模态这些每个引擎都要有的基础设施。

一句话定位:**SGLang 把「radix 树前缀缓存 + 缓存感知调度 + 零开销 CPU/GPU 重叠 + 三层 KV 缓存 + 大规模 MoE 部署」做成了一套推理服务栈,并把缓存感知一路延伸到跨实例的路由网关。** 官方称部署量超过四十万张 GPU(README 说法),也是多个 RL 训练框架的 rollout 后端。

顶层入口(仓库根 `python/sglang/`):

- `sglang.Engine(...)`:离线批量推理,Python API,入口在 `srt/entrypoints/engine.py`。
- `python -m sglang.launch_server` 或 `sglang serve`:启动 OpenAI 兼容 HTTP server,入口 `srt/entrypoints/http_server.py`;设环境变量后 HTTP 前端可换成 Rust 进程。
- `sgl-model-gateway`:多实例部署时的路由网关,独立的 Rust 二进制。

代码组织上,推理运行时全部在 `python/sglang/srt/`(三万 KB),另有三块体量不小但本解读不涉及的东西:`python/sglang/kernels/`(树内统一 kernel 命名空间,一万四千 KB,算子层本解读只讲到「用哪个后端」)、`python/sglang/multimodal_gen/`(SGLang Diffusion,图像视频生成,一万 KB,是独立产品)、`srt/hardware_backend/`(NPU / MLX / XPU / MUSA 移植)。从体量看,`srt/` 里模型实现与算子层各占五分之一,KV 管理一成,调度、PD 分离、推测解码各占百分之四到五。

## 二、六个招牌:先建立全局图景

```text
                客户端并发请求 ── 多副本时先过 [6] Model Gateway(缓存感知路由)
                                        |
                    ┌───────────────────┴───────────────────┐
                    ▼                                       ▼
        [1] RadixAttention                       [2] 零开销调度
        radix 树存前缀 KV,命中到 token           CPU 提前一批准备,GPU 不等 CPU
        调度器按命中长度排序                       占位 token + CUDA event
                    |                                       |
                    └───────────────────┬───────────────────┘
                                        ▼
                    [3] HiCache:GPU / host / 分布式存储三层
                    显存放不下的前缀往外放,14 种 L3 后端
                                        |
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
        [4] 推测解码 Spec V2    [5] 大规模 MoE          PD 分离 / 量化 / 多模态
        七种草稿算法与 overlap   DeepEP + 双批重叠        每个引擎都要有的基础设施
        调度协同,DFlash         + 专家负载均衡 + DPA
```

一句话记忆:

- **RadixAttention**:前缀缓存用 radix 树而不是块哈希,自动复用、命中到 token、驱逐按 LRU 递归走叶子。
- **零开销调度**:CPU 决策与 GPU 计算错开一批,官方数字是省下最多一半的 CPU 时间。
- **HiCache**:把前缀缓存从显存扩到主机内存和分布式存储,多轮长上下文不再被显存容量卡命中率。
- **Spec V2**:推测解码的草稿阶段也和 overlap 调度器协同,消掉 host-device 同步。
- **大规模 MoE**:PD 分离、DeepEP、双批重叠、专家负载均衡、DP attention 一套打通,官方数字是 decode 相对 TP16 五倍。
- **Model Gateway**:跨实例维护一棵近似 radix 树做路由,官方数字是命中率从两成到七成五。

## 四、一条请求怎么串起来

一条请求进来后依次落在三类进程手里:**主进程**里的 TokenizerManager 套聊天模板、切词、构造请求对象;**Scheduler 子进程**(每个 TP / PP rank 一个)的事件循环做调度(这里用上连续批处理、缓存感知排序、radix 树匹配、PD 分离),准备好下一批的元数据后交给同进程里的 TpModelWorker 跑前向与采样(这里用上注意力后端、量化、并行、推测解码、约束掩码);**Detokenizer 子进程**把 token 变回文本,流式吐回主进程再到客户端。数据并行时主进程和 Scheduler 之间多一个 DataParallelController 子进程分发请求。

零开销调度的意思是:Scheduler 在 GPU 跑第 N 批时,已经在准备第 N+1 批,第 N 批还没出的 token 用占位符先记着。

多副本部署时,请求先经过 Model Gateway,它按各副本的缓存内容决定发给谁。

## 六、阅读顺序

主干是 01 → 02 → 03 → 04 → 05,读完就抓住了 SGLang 的缓存主线。06 到 08 是单卡执行栈,09 到 11 是多卡与分离,12 到 17 按需查阅,18 只在做多副本部署时读。

**已读 vLLM 解读的人怎么读**:本站把 vLLM 当推理引擎的基石解读,共有的原理只在那边展开一遍。sglang 里 B 类和 C 类章的原理段只回指、不重讲,所以直接从 A 类六章切入即可(01、02、04、05、10、18),B 类章只看「机制之外」和「对比与决策」两段。两个项目的力气花在不同地方:

| 维度 | vLLM | SGLang |
|---|---|---|
| 前缀缓存 | 按块做链式哈希,命中粒度是整块 | radix 树,边可拆分,命中到 token;调度器按命中长度排序 |
| CPU 与 GPU 的关系 | 异步调度,采样结果留 GPU | 调度器提前一批准备元数据,用占位 token 让 GPU 不等 CPU |
| 缓存层次 | GPU 为主,offload 是一节 | GPU / host / 分布式存储三层,再往上有跨实例的缓存感知路由 |
| 大规模 MoE | EP 与 DP 各自支持 | PD 分离 + DeepEP + 双批重叠 + 专家负载均衡 + DP attention 一整套 |
| 服务层 | Python 进程 | HTTP 前端与路由网关可换成 Rust |

章表上的差异也由此而来:HiCache 从 vLLM 的一节升为一章,大规模 MoE 从并行章拆出,网关是新增章,采样、结构化输出、确定性合为一章。

## 七、术语表

| 术语 | 一句话 |
|---|---|
| SRT | SGLang Runtime,`python/sglang/srt/`,后端运行时 |
| RadixAttention | 用 radix 树管理前缀 KV 缓存的机制,SGLang 的第一个招牌 |
| 零开销调度 | CPU 调度提前一批与 GPU 计算重叠的事件循环 |

| HiSparse | 稀疏注意力模型 decode 时只在 GPU 留热 KV 的机制 |
| DPA | DP attention,注意力层走数据并行、FFN 照旧的并行方式 |

| SMG | SGLang Model Gateway,Rust 写的路由网关 |
