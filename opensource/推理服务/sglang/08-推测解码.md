# SGLang 08|推测解码

推测解码为什么几乎白送、接受率怎么决定加速比、草稿从哪来、被拒的 KV 怎么办,vLLM 解读的「推测解码」一章已经讲透;拒绝采样的数学在 vLLM 解读的「采样机制」一章。这一页只说 SGLang 遇到的问题、它的解法、代价、以及和 vLLM 不一样的地方。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、核心问题

decode 每步只出 1 个 token,却要把整份权重从显存搬一遍,GPU 大部分时间在等内存。推测解码让一个便宜的草稿先猜 k 个,主模型一次前向验完,搬一次权重出多个 token。

麻烦在草稿这一段自己的开销。每一步 CPU 都想知道「这次接受了几个」:接受几个决定序列长度、下一步的位置、要不要再分配 KV。要知道就得等 GPU 把数字拷回来,一等,02 章辛苦建起来的 CPU 与 GPU 重叠就断了。草稿模型本身又是一串很小的 kernel,k 步就是 k 组下发。结果是小批量下 GPU 空转比例更高。

哪种负载会坏:接受率低的负载(高温采样、开放式写作、草稿和主模型不配对),草稿全白算,主模型每步从算 1 个 token 变成算 k+1 个,TPOT 比不开还长。批大了也坏:验证的 token 数是并发乘草稿宽度,并发 64 时每步验 256–512 个 token,decode 从等内存变成等算力,草稿每浪费 1 步就是整批一起浪费。

## 二、解法:接受了几个,CPU 不问

最天然的直觉:草稿、验证、结果全留在 GPU 上,CPU 只管形状不管数值。SGLang 的 V2 worker 一步做四件事:草稿连猜 k 步,主模型一次验证,把「每个请求新的序列长度」写进显存里自己的格子,再让草稿模型追上被接受的那几个 token 的 KV。写格子那一下就是 02 章的公告板:下一步的输入 token、草稿要用的隐状态和 topk 概率都按请求号存在 GPU 缓冲区里,下一步的草稿直接从格子里取,CPU 全程只碰格子号。

CPU 不知道接受了几个,那 KV 怎么分?按最坏情况分:每个请求每步先占「草稿宽度」的格子,验证后只提交接受的那几个,03 章的两个长度 kv_allocated_len 和 kv_committed_len 就是为这个准备的;再多留 1 倍当双缓冲,吸收提交晚一步的滞后。调度器要用的序列长度走一条私有拷贝流,等发布事件到了再拷,不同步计算流。约束解码本来必须每步同步一次文法状态,EAGLE 家族、STANDALONE、DFLASH、DSPARK 把这一步挪进验证里,用一道屏障在主模型前向期间推进文法,重叠不断;只有 NGRAM 因为草稿在 CPU 上查表,配文法时每个 decode 步照旧同步。

为什么实际不吃亏:草稿 k 步捕成一张 CUDA graph,验证是固定宽度的 extend,也有自己的图,追赶那一步也有;三个阶段各一套注意力后端和图。8 个内建算法全跑在这一个 V2 worker 骨架上,关掉重叠只是让调度器同步地跑同一个 worker,V1 路径已经删掉。草稿来源分四类:EAGLE、EAGLE3 是拿主模型隐状态当输入的小头(MTP 模型自带,`--speculative-draft-model-path` 自动指向主模型,NEXTN 是别名;Gemma4 的助手草稿会被提升成 FROZEN_KV_MTP,只读主模型 KV、自己没有池);STANDALONE 是独立的小模型,不共享 embedding 和 lm_head;NGRAM 不跑模型,从已生成 token 的语料树里查,还能在启动或运行时挂外部语料;DFLASH 和 DSPARK 是块扩散草稿,一次前向出整块;UNO 用一个训练好的 LoRA 让主模型自己当草稿。不满意就用 `SpeculativeAlgorithm.register` 装饰器注册自己的名字和 worker 工厂,内建名和 NEXTN 不能占,注册时要声明支持重叠,不声明就只能在关掉重叠时跑,并且会打一行弃用警告。

自适应步数只有 EAGLE、EAGLE3 加 topk 1 才有:每个批大小区间各记一条接受长度的指数平均,起步 10 个批不动,之后每 5 个批算一次「取整加 1」落到候选阶梯的哪一档,往下降要多跌 0.25 才动。内置阶梯按并发分 4 档:1 起 1、3、5、7 步,8 起 0、1、3 步,32 起 0、1 步,64 起只有 0 步,0 步就是不猜。每一档启动时都捕好三个阶段的图,切档是换引用,不重录。

## 三、代价

- **KV 按最坏情况占。** 每请求每步预留 2 倍草稿宽度的格子,topk 大于 1 且页大于 1 时按分支数乘。所以一开推测,并发上限被改成 48,日志一行 warning,要自己算好再显式指定。
- **草稿有自己的 KV 池。** 每个主模型 token 配一个草稿槽,DFLASH 的 5 层草稿 bf16 下每 token 10240 字节,和主模型池同量级;草稿 KV 改 FP8 省出来的是空闲显存,要再抬 `--mem-fraction-static` 才变成容量。
- **图占显存。** 草稿、验证、追赶各一套图;自适应每一档再各一套。小批量下的捕图列表比不开推测更密。
- **接受率决定一切。** 每步固定验 `num_draft_tokens` 个 token,接受长度低于 2 时算力白烧。
- **有的功能关掉或降级。** NGRAM、UNO、FROZEN_KV_MTP 关混合分块;STANDALONE、NGRAM、UNO、非 NPU 的 DFLASH 不配 DP attention,DSPARK 配 DP attention 要开 `--enable-dp-lm-head`;DFLASH、DSPARK、UNO 只能 pp 为 1,流水线并行配推测要开实验环境变量;PD 分离的 decode 端开树和角色切换都拒绝推测;Flex attention 拒绝推测;trtllm_mha 只收 topk 1;LoRA 有白名单(15 章);`return_sampling_mask` 拒绝。
- **多卡每步广播。** TP 各卡 softmax 有浮点差异,验证结果由 rank 0 广播,每步多一次集合通信。

## 四、和 vLLM 不一样的七处

1. **默认怎么验。** vLLM 默认标准拒绝采样,比主模型概率和草稿概率的比值。SGLang 默认只看主模型概率,草稿概率当 0:一个草稿 token 被接受的概率就是主模型给它的概率,兄弟节点的概率累加着比,相当于 vLLM 里草稿贪心的那种情况;全批贪心时直接比 argmax。标准拒绝采样要显式开 `--speculative-use-rejection-sampling`,只有 EAGLE、EAGLE3、topk 1、词表一致才行,ROCm 上会自动开,因为那里没有采样验证 kernel,不开就退成贪心、温度失效。
2. **树还是链。** vLLM 验一条链。SGLang 的 topk 大于 1 时草稿是一棵树,验证用一张树掩码一次算完;树在页大于 1 时只有 flashinfer、fa3、triton 能跑,Hopper 上默认后端也会从 fa3 换成 flashinfer。
3. **三个旋钮不是一个。** vLLM 一个 k。SGLang 是步数、每步宽度、验证宽度三个,要么全不设走按模型的默认表(Llama 与 Grok 5、4、8,MTP 系和其它 3、1、4,STANDALONE 3、1、4),要么三个全设;topk 1 时验证宽度被强制改成步数加 1。
4. **重叠默认开。** vLLM 的异步调度要开、还要草稿批次补齐。SGLang 推测解码默认就是重叠的 V2,只有 CPU 设备自动关。
5. **接受阈值可以运行时改。** vLLM 没有。SGLang 的两个阈值是 `/set_internal_state` 能改的仅有几项之一;改了分布就不再等于主模型,而且改成功时顺手把累计接受长度清零。
6. **自适应是运行时阶梯。** vLLM 是按批大小的静态分段表。SGLang 按观测到的接受长度在候选步数里上下走,大批时可以降到 0 步。
7. **算法清单不同。** vLLM 有 Medusa、Suffix Decoding,SGLang 没有;SGLang 的 NGRAM 是跨请求的语料树、能挂外部语料,另有 UNO 和 FROZEN_KV_MTP。两边都有 EAGLE、MTP、独立草稿、DFlash、DSpark。

## 五、调参与观测

**参数在哪调。** 这一页几乎全是启动参数,改了要重启;自适应的阶梯是一个 JSON 文件,启动时读;几个内部开关是环境变量。运行时只有 `/set_internal_state` 能改两个接受阈值和 DSPARK 的两个字段;NGRAM 的外部语料走 `/add_external_corpus`。请求参数没有推测相关的字段,采样参数照常传,惩罚在验证时按草稿宽度展开,`min_p` 和 `logit_bias` 的限制见 13 章。

|---|---|---|---|---|
| `--speculative-algorithm` · 用哪种草稿 | 启动 | 关 | 8 个内建:EAGLE、EAGLE3、STANDALONE、NGRAM、DFLASH、DSPARK、UNO、FROZEN_KV_MTP,NEXTN 是 EAGLE 别名;一开并发上限变 48 | 启动日志「Max running requests is reset to 48」 |
| `--speculative-draft-model-path` · 草稿权重 | 启动 | 无;DeepSeek、GLM、Bailing 等 MTP 模型自动指向主模型 | MTP 模型再给会打「does not require」;UNO 不接受,改用 `--uno-lora-path` | 启动日志 |
| `--speculative-num-steps` · 草稿连猜几步 | 启动 | 按模型表,Llama 5、其余 3 | 调高:接受长度上限升,草稿时间线性涨;接受率低时 TPOT 反而长 | `Decode batch` 行 `accept len` |
| `--speculative-eagle-topk` · 每步留几个候选 | 启动 | Llama 4、其余 1 | 大于 1 变树验证,后端受限、每步 KV 预留按分支乘;等于 1 时验证宽度被强制为步数加 1 | 启动 warning「adjusted to speculative_num_steps + 1」 |
| `--speculative-num-draft-tokens` · 一次验几个 | 启动 | Llama 8、其余 4;NGRAM 12;DFLASH 读草稿配置否则 16;DSPARK 是块长加 1,块长默认 7 | 调高:每步验证算力和 KV 预留同步涨;并发要重算 | 就绪前日志 `max_running_requests` |

| `--speculative-adaptive` · 按接受长度自动调步数 | 启动 | 关 | 只 EAGLE、EAGLE3 加 topk 1;不满足或配 DP attention、多层 EAGLE、TBO、PDMux 时退回静态并打 warning;与 LoRA 互斥 | 日志「Adaptive spec params updated: steps a -> b」;`/server_info` 的 `speculative_num_steps` |
| `--speculative-adaptive-config` · 阶梯 JSON | 启动 | 内置 4 档,见上文 | 候选步数集合决定捕多少套图;`ema_alpha` 0.2、`warmup_batches` 10、`update_interval` 5 | 同上 |
| `--speculative-token-map` · 草稿只在高频词表上算 lm_head | 启动 | 无 | EAGLE 有效,EAGLE3 忽略;与拒绝采样互斥 | 草稿阶段耗时 |

**怎么看。** 开了推测,`Decode batch` 行多出 `accept len` 和 `accept rate`:前者是每次验证平均收下几个 token,含最后那个免费 token,直接对应加速比;后者是草稿 token 被接受的比例,分母是验证次数乘草稿宽度减 1。DSPARK 再多 `cap len`、`block accept len`。`/server_info` 里 `avg_spec_accept_length` 是从启动以来的累计值,自适应下还有当前 `speculative_num_steps`。每条响应的 `meta_info` 有 `spec_accept_length`、`spec_accept_rate`、`spec_verify_ct`、`spec_num_correct_drafts`、`spec_num_proposed_drafts`。`/metrics` 有 `sglang:spec_accept_length`、`sglang:spec_accept_rate`、`sglang:spec_num_steps` 等 gauge。参数最佳组合官方给了 `bench_speculative` 脚本扫。

| 症状 | 先查 | 然后 |
|---|---|---|
| 开了推测反而变慢 | `accept len` 是否低于 2 | 换草稿或算法;高并发开 `--speculative-adaptive` 或降步数 |
| `#running-req` 卡在 48 | 启动日志 reset to 48 | 显式指定 `--max-running-requests`,同时算 KV 预留 |
| 启动 OOM | 三个参数和 `--cuda-graph-max-bs-decode` | 文档配方:比例 0.5、图批 2、步数 3 宽度 1 验证 4、并发 4,稳了再逐项抬 |
| 报 topk > 1 with page_size > 1 | 后端 | 换 flashinfer、fa3、triton,或页 1 |
| ROCm 上温度像没生效 | 是否退成贪心验证 | 确认「Rejection sampling is enabled」 |
| `accept rate` 高、`accept len` 上不去 | 步数太小 | 加步数,或开自适应 |
| 自适应没动 | 日志「speculative_adaptive disabled」 | 改 EAGLE 加 topk 1;去掉 DP attention、TBO |
| 「LoRA with EAGLE ... does not support」 | 15 章的 4 条组合 | 关对应那项 |

| TP 多卡挂死 | rank 分叉 | 13 章的同步开关;`SGLANG_SPEC_TP_SYNC` 缩范围定位 |
| 改了阈值答案变怪 | 两个阈值不是 1.0 | 改回 1.0;想提速去调步数 |

## 六、常见误区

- **以为 V2 是个要开的选项。** 老文档和老环境变量 `SGLANG_ENABLE_SPEC_V2` 留下的印象。这个基准上推测解码只有 V2 worker,环境变量还设着会打一行「has been removed」;想要同步路径是 `--disable-overlap-schedule`,跑的仍是同一个 worker。
- **以为 SGLang 和 vLLM 一样默认是标准拒绝采样。** 两边都叫「验证」。SGLang 默认不看草稿分布,接受概率就是主模型给的概率;标准拒绝采样要显式开,而且只有 EAGLE 家族链式才有。
- **把 `--speculative-eagle-topk` 当采样的 top_k。** 名字里都有 topk。它是草稿树每层的分支数,和请求的 `top_k` 无关;UNO 的 K 也是这个意思。
- **只设三个参数里的一个。** 以为另外两个会按默认表补。不会:三个要么全不设,要么全设;topk 1 时验证宽度会被悄悄改成步数加 1,日志里只有一行 warning。
- **照文档设 topk 1 才敢开重叠。** 文档 V2 一节写着重叠只支持 topk 1、大于 1 会报错。这个基准上启动没有这条检查,Llama 默认表就是 topk 4 且重叠开着,分配器也有 V2 树的分支;文档那段是老的。
- **看 `accept rate` 0.6 就觉得差。** 它是逐草稿 token 的比例,尾部的 token 本来就接不住。看 `accept len`,3 以上就值。
- **把 `avg_spec_accept_length` 当最近值。** 它从启动累计,而且 `/set_internal_state` 每成功一次就清零,前后对不上不是 bug。
- **以为 NGRAM 免费。** 不跑模型不等于不花钱:每步固定验 12 个 token,语料树在 CPU 上、容量 1000 万节点,配文法时每步同步,不配 DP attention。
- **给 MTP 模型手动传草稿路径。** 以为草稿总要单独指定。DeepSeek、GLM、Bailing 这一串自动指向主模型,手动传会打「does not require」,而且传错了会真的去加载。
- **调低接受阈值当免费加速。** 阈值低于 1.0 后接受的 token 不再服从主模型分布,是有损的;它能在运行时改,正因为它是给实验用的。
- **以为自适应也会调 topk 和验证宽度。** 它只调步数,验证宽度跟着等于步数加 1,topk 必须是 1;并发 64 以上内置阶梯只有 0 步,看到它把推测关了是设计如此。
- **推测解码下按接受长度估 KV 用量。** 分配是按最坏情况的 2 倍草稿宽度每步预留的,并发 48 就是这么来的;显存空着一半也进不了更多请求,要显式抬并发。
