# SGLang 17|RL 训推一体:权重同步与显存让出

vLLM 解读没有对应章;权重怎么装进来见「模型生态与权重加载」一章。这一页只说训练和推理挤在同一批卡上时 SGLang 怎么让出显存、怎么把新权重换进来、以及它和 vLLM 的 sleep 与权重更新行为上不一样的地方。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、核心问题

RL 一步分两段:推理引擎跑 rollout,训练引擎拿这些样本算梯度。两段共用同一批卡时三个指标会坏。

- **显存峰值。** 推理引擎把权重、KV 池、CUDA graph 的缓冲全买断了,训练那一段要么放不下,要么只能杀掉服务再起。
- **权重同步延迟。** 每一步训练完都要换一次权重。杀掉重起是重读 checkpoint 加重抓 CUDA graph,大模型上 30–300 秒,这段时间 rollout 吞吐是 0。
- **正确性。** 前缀树里存的是旧权重算出来的 KV。换了权重不清树,前缀命中越高答案错得越多,没有任何报错;一条请求跨了换权重那一刻,前半截 token 是旧策略生成的,后半截是新策略的。

## 二、解法:让服务睡觉,而不是杀掉它

最天然的直觉:训练要卡的时候把推理进程的显存交出去,训练完再拿回来,进程本身一直活着。SGLang 把自己的显存分成三类贴标签:`kv_cache`、`weights`、`cuda_graph`,`/release_memory_occupation` 按标签把物理显存还给驱动,`/resume_memory_occupation` 按相反顺序拿回来。底下是 torch_memory_saver:它只释放物理显存,虚拟地址留着,所以 CUDA graph(把地址烤死在图里的那种预录前向)拿回显存后直接重放,不用重抓。

权重换进来有 4 条路,对应 4 种部署:从磁盘重读 checkpoint(最简单,新副本扩容也走它);训练端拉一个 NCCL 组从 rank 0 广播(训推分开在两批卡上);直接给张量的 CUDA IPC 句柄(训推同机同卡,传的是指针不是数据);checkpoint-engine 走 ZMQ 按 GPU 的 UUID 握手(多机各读一部分 checkpoint 再互相分发)。4 条路的收尾一样:参数原地覆写,不重新分配;默认清空整棵前缀树;记下新的版本号。

为什么实际不吃亏:权重是原地写进已有张量,显存布局不变;让出权重前 SGLang 自己把模型的 buffer(旋转位置编码表这类不是参数但算过一次的东西)拷到内存,拿回来再写回去;清树只是重置树和分配器,不搬数据。

## 三、代价

让出显存要求服务**完全空闲** ,它不等、不排空,有请求在飞直接断言失败,得先自己 `/pause_generation`。让出权重后默认不备份到内存,拿回来的是垃圾,必须紧接着推一次权重(或者启动时开 `--enable-weights-cpu-backup`,代价是内存多放一份权重)。每次换权重清整棵树,之前的前缀命中全丢,下一批 rollout 全部重算 prefill。不 pause 直接调更新接口,更新会等所有在飞请求跑完才动手,这段时间新请求进不来。NCCL 通道默认一个张量一次集合通信,不拼桶时大模型一次更新是 500–2000 次 broadcast;它只换主模型,草稿模型不跟着换。

## 四、和 vLLM 不一样的六处

1. **入口开关。** vLLM 的 sleep 和权重更新路由要 `VLLM_SERVER_DEV_MODE` 环境变量才注册,sleep 还要 `--enable-sleep-mode`。SGLang 的路由一直在,只是不开 `--enable-memory-saver` 时释放接口一个字节的显存都不还,只清树,连一行警告都没有。
2. **睡眠的粒度。** vLLM 分 level:1 是权重搬到内存、KV 丢掉,2 是全丢。SGLang 没有 level,只有三个标签各放各的;权重默认丢,备份到内存是启动旗标决定的。
3. **有请求在飞怎么办。** vLLM 的 sleep 自带 abort、wait、keep 三种模式,自己先暂停调度器,level 1 以上顺手清前缀缓存。SGLang 的释放接口只断言空闲,暂停是另一个接口 `/pause_generation`,三种模式是 abort、retract、in_place。
4. **权重更新的协议。** vLLM 是一个会话:init 传输引擎、start、分块 update、finish 时带版本号;传输后端有 NCCL、IPC、分片 RDT、稀疏 NCCL 4 种;finish 只记版本号,不清前缀缓存。SGLang 是 4 个各自独立的接口,一次调用一次完成,清树和记版本号都打包在里面,默认开。
5. **草稿模型。** vLLM 要显式调 `start_draft_weight_update` 才更新草稿模型。SGLang 磁盘和 IPC 通道先换主模型再自动换草稿模型;张量通道两个一起换,可用 `disable_draft_model` 跳过;NCCL 通道只换主模型。
6. **版本号怎么查。** vLLM 是 `GET /weight_info`。SGLang 的 `/get_weight_version` 是一个只返回 404 的壳,要看 `/model_info`;另外 SGLang 在每条响应的 `meta_info` 里给出每段 token 各是哪个版本生成的,vLLM 有没有对应字段基准外,未核。

## 五、调参与观测

**参数在哪调。** 这一章几乎全是运行时接口。启动时只有 4 组旗标:`--enable-memory-saver` 决定能不能真的还显存;`--enable-weights-cpu-backup` 与 `--enable-draft-weights-cpu-backup` 决定让出权重时备不备份;`--weight-version` 是起始版本号;`--load-format dummy` 加 `--checkpoint-engine-wait-weights-before-ready` 让服务先用随机权重起来、等第一次 IPC 更新才就绪。`--weight-cache-mode` 必须是 off,否则所有让出与更新接口都拒绝。环境变量只有 `SGLANG_WAIT_WEIGHTS_READY_TIMEOUT`。运行时接口按 RL 一步的顺序:`/pause_generation` → `/release_memory_occupation` → 训练 → `/resume_memory_occupation` → 4 个 `/update_weights_from_*` 之一 → `/continue_generation`;`/init_weights_update_group` 只在用 NCCL 通道前调一次;`/update_weight_version` 只改版本号;`/weights_checker` 算校验和。多 DP 副本时 NCCL、张量、IPC 三条通道要求 `dp_size` 为 1 或开了 DP attention,磁盘通道会扇出到每个副本并要求全部成功。

| 参数或接口 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--enable-memory-saver` · 让三类显存能整体让出 | 启动 | 关 | 开:释放接口真的把物理显存还给驱动。不开:只清树,显存一字节不动 | 释放后 `nvidia-smi` 是否真降;日志里不会有任何提示 |
| `--enable-weights-cpu-backup` · 让出权重时先拷到内存 | 启动 | 关 | 开:拿回权重后不用重新推;内存多占一份权重,让出与拿回各多一次拷贝 | 拿回后不推权重直接 `/weights_checker`,校验和是否与训练端一致 |
| `--enable-draft-weights-cpu-backup` · 只备份草稿模型 | 启动 | 关 | 同上,只管草稿模型 | 同上 |
| `--weight-version` · 起始版本号 | 启动 | `default` | 之后每次更新带 `weight_version` 就换成新的 | `/model_info` 的 `weight_version`;响应 `meta_info.weight_version` |
| `--checkpoint-engine-wait-weights-before-ready` · 等第一次 IPC 更新才就绪 | 启动 | 关 | 配 `--load-format dummy`:随机权重起服务、抓好 graph,多机各读一部分 checkpoint 再分发 | 日志 `Weights are ready after N seconds`;超时看 `SGLANG_WAIT_WEIGHTS_READY_TIMEOUT`,默认 120 秒 |
| `/pause_generation` 的 `mode` · 在飞请求怎么处理 | 运行时 | `abort` | `abort` 全部打回客户端;`retract` 退回队列、恢复后按新权重重算;`in_place` 原地停、KV 留着,之后 flush 会失败 | `Decode batch` 行 `#running-req` 归零 |
| `/release_memory_occupation` 的 `tags` · 放哪些类 | 运行时 | 空 = 三类全放 | `kv_cache`:清 PD 队列、还池、清树;`weights`:buffer 存内存再还;`cuda_graph`:还 graph 缓冲 | 前后 `nvidia-smi`;日志 `Cache flushed successfully!` |
| `/resume_memory_occupation` 的 `tags` · 拿回哪些类 | 运行时 | 空 = 三类全拿回 | 顺序固定 graph → 权重 → KV;拿回权重后不推权重就是垃圾 | 拿回后先跑一条固定 prompt 比对 |
| `/update_weights_from_disk` · 从 checkpoint 重读 | 运行时 | `flush_cache` 开、`abort_all_requests` 关、`recapture_cuda_graph` 关 | 失败自动回滚到原权重;`recapture_cuda_graph` 开了会重抓 graph | 日志 `Update engine weights online from disk begin. avail mem=` 到 `Update weights end.`;指标 `sglang:weight_load_duration_seconds{source="disk"}` |
| `/init_weights_update_group` + `/update_weights_from_distributed` · NCCL 组广播 | 运行时 | `backend=nccl`、`group_name=weight_update_group`、`flush_cache` 开 | 训练端 rank 0 广播,每个张量一次;`load_format=flattened_bucket` 把一批拼成一条只广播一次 | 日志 `init custom process group:`;指标 `{source="distributed"}`;失败信息含 `partially updated` |
| `/update_weights_from_tensor` · 传 CUDA IPC 句柄 | 运行时 | `flush_cache` 开、`disable_draft_model` 空 | 只传指针不传数据,只能同机;每个 TP rank 只解自己那份 | 指标 `{source="tensor"}` |
| `/update_weights_from_ipc` · checkpoint-engine 通道 | 运行时 | `flush_cache` 开 | ZMQ 按 GPU UUID 握手;UUID 对不上直接报错 | 日志 `Starting IPC weight update`;指标 `{source="ipc"}` |
| 请求字段 `flush_cache` · 更新后清不清树 | 每次请求 | 开 | 关:旧 KV 配新权重,只该在连续多次更新的中间那些次关 | 响应质量;`cached_tokens` 是否归零 |
| 请求字段 `torch_empty_cache` · 清树时顺带把分配器缓存还给驱动 | 每次请求 | 更新接口关;`/continue_generation` 开 | 开:更新中临时张量多时省出余量;多一次同步 | 日志 `[continue_generation] torch.cuda.empty_cache() called: reserved … MB -> … MB` |
| `/update_weight_version` · 只改版本号 | 运行时 | `abort_all_requests` 开 | 默认先打掉在飞请求再改号;不动权重 | 日志 `Weight version changed. old_version= new_version= num_recorded=` |
| `/weights_checker` · 每个 rank 算权重校验和 | 运行时 | `action=checksum` | 含草稿模型;TP 各 rank 分别报,DP 各副本分别报 | 响应 `ranks`、`per_engine_checksum` |

**怎么看。** 版本号看三处:`/model_info` 的 `weight_version` 是当前生效的;每条响应 `meta_info.weight_version` 是这条最后一个 token 用的;请求跨了换权重时 `meta_info.weight_versions` 给出每段 token 各用哪个版本,左闭右开、只数输出 token,一段以上就说明这条不是纯 on-policy。日志看 5 行:`Start update_weights. Load format=`、`Update weights end.`、`Cache flushed successfully!`(有请求在飞时是 `Cache not flushed because there are pending requests`)、`Weight version changed.`、`init custom process group:`。指标只有一个 `sglang:weight_load_duration_seconds`,带 `source` 标签,是 gauge 不是直方图,每次更新结束时写一次最近一次的秒数,更新期间引擎暂停,周期性统计不会跑。

| 症状 | 先查 | 然后 |
|---|---|---|
| 释放接口断言 `should be called only when server is idle` | `#running-req`、`#queue-req`、PD 队列、HiCache 在途读写 | 先 `/pause_generation`,等 `#running-req` 归零再放 |
| 放了显存 `nvidia-smi` 没降 | 有没有 `--enable-memory-saver`;没有的话日志里什么都不会留 | 加旗标重启;装 `torch-memory-saver` |
| 拿回显存后答案是乱码 | 让出过 `weights` 且没开 CPU 备份 | 拿回后立刻推一次权重;或开 `--enable-weights-cpu-backup` |
| 换权重后质量变差、指标全正常 | 请求里 `flush_cache` 是不是被关了;用的是不是 `in_place` 暂停 | 别关 flush;换 `retract` 暂停 |
| 更新接口卡住不返回 | 没 pause,更新在等在飞请求跑完 | 先 pause;或带 `abort_all_requests=true` |
| 返回 `partially updated … discard the whole weights` | NCCL 组里张量名、dtype、shape 与训练端对不上 | 整批重发,不要只补发失败的那些 |
| 返回 `weight cache is active` | `--weight-cache-mode` 不是 off | 改回 off 重启;守护进程共享的权重不能原地改 |
| 返回 `HPC-Ops bf16xfp32 GEMM` | 该算子缓存了 fp32 拆分,原地写它看不见 | 关掉这个优化再更新 |
| 多 DP 副本更新直接断言 | `dp_size must be 1 or dp attention must be enabled` | 开 DP attention;或每个副本各起一个服务分别推 |
| 草稿模型没跟着换 | 走的是 NCCL 通道 | 草稿模型用磁盘、IPC 或张量通道另外推 |
| 响应 `weight_versions` 有两段 | 请求跨了一次换权重 | 正常;要纯 on-policy 就用 `retract` 而不是 `in_place` |
| 服务起来了一直不就绪 | 在等 checkpoint-engine 第一次 IPC 更新 | 看 `Weights are not ready after waiting`;调 `SGLANG_WAIT_WEIGHTS_READY_TIMEOUT` |

## 六、常见误区

- **以为释放接口会自己等请求跑完。** 因为 vLLM 的 sleep 是这么做的,大家把它当同一个东西。SGLang 的释放接口只断言空闲,断言失败直接抛异常,请求处理器不兜。空闲不只是 `#running-req` 为 0:PD 的 bootstrap、prealloc、transfer 队列,HiCache 在途的写回与预取,grammar 队列,都算不空闲。
- **以为让出权重再拿回来,权重还在。** 因为 KV 那边拿回来就能用,想当然权重也一样。KV 能用是因为反正要重算;memory saver 只留地址不留内容,拿回来的权重是未初始化的显存。SGLang 自己只存了 buffer,参数默认不存,`--enable-weights-cpu-backup` 才存。
- **以为不开 memory saver,释放接口也能省一点。** 它退化成一个什么都不做的适配器,只清树,一个字节都不还,日志里一个字都不留,唯一的证据是 `nvidia-smi`。
- **以为 `flush_cache` 是可选的优化,关掉更快。** 4 个更新接口默认都开,关掉的唯一正当理由是连续推多批张量时中间那些次省一下,最后一次必须开。关掉不会报错,只会答错。
- **以为 `abort_all_requests` 默认会打掉请求。** 4 个更新接口默认都是关,只有 `/update_weight_version` 默认开。不 pause 又不带这个字段,更新接口就在那等在飞请求全部跑完。
- **以为 `in_place` 暂停加更新等于 `retract`。** `in_place` 把 KV 留着,更新后 flush 因为 running_batch 非空而失败,断言直接炸;就算过了,也是旧 KV 配新权重。PD 分离的 prefill 节点上 `retract` 也留着正在分块的那条请求,源码注释自己写了这一条会带旧权重的前缀 KV。
- **以为 NCCL 通道一次广播一批。** 默认一个张量起一次异步 broadcast,再统一等;`load_format=flattened_bucket` 才是拼成一条只广播一次。
- **以为草稿模型自动跟着换。** 只有磁盘、IPC、张量三条通道会;NCCL 通道全树只有主模型那一份实现。
- **以为 `/get_weight_version` 能查版本。** 它只返回 404,让你去 `/model_info`。响应里的 `weight_version` 也不是全局的,是这条请求最后一个 token 用的那个。
