# SGLang 13|采样、约束解码与确定性:五种事故,一张分数表

采样这一层坐在每一步的最末端,前向交出来的是一张每行 10 多万列的分数表,它要从每一行里挑一个 token 交回调度器。维护这一层的人处理的事故就五种:慢,这里多一次 GPU 到 CPU 的同步,整条流水线就停一次;错,加工步骤的顺序换了,参数的语义悄悄变了,没人报错;坏输出,模型吐出解析不了的 JSON,或者一行 NaN 让抽样直接崩;卡,一个大 schema 的编译把调度循环停住,或者多卡采样结果分叉整组挂死;不可复现,同一个 prompt 换个并发就换个答案,RL 训练的 logprob 对不上。三件事互不依赖,只想读其中一条可以直接跳。

采样、拒绝采样、约束掩码与批不变性的数学原理,vLLM 解读的「采样机制」「结构化输出」「确定性推理与批不变性」三章已经讲透,本章只写 SGLang 自己怎么防这五种事故。全章内容都在源码上逐条核对过;每节对应源码的哪个文件与符号,见代码索引页;正文不写路径与行号。

## Part 1|五种事故

### 1.1 事故表

| 事故 | 谁干的 | 症状 | 动哪个指标 | 防线在哪 |
|---|---|---|---|---|
| 慢 | 采样路径上加了一次同步,或者给每个请求各算一遍 | TPOT 翻倍,GPU 在等 CPU | TPOT、吞吐 | Part 2:全批贪心走 argmax;惩罚张量上一步算好;各 rank 不同步;掩码只填有文法的行 |
| 错 | 惩罚、掩码、偏置、温度的顺序换了 | 惩罚力度随温度变;偏置像没生效;logprob 对不上 | 正确性 | Part 3:顺序钉死,两处相邻关系不能换 |
| 坏输出 | 让模型自由生成再解析;分数表里混进 NaN;停止条件写错 | 非法 JSON;multinomial 崩;停不下来或停错位置 | 稳定性 | Part 4:采样前掐掉非法 token;NaN 先清;不接受的 token 抛错不静默 |
| 卡 | 一个大 schema 在调度循环里同步编译;多卡各自采样结果分叉 | 所有请求等一个 schema;TP 组挂死没有超时 | 尾延迟、稳定性 | Part 5:编译异步进专门的队;有文法时各 rank 取最小值 |
| 不可复现 | 同一请求换个 batch;RL 拿推理 logprob 做 on-policy | 温度 0 也两次不一样;训练发散 | 可复现 | Part 6:一个开关换算子、限后端、种子化采样,并连带关掉一串东西 |

### 1.2 这些事故在不同负载下各自先来哪一种

| 负载 | 先撞哪种 | 为什么 |
|---|---|---|
| 高并发混合批 | 慢 | 一个随机请求混进来,整批从 argmax 快路掉回完整管线 |
| agent 工具调用 | 卡、坏输出 | 同一个 schema 反复来,第一次付编译;schema 拼错要能拒得干脆 |
| 思考模型 | 坏输出 | 思考段被 schema 掐死,或者答案段没被约束 |
| RL rollout | 不可复现 | 同一 prompt 采 n 条,每条都要能重跑出同样的 logprob |
| 推测解码 | 坏输出、不可复现 | 草稿被拒后文法状态没回滚;带种子的裁剪路径有的不支持 |
| TP 多卡 | 卡 | rank 分叉没有超时,只能靠外部探活 |
| 流式多轮 | 慢、坏输出 | 停止正则每步在尾部跑;贪婪匹配拖慢每一步 |

### 1.3 由此对这一层的三条纪律

1. **不排序、不同步、不回 CPU**,能提前算的在上一步算好。
2. **顺序写进代码,不给调用方选**;能被顺序改变语义的参数,文档里明说它排在谁后面。
3. **出错就抛,不静默继续**:不接受的 token、非法的正则、编译失败的 schema,都在当步中止那条请求。

## Part 2|不慢:采样在流水线末端,一次同步停一次

### 2.1 事故:加一个功能,TPOT 翻倍

零开销调度(02 章)让 CPU 在 decode 一步里几乎不做事,GPU 连续跑。采样在这一步的最末端,只要这里出现一次 GPU 到 CPU 的同步,或者一段逐请求的 Python 循环,GPU 就停下来等。这一层每一个看起来绕的写法,动机都一样。

### 2.2 全批贪心走一条快路:一次 argmax,不做 softmax 也不裁剪

温度小于 1e-6 的请求在参数归一化时被改写成温度 1、top-k 等于 1,管线里没有「贪心」这个概念,只有「候选集只剩一个」。整批都是 top-k 等于 1 时直接对分数表取 argmax。**混合批里只要有一个随机请求,整批就掉回完整管线**,贪心请求照常走完 softmax 和裁剪,top-k 等于 1 自然只剩最大的。高并发下想保住快路,把贪心和随机请求分到不同实例。

### 2.3 惩罚的账在上一步算好,前向后只做一次加一次乘

惩罚要知道每个请求到现在为止输出过哪些 token。每步采样之后新 token 喂给惩罚器累积;下一步前向之前,惩罚器把累积结果变成两张与分数表同形状的张量,一张加法的一张乘法的,前向后直接加上和乘上。零开销调度下这两张张量在上一步就准备好,采样时不等 CPU。没有任何请求用惩罚时整个惩罚器不构造张量,一批里有一个请求用了,整批就要建两张 batch 乘词表大小的张量。

### 2.4 分数表只取每个请求的最后一行

前向结束时每个请求只需要最后一个位置的分数。logits 处理器先从隐状态里挑出每个请求的最后一行,再过词表投影。prefill 时如果要返回输入 token 的 logprob,才对更多位置做投影。省掉的是整段 prompt 乘以词表大小的矩阵乘。

### 2.5 掩码只给带文法的行填,用完立刻删

批级位掩码新分配时是「全部允许」,只有带文法且未结束的请求才往里填,所以一个批里有的行受约束有的不受,一个 kernel 就能处理。掩码用完立刻从批信息里置空,注释说否则延迟采样的闭包会一直持有它,1000–5000 个请求的掩码在 GPU 上堆着不放。

### 2.6 各 rank 各自采样,默认不同步

张量并行的每个 rank 都有一份完整的分数表,各自采样,默认不做 all-reduce 统一结果,省一次通信。正确性依赖最后一次 all-reduce、词表投影、采样 kernel 都是确定性的。这条省下的东西和它的风险在 Part 5 一起算。

### 2.7 两个采样后端,装了 flashinfer 就默认它

flashinfer 后端把 top-k 和 top-p 融合成一个 kernel,不排序;min-p 走单独路径。PyTorch 后端是教科书做法:排序、累积和、置零、multinomial。flashinfer 不支持带种子的抽样,确定性模式会把后端强制改成 PyTorch 并打警告。

## Part 3|不错:顺序即语义,两处相邻关系换不得

### 3.1 事故:参数没变,行为变了,没有任何报错

惩罚、掩码、偏置、温度、裁剪每一步都在改同一张分数表。顺序换一下,惩罚的力度会随温度缩放,或者偏置能把被文法禁掉的 token 救回来。这类改动不会让任何测试失败,只会让用户说「同样的参数今天不一样」。所以顺序写死在代码里,不给调用方选。

### 3.2 固定顺序

1. 自定义 logit 处理器(按请求传进来的),然后把非有限值清成安全值。
2. 惩罚:频率惩罚和存在惩罚是加法,重复惩罚是乘法,最小输出长度惩罚把 EOS 压成负无穷。
3. 文法掩码:不允许的 token 置负无穷。
4. logit 偏置:调用方指定的按 token 加分。
5. 除以温度。
6. softmax。
7. top-k、top-p、min-p 裁剪。
8. 抽一个。

### 3.3 惩罚在温度之前,所以惩罚力度不随温度变

惩罚先加在原始分数上,再一起除以温度,惩罚和分数按同一个比例缩放,相对关系不变。反过来放,温度 0.5 时惩罚等于被放大 2 倍,温度 2 时被削掉一半,同一个 repetition_penalty 在不同温度下是两个不同的参数。

### 3.4 偏置在掩码之后,所以偏置救不回被掩掉的 token

掩码把不允许的 token 置负无穷,偏置再加任何有限值还是负无穷。想用 logit_bias 绕过 schema 的人会发现偏置像没生效,那不是 bug。要放开某个 token,改 schema。

### 3.5 logprob 默认是温度之后、裁剪之前的

返回的 logprob 取的是除完温度、还没裁剪的那一步。有环境变量可以改成温度之前的原始值,整个服务只能选一种。确定性模式下 logprob 必须走 log_softmax 这个 kernel,而不是先 softmax 再取对数,注释说两者差在 1e-6 量级,足以破坏 prefill 与 decode 的 logprob 逐位对齐,RL 对齐就靠这个。

### 3.6 自定义处理器排在最前面,它改出来的分数会被后面每一步继续加工

调用方可以按请求指定一个处理器类和参数,处理器在管线第一步拿到整张分数表和每个请求的参数,还拿得到请求对象本身,能看到完整的输入输出历史。内置两个:禁词处理器把一组 token 置负无穷;思考预算处理器数思考段已经出了多少 token,到预算就强制输出思考结束符。它排在惩罚和掩码之前,所以它放开的 token 掩码仍然能禁掉。

## Part 4|不出坏输出:采样前掐掉非法 token,NaN 先清,停止条件当步判

### 4.1 事故:解析失败率 3%,和一行 NaN 让整批崩

让模型自由生成再解析 JSON,失败率随 schema 复杂度涨,靠重试是赌运气。另一种坏输出更直接:分数表里混进一个 NaN,softmax 之后整行 NaN,multinomial 直接报错,整批请求跟着死。第三种是停不下来或停错位置:停止串没匹配上,或者停止正则写错。

### 4.2 非有限值先清掉

进管线的第一件事是把分数表里的 NaN 和无穷清成安全值。这一步没有开关,每步都做。

### 4.3 四种约束三个后端,不支持的组合当场拒

请求可以带 JSON schema、正则、EBNF 文法或结构化标签四种约束之一。xgrammar 默认,支持全部四种;outlines 支持 JSON 和正则;llguidance 支持前三种。后端是服务级的,不支持的组合返回一个无效文法对象,请求中止。

### 4.4 每步一张位掩码,采样后推进状态,不接受就抛错

采样前,批里每个带文法的请求让 matcher 按当前状态标出哪些 token 允许,打包成位图,整批一次搬到 GPU,一个 kernel 把不允许的位置置负无穷。采样出的 token 送回调度器后喂给 matcher 推进状态。**matcher 不接受这个 token 时直接抛错**,这是不该发生的,掩码已经保证它可选;真出现了,先查是不是有自定义处理器或偏置在掩码之后改了分数,再查推测解码有没有回滚。matcher 走到终止状态后,后面的步不再填掩码,让模型自由收尾。

### 4.5 思考模型:先放开,再收紧

带思考段的模型在思考时要自由生成,思考结束后才该受约束。一个包装器套在真正的文法对象外面:匹配到思考结束序列之前,填掩码时不施加约束;匹配到之后才把每个 token 转给内层文法。可以给思考段设最大长度,到了就只允许结束序列。没有这个包装器,schema 会把思考段第一个 token 就掐死。

### 4.6 判停每步在尾部做一次,非法正则直接中止

token 级:命中 EOS、调用方给的停止 token、tokenizer 附加的停止 token,忽略 EOS 的请求跳过这一条。字符串级:停止字符串只在输出尾部一个窗口里找,窗口长度是最长停止串的长度。正则级:每步在尾部跑一次搜索,正则非法的话请求直接中止,不是忽略。长度级:到达最大输出长度。停止串默认从输出里裁掉,有开关可以保留。停止正则写成贪婪匹配会拖慢每一步,这是流式负载里 TPOT 的隐蔽来源。

### 4.7 跳跃前填的接口还在,调度器没有调用点

文法对象的接口上有三个方法:能不能跳、跳过去的字符串和下一个状态、跳完之后重新分词并同步状态;outlines 后端还带一份压缩状态机的实现。基准上调度器没有任何地方调用它们,也没有对应的启动参数。**约束解码目前每步只出一个 token**,schema 里固定的键名和引号也是一个一个采出来的。

## Part 5|不卡:编译不进调度循环,分叉不靠运气

### 5.1 事故:一个 schema 编译 3 秒,所有请求等 3 秒;多卡挂死,没有日志

文法编译要把约束展开成对整个词表的自动机,10 毫秒到几秒。如果在调度循环里同步编译,一个大 schema 到达,整个实例的所有请求停 3 秒。另一种卡更难查:张量并行下各 rank 各自采样,某一步两个 rank 采出不同的 token,后面的前向形状对不上,整组挂死,没有超时,没有日志。

### 5.2 编译交给线程池,请求进专门的文法队列

请求到达先按(类型,约束字符串)查缓存;没命中就交给线程池编译,请求进一个文法队列,不进普通等待队列。每轮调度先看队列里谁编译完了,把它们挪进等待队列。同一个 schema 的第 2 到第 n 个请求一分钱不付。

### 5.3 失败也缓存,等待有上限

编译失败的请求中止,失败结果也缓存起来,**同样的坏约束下次直接拒,不再编译**。等待轮数有上限,默认 10000 轮,每轮实际等的是轮询间隔 5 毫秒与一步前向耗时中较大的那个,所以至少 50 秒,decode 一步 20 毫秒时是 200 秒;超过判失败中止,不是继续等。张量并行的各 rank 各自编译,准备好的集合取交集、失败的取并集,保证各 rank 对同一请求做同样的决定。

### 5.4 有文法就同步,同步的方式是取最小值,不是投票

默认不同步 token 的正确性依赖 kernel 确定性,注释承认少数情况下不成立;用了文法约束时分叉概率更高,所以有文法时自动同步。同步做的是对 token id 做 all-reduce 取 MIN:哪个 rank 采出了更小的 id,所有 rank 就用它。这比广播便宜,而且各 rank 本来一致时结果不变。也可以用环境变量强制每步都同步,默认关。多卡挂起时开着它排查。

### 5.5 推测解码:草稿被拒,文法状态要回滚

草稿 token 被验证拒绝后,该请求的 matcher 要回滚相应步数,否则掩码状态和实际输出错位,下一步就「不接受」。推测解码自己的采样在 08 章。

## Part 6|可复现:一个开关,带出一串你没按的改动

### 6.1 事故:温度 0 也两次不一样,RL 的 logprob 对不上训练框架

同一个请求这次和 3 个请求拼在一起、下次和 300 个拼在一起,矩阵乘和归约的拆分方式不同,加法顺序不同,分数在 1e-7 那一位不同,某一步的 argmax 就翻了。前缀缓存也参与:命中了前缀和没命中,注意力分块边界不一样。对聊天服务这是「偶尔答案不同」,对 RL 训练这是 on-policy 假设不成立,训练发散。

### 6.2 换算子:归约顺序只看形状,不看 batch 里有几行

开确定性模式后,运行时用 PyTorch 的算子注册机制把矩阵乘、带偏置的矩阵乘、批矩阵乘、log_softmax、按维求均值、RMS 归一化换成自己的实现:持久化的 Triton kernel,来自 Thinking Machines 的批不变算子库。批矩阵乘还额外把 torch 的函数入口本身换掉,防止绕过注册。

### 6.3 注意力限 6 个后端,FlashInfer 下前缀缓存被自动关掉

注意力后端只能是 fa3、fa4、flashinfer、triton、ascend、intel_xpu 之一,不指定时按显卡代选:Blackwell 上非 DeepSeek 模型选 flashinfer,DeepSeek 选 triton;Hopper 及更早选 fa3;指定了不在清单里的直接报错。再往下一层:**只有 fa3、fa4、triton、ascend 在确定性下支持前缀缓存**,选了 flashinfer 或 intel_xpu,启动时自动关掉前缀缓存,只打一行警告。DeepSeek 这类吸收式 MLA 模型更严,后端不在这四个里直接报错。**Blackwell 上跑确定性模式不显式指定后端,得到的是一个没有前缀缓存的服务**,多轮负载的 TTFT 明显变差,而日志里只有那一行警告。

### 6.4 种子:默认 42,不带种子的 n 条采样是同一个答案

确定性模式下采样不用 multinomial,用 Gumbel-max:种子、当前位置、词表下标三者哈希得到均匀随机数,变成 Gumbel 噪声加到 logprob 上取 argmax,随机数只由种子和位置决定,和它在 batch 里排第几无关,噪声全程 float64。种子张量只在确定性模式下构造,请求不带种子时填 42。**所以确定性模式下同一个 prompt、温度 0.8、不带种子,跑 100 次是同一个回答;一次请求要 n 条,展开时采样参数原样复制,n 条也是同一个回答。** 想要多条不同但可复现的回答,每条给不同的种子。不开确定性模式时种子张量是空的,走普通 multinomial。

### 6.5 设了 on-policy 目标,确定性自动开

rl_on_policy_target 目前只有一个取值 fsdp。设了它,确定性推理自动打开,VLM 特征缓存关成 0,logprob 走 log_softmax。另有一条给 RL 的路径:请求可以要求返回「这一步裁剪之后还剩哪些 token、各自权重多少、选中的那个权重多少」,实现上在裁剪的同时抓一份过滤后的概率,注释把它写成正确性不变量:融合采样 kernel 和单独的重归一化原语必须在截断、并列、联合支持集三件事上语义一致。

### 6.6 代价:慢,以及一串被连带关掉的东西

批不变 kernel 比厂商库慢,文档没给比例。开关带出的改动:采样后端强制 PyTorch;flashinfer 与 aiter 的 all-reduce 融合关掉;张量并行时 NCCL 改用树算法,自定义 all-reduce 与对称内存 all-reduce 关掉;flashinfer 与 intel_xpu 后端下前缀缓存关掉;PyTorch 后端的 min-p 裁剪遇到种子直接断言失败,所以确定性下 min-p 不可用;多模态模型的 VLM 特征缓存关掉。没有一条需要用户手动做,也没有一条会出现在你敲的启动参数里,启动日志的警告要逐行看。

## Part 7|图解

### 7.1 从分数表到判停

```text
  前向 ──> 最后一行做词表投影 ──> [每请求一行分数]
                                        |
      自定义处理器 -> NaN 清洗 -> 惩罚(加法 / 乘法 / 压 EOS)
                                        |
                              文法掩码(不允许的置 -inf)
                                        |
                                   logit 偏置          <- 救不回上一步被掩的
                                        |
                          / 温度 -> softmax -> top-k / top-p / min-p
                                        |
               全批贪心:argmax     否则:multinomial 或 带种子 Gumbel-max
                                        |
                        有文法或强制同步:各 rank 取 MIN
                                        |
                              token 回到调度器
                                        |
        文法 matcher 推进 -> 惩罚器累积 -> 判停(token / 字符串 / 正则 / 长度)
```

### 7.2 一条带约束的请求的一生

```text
  请求到达(json_schema)
       │
       ├─ 查编译缓存 (类型, 约束串) ──命中──> 进等待队列
       │                                        ▲
       └─ 未命中 ──> 线程池编译 ──> 进文法队列 ──┤ 每轮调度轮询:编译完了就挪
                        │                       │ 等待计数 ≥ 10000 轮 -> 判失败中止
                        └─ 编译失败 ──> 缓存失败结果,请求中止;同样的约束下次直接拒
       │
  每步:matcher 填一行位掩码 ──> 整批搬 GPU ──> kernel 置 -inf ──> 采样
       │
  token 回来 ──> matcher.accept ──不接受──> 抛错「Tokens not accepted」
       │                        └─ 推测解码被拒的草稿:rollback
       └─ 终止状态 ──> 后续步不再填掩码
```

### 7.3 一个开关带出的一串改动

```text
  --enable-deterministic-inference (或设了 rl_on_policy_target)
       │
       ├─ 算子:mm / addmm / bmm / log_softmax / mean / rms_norm 换成批不变 Triton kernel
       ├─ 采样后端:flashinfer -> pytorch(Ascend 除外);min-p 与种子互斥
       ├─ 种子张量:构造;不带种子的请求填 42
       ├─ 注意力后端:限 fa3 / fa4 / flashinfer / triton / ascend / intel_xpu
       │      └─ flashinfer / intel_xpu:disable_radix_cache = True
       ├─ 通信:关 allreduce 融合;TP>1 时 NCCL_ALGO=allreduce:tree,关自定义 all-reduce 与对称内存
       ├─ logprob:走 log_softmax kernel
       └─ on-policy 目标下:VLM 特征缓存 = 0
```

## Part 8|机制之外:源码里额外读到的

### 8.1 top-k 的哨兵,以及 NPU 的范围

「不裁剪」用 2 的 30 次方的常量表示,而不是负 1 或空值,这样 kernel 不需要特判。NPU 后端的 kernel 只接受 1 到 1024 的 top-k,超出范围整批退回通用实现。

### 8.2 各 rank 取最小值是为了省一次通信,不是为了公平

同步只在有文法或显式打开时做,做的是 all-reduce 取 MIN,比广播便宜,各 rank 本来一致时结果不变。

### 8.3 Gumbel 噪声必须是 float64

注释明说这一步用 float32 会数值不稳,所以整条路径都是 float64,即使分数表本身是 bf16。

### 8.4 返回原始 logprob 是一个环境变量

不是请求级参数,整个服务只能选一种。

### 8.5 on-policy 目标连带关掉 VLM 缓存

缓存的特征是上一次前向算出来的,和本次逐位对齐没有保证。

### 8.6 束搜索的裸行在采样前切掉

宽度为 k 的束搜索请求跑成一个领队请求加 k 减 1 行没有请求对象的裸行,裸行在分配前拼到批尾,在采样前从分数表里切掉,由束搜索自己按联合分数选。整组共享 KV 的槽由组统一释放。日志里的请求数不包含裸行。

### 8.7 采样支持集的正确性不变量

返回裁剪后支持集那条路径在裁剪的同时抓一份过滤后的概率,注释要求它和融合采样 kernel 在截断、并列、联合支持集三件事上语义一致,否则返回的权重和实际采样的分布对不上。

### 8.8 min-p 与种子互斥的原因是没重归一化

PyTorch 后端的排序路径在 min-p 之后没有把概率重归一化,直接取对数做 Gumbel-max 会得出错的分布,注释写明了这一点并用断言挡住,而不是静默出错。

## Part 9|对比与收益账

### 9.1 和 vLLM 比

| 维度 | vLLM | SGLang |
|---|---|---|
| 管线顺序 | 白名单 → 偏移 → 禁词 → 惩罚 → 温度 → 裁剪 | 自定义处理器 → 惩罚 → 文法掩码 → 偏置 → 温度 → 裁剪 |
| 惩罚的记账 | 两套,一套回 CPU 一套不回 | 累积在 CPU 端,变成两张张量在前向前加乘 |
| 采样 kernel | 自写 top-k/top-p 融合 kernel,不排序 | flashinfer 融合 kernel 或 PyTorch 排序法,二选一 |
| 带种子抽样 | 先批量填再逐行覆盖 | 只在确定性模式下构造种子张量;默认种子 42 |
| TP 上的 token 一致 | 见 vLLM 采样机制章 | 默认不同步,有文法时取 MIN |
| 文法编译 | 线程池异步,请求进阻塞等待态 | 线程池异步,请求进独立的文法队列,各 rank 取交集,失败也缓存 |
| 跳跃前填 | 无 | 接口在,调度器未接线 |
| 批不变 | 换 kernel,注意力 split 钉 1 | 用算子注册机制换 aten 算子,注意力限 6 个后端,部分后端下关前缀缓存 |

### 9.2 管线的账:一步里省掉的三次同步

全批贪心时不做 softmax 和裁剪,一次 argmax;惩罚的两张张量上一步准备好,前向后一次加一次乘;各 rank 不做 all-reduce 统一 token。对应的三条限制:批里混进一个随机请求就掉回管线;惩罚器在 CPU 上逐 token 累积;rank 分叉时挂起而不是报错。

### 9.3 文法的账:编译摊销,等待有上限

编译一次 10 毫秒到几秒,同一个 schema 的第 2 到第 n 个请求不付;失败也缓存,坏 schema 只付一次。每步固定开销是填一行位掩码加一次搬运,只有带文法的行付。等待上限 10000 轮乘以 max(5 毫秒, 一步前向),至少 50 秒。agent 负载里 TTFT 是双峰的:缓存命中的请求和普通请求一样,第一次见到的 schema 多付一次编译。

### 9.4 确定性的账:关掉了什么

批不变 kernel 慢于厂商库,文档没给比例。可以数清楚的是关掉的东西:flashinfer 采样 kernel、all-reduce 融合、自定义 all-reduce、对称内存 all-reduce、min-p 裁剪、flashinfer 与 intel_xpu 后端下的前缀缓存、on-policy 目标下的 VLM 缓存。前缀缓存那一条在多轮负载上最贵。

### 9.5 TP 同步的账:一次 all-reduce 对一次挂起

默认不同步省的是每步一次 all-reduce,一个 int32 向量,批 256 是 1 KB,通信本身不到 10 微秒,省的主要是一次 kernel 发射和一次流同步。付的是分叉后整个 TP 组挂起,没有超时。有文法时分叉概率高到不值得省,所以自动同步。

## Part 10|参数、开关与排障

### 10.1 关键参数

| 参数 | 默认 | 作用 | 怎么调 |
|---|---|---|---|
| temperature / top_k / top_p / min_p | 1.0 / 全词表 / 1.0 / 0 | 分布尖锐度与候选集 | 温度低于 1e-6 即贪心;确定性下 min_p 不可用 |
| frequency_penalty / presence_penalty / repetition_penalty | 0 / 0 / 1.0 | 加法、加法、乘法惩罚 | 重复严重先试 repetition 1.05 到 1.2;力度不随温度变 |
| min_new_tokens | 0 | 到达前压住 EOS | 防止秒答 |
| stop / stop_token_ids / stop_regex / no_stop_trim / ignore_eos | 空 | 判停 | 正则每步在尾部跑,别写贪婪匹配 |
| json_schema / regex / ebnf / structural_tag | 空 | 四选一的约束 | 提示词里同时说明格式,约束只保证合法不保证合理 |
| grammar_backend | xgrammar | 服务级文法后端 | 只在 xgrammar 不支持时换 |
| sampling_backend | 有 flashinfer 就 flashinfer | flashinfer 或 pytorch | 确定性模式自动改 pytorch |
| sampling_seed | 不填;确定性下填 42 | 带种子的可复现抽样 | 同 prompt 多回答时每条不同种子 |
| logit_bias | 空 | 按 token 加分 | 在掩码之后,救不回被掩的 token |
| custom_logit_processor | 空 | 按请求的处理器类与参数 | 思考预算用内置的 |
| enable_deterministic_inference | 关 | 换批不变算子、限注意力后端、强制 pytorch 采样、改通信 | RL 或复现问题时开;Blackwell 上显式指定 fa4 或 triton 才能保住前缀缓存 |
| rl_on_policy_target | 空 | logprob 与训练框架对齐,并自动开确定性 | 只在做 on-policy RL 时设 |
| SGLANG_SYNC_TOKEN_IDS_ACROSS_TP | 关 | 每步各 rank 同步 token | 多卡挂起时开着排查 |
| SGLANG_GRAMMAR_MAX_POLL_ITERATIONS / POLL_INTERVAL | 10000 / 0.005 秒 | 文法队列等待上限 | 编译要几分钟的 schema 才需要调 |

### 10.2 排障:症状先查什么

| 症状 | 先查 | 然后 |
|---|---|---|
| 「Tokens not accepted」 | 自定义处理器或偏置是否在掩码之后改了分数 | 推测解码的回滚 |
| 多卡挂起且请求带文法 | 开强制同步的环境变量确认是 rank 分叉 | 查 kernel 确定性 |
| 开了确定性还是不一致 | 注意力后端是否 6 个之一;采样后端 | 有没有请求带 min_p |
| 开了确定性后多轮 TTFT 变差 | 启动日志「radix cache is not compatible」 | 换 fa3、fa4 或 triton |
| 确定性下 n 条采样全一样 | 没给种子 | 每条给不同的 sampling_seed |
| 约束请求迟迟不开始 | 文法队列,编译慢的 schema 在那里等 | 最长 50 秒以上才判失败 |
| 同样参数不同温度下重复程度不同 | 不是 bug,惩罚在温度前 | 按温度分别调惩罚 |
| logit_bias 像没生效 | 那个 token 是否被 schema 掩掉 | 改 schema |

### 10.3 常见误区

- 温度为 0 不等于确定性,batch 组成才是主要变量,前缀命中与否也是。
- logit 偏置改不了被文法掩掉的 token。
- 跳跃前填在基准上不生效,约束解码每步一个 token。
- 各 rank 默认不同步采样结果,依赖 kernel 确定性;这是性能取舍,不是 bug。
- 确定性模式下不带种子不等于随机,而是所有请求共用种子 42。
- 确定性只按一个开关,但它连带关掉的东西不止一样,启动日志里的警告要逐行看。
- 束搜索的成员行不是请求,日志里的请求数不包含它们。
