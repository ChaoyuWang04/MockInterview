# SGLang 13|采样、约束解码与确定性

采样的数学、约束掩码的原理、批不变性为什么难,vLLM 解读的「采样机制」「结构化输出」「确定性推理与批不变性」三章已经讲透。这一页只说 SGLang 在这三件事上各自遇到的问题、它的解法、以及它和 vLLM 不一样的地方。三件事互不依赖。每一条对应源码的哪个文件与符号,见代码索引页。

## 一、采样管线

**问题。** 前向交出一张每行 10 多万列的分数表,要从每一行里挑一个 token。挑之前要做惩罚、掩码、偏置、温度、裁剪几步,每一步都在改同一张表,顺序换了语义就变,而且不报错。这一步又在每步的最末端,这里多一次 GPU 等 CPU,整条流水线就停一次。

**解法。** 顺序写死在代码里,不给调用方选:自定义处理器、惩罚、文法掩码、偏置、温度、softmax、裁剪、抽一个。两处顺序决定语义:惩罚在温度之前,所以惩罚力度不随温度变;偏置在掩码之后,所以偏置救不回被掩掉的 token。为了不停流水线:整批都是贪心时一次 argmax,不做 softmax 也不裁剪;惩罚要用的两张张量在上一步就算好;多卡时各 rank 各自采样,默认不互相对答案,省一次通信。

## 二、约束解码

**问题。** 让模型自由生成再解析 JSON,解析失败是常事。另一个问题是文法要先编译成对整个词表的自动机,10 毫秒到几秒,放在调度循环里编译,一个大 schema 会让所有请求等它。

**解法。** 每步采样之前,用文法算出当前位置允许哪些 token,其余置负无穷,模型只能从合法的里面挑。编译交给线程池,带约束的请求先进一个专门的队列,编译完了才进等待队列;同一个 schema 第二次来直接用缓存,编译失败的也缓存,同样的坏 schema 下次直接拒。带思考段的模型思考时不加约束,思考结束后再收紧。每步只出一个 token,「跳过固定字符」的接口在代码里但调度器没接。

## 三、确定性

**问题。** 同一个请求这次和 3 个请求拼在一起、下次和 300 个拼在一起,GPU 里矩阵乘的加法顺序不同,分数在小数点后第 7 位不同,某一步选中的 token 就翻了。温度 0 也一样。对聊天服务这是偶尔答案不同,对 RL 训练这是推理侧的 logprob 和训练框架对不上。

**解法。** 一个开关。开了之后:矩阵乘、log_softmax、归一化这些算子换成「加法顺序只看形状、不看批里有几行」的版本;注意力只能用 6 个后端;抽样改用种子加位置算出来的噪声,和批里排第几无关;logprob 走一条和训练框架逐位对齐的路径。设了 RL 的 on-policy 目标,这个开关自动打开。

**要知道的三件事。** 这个开关连带关掉一串东西:flashinfer 的采样、通信融合、min-p 裁剪,以及在 flashinfer 后端下的前缀缓存,Blackwell 卡上不指定后端默认就是 flashinfer,多轮对话会明显变慢。不带种子的请求默认种子 42,所以温度 0.8 跑 100 次是同一个回答,要多条不同的回答每条给不同的种子。批不变的算子比厂商库慢,文档没给比例。

## 四、和 vLLM 不一样的四处

1. **管线里掩码的位置。** vLLM 把白名单和禁词放最前面,SGLang 把文法掩码放在惩罚之后、偏置之前。
2. **多卡要不要对答案。** vLLM 见它的采样章;SGLang 默认不对,靠 kernel 确定性,只在请求带文法时对一次,对的方式是取各卡里最小的那个 token id。
3. **带约束的请求排哪。** vLLM 进阻塞等待态,SGLang 进一个独立的文法队列,各卡编译结果取交集。
4. **确定性怎么换算子。** vLLM 换 kernel 并把注意力的 split 钉成 1;SGLang 用 PyTorch 的算子注册机制整体替换 aten 算子,注意力限 6 个后端,部分后端下关掉前缀缓存。
