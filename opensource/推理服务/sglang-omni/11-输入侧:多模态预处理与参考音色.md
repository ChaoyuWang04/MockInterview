# 输入侧:多模态预处理与参考音色

同一段参考声音被反复使用时,怎样少做重复编码,又不把改过的音频或新注册的音色认成旧数据——这一章回答这个。说法都在源码基准 `89e60d0bf2`(tag `v0.1.6`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

多模态请求带来的并不总是模型能直接使用的张量。远程图片要下载,音频要解码和重采样,视频要抽帧;语音克隆还要从参考录音提取说话人特征,某些模式还需要参考音频码。

当许多请求共用同一段参考声音时,每条请求都重新编码,会把相同计算堆在首音频之前。简单地「按文件名缓存」又不够:文件内容会变,参考文字和编码模式也可能不同。**复用的关键不是有没有缓存,而是哪些输入真的对应同一份产物。**

## 二、解法

先把资源加载与模型计算分开。公共预处理工具负责把路径、URL、Base64 等来源转换成波形、图像或视频帧;模型侧再组织自己的输入与参考特征。下载和解码可以异步组织,但它们并不会因此变成跨请求的模型编码合批。

参考编码服务把一次计算的身份拆清楚:模型身份、编码器身份及配置、产物类别、输入身份和影响产物的选项共同组成键。以 Qwen3-TTS 的临时参考音频为例,参考文字与是否只提取说话人特征也进入键,不能仅凭声音相同就复用所有产物。

同键并发第一次到来时,只让一个请求负责计算,其余请求等待同一份结果。这就是 **single-flight**:合并的是正在进行的重复工作。已经完成的结果则进入有容量上限的 LRU 缓存。编码完成后还要重新确认输入身份;身份已经变了就不写入长期缓存,失败也会解除等待关系,把错误交给等待者。

![临时参考请求在同一编码服务实例内合并同键工作,注册音色则以名称和版本区分缓存;覆盖音色产生新版本,旧键不再命中新请求。](/opensource/sglang-omni/11a-reference-identity.svg)

**注册音色是另一种生命周期。** 服务将上传的录音及元信息保存成文件,为音色分配版本身份;模型侧缓存使用音色名称、版本、模型类别和产物类别。覆盖同名音色会更新版本,删除则移除注册记录和文件,并清理当前进程对应的音色缓存。

这两条路径不能混为一谈。在 Qwen3-TTS 中,临时参考走 single-flight 服务;注册音色未命中时直接执行编码钩子,随后写入版本缓存。缓存对象也在各自进程内,不是所有 Stage 共享的一张跨进程表。

## 三、代价

**确认身份也要花时间。** 通用媒体键对 URL 使用地址字符串,对本地文件使用采样内容;专门的参考文件键则使用完整内容摘要,再用文件大小、修改时间、状态变更时间和采样哨兵减少重复读盘。二者不能互相替代,更不能笼统地说「所有 URL 都按下载内容缓存」。例如 Higgs 的参考编码键取自解码、重采样后的实际波形,这是模型调用链自己补上的内容身份。

**命中节省计算,占用的内存仍要受控。** 条目数或字节预算达到上限后淘汰最久未用项,单份产物超过字节预算就不保留。Qwen3-TTS 的临时参考服务还绑定模型与包装器对象,替换所属对象时会重建服务,不能将进程内热缓存当成持久资产。

**持久音色不等于持久特征。** 重启能从音色文件恢复注册记录,模型特征缓存仍可能是冷的。覆盖时清理的是当前缓存对象,其他进程里的旧版本产物可能继续占内存直至淘汰;新请求携带新版本,因此不会把它当成新版命中。

Encoder 怎样把不同输入攒成批,见 05 章;本章只说明同键复用与输入身份。上传、查询、删除的服务协议归 12 章,模型如何实现编码钩子归 13 章。

## 四、与 vLLM-Omni 的输入适配分工

两边都要把外部输入整理成模型可消费的数据。vLLM-Omni 的输入适配层复用上游 vLLM Renderer,在其基础上保留 Omni 的附加信息和阶段载荷;SGLang-Omni 在本章展示的是公共媒体加载工具,以及模型侧调用的参考编码服务。

另一个容易误比的地方是「预处理」这个词。vLLM-Omni 还有运行器在每一步调用的模型预处理钩子,会显式传入当前是 prefill 还是 decode、已经计算到哪里。这属于运行期输入准备,不能拿来直接对应本章的录音下载与音色注册。这里只比较已核到的职责,不据此断言哪边有更多缓存能力。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

下表前 4 项遵循这条规则;请求字段随请求生效。内部缓存预算单独列为实现默认值,不把它们伪装成可直接传入的命令行选项。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--allowed-local-media-path` | 启动命令,TTS 参考媒体加载 | 不设 | 设置后启用限定目录内的 `file://`;裸路径也受该目录约束 | 请求的路径校验错误 |
| `--allowed-media-domain` | 启动命令,可重复 | 不设域名列表 | 设置后仅允许匹配域名;TTS 仍拒绝解析到私网、回环等地址 | `Domain ... is not allowed` 或地址类别错误 |
| `SPEAKER_SAMPLES_DIR` | 服务进程环境变量 | `~/.cache/sglang-omni/speakers` | 更换持久音色目录,影响可恢复的注册记录 | 音色列表与启动恢复日志 |
| `SPEAKER_MAX_UPLOADED` | 服务进程环境变量 | 1000 | 限制注册数量,不限制模型特征缓存字节数 | 上传限额错误与恢复跳过日志 |
| `ref_audio` / `ref_text` | TTS 请求 | 按模型任务要求提供 | 临时参考内容与文字影响编码身份;Qwen3-TTS 的完整克隆模式要求参考文字 | 参数校验、参考编码统计 |
| `x_vector_only_mode` | 支持该字段的 Qwen3-TTS 请求 | 未显式设置时,无参考文字为 `true`,有参考文字为 `false` | 设为 `true` 只提取说话人特征,省去参考音频码编码;音色条件也随之改变 | 输入校验与编码路径,不要只比延迟 |
| `voice` | TTS 请求 | 按模型预设 | 使用注册名称时解析到对应版本及参考音频 | 列表中的 `uploaded_voices` 与 `created_at` |

**路径的准确边界。** 对这里核对的 TTS 参考媒体入口,不设本地允许目录时,`file://` 被禁用,裸本地路径仍按受信本地调用方式读取;一旦设置目录,两者都经过解析后的目录包含性校验。不能把「禁用 file URL」理解成「禁用所有本地文件」。公共图像和音频便捷加载函数还有直接读取裸路径的分支,不要把 TTS 入口的策略外推成所有模型入口的统一保证。

**这些容量是代码默认值,不是通用启动参数。**

| 缓存或记录 | 实现默认 | 实际限制 | 观测 |
|---|---|---|---|
| Qwen3-TTS 临时参考编码 | 256 项、64 MiB | 属于该参考服务实例;有等待超时 130 秒 | 日志前缀 `Qwen3-TTS ad-hoc reference`,统计 `hits`、`misses`、`merged`、`failed`、`evictions` |
| 进程内注册音色产物 | 512 MiB | 所在进程的音色产物缓存,不是全服务总预算 | 音色列表的 `cache_stats` 只反映该列表使用的缓存对象 |
| 上传参考录音 | 1–30 秒 | 解码后检查单声道、时长与非静音,不是任意长音频存储 | `audio_sample` 校验错误 |

**典型使用组合。** 以下均接在已验证可运行的模型启动命令后;模型相关请求以 Qwen3-TTS Base 为例。

| 场景 | 怎么起或请求 | 拿什么换什么 |
|---|---|---|
| 本地文件作为临时参考 | 启动命令加 `--allowed-local-media-path /srv/refs`,请求 `ref_audio` 指向该目录中的文件,附对应 `ref_text` | 限定读取范围,重复同内容与同选项可复用参考计算 |
| 远程参考来源固定 | 启动命令加 `--allowed-media-domain media.example.com`,请求 `ref_audio` 使用该域名的真实音频 URL | 限定来源;媒体仍需按入口加载,不能把地址不变当成内容永远不变 |
| 多请求复用已登记的音色 | 启动前设 `SPEAKER_SAMPLES_DIR=/srv/voices`,上传后请求 `voice` 使用返回名称 | 持久化录音与注册身份,换取目录维护成本;重启后特征可能需要重新编码 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 同参考并发仍重复计算 | 是临时参考还是注册音色,是否进入同一个服务实例 | 再查参考文字、模式和模型身份是否使键不同 |
| 热请求突然变慢 | 参考服务的 `evictions`、进程是否重启或模型对象是否替换 | 区分容量淘汰与服务重建,不要先增加模型并发 |
| 文件替换后仍怀疑旧音色 | 请求实际使用的是路径、临时内容还是注册名称 | 注册名称应核版本;临时参考核内容键,通用媒体键另行判断 |
| 上传成功但首次生成慢 | 注册记录是否存在,模型特征是否尚未生成 | 上传保存录音并不预热所有模型侧编码器 |
| 编码失败后持续报错 | `failed` 与本轮编码异常 | 失败不作为成功产物缓存,先修复输入或依赖,无需靠改文件名逃避缓存 |

## 六、常见误区

**「同名 voice 覆盖以后,所有进程的缓存立刻被清空。」** 删除和覆盖调用的是当前进程的缓存对象,不能把函数名中的全局理解成跨进程广播。避免新版误用旧产物还依赖请求携带的新版本身份。

**「缓存命中率不高,所以 single-flight 没起作用。」** 同时到来的重复请求可能都赶在首份结果写入前,计入的是 `merged`,不是 `hits`。只盯命中计数会漏掉已经省掉的重复工作。

**「内容相同就一定能命中。」** 编码产物还受参考文字、编码模式和模型身份影响。Qwen3-TTS 临时参考把这些选项编入键,修改参考文字后重新计算并不一定是缓存失效故障。

**「音色列表里的缓存统计就是模型编码命中率。」** 列表从服务持有的缓存对象取数,它还会缓存录音的传输表示。模型侧进程有自己的对象,应结合参考编码日志看,不能拿一份统计代表整条管线。
