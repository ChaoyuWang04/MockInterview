# TensorRT-LLM 06|推测解码

小 batch 的 decode 被访存卡住时,草稿先猜、目标一次核对能摊薄搬权重的成本;高并发开着草稿反而更慢。

说法都在源码基准 `59f5c47f`(tag `v1.2.1`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

decode 一步只出一个 token,却要把整份目标权重从显存搬一遍。小 batch 时 GPU 大部分时间在等内存,每个 token 的间隔被访存拖死。

最天然的补救是让便宜的草稿先猜一串,目标模型一次前向把整串核完,搬一次权重出多个 token。麻烦在账怎么算:**草稿本身也要跑,核错了前面全白算。** 并发一大,每步要核的位置是「在跑的条数 × 草稿长度」,decode 从等内存变成等算力,再挂草稿就是整批一起多付一次前向,吞吐和每个 token 的间隔都会比不开更差。

文档写明:现实现在低并发才看得到加速;默认每条请求一份定长草稿链,没有「这一步临时不猜」的请求级开关。

## 二、解法:草稿出候选,目标一次核对

最天然的直觉:另起一个小模型串行猜,大模型逐步验。实际不吃亏的做法是把「出候选」和「一次核对」收进同一套执行器循环。没挂推测配置就是普通 decode,不出候选。挂上之后,每条请求按草稿长度铺一条链(树是可选加钱,不是默认),目标模型把这些位置摊进同一次前向;对上的收下,错的截断,全对时顺带白送一个。

![低并发时绿框出一条定长候选链,紫框目标一次前向核对,黄框收下并白送;高并发灰框走虚线,把草稿长度压到 0 或把门禁关掉,不再进绿框](/opensource/TensorRT-LLM/06a-draft-verify.svg)

候选从哪来,热路径就三类,不要当成等量算法清单。一是训练好的草稿头,吃目标若干层的隐状态,和目标装在同一套引擎里。二是模型自带的下一 token 模块,权重往往已经在目标检查点里,不必另找一份完整小模型。三是不跑模型,按已经出现过的前缀在池子里查。其余并行草稿、用户自写草稿、只存隐状态给训练用的模式,不是这一页的默认热路径。

PyTorch 后端只认三代草稿头,一代名字会被改写成三代并打警告,旧检查点对不上。查表和独立草稿模型默认不支持重叠调度,执行器会警告后把重叠关掉;草稿头和自带模块可以跟重叠一起跑。

高并发不是没人管。可以按在跑条数把草稿长度往下压,超过表上最后一档就变成 0,也就是这步不猜;也可以设一条滚动接受率门禁,窗口内均值掉到阈值以下就**永久**关掉推测,要重新拉起才回来。默认这两样都不开:配置是空就不推测,挂上了就一直猜到你自己把长度压掉或把门禁打响。

为什么实际不吃亏:小 batch 时目标前向的大头是搬权重,多核几个位置几乎白送;草稿比目标便宜,平均收下超过约 2 个 token 就划得来。批大了这笔账反过来,所以加速只在低并发成立。

## 三、代价

**默认就是关的。** 推测配置为空时整条路径不在循环里。挂上要草稿权重或一张查表池,还要按草稿长度多留 KV。

**草稿长度写死在启动时。** 每条请求一份定长链,没有按请求关掉。要随并发改长度,得自己给一张批大小到草稿长度的表,或给一个并发上限;不给就一直猜。

**接受率决定盈亏。** 高温采样、草稿和目标词表不一致、开放式写作,核错就变成「目标每步算得更多」。文档把草稿和目标必须同一套分词器写进独立草稿那条。

**有的组合会关重叠或直接拒。** 查表和独立草稿会警告后关掉重叠;一代草稿头名字在 PyTorch 上不能当真用;拒绝采样默认关,查表没有草稿分布,开了会在校验处失败。核库注意力和「草稿、目标各一份 KV」的一体引擎路径互斥。

**门禁是单向的。** 滚动接受率一旦打穿阈值,本进程里推测不再回来。

## 四、草稿怎么出候选、一次核多少、高并发划不划算

这一页比的是草稿怎么出候选、目标模型一次核多少、高并发时划不划算。

| 维度 | TensorRT-LLM | vLLM | SGLang |
|---|---|---|---|
| 默认开不开 | 配置为空就不猜 | 要显式开推测器 | 要显式选算法 |
| 草稿默认长什么样 | 每条请求一条定长链 | 一条链,宽度是一个 k | 步数、每步分支、验证宽度三个旋钮,可成树 |
| 高并发怎么办 | 文档说低并发才划算;可选按批压草稿长度,或接受率门禁永久关 | 按批大小查静态表;异步调度只对白名单算法开放 | 重叠是默认骨架;自适应可把步数降到 0 |
| 草稿从哪来 | 热路径是草稿头、自带下一 token 模块、前缀查表;其余不按等量热路径写 | 两套实现并存,提议者和推测者目录都叫同一名字 | 八种内建算法走同一套重叠工人 |
| 核对默认怎么判 | 非贪心批默认精确匹配;拒绝采样要另开且是原型 | 默认拒绝采样,草稿常贪心,比值退化成目标概率 | 默认不看草稿分布,接受概率就是目标给的那个 |

重心在本项目:没挂配置就是不推测;挂上之后默认一条定长链,加速写在低并发上。高并发要自己压长度或接受门禁,不会像对面那样默认把步数降到 0。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `speculative_config` · 要不要推测、用哪种草稿 | 启动(LLM 构造或 yaml 的 `speculative_config`) | 空,不推测 | 填配置才出候选;yaml 要带 `decoding_type` | 启动日志是否加载草稿;指标 `trtllm_speculative_config_info` |
| `decoding_type` · 草稿种类 | 上面那份配置里 | 无,必填(走 yaml 时) | `Eagle3`:草稿头;`MTP`:自带模块;`NGram`:查表;`DraftTarget`:独立小模型。`Eagle` 在 PyTorch 上改写成 `Eagle3` 并警告 | 警告 `only 'Eagle3' is supported` |
| `max_draft_len` · 一条链猜几个 | 配置 | 无,必填且大于 0 | 调高:一次核得更多,KV 多留,接受率低时更慢 | `trtllm_spec_decode_acceptance_length` |
| `speculative_model` · 草稿权重 | 配置 | `MTP` 常空,用目标里的模块;`Eagle3` / `DraftTarget` 必填 | 填 Hub 名或本地路径 | 启动是否去拉草稿检查点 |
| `max_concurrency` · 超过这个批大小就不猜 | 配置 | 空,一直猜 | 写成一张「该批大小 → 当前草稿长度」的表,再大就 0;不能和下一张表同时给 | 大 batch 时草稿长度是否掉到 0 |
| `draft_len_schedule` · 按批大小改草稿长度 | 配置 | 空 | 例如 `{4:4, 8:2, 32:1}`,超过 32 不猜;最小档必须等于 `max_draft_len`;会自动打开 CUDA Graph 补齐 | 日志 `Automatically enabling cuda_graph_config.enable_padding` |
| `acceptance_rate_window_size` / `acceptance_rate_threshold` · 滚动接受率门禁 | 配置 | 空或 0,门禁关 | 窗口内均值低于阈值则永久关推测 | 日志 `[SpeculationGate] Speculative decoding disabled` |
| `use_rejection_sampling` · 按草稿分布做拒绝采样 | 配置,原型 | 关 | 开:非贪心批走拒绝采样,要 FlashInfer;查表和无分布的增强互斥 | 启动 `use_rejection_sampling=True is not supported` |
| `use_dynamic_tree` · 每层展开多个候选 | `Eagle3` / `MTP` 配置 | 关 | 开:树验证,要 `dynamic_tree_max_topK`;滑窗注意力和 MLA 当前不支持 | 启动是否走到动态树工人 |
| `max_matching_ngram_size` · 查表时前缀多长 | `NGram` 配置 | `2` | 调高:更容易命中,池更大 | 接受长度 |
| `is_public_pool` · 查表池是否跨请求共享 | `NGram` 配置 | 开 | 关:每条请求自己的池,结束就清 | 重复负载的接受率 |
| `disable_overlap_scheduler` · 关掉重叠 | 启动 | 关(重叠开) | 查表和独立草稿会警告后强制打开这一项 | 日志 `Disable overlap scheduler for speculation mode` |

**怎么看。** 一是配置信息指标 `trtllm_speculative_config_info`。二是计数:`trtllm_spec_decode_num_draft_tokens_total`、`trtllm_spec_decode_num_accepted_tokens_total`、`trtllm_spec_decode_acceptance_length`、`trtllm_spec_decode_draft_overhead`;还有按位置的接受计数。三是门禁那行 `Speculative decoding disabled`。接受长度长期低于 2,低并发也该换草稿或关掉。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡低并发、手上有三代草稿头 | `trtllm-serve meta-llama/Llama-3.1-8B-Instruct --config eagle3-spec.yaml`,yaml 写 `speculative_config: {decoding_type: Eagle3, max_draft_len: 3, speculative_model: yuhuili/EAGLE3-LLaMA3.1-Instruct-8B}` | 用一份草稿头换小 batch 的 decode 间隔;高并发不压长度就会更慢 |
| 目标自带下一 token 模块(DeepSeek 一类) | `python -c "from tensorrt_llm.llmapi import MTPDecodingConfig; from tensorrt_llm import LLM; LLM('deepseek-ai/DeepSeek-V3', speculative_config=MTPDecodingConfig(max_draft_len=3))"` | 零额外完整小模型换核对宽度 3;模块层数要和检查点一致 |
| 代码补全、前后文重复多、零草稿权重 | `trtllm-serve Qwen/Qwen2.5-7B-Instruct --config ngram-spec.yaml`,yaml 写 `disable_overlap_scheduler: true` 和 `speculative_config: {decoding_type: NGram, max_draft_len: 3, max_matching_ngram_size: 4, is_public_pool: true}` | 用查表换重复负载的接受;重叠会被关,开放式写作接受率低 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 开了推测比不开更慢 | 并发是否已经不小;接受长度是否低于 2 | 加 `draft_len_schedule` 或 `max_concurrency`;换草稿或关掉配置 |
| 启动警告 `only 'Eagle3' is supported` | yaml 是否写了 `Eagle` | 改成 `Eagle3`,并换三代草稿检查点 |
| 日志 `Disable overlap scheduler for speculation mode` | 是不是查表或独立草稿 | 接受重叠被关,或改走草稿头 / 自带模块 |
| `[SpeculationGate] Speculative decoding disabled` | 窗口和阈值 | 接受率确实差;要再开只能重启 |
| `use_rejection_sampling=True is not supported` | 是否查表或开了后缀自动机增强 | 关掉拒绝采样 |
| 独立草稿几乎全拒 | 草稿和目标是不是同一套分词器 | 换配对的草稿 |
| CUDA Graph 形状对不上 | 是否给了 `draft_len_schedule` 却关掉补齐 | 让它自动打开补齐,或自己把档位写进 batch 列表 |

## 六、常见误区

- **以为默认已经在猜。** 推测配置默认是空。没挂就是普通一步一 token。
- **以为高并发也能靠草稿提吞吐。** 文档把加速写在低 batch。批大了 decode 已经不闲,草稿是额外前向。
- **以为写了一代草稿头名字就能用旧检查点。** PyTorch 只认三代,一代名字只是改写成三代并警告,权重对不上。
- **以为查表免费。** 不跑草稿模型,但每步仍按草稿长度核目标,还要关重叠;开放式写作经常更慢。
- **以为接受率门禁会自动再开。** 它是单向永久关,窗口和阈值都要自己设,默认根本没装。
- **以为拒绝采样是默认正确性开关。** 默认精确匹配;拒绝采样是原型,查表没有草稿分布,开了会拒。
