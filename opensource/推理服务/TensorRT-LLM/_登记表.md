**这个项目和 TensorRT SDK、和 vLLM 讲稿都不一样的四处**,动笔前先读:

1. **它不是 `projects/推理服务/TensorRT`。** 那是 NVIDIA 的 TensorRT SDK。本仓是 LLM 推理与服务栈,入口是 `tensorrt_llm.LLM` 与 `trtllm-serve`。

3. **VisualGen 是旁边的扩散生成栈,不是 LLM 后端。** 官方自己把 API、参数、输出和 `DiffusionExecutor` 分开。本解读不立章,总览给入口,覆盖率表记理由。
4. **不抢参照、不抄 sglang/vLLM 的章数。** 页头定位本章的问题。第四段对照列是 vLLM 与 SGLang(大厂大规模在用的推理引擎);AutoDeploy 不是对等引擎,不进对等列。

### 对照用的同领域仓库

第四段对照对象是同类推理引擎 **vLLM** 与 **SGLang**,都是大厂大规模在用。本站 vLLM 是讲稿例外、SGLang 已过门;关于它们的断言核已发表解读或快照,核不动就不写。TensorRT SDK、AutoDeploy、FlashInfer、NIXL、Dynamo 不是对等引擎:SDK 是另一产品,AutoDeploy 是本仓第二条前端,其余是核库或编排,总览可一句分界,不进对照表。

## 二、一句话核心

TensorRT-LLM 是 NVIDIA 的 LLM 推理与服务栈:今天唯一执行后端是 PyTorch 运行时,每 rank 一个 `PyExecutor` 做 IFB（连续批处理）。代码花在注意力与 MoE、执行器、服务层,以及一条尚未成为默认路径的 AutoDeploy 图变换前端。旧的 TensorRT 引擎编译链已经不在。
