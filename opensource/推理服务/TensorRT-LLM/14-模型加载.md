# TensorRT-LLM 14|模型加载

磁盘上的名字、形状和运行时要的张量对不上时,加载会装错数;多卡再各读一遍盘,启动被读盘拖死。本基准已经删掉离线转换加引擎编译,权重直接进 PyTorch 运行时。

说法都在源码基准 `59f5c47f`(tag `v1.2.1`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

坏的是**启动时间**和**算得对不对**。仓库按训练时的模块名存,运行时为了少几次矩阵乘会把查询、键、值融成一块,门控和上投影也并成一块。映射表对不上时,缺的键会在装载时断言炸掉;更糟的是键都在、切法和拼接却错了——进程活着,前向用错权重,答案静默变差。

另一头是读盘。单机 8 个 rank 各把同一份安全张量再读一遍,网络盘上流量按卡数翻倍,70B 级要付 8 份。同机再起第二个实例,又是一份主机内存加一份显存。旧习惯还想先跑转换脚本再编译引擎;那条链在本基准已经删掉,再走只会起不来。

## 二、解法:四种插件拼一种格式,读盘和映射拆开

最天然的直觉:一种磁盘格式对应一个加载器。本项目把它拆成四件,由总装加载器捏在一起:配置解析器把仓库配置收成运行时模型配置;权重加载器只负责把字节从盘读进主机;权重映射器按架构把名字改掉、把该融的融上、按并行切好;总装加载器对外只暴露「读配置、读权重、交出已初始化的映射器」。内建格式是 HuggingFace;ModelExpress 挂在同一套总装上,先尝试从正在跑的实例点对点搬权重,搬不成再退回读盘,并不要求另存一份专用 checkpoint。Mistral 原生目录另注册了总装,权重加载器仍可复用 HuggingFace 那套。

默认不写格式时校验会填成 HuggingFace。加载器对象和格式名不能一起给,一起给时对象被丢掉、以格式名为准。新格式要四件都实现;只是存储介质不同,可以只换权重加载器,映射仍用架构注册表。

读盘策略和格式正交。默认自动:兼容的内建 HuggingFace 安全张量走同节点条带预读——各 rank 对文件区间做互不重叠的后台读,先热操作系统页缓存,映射、变形、主机到设备仍走原来那条;其余情况走同步预取。显式点名条带但配置不兼容时打警告并退回同步,启动不失败。进程内还可开一份主机权重缓存,默认只留 1 份,避免二次冷读把主机峰值顶到约两倍。

同机多实例要免重复装卡,走节点共享显存服务:第一个实例按普通路径装进池并提交,后面的实例零拷贝映射,不再读盘。身份对不上时这条路没有退回读盘,直接失败。

![总装加载器把配置解析、读盘、映射三件捏成一种格式;实线是 HuggingFace 热路径。虚线落到同节点条带预读:各 rank 只热互不重叠的文件区间,映射与上卡仍走原路径](/opensource/TensorRT-LLM/14a-four-plugins-one-format.svg)

为什么实际不吃亏:热路径不再经过离线转换和引擎编译,HuggingFace 目录可以直接起服务。映射错在缺键时仍会断言;条带预读只热页缓存,不改张量语义。共享显存把第二份副本从「再读一遍盘」改成「映射别人已经装好的布局」。

## 三、代价

**映射器是格式加架构的积木,不是万能翻译。** 查询键值融合、门控上投影拼接写在映射表里;架构特有的跳过规则(词嵌入绑定时跳过输出头、下一层归一化、LoRA 自定义嵌入)在子类里。用错映射器时,对得上的键会被拷进错误的槽,缺的键才断言。允许部分装载时缺键被跳过,张量保持初始化值,前向照样跑。

**条带预读不是全场景默认生效。** 自定义加载器、非自动的装载格式、点对点路径、已知的部分模型装载、主机内存余量不够、老的二进制权重,都会在启动前退回同步。草稿头、多 token 预测另读一份 checkpoint 时也走同步,因为那次调用留不住读会话。显式点名条带却退回,只打警告。

**共享显存和点对点都有身份门。** 点对点在制品身份建失败时可以退回读盘;共享显存没有这条退路。读后变换资格不够时,点对点不能只给目标模型交变换后的字节。主机常驻权重要求走标准 HuggingFace 自动装载,假权重、只装视觉塔、共享显存、点对点都会拒。

**主机缓存按整份 checkpoint 钉在内存里。** 默认只留 1 份;条目开多,峰值按份数涨。缓存约定只读,原地改权重会被指纹打成未命中。

## 四、四种插件怎么拼一种格式、映射错了会不会静默算错、多副本会不会重复读盘

这一页比的是四种插件怎么拼一种格式、映射错了会不会静默算错、多副本会不会重复读盘。对等列是 vLLM 和 SGLang。

| 维度 | TensorRT-LLM | vLLM | SGLang |
|---|---|---|---|
| 磁盘到运行时几段 | 总装、配置、读盘、映射四件可单换 | 格式名落到加载器类,映射在模型实现里 | 格式枚举落到加载器,量化配置可以整类换掉 |
| 热路径还要不要离线转换 | 本基准已删转换加编译,HuggingFace 直接进 | 直接吃 HuggingFace | 直接吃 HuggingFace |
| 缺键还是错切 | 默认缺键断言;切错、跳过模块可以装上错数 | 严格模式缺键失败 | 远程格式参数不全会警告并静默退回默认格式 |
| 多 rank 读盘 | 默认可走同节点条带预读,一份逻辑副本热页缓存 | 可自动判断文件系统再预取 | 网络盘预取要手动开,开了默认关多线程读 |
| 同机第二份实例 | 共享显存零拷贝;身份不对直接失败 | 多进程各装各的,另有共享方案 | 权重守护进程跨进程映射,指纹不对退出不退回读盘 |
| 正在跑的实例借权重 | 点对点,失败退回读盘 | 视部署 | 内建远程借权重,参数不全静默降级 |

重心在本项目:用四件插件拼格式,而不是恢复已删除的转换加编译。缺键默认炸;真正的静默错来自映射切错和跳过列表。多副本先靠条带预读少付读盘,再靠共享显存少付第二份卡上副本。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `checkpoint_format` | YAML | 空,校验填成 `HF` | `HF`:内建 HuggingFace。`MX`:先点对点再退回读盘,要同时给服务地址,否则启动拒。`mistral` / `mistral_large_3`:原生目录。和加载器对象一起给时对象被忽略 | 日志 `checkpoint_format will be set to HF`;点对点失败后的退回警告 |
| `checkpoint_loader` | YAML / Python | 空,不表示跳过加载 | 空且格式也空:格式被填成 `HF`。自定义总装从这里注入;与格式名同时出现时本项被丢掉 | 启动是否仍走内建 HuggingFace |
| `checkpoint_io_policy` | YAML | `auto` | `auto`:能走条带就条带,否则同步。`native`:强制同步预取。`rank_striped_read_ahead`:点名条带,不兼容只警告并退回,不拒启动 | 日志 `Checkpoint I/O policy: requested=… selected=… activated=… effective=…` |
| `load_format` | YAML | `auto` | `auto`:按 checkpoint 装。`dummy`:随机数测性能。`vision_only`:只装视觉塔。`gms`:走共享显存,连接失败硬错误 | 日志 `Use … GB for model weights`;`gms_config is set but load_format is` |
| `TRTLLM_HF_WEIGHT_CACHE` | 环境变量 | 关(`0`) | 开:进程内按文件指纹缓存整份主机权重,默认最多 1 份 | 二次加载是否不再打满读盘;指纹变了会未命中 |
| `TRTLLM_HF_WEIGHT_CACHE_MAX_ENTRIES` | 环境变量 | `1` | 调高:跨模型缓存,主机峰值按份数涨;非法值视为 0,等于关掉缓存 | 主机内存;警告 `disabling HF weight cache` |
| `mx_config.server_url` | YAML | 配置对象默认就在,地址空 | 地址空且格式是 `MX`:启动拒,不是悄悄读盘。地址有但格式不是 `MX`:只警告,点对点不启用 | 报错缺地址;警告 `not MX` |
| `gms_config` | YAML | 默认对象:`mode` 为 `auto`,`tag` 为 `weights`,套接字空则库按卡解析路径 | 改了套接字、模式或标签但 `load_format` 不是 `gms`:只警告并忽略。是 `gms` 时连不上直接失败,身份不对也不退回读盘 | 警告 `The GMS config will be ignored`;连接失败堆栈 |

**怎么看。** 一是总装计时:`total_model_loading_seconds` 夹住整段;`checkpoint_preparation_seconds`、`weight_population_seconds`、`checkpoint_finalization_seconds` 把读会话、填参数、收尾拆开,草稿头另有一组 `draft_*`。二是显存:`Use … GB for model weights` 是本 rank 权重,不是磁盘文件大小。三是读盘策略那行四个字段:请求、选定、激活、生效;退回原因在 `fallback_reason`。四是映射:缺键是断言而不是 HTTP 4xx;答案变差但启动成功,先怀疑映射切错或开了部分装载。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡、HuggingFace 目录、第一次上线 | `trtllm-serve Qwen/Qwen2.5-7B-Instruct --config checkpoint-hf.yaml`(文件写 `checkpoint_format: HF` 与 `load_format: auto`) | 用四件插件直装换掉已删除的转换加编译;映射错了缺键会断言 |
| 单机多卡、安全张量、网络盘 | `trtllm-serve Qwen/Qwen2.5-32B-Instruct --config checkpoint-io-striped.yaml`(文件写 `checkpoint_io_policy: rank_striped_read_ahead`、`checkpoint_format: HF`、`load_format: auto`) | 用条带预读把同节点读盘收成一份页缓存;不兼容只警告退回同步,主机内存要够 |
| 同机第二份实例、权重已在第一份卡上 | `TRTLLM_HF_WEIGHT_CACHE=1 trtllm-serve Qwen/Qwen2.5-7B-Instruct --config checkpoint-gms-share.yaml`(文件写 `load_format: gms` 与 `gms_config: {mode: auto, tag: weights}`) | 用共享显存零拷贝换第二份读盘;连不上或身份不对直接失败,不要指望退回磁盘 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动要跑转换或编译命令 | 是不是还在用已删除的引擎链 | 改 HuggingFace 目录直起;`backend` 填旧引擎名会报错,见 01 章 |
| 启动断言缺某个投影 | 映射器是不是这个架构的;查询键值是否应融合 | 换对格式与架构;不要开部分装载把缺键藏过去 |
| 启动成功但答案明显差 | 是否切错、跳过了输出头或归一化;缓存指纹是否仍命中旧张量 | 关进程内缓存再装;核对架构名 |
| 8 卡启动读盘像 8 份 | I/O 策略四个字段是不是还停在同步 | 点名条带;自定义加载器、点对点、部分装载都会退回 |
| 点名条带仍慢 | `fallback_reason`;是不是 `.bin` / `.pth`、主机内存不够、草稿另读 | 换安全张量、加主机余量;草稿路径本来走同步 |
| 第二份实例仍读盘 | `load_format` 是不是 `gms`;有没有那条忽略警告 | 两边都写成 `gms` 且标签一致;连不上先查套接字 |
| 格式写成点对点却起不来 | 服务地址空没有 | 补地址,或改回 `HF` |
| 只改了共享显存配置,行为没变 | 装载格式仍是 `auto` | 警告说忽略;把装载格式改成 `gms` |

## 六、常见误区

- **以为还要先转换再编译。** 旧教程全是那条链。本基准已经删掉,热路径是四件插件直装 HuggingFace。再跑旧命令只会找不到入口。
- **以为格式名空着就是不加载。** 空会在校验里填成 HuggingFace。加载器对象空同样不是跳过,只是用内建总装。
- **以为缺键会静默填零。** 默认缺键断言。静默错来自键都在但切错,以及跳过列表。部分装载才跳过缺键,那是增量更新口,不是首次装载默认。
- **以为点名条带就一定条带。** 不兼容只警告退回同步,进程照样起来。要看四个字段的生效值,不要看请求值。
- **以为共享显存配置写上就会共用。** 配置对象启动时就在;不把装载格式改成对应取值,字段被忽略。套接字空也不是关闭,库会按卡解析默认路径。
- **以为点对点和共享显存一样能退回读盘。** 点对点在制品身份建失败时可以退;共享显存连不上或身份不对是硬错误。
- **以为主机缓存能当跨进程守护。** 它钉在本进程主机内存,默认 1 份,只挡同进程二次装。跨进程要用共享显存,不是把缓存条目开到 10–50。
