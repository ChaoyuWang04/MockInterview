# TensorRT-LLM 03|KV 缓存、跨请求复用与连接器

KV 块占满显存时并发上不去;多轮前缀不复用就反复算;显存放不下又没有卸口时只能踢请求重算。

说法都在源码基准 `59f5c47f`(tag `v1.2.1`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

分页注意力把碎片压住了,可块还是要占显存。默认把空闲显存的 90% 划给 KV 池;对话一长、并发一高,池先满,新请求进不了批,已经在跑的也会被踢出去重算。坏的是**并发上限和长上下文的首 token 时延**。

多轮、系统提示、agent 循环里,后一条请求的前缀常常和前一条一模一样。块不进搜索树、不给后来的人共用,前缀每来一次都要再算一遍、再占一份。共享系统提示越长,浪费越大。

显存见底时如果只能丢块、不能卸到主机或外部,命中率跟着掉。反过来,外部存储如果没有插进这块池的口,PD 分离和跨实例共享也接不上。

## 二、解法:块池、填满进树、连接器只是插口

最天然的直觉:KV 按固定大小的块从池里领,用完还回去;填满的块立刻挂到一棵前缀搜索树上,后来的请求先查树,命中了就少算、少占。本项目默认就是这么做的。跨请求复用默认开。

![GPU 块池里空闲块发给请求,写满后挂进前缀搜索树供后来请求复用;主机卸载和连接器是默认关掉的黄框,图上不画箭头](/opensource/TensorRT-LLM/03a-kv-block-reuse.svg)

一块默认装 32 个 token,必须是大于 1 的 2 的幂。同一块里打多层 KV,所以头数和注意力窗口不同的层会拆成不同的池,启动时把显存按比例切开,之后不再改。窗口层的块滑出窗口就会被释放,再挂回树上。

驱逐是带优先级的 LRU:优先级 0 到 100,低的先走;同优先级才看最近用过没有。现在只能踢叶子——没有后代的块。部分命中默认也复用:尾巴对不上时可以拷一份再切。请求还可以带盐,盐不同的前缀互不命中,用来隔租户。

显存放不下时,可以给主机缓存划字节,块被踢出 GPU 之前先拷到主机,树上还留着,命中时再拷回来。磁盘这一层只在第二代管理器上。两者默认都不划。连接器是这块 KV 系统的插口:调度侧决定卸什么、装什么,工人侧搬张量。默认没有实现;登记表里有几套具名预设,也可以自己填模块。挂上连接器后再给主机或磁盘字节数,启动会拒;不设就丢掉这两层,插口自己去外部存。压缩是另一套配件,不改池怎么发、树怎么查。

为什么实际不吃亏:查树和发块是 CPU 上的整数活,相对一步 decode 的 GPU 时间可以淹没。共享的是已经算完的前缀,不是把整段历史再投影一遍。

## 三、代价

**池是启动时买断的。** 空闲显存比例和最大 token 数取更紧的那个。比例给高了,激活和 CUDA graph 余量变薄;给低了,并发先见底。多池时比例切错,有的层先满、有的层空着。

**复用按块对齐。** 分叉落在块中间,没填满的尾巴不能给别人用。默认 32 一格,内部碎片最多差半块。部分复用开拷贝时,命中尾巴要再占一块。

**只能踢叶子。** 窗口注意力下,该踢的不一定是叶子,树可能顶着不该留的块,有效容量变虚。

**连接器不是默认路径。** 挂上之后推测解码、非「保证不踢」的调度会拒;再给主机或磁盘字节数也会拒,不设就丢掉这两层。第二代管理器在复用被关掉时也不许挂连接器:外部送回来的前缀仍会被当真,prefill 跳过那段,生成会漂。部分量化、部分卡型和混合线性模型会自己把复用关掉,这时连接器同样起不来。

## 四、KV 块怎么占、跨请求怎么复用、显存放不下时往哪卸

这一页比的是 KV 块怎么占、跨请求怎么复用、显存放不下时往哪卸。对等列是 vLLM 和 SGLang。

| 维度 | TensorRT-LLM | vLLM | SGLang |
|---|---|---|---|
| 一块几个 token | 默认 32,必须是大于 1 的 2 的幂 | 默认 16 | 默认 1;部分注意力后端会改成 32 或 64 |
| 谁记得前缀还在 | 填满的块进搜索树,按块查 | 按块算哈希查表 | 前缀树,默认可以切到单个 token |
| 跨请求复用默认 | 开;调度器另有一份按命中估预算的开关,关了也不停块复用 | 开前缀缓存 | 开前缀缓存 |
| 显存放不下先往哪 | 默认只踢 GPU 上的叶子;主机和磁盘要显式划容量;连接器是外部插口,默认没有 | 默认关着的 CPU 卸载;分页池本身不接外部产品 | 踢在跑的请求并驱逐树上没人用的节点;分级缓存是另一章 |
| 外部怎么接 | 连接器:调度侧编排、工人侧搬块;具名预设或自写模块 | 引擎内前缀缓存,外接缓存是另一套产品 | 引擎内前缀树,分级缓存是引擎自己的层 |
| 部分命中 | 默认开,可拷一份再切 | 按块,对不上的半块不算命中 | 粒度是 1 时没有半块问题 |

重心在本项目:默认就把填满的块送进搜索树,复用开着;卸到主机、磁盘、外部都要另开。连接器是本引擎 KV 系统的插口,不是另一套缓存产品。vLLM 和 SGLang 的块粒度和树的切法不同,外部产品不拿来当对等列。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `kv_cache_config.enable_block_reuse` · 填满的块能不能给后来请求用 | 启动 YAML / LLM 构造 | `True` | 关:每条请求独占块,前缀重算;部分模型或量化会自己关掉 | 同样系统提示的第二条是否还要完整 prefill |
| `kv_cache_config.free_gpu_memory_fraction` · 空闲显存划多少给 KV 池 | 启动 | `0.9` | 调高:槽变多,激活余量变薄。调低:并发先掉 | 迭代统计里的 KV 块占用 |
| `kv_cache_config.max_tokens` · 池最多存多少 token | 启动 | 空,按比例买 | 和比例同时给时取更紧的那个 | 启动后池容量不再涨 |
| `kv_cache_config.tokens_per_block` · 一块几个 token | 启动 | `32` | 变大:内部碎片变大,命中退到块边界 | 块数 × 每块 token 是否对得上上下文 |
| `kv_cache_config.host_cache_size` · 主机卸载划多少字节 | 启动 | 空,不卸 | 大于 0:踢出 GPU 前先拷到主机,命中再拷回 | 主机缓存命中;挂连接器时启动会拒 |
| `kv_cache_config.disk_cache_size` · 磁盘卸载划多少字节 | 启动 | 空;第二代管理器才用 | 大于 0 必须同时给目录 | 磁盘层统计;挂连接器时启动会拒 |
| `kv_cache_config.enable_partial_reuse` · 半块对上能不能用 | 启动 | `True` | 关:只有整块命中才复用 | 分叉落在块中间时命中长度是否总是块的倍数 |
| `scheduler_config.enable_prefix_aware_scheduling` · 调度要不要按命中估预算 | 启动 | `True` | 关:准入不再给复用打折,块复用仍听上一行 | 重复前缀是否仍少算,只是进批更紧 |
| `kv_connector_config` · 要不要挂外部插口 | 启动 | 空,不挂 | 填具名预设或模块类名;还要复用保持开 | 启动是否报连接器与复用/卸载冲突 |
| `kv_cache_config.event_buffer_max_size` · 块事件缓冲多大 | 启动 | `0`,不缓冲 | 大于 0 且复用开:可拉块存入/踢出事件给路由 | `LLM.get_kv_cache_events` 或服务 `/kv_cache_events` |

**怎么看。** 一是迭代统计里的 KV 段:空闲块、已用块、每块 token 数。二是同样前缀连打两条,第二条的 prefill 是否明显变短。三是事件接口:缓冲打开后才能拉到块的存入和移除;流式推送是原型路径,默认那条拉接口会变成空列表。四是启动报错:连接器又划了主机或磁盘字节、或复用被关掉,应当直接起不来,不要等第一个请求才炸。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡多轮对话,前缀重复多 | `trtllm-serve Qwen/Qwen2.5-7B-Instruct --extra_llm_api_options kv-reuse.yaml`,YAML 里只写 `kv_cache_config: {enable_block_reuse: true, tokens_per_block: 32}` | 用默认块复用换重复系统提示的 prefill;半块分叉仍可能重算 |
| 长上下文把 GPU 池打满,还想留住前缀 | `trtllm-serve Qwen/Qwen2.5-14B-Instruct --extra_llm_api_options kv-host.yaml`,YAML 写 `kv_cache_config: {free_gpu_memory_fraction: 0.8, host_cache_size: 17179869184}` | 用约 16 GB 主机内存换 GPU 被踢掉的块;命中要付一次拷回 |
| 要把块接到外部缓存进程 | `trtllm-serve meta-llama/Llama-3.1-8B-Instruct --extra_llm_api_options kv-connector.yaml`,YAML 写 `kv_cache_config: {enable_block_reuse: true}` 和 `kv_connector_config: {connector: lmcache}` | 用连接器插口换跨进程命中;不要再开主机或磁盘层,也不要关复用 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 第二条相同前缀仍在完整 prefill | 复用是否仍是开;模型是不是自己关了 | 打开复用;混合线性或某些量化不要指望复用 |
| GPU 池很快满,主机还空着 | 主机容量是不是空的 | 给主机划字节,或把空闲显存比例略降给激活留余量 |
| 挂连接器启动失败 | 是否同时划了主机或磁盘,复用是否被关掉 | 只留 GPU 池加连接器;确认管理器没有自己关复用 |
| 命中长度总是 32 的倍数 | 一块几个 token | 接受块边界,或打开部分复用 |
| 窗口模型容量虚高 | 是不是只能踢叶子 | 不要按树上块数当有效窗口容量 |
| 事件接口一直空 | 缓冲是不是 0;是不是改走了流式推送 | 缓冲大于 0 才拉;流式开着时拉接口故意返回空 |

## 六、常见误区

- **以为关掉调度器那份前缀感知就等于关掉块复用。** 那一行只影响进批时怎么估 token 预算。块还在不在树上,听的是复用开关本身。
- **以为连接器是另一套缓存产品。** 它只是这块池的读写插口。没有实现时什么都不搬;具名预设只是把模块名填上。
- **以为默认会卸到主机。** 主机容量默认空着。不划字节,满了就从 GPU 树上踢叶子。
- **以为挂了连接器还能再开主机卸载当备份。** 启动会拒。连接器要的是稳定的 GPU 槽位,卸走再指回来会把外部登记的地址弄乱。
- **以为复用默认关。** 字段默认是开。真正关掉的是部分模型、部分量化和部分卡型自己改的,不是这一页的默认。
- **以为压缩可以当这一页的第四条路径。** 压缩不改块怎么发、树怎么查,容量账仍按未压缩的池来看。
