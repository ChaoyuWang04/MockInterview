# TensorRT-LLM 08|大规模 MoE 与 Wide-EP

细粒度 MoE 把专家整份分到各卡之后，热专家把一张卡打满，all-to-all 让最慢的专家决定整步时间。

说法都在源码基准 `59f5c47f`(tag `v1.2.1`)上核过，「当前」与「默认」都指这组基准。

## 一、核心问题

细粒度 MoE 专家很多、每个专家很小。一张卡装不下全部专家权重，只能按专家整份切开。切开之后，一个 token 要用的那几个专家散在别的卡上，通信是形状每步都变的 all-to-all：派出去一次、收回来一次，这两段跑在网上时 SM 空转。

更要命的是路由天生不均。某几个专家突然变热，持有它们的那张卡算得久，别的卡卡在集合通信的同步点上陪等。**整步时间由最慢的那个专家决定。** 昨天均衡的部署，今天换一批流量就能冒出一张慢卡把整机按住。高并发 decode 的每个 token 间隔和生成吞吐先坏。

## 二、解法:专家和槽位分开，热专家可复制，负载均衡只改路由表

最天然的直觉：专家多就多切几份，每张卡少放几个。本项目允许专家并行度独立给，也可以和专家上的张量并行混切——世界规模那一组卡上，专家并行乘专家张量并行要对上 MoE 那一层看到的规模；两个都空着时，默认专家并行为 1，专家权重跟着张量并行切开。这能把权重大致摊开，但解决不了热专家：一个逻辑专家仍然只落在一张卡上。

Wide-EP 多走一步：**逻辑专家和引擎里的槽位脱钩。** 槽比专家多，热专家可以在多张卡上各占一个槽；路由表把专家编号映射到槽编号。负载均衡改的是这张表，不是模型里的专家编号。离线可以按历史统计把初始摆位写进配置；在线则每若干层搬一次权重。每步前向包在负载均衡的迭代上下文里：可以只记统计、只搬权重，或两者一起。

![四张卡上槽比专家多，热专家 0 同时占卡 0 和卡 2 两个槽；负载均衡用虚线改路由表，token 经 all-to-all 派到持槽的卡再收回，最慢的专家决定整步](/opensource/TensorRT-LLM/08a-expert-slot-eplb.svg)

通信侧，专家并行大于 1 时不再每卡跑完全部 token 再求和，而是按槽做派发与合并。具体走 NVLink 一侧、DeepEP 还是 NCCL 专家通道，由工厂按硬件和配置挑，这一页不展开 kernel。为什么实际不吃亏：复制的是热的那几个，冷专家仍一份；改表比把整个专家表重切一次便宜，最慢那张卡上的活被摊开，整步就不再被它按住。

## 三、代价

**槽比专家多，多出来的是权重副本。** 槽数必须能被专家并行度整除；每卡本地槽数是总槽数除以并行度。冗余吃显存，给 KV 的空间变少。

**在线搬权重会打断前向。** 每步更新的层数大于 0 才走动态路由；为 0 就是静态摆位，启动时摆好就不再搬。搬的那段不出 token。

**all-to-all 把 SM 和互联打满。** 一步里要派的 token 太多，就要按 MoE 配置里的上限切块循环，decode 间隔被这段通信拖长。

**负载均衡不是随专家并行自动开。** 要显式给负载均衡配置，且模型架构在支持名单里、专家并行大于 1、也没有走已弃用的集群切法。没挂上时，专家仍等于槽，热专家问题还在。

**和主机侧零拷贝权重池不兼容。** 槽位登记发生在池关闭之后，对端会拿到坏掉的路由状态，配置阶段直接拒。

## 四、专家和槽位怎么分开、热专家怎么复制、最慢的专家怎样拖死整步

这一页比的是专家和槽位怎么分开、热专家怎么复制、最慢的专家怎样拖死整步。

| 维度 | TensorRT-LLM | vLLM | SGLang |
|---|---|---|---|
| 专家份数怎么定 | 专家并行可独立给，也可与专家张量并行混切，乘积要对上 MoE 世界规模；都空则专家并行为 1 | 布尔开关，份数由张量并行乘副本等推出来 | 自己给一个数，可小于张量并行做混合切；点名全交换后端后被改成相等 |
| 专家和槽是否分开 | 槽与专家脱钩，热专家可多槽复制，负载均衡改路由表 | 专家整份分卡；均衡是把热专家迁到轻载卡 | 物理槽等于逻辑数加冗余，热专家多卡各放一份 |
| 默认通不通信 all-to-all | 专家并行大于 1 走派发与合并，具体后端由工厂选 | 开了专家并行仍可能走 all-gather 加 reduce-scatter | 默认每卡跑全批再 all-reduce，必须点名后端才派发 |
| 均衡何时动 | 配置里每步更新层数为 0 则静态；大于 0 则在前向迭代里搬 | 必须先开专家并行，运行时迁移 | 默认关，打开后按步数重排，可分块搬层 |
| 最慢专家怎么拖死整步 | 集合通信同步点等最慢槽；复制热专家是为了拆掉这张卡 | 同样等最慢卡，补齐与迁移是两条对策 | 同样等最慢卡，记录加冗余再重排 |

重心在本项目：招牌是槽位与专家脱钩。vLLM 把专家并行规模压进张量并行那条账；SGLang 用独立份数加一套全交换后端。本项目用槽位吸收热专家，路由表可以在服务过程中改，不必把 MoE 层重新切一遍。

## 五、调参与观测

这一页的参数全是启动配置，改了要重新拉起整个作业。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `moe_expert_parallel_size` / `--ep_size` · 专家切几份 | 启动或 YAML | 空，校验后写成 `-1`，映射里落到 1 | 大于 1：专家整份分卡，走派发与合并；须与专家张量并行乘积对上 MoE 世界规模 | 启动报 `moe_tp_size * moe_ep_size * moe_cluster_size must equal to moe_world_size` |
| `moe_tensor_parallel_size` · 每个专家再切几份 | YAML | 空，写成 `-1` | 与专家并行混切；只填这一项时专家并行被除出来 | 同上乘积 |
| `moe_config.load_balancer` · 槽位数与是否在线搬 | YAML 对象、字典或文件路径 | 空，不创建负载均衡器 | 给 `num_slots` 并 `setup`：槽与专家脱钩；`layer_updates_per_iter` 为 0 静态，大于 0 在线搬 | 日志 `Created MoE LoadBalancer, layer_updates_per_iter=`；文件不存在直接 `FileNotFoundError` |
| `moe_config.max_num_tokens` · 一次送进融合 MoE 的 token 上限 | YAML | 空，不切块 | 超过就切块 for 循环，通信峰值下降，一步变长 | 一步耗时是否随批变长出现台阶 |
| `moe_config.backend` · 专家 GEMM 选哪条实现 | YAML | `AUTO` | 按模型挑；名为 `WIDEEP` 的旧后端已不能选，Wide-EP 走其余后端 | 启动选路日志；点名已删后端会拒 |
| `EXPERT_STATISTIC_ITER_RANGE` · 记哪些迭代的专家被选次数 | 环境变量 | 不设则不创建记录器 | 写成 `start-stop`，停在右端时 rank 0 写元信息，各 rank 写 safetensors | 目录默认 `expert_statistic`，可用 `EXPERT_STATISTIC_PATH` 改 |

**怎么看。** 一是启动：专家并行与专家张量并行的乘积必须等于 MoE 世界规模，对不上立刻失败。二是负载均衡：只有支持名单里的架构、专家并行大于 1、且配置不是空，才会打 `Created MoE LoadBalancer`。三是热专家：把环境变量区间对准稳态 decode，对比各 rank 写出的被选次数；某一逻辑专家远高于均值、又只出现在一个 rank 上，就是槽位还没把热专家摊开。

**典型配置。** 三套能直接抄走的起法，参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机 8 卡中等 MoE，先把专家整份切开 | `trtllm-serve Qwen/Qwen3-30B-A3B --ep_size 8 --config moe-ep8.yaml`（文件写 `tensor_parallel_size: 8` 与 `moe_expert_parallel_size: 8`） | 用 8 路专家并行换每卡少放专家；没有槽位冗余，热专家仍可能单卡拖死 |
| 8 卡要混切，专家份数不必等于张量并行 | `trtllm-serve Qwen/Qwen3-30B-A3B --config moe-hybrid-etp.yaml`（文件写 `tensor_parallel_size: 8`、`moe_tensor_parallel_size: 4`、`moe_expert_parallel_size: 2`） | 用每专家再切 4 份换通信形状更接近稠密；热专家问题还在 |
| 大规模细粒度 MoE，流量会漂，要复制热专家 | `trtllm-serve deepseek-ai/DeepSeek-V3 --tp_size 16 --ep_size 16 --config wide-ep-eplb.yaml`（文件写 `moe_config.load_balancer: {num_slots: 256, layer_updates_per_iter: 1}`） | 用多出来的槽换热专家多副本；在线搬权重会打断前向，静态则把更新层数改成 0 并给初始摆位 |

组合与推荐值是按语义推的起点，不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动报专家三项乘积不等于 MoE 世界规模 | 专家并行、专家张量并行、张量并行是否同改 | 按文档让乘积相等，不要只改专家并行 |
| 开了专家并行，一张卡持续比别的卡慢 | 有没有负载均衡配置、槽数是否大于专家数 | 给槽位并复制热专家；或先用统计环境变量看谁热 |
| 写了负载均衡却没有创建日志 | 架构是否在支持名单、专家并行是否大于 1 | 名单外或并行度为 1 时创建路径直接跳过 |
| 在线搬权重时吞吐周期性掉一截 | `layer_updates_per_iter` 是否大于 0 | 流量稳定就改 0 做静态摆位 |
| decode 一步随批突然变长 | `moe_config.max_num_tokens` 是否把一步切成多块 | 内存够就调高上限，不够就接受切块 |
| 和零拷贝权重池一起起直接拒 | 是否同时给了负载均衡 | 二选一：关掉负载均衡，或不要用那种装载格式 |

## 六、常见误区

- **以为专家并行度等于张量并行度。** 两个都能空着，空着时专家并行落到 1，专家权重按张量并行切。只改专家并行、不改张量并行，乘积对不上就起不来。
- **以为开了专家并行就是 Wide-EP。** 没挂负载均衡时，专家仍等于槽，热专家还是一份。Wide-EP 的那一步是槽位和路由表。
- **以为负载均衡会改模型里的专家编号。** 它改路由表：同一个专家编号可以指向多个槽。统计环境变量记的是逻辑专家被选次数，不是槽号。
- **以为每步更新层数为 0 就是关掉均衡。** 那是静态路由：启动摆位仍有效，只是前向里不再搬权重。真正不创建均衡器，是配置留空。
- **以为名为 Wide-EP 的旧 MoE 后端还要选。** 那条选路已经删掉。槽位和均衡由其余后端承载。
- **把张量、流水线、Helix 的切法当成这一页的旋钮。** 那些归 07 章。三项世界规模对得上，也不等于专家已经切开，更不等于热专家已经复制。
