# TensorRT-LLM 12|多模态(LLM 侧)

非文本先过处理器和编码器,embedding 再融进 decoder;图和视频编码会堵住同一步的文本 decode,KV 复用还会因为图像摘要对不上而认错图。

说法都在源码基准 `59f5c47f`(tag `v1.2.1`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

引擎只认 token,图和视频是字节。字节要先变成和文本同一张量上的几行,才能进 decoder。这条路上坏两个指标。

**图和视频编码堵住文本 decode。** 塔跑在执行器循环里,默认跟语言模型抢同一步、同一张卡。一张高分辨率图或一段视频要 20–100 毫秒甚至更长;这段时间同批里已经在 decode 的请求一起等,坏的是每个 token 间隔的尾巴。视频还要先拆帧,帧一多,编码器一步的激活把余量吃光,直接 OOM。

**KV 复用对不上图像摘要。** 占位 token 共用一个词表编号,两张内容完全不同的图在 prompt 里看起来一样。跨请求复用按块查前缀(03 章);不把图像内容摘要和块内偏移写进键,树会把猫的 KV 借给狗。摘要缺了、长度和位置对不上、或者混进了租户隔离用的身份串,命中就漂,答错还不报错。

这一页不写扩散生成栈。出去的仍是 token。

## 二、解法:先编码,再盖进占位行

最天然的直觉:图先在 CPU 上预处理成像素,再过视觉塔变成 embedding,按占位位置盖进文本 embedding,后面的 decoder 当普通 token 用。本项目官方文档就是这三段:处理器、编码器、融进 decoder。CPU 预处理可以和 GPU 编码重叠,不必串成一条线。

![一条带图请求先在 CPU 上预处理、再在 GPU 上过编码器,embedding 盖进占位行后才进 decoder;编码器输出缓存是虚线框,侧流预取是虚线箭头且默认关](/opensource/TensorRT-LLM/12a-processor-encoder-fuse.svg)

一条请求的路径:

- 对外侧把图、视频、音频字节读进来,处理器做解码、缩放、归一化,产出像素张量和一段占位 token。视频解码依赖可选的图像库,没装就走不了视频。
- 执行器里编码器把像素编成和隐层同宽的 embedding。有的模型报名了编码器输出缓存:按内容摘要查,命中不跑塔;没报名则启动里划的那块字节也不会生效。混模态一份对象会绕过这份缓存。
- embedding 按占位位置盖进文本那一行。decoder 只看见一串向量。decode 阶段塔不再参与,像素也可以剥掉,只留位置编码要用的那一点。
- 跨请求复用打开时,占位区不会原样进搜索树。系统用内容摘要(可选再拼调用方给的身份串)生成一段超出词表的键,再带上块内偏移,让两张图的块对不上。摘要、位置、长度缺一,就退回共用编号,复用会认错。

为什么实际不吃亏:塔比语言模型小一个数量级,一张图的编码时间和同等长度的 prefill 相当。真正省的是重复图——缓存命中跳过塔,摘要写进块键后前缀也能命中。侧流预取想把下一请求的编码藏进当前步 decode,但默认最大提前条数是 0,要显式打开,而且和编码器整图录制互斥。

## 三、代价

**编码器默认跟 decode 同一步。** 没有单独把塔拆到另一台机器。图多的负载下,文本请求的间隔被拖长。按条调度编码器是另一条报名路径,只有少数模型接了;接了之后 prefill 仍要等这条请求的全部图编完,超预算的请求在准入就被拒。

**缓存和预取都要模型报名,还要显存。** 输出缓存默认划 128 MiB,但类变量没报名就不建。侧流预取会让原始像素和算完的 embedding 在 prefill 前同时驻留,峰值升高。关塔省显存只对少数家族生效,发图会被拒。

**摘要对不上就静默答错。** 调用方自带身份串时,同一张图不同身份互不命中;身份给错,键也对错。词表大小解析不出来时,复用路径直接起不来。视频若把文本插在帧与帧之间,还要精确的分段元数据,旧的「一整段连续占位」不够用。

**功能表打折。** 编码器整图、侧流、按条调度在配置里标成原型。按条调度的急切策略还不能和注意力数据并行、分离式服务同开。

## 四、图和视频怎么先编码再融进 decoder

这一页比的是图和视频怎么先编码再融进 decoder、会不会堵住文本 decode。对等列是 vLLM 和 SGLang。

| 维度 | TensorRT-LLM | vLLM | SGLang |
|---|---|---|---|
| 三段怎么串 | 处理器、编码器、融进 decoder;文档写明 CPU 预处理可与 GPU 编码重叠 | 对外进程预处理,塔在引擎里跑,占位行覆盖 | 主进程预处理,调度器进程里跑塔再散布 |
| 编码器和 decode 谁让谁 | 默认同一步;按条调度要模型报名;侧流预取默认关 | 每步有编码器预算,不够就给这条 0 个 token | 没有这道闸,批里有多少图就编多少 |
| 编码器输出怎么记 | 可选的按条缓存,默认划 128 MiB,模型没报名不生效;混模态绕过 | 三级缓存,编码器那一级按内容标识 | 特征张量哈希,和前缀树共用一个数 |
| 图像怎么进 KV 复用 | 占位编号不够,要把内容摘要和块内偏移写进键;缺了就撞车 | 媒体身份加起始偏移混进块哈希 | 占位 token 改写成那个特征哈希 |
| 能不能把塔卸掉 | 少数家族可跳过装塔,发图就拒;只跑塔是另一条互斥开关 | 某模态数量上限设 0 可不装该塔 | 数量上限只拒请求;真不装塔是另一模式,只认少数架构 |
| 视频 | 可选图像库;剪枝率只在特定家族上是原型 | 请求级剪枝,塔可能退出图捕获 | 配置里的剪枝率,接的家族更窄 |

重心在本项目:默认把塔留在执行器循环里,用摘要修补 KV 键,而不是另造一套前缀树。vLLM 用预算把编码从 decode 里挤出去,SGLang 用同一个数同时管塔缓存和前缀树。本项目的缓存和预取都是报名制,没报名就别指望那 128 MiB 在干活。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `multimodal_config.encoder_cache_max_bytes` · 编码器输出缓存划多少字节 | YAML | `134217728`(128 MiB) | 调高:重复图少跑塔;设 `0` 关掉。关塔时会被改成 0。模型没报名则划了也不建 | 重复同一张图时 GPU 时间是否明显下降 |
| `multimodal_config.encoder_side_stream_max_ahead` · 侧流最多提前编几条 | YAML | `0`,关 | 大于 0:编码藏进当前 decode;峰值显存升高;不能和编码器整图同开,也不能和按条调度同开 | 日志 `Using multimodal encoder side stream`;启动互斥报错 |
| `multimodal_config.encoder_scheduling_policy` · 编码器按条怎么进循环 | YAML | `DEFAULT`(模型报了名才按条) | `DISABLED`:回到请求内联编码;`EAGER`:准入前先推进编码,暂不支持注意力数据并行和分离式服务 | 启动是否报 `does not yet support` |
| `encoder_max_num_tokens` · 一步编码器最多编多少注意力 token | YAML | 空,回落到 `max_num_tokens` | 小于模型最大不可切分项时会被抬上去 | 日志 `using … as the effective encoder runtime budget` |
| `encoder_max_batch_size` · 一步最多编几件原子媒体 | YAML | 空,回落到 `max_batch_size` | 一件图或一段视频算 1,不管内部切成多少段注意力 | 多图请求是否被拆到多步 |
| `disable_mm_encoder` · 不装视觉塔,当纯文本服 | YAML | `False` | `True`:省塔的显存给 KV;发图拒。只对少数家族生效,否则空操作。与只跑塔互斥 | 发图是否被拒;缓存字节是否被改成 0 |
| `mm_encoder_only` · 只跑视觉塔 | YAML | `False` | `True`:不跑自回归循环。与关塔、以及只做一次前向的编码路径互斥 | 返回是 embedding 而不是生成文本 |
| `multimodal_config.video_pruning_rate` · 视频帧剪枝比例 | YAML | 空,关 | `[0, 1)` 启用;目前只接到特定家族 | 视频 `prompt_tokens` 是否变短 |
| `kv_cache_config.enable_block_reuse` · 跨请求块复用(图像键依赖它) | YAML | `True` | 关:不再把摘要写进块键,图不会张冠李戴,但前缀全重算。词表大小解析失败时复用路径会报错 | 换图同占位时答案是否串台 |

**怎么看。** 一是启动:侧流那行、编码器预算被抬高的警告、关塔后缓存改 0 的信息、按条调度与数据并行或分离式服务的互斥错误。二是请求:同一张图连打两条,第二条 GPU 时间应接近纯文本;换一张图、占位不变,答案必须换,否则摘要没进键。三是显存:侧流打开后峰值应高于默认;关塔后 KV 池应变大。四是视频:没装可选图像库时起服务或首个视频请求会在解码处失败,不要先怪模型。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。

| 什么场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡图文在线,图会重复 | `trtllm-serve Qwen/Qwen2-VL-7B-Instruct --config mm-vl-inline.yaml`,文件写 `multimodal_config: {encoder_cache_max_bytes: 134217728}` | 用 128 MiB 换重复图的塔;模型没报名则白划,先看第二条是否真变快 |
| 图多、decode 间隔被编码拖长 | `trtllm-serve Qwen/Qwen2-VL-7B-Instruct --config mm-side-prefetch.yaml`,文件写 `multimodal_config: {encoder_side_stream_max_ahead: 2, encoder_cache_max_bytes: 268435456}` | 用侧流提前 2 条和 256 MiB 缓存换重叠;峰值显存升高,不要再开编码器整图 |
| 这张卡只接纯文本,仓库却是多模态 | `trtllm-serve Qwen/Qwen3-VL-8B-Instruct --config mm-skip-tower.yaml`,文件写 `disable_mm_encoder: true` | 用卸塔换 KV 槽;发图会被拒。换错家族则开关空操作,塔还在 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 图一来,纯文本 decode 也抖 | 编码器是否跟循环同一步;侧流是不是 0 | 打开侧流,或换报名了按条调度的模型;仍堵就把图限分辨率 |
| 同一张图第二条并不快 | 这个模型有没有报名输出缓存;缓存字节是不是 0 | 显式给字节;没报名的模型调这个字段无效 |
| 换图答案却像上一张 | 复用是否开;请求有没有摘要、位置、长度 | 不要只关复用当长期方案;先保证摘要进键。串台是键的问题,不是采样 |
| 启动报侧流与整图互斥 | YAML 是否两个都开 | 只留一个 |
| 启动报按条调度不支持数据并行或分离式 | 急切策略是否开着 | 改回默认策略,或关掉那两个特性 |
| 发图被拒,KV 却没变大 | 关塔是否作用在这个家族 | 换成文档点名的家族,或接受塔仍加载 |
| 视频请求在读帧处炸 | 可选图像库装了没有 | 只为视频工作流安装无头图像库 |
| 关塔后又划了缓存字节 | 关塔会把缓存改成 0 | 不要指望这份缓存还在 |

## 六、常见误区

- **以为多模态章会讲文生图。** 人们把仓库里另一条扩散栈当成这一页。本页只把图编进 LLM;出去的是 token,不是像素。
- **以为划了 128 MiB 就一定有编码器缓存。** 默认值看起来像开着。模型类变量没报名就不建;混模态对象也会绕过。
- **以为侧流预取默认在重叠。** 文档写了 CPU 与 GPU 可重叠,容易看成已经打开。侧流最大提前条数默认 0;打开后峰值显存升高,且不能和整图录制一起用。
- **以为占位 token 进复用树就够了。** 占位编号对所有图都一样。必须把内容摘要和偏移写进键;缺摘要时不是「不复用」,而是可能复用错图。
- **以为关塔和只跑塔是同一件事。** 一个不装塔、发图就拒;一个只跑塔、不生成文本。两个开关互斥。
- **以为按条调度能把一张图切开编码。** 原子项不能切,预算不够会被抬到最大项;prefill 仍等这条请求全部图编完。
- **以为 KV 复用对不上图是 03 章调块大小能修好的。** 03 管池和树;本页管摘要怎么进键。块再小,编号撞了还是错图。
