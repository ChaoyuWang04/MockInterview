# 扩散并行：七种切法

这一页说明扩散作业怎样把权重、序列、guidance 分支和媒体解码分给多张卡,以及哪些并行方式共用同一批 rank。说法都在源码基准 `4d877780d3`(tag `v0.29.0rc1`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

扩散生成的显存峰值不总在同一处。DiT 权重可能在加载时就装不下;高分辨率和长视频把 denoise 激活撑大;也可能 denoise 已完成,VAE decode 才 OOM。把这些问题统称为「卡不够」,容易增加了 GPU,却没切中真正占空间或耗时间的部分。

**本章的关键是先选切分对象,再算 rank 布局。** TP、SP、PP、CFG、HSDP、EP 与 VAE 并行不是可以逐项相乘的 7 个独立维度。增加 rank、在已有 rank 上分片权重、让后续解码复用这些 rank,是不同的资源动作。通用并行原理见知识库《并行策略》,这里只看本项目怎样接入。

## 二、解法

**权重放不下,先看切哪一部分。** Qwen-Image 和 Wan 的 DiT 使用 vLLM 的并行 Linear 接入 TP;Wan 还把 Transformer blocks 分给连续 PP stage。HSDP 则由加载器找到外层 DiT,按模型声明的 block 边界调用 FSDP2,前向时临时聚合权重。HunyuanImage3.0 的 MoE 接入 FusedMoE,EP 重新组织现有 rank 上的专家归属。这些入口都需要模型适配,配置合法不能代替调用链存在。

**序列太长,把切分位置和 attention 通信一起接上。** Qwen-Image 的 SP plan 在输入准备模块同时切 hidden states 与 RoPE,在输出投影处聚合,避免 token 与位置错位。attention 再选择 Ulysses、Ring 或聚合 K/V 的通信路径;Ulysses 与 Ring 可以组合,聚合 K/V 则是替代路径。这里的 SP 是沿 token 序列切分,不是把一个请求分成互不相干的图片。

**同一步有独立 guidance 分支,再考虑 CFG 并行。** 常见双分支路径让不同 CFG rank 分别算条件预测与无条件预测,聚合后得到相同的引导结果。Wan 的 PP 路径由末段完成采样器更新,再把 latent 送回首段,供下一步 denoise 使用;PP stage 不等于前面章节的服务阶段。

![SP 与 CFG 将一个作业展开为四个 rank,HSDP 可以覆盖这四个 rank 分片权重,VAE decode 随后复用这四个 rank 分配 tile,后两者不把卡数继续相乘](/opensource/vllm-omni/10a-parallel-rank-reuse.svg)

**最后的解码有自己的切法。** 通用分布式 VAE 执行器在已有 worker WORLD 内分配 tile,收集后由主 rank 合并。Wan 还实现按空间维切 feature map、交换 halo 的 decode。模型要提供对应 VAE 实现;开关不会自动给任意 decoder 加上这套能力。

## 三、代价

**显存减少的位置不同,通信却都要付账。** TP 在层内交换结果,SP 在 attention 周围搬张量,HSDP 在执行 block 时聚合权重。短序列或慢互联上,节省的计算可能抵不过通信。PP 主要解决模型容量,下一步仍依赖上一轮末段传回的 latent,不能把切了几段直接当作几倍时延收益。

**HSDP 不等于整个 pipeline 的权重都被均分。** 加载器主要分片 DiT;VAE、encoder 以及显式排除或不能分片的参数仍需放置。VAE 的 tile 分工也不消除结果聚合、边界处理及最终输出的内存。

**组合有硬边界。** 当前 HSDP 不与 TP、普通 DP、PP、EP 组合;它能覆盖 SP、CFG 已有的 rank,也能独立确定作业规模。EP 使用当前 PP stage 内已有的 TP、SP、CFG、DP rank,并不再乘一个专家维度。VAE 执行器也复用 worker WORLD。阶段副本数属于另一层部署容量,不要混进单个扩散作业的并行度。

## 四、和 sglang-omni 的并行边界对照

sglang-omni 的 Stage 启动器按 TP rank 生成独立进程记录,把 rank、设备与通信端口传给模型工厂;Stage Runtime 按 Scheduler 的声明决定是否复制工作载荷。那一层解决的是怎样让参与同一阶段计算的进程收到工作。

vLLM-Omni 在扩散执行侧继续组织 token、guidance、层与专家的通信组,并把 SP hooks、FSDP2 和分布式 VAE 接到模型内部。这个对照只说明本章优化落在哪层,不把对方的 Stage 进程数当成扩散并行能力表,也不据此比较速度。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

以下默认值来自 `DiffusionParallelConfig`。CLI 没有显式值的字段会交给扩散配置处理。部署配置中的 `parallel_config` 或 Python 同名对象也是入口;阶段部署方式见 02 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--tensor-parallel-size` | CLI / `tensor_parallel_size` | 1 | 在适配模型上分片 DiT Linear,减少这部分权重,增加层内通信 | 加载显存、denoise 时间、维度整除报错 |
| `--pipeline-parallel-size` | CLI / `pipeline_parallel_size` | 1 | Wan 按层分段,降低单 rank 的主干权重容量 | 层分配、段间通信及端到端时间 |
| `--usp`、`--ring` | CLI / `ulysses_degree`、`ring_degree` | 各 1 | SP 大小为两者乘积;降低本地序列长度,增加通信 | attention 策略 debug 日志、单步时间和峰值显存 |
| `--allgather-degree` | CLI / `allgather_degree` | 1 | 启用 AllGather-KV SP;只接受非 causal attention,不与 Ulysses/Ring 叠加 | 互斥或 causal 校验错误;本地仍持有完整 K/V |
| `--ulysses-mode` | CLI / `ulysses_mode` | `strict` | `advanced_uaa` 放宽头数与序列形状限制,引入补齐和形状协调成本 | strict 的整除报错、UAA padding 警告;混合 Ring 仍有形状约束 |
| `mask_sp_padding` | `parallel_config` | `false` | 在支持模型上给自动补齐 token 加 mask,可能增加 attention 开销 | 对照输出与耗时;不要把它视为所有 Ring 路径可用的开关 |
| `--cfg-parallel-size` | CLI / `cfg_parallel_size` | 1 | 双分支通常从 2 开始,并行执行 guidance passes | `CFG Parallel` debug 日志、模型的 CFG 有效性警告 |
| `--use-hsdp`、`--hsdp-shard-size`、`--hsdp-replicate-size` | CLI / 同名下划线字段 | `false`、-1、1 | 分片 DiT 权重;独立 HSDP 要显式给 shard 数,覆盖模式自动按已有规模求值 | `HSDP Inference (FSDP2)`、`Sharded … modules + root` 和排除参数日志 |
| `--enable-expert-parallel` | CLI / `enable_expert_parallel` | `false` | MoE 专家按既有 `TP × SP × CFG × DP` rank 组织;非 MoE 会报错 | 专家权重显存与通信耗时,不要再乘 EP 得卡数 |
| `--vae-patch-parallel-size` | CLI / `vae_patch_parallel_size` | 1 | 支持的 VAE 在 WORLD 内分 tile;超出 WORLD 的值会被限制 | VAE 阶段峰值显存、忽略或限幅警告 |
| `--vae-parallel-mode` | CLI / `vae_parallel_mode` | `tile` | Wan 可选 `spatial_shard_height` 或 `spatial_shard_width`;所选大小须等于执行器 WORLD | `falling back to tiled decode` 警告 |
| `--vae-use-tiling` | CLI / `vae_use_tiling` | `false` | 为分布式 VAE 开启 tiling;支持的 Mixin 路径会自动补开 | `automatically enabling it` 日志 |
| `--text-encoder-tp-size` | CLI / `text_encoder_tp_size` | 1 | MiniMax H3 的 Qwen3-VL text encoder 可在前若干 DiT rank 上 TP;不超过作业规模且满足头数约束 | encoder 加载日志及校验错误;不是所有模型通用支持 |

**先计算作业规模,再检查模型。** 非 HSDP 路径为 `PP × DP × TP × SP × CFG`;SP 使用 `Ulysses × Ring` 或独立的 AllGather-KV 度数。HSDP 的 `replicate × shard` 必须等于它所覆盖的作业规模。VAE 和 encoder 的复用范围单独校验,不加入上述乘积。

**不要从声明类型推断配置已贯通。** `StrategySpec` 的类型表包含扩散轴,但当前可组合策略翻译器只接通 `tp`、`dp`、`pp`、`ep`、`stage_replica`;本章 SP、CFG、HSDP、VAE 配置应走实际的扩散配置入口。

以下是同机 CUDA GPU 的起点,假定模型权重与各卡剩余显存已核对,卡间通信可用。卡数由配置计算,不代表最低硬件需求;本章未做 GPU 实测。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 2 张 GPU,Qwen-Image 高分辨率请求,先隔离 SP 收益 | `vllm serve Qwen/Qwen-Image --omni --usp 2` | 用 attention 通信换更短的本地序列;先固定分辨率与 denoise 步数作对照 |
| 2 张 GPU,Wan2.2 14B,DiT 权重与长序列同时受限 | `vllm serve Wan-AI/Wan2.2-T2V-A14B-Diffusers --omni --usp 2 --use-hsdp` | HSDP 覆盖同一组 2 个 rank,增加权重聚合以减少驻留权重;encoder/VAE 仍须能放下 |
| 2 张 GPU,Z-Image,主干和 VAE decode 都需要分担 | `vllm serve Tongyi-MAI/Z-Image-Turbo --omni --tensor-parallel-size 2 --vae-patch-parallel-size 2 --vae-use-tiling` | DiT 用 TP,VAE 随后复用这 2 张卡;观察解码峰值及拼接结果 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 加卡反而慢 | 瓶颈是否在 denoise,互联及实际序列长度 | 固定请求分别测单步、编码和解码时间,先减并行度 |
| CFG 开了但没收益 | Qwen-Image 的请求是否满足 `true_cfg_scale > 1` 且有 negative prompt 或 embeddings | 看有效性警告;不要靠继续增加 CFG rank 修正请求语义 |
| SP 一启动就报头数错误 | `strict` 整除约束、TP 后本地头数 | 先选可整除的度数,确需不均匀切分再验证 UAA |
| HSDP 仍在 OOM | 出错时在权重加载、DiT forward、encoder 还是 VAE | 查排除参数与各阶段峰值,避免继续分片错误组件 |
| VAE 参数没效果 | 是否出现 `NOT enabled … ignoring` 或回退警告 | 核模型 VAE 类型与 WORLD 大小,再比较 decode 峰值 |
| 配置算出过多 GPU | 是否把 EP、VAE 或 HSDP 覆盖重复相乘 | 按实际 WORLD 关系重算,再检查设备数 |

## 六、常见误区

**看到 HSDP 的名字,就以为会把整套生成模型均分。** 指南讲的是权重分片,容易让人把 encoder、VAE 也算进去;加载器实际挑选外层 DiT,还有不能分片的参数会保持驻留。排查时先看 OOM 属于哪个组件。

**照指南把 Ulysses 默认模式填成 default。** 指南的参数表与代码已有差异,当前 CLI 和配置都使用 `strict`,可选的宽松模式是 `advanced_uaa`。使用错误字符串会在校验处失败,不表示通信库坏了。

**TP 指南说 encoder 不支持分片,便认定所有模型都如此。** 这个概括漏掉了 MiniMax H3 的专用 Qwen3-VL encoder TP;反过来,它的独立开关也不能使别的模型自动获得 encoder TP。

**服务能启动,就把 VAE 并行当成已经生效。** 不支持的 VAE 会记录忽略警告;Wan 空间分片大小不匹配会退回 tile。忽略这两类日志,会把串行或另一条解码路径的结果误记成目标方案。
