# 数据接入：提示词、媒体与偏好样本

怎样让正负提示词、媒体条件和离线偏好对进入同一套批处理接口,又不丢掉各自的含义。说法都在源码基准 `b708218d5b`(tag `v0.2.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

**训练器拿到一行数据时,必须知道这一行究竟代表什么。** 在线图像生成的一行可以只有生成条件和奖励元信息;视频问答还要携带画面与音轨;离线偏好的一行则包含同一条件下的两个候选。把它们都当成一条普通回答,轻则漏掉条件,重则把偏好关系拆散。

媒体又有第二层含义:文件里存的是路径、字节或结构化消息,模型消费的是 Token、媒体特征与位置。批处理能够收下某个字段,不等于两侧模型已经按同一种方式解释它。

## 二、解法

**复用入口和批接口,在样本变形的位置做适配。** 默认在线数据集继承 verl 的读取流程,补上负提示词通道,并允许在没有 Processor 时把媒体组织进结构化消息。它交出的是原始消息;扩散 AgentLoop 随后读取媒体、编码正负提示词,再请求生成,并不是提示词从此不经过 Tokenizer。

在线 Omni 的专用数据集主要替换媒体解析钩子:借 Qwen 的工具读取图像、视频和音频,并把音频补齐到特征提取的步长倍数,避免 Actor 与 Rollout 对同一音频展开出不同数量的 Token。NExT-QA 再补一层:在视频后插入同源音轨,保持画面与声音都进入条件。

离线偏好把转换提前到读取阶段。扩散样本带着已预计算的干净 latent 与提示词 embedding;Omni 样本把共享媒体上下文分别接上首选、非首选回答,转换成模型输入与回答标签。两条离线支路都在组批时把每对展开成相邻的两个样本,保留共同标识。

![三条数据入口图:在线扩散保留正负消息,在线 Omni 保留媒体消息并挂接媒体解析,离线偏好将每行展开为相邻的 chosen 与 rejected;这些不同字段通过共用批接口交接,在线编码仍由 AgentLoop 完成。](/opensource/verl-omni/10a-sample-to-batch.svg)

图中的共同点是字段可以随批次一起搬运,不是所有路径都拥有相同字段。在线输入的回答尚未生成,不能要求它具备离线偏好样本已有的标签或 latent。

## 三、代价

**数据转换与模型绑定。** Omni 离线转换含有 Qwen 家族的系统消息、模态占位符和多模态位置处理。换数据源往往只需改列与路径;换模型家族却可能必须改转换器,不能仅凭共同接口就认定兼容。

**预计算把成本移到了准备阶段。** 扩散离线数据省去逐步读取时重新生成这些条件,但文件必须携带配套模型的 latent 与 embedding。媒体路径也必须在真正读取它的 worker 上可见,主机能够打开文件并不足够。

**一行不再等于一个训练样本。** 偏好对展开后,批中元素数量增加;Omni 离线组批还要求同一批只含一种模态。准备数据与配置采样器时,要保留成对关系并满足组批约束。

## 四、与上游 verl 的关系

固定依赖版本的 verl 已经提供结构化媒体消息、延迟到 AgentLoop 的在线编码,以及自定义数据集入口。VeRL-Omni 沿用这些能力,默认子类主要补负提示词与媒体运输适配,不能把这些共同能力都算作本项目新增。

离线扩散数据集是本项目独立实现的。离线 Omni 数据集虽然继承上游的多轮 SFT 类,但初始化、读取与样本转换等核心方法由本项目重写,实际偏好处理不能归成“上游已经做好”。

目录中另有视觉反思的离线 SFT 样本构造工具库,已有测试,但在该基准下尚未接入生产训练调用链。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `data.train_files` / `data.val_files` | 启动配置 | 继承的 GSM8K 示例路径 | 改为对应配方生成的数据文件 | 文件列、加载样本数与媒体可达性 |
| `data.prompt_key` / `data.negative_prompt_key` | 数据配置 | `prompt` / `negative_prompt` | 改输入列映射,后者由类内兜底 | 抽查 `raw_prompt` 与 `raw_negative_prompt` |
| `data.custom_cls.path` / `name` / `collate_fn` | 数据配置 | 均为 `null` | 替换数据集与必要的组批函数 | 默认路径会记录数据集类与 collate 选择 |
| `data.filter_overlong_prompts` | 在线数据配置 | `false` | 打开后提前按编码长度过滤,增加预处理工作 | `filter dataset len` 与保留样本比例 |
| `data.max_prompt_length` | 在线长度配置 | `512` | 放宽可接受的提示词长度,也提高后续负载 | 编码后的长度,不只看原始文本字符数 |
| `data.dataloader_num_workers` | 数据配置 | `8` | 增加读取并发,也增加 CPU 与内存压力 | 等待数据的时间与主机资源占用 |
| `data.max_length` / `data.truncation` | 离线 Omni 数据配置 | 类内为 `1024` / `error` | 限制已编码的完整分支长度;截断可能损失回答或条件 | 长度报错、回答标签覆盖范围 |
| `data.train_sampler` / `data.val_sampler` | 离线 Omni 配方 | 公共配置未设置 | 配方挂接按模态分组的采样器 | 每批模态与各模态样本覆盖 |

**典型配置方向。** 从官方对应模型的完整配方调整,这里列的是数据接入的检查重点。

| 场景 | 怎么配 | 拿什么换什么 |
|---|---|---|
| OCR 在线扩散 | 使用官方 OCR 转换结果,先保留默认数据集 | 复用标准读取;必须把目标文字放进奖励元信息 |
| 图像、音频联合问答 | 按 AVQA 配方设置 `data.custom_cls`,保留媒体路径布局 | 加载时解码媒体,换取原始数据文件与模型输入分离 |
| 离线 Omni 偏好 | 同时沿用配方的自定义数据集、collate 与模态采样器 | 维持两分支与同模态批约束,接受转换与组批成本 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测应从一条样本开始。** 在线检查消息里的媒体项是否对应真实资源,离线检查同一标识的两个分支是否共享条件、顺序正确。只看数据集总行数,看不出条件错位或回答标签丢失。

| 症状 | 先查 | 然后 |
|---|---|---|
| 媒体占位符断言失败 | 消息占位符与媒体列表是否一一对应 | 修正转换数据,不要用删占位符掩盖漏媒体 |
| 音频输入两侧 Token 数不一致 | 是否采用配方的媒体解析与补齐方式 | 再核对采样率及 Processor 配置 |
| 离线扩散提示缺少字段 | 是否只有图片路径,缺 latent 或 embedding | 用对应模型的数据准备流程重新生成 |
| 离线 Omni 报混合模态 | 自定义采样器是否实际挂接 | 按模态组织批次,保持每对相邻 |
| 加载成功但训练条件不对 | 原始消息、媒体路径及回答标签 | 在扩批前抽查单行两分支,再扩大作业 |

## 六、常见误区

- **看到原始提示词就以为没有 Tokenizer。** 延迟编码只是改变发生位置;在线扩散 AgentLoop 仍会编码,离线扩散数据集也会生成提示词 Token。
- **沿用普通 collate 就以为偏好对会自动展开。** 数据集输出能被装进批,不代表两个候选已变成训练需要的相邻样本;离线配方的数据集与组批函数要配套。
- **视频文件自带声音,就以为模型一定听到了。** NExT-QA 适配明确插入并解码音轨,不会仅凭一个视频路径自动获得同样的音频条件。
- **只换模型名,继续使用旧的预计算文件。** 文件能读开无法证明 latent、embedding、媒体占位符和位置编码与新模型一致,应先核对对应准备流程。
