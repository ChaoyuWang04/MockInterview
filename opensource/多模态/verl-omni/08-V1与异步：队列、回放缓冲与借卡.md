# V1 与异步:队列、回放缓冲与借卡

生成凑不齐样本时,怎样让 Actor 少空等,又不让旧样本无限积压。说法都在源码基准 `b708218d5b`(tag `v0.2.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

同步训练要等一批 Rollout 完成,才能把共用 GPU 交给 Actor。图像或视频生成、评分一旦拖长,训练就得跟着等。**把生成挪到独立 GPU,只解决了资源冲突,没有保证训练需要的样本随时够数。**

生成慢于消费时,Actor 仍会饿住;生成快于消费时,库存又会越来越旧。V1 要管理的是这两个相反方向的压力:让训练不必等原来那一整批,同时限制它能使用多早提交的题组。这里的题组是同一提示词的全部生成会话,不是任意拼起的几张图片。

## 二、解法

**把数据存放与取样资格拆开。** TransferQueue 存提示词、轨迹与状态标签;ReplayBuffer 根据这些标签挑选可用题组。分卡异步按已经完成的题组凑训练子批,不要求恰好是这次提交的整批。预热提前投任务,训练期间独立 Rollout 可以继续补货。

一个权重同步周期包含若干次 Actor 训练调用,每次消费一个完整子批,周期结束才给独立 Rollout 同步权重。这里没有承诺“一次训练调用只有一次优化器更新”。同步 V1 也使用这套交接结构,但仍按完整训练批等待,队列本身不等于异步。

**缓冲有年龄门槛,也有补货规则。** 默认异步策略丢弃提交年龄超限的完成题组,失败组也整组清走,再补入等量新提示词。另一个策略不按年龄淘汰,而是在仍在途的题组达到门槛时暂停取样,等它们结束。它保住的是这类旧任务,代价是可能重新等待长尾;失败组仍会被淘汰。

**库存不足时,还可以临时借用训练卡上的 Rollout 副本。** 这个开关默认关闭。打开后,借卡发生在周期边界,收回发生在下个周期开训前;训练子批之间不反复来回切。下图只画满足借出条件的一次交接。

## 三、代价

**并行需要额外 GPU,缓冲需要存储。** 增加预热深度只能缓冲短时供需波动,不会让长期偏慢的生成器变快;积压还会增加淘汰与重算。提交年龄从入队步号开始计,轨迹指标则记录实际接触过的权重版本,两者不能混读。

**借卡也会消耗时间。** 借出前要安装新权重、恢复生成并加入路由;收回要先摘路由,再中断、sleep。扩散引擎可能要等正在执行的整批生成结束才处理后续操作,所以收回不是瞬时的。中断后整条样本重试,已经做过的生成计算未必能保留。

是否借出,取决于预计减少的等待能否覆盖近期切换往返成本;还没有收益或成本历史时允许尝试。这个估计利用卡数比例近似新增产能,**不是实际加速比保证**。周期内旧策略重算还会保存和恢复周期起点的权重快照,不能只按少了多少次同步估计总收益。

## 四、与上游 verl 的关系

队列、回放缓冲和共卡借用不是 VeRL-Omni 独创。本项目直接复用固定依赖中的 ReplayBuffer,扩散训练器保留上游 V1 的生命周期分工;同样按题组取样、控制提交年龄,同步与分卡异步只是不同的调度钩子。

扩散适配改变了**交接的顺序和被中断后的处理**。本项目先完成独立 Rollout 权重同步,再看库存是否缺货,避免忽略同步期间已落地的结果;借出的共卡副本恢复后才加入路由,避免请求落到仍在 sleep 的引擎。中断请求从原始输入重新生成整条扩散样本,不能照搬文本 Token 续写的想象。

V1 支持 Policy Gradient 与在线 Direct Preference,拒绝的是离线 Direct Preference。同步、分卡异步以外的共卡异步模式在本基准尚未实现;不能把上游 verl 的所有模式直接当成本项目能力。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

表中 `S` 表示 `trainer.v1.separate_async`, `H` 表示 `S.hybrid_rollout`, `R` 表示 `trainer.v1.sampler`;默认列指配置文件,不是示例脚本覆盖后的值。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `trainer.use_v1` / `trainer.v1.trainer_mode` | V1 启动配置 | `false` / `sync` | 入口仍检查开关;启用后选择 `sync` 或 `separate_async` | 回退警告与实际训练器 |
| `S.parameter_sync_step` | V1 启动配置 | `4` | 增大一个同步周期内的训练调用数;须满足 `data.train_batch_size = S.parameter_sync_step × actor_rollout_ref.actor.ppo_mini_batch_size` | 启动断言、同步耗时与轨迹版本指标 |
| `S.num_warmup_batches` | V1 启动配置 | `1` | 提前提交更多任务,增加供给余量和积压 | 预热日志、取样等待与淘汰数 |
| `S.sync_compatible` | V1 启动配置 | `false` | 为真时训练期间暂停独立生成;要求预热为 `0` | 暂停/恢复日志,是否实际重叠 |
| `H.enable_switch` | V1 启动配置 | `false` | 开启动态借卡;要求 `S.sync_compatible=false`,且 Rollout disaggregation 关闭 | `separate_async/decision/should_switch_to_rollout` |
| `H.switch_threshold_ratio` | V1 启动配置 | `0.4` | 决定攒够多少题组才收回卡;四舍五入后钳在一个子批与整批之间 | `separate_async/switch/threshold_ratio`、`timing_s/switch_wait` |
| `H.adaptive_switch_threshold` | V1 启动配置 | `true` | 连续等待后提高收回门槛,持续平稳后降低;默认连续 `2` 步触发,分别加 `0.05`、减 `0.03` | 阈值曲线与 `separate_async/switch/idle` |
| `R.max_off_policy_threshold` / `R.max_off_policy_strategy` | V1 启动配置 | `8` / `drop` | 完成组提交年龄大于阈值时淘汰;`wait` 在在途组年龄达到阈值时暂停取样 | `training/off_policy/evicted_samples` 与等待时间 |
| `actor_rollout_ref.rollout.nnodes` / `.n_gpus_per_node` / `.checkpoint_engine.backend` | Rollout 启动配置 | 配方须明确配置 | 分卡异步要求独立资源数大于 `0`,传输后端不能是 `naive` | 资源与后端启动断言 |

**配置方向。** 从官方 SD3.5 Medium OCR 的完整 V1 配方开始,保留模型、数据、Reward 与并行配置,再调整下面的调度组合。分卡配方默认使用同步兼容设置,与上表的 YAML 默认不同。

| 场景 | 在官方完整配方上的调整 | 拿什么换什么 |
|---|---|---|
| 先建立同步基线 | 用 V1 sync 配方;分卡对照可保留 separate-async 配方默认的同步兼容、预热 `0`、同步间隔 `1`、年龄阈值 `1` | 先固定交接语义,暂不追求训推重叠 |
| 独立生成能持续供货 | separate-async 配方关闭同步兼容,恢复预热 `1`、同步间隔 `4`、年龄阈值 `8`,满足批量乘法约束 | 接受跨周期库存,减少等待整批的机会 |
| 真重叠后 Actor 仍常缺货 | 在上一组合上开启借卡,先保留默认收回比例与自适应 | 增加生成资源,承担切换与整条重试成本 |

组合与推荐值是按语义推的起点,不是实测最优。

**把等待与计算分开看。** `timing_s/gen` 在 V1 包含从缓冲取样的等待,不是独立 Rollout 的纯引擎时间。借卡另外看 `timing_s/switch_wait`、`timing_s/switch_to_rollout`、`timing_s/switch_to_trainer`;决策库存与成本看 `separate_async/decision/*`。已训练轨迹的版本滞后看 `training/off_policy/trajectory_staleness/*`,跨尝试最早版本的滞后看 `trajectory_staleness_worst/*`。吞吐归一已经计入独立 Rollout GPU,比较实验时须保持资源口径一致。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动了 V1 文件却没有队列路径 | `trainer.use_v1` 是否显式为真 | 修正入口开关;只改文件名仍会回退 |
| 分卡后生成仍在训练时停下 | 配方的 `SYNC_COMPATIBLE` 覆盖值 | 若要重叠,关闭兼容模式并核对预热与年龄预算 |
| 借卡后整步反而变长 | 收回成本与整条重试,而非只看生成吞吐 | 对照关借卡基线,确认节省等待是否覆盖切换 |
| 缓冲看似有样本,Actor 仍等待 | 完整可用题组数、失败组、年龄策略 | 区分未完成、超龄淘汰和 `wait` 主动阻塞 |

## 六、常见误区

- **看到 ReplayBuffer 就以为历史样本会反复训练。** 名字容易让人想到长期经验回放,这里正常流程取走题组后移除提示词键,周期结束再清理轨迹,主要作用是生成与训练之间的交接。
- **以为开借卡会在每次子批缺货时救场。** 切换安排在周期边界,卡已经收回后不会在同一周期中途反复借出;提高收回门槛是在开训前多攒库存。
- **以为调高年龄阈值总能减少空等。** 它放宽的是可用库存年龄,不能修复生成吞吐不足;更不能替代对 Reward、策略偏移与整步耗时的联合观察。
- **把同步兼容配方的稳定性直接当作异步验证。** 即使训练器名称写着异步,实际仍可能在 Actor 更新时暂停独立生成;先确认真实执行重叠,再讨论异步收益。
