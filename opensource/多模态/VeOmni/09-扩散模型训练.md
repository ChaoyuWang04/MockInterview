# 扩散模型训练

这一页回答一件事:训练扩散主干时,文本编码器和 VAE 这些只做前向、不训练的模型放在哪、什么时候算,主干一步又吃进去什么形状的数据。说法都在源码基准 `019b1c0276`(tag `v0.1.12`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

扩散主干(DiT)训练时吃的不是原始视频和提示词,而是 VAE 编出来的潜变量和文本编码器吐出来的嵌入。这两个编码器都冻结,但前向一点不轻:Wan 的文本编码器是 UMT5,VAE 要按 fp32 把整段视频压成潜变量。每一步都现编,算力就持续花在一个不训练的部分上;训 20 轮,同一段视频就被编 20 遍,编出来的结果每次都一样。

显存也被它们占着。编码器要整份常驻在每张卡上,和主干的参数、激活、优化器状态抢同一块显存,主干能开的序列长度与批大小跟着缩。开了序列并行更糟:一个序列并行组里的几张卡读的是同一份数据,各自编码就等于同一段视频在组里被编了好几遍。

批的形状也和文本不一样。视频的分辨率、帧数各不相同,拼不成一个张量;按 token 预算凑批的动态批在这里也不对——loss 若按 token 平均,长视频一条样本的权重就比短视频大好几倍。

还有随机性。扩散训练每一步都要抽噪声、抽时间步,这串随机数本身就是训练轨迹的一部分。续训时如果只恢复了权重和优化器,条件那一侧重新按种子起步,就会把训练开头那串噪声原样再喂一遍,不报错,只是训练悄悄偏了。

## 二、解法

最天然的直觉:**把条件模型当成数据管线的一段,而不是模型的一部分**。它冻结、不求导、输出只取决于输入,那它的输出就能存盘;存了盘,一次训练就拆成两个作业——先把整份数据编码一遍,之后训多少轮都只读盘。扩散模型、flow matching、DiT 与 VAE 本身的原理见知识库「Diffusion」「FlowMatching」「DiT」「VAE」四篇。

![在线训练与离线嵌入两条流水的对照:在线训练的每一步依次跑原始样本、条件模型编码(文本编码器与 VAE,冻结,整份放在每张卡上)、条件模型加噪、DiT 前向加反向;离线时拆成两个作业,第一个作业只跑原始样本与编码并把每个样本写成 parquet 的一行,不建 DiT 与优化器,第二个作业每一步从磁盘读回、在只剩空壳的条件模型上加噪、再做 DiT 前向加反向,编码那一格不再出现在训练步里](/opensource/VeOmni/09a-online-vs-offline-embedding.svg)

**两个模型,两套待遇。** 扩散训练器是 01 章那种拼出来的训练器,它的模型运行时里装着两个模型:主干照常走建模型、冻结或挂 LoRA、FSDP2 切分、建优化器那一整套;**条件模型**只被建出来、整体关掉梯度,不切分、不进优化器、不进 checkpoint 的权重部分,整份放在每张卡上。两者靠主干配置里的一个字段接起来:主干配置写着它的条件模型叫什么名字,训练器拿这个名字去 02 章那张注册表里取出条件模型的类。所以接一个新的扩散模型族,要登记的是一对名字。

**条件模型只交两个接口。** 一个是**编码**:原始提示词和视频进去,每个样本出一份潜变量参数和一份文本嵌入。一个是**加噪**:拿编码结果,抽噪声和时间步,造出带噪输入与训练目标,键名正好对上主干前向的参数名。拆成两个,是因为前者对同一个样本永远算出同一个结果,可以存盘复用;后者每一步都必须重新随机。Wan 的加噪取 VAE 后验的均值(不再采样),按 VAE 配置里的统计量归一化,在调度器的 1000 个训练时间步里均匀抽一个,按 flow matching 的插值造出带噪输入,目标是噪声减潜变量;另有 10% 的概率把这条样本的提示词嵌入换成负提示词的嵌入——不是置空——好让同一个主干顺带学会无条件那一支,CFG 的原理在知识库「Diffusion」。各族各用各的调度器:Wan 与 Qwen-Image 直接用 diffusers 的欧拉离散调度器,LTX-2.3 与 MiniMax-H3 带着自己的实现。

**三种任务,共用一条训练步。** 一个开关在三种任务之间选:在线训练每步先编码再加噪;**只做编码**的作业只跑编码,把结果写盘;离线训练跳过编码,从盘上读回来直接加噪。三者走的是同一个训练步,区别只在哪一格被跳过。

**只做编码的作业**是一个被削成只剩一半的训练作业:不建主干、不建优化器、不存 checkpoint、不打乱,全局批改成「微批 × 数据并行度」、不累积,只跑 1 轮。数据集先按全局批补齐成整数倍,让每张卡都拿到完整的批;补出来的那几条是重复样本,写盘器按每张卡该写的真实条数截住,每个原始样本只写一次。写盘的格式是约定俗成的一种:每个数据并行 rank 写自己的 parquet 文件,**每个样本一行,每一列是一个字段**,列值是这个字段搬到 CPU 后用 pickle 序列化出的字节。Wan 存两列:VAE 后验的均值与对数方差沿通道拼在一起(通道数 32 = 2 × 16),和文本嵌入。读回时,离线训练固定换上一个数据变换,把每一列反序列化回原来的对象,别的什么也不做。LTX-2.3 自带的预处理脚本写出的也是这种每样本一行、列值为 pickle 字节的 parquet,所以同一套离线训练能直接读。

**离线训练时,条件模型只剩空壳。** 加噪还要用到一点编码器的东西——VAE 的归一化统计量、负提示词的嵌入——所以条件模型仍然要建,但只建够用的部分,也不搬上 GPU。Wan 的 VAE 只按配置建出结构、不读权重;文本编码器启动时照常整份读进来,在 CPU 上把负提示词编码一次,然后就删掉。Qwen-Image 的空壳连编码器都不建;MiniMax-H3 靠它自己配置里一个跳过加载编码器的开关。

**固定微批:一个微批是一张「字段 → 样本列表」的字典。** 扩散训练器无条件关掉动态批(07 章),回到按样本数凑批:全局批 = 微批 × 数据并行度 × 累积步数,dataloader 每步给每张卡取「微批 × 累积步数」条,切成累积步数个微批。每个微批里,每个字段是一个长度等于微批大小的列表,一个样本一项,**不拼接、不打包、不按序列并行切**——打包、切序列、边界处理全归模型自己的代码。Wan 的前向就是一个循环,一个微批 2 条样本就是 2 次完整的主干前向;每条样本的 MSE 先在样本内部平均,再在样本之间平均,训练器最后除以这一步实际的微批数。这样长视频和短视频在梯度里分量相同,累积的各个微批之间权重也一致。

**序列并行:一张卡读,整组编码,整组同噪声。** 扩散训练器里只有序列并行组的 0 号卡建 dataloader,每步取出一整组微批,当成 Python 对象广播给组内其他卡;序列怎么在主干里切开、注意力怎么交换在 06 章。组内每张卡随后拿同一份数据各自走编码与加噪。噪声生成器的种子是「训练种子 + 数据并行序号」,同一个序列并行组里的卡数据并行序号相同,于是抽到一模一样的噪声、时间步和负提示词替换,各自切下的那段序列拼回去仍是同一条样本。

**checkpoint 里多存的一样东西:噪声生成器的状态。** 条件模型的权重不存,反正它冻结、每次都从原路径读。但它的噪声生成器会随训练推进,Wan 与 Qwen-Image 的条件模型把这个生成器的状态交给模型运行时,跟学习率调度器的状态一起写进这个模型那份按 rank 存的附加状态文件(目录结构在 13 章);续训时原样装回,噪声序列接着往下走。LTX-2.3 与 MiniMax-H3 用的是设备的默认随机数流,靠作业级的随机状态恢复。导出给推理用的主干则是纯 diffusers 格式:保存前把配置换成只含 diffusers 构造参数的那份,VeOmni 自己加的字段(模型类型名、条件模型名、注意力实现)一概不写,diffusers 的推理流水线不装 VeOmni 也能直接加载。

**为什么实际不吃亏**:编码只在只做编码的那个作业里算一遍,之后每一轮训练步里的条件模型只剩加噪那点标量运算;主干的显存里也只剩它自己和它的优化器状态。在线训练的编码在不求导的上下文里跑,不给反向留激活。

## 三、代价

**在线训练时,编码器是满配常驻。** 条件模型不切分,文本编码器与 VAE 在每张卡上各有一整份;开序列并行时,组内每张卡都把同一份数据完整编码一遍,省下的只有读数据那一下,而且广播的是解码后的视频帧,序列化开销随视频体积涨。

**离线嵌入把数据增强冻住了。** 缩放尺寸、帧数、提示词都在编码那一刻定死;想换分辨率或换一批提示词,整个预处理重跑。每步还在变的只剩噪声、时间步和负提示词替换。

**写盘器攒满一整份才写。** 只做编码时,写盘器默认把这张卡要写的全部样本先攒在主机内存里,攒够了才落成一个 parquet 文件。视频潜变量体积大,数据集一大,主机内存先撑不住;默认没有按条数分片的开关暴露出来。

**只做编码时开序列并行是纯浪费。** 组里每张卡都跑编码,只有 0 号卡写盘,其余卡的编码结果直接丢掉。官方示例在这一步把序列并行度设成 1。

**离线训练也要读编码器。** Wan 的空壳在启动时仍要把整份文本编码器读进主机内存、在 CPU 上算一次负提示词,条件模型的路径因此在离线训练里也必须给对。

**大一点的微批不等于更快。** 训练器只负责把样本装进列表,怎么处理多条样本是每个模型自己的事:Wan 逐条循环,微批变大只是把循环拉长,显存按最长那条算;MiniMax-H3 直接拒绝一个微批里超过 1 条样本;Qwen-Image 的时间步偏移随图像序列长度变,一个微批里所有样本必须同一分辨率,否则报错。

**各族的入口并不对称。** LTX-2.3 不支持在线编码,只能先跑它自带的预处理脚本再做离线训练;条件模型如果持有噪声生成器却没交出状态,续训只打一行警告,噪声序列从头重放。扩散训练器还重写了前向加反向(01 章),不支持分通道 loss,也不支持编译。

## 四、和同类大厂框架不一样的地方

对照对象是 Megatron-LM(基准 fb6a123a09)。

Megatron 在这个基准上没有扩散模型训练路径:它的多模态文档把扩散模型指向另一个仓库,核心库里只留了一个钩子,在流水并行各级之间同步条件嵌入层(时间步嵌入这类)的梯度,由模型配置里的一个标志打开。所以下面按「冻结的编码器塔怎么处理」这几件两边都得回答的事,拿它的多模态路径(LLaVA 与 MIMO)来对照。

| 两边都得回答的事 | VeOmni 的扩散训练 | Megatron-LM 的多模态路径 |
|---|---|---|
| 冻结的编码器塔算在谁身上 | 条件模型不属于主干,是运行时里另一个对象,不切分、不进优化器 | 视觉塔、音频塔是模型里的子模块;冻结就是把这些子模块参数的求导标志关掉 |
| 编码器放在哪张卡上 | 整份放在每张卡上,和主干共置 | LLaVA 的编码器跟着流水并行放在构造了编码器的那一级;MIMO 可以让编码器与语言模型占不重叠的两组卡,每张卡只跑其中一边 |
| 一个微批长什么样 | 字段到样本列表的字典,每个样本各自形状,由模型逐样本处理 | 图像按块堆成一个张量,和文本 token 一起走同一次前向 |
| 编码结果能不能提前算好存盘 | 能:只做编码的作业写 parquet,离线训练直接读 | 训练路径上没有把编码结果存盘再读回的机制,冻结的塔每步仍在前向里跑;只在推理侧有一个视觉嵌入缓存 |

这组差异背后是目标不同。Megatron 的多模态是「理解」:编码器的输出要和文本 token 交织成一条序列进语言模型,编码器与主干天然是一个图,冻结只是不求导。扩散训练里编码器只是给主干备料,备料结果与训练步无关,VeOmni 就干脆把它挪出训练步。

|---|---|---|---|---|

| `model.accelerator.ulysses_size` · 序列并行度 | YAML 或命令行 | 1 | 离线训练时切长视频;只做编码时应保持 1 | 日志 `Applied VeOmni SP patch to WanTransformer3DModel.forward.` 与拓扑那行 |

**观测。** 本章看 4 处。一是任务与条件模型:`Detected DiT model type: …` 给出主干类型,紧跟的 `Task: …` 与 `Condition model loaded …` 两行说明这次建了什么、条件模型是满配还是空壳。二是批形态:`Use fixed_sample_batching -->` 那段里的 `num_micro_batch` 就是累积步数。三是写盘:每张卡一行 `Rank … data length to save: n`,所有卡的 n 加起来应当等于原始数据集条数;写完看目录里每个 rank 各有几个 parquet。四是指标:Wan 的 loss 以 `training/mse_loss` 上报,是在 FSDP 组上平均过的;存 checkpoint 时如果出现以 `Condition model owns a` 开头的警告,说明这个条件模型的噪声序列续训时接不上。

**典型配置。** 三套起法,参数名与默认值都来自上表。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| Wan2.1 1.3B LoRA,8 卡,数据要训多轮 | 以 `configs/dit/wan2.1_I2V_1.3B_lora.yaml` 为底;第一步 `train.training_task: offline_embedding`、`model.accelerator.ulysses_size: 1`、设 `data.offline_embedding_save_dir`;第二步 `train.training_task: offline_training`、`data.train_path` 指向上一步的目录、`ulysses_size: 2`、`train.global_batch_size: 8`、`train.micro_batch_size: 1` | 用一次完整编码和一份磁盘占用,换每步不跑编码器、显存只留主干与优化器;代价是分辨率和帧数被第一步定死 |
| 新数据先跑通,不想先做预处理 | 同一份底配置,`train.training_task: online_training`、`ulysses_size: 1`、`train.max_steps: 20` | 省掉预处理与磁盘,换每步多付编码的算力与编码器常驻的显存 |

|---|---|---|
| Wan 起步就报 RoPE 实现没有后端 | `rotary_pos_emb_implementation` 是否还是默认值 | 填 `eager` |
| 用 `configs/dit/wan_sft.yaml` 起不来 | 它的 `config_path` 指向模型类型名为 `wan` 的旧配置,注册表里没有这个名字,也没设条件模型路径 | 改用 `wan2.1_I2V_1.3B_lora.yaml` 那种直接指向 diffusers 目录的写法 |
| 只做编码的作业很慢,或组里几张卡显存一样满 | `ulysses_size` 是否大于 1 | 设成 1;序列并行留到训练作业再开 |
| 只做编码时主机内存持续上涨直到被杀 | 单张卡要写的条数 × 每条潜变量体积 | 把数据集拆成几份分别跑,各写各的目录 |
| 离线训练报找不到条件模型的文件 | `model.condition_model_path` 是否给了 | 给回原模型目录,空壳也要从这里建 |
| Qwen-Image 报一个微批里图像序列长度不一致 | 微批里是否混了分辨率 | 微批设 1,或按分辨率分开数据 |
| MiniMax-H3 报只支持微批为 1 | `train.micro_batch_size` | 设 1,用累积步数凑全局批 |
| LTX-2.3 在线训练报不支持在线编码 | `training_task` | 先用它自带的预处理脚本产出 parquet,再 `offline_training` |
| 续训后 loss 曲线和刚开训时一模一样地抖 | 存 checkpoint 时有没有 `Condition model owns a` 开头的那条警告 | 给条件模型补上交出与装回生成器状态的两个方法 |

## 六、常见误区

- **以为离线训练就不用条件模型了。** 会这么以为,是因为嵌入都在盘上了。实际上加噪还要 VAE 的归一化统计量和负提示词嵌入,条件模型照样要建;Wan 在启动时甚至把整份文本编码器读进来、在 CPU 上算一次负提示词再删。条件模型路径缺了或指错,离线训练一样起不来。
- **以为把微批调大就会像文本训练那样打包提速。** 会这么以为,是因为文本训练里微批大了就是打包更长。扩散训练器只把样本装进列表,Wan 逐条跑完整的主干前向,微批 4 就是 4 次串行前向;MiniMax-H3 和 Qwen-Image 还会直接报错。要吞吐,先看模型自己支不支持。
- **以为扩散 loss 和文本一样按 token 平均。** 文本训练按全局有效 token 数归一。扩散这里是先在每条样本内部平均、再按样本平均、最后除以微批数,一条 81 帧的视频和一条短视频在梯度里分量相同。自己接新模型时如果按拼起来的全部 token 求平均,长样本就会被悄悄加权。
- **以为只做编码时开序列并行能把编码分摊掉。** 组内只有 0 号卡读数据和写盘,但每张卡都完整跑一遍编码,开得越大浪费越多。
- **以为 README 模型表里那份 Wan 配置就是当前的 Wan 入口。** 那份 `wan_sft.yaml` 指向模型类型名 `wan` 的旧配置,对应的是 `veomni/models/transformers/wan/` 里那个自写模型,它没有登记进注册表,只剩测试在用;配套的随机张量脚本写出的 `.tensors.pth` 文件,也只有 `veomni/data/diffusion/` 里那组没有任何调用点的数据集读得了。当前能跑的 Wan 走 `veomni/models/diffusers/wan_t2v/`,样例是 `wan2.1_I2V_1.3B_lora.yaml` 与对应的 1.3B 训练指南。
- **以为仓库里那个 flow matching 调度器是训练在用的。** `veomni/schedulers/flow_match.py` 当前没有调用点;Wan 与 Qwen-Image 用 diffusers 的调度器,LTX-2.3 与 MiniMax-H3 各带一份自己的。排查时间步分布要去看各族条件模型里那一个。同理,`veomni/utils/dit_utils.py` 也没有调用点。
- **以为续训会自动接上噪声序列。** 只有条件模型交出了生成器状态才会。Wan 与 Qwen-Image 交了;自己新接的条件模型如果只建了一个生成器却没实现交出与装回,续训只打一行警告,噪声从训练开头重放,loss 曲线不会报任何错。
