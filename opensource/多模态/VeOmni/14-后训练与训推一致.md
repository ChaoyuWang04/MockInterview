# 后训练与训推一致

这一页回答一件事:VeOmni 做后训练时——自己跑 DPO,或者给 RL 框架当训练引擎——逐 token 的 logprob 怎么算才放得下,怎么算才和推理侧对得上。说法都在源码基准 `019b1c0276`(tag `v0.1.12`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

后训练的 loss 不再是「全部 token 的交叉熵取平均」这一个数,而是**每个 token 的 logprob**:DPO 要 chosen 与 rejected 两段各自的 logprob 之和,PPO 一类要逐 token 的新旧概率比,蒸馏要学生在老师前 k 个候选词上的分布。HF 的原生写法是先把整段隐藏状态乘上输出层,得到一张「token 数 × 词表大小」的 logits,再做 log-softmax、取出目标 token 那一列。这张表是显存杀手:一个微批打包 32768 个 token、词表 151936(Qwen3 系),fp32 的 logits 就有 19.9 GB,log-softmax 的输出和反向的梯度又各是同样尺寸。长上下文的后训练常常先在这一步 OOM,轮不到注意力或专家。

第二件事只在 RL 里出现。同一段回答,推理引擎生成时算过一遍 logprob,训练引擎更新前再算一遍,两者之比进 loss。权重完全相同,数却可能不同:矩阵乘会按这一批有多少行挑不同的切法,归约顺序跟着变,bf16 下差在末几位;MoE 更糟,打分差一点就让 top-k 换掉一个专家,这个 token 往后每一层的输出都不一样。比值偏离 1 不是因为策略变了,而是两边的算子不一样——算法以为在做 off-policy 修正,实际在修正数值噪声,训练慢慢漂走。

第三件是 DPO 自己的形状:一对偏好是两段序列,要过两个模型(策略与冻结的参考)。两段怎么装进打包好的批、交界处的标签怎么对齐、参考模型用什么精度,错一处,轻则奖励从第一步起就不为零,重则 chosen 的最后一个 token 被当成在预测 rejected 的第一个 token,偏好信号里混进了跨段的内容。

## 二、解法

最天然的直觉:**logprob 是按 token 各自独立的数,根本不必同时握住整张 logits**。把 token 切成块,每块乘一次输出层、立刻取出要的东西、丢掉,显存里同一时刻只活一块。数值对不上的那一半,直觉同样朴素:**训练侧照推理侧的方式算**——换成不随批大小改变归约顺序的算子;MoE 的路由干脆不让训练侧自己选,照记录下来的专家编号走。

**一个标记把 loss 换成逐 token 输出。** VeOmni 改写过的模型前向,本来就把隐藏状态和输出层权重一起交给损失包装(03 章的融合交叉熵靠的也是这一点)。调用方在前向里多带一个「要 logprob」的标记,损失包装就不再算交叉熵平均,而是把这两样交给按块算子;返回时 loss 与 logits 两个位置留空,逐 token 的 logprob 和熵装进输出对象上的一个附加字段。以后要加新的逐 token 量,只扩这个字段,不必改每个模型的前向。DPO 训练器和外部的 RL 框架走的是同一个入口。

![按块融合的 logprob 与一次物化的对比:左边一次物化,隐藏状态 [T, H] 乘输出层权重得到整张 [T, V] 的 fp32 logits,32 个块高度全部同时占着显存;右边按块,隐藏状态切成 32 块,每块只和输出层权重相乘得到一块 [1024, V] 的临时 logits,取出目标 token 的 logprob 与熵写进长度为 T 的两条输出后立即丢掉,前向只把隐藏状态、输出层权重和标签存给反向,反向按块重算 logits 写出两份梯度](/opensource/VeOmni/14a-chunked-logprobs.svg)

**按块,前向不留 logits,反向再算一遍。** 默认 1024 个 token 一块:取出这一块的隐藏状态,乘输出层权重,转成 fp32,取出目标 token 的 logprob 和整行的熵,写进长度为 token 数的两条输出,这块 logits 随即丢掉。标签是忽略值的位置两项都记 0,也不回传梯度。反向不存任何 logits,按同样的块重算一遍,直接写出隐藏状态与输出层权重的梯度。所以前向必须把**输出层权重本身**存进反向上下文,这正是 04 章根模块前向后不释放的原因。运算顺序刻意照着 verl 自己的融合算子排:先在输入精度下做乘法与除温度,再升到 fp32;装了 flash-attn 时,逐 token 的负对数似然走同一个 Triton 交叉熵核,源码注释的说法是两边在确定性加批不变模式下逐位相同。

**top-k 蒸馏是同一个骨架多算三样。** 调用方再给出老师在每个位置的前 k 个候选词编号和对应 logprob,形状 [B, L, K],老师的 logprob 可以是 bf16,进来转 fp32。同一趟按块循环里,除了 logprob 和熵,再算只在老师 top-k 支撑上的前向 KL,以及学生、老师各自落在这 k 个词上的概率质量;两个质量只当指标,不回传梯度。可以给一个对数概率下限,两边先截再算 KL。它单独成一个算子而没有并进 logprob 那条,是因为后者是 DPO 与 PPO 的热路径、已经和 verl 逐位对过,作者不想让没有老师的调用也多走一条梯度支路。

**序列并行下各卡只算自己那段。** 标签在切序列之前已经整体错开一位,每张卡上的隐藏状态与标签天然对齐,算 logprob 不用向邻卡要下一个 token。要逐样本结果时,再在组内收集、去掉补齐的尾巴、按样本边界拆开(收集这一步见 06 章)。

**给 RL 框架当引擎,VeOmni 这一侧只多一个训练器基类。** 仓库里不带任何 RL 算法。这个基类和普通训练器只差两处:dataloader 不打包、不切序列,改在训练循环里、前向之前才做这两件事;前向之后按样本边界把输出收回来,得到逐样本的 logits。文本与视觉语言各有一个任务脚本把它拼起来。verl 真正接入时不走这个训练器,而是直接调模型前向:带上 logprob 标记和已经错好位的标签,需要时再带老师的 top-k,读回那个附加字段。verl 那一侧怎么接、权重怎么交给推理侧,见 verl 解读 03 章。

**DPO 把一对偏好拼成一条样本。** 数据变换把 chosen 与 rejected 首尾相接,位置编号在交界处归零,于是打包、序列并行都把它当普通样本处理,不需要专门的 collator;两段各自截到最大序列长度,所以一条样本最长是它的 2 倍。一条样本只带一份来源信息,按数据源拆 loss 时一对算一个来源(15 章)。每个微批先让参考模型不求导地前向一次,再让策略模型前向;整包的逐 token logprob 按样本边界切成段,偶数段是 chosen、奇数段是 rejected,各自在有效标签上求和。交界处要单独屏蔽:开着序列并行时标签是整包统一错位的,chosen 末位的标签其实是 rejected 的第一个 token;不开时按段各自错位,末位补忽略值。loss 有两种,标准的 sigmoid 形式(可加标签平滑)和 IPO 的平方形式;还可以不用参考,把参考那一侧的对数比当成 0。两个模型运行时怎么分工、各进哪套拓扑见 01 章;参考模型默认按 bf16 装载,正好等于策略模型混合精度下的计算精度。

**批不变模式换掉 4 个底层算子。** 打开之后,训练循环里策略模型前向与反向期间,在 CUDA 的分派层把矩阵乘、带偏置的矩阵乘、log-softmax、按维求均值换成改自 Thinking Machines 批不变算子库的 Triton 实现,出了作用域就撤回。矩阵乘是持久化核:每种数据类型固定一套 tile 大小,沿归约维按固定步长累加,不做归约维切分,一行结果怎么累加只取决于这套 tile,不取决于这一批有多少行。为什么这样就能让结果与批大小无关,见知识库「连续批处理」。注意力与 RMSNorm 不在这 4 个里;DeepSeek-V3 的批不变 RMSNorm 与确定性 RoPE 走 03 章的算子选择。

**完全确定性是另一个开关,管的是复现。** 它在设随机种子时一起生效:设 NCCL、cuBLAS 工作区与 FlashAttention 的确定性环境变量,打开 PyTorch 的确定性算法并关掉 cuDNN,昇腾上另设两个变量。它保证的是同一个作业重跑一遍结果一样,不是训练侧与推理侧一样。

**路由回放:VeOmni 只给钩子,不给路由。** 接了回放的 MoE 块,在路由器选出 top-k 之后调一个钩子。没有装管理者时原样返回,默认训练路径只多一次判空。装了管理者,就把专家编号交给它:记录模式存下来照用,回放模式换成事先记下的目标编号。换了编号之后,专家权重按原生路由器的同一套算术重算——同样的 softmax、gather、归一化、转精度——所以回放出来的前向,和「原生 top-k 恰好选中这几个专家」逐位相同。管理者由 RL 框架提供:verl 的 VeOmni 引擎里,一种模式在重算旧 logprob 时记录、更新时回放,另一种直接用 rollout 带回的逐层专家编号(verl 解读 12 章)。当前接了回放的是 Qwen3-MoE、Qwen3.5-MoE、DeepSeek-V4 三个族。

DPO、RLHF 与 KL 的原理见知识库「DPO」「RLHF与RM」「KL散度」,蒸馏见「蒸馏」,这里不重讲。

## 三、代价

**按块是用算力换显存。** 反向把输出层乘法按块重做一遍,等于多一次「token 数 × 隐藏维 × 词表」的矩阵乘;块在 Python 里串行循环。输出层权重从前向一直留到反向,不能在前向后释放。算子不支持输出层带偏置;温度只能是一个标量,不能按样本不同。

**逐 token 入口不挑交叉熵实现,但 eager 会白算一遍。** 选了非 eager 的交叉熵实现时,模型前向直接把隐藏状态交给损失;选 eager 时,前向先照常乘出整张 logits,再进损失包装,才转去 logprob 分支——整张 logits 已经物化过,按块省下的显存又花了回去。

**RL 训练器基类自己的收尾不省显存。** 它按样本拼出完整 logits,再算普通交叉熵,是给本仓库跑通流程用的;真正省显存的是 RL 框架直接走的那个前向入口。

**DPO 每个微批都付两次前向。** 参考模型完整装载一份,每个微批都前向一次,哪怕打开了「不用参考」——那时参考前向照做,结果被丢掉。参考前向也不在批不变作用域里,不经过按数据源拆 loss 的观测。

**DPO 的 loss 不按全局加权。** 基类训练器按每个微批占全局有效 token 的比例缩放 loss;DPO 训练器没有这一步:每个微批的 loss 是本微批偏好对的平均,直接反向,梯度在微批之间相加。动态批下每个微批装的对数不同,对数少的微批里每一对分到的权重更大;梯度量级也随累积步数放大,梯度裁剪的阈值要按这个量级看。日志里的 loss 与奖励指标倒是除过微批数的。

**DPO 当前只有文本版,且功能收窄。** 没有视觉语言的 DPO 训练器;参考模型不能单独配;多 token 预测的标签不会构造(02 章);MoE 模型走 logprob 路径时不带负载均衡辅助损失。

**批不变模式只在 CUDA 上生效,也不白给。** 其他设备上打开它等于没开,不报错。矩阵乘不再走 cuBLAS,改走固定 tile 的 Triton 核;log-softmax 只支持最后一维。完全确定性关掉了 cuDNN,确定性算法检查只告警不报错,不能拿它当逐位复现的保证。

**路由回放覆盖面窄。** 9 个 MoE 族里只接了 3 个,DeepSeek-V3、GLM-MoE-DSA、gpt-oss、Qwen3-VL-MoE、Qwen3-Omni-MoE、Qwen4-Exp 都没接,装管理者时的校验按模型类型直接拒绝。校验只看模型类型、不看设备:昇腾上的 Qwen3-MoE 能过校验,但它的生成文件不调钩子(02 章)。回放只换专家编号与权重,给负载均衡辅助损失用的路由 logits 仍是训练侧自己算的。

## 四、和同类大厂框架不一样的地方

对照对象是 verl(基准 f3d9b56e78)。

它是字节 HybridFlow 的 RL 训练框架,大规模 RL 在用,VeOmni 是它可选的训练后端之一,所以两边的分工本身就是这一章的边界。按两边都必须做的事分行:

| 要做的事 | VeOmni | verl |
|---|---|---|
| logprob 怎么算才不爆显存 | 损失包装里的按块算子,默认 1024 个 token 一块,自定义反向按块重算;模型前向带一个标记即启用,top-k 蒸馏同一个骨架 | 自带按块融合算子,默认 512 个 token 一块,打开融合内核后替换 HF 模型的前向;把 VeOmni 当后端时不用自己的,改给 VeOmni 模型前向传标记、读回附加字段 |
| 训推数值怎么对齐 | 训练侧换算子:批不变模式换 4 个底层算子,完全确定性开关;按块算子的运算顺序照 verl 的融合算子排 | 主要在损失端:保留 rollout 的 logprob,用重要性采样截断或拒绝采样过滤剩余偏差;计算端另有 QAT;确定性开关让推理侧打开 vLLM 的批不变模式 |
| MoE 路由怎么对齐 | 只提供钩子和「按原生算术重算权重」的保证,3 个模型族接了 | 提供管理者:一种记录重算旧 logprob 时的路由,一种用 rollout 带回的路由;VeOmni 后端把管理者装进 VeOmni 的钩子 |
| 参考模型放在哪 | 同一进程里第二个模型运行时,复制策略模型的配置,只服务本仓库的 DPO | RL 流程里的一个角色,默认与 Actor 同一组 worker 共卡,可以换后端,开 LoRA 时复用 Actor 的底座 |

两边是互补而不是竞争:VeOmni 把「算得省、算得和推理侧一样」做进模型前向与底层算子,自己不带 RL 流程;verl 管流程和损失端的兜底,需要逐位对齐时借用后端的实现。代价也各落一边——VeOmni 的批不变与回放只覆盖它接了的算子和模型族,覆盖不到的偏差仍要靠 verl 那一侧的修正去吸收。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。另有一组是集成方调模型前向时传的关键字参数与一个运行时接口,每次调用各自生效,放在第二张表。DPO 的超参数挂在顶层的 `dpo_config` 下,只有 DPO 任务脚本认。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `data.data_type` · 数据变换 | YAML 或命令行 | `conversation` | 设 `dpo`:每条样本拼成 chosen 加 rejected;对话格式要配 `chat_template`,纯文本格式读 `prompt` 字段并屏蔽提示词部分 | 样本长度约等于两段之和 |
| `data.max_seq_len` · 最大序列长度 | YAML 或命令行 | 2048 | DPO 下两段各自截到它,一条样本最长 2 倍;超出 token 预算的一对单独成一个微批 | 动态批日志里的 `batching_token_len` |
| `dpo_config.beta` · 偏离参考的代价 | YAML 或命令行 | 0.1 | 调大:偏离参考更贵,sigmoid 形式下 loss 更陡;IPO 下目标间隔 1/(2β) 变小 | `chosen_rewards`、`rejected_rewards` 都是 β 乘对数比 |
| `dpo_config.loss_type` · loss 形式 | YAML 或命令行 | `sigmoid` | `ipo`:平方损失,把对数比拉向 1/(2β),不再无上限地拉开 | `reward_margin` 是否停在一个值附近 |
| `dpo_config.label_smoothing` · 标签平滑 | YAML 或命令行 | 0.0 | 只对 sigmoid 形式生效;非零时按这个比例把偏好当成可能标反 | `reward_accuracy` 不再逼近 1 |
| `dpo_config.reference_free` · 不用参考 | YAML 或命令行 | false | true:参考那一侧的对数比当 0;参考模型照样装载、照样前向 | 显存与每步耗时不变 |
| `dpo_config.average_log_prob` · 按 token 平均 | YAML 或命令行 | false | true:每段 logprob 按有效 token 平均而不是求和,长回答不再因长度占便宜 | 奖励的量级变小 |
| `dpo_config.refer_model_precision` · 参考模型精度 | YAML 或命令行 | `bfloat16` | `float32`:参考模型权重与计算都是 fp32,显存翻倍,且与策略模型的 bf16 计算不再同精度 | 第一步的 `chosen_rewards` 是否为 0 |
| `train.enable_batch_invariant_mode` · 批不变模式 | YAML 或命令行 | false | 开:策略模型前向与反向期间 4 个底层算子换成批不变 Triton 核,只在 CUDA 上生效 | 每步耗时上升;同一批 token 换批组成重算 logprob 应逐位相同 |
| `train.enable_full_determinism` · 完全确定性 | YAML 或命令行 | false | 开:设确定性环境变量、打开确定性算法、关 cuDNN | 同配置重跑两遍逐步比对 loss;日志里的确定性告警 |

|---|---|---|---|---|
| `return_log_probs` | 模型前向 | False | 走逐 token 分支;必须同时给 `labels`,否则走普通 logits 路径 | `outputs.fused_linear_aux.log_probs`、`.entropy` |
| `shift_labels` | 模型前向 | 不传 | 传了就照用,不再内部错位,输出长度等于它 | 同上 |

| `log_prob_min_clamp` | 模型前向 | 不传 | 两边 top-k logprob 先截到这个下限再算 KL;两个质量指标用截之前的值 | `.distillation_losses` |
| `set_active_replay(manager)` | `veomni.utils.moe_router_replay` 运行时接口 | 未装 | 装上后接了回放的 MoE 块把 top-k 交给管理者;传 `None` 卸下 | 装之前先调 `validate_model_for_replay`,族没接会抛错 |

**观测。** DPO 作业看 3 处。一是启动:`Build DPO reference model` 之后才有 `Start DPO training.`,中间的拓扑日志应该全是复用(01 章)。二是每步的 5 个指标 `dpo_loss`、`chosen_rewards`、`rejected_rewards`、`reward_accuracy`、`reward_margin`,都是先在每个微批里算平均、再按微批数平均后上报;奖励是 β 乘「策略减参考」的对数比,不是 logprob 本身。三是交叉熵用的是哪种实现,看 03 章那行 `✅ VeOmni ops config applied: CrossEntropy (…)`,选 eager 意味着前向会先物化整张 logits。给 RL 框架当引擎时,本仓库这一侧没有专门的日志,逐 token 结果都在输出对象的 `fused_linear_aux` 里,在集成方那边看。

**典型配置。** 四套能直接抄走的起法,参数名和默认值都来自上表。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机 8 卡、Qwen3-0.6B 量级,先跑通 DPO | `bash train.sh tasks/train_text_dpo.py configs/text/qwen3_dpo.yaml`,样例里 `lr: 5.0e-7`、`max_grad_norm: 1.0`、`dpo_config.beta: 0.1`、`loss_type: sigmoid`、`refer_model_precision: bfloat16` | 用参考模型一整份显存和每个微批一次额外前向,换标准 DPO |
| 偏好标注噪声大 | 在上一行基础上加 `dpo_config.label_smoothing: 0.1`,或改 `dpo_config.loss_type: ipo` | 前者用 `reward_accuracy` 的上限换对标反样本不那么敏感;后者用有界目标换更慢地拉开间隔 |
| chosen 与 rejected 长度悬殊 | `dpo_config.average_log_prob: true`,β 从 0.1 起重调 | 用每 token 平均换掉「长回答的 logprob 和天然更小」的偏置,奖励量级随之变小 |
| 对齐实验:核对训练侧与推理侧的 logprob | `train.enable_full_determinism: true`、`train.enable_batch_invariant_mode: true`,交叉熵选非 eager(03 章) | 用吞吐换同一批 token 在不同批组成下逐位相同 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| DPO 第一步 `reward_accuracy` 是 0 | 第一步策略与参考权重相同,两个奖励本应都是 0 | 正常:这个指标按「chosen 奖励严格大于 rejected」算,平局记 0 |
| 第一步 `chosen_rewards` 就明显不为 0 | `refer_model_precision` 是否 `float32`;是否开了批不变模式 | 前者改回 `bfloat16`;后者是参考前向不在批不变作用域里,差在末几位属预期 |
| 长序列 DPO 在 loss 处 OOM | 交叉熵是否选了 `eager` | 改非 eager 实现(03 章),前向就不再物化整张 logits |
| 只改了全局批,DPO 训练行为就变了 | 累积步数 = 全局批 ÷(微批 × 数据并行度)变了没有 | DPO 的梯度随累积步数放大,按新的量级重看梯度裁剪与学习率 |
| MoE 模型 DPO 第一次前向就报类型错误 | 模型配置是否打开了 `output_router_logits` | 关掉;logprob 路径的 loss 位置是空的,不能再往上加辅助损失 |
| 开路由回放报 `router replay is not wired for model_type=…` | 模型族在不在已接的 3 个里 | 换已接的族,或关掉回放 |
| 昇腾上 Qwen3-MoE 开了回放,记录不到路由或回放不生效 | 用的是不是 NPU 生成文件 | 它没接钩子(02 章);回放放到 GPU 上跑 |

## 六、常见误区

- **以为打开 `reference_free` 能省掉参考模型。** 会这么以为,是因为名字写的是「不用参考」。实际上它只把参考那一侧的对数比换成 0;参考模型照样按策略模型的切法装载一整份、每个微批照样前向。想省这份显存,当前没有开关。
- **以为参考模型用 fp32 更准。** 会这么以为,是因为 fp32 听上去总比 bf16 精确。但策略模型开着混合精度时是在 bf16 下算的;参考用 fp32,两边第一步的 logprob 就不相等,奖励从第一步起带着一个与训练无关的偏移,还多占一倍显存。默认 bf16 恰好是和策略同精度的选择。
- **以为打开批不变模式就训推一致了。** 它只换训练侧 4 个底层算子,只在 CUDA 上生效,只罩住训练循环里策略模型的前向与反向;注意力不在里面,推理侧也得用同样不随批变的算子才对得上。完全确定性则是另一回事,它让同一个作业重跑一样,不让训练侧和推理侧一样。两个都开,也只是把 VeOmni 这一侧能做的做完。
- **以为路由回放是 VeOmni 在记推理侧的路由。** 会这么以为,是因为回放的文件和钩子都在 VeOmni 里。实际上 VeOmni 只在路由器之后留一个钩子,记什么、何时回放、编号从哪来,全由 RL 框架装进来的管理者决定;没有管理者时钩子什么也不做。排查回放问题要先看管理者那一侧有没有把逐层编号交进来。
- **以为选哪种交叉熵实现,logprob 都一样省显存。** 逐 token 入口确实不挑实现,所以很容易以为结果只差速度。但选 eager 时,模型前向在进损失包装之前就已经乘出整张 logits;按块算子照样跑,省下的那部分显存早被这张表占掉了。长序列后训练要用非 eager 的实现。
- **以为 MoE 模型做 DPO 会带上负载均衡辅助损失。** 会这么以为,是因为同一个模型做 SFT 时 loss 里有它。logprob 路径把 loss 位置留空,DPO 训练器只用逐 token logprob 算自己的 loss,辅助损失不参与;模型配置里如果打开了路由 logits 输出,前向还会在往空 loss 上加辅助损失那一步直接报错。
- **以为 DPO 的 loss 像 SFT 一样按全局 token 加权。** 会这么以为,是因为同一个框架的其他训练器都这么做。DPO 训练器每个微批按偏好对取平均后直接反向,不按全局比例缩放;累积步数一变,梯度量级就跟着变。
