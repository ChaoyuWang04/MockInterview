# VeOmni 框架总览

源码基准:官方仓库 <https://github.com/ByteDance-Seed/VeOmni>,分支 `main`,commit `019b1c0276f0fee6175413367910c0a649593131`,最近的发布 tag `v0.1.12`(仓库自报版本 `0.1.12`),核对日期 2026-09-23。全篇的「当前」「默认」都指这组基准。

## 一、VeOmni 是什么

**VeOmni** 是字节 Seed 团队开源的多模态训练框架,文本、视觉语言、Omni、扩散模型都用同一套代码训,预训练与后训练都覆盖。它要解决的问题是:**新模型接进来太贵**。像 Megatron-LM 那样以系统为中心的框架,模型定义和并行逻辑缠在一起,每来一个新结构——多一个视觉塔、多一个音频塔、专家数换了、注意力变稀疏了——都要有人去改分布式代码。

VeOmni 的回答是把两件事拆开,并把「这个模型该怎么切」交还给模型自己:

- **模型那一侧**,官方 HF 的 modeling 原样拿来,用代码生成改写成训练版,每个模型再自报一份并行计划,说清哪些参数要沿哪一维额外切
- **框架那一侧**,只提供一套底座:FSDP2 管所有参数的分片,Ulysses 序列并行管长序列,专家并行管 MoE;底座按模型交来的计划去切,不认识任何具体模型

一句话定位:**VeOmni 是一个以模型为中心的 FSDP2 训练框架——模型自带并行计划与生成的训练版 modeling,算子按配置与硬件逐个解析,框架只负责把这些拼成一次训练。**

它**不做**的事同样要先说清:张量并行与流水并行不支持(配置里两者大于 1 会直接报错);Omni 模型训练时只训 thinker,说话的 talker 部分在训练前被关掉。

顶层入口(仓库根):

- `train.sh <任务脚本> <配置文件> [命令行覆盖]`:探测本机是 NVIDIA、AMD 还是寒武纪设备,数出卡数,再用 `torchrun` 拉起任务脚本
- `tasks/train_text.py`、`train_vlm.py`、`train_dit.py`、`train_text_dpo.py`:文本、视觉语言与 Omni、扩散、DPO 四种训练,每个脚本只有 8 行,构造一个 trainer 然后调用 `train()`
- `tasks/train_text_rl.py`、`train_vlm_rl.py`:给强化学习框架当训练引擎时用的变体,本身不含 RL 算法
- `patchgen`:把 HF modeling 改写成训练版的代码生成器,是仓库里单独发布的一个包(`patchgen-pkg/`)

**代码花在哪**(只算 `veomni/` 下的 `.py`,不含测试):共 7402 KB、454 个文件。**按模型族的代码占 66%**——其中 2888 KB 是生成出来、不许手改的 modeling,约 2000 KB 是按族手写的补丁配置、扩散模型与权重转换器;算子实现 717 KB;而真正的训练框架本体(trainer、分布式、数据、checkpoint、优化器、配置)加起来约 1.3 MB,**不到 18%**。这个比例本身就是「以模型为中心」的样子:框架很薄,厚的是一个个模型。

一句话记忆:

- **生成的 modeling**:改 HF 模型不在运行时打猴子补丁,而是用一份补丁配置声明「换掉哪个类、重写哪个方法」,生成器吐出一个自包含的 modeling 文件。改了什么、为什么改,都写在生成文件的注释里,升级 transformers 时重新生成、看差异即可。多数模型族在 GPU 之外另生成一份昇腾 NPU 版。
- **模型自报并行计划**:模型实现一个返回并行计划的方法,按参数名模式声明「这些参数沿第 0 维切给某个并行组」。专家并行、词表并行都是这套机制的实例,框架统称为额外并行;没有计划的模型只走 FSDP2。
- **算子逐个解析**:注意力、RMSNorm、旋转位置编码、SwiGLU、交叉熵、MoE 专家计算等每个可替换的算子,在生成的 modeling 里是一个空位;建模型之前按配置与硬件把实现绑进去。同名算子数学不同(标准 RMSNorm 与带偏移的 RMSNorm)被当成不同变体,不会被误替换。
- **只用 FSDP2**:FSDP1 已移除,初始化默认在元设备上,不分配显存先把结构搭出来,切完再装权重;额外并行的参数沿第 1 维交给 FSDP2,普通参数沿第 0 维。
- **Ulysses**:序列沿卡切开,注意力前一次 all-to-all 换成按头切,算完再换回来;还有一个把通信和 QKV 投影重叠起来的异步版本。DeepSeek-V4 另有一条只切 query、KV 全收集的上下文并行,两者互斥。
- **作业一半、模型一半**:trainer 只管一个作业只有一份的东西(进程组、数据、循环、回调);模型的构建、冻结、分片、优化器与存取归一个模型运行时对象,各自按名字注册一套并行拓扑。DPO 的策略模型与参考模型就是一个作业里的两个运行时。

下表是本解读的章表。**这里只回答「它存在是为了解决什么」**;展开讲解在各章,代码在哪见代码索引页。

| 主题 | 不这么做会怎样 | 做法一句话 | 详见 |
|---|---|---|---|
| 一次训练的形状 | 一个作业里有两个模型时,谁在哪套网格上建、上下文漏一处就用错进程组,静默算错或挂住 | trainer 只管作业级的东西,每个模型交给一个自带网格与构建顺序的运行时 | 01 章 |

| FSDP2 装配 | 几百 B 的 MoE 每个 rank 完整实例化一份就 OOM;装完初始权重再读续训 checkpoint,显存二次冲顶 | 元设备建空壳、自底向上分片、分片后再逐块装载,续训时跳过初始权重 | 04 章 |
| 专家并行:两维切专家 | 专家维同时给专家并行和 FSDP 切,两者乘积必须等于专家数,规模一大就配不出来 | 专家数那一维给专家并行,隐藏维那一维给 FSDP2,再按嵌套分片手动排预取 | 05 章 |
| 长序列 | 序列一长激活放不下;头数不能被并行度整除时根本开不了 | Ulysses 在注意力前后换切法;DeepSeek-V4 改走只切 query 的上下文并行 | 06 章 |
| 数据:打包与动态批 | padding 浪费算力;各 rank token 数不齐,快的等慢的;续训时数据重放或跳过 | 去掉 padding 拼成一条,按 token 预算动态凑批,数据游标按 rank 各存一份 | 07 章 |
| 多模态进同一条线 | 图像与视频数量不均让编码器负载在 rank 间悬殊;前向里从 GPU 张量推元数据引发隐式同步;视觉塔被主干学习率冲坏 | 元数据在 CPU 的 collator 里预先算好,塔可冻结或单独给学习率;编码器负载均衡的开关与均衡器都在,当前没有模型接上 | 08 章 |
| 扩散模型训练 | 文本编码器与 VAE 每步重算,算力与显存都浪费在不训练的部分 | 条件模型冻结,可以离线先算好嵌入,主干按固定微批训练 | 09 章 |
| 显存:重算与激活卸载 | 长序列下激活显存超过权重;同步卸载把每一步拖慢 | 默认按层重算,再往下可以把激活异步搬到主机内存 | 10 章 |
| LoRA | 大 MoE 全量微调装不下;通用 LoRA 库与 FSDP2、专家并行接不上 | 自带一套与 PEFT 格式兼容的 LoRA,专家权重也能挂适配器 | 11 章 |
| 优化器:分片下的 Muon | Muon 要对整块矩阵做正交化,FSDP 与专家并行把矩阵切碎,不聚合就算错,全聚合通信又太重 | 按参数的分片方式分类,各走本地、聚合或专家分组三条路 | 12 章 |
| checkpoint | 续训后数据错位;导出 HF 权重时单卡聚合 OOM;并行度一换读不回 | 权重与优化器走 DCP,数据游标与随机状态按 rank 各存,导出与续训分两棵目录 | 13 章 |
| 后训练与训推一致 | 算 logprob 时物化整张词表维 logits 爆显存;训练侧与推理侧数值不一致、MoE 路由不一致让 RL 漂 | DPO 双模型、按块融合的 logprob 与蒸馏损失、批不变算子与路由回放 | 14 章 |
| 可观测 | 多源混训时总 loss 平稳,某一个数据源却在退化;专家负载失衡没人报 | 按数据源拆 loss,监控路由分布,按实际 FLOPs 报 MFU | 15 章 |

## 四、一次训练怎么串起来

![VeOmni 一次训练的总图:左侧构造期,trainer 先建进程组并注册并行拓扑,再由模型运行时依次完成注册表取类、算子绑定、冻结或 LoRA、按并行计划与 FSDP2 分片装载、建优化器;右侧每一步,dataloader 在 CPU 上把样本打包、切序列并凑成若干微批,trainer 逐微批前向反向,最后裁剪梯度、更新参数并交给回调存 checkpoint 与上报指标](/opensource/VeOmni/00a-one-training-job.svg)

**构造期**分两半。trainer 先做作业级的事:初始化进程组,按配置注册一套名为 `base` 的并行拓扑,设随机种子。然后构造**模型运行时**——构造它就等于把模型建好:在这个模型自己的拓扑下,按模型类型从注册表取出生成的 modeling 类,把各算子空位绑上具体实现,在元设备上建出空壳;冻结不训的部分或挂上 LoRA;先按模型自报的计划把额外并行的参数切开,再自底向上逐层分片、装入权重;最后建优化器。回到 trainer,在同一套拓扑下建数据变换、数据集、collator 与 dataloader。数据集建好才知道一共多少步,所以学习率调度器最后建。

**每一步**从 dataloader 取出**一组微批**。打包、切序列、凑批都在 dataloader 的 CPU 进程里做完:样本去掉 padding 首尾相接,边界记成位置编号;开了序列并行就在这里按 rank 切好;开了动态批就按 token 预算决定每个微批装几条样本。微批个数等于全局批大小除以「微批大小 × 数据并行度」。

trainer 先把这组微批的有效 token 数在全体数据并行 rank 上归约一次,loss 按**全局有效 token 数**平均——这样不管每张卡分到多长的样本,每个 token 的权重都一样。然后逐个微批前向、反向。默认每个微批反向后都重分片;关掉反向后重分片时,改为只在最后一个微批做一次。开了组间复制时,跨副本的梯度归约同样只在最后一个微批做。最后裁剪梯度、优化器与调度器各走一步,回调按顺序处理指标、checkpoint 与评估。存 checkpoint 时权重先落盘、数据游标后落盘,这样两者之间崩溃也只是丢游标,不会让游标跑在权重前面。

## 六、怎么调它、怎么看它

各章「调参与观测」只写自己的参数,入口在这里说一次。

**配置只有一个真源:`veomni/arguments/arguments_types.py` 里的一组数据类。** YAML 与命令行都只是给这些字段赋值,改了都要重新拉起作业。

| 入口 | 长什么样 | 什么时候用 |
|---|---|---|
| YAML 配置 | `configs/text/`、`configs/multimodal/`、`configs/dit/` 下按模型给的样例,顶层分 `model`、`data`、`train` 三段 | 定一套固定的实验配置 |
| 命令行覆盖 | 启动命令末尾追加点分路径写法,如 `--model.accelerator.ulysses_size 4` | 单次实验调某几个值 |
| 配置数据类 | 字段默认值、校验逻辑与帮助文字都在这里 | 查一个字段的真实默认值 |

三段的分工:`model` 下是模型路径、并行与分片(`model.accelerator.*`)、算子选择(`model.ops_implementation.*`)、LoRA 与优化器;`data` 下是数据路径、数据集类型、最大序列长度;`train` 下是批大小、动态批、checkpoint 与日志。**并行与算子挂在 `model` 下而不是 `train` 下**,因为一个作业里的每个模型各有一份——这正是「模型一半」的配置形态。

作业启动时,解析后的完整配置会落一份 `veomni_cli.yaml` 到输出目录;复现一次实验以它为准,不以你手上的 YAML 为准。

观测的三处:每步的 loss、梯度范数、学习率显示在 rank 0 的进度条上,不落进文本日志;打开 wandb 开关(默认关)后才成曲线,MFU 与每秒 token 数也只在 wandb 里;显存在建完模型、每个 epoch 结束时各打印一次到日志;更细的归因走 profiler 回调,多数据源与 MoE 的专项指标见 15 章。

## 七、阅读顺序

主干是 01 → 02 → 03 → 04,读完就抓住了 VeOmni 的主线:一次训练怎么分成两半、模型从哪来、算子怎么选、怎么切开放下。05 与 06 是把这条主线推到大模型与长序列上的两件事(专家怎么切、序列怎么切),训 MoE 或长上下文时读。07 与 08 是数据侧,**训多模态之前必读 08**——它讲的是编码器塔怎么不拖垮整条线。09 到 15 按需查阅,其中 13 章在你第一次存 checkpoint 之前就该读。

**怎么读**:本解读**不讲这些机制本身是什么**——FSDP 分片、序列并行、专家并行、LoRA、Muon 的原理,知识库里各有一篇,这里只写 VeOmni 怎么落地、和大厂框架差在哪、怎么调。每一章都是短页:核心问题、解法、代价、和同类大厂框架不一样的地方、调参与观测、常见误区。哪一句想展开,在对话里问。

和站内另外几份训练侧解读的分工:

- **FSDP**:VeOmni 把 FSDP2 当成唯一底座直接用。FSDP2 自己怎么分片、预取、改存储,见 FSDP 那份;这里只写 VeOmni 怎么调用它、在它之上加了哪一层(额外并行的第 1 维分片、手排的预取)
- **Megatron-LM**:同是大模型训练框架,但路线相反——Megatron 自己写模型层,并行逻辑写进层里,支持张量与流水并行;VeOmni 拿 HF 模型来改写,并行计划挂在模型外面,不做张量与流水并行。两边的对照集中在各章第 4 段
- **verl**:verl 把 VeOmni 当成可选的训练后端之一。VeOmni 怎么被接进 RL 训练循环、权重怎么交给推理侧,写在 verl 那份;这里的 14 章只写 VeOmni 这一侧为 RL 提供了什么

## 八、术语表

| 术语 | 一句话 |
|---|---|
| 生成的 modeling | 由补丁配置加官方 HF 源码生成的训练版模型文件,不许手改,改动要回到补丁配置 |
| 补丁配置 | 声明换掉哪个类、重写哪个方法、加哪些导入的 Python 文件,按模型族与硬件各一份 |
| 模型注册表 | 按模型类型登记「用哪个类」的表,没登记的类型默认直接报错;配置类没登记时才沿用 HF 的 |
| 算子空位 | 生成的 modeling 里为可替换算子留的占位对象,建模型前绑定实现,未绑定时走 HF 原逻辑 |
| 变体 | 同名算子的数学口径,只有同一变体的实现才能互相替换 |
| 并行计划 | 模型自报的一张表:哪些参数名模式、沿哪一维、切给哪个额外并行组 |
| 额外并行 | 在 FSDP2 之外按并行计划另切的一维,专家并行是其中名叫 ep 的那一种 |
| 模型运行时 | 一个模型的训练单元,构造它就完成建模型、冻结、分片、建优化器 |
| 命名拓扑 | 按名字注册的一套设备网格与进程组,一个进程里可以有多套,拓扑相同的共用一份 |
| 打包 | 把一个微批里的样本去掉 padding、首尾相接成一条,用位置编号标出样本边界 |
| 动态批 | 按 token 预算而不是样本条数决定每个微批装多少样本 |
| thinker 与 talker | Omni 模型里负责理解并生成文本的部分,和负责生成语音的部分;VeOmni 训练时只保留前者 |
