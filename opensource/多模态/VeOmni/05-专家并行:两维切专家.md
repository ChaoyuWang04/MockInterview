# 专家并行:两维切专家

这一页回答一件事:MoE 的专家权重怎样同时交给专家并行和 FSDP2 去切,token 又怎样在切开的专家之间走一个来回。说法都在源码基准 `019b1c0276`(tag `v0.1.12`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

只用 FSDP2 训 MoE,专家权重和其他参数一样沿第 0 维切给全部卡,每层前向先把整层专家聚合回来。Qwen3-30B-A3B 一层有 128 个专家,每个 token 只用其中 top-k 个,可每张卡每一层都要把 128 个专家的权重全部聚合一遍:通信和临时显存按「全部专家」付,计算只用到一小撮。

专家并行把专家整块分给不同的卡,让 token 去找专家,专家权重就不用再聚合。但它只切了专家数这一维,剩下的卡还要做数据并行,专家权重在这些卡之间是整份复制的。最顺手的补法是让 FSDP 沿专家数那一维接着切:两刀落在同一维上,每张卡的专家数 = 专家数 ÷(专家并行度 × 专家内分片度)。128 个专家、256 张卡、专家并行度 8 时,每组 16 个专家要再分给 32 张卡——除不尽,大量卡分到空片。卡数一变、专家数一变,就得重新凑一组能整除的数,**规模一大就配不出来**。

切成两刀之后,一层里就有了两套分片组:专家挂在一套,注意力、路由、norm 挂在另一套。凡是「全模型只算一遍」的事都得分两边算,而且算错不报错。专家的梯度里混着全体卡送来的 token,只按本组大小平均,口径就比稠密参数大专家并行度倍;梯度范数在错的组里重复求和,范数虚高,裁剪过狠;FSDP2 默认按组各自在用到前才聚合,专家那一组的聚合来不及被注意力的计算盖住,每层前向都要干等一截。

专家以外也有同样形状的参数。Qwen4-Exp 的多个层带一张按 n-gram 查表的嵌入(PLE),发布的表合计约 95 GiB。只按行切给一组卡、再交给 FSDP2 按列存,前向时 FSDP2 仍要把本卡那些行的整列聚合回来,峰值还是整表的 1/行切分度。

## 二、解法

最天然的直觉:**两刀切在不同的维上**。专家数那一维按专家并行整块分,每张卡只负责若干个完整的专家;持有同一批专家的那几张卡之间,再由 FSDP2 沿第 1 维切开存。两刀互不相干,约束就从「乘积凑整专家数」变成两条各自的整除。

![16 张卡、专家并行度 8 时同一层参数的切法。左边是专家权重的二维网格,横向 8 块对应专家并行,每块 16 个专家;纵向 2 行对应专家内 FSDP,把隐藏维 2048 切成前后两半;16 个格子各标一个 rank,第一行是 0 到 7,第二行是 8 到 15,每格本地形状是 16 乘 1024 乘 768。绿框圈出第一行,是一个专家并行组;紫框圈出第一列 rank 0 与 8,是一个专家内 FSDP 组。右边是非专家参数,沿第 0 维切成 16 条,分给 rank 0 到 15,整体是一个 FSDP 组](/opensource/VeOmni/05a-two-dim-expert-sharding.svg)

**切法由模型声明。** 每个 MoE 模型族自带一份并行计划(ParallelPlan):按参数名模式列出哪些参数、沿哪一维、交给哪个名字的组。Qwen3-MoE 和 DeepSeek-V3 的计划都只有 2 行,每层融合的 gate+up 专家张量和 down 专家张量,沿第 0 维交给名叫 ep 的组;GPT-OSS 多 2 行专家偏置。框架不认识任何具体模型,切分时只按计划匹配参数名;挂了 LoRA 之后参数名会变,计划由框架自动改写对齐(11 章)。

**先切专家并行,再交给 FSDP2。** 在逐层分片之前(04 章构建顺序里的第二步),框架把每个命中的参数在专家并行组上沿第 0 维切片,然后换成本地那一块普通张量,丢掉它的分布式身份。设计文档写明了理由:专家计算时不需要像 FSDP 那样把它聚合回来,专家之间怎么通信由融合 MoE 算子自己管。每个参数都挂一张分片说明(SpecInfo),记下它属于哪个组、沿哪一维切、FSDP 那一刀落在第几维;存 checkpoint 时靠它临时把专家维补回去(13 章)。

**二维网格在建拓扑时一次建好。** 开了专家并行,拓扑在普通网格之外再建一张二维子网格,两维依次是专家内 FSDP 与专家并行。专家并行固定在最内一维,所以一个专家并行组是编号相邻的一段卡,上图里是 0–7 和 8–15;专家内 FSDP 组隔一个专家并行度取一张,是 0 与 8、1 与 9,依此类推。这张网格铺的是 FSDP 分片那一侧,即数据并行分片度乘上序列并行度;开了 HSDP,最前面再加一维复制。专家内 FSDP 的度数自动等于「分片侧卡数 ÷ 专家并行度」,不用配。硬约束只有两条:专家数能被专家并行度整除,专家并行度能整除分片侧卡数。

**逐层分片时专家单独成组。** 要单独分片的专家模块,取的是计划里模式的父模块,不靠 mlp.experts 这种固定路径。分片自底向上:每个解码层里,专家模块先在专家内 FSDP 组上分片,落在第 1 维;这一层剩下的参数再在全卡 FSDP 组上按第 0 维分片;根模块最后收尾。第 1 维对 down 专家张量 [E, H, I] 是隐藏维 H,对融合的 gate+up 张量 [E, 2I, H] 是 2I。

**token 的一个来回。** 开了专家并行,03 章选中的融合专家实现会进入专家并行分支,每个 MoE 层依次做 6 步:

1. 专家并行组内 all-gather 一次「本卡要发给每个专家多少行」的计数,算出发往每张卡、从每张卡收多少行,并拷回主机
2. 本地按专家重排,一个 token 选了几个专家就复制几行,同一张卡上的两个专家也各一行
3. 变长 all-to-all 把这些行送到持有目标专家的卡
4. 收到的行按本地专家重新归拢,每个专家一段
5. 分组矩阵乘(EPMergedFc1GroupGemm):gate+up 一次、激活、down 一次;反向时用同一组计数把 all-to-all 倒着走
6. 逆重排,all-to-all 送回原卡,乘上路由权重,按 FP32 累加回原位置

不设容量,不丢 token。Triton、Quack、寒武纪三家的专家实现直接调同一组分发函数;昇腾实现自带计数与重排,用的是同一个 all-to-all。专家计算有哪几种实现、默认哪个,归 03 章。

**预取手排。** 一个解码层现在是 2 个分片组(模型声明了精度豁免模块时是 3 个)。开了额外并行,框架给每个解码层排好:前向执行第 i 层时,预取第 i+1 层的全部分片组,顺序是层本体、精度豁免模块、专家;反向对称地预取前一层。这样专家那一组的聚合提前一整层发出,不再只靠本层注意力的计算去盖。

**专家梯度除以全体卡数。** 专家的梯度里混着全体卡的数据:all-to-all 送来的是整个专家并行组的 token,再在专家内 FSDP 组上归约,合起来正好覆盖全部卡。FSDP2 默认按本组大小求平均(上图是 2),框架对每个专家分片组显式把梯度除数改成全体卡数,和稠密参数同一个口径;源码注释写明,开不开 HSDP、开不开序列并行都是这个数。昇腾的通信库缺这种自定义除数所需的归约算子,框架打补丁补上。

**优化器和裁剪按网格分家。** 专家参数与其他参数挂在不同的网格上,批量更新的算子不接受混着两张网格的张量列表,所以每张网格各建一个优化器,再合成一个对外;学习率调度器同理。梯度裁剪按组归约平方和:非专家参数沿 FSDP 组归约;专家参数先沿专家内 FSDP 组、再沿专家并行组归约;几路相加后开方得到一个全局范数,所有参数用同一个系数裁剪。04 章讲的是裁剪按参数分法选路的总体,这里是其中额外并行那一路。

**额外并行不止专家。** 这套机制在代码里叫额外并行(ExtraParallel),专家并行只是名叫 ep 的那一个。名字可以列任意多个,每个名字各有一张二维网格;一个参数同时匹配两个启用的名字,直接报错。框架只管三件事:按计划切存储、单独分片、裁剪时分组归约;前向里怎么使用这块切片,由模型自己写。测试里用玩具模型演示过词表嵌入按行切,树内模型除专家之外只有 Qwen4-Exp 的 PLE 表用了它。

**PLE 表是二维常驻切。** PLE 在名叫 ple 的组上按行切,在它的互补组上按列切,两刀都常驻:参数保持为二维网格上的分布式张量,每卡只存 [行数 ÷ 行切分度, 列数 ÷ 列切分度] 这一块,FSDP2 整个跳过它们,前向反向都没有参数聚合。查表改成路由请求:每个请求按行号找到行主人,再复制给该行的每个列主人,在两维摊平成的一个组上做变长 all-to-all;主人本地查表,把列切片送回来拼成整行。梯度沿返回那次 all-to-all 回到唯一的主人,在查表的反向里除一次全体卡数;裁剪时在摊平的组上归约一次。PLE 和专家并行可以同时开:两组参数不相交,各用各的网格,上游内部示例是行切分度 8、专家并行度 4。

**DDP 不行。** 只有 FSDP2 路径会应用并行计划。数据并行模式选 DDP、模型又带额外并行计划时,构建直接报错,而不是把完整的专家装进一个计划上说已经切开的模型。

**为什么实际不吃亏**:all-to-all 搬的是 token 行,不是权重;专家权重的聚合只发生在专家内 FSDP 组那「全部卡数 ÷ 专家并行度」张卡里,每张卡聚合回来的是本地那 E ÷ 专家并行度 个专家,而不是整层 E 个。上图的 16 卡里,专家聚合只在 2 张卡之间做,每张卡聚合回来 16 个专家。

## 三、代价

**每层一次主机同步。** all-to-all 的切分要等计数拷回主机才定得下来,每个 MoE 层的前向都要等一次设备;接收的行数随路由变,每一步的形状都不同。

**负载不均直接变成卡间不均。** 不设容量,热门专家所在的卡收到的行多,算得久、激活占得多,整个专家并行组一起等它。路由分布的监控在 15 章。

**按专家复制,不按卡合并。** 一个 token 选中同一张卡上的 2 个专家,就发 2 行。all-to-all 的数据量按 token 数 × top-k × 隐藏维算,专家并行度再大也省不掉这一份。

**两个组不能同时在机内。** 专家并行在最内一维,专家并行度等于单机卡数时,all-to-all 留在机内,专家内 FSDP 组的参数聚合与梯度归约就全部跨机;专家并行度调小,专家内 FSDP 组能回到机内,all-to-all 却要跨机。

**一层两套分片组,很多事都做两遍。** 优化器、学习率调度器、梯度裁剪都分了家;新写的按参数遍历的逻辑,比如自定义的梯度统计,要自己分清参数挂在哪张网格上。

**计划的写法有隐含约束。** 框架只拿每个名字下第一个模式的父模块,当作要单独分片的模块,所以同一个名字下的所有模式必须挂在同一个父模块下;这个模块还必须落在某个逐层分片的组里面,否则不会被单独分片。

**逐专家循环不能配专家并行。** 专家计算的 eager 实现里没有 all-to-all,本卡只存 E ÷ 专家并行度 个专家,它却按全局编号去取,越界出错或取错专家;配置阶段不拦。

**PLE 的限制最多。** 不支持 HSDP、序列并行与 FSDP 卸载;二维网格必须铺满全部卡;行切分度必须整除分片度;必须每卡只读自己那一块的流式装载(04 章);分布式 PLE 不能从随机初始化开始训练。

## 四、和同类大厂框架不一样的地方

对照对象是 Megatron-LM(基准 fb6a123a09)。

两边都把专家整块分给专家并行组,分歧在专家并行组之外剩下的那些卡怎么用,以及 token 走哪条路。Megatron 的专家通信见它的解读 10 章,专家侧的编组见 02 章。

| 比较维度 | VeOmni | Megatron-LM |
|---|---|---|
| 专家侧的卡怎么编组 | 在 FSDP 分片那一侧铺一张二维子网格,专家并行固定在最内一维,另一维自动取剩下的卡 | 专家层另用一套编组发生器,按专家张量并行、专家并行、专家数据并行、流水线编排,和稠密侧强制对齐的只有流水线一维 |
| 一个专家要不要再切 | 不切计算,只切存储:第 1 维交给 FSDP2,算前聚合回完整专家 | 有专家张量并行,把一个专家的矩阵乘拆到多卡,默认跟随稠密侧的张量并行度 |
| 专家参数的数据并行副本 | 专家内 FSDP 组分片存储,参数、梯度、优化器状态都只有一份切片 | 专家数据并行组内默认整份复制,梯度在专家专用的缓冲里归约;分布式优化器在这个组内切优化器状态,它自己的 FSDP 还能给专家单独选分片策略 |
| 专家梯度的平均口径 | 把专家分片组的梯度除数改成全体卡数 | 平均归约前先乘上「专家数据并行度 ÷ 稠密数据并行度」,结果同样是按稠密数据并行度平均 |
| token 怎么走 | 只有一条路:组内交换计数,再做变长 all-to-all,不设容量 | 3 种 dispatcher 可选,默认是聚集式;灵活路径可换 DeepEP 等融合通信后端;可选按专家容量丢弃或补齐 |

差异来自同一个出发点。Megatron 自己写专家层,要把一个专家的矩阵乘拆开,改的是自己的代码;VeOmni 拿的是 HF 的 modeling,不改层就只能动存储——第 1 维那一刀只切存储、算前聚合,和 FSDP2 对其他参数做的事一样。token 只有一条路,换来的是四家专家算子只需要接一套分发。梯度口径两边殊途同归:专家的梯度都按稠密数据并行度平均,只是一个在集合通信的除数上改,一个在归约前预乘。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。装载相关的两个开关在 04 章,专家计算选哪种实现在 03 章,Muon 在专家上的零通信切法在 12 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `model.accelerator.ep_size` · 专家并行度 | YAML 或命令行 | `1` | 大于 1 开启;必须整除专家数,也必须整除分片侧卡数(`dp_shard_size` × `ulysses_size` × `cp_size`);调大:每卡专家数与专家显存降,all-to-all 组变大,专家内 FSDP 组变小 | 日志 `Initializing parallel state: … ep_size N` 与 `ep FSDP device mesh: …` |
| `model.accelerator.ep_outside` | YAML 或命令行 | `false` | `true` 启动即断言失败;专家并行只能在最内一维 | 报错 `ep is not supported when para_outside is True.` |
| `model.accelerator.extra_parallel_names` / `extra_parallel_sizes` / `extra_parallel_placement_innermost` · 额外并行的名字、度数、摆位 | YAML 或命令行 | 都是 `[]` | 三个列表等长、一一对应;名字要和模型并行计划里的名字一致(Qwen4-Exp 是 `ple`);摆位只能填 `false`;`ep` 由 `ep_size` 自动追加,不用写 | 日志 `Initializing parallel state:` 那一行里每个名字的 `…_size`,以及每个名字一行 `… FSDP device mesh: …` |

| `model.accelerator.fsdp_config.forward_prefetch` · 额外并行下的手排预取 | YAML 或命令行 | `true` | `false`:前向与反向的手排预取一起取消,退回 FSDP2 默认 | profiler 里专家那一组的 all-gather 是否紧贴在专家计算之前 |
| `model.ops_implementation.moe_implementation` · 专家计算 | YAML 或命令行 | `fused_triton` | 开专家并行时只能选融合实现;`eager` 没有 all-to-all,且配置阶段不拦 | 日志 `OpSlot dispatch bound: … moe_experts (…)` |

**观测。** 本章看 4 处。一是网格:`ep FSDP device mesh: DeviceMesh(…)` 打出二维网格的形状与维名,核对专家并行度和专家内 FSDP 度是否是你想的。二是切了什么:`ParallelPlan` 对每个命中的参数打一行 `ep sharding: slicing param … along ep_mesh with placement [Shard(dim=0)]`,随后 `Applied ep: tensors sliced along dimension (ep mesh: …)` 与 `ep Map: {…}` 列出要单独分片的专家模块;数一数专家模块数是否等于 MoE 层数。三是分组与梯度口径:每层的 `layer_fqn=…, layer_mod._fsdp_modules=[…]` 里应当同时有专家模块和层本体;每个 rank 为每个专家模块各打一行 `setting grad divide factor for ep module to N`,N 应当等于总卡数。四是 PLE:`Persistent ple 2D layout: rows=… (ple), columns=… (ple_fsdp); parameter all-gather is disabled.` 出现才说明 PLE 走的是二维常驻切。

**典型配置。** 四套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机 8 卡训 Qwen3-MoE 这类 128 专家的模型 | `ep_size: 8`,其余默认 | 每卡 16 个完整专家,专家内 FSDP 度为 1,专家权重不再聚合,all-to-all 全在机内;代价是专家这边没有 FSDP 那一刀,每卡常驻 16 个完整专家的参数、梯度与优化器状态 |
| 2 机 16 卡,就是上图那套 | `ep_size: 8` | all-to-all 留在机内,每卡专家常驻 1/16;跨机的是专家那一组的参数聚合与梯度归约,以及稠密参数本来就铺满 16 卡的 FSDP 通信,机间带宽弱时要靠手排预取提前发出 |
| 4 机 32 卡,机间带宽弱 | `dp_replicate_size: 4`、`dp_shard_size: 8`、`ep_size: 8` | 分片侧只有机内 8 卡,专家内 FSDP 度为 1,all-to-all 与所有分片通信都在机内,跨机只剩梯度 all-reduce;代价是每卡常驻 1/8 的专家和 1/8 的稠密参数 |
| Qwen4-Exp 同时开 PLE 与专家并行 | `ep_size: 4`、`extra_parallel_names: [ple]`、`extra_parallel_sizes: [8]`、`extra_parallel_placement_innermost: [false]`、`ulysses_size: 1`、`broadcast_model_weights_from_rank0: false`、`ep_sharded_stream_load: true` | 约 95 GiB 的 PLE 表按二维常驻切、前向不聚合,专家按常规两维切;换来的是不能开序列并行与 HSDP、每卡要能直读权重文件 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 切专家时报一个不带消息的 `AssertionError`,栈停在 `ParallelPlan.apply` | 专家数能不能被 `ep_size` 整除 | 换一个能整除的专家并行度 |
| 启动报 `ep_size(8) must be a factor of dp_shard_sp_size(…)` | 分片侧卡数 = `dp_shard_size` × `ulysses_size` × `cp_size` 是多少 | 调专家并行度,或调小 HSDP 的复制度让分片侧变大 |
| 启动报 `ExtraParallel needs parallel plan defined in the model!` | 模型是不是稠密模型、或这个模型族没有 `parallel_plan.py` | 稠密模型把 `ep_size` 改回 1;新接的 MoE 模型族先写并行计划 |
| 启动报 `ExtraParallel (ep) requires fsdp_mode='fsdp2'` | `fsdp_mode` 是不是 `ddp` | 换回 `fsdp2` |
| 启动报 `ExtraParallel parameter … matches multiple enabled dimensions` | 两个名字的计划模式是否匹配到同一个参数 | 收窄模式,每个参数只归一个名字 |
| 配了 `ep_size` 却看不到专家被切 | `extra_parallel_names` 里是不是手写了 `ep` | 删掉手写的 `ep`,或者在 `extra_parallel_sizes` 对应位置写上度数 |
| 每层前向都有一段空等,专家计算前有一次长 all-gather | `forward_prefetch` 是否被关掉;专家内 FSDP 组是否跨机 | 打开手排预取;或用 HSDP 把分片侧压回机内 |

## 六、常见误区

- **以为 `extra_parallel_placement_innermost: true` 是把额外并行放到最内一维。** 会这么以为,是因为参数说明文档正是这么写的。实际上字段自己的帮助文字写的是「放在外面」,而代码对 `true` 直接断言失败;额外并行(包括专家并行)永远在最内一维,这一列只能填 `false`。`ep_outside` 是同一件事的专家版,同样只能是 `false`。
- **以为专家并行度 × FSDP 度要凑成卡数或专家数,还要自己配专家内的 FSDP 度。** 会这么以为,是因为设计文档写了「专家并行度 × 专家 FSDP 度 = 总卡数」,读起来像一条要人去满足的等式。实际上没有专家内 FSDP 度这个字段,它由分片侧卡数除以专家并行度自动得出;非专家参数永远在全部分片侧上切。要你满足的只有两条整除。
- **以为专家权重是 gate、up、down 三个张量,第 1 维都是隐藏维。** 会这么以为,是因为专家并行的设计文档按拆开的 gate 与 up [E, I, H] 讲。实际上当前 Qwen3-MoE、DeepSeek-V3 等的计划里是融合的 gate+up [E, 2I, H] 和 down [E, H, I] 两个张量;融合张量的第 1 维是 2I,估每卡显存要按这个形状算。
- **以为在 `extra_parallel_names` 里写上 `ep` 能更显式地控制专家并行。** 会这么以为,是因为 PLE 的配置就是这样把名字写进列表的。实际上只有名字列表里没有 `ep` 时,`ep_size` 才会被追加进去;手写了 `ep`,`ep_size` 就被整个忽略,度数只看 `extra_parallel_sizes` 里对应那一项,漏写就是没开。
- **以为专家梯度按专家并行度平均。** 会这么以为,是因为源码里设置除数那几行上方的注释就写着「应当除以专家并行度」。实际上代码除的是总卡数,这才和稠密参数口径一致;照着注释在自己的分片代码里改成除以专家并行度,专家梯度就比稠密参数大「总卡数 ÷ 专家并行度」倍;不报错,但全局梯度范数被专家撑大,同一个裁剪系数把稠密参数也一起压小。
- **以为给词表嵌入写一份计划就能开「嵌入并行」。** 会这么以为,是因为额外并行的文档把嵌入层当成第二个例子。实际上框架只切存储、单独分片、分组裁剪,前向里本卡只有一段行,查表的通信得模型自己写;树内只有 Qwen4-Exp 的 PLE 写了这段路由查表,普通的嵌入层照原样前向会越界或查错行。
- **以为专家计算选 `eager` 能用来对拍专家并行的结果。** 会这么以为,是因为其他算子排查问题时都先退回 eager。实际上专家的 eager 实现是逐专家循环,里面没有 all-to-all,开了专家并行就会拿全局专家编号去取本卡的局部切片;要对拍,用 `ep_size: 1` 的同一套融合实现去比。
