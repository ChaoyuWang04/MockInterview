# 量化张量与 extra state

这一页回答一件事:量化张量往往要两份排布,缩放因子和绝对值最大值落在哪,以及它们怎么进断点。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

低精度已经打开,权重却仍是高精度;或者断点只存了权重数值,没带上缩放因子和绝对值最大值的历史。续训时 loss 会跳一截,看起来像步数对了、数值却从另一条轨道接上。更硬的一种是:根本没在量化初始化上下文里建权重,模块手里始终是高精度主副本,前向再现量化一遍,显存账和「权重已经是八位」对不上。

训练一步里,一层线性要做三次矩阵乘:前向、权重梯度、输入梯度。同一块数据,前向按行取,反向按列取。多数配方和多数卡上,按行用的那份和按列用的那份不是同一块内存。Hopper 上按列那份还要物理转置;Blackwell 上两份可以共用同一块布局。少做一份,反向某一跳就会现转或现量化,延迟上去;两份都捏着不放,激活显存又涨一截。

所以这一章的问题不是「八位怎么算」,而是:**量化张量怎么活着、元数据坐在哪、断点漏了会怎样。**

## 二、解法

量化张量不是普通张量换个类型。外面是一层能进自动求导的壳,里面是一份存储:按行数据、按列数据、缩放、绝对值最大值,配方不同字段不同。壳给框架看,存储给核看。量化器带着「这一次要行还是要列」,量化时按开关只造需要的那一份;前向结束可以把按行那份丢掉,只留按列给反向。

![一层线性的三次矩阵乘画成三行:前向只按行取输入和权重;权重梯度两边都按列取;输入梯度一边按行取输出梯度、一边按列取权重。旁注写 Hopper 上按列要物理转置,Blackwell 上两份可共用布局](/opensource/TransformerEngine/03a-linear-three-gemms-layouts.svg)

缩放和绝对值最大值不跟权重挤在同一个参数里。delayed 配方把前向、反向各一份缩放和一段绝对值最大值历史放进模块的量化元数据;当前缩放、当前块缩放这类配方本身没有要进断点的状态,存额外状态时交出空字节。PyTorch 的额外状态通道不保证任意对象都能搬设备,所以这份元数据先拷到 CPU 再序列化成无符号八位张量,避免加载时落到错误设备。

建权重和跑前向是两套上下文。量化初始化上下文打开时,新积木只持量化副本;需要给优化器一份高精度主权重时,可以额外在 CPU 上留初值,主权重填完必须清掉。前向上下文管的是这一跳激不激活量化,不管参数以什么类型住在模块里。两套都忘了,权重仍是高精度。

**为什么实际不吃亏。** 两份排布看起来浪费,换来的是三次矩阵乘不必在反向现场转置整块激活。元数据走框架自带的额外状态通道,普通状态字典就能带走 delayed 配方的历史,不必另写一套存盘。无状态配方交出空张量,加载时直接返回,不会误把 pickle 当状态。

## 三、代价

**两份排布占显存。** 训练时输入、权重、输出梯度各自都要按行和按列各用一次。前向只造按行、反向再融合造按列,能省一份激活;两边一起造,核更好融,激活更肥。

**断点漏元数据会跳点。** delayed 配方续训必须把缩放和绝对值最大值历史装回去。空额外状态或加载被策略拒绝,历史会从默认的 1 和 0 重新长,看起来像换了一套 scale。

**pickle 默认不加载。** delayed 配方的额外状态仍是 Python pickle。默认识别到这份载荷会拒绝,除非显式打开不安全加载,且断点来源可信。无状态配方和空字节走忽略,不触发这条。

**建权重忘包初始化上下文。** 模块参数仍是高精度,优化器里再留一份主权重就是三份账。CPU 上的高精度初值忘了清,主机内存一直占着。

**额外状态不跟普通参数一起做设备重映射。** 实现才把张量先拷到 CPU。自己手写存盘、把 GPU 上的元数据塞进别的键,加载时设备可能对不上。

## 四、和同类算子库不一样的地方

本页只比量化张量的两份布局、缩放和绝对值最大值怎么进断点。Apex 的断言核在主干 8a6508aa:没有本库这种量化张量子类,也没有八位额外状态。FlashAttention 没有单独镜像,核吃你塞进去的类型,没有带历史的量化对象。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 量化张量是不是一等对象 | 有按行/按列两套存储的量化张量,配方对应不同子类 | 公开融合核走框架张量类型,没有本库这种量化张量子类 | 核吃你塞进去的类型,没有量化张量对象 |
| 缩放和绝对值最大值放哪 | 模块量化元数据;delayed 配方进额外状态,无状态配方存空 | 没有为本库八位准备的额外状态通道 | 没有 scale 历史对象 |
| 断点漏了会怎样 | delayed 续训数值从默认历史重长;无状态配方本来就没有历史 | 不适用:没有这份元数据要带 | 不适用 |
| 权重以量化形式住在模块里 | 量化初始化上下文里建层,模块只持量化副本 | 融合层参数仍是框架普通参数 | 无权重对象,只有注意力核 |

Megatron 是宿主,不进对等列。

## 五、调参与观测

这一页的参数管量化张量怎么建、缩放和绝对值最大值怎么进断点;前向开关见 01 章,配方切分见 02 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `quantized_model_init` | 建模型 | 不包则权重仍是高精度 | 模块只持量化副本 | 参数是不是量化张量 |
| `enabled` | 量化初始化上下文 | `True` | 关掉则仍建高精度参数 | 模块参数类型 |
| `recipe` | 量化初始化上下文 | 不传则默认配方 | 决定量化张量子类和元数据要不要进断点 | 02 章;无状态配方额外状态为空 |
| `preserve_high_precision_init_val` | 量化初始化上下文 | `False` | CPU 上留高精度初值给主权重;实验性 | 取完必须清掉,否则主机内存不放 |
| `rowwise_usage` / `columnwise_usage` | 量化器 | 通常两份都开 | 关掉一份就不造那份排布 | 反向是否现转或现量化 |
| `update_usage` | 量化张量 | 不调则两份都留着 | 前向后丢掉按行、只留按列给反向 | 激活显存 |
| `get_extra_state` / `set_extra_state` | 模块断点 | 无状态或未开量化交空张量 | delayed 把缩放和 amax 历史打进 CPU 上的字节张量 | 断点里模块 `_extra_state` 是否非空 |
| `NVTE_ALLOW_UNSAFE_PICKLE_EXTRA_STATE` | 环境变量 | `0` | 设成 `1` 才反序列化 delayed 的 pickle | 加载时报拒绝还是接上历史 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 优化器已有高精度主权重 | `quantized_model_init(enabled=True, preserve_high_precision_init_val=True)` 建层,填完主权重立刻 `clear_high_precision_init_val` | 模块侧少一份高精度;忘清 CPU 初值会多占主机内存 |
| 推理或参数几乎不动的微调 | `quantized_model_init(enabled=True)` 建层,不留 CPU 初值 | 显存最瘦;不能从量化副本无损还原主权重 |
| delayed 配方续训 | 用框架 `state_dict` 带走模块 `_extra_state`;加载前设 `NVTE_ALLOW_UNSAFE_PICKLE_EXTRA_STATE=1`,且断点可信 | 历史接得上;换来的是 pickle 风险,来源不可信就不要开 |
| 当前缩放或块缩放配方 | 不必为额外状态开不安全加载;空字节直接忽略 | 少一份断点状态;scale 每步现算,不靠历史 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:参数是不是量化张量,不要只看前向套了上下文;delayed 续训看模块额外状态是否非空、加载有没有被拒绝;激活显存看前向后有没有丢掉按行那份。

| 症状 | 先查 | 然后 |
|---|---|---|
| 续训 loss 跳一截 | 断点有没有模块额外状态;加载是否被 pickle 策略拒绝 | delayed 打开不安全加载且来源可信;无状态配方本来就没有历史 |
| 权重仍是高精度 | 建层是否在量化初始化上下文里 | 包上;与前向上下文不是同一套 |
| 激活显存比预期肥 | 量化器是否两份排布都留着 | 前向后丢掉按行,或反向再造按列 |
| 反向某一跳突然变慢 | Hopper 上按列那份是否缺失 | 让量化器在需要前列好,或接受现转置 |
| CPU 内存建完模型后不降 | 高精度初值有没有清 | 主权重填完立刻清 |

## 六、常见误区

**「断点里有权重,续训数值应该接得上」——delayed 的历史不在权重里。** 缩放和绝对值最大值走额外状态。只存普通参数,历史从 1 和 0 重长,跳点像换了一套 scale。人们会这么以为,是因为别的混合精度把状态写进优化器,这里写在模块额外状态里。

**把量化初始化上下文和前向上下文当成同一个。** 前者决定参数以什么类型住在模块里,后者决定这一跳激不激活量化。只套前向,权重仍是高精度。

**FAQ 里额外状态键换过位置,就按旧键去找。** 当前多头注意力把注意力侧元数据存在核心注意力模块的额外状态上。按更早版本的嵌套键去取会取空,元数据被当成默认值。本页只写当前行为,不追哪一代搬过键。

**无状态配方也去开不安全 pickle。** 当前缩放、块缩放、MXFP8、NVFP4 存的是空字节,加载直接返回。开不安全开关帮不上,只放大风险。

**Hopper 和 Blackwell 共用「两份排布」的直觉。** Blackwell 上按行按列可以同一块布局;Hopper 上按列要物理转置。少一份在 Hopper 上是现转置的延迟,不是少算一次。
