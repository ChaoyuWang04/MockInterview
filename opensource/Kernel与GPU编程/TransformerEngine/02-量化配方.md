# 量化配方

这一页回答一件事:低精度打开之后,scale 从哪来、切多细,以及为什么配方选错会让 Tensor Core 空转或 loss 发散。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

量化上下文只负责把开关打开。真正决定「这一跳怎么量化」的是配方:scale 用上一步的历史还是本步当场的峰值,以及多少个数共用一个 scale。配方和硬件、激活分布对不上,最常见的不是报错,是 **Tensor Core 空转,或者 scale 跟不上、loss 发散**。

两种骨折很直白。第一种:卡已经能跑更细的切块,配方却还按整张张量一个 scale 走,硬件核吃不到,看起来像没换精度。第二种:激活分布这一步跳得很厉害,配方却拿上一步窗口里的峰值来缩放,本步该夹的没夹、不该夹的夹死,loss 从打开低精度那一步开始飘。

还有第三种不给面子:编译区域里撞上延迟缩放,直接报错;编译区域里现场构造配方对象,同样立刻失败。默认配方按设备挑,Hopper 上常常落到延迟缩放,一开编译就撞墙。

所以这一章的问题不是「八位长什么样」,而是:**scale 从哪来、切多细、默认会落到哪条、哪条跟编译打架。**

## 二、解法

配方是量化上下文上的一份参数,积木进去之后按这份参数建量化器。轴只有两根。

**从哪来。** 延迟缩放用上一步窗口里的绝对值最大值算 scale,本步量化时不再先扫一遍张量,只把本步峰值记进窗口,留给下一步。当前缩放和后面几条切块配方都是本步当场扫峰值再量化,跟得上这一跳的分布,代价是多读一遍。

**切多细。** 延迟缩放和当前缩放都是整张张量一个 FP32 scale,切得最粗。FP8 切块默认 128 个值共用一个 FP32 scale(默认为 2 的幂)。MXFP8 是 32 个值一块,scale 是只有指数的八位,只能是 2 的幂;Blackwell 上有硬件微缩放。NVFP4 再细一档:16 个值一块用 E4M3 的块 scale,外面再乘一个整张的 FP32 全局 scale;权重默认还可以按 16×16 的二维块切。

![五列配方从左到右变细:延迟缩放用上一步窗口、整张一个 scale;当前缩放用本步当场、仍是整张一个;FP8 切块当场、约 128 个值一块;MXFP8 当场、32 个值一块;NVFP4 当场两级、16 个值一块再乘全局 scale。黄表示历史,紫表示当场,绿格子数表示一块里共用 scale 的元素变少](/opensource/TransformerEngine/02a-scale-source-and-grain.svg)

**默认怎么挑。** 不显式传配方时:设备宣称 MXFP8 可用,就用 MXFP8;计算能力已经到 12.0、MXFP8 还盖不全所有矩阵布局,就退到当前缩放;其余回落到延迟缩放。计算能力 10.0 到 12.0 之前,MXFP8 检查会通过,所以 Blackwell 上默认是 MXFP8,不是延迟缩放。

**为什么实际不吃亏。** 换配方不必拆模型,量化上下文换一份参数即可。细切不是永远更快:切得越细,scale 张量越大、核越挑布局;粗切少读一遍,但激活一跳就跟不上。默认按「这张卡现在哪条核盖得全」来挑,不是按「最新的名字」。

自定义配方走工厂函数,实验性,日常训练不走这条。

## 三、代价

**延迟缩放跟不上跳变。** 窗口默认很长,算法默认取窗口里的最大峰值。分布平稳时少读一遍张量是赚的;分布这一步炸了,用的还是旧 scale,夹死或溢出都发生在沉默里。退出上下文时才把各模块记下的峰值拼起来归约,所以同一模块进两次会盖掉第一次——这条限制属于延迟缩放,不是所有配方。

**当场算要多读。** 当前缩放先扫峰值再量化,scale 准,带宽和 launch 多一截。切块还要存一块一块的 scale:128、32、16,格子越密,附属张量越大。MXFP8 的量化张量和它的转置数值上不等价,前向反向都要时必须从高精度各量化一次,不能转置凑合。

**硬件门槛是硬断言。** 八位整张配方要计算能力 8.9;切块还要 9.0 且 CUDA 至少 12.9;MXFP8 与 NVFP4 要 10.0。12.0 上 MXFP8 检查会失败(布局还没盖全),默认不会选它。FP8 切块不做注意力量化。纯 E5M2 训练各条配方都拒绝。

**编译和延迟缩放互斥。** 编译中碰到延迟缩放直接失败;编译区域里也不能现场 new 一份配方,必须从外面传进去。Hopper 上默认常常就是延迟缩放,开编译却不显式换配方,是这条路上最常见的撞击。

**细到四位不是免费。** NVFP4 默认还给梯度随机舍入、给输入和梯度做随机 Hadamard,权重走二维块。关掉这些会更容易训不稳;打开则多算。它不是默认配方,要自己传。

## 四、和同类算子库不一样的地方

本页只比 scale 从哪来、切多细。Apex 核在主干 8a6508aa;FlashAttention 只写本库快照里怎么对待它。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 有没有配方对象 | 有。上下文上的一份参数,决定 scale 从哪来、切多细,积木按它建量化器 | 没有八位配方。今天公开入口是融合归一化和融合优化器,融合稠密层搭在框架混合精度上,进核时关掉那层上下文 | 没有配方。精度就是你塞进核的类型 |
| 默认怎么选 | 能跑 MXFP8 就 MXFP8;计算能力 12.0 且 MXFP8 盖不全布局就当前缩放;否则延迟缩放 | 不适用:没有配方可选 | 不适用 |
| 和编译的关系 | 延迟缩放在编译区域里直接报错;配方对象也不能在编译区域里现场构造 | 不提供这条门禁 | 核本身不管你外面有没有编译 |
| 切到多细 | 从整张一个 scale,到 128、32、16,再到四位两级 | 不做这块 | 不做这块 |

Megatron 是宿主,按层代劳套上下文时把配方传进去,不进对等列。FlashInfer 不进本列。

## 五、调参与观测

这一页的参数是量化上下文上的配方,换配方不必拆模型,但要重新走进那一层上下文;编译区域必须从外面把配方对象传进去。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `recipe` | 量化上下文 | 不传则 `get_default_fp8_recipe`:MXFP8 可用用 MXFP8;计算能力 ≥12.0 用当前缩放;否则延迟缩放 | 决定 scale 来源与块大小;编译区必须显式传入且不能是延迟缩放 | 进入上下文时的设备检查;编译则看是否立刻报 DelayedScaling / 不可追踪 |
| `DelayedScaling` | 自己构造再传给上下文 | `margin=0`,`HYBRID`,窗口 1024,算法 `max`,`reduce_amax=True` | 用历史窗口;退出时归约 amax;与编译互斥 | 多卡数值是否对齐;loss 是否从打开低精度起飘 |
| `amax_history_len` | 延迟缩放配方 | 1024 | 窗口越短越跟得上跳变,越容易抖 | 窗口张量的第一维 |
| `amax_compute_algo` | 延迟缩放配方 | `max` | 改成 `most_recent` 只用最新一条,不再取窗口最大 | 跳变步上的溢出或欠缩放 |
| `reduce_amax` | 延迟缩放配方 | `True` | 关掉则每卡自己的 scale,断点必须每卡都存 | 多卡 loss 对不齐时先看这个 |
| `Float8CurrentScaling` | 自己构造 | `HYBRID`;前向 GEMM 默认不用 split accumulator | 本步当场、整张一个 scale;编译可用 | 相对延迟缩放多一次读 |
| `Float8BlockScaling` | 自己构造 | 格式 E4M3;输入/梯度 1D、权重 2D;split accumulator 强制开 | 默认约 128 一块;不可 2D×2D;不做注意力量化;JAX 不支持 | 进入时的切块支持检查(9.0 且 CUDA≥12.9) |
| `MXFP8BlockScaling` | 自己构造;也是 Blackwell 默认 | 格式 E4M3;32 一块;E8M0 scale | 更细;12.0 上检查失败,不会被选成默认 | `check_mxfp8_support` 的返回 |
| `NVFP4BlockScaling` | 自己构造,不会被默认选中 | E2M1;16 一块加全局 FP32;权重默认可 2D;梯度随机舍入;输入与梯度默认 RHT | 四位训练;关掉 RHT / 随机舍入 / 2D 更容易不稳 | 计算能力 10.0;进入时配方支持检查不覆盖这一条,要自己确认设备 |
| `fp8_format` / `fp4_format` | 各配方 | 延迟/当前默认 HYBRID;切块与 MXFP8 默认 E4M3;NVFP4 固定 E2M1+E4M3 | 纯 E5M2 一律拒绝 | 构造配方时的断言 |
| `fp8_dpa` / `fp8_mha` | 延迟、当前、MXFP8 | `False` | 切块配方强制关;延迟/当前上是 Beta | 注意力是否真的走进八位后端 |
| `CustomRecipe` | 自己提供工厂 | 实验性;`quantization_alignment=128` | 按角色返回量化器;可内部再挂延迟缩放的共享缓冲 | 工厂是否对每个角色都返回了对象 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| Hopper 把官方延迟缩放跑通 | 现成一层,前向套量化上下文,显式传入延迟缩放,窗口保持 1024,反向在外面 | 少读一遍张量;换来的是跟不上跳变,且不能进编译 |
| Blackwell 用默认微缩放 | 现成一层,上下文不传配方(或显式 MXFP8),反向在外面 | 32 一块、硬件微缩放;12.0 上这条检查会失败,不要硬套 |
| 要 `torch.compile` 且卡还在 Hopper | 上下文显式传入当前缩放,配方对象在编译区域外构造 | 能进编译;多读一遍,仍是整张一个 scale |
| Blackwell 试四位预训练配方 | 上下文显式传入 NVFP4,保持默认 RHT 与随机舍入,不要关 2D 权重块 | 更细的块和更窄的格式;换来的是额外变换,且不是默认路径 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:默认到底落到哪条,看设备计算能力,不要看「我没传配方所以一定是延迟缩放」;编译失败先看是不是延迟缩放、是不是在编译区域里现场构造;loss 飘先问这条配方的 scale 是历史还是当场,历史才查窗口和退出时归约。

| 症状 | 先查 | 然后 |
|---|---|---|
| 换成积木几乎没加速,卡却是 Blackwell | 默认是不是 MXFP8,形状是否满足该配方对齐 | 显式传 MXFP8;12.0 就改当前缩放,不要幻想默认还是延迟缩放 |
| 一开 `torch.compile` 就失败 | 是不是默认落到延迟缩放;配方是否在编译区域内构造 | 从外面传入当前缩放或切块,禁止延迟缩放 |
| loss 从打开低精度起发散 | 是不是延迟缩放;窗口是不是 1024 取 max;同一模块是否进了两次 | 换当前缩放或切块;两次前向就拆成两次上下文 |
| 进入上下文直接断言 | 计算能力、CUDA、配方种类 | 8.9 以下没有 FP8;切块要 9.0 加 12.9;MXFP8 / NVFP4 要 10.0 |
| 切块注意力没走进八位 | 是不是 FP8 切块配方 | 换延迟/当前/MXFP8,切块强制关注意力量化 |
| 多卡数值对不齐 | 延迟缩放的 `reduce_amax` 和归约组 | 打开归约;关归约则每卡断点都要存 |

## 六、常见误区

**「没传配方就是延迟缩放」。** 默认按设备挑。Blackwell 上 MXFP8 检查通过就是 MXFP8;计算能力 12.0 会退到当前缩放。只有更老的八位卡才回落延迟缩放。

**「编译失败是积木的问题」。** 编译区域禁止延迟缩放,也禁止现场构造配方。Hopper 默认偏偏是延迟缩放,开编译却不显式换,报错是门禁,不是核坏了。

**「切得越细一定越稳、越快」。** 细切跟得上分布,但 scale 附属更大、布局更挑,12.0 上 MXFP8 甚至还盖不全 GEMM。粗切少读一遍,激活一跳就翻车。两根轴要一起看,不是单看块大小。

**「NVFP4 会像 MXFP8 一样被默认选中」。** 默认函数只在 MXFP8、当前缩放、延迟缩放三者里跳,不会返回 NVFP4。要四位必须自己传。

**「配方支持检查会拦住一切不该进的配方」。** 进入时的检查覆盖延迟、当前、切块、MXFP8;NVFP4 和自定义不走同一条。卡不够新时,NVFP4 可能要更晚才爆。

**把延迟缩放的「同一模块不能进两次」套到所有配方上。** 那条限制来自退出时归约绝对值最大值。当前缩放和切块这条缓冲区是空的,退出时什么也不做。
