# Norm 与融合层

这一页回答一件事:归一化和线性拆开之后,多卡时 launch 与中间激活怎样把吞吐打掉,以及融合层什么时候会自己拆开。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

库里的归一化和线性可以单独用。单独用时每层各 launch 一次,中间那份归一化后的激活必须落地,再喂给线性。单卡上这两次核都短,账上看不大出来;多卡时每次 launch 都要排队,中间激活还要进出显存,吞吐打掉的是启动和带宽,不是归一化公式算错。

官方上手写得很直:融合模块靠把多步合成一次,单卡加速有限,多卡时更值钱。只换散装积木、不走上融合层,就是把这条收益留在桌上。

还有一种看起来已经融合、实际又拆开的写法:残差要从归一化之后接出去,于是要求模块把归一化输出再吐一份。一吐,量化就不能写进同一份缓冲,中间激活又回来了。

所以这一章的问题是:**归一化和线性/MLP 有没有融在一次 launch 里,中间激活还要不要落地。**

## 二、解法

散装归一化(层归一化或 RMSNorm)自己是一条核,后面再接线性就是两次 launch。融合层把这两步收进同一个模块:先做归一化,量化开着且不吐中间结果时,归一化直接写进给线性用的量化缓冲,紧接着做矩阵乘。MLP 那条同理:归一化之后接两段线性,中间夹激活函数,默认偏置和 GELU 还可以再融一截。

![上段红框是拆开的归一化核、落地的中间激活、再一次线性核,两次 launch;下段绿框是融合归一化加线性一次 launch,默认不吐中间结果;右侧黄框写官方上手:单卡收益有限,多卡 launch 更值钱](/opensource/TransformerEngine/05a-fused-norm-linear.svg)

归一化公式仍是那一套:层归一化减均值再除方差,RMSNorm 只除均方根;可学的缩放默认从 1 起,也可以改成从 0 起、公式里写成 1 加缩放。融合层用同一套归一化核,只是调用点改在线性前面,不再单独占一个模块。

**为什么实际不吃亏。** 训练循环不用改残差怎么加,只是把「归一化再线性」换成一块积木。单卡上核本来就短,融不融差不大;多卡时少一次 launch、少一份中间激活,才是这笔账。量化开关仍在外面的上下文里读,融合成一层不会自动打开低精度。

## 三、代价

**吐出归一化输出,融合会拆。** 残差要归一化后的激活、或序列并行下要把这份激活 gather 再接出去,模块就得把中间结果再交出来。量化核这时不走「写进同一份缓冲」,中间激活重新落地。

**SM 要留给通信。** 归一化核默认会吃满流处理器。多卡要把通信叠在归一化上,得从环境里扣几块 SM;扣多了归一化变慢,扣少了重叠不上。通信怎么和矩阵乘重叠见 08 章,本章只记住归一化自己也有这条余量。

**归一化后端可以换。** 前向、反向可以改走 cuDNN 那条,而不是库自带的核。换了布局和版本门槛跟着变,不是免费加速开关。

**MLP 里激活函数默认 GELU。** 偏置与 GELU 的融合默认开;换成别的激活,这条融合就不走。选择性重算可以丢掉后一段线性的激活、反向再算一遍,省显存、加一次前向。

**融合层上的切分模式、用户缓冲,不是本章的主场。** 打开相关开关会去碰 08 章那套通信重叠;本章只保证归一化和线性已经合成一次 launch。

## 四、和同类算子库不一样的地方

本页只比归一化和线性/MLP 融不融在一次 launch。Apex 核在主干 8a6508aa,公开入口有融合层归一化和融合 RMSNorm。FlashAttention 不是归一化库,表里那一列不是漏写。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 归一化本身 | 散装层归一化 / RMSNorm,各是一条核 | 公开融合层归一化、融合 RMSNorm,也是把公式收进一条核 | 不是归一化库,没有这条入口 |
| 和线性 / MLP 融不融 | 另有融合归一化加线性、融合归一化加 MLP,一次 launch,中间激活默认不落地 | 公开入口停在融合归一化,没有「归一化再接线性」这一块积木 | 不适用 |
| 吐出中间激活 | 打开吐出,量化核拆开,中间激活重新落地 | 融合归一化本来就把结果交出来给下一层,没有「不吐则写进线性缓冲」这条 | 不适用 |
| 多卡这笔账 | 官方上手写明单卡加速有限,多卡时融合层更值钱 | 融合归一化减的是归一化自己的 launch,不负责后面的线性 | 不适用 |

Megatron 是宿主,不进对等列。

## 五、调参与观测

这一页的参数是归一化积木和融合层怎么建、中间激活要不要吐出来,改了要重建模块;量化开关仍见 01 章,矩阵乘精度见 04 章,张量并行与用户缓冲见 08 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `normalization` | 融合层建层 | `LayerNorm` | 改成 `RMSNorm` 则没有归一化偏置 | 模块有没有 `layer_norm_bias` |
| `eps` | 散装归一化 / 融合层 | `1e-5` | 分母稳定项;过小容易在低精度里抖 | loss 是否从换积木起抖 |
| `zero_centered_gamma` | 散装归一化 / 融合层 | `False` | `True` 时缩放从 0 起,公式变成 1 加缩放 | 权重初值是不是 0 |
| `return_layernorm_output` | 融合层建层 | `False` | `True` 则前向多交一份归一化激活,量化核拆开 | 返回值是不是一对张量 |
| `return_layernorm_output_gathered` | 融合层建层 | `False` | 只在上一开关开着时生效;序列并行下把归一化结果 gather 再交出去 | 残差侧是否还要自己 gather |
| `activation` | 融合 MLP | `gelu` | 换成别的激活,偏置加 GELU 那条融合不走 | 前向是否还走偏置融合 |
| `NVTE_BIAS_GELU_NVFUSION` | 环境变量 | `1` | 设 `0` 则偏置和 GELU 拆开;仅 GELU 时有效 | 核时间线是一次还是两次 |
| `NVTE_FWD_LAYERNORM_SM_MARGIN` | 环境变量 | `0` | 前向归一化扣下若干 SM 给通信 | 多卡重叠时归一化是否打满卡 |
| `NVTE_BWD_LAYERNORM_SM_MARGIN` | 环境变量 | `0` | 反向归一化同样扣 SM | 反向通信是否叠得上 |
| `NVTE_NORM_FWD_USE_CUDNN` | 环境变量 | 未设视为关 | 前向改走 cuDNN 归一化 | 核名是否变成 cuDNN |
| `checkpoint` | 融合 MLP | `False` | `True` 则丢掉后一段线性的激活,反向再算,省显存 | 激活显存与前向耗时 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡把融合层接上 | 融合归一化加线性替换拆开的归一化与线性,前向仍套量化上下文,反向在外 | 少一次 launch;单卡上看不大出来,只确认积木换对 |
| 多卡吞吐优先 | 注意力前投影用融合归一化加线性,前馈用融合归一化加 MLP,中间激活默认不吐 | 少一份落地激活、少一轮排队;残差只能接归一化之前 |
| 残差要归一化后的激活 | 融合层打开返回归一化输出,接受量化核拆开 | 残差形状对了;中间激活和第二次量化又回来 |
| 归一化要和通信重叠 | 前向归一化 SM 余量先留 8,反向同样留 8,再看时间线 | 重叠换来归一化变慢;余量过大核会饿 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:融没融看前向是不是只进融合层一次,不要看「归一化和线性都换成库里的」;中间激活有没有落地,看有没有打开吐出开关;多卡吞吐看 launch 次数和 SM 余量,不要只看单卡微基准。

| 症状 | 先查 | 然后 |
|---|---|---|
| 换成库里的归一化和线性,多卡仍慢 | 是不是两块积木拆开接,中间激活是否落地 | 换成融合归一化加线性 / 融合 MLP |
| 融合层换上,显存几乎没少 | 有没有打开返回归一化输出 | 残差能接前面就关掉吐出 |
| 低精度开着,融合层输出却像高精度中间结果 | 吐出开关、调试、自定义量化器是否把量化核拆开 | 关掉吐出;量化开关见 01 章 |
| 多卡重叠时归一化打满卡、通信排后面 | 前向 / 反向 SM 余量是不是 0 | 先留几块 SM,再看时间线 |
| MLP 里偏置加激活仍是两次核 | 激活是不是 GELU,环境变量有没有把融合关掉 | 回到 GELU 且保持融合开着,或接受拆开 |

## 六、常见误区

**「归一化和线性都换成库里的了,就等于融合。」** 散装两条核仍是两次 launch,中间激活照样落地。融合是另一块积木,不是两个类名并排。

**「官方上手说单卡加速有限,所以融合层可以不换。」** 那句话的后半句是多卡更值钱。单卡微基准看不出的,正是多卡排队和中间激活。

**「残差要归一化后的张量,融合层反正都会给。」** 默认不给。打开吐出,量化核拆开,融合的那一半收益吐回去了。

**「扣 SM 余量越大,重叠越好。」** 余量是从归一化核里挖出来的。挖空了归一化自己变慢,通信也填不满。

**「融合层换上就不用套量化上下文。」** 和 01 章同一件事:积木在,开关在外面。融合成一层不会替你打开低精度。
