# Debug:对着哪一层看 amax

这一页回答一件事:量化不收敛时,怎么对着某一层读绝对值最大值,而不是整网重训猜。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

八位训着训着 loss 炸了。整网看起来都在量化,日志里没有按层的绝对值最大值,只能猜:是某一层溢出、某一跳没量化、还是配方本身切错。猜完只能整网关掉八位再训一遍。吞吐掉回去,问题层还是看不见。

所以这一章的问题是:**不收敛时能不能对着一层读绝对值最大值,而不是整网重训。**

## 二、解法

先写一份配置:哪几层、哪几次矩阵乘、记哪些统计。再在训练脚本里初始化检查器,把本库自带的功能目录交进去。建层时给名字,方便对上配置;不给名字也能从类名推断。每一次前向加反向结束,调一步冲刷,统计才会写进日志。

检查器按配置把功能插进积木。记张量统计时,可以直接要当前绝对值最大值;记量化统计时,还能看下溢百分比、缩放倒数的最小最大。怀疑某一层,就把那一层的量化关掉、改走较高精度,旁边的层继续八位。不必整网重训。

![左边灰框:没有层内统计时对着整网猜,只能整网重训;右边紫框:检查器按配置插进各层,日志里能读每一层的绝对值最大值;绿框是关掉某一层量化、旁边仍走八位](/opensource/TransformerEngine/12a-per-layer-amax.svg)

**为什么实际不吃亏。** 没开功能的层按正常速度跑。统计很贵,拉大记录间隔就能把开销压下来。配置按层名或层类型选,一次只盯嫌疑层。文档写明目前只支持 PyTorch。

## 三、代价

**必须先初始化再建模。** 检查器没起来就先建了积木,再建模会直接报错。忘了每步冲刷,统计攒在缓冲里不落盘。

**统计贵。** 记量化统计时,若配方和训练当前配方不一致,要多一次转换。间隔写成 1、全程全层全开,训练会被拖成排障作业。

**一层只能落进一个配置段。** 名字对不上就插不进去。现成一层是若干线性子层拼起来的,配置打到融合名时,真正受影响的是里面那条线性。

**多卡要对齐归约组。** 不指定就把统计在全体进程上归约,日志看起来人人一份同样的数。权重默认在张量并行组内归约;激活和梯度要自己指定组。按张量缩放和假量化在各卡独立算缩放,卡数一变结果会变,和 delayed 配方那种同步缩放不是一回事。

**调试和激活卸数互斥。** 卸数那一章已经写过:调试一开,卸数直接失败。本页不重复那条路径。

## 四、和同类算子库不一样的地方

本页只比量化不收敛时对着哪一层看绝对值最大值。Apex 核在主干 8a6508aa。FlashAttention 是注意力核。两者都不是按层读八位绝对值最大值的调试工具,表里那两列不是漏写接口。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 能不能按层读绝对值最大值 | 有。配置点名层,日志里出当前绝对值最大值和量化下溢 | 不是按层八位调试工具,没有这套检查器 | 不是按层八位调试工具,核不管层统计 |
| 能不能只关一层量化 | 有。关掉那一层的量化矩阵乘,旁边继续八位 | 不适用 | 不适用 |
| 多卡统计怎么对齐 | 权重默认在张量并行组内归约,激活梯度要指定组 | 不适用 | 不适用 |
| 和卸数能不能一起开 | 不能。调试模式和卸数互斥 | 不适用 | 不适用 |

Megatron 是宿主,不进对等列。

## 五、调参与观测

这一页的参数是精度调试怎么挂到层上:配置文件、检查器初始化和一步结束时冲刷统计。配方内部的缩放见 02 章;卸数不要和本页一起开,见 09 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `config_file` | 检查器初始化 | 空字符串则不读文件 | 指定哪几层开哪些功能 | 主日志里有没有载入对应段 |
| `feature_dirs` | 检查器初始化 | 必填才能用本库功能 | 必须指到本库 debug 功能目录 | 功能名对不上则插不进层 |
| `log_dir` | 检查器初始化 | 当前目录 | 主日志和统计日志写到这里 | `nvdlfw_inspect_statistics_logs` 下按 rank 分文件 |
| `default_logging_enabled` | 检查器初始化 | `False` | 打开才往文件写默认日志 | 目录里有没有主日志 |
| `tb_writer` | 检查器初始化 | `None` | 传了才往 TensorBoard 写;多卡只需流水线组里一人传 | 面板里有没有层统计曲线 |
| `debug_api.step` | 每步结束 | 不调则不冲刷 | 把缓冲里的统计落到日志 | 统计文件有没有新 iteration |
| `LogTensorStats` 的 `stats` | 配置文件 | 无,必填才记 | `cur_amax` 就是当前绝对值最大值;`max`/`min`/`mean` 等同开 | 统计日志里层名加张量名加指标 |
| `LogFp8TensorStats` | 配置文件 | 不开 | 记下溢百分比、缩放倒数的最小最大;跨配方要多一次转换 | 统计日志;间隔建议大于 1 |
| `DisableQuantizationLayer` | 配置文件 | 不开 | 该层全部量化矩阵乘改走较高精度 | 主日志里该层写成 High precision |
| `freq` / `start_step` / `end_step` | 配置文件 | 间隔默认 1,起止默认空 | 拉大间隔降开销;只在嫌疑步打开 | 统计是不是每隔若干 iteration 才出现 |
| `set_tensor_reduction_group` | 运行时 | 不设则全体进程归约 | 激活和梯度在指定组上归约 | 各 rank 统计文件是否同组同数 |
| `set_weight_tensor_tp_group_reduce` | 运行时 | `True` | `False` 则权重按分片各自记,不再在张量并行组内归约 | 权重统计是否仍人人一份 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡,怀疑某一层绝对值最大值炸 | 配置只给含 layernorm_linear 的层开张量统计,指标写成当前绝对值最大值,间隔 1,步 2 到 5;初始化时带上功能目录和日志目录,每步冲刷 | 只看那一层的峰值;别的层不开功能,速度接近平时 |
| 关一层量化对照 | 配置按层类型点名 fc1,打开关掉整层量化 | 那一层走较高精度,旁边仍八位;对照 loss 是不是这一层的锅 |
| 多卡要对齐激活统计 | 初始化之后指定张量归约组,权重保持默认在张量并行组内归约 | 同组日志数字一致;不指定会在全体进程上揉成一份 |
| 统计太贵 | 间隔改成 5 或 10,起止只包嫌疑窗口;跨配方的量化统计更要拉大间隔 | 少几次转换换吞吐;跳过的步几乎不付额外成本 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:功能有没有插进去,看主日志里该层矩阵乘写成量化还是较高精度,不要看「检查器已经初始化」;绝对值最大值看统计日志里层名加激活再加当前绝对值最大值,没有新 iteration 先查有没有冲刷;多卡先看归约组,同组数字应对齐。

| 症状 | 先查 | 然后 |
|---|---|---|
| 统计文件是空的 | 初始化是不是在建模之前、每步有没有冲刷、配置段 enabled 开没开 | 先初始化再建层;每步冲刷;打开对应段 |
| loss 炸了仍看不出哪一层 | 配置是不是打到了真正含线性的子层名 | 对照主日志里的层名改配置,不要只写现成一层的外层名 |
| 一开调试训练极慢 | 间隔是不是 1、是不是全层全开、有没有跨配方量化统计 | 拉大间隔,只盯嫌疑层 |
| 各卡统计对不上 | 归约组、权重是否仍在张量并行组内归约 | 指定激活梯度的组;要看分片就把权重归约关掉 |
| 调试和卸数一起开直接失败 | 是不是同时开了卸数 | 先关卸数,见 09 章 |

## 六、常见误区

**「整网重训成较高精度,才能证明是量化的锅。」** 可以只关一层量化。旁边继续八位,对照更快。

**「初始化了就会自动记。」** 统计要配置点名,还要每步冲刷。只初始化,缓冲不落盘。

**「先建模型再开检查器。」** 第一块积木建起来时检查器必须已经在。反过来会报错。

**「统计日志里的数就是这一卡自己的张量。」** 默认会归约。要对着分片看,先改归约组或关掉权重组内归约。

**「和卸数一起开,两边都省事。」** 调试模式打开,卸数直接失败。两件事不能叠。
