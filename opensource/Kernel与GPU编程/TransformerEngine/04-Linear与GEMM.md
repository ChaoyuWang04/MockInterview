# Linear 与 GEMM

这一页回答一件事:线性层什么时候真的走进对应精度的 Tensor Core,以及 MoE 专家侧为什么必须合成一次分组矩阵乘。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

换成库里的线性层之后,训练步看起来在跑,耗时却几乎不动。最常见的原因不是核写错,而是**矩阵乘没走进你以为的那一档精度**。开关关着,量化器全是空的,走的是较高精度的核;形状对不齐八位约束,同样进不去。看起来像「已经换了积木」,账上仍是十六位矩阵乘。

MoE 还有第二条骨折。每个专家各调一次普通线性层,就是 N 次小矩阵乘:每次 launch 都贵,M 又短,Tensor Core 吃不饱。专家数一多,时间全耗在排队启动上,不是在算。

所以这一章的问题是:**这一跳矩阵乘有没有走到对应精度的 Tensor Core;专家侧有没有合成一次分组乘,而不是 N 次小乘。**

## 二、解法

线性层前向先准备:读全局量化开关、按配方建元数据。开关开着才去拿输入、权重、输出、梯度四侧量化器;关着六个位置全是空,后面的矩阵乘按当前激活类型走。真正干活的是一条通用矩阵乘:权重转置乘输入,可选偏置,可选切分累加器。八位时切分累加器跟配方走,前向默认关、反向默认开。

![按专家切开的 token 先经准备前向读全局开关；上支绿框是分组线性层一次 cuBLASLt 分组矩阵乘，量化器非空才进八位核；下支红框是普通线性层乘专家数，N 次小矩阵乘把启动开销叠在短 M 上](/opensource/TransformerEngine/04a-grouped-vs-n-gemm.svg)

专家侧用分组线性层:一次前向带上各专家的切分长度,把 N 组形状不同的乘加交给分组矩阵乘。原生分组张量路径把切分留在设备上、一次 launch;没打开这条路径时,仍会先按专家切开再进分组矩阵乘——比 N 次独立线性层好,但 delayed 配方、校准、调试、CPU offload、输出量化会把它打回去。行缩放的四位路径在分组入口里甚至会退成逐专家循环普通矩阵乘。

**为什么实际不吃亏。** 稠密层还是一层、一次乘;专家层把 N 次小乘合成一次。量化不是线性层上的类型开关,是准备前向时读到的那份全局状态,所以同一套模块,包了上下文就走低精度核,不包就走较高精度,不必维护两份权重布局。张量并行怎么切、通信怎么和矩阵乘重叠,见 08 章,本章不展开。

## 三、代价

**开关没开,核就不会换成八位。** 准备前向里若全局未开,元数据直接关掉;量化器全空,矩阵乘看见的是普通张量。

**形状卡核。** 编译路径上八位要求:除最后一维外的乘积能被 8 整除,最后一维能被 16 整除。对不齐就走不进这条核。

**分组路径不是默认。** 建层时不显式打开原生分组张量,环境变量缺省当关。打开了还要设备算力、cuBLASLt 版本、配方对得上;Hopper 上分组还要更高版本的库,块缩放、当前缩放各有一条版本线。对不上就回切分路径;单参数分组权重在回退时直接报错,不会默默拆开。

**分组层不管通信。** 并行度大于 1 时偏置直接拒绝,切分形状只用来改权重宽高,集合通信应在专家分发与合并里做。分组层也不做用户缓冲重叠,打开相关开关会立刻失败。

**八位矩阵乘不接三十二位偏置。** 激活是三十二位时,偏置会先转到十六位再进核。

**量化权重建了、计算没开。** 权重已是量化张量但开关关着,会先反量化再乘,并打一条警告:这通常不是你想要的账。

## 四、和同类算子库不一样的地方

本页只比矩阵乘有没有走到对应精度的核,以及专家侧是一次分组乘还是 N 次小乘。Apex 核在主干 8a6508aa;FlashAttention 只写本库快照里它不是矩阵乘库。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 线性层怎么乘 | 自己的线性层走通用矩阵乘;专家侧另有分组线性层,一次分组乘代替 N 次小乘 | 融合稠密层是矩阵乘加偏置,搭在框架混合精度上,没有八位配方路径 | 不是矩阵乘库。没有稠密线性层,也没有分组矩阵乘接口 |
| 精度谁决定 | 准备前向读本库全局开关;量化器空则较高精度核 | 看见框架的混合精度上下文就先把张量转好,进核时把那层上下文关掉 | 不适用:核不管线性层 |
| 专家侧 | 分组线性层把切分交给 cuBLASLt 分组;条件不够则切分后再分组,极端路径退成循环普通乘 | 没有分组专家入口,N 个专家就是 N 次融合稠密 | 不适用 |
| 和通信的边界 | 线性层上的切分模式与用户缓冲重叠交给 08 章;分组层明确不管集合通信 | 融合稠密不管张量并行 | 不适用 |

FlashAttention 没有稠密线性层,表里那一列不是漏写。

## 五、调参与观测

这一页的参数是线性层与分组线性层上的矩阵乘入口,改了要重建模块或重跑前向。配方内部的 scale 见 02 章;张量并行切分与用户缓冲见 08 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| 量化上下文是否包住前向 | 训练步 | 不包则全局关 | 关着时量化器全空,走较高精度矩阵乘 | 模块上读到的全局开关,不要只看类名 |
| `is_first_microbatch` | 线性 / 分组线性前向 | `None` | 同一小批第一段可缓存量化权重、跳过第一次梯度累加 | 微批之间权重未更新时的耗时 |
| `fp8_output` / `fp8_grad` | 线性层前向 | `False` | 给输出或输入梯度也挂量化器;可微的八位输出会逼编译回退 eager | 输出是不是量化张量 |
| `use_grouped_tensor` | 建分组线性层 | `None`,环境变量缺省当 `0` | `True` 才走原生分组张量加 cuBLASLt 分组;配方或设备不支持则回切分路径 | 是否要求切分张量在 CUDA 上 |
| `NVTE_GROUPED_LINEAR_USE_FUSED_GROUPED_GEMM` | 环境变量 | 未设视为关 | 仅当建层参数为 `None` 时顶上;已标废弃 | 启动日志里的废弃警告 |
| `NVTE_GROUPED_LINEAR_SINGLE_PARAM` | 环境变量 | `0` | 大于 0 才允许单参数分组权重 / 偏置,实验性且某些情况非确定 | 未设却传了单参数会警告并打回逐专家参数 |
| `m_splits` | 分组线性前向 | 无,必填 | 长度必须等于专家数;原生路径必须是 CUDA 上的整型张量 | 形状与专家数对不上会直接报错 |
| `delay_wgrad_compute` | 建层 | `False` | 权重梯度推迟到单独一次调用;分组层在隐式回退切分路径时与推迟梯度不兼容 | 是否还要调延迟权重梯度入口 |
| `NVTE_EXT_MARGIN_SM` | 环境变量 | 等于当前 SM 数,等于把可用 SM 减到 0 的写法需核对现场 | 分组矩阵乘留给通信的 SM 余量 | 与 08 章重叠开关一起看 |
| `save_original_input` | 建层 | `False` | 反向用原输入重建;不能和 delayed 配方一起用 | 显存是否少了一份量化输入 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡稠密,确认八位矩阵乘真开 | 线性层替换原生线性,前向只包量化上下文,反向在外,配方显式传入 | 最少胶水;还没接张量并行,也没有通信重叠 |
| MoE 专家,Hopper,当前缩放或十六位 | 分组线性层 `use_grouped_tensor=True`,切分长度放 CUDA,前向同样套量化上下文 | 一次分组乘换掉 N 次小乘;cuBLASLt 版本不够会回切分路径 |
| delayed 配方的 MoE | 分组线性层显式 `use_grouped_tensor=False`,接受切分后再分组 | 能跑 delayed;不要指望原生分组张量,那条谓词直接拒绝 delayed |
| 权重已量化、计算仍想十六位 | 不要这么配;开关关着会反量化再乘并警告 | 看起来省了一次量化,实际多一次反量化 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:矩阵乘精度看准备前向之后量化器是不是空的,不要看模块已经换成库里的;专家侧看切分长度是否一次交给分组线性层,而不是循环调普通线性层;原生分组是否生效,看切分张量在不在 CUDA、建层有没有打开原生路径。

| 症状 | 先查 | 然后 |
|---|---|---|
| 换了线性层,速度几乎没变 | 前向有没有套量化上下文;最后一维是否 16 的倍数 | 套上上下文;形状补齐,见 01 章整除约束 |
| MoE 专家数上去,耗时线性涨 | 是不是每个专家各调一次普通线性层 | 换成分组线性层,并打开原生分组张量(配方允许时) |
| 分组线性一进前向就报错 | 切分长度形状、是否 CUDA、单参数分组是否缺环境变量 | 切分改成专家数长的 CUDA 整型;单参数先关,或补环境变量 |
| 打开原生分组,Blackwell 块缩放失败 | 块缩放加原生路径在 Blackwell 上被直接拒绝 | 关掉原生路径走切分,或换配方 |
| 量化权重却打出「没有量化计算」警告 | 全局开关是不是关着 | 包量化上下文,不要只量化权重 |

## 六、常见误区

**「线性层已经换成库里的,矩阵乘就该是八位。」** 准备前向读到开关关着,量化器全空,通用矩阵乘按激活类型走。这和 01 章「积木在、低精度没开」是同一件事,只是落点在矩阵乘这一跳。

**「MoE 有 N 个专家,就建 N 个线性层循环调用。」** 每次都是短 M 的独立矩阵乘,启动把卡吃满。分组线性层才是把 N 组合到一次分组乘。

**「建了分组线性层就等于走了原生分组张量。」** 默认当关。不显式打开,走的是切分量化再分组;delayed、校准、调试、offload 还会把原生路径打掉。

**「FlashAttention 也能当线性层加速。」** 它不是矩阵乘库。线性层的核在本库自己的通用矩阵乘和 cuBLASLt 分组里。

**「分组线性层会帮我做张量并行通信。」** 文档写明不管。并行只改权重形状,集合通信在分发与合并,重叠在 08 章。
