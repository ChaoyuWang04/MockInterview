# 权重通路

这一页回答一件事：训完一步之后，新权重怎么从训练切法变成生成切法，四条路怎么选、哪两条互斥。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过，「当前」与「默认」都指这组基准。

## 一、核心问题

训练侧按自己的并行切参数，生成侧按服务形态切。每训完一步都要把前者变成后者一次。共卡还是分卡，02 章已经定了槽；服务怎么起，04 章已经定了。本章只定这一趟搬运。

最天然的做法是每步把每个参数拼成整张量再整包推过去。它一定对。坏在字节数等于参数字节数，而且每步一遍。模型一大，通信或写盘会吃掉一步的大头——生成和训练都在干等这一段。跨机房时整包走网更难看。

反过来只传变了的字节，听起来能把线上量砍掉。但它要一份对照基准、一次比对、一次落盘打补丁。共卡时两边本来就在同一张卡上，交的是句柄，这份比对是纯开销，工厂直接拒绝。

所以真问题是：共卡走张量、分卡走集合通信或盘、跨机房走增量；增量不能和共卡一起开。

## 二、解法

工厂按三个开关四选一，顺序写死：先看是不是增量，再看是不是盘，再看是不是共卡。

**增量必须走盘，而且禁止共卡。** 持有整张量的那些 rank 把当前参数和上一份主机端副本按字节比一遍，只把变了的写成一版补丁目录。每台生成机器把自己的本地检查点打上补丁，再走引擎普通的读盘重载。第一次调用只钉基准、不发补丁，所以第一步看起来像「没推」。补丁默认按位异或，对着错的基准多打一次会退回去；另一种记绝对位置，可以重复打。

**全量走盘时，训练侧写下完整的 HuggingFace 检查点，生成侧再读。** 生成期间杀掉训练进程那一档，权重必须走这条：进程已经没了，句柄和集合通信组都不在。写完之后由训练组决定引擎何时读盘，好让杀进程发生在文件齐了之后。

**共卡且不走盘，交的是张量。** 同卡上只把句柄递过去，不必再走一遍网。工厂注释写明：共卡这条路上增量那套记账是纯开销，所以增量箭头进不了这个框。

**分卡且不走盘，默认走集合通信。** 按流水线分段建组，源 rank 把拼好的块广播给各引擎。缓冲按字节分块，默认同步一块大约 512 MB，给 MoE 那种参数特别碎的模型用。

![四条权重通路的分流：先问增量，共卡则拒、分卡则走盘上的补丁；全量再问盘还是网，盘写下完整检查点，网在共卡走张量、分卡走集合通信](/opensource/slime/05a-weight-route-select.svg)

循环里提交作业的进程在训完之后调一次推权重；训练组再打到每个训练进程。只跑生成或只跑训练时，这一趟直接返回。

## 三、代价

**第一笔是全量每步的字节。** 默认就是全量。分卡走集合通信时，线上是整模型；走盘时，线上是整份检查点再加一次读盘。模型越大，这一段在一步里的占比越难看。

**第二笔是增量省通信、把正确性押在链上。** 第一次只钉基准；之后每步依赖副本对、补丁只打一次、本机检查点还在。异或是对合，打两次等于没打。跨机房的共享盘若没有写后可见，还要在写完之后挂一个钩子把文件公布出去，否则生成侧会读到半份。

**第三笔是共卡与增量互斥、杀进程与增量互斥。** 杀进程要全量盘；增量要分卡、要盘、还要本机检查点目录。想「同卡又只传变化」或「杀掉训练进程又走增量」，启动就会拒。

**第四笔是切法翻译仍在训练后端目录里。** 更新器自己既懂切法又负责发出去。换切法不用中间那层声明，也没有第二张传输后端表可以往外长。

## 四、和同类大厂框架不一样的地方

对照只取大厂在大规模训练里真用的框架；这一页主对 verl。重点在 slime 怎么选路，不评哪家更好。

| 比什么 | slime | verl |
|---|---|---|
| 谁来折切法、谁来发 | 更新器贴在唯一的训练后端目录里，自己既折又发 | 中间抽一份与后端无关的声明，传输层不认识并行方式 |
| 共卡怎么交 | 同卡句柄直交张量，不走盘、不走增量 | 共卡那组管理器走进程内直给，不读分卡那套传输名 |
| 只传变了的字节 | 只走共享盘加本机打补丁，明文禁止共卡 | 走集合通信上的稀疏补丁，禁止的是共卡那一半 |
| 补丁编码 | 默认按位异或，另有可重复打的绝对值 | 位置加绝对值，天然可重放 |
| 杀掉训练进程时 | 必须全量盘，文件齐了才让引擎读 | 没有「杀掉训练进程再拉起」这一档绑在权重通路上 |

换句话说，slime 拿「只贴一个训练后端、增量走盘」换掉了中间那层声明。适用面砍掉共卡那一半；verl 砍掉的也是共卡，但增量走的是网而不是盘。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。** 作业入口仍是仓库根那份训练脚本;本表只列通路上的开关。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--update-weight-mode` · 全量还是增量 | 启动 | `full` | `delta`：只发变了的字节；必须同时走盘、关共卡、给本机检查点目录 | 启动校验；第一步是否只有钉基准的日志 |
| `--update-weight-transport` · 走网还是走盘 | 启动 | `nccl` | `disk`：写下检查点或补丁目录；必须给共享目录 | 该目录下是否出现带版本号的子目录 |
| `--update-weight-disk-dir` · 盘同步的共享目录 | 启动 | 空 | 走盘时必填，训练与生成都要看得见 | 启动即报缺目录 |
| `--update-weight-disk-keep-files` · 全量盘子目录删不删 | 启动 | 关 | 开：读完不删；默认读完就清 | 共享目录是否堆积 |
| `--update-weight-delta-encoding` · 补丁怎么编码 | 启动 | `xor` | `overwrite`：可重复打，线上更大 | 补丁目录元数据里的编码名 |
| `--update-weight-delta-checksum` · 补丁校验算法 | 启动 | `xxh3-128` | 另两档给不信任存储或要对齐别的系统 | 同上 |
| `--update-weight-local-checkpoint-dir` · 生成机器本机检查点 | 启动 | 空 | 增量时必填；全量盘选填，填了先拉到本机再读 | 引擎是否从本机路径重载 |
| `--custom-update-weight-post-write-path` · 写完后公布文件的钩子 | 启动 | 空 | 非 POSIX 共享盘要显式同步时用 | 钩子跑完引擎才读得到 |
| `--update-weight-buffer-size` · 分块推送的字节预算 | 启动 | 512 MiB | 大了块少、峰值高；给 MoE 那种碎参数 | 推送时的分块次数 |
| `--colocate` · 共卡 | 启动 | 关 | 开且不走盘：走张量；与增量互斥 | 启动校验 |
| `--release-train` · 生成期间杀掉训练进程 | 启动 | 关 | 开：必须全量盘、要保存路径；不能和价值网络、增量一起开 | 每步训练前是否重建 actor |

**怎么看。** 一是提交作业的进程卡在推权重还是已经返回。二是训练组日志：增量密度、线上字节、是否「没有可更新的引擎」。三是共享目录和本机检查点：版本号是否前进、全量盘子目录读完是否被清。

**典型配置。** 三套能直接抄走的起法，参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 分卡、机房内网、先把通路跑通 | 模式保持全量，载体保持集合通信 | 用每步整包通信换实现简单、无补丁链 |
| 共卡、同机 | 打开共卡，不要改成盘、不要开增量 | 用句柄直交换掉网和盘；显存让出仍按放置章 |
| 分卡、跨机房或模型很大 | 模式改增量，载体改盘，给共享目录和本机检查点；不要开共卡 | 用补丁链和第一次只钉基准，换掉每步整包 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动报增量不支持共卡 | 共卡和增量是否同时开 | 只能留一个；共卡请走张量 |
| 启动报增量必须走盘 | 载体是不是还停在集合通信 | 增量没有网这条路 |
| 启动报缺本机检查点目录 | 增量有没有给生成机器的本地路径 | 共享目录不够，打补丁要落在本机 |
| 启动报杀进程必须全量盘 | 模式和载体是不是全量加盘 | 杀了进程就没有句柄和通信组 |
| 第一步增量像没推 | 是不是第一次调用 | 第一次只钉基准，下一训完才发补丁 |
| 生成侧权重半新半旧 | 异或是否打了两次、共享盘写后是否可见 | 换可重复打的编码，或挂上写完公布的钩子 |
| 推权重日志说没有可更新的引擎 | 冻结的模型会不会把更新关掉 | 没人收权重时这一趟会跳过 |

## 六、常见误区

**以为默认会走增量。** 默认是全量加集合通信。没改两个开关，每步仍是整包。按「后训练变化很小所以线上一定很瘦」估一步时间，会低估通信。

**以为共卡加上增量能两头讨好。** 共卡交句柄，比对没有对象可省。工厂在选路和启动校验两处都拒，不是漏实现。

**以为杀掉训练进程还能走张量或增量。** 进程没了，句柄和组都不在，只剩下盘上的全量文件。和价值网络也互斥，那是放置章的条件，不要在这里再开一组卡来绕。

**把第一次增量同步当成故障。** 第一次只钉基准，好让下一份补丁有对照。去引擎日志里找「第一步没重载」，找的是设计如此。

**把按位异或当成可以随便重放的补丁。** 它最快、线上最省，但是对合。失败重试多打一次会退回旧值。需要重放，换绝对值那一档。
