# 可插拔数据生成

这一页回答一件事:默认生成只负责并发与回收;每条样本怎么出字、走几轮、调不调工具、进不进沙箱,是一条用户函数;agent 适配器只是这条函数的便利层。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

生成侧已经是一组 HTTP 服务了。服务只认一件事:给我一段输入,还你一段输出。任务却差得很远——单轮答题、多轮改代码、外面已经写好的编码 agent——每一种都想改「这一条怎么跟服务器说话」。

最常见的两种做法都会把指标弄坏。一种是每种任务 fork 一套框架:循环、调度、权重通路一起抄走,补丁跟不上,崩在漏掉的那一处,坏的是**稳定性**。另一种是把现成 harness 当黑盒:它自己再切一遍词,训练侧看到的 token 和生成时真吐的那一串对不上,坏的是**训推一致**——比值失真,曲线慢慢不对,往往还不崩。

所以真问题是:循环和引擎接口必须稳住,任务差别只能换「这一条怎么生成」。

## 二、解法

生成管理器启动时按路径装进一条生成函数。循环每步只调这一条,不按任务再开一套入口。

**默认那条函数只做并发与回收。** 它从数据源按组取出样本对象,用信号量卡住同时在飞的请求数,谁先完成谁先交卷,凑够这一步的题数就把还在飞的中止掉。中止下来、已经写出半截的组可以送回数据源,下一步接着飞。打分、组过滤、过采样闸门在生成之后、训练之前,细节在 08 章;默认路径里,一条样本生成完若还没有分数,会就地调一次打分。

**每条样本怎么跟服务器说话,是另一条用户函数。** 没给路径时,默认就是发一次请求、把返回的 token 和 logprob 接到这条样本上。给了路径,就整段换掉:多轮、工具、沙箱都写在你这份代码里。函数还可以标「按请求中止」——否则中止走整组服务。一条执行可以扇出成多条可训样本,但必须共用同一个编号,训练侧才不会把一次执行算成多条。样本对象自己也能指定另一条路径,评测集可以和训练用不同的函数。

**agent 适配器不是独立框架。** 它是这条用户函数里的便利层:在模型 API 边界拦请求,把引擎当时吐出的 token 记进轨迹,再线性化成带掩码的样本对象。外面的编码 agent 仍在沙箱里原样跑,工具属于那个 harness,不属于 slime。核心里搜不到工具注册表。适配器自己会处理切词漂移:用引擎快照对齐,而不是把对话再套一遍模板。

数据源默认带一块缓冲:先从缓冲取,不够再从全局题库切。生成函数负责把中止的组加回去;只读数据源会拒绝写入。

## 三、代价

**第一笔是合同薄。** 循环帮你并发和回收,不帮你把多轮写对。用户函数漏接 token、漏写掩码、漏填编号,训练侧照单全收。合同以外的事,循环不会替你补。

**第二笔是并发上限在默认函数里。** 同时在飞的条数是「每台引擎允许的并发」乘引擎台数。用户函数里再自己开一批协程,不会自动再领一张通行证;慢工具占的是这条样本的槽位,也占着信号量。

**第三笔是黑盒切词这条路被故意堵住。** 适配器要的是引擎快照,不是 harness 事后再切的那一串。图省事把最终消息列表重新套模板,单轮上就足以让训练不收敛——这不是风格问题,是这条合同要守住的那条线。

**第四笔是换整条生成函数时,默认那套并发与回收一起被换掉。** 完全异步就是这样换的,后台工人跨步保持在飞的轨迹,循环骨架不动;那是 07 章的主场。本页只提醒:换整条和只换「每一条怎么生成」不是同一个旋钮。

## 四、和同类大厂框架不一样的地方

对照栏只放 verl。

| 比什么 | slime | verl |
|---|---|---|
| 多轮循环写在哪 | 不在核心主路径。默认生成函数发一次请求;要多轮,换的是每一条上的用户函数,循环写在你自己那份代码里 | 会话循环是生成的唯一入口;连一问一答也是注册在册的一套循环,只跑一轮就收 |
| 工具算不算框架概念 | 核心里没有工具注册。工具属于外面的 harness;slime 只在模型 API 边界做代理 | 有自己的工具契约,按名字装进会话进程,返回值包成消息接回对话 |
| 谁负责解析动作 | 不自带按模型族分的解析器;借唯一那家推理引擎当时吐出的结构 | 自带按模型族分开的解析器,因为同一套循环要在多家推理后端上成立 |
| 整层能换到哪 | 两条旋钮:只换每一条怎么生成,或换掉整条生成函数(连并发回收一起) | 数据集一列名字选循环类;管理器本身也能按类名整层换成别人的 agent 框架 |
| 训练看到什么 | 样本对象上的 token、长度、分数、状态;一次执行拆多段必须共用编号 | 轨迹写进队列的键,训练侧按键自取 |

slime 拿「生成可插、核心不养一套 agent 运行时」换了跟任务的速度:新 harness 不用 fork 框架。付出去的是:用户函数和适配器必须自己把 token 账做平。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。** 启动方式是跑仓库根的训练脚本。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--rollout-function-path` · 整条生成函数 | 启动 | `slime.rollout.sglang_rollout.generate_rollout` | 换掉并发、回收、评测分支整段;样本至少要填 token、回复长度、分数、状态 | 生成管理器启动日志里导入了哪条 |
| `--custom-generate-function-path` · 每一条怎么生成 | 启动 | 空,走默认的一次请求 | 多轮、工具、沙箱写在这条函数里;可给函数打上按请求中止 | 同上;空则走内置一次请求 |
| `--eval-function-path` · 评测用的生成函数 | 启动 | 空则抄生成函数那条 | 评测与训练可以分家 | 评测日志 |
| `--data-source-path` · 数据源类 | 启动 | `slime.rollout.data_source.RolloutDataSourceWithBuffer` | 换成只读源则中止半截无法加回 | 中止后下一步是否还能接到半截 |
| `--n-samples-per-prompt` · 每题几条回答 | 启动 | 1 | 一组里并发生成这么多条;默认函数断言组长度等于它 | 生成日志里这一组的条数 |
| `--over-sampling-batch-size` · 一次从数据源取几组 | 启动 | 空则等于每步题数 | 必须大于等于每步题数;动态过滤吃掉的组靠它补 | 过滤后仍凑不齐时会再取 |
| `--sglang-server-concurrency` · 每台引擎允许的并发 | 启动 | 512 | 信号量上限 = 它 × 引擎台数 | 生成侧同时在飞的条数 |
| `--rollout-sample-hook-path` · 生成后、打分前的钩子 | 启动 | 空列表,可重复 | 每条样本生成完先过钩子 | 钩子里打的日志 |
| `--partial-rollout` · 中止半截是否回收 | 启动 | 关 | 开:中止且已有回复的组加回数据源 | 日志里回收了多少条 |
| `--disable-rollout-global-dataset` · 关掉全局题库 | 启动 | 关(即默认用全局题库) | 开:默认生成函数会断言失败,题目得自己管 | 启动断言 |

样本对象上还有一条按条覆盖的生成函数路径,评测集配置也可以单独给。一次执行拆成多段时,各段要写上同一个编号,否则损失会按多条独立样本计。

**怎么看。** 一是生成管理器启动日志:导入了哪条生成函数、哪条评测函数。二是第一步打出来的样例:提示、回复、分数是否像你写的那条函数。三是训练侧样本数:每步题数乘每题几条,再核对有没有扇出却没共用编号。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 单轮可验证答题 | 不要设每一条怎么生成;数据源保持默认带缓冲 | 用一次请求换最短路径,先确认并发与回收是通的 |
| 多轮或要跑沙箱 | 只设每一条怎么生成,指向你的用户函数;需要按请求中止就给函数打上相应标记 | 用自己维护 token 账,换「不 fork 框架」 |
| 连并发回收都要自己写 | 换整条生成函数;完全异步走这一档,细节见 07 | 用整段替换换跨步在飞;默认那套回收不再替你干活 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动日志导入的不是你以为的那条 | 整条生成函数和每一条怎么生成是不是设反了 | 前者换并发回收,后者只换一条样本 |
| 训练样本数是预期的好几倍 | 用户函数是否扇出多段却没共用编号 | 补同一个编号,否则损失会重复计 |
| 训推 token 对不上 | 用户函数有没有把对话重新套模板切词 | 用引擎当次回包里的 token,不要事后再切 |
| 中止后半截再也接不回来 | 数据源是不是只读、半截回收开没开 | 默认带缓冲的源才能 `加回去`;开关在上表 |
| 生成一直占满、像死锁 | 用户函数是否在信号量里面又同步死等 | 慢等待要让出槽位,或把中止标成按请求 |
| 评测走了训练那套多轮 | 评测函数路径空着 | 空则抄生成函数;评测要单轮就单独给 |

## 六、常见误区

**以为 agent 适配器是另一套运行时。** 官方文档写明它不是独立 agent 框架。把它当成可以单独拉起的调度器,会去核心里找工具表、会话进程,找不到就误以为缺功能。

**以为换任务就要换整条生成函数。** 多轮、工具、沙箱通常只换「每一条怎么生成」。整条换掉时,默认的并发与回收一起消失,那是另一档需求。

**以为 harness 再切一遍词也没关系。** 训练要的是生成时那一串。事后套模板切出来的 id,和模型当时吐的不是同一串。

**以为默认生成函数会替你写多轮。** 它只发一次请求。多轮循环在用户函数里,不在默认路径里。

**以为数据源总能收回中止的组。** 只有带缓冲的那一类实现了加回;基类是只读的,写入会直接报错。
