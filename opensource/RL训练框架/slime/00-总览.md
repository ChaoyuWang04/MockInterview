# slime 框架总览

源码基准:官方仓库 <https://github.com/THUDM/slime>,分支 `main`,commit `5bae5bb7928d65906e24e99f5b5d3f99a4daaf93`,最近的发布 tag `v0.3.2`,核对日期 2026-09-21。全篇的「当前」「默认」都指这组基准;带「官方数字」的性能数据来自官方文档,未实测。

## 一、slime 是什么

**slime** 是清华 KEG / 智谱系开源的大模型后训练框架,定位是 RL scaling。它要解决的事情和推理引擎不同,也和「再做一个万能 RL 平台」不同:一次强化学习后训练里,同一批或两批卡上要同时活着**更新策略的训练进程**和**出样本的推理服务**,它们每一步交换权重,而样本从哪来——数学题、搜题、改代码、多 agent——差别极大。社区常见的做法是为每种任务 fork 一个框架,结果补丁跟不上、训练崩在漏掉的那一处。

slime 的回答是把这件事收成**一条路径上的两件事**。训练固定走 Megatron,生成固定走 SGLang 服务器,中间用 Data Buffer 传同一种样本对象。任务差别全部塞进「这一条样本怎么生成、怎么打分」的函数,而不是另起一套训练循环。官方 README 把 GLM-5.3 到 GLM-4.5 的完整后训练闭环算作实战验证,不是孤立 example。

一句话定位:**slime 把「Megatron 直通训练 + SGLang 原生生成 + 可插拔数据函数」收成一套后训练路径,用少一层抽象换跟上游、用一条生成接口换不 fork 框架。**

顶层入口(仓库根):

- `python train.py`:唯一的训练主入口,参数由 `slime.utils.arguments.parse_args` 解析,把 Megatron 原样参数、加了前缀的 SGLang 参数和 slime 自己的参数拼在一起。
- 没有第二套异步训练入口。完全异步是把默认生成函数换成 `slime.rollout.fully_async_rollout.generate_rollout_fully_async`,循环仍在 `train.py` 里。
- 监督微调走另一条生成函数,官方博客标为试验状态,本解读不展开。

代码组织上,主体在 `slime/`(1443 KB、159 个文件),模型接线在旁边的 `slime_plugins/`(190 KB)。另有三块体量不小但本解读不涉及的东西:`docs/_static` 的图资产、`docker/` 与 `.github/`、`tests/`。从体量看,`slime/` 里 Megatron 适配占 46%,参数与工具 23%,生成与奖励 8%,agent 适配 7%,观测 6%,Ray 编排 4%。**而全篇的核心、那条 `train.py` 里的顺序循环只有 4 KB。**

## 二、6 个招牌:先建立全局图景

```text
                控制器进程:一步 RL 的训练循环顺序写在这里
                生成 → 训练 → 把新权重推给生成侧
                                    │
              [1] 一条路径:训练 / 生成 / Data Buffer 共用同一种样本
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
   [6] 可插拔生成              [2] Megatron 直通            [4] 放置
   每条样本是一条用户函数      参数原样透传,没有引擎层      共卡或分卡一个开关
   agent 只是这条函数的便利层   损失和优势挂在训练步上       共卡就要让显存
        │                           │                           │
        └───────────────────────────┼───────────────────────────┘
                                    ▼
                  [3] SGLang 原生:服务器模式 + 参数加前缀透传
                   路由、PD 分离、外部引擎都是起服务的变体
                                    │
                                    ▼
                  [5] 权重通路:共卡走张量,分卡走 NCCL 或盘,跨机房走增量
```

一句话记忆:

- **一条路径**:训练、生成、自定义数据、奖励、环境交互走同一条 training / rollout / Data Buffer,不为每种任务 fork 框架。
- **Megatron 直通**:训练侧没有「六个后端」的抽象,Megatron 的并行、优化器、检查点参数原样进来。
- **SGLang 原生**:生成侧故意只接一家,服务器模式启动,已安装版本的 SGLang 参数加前缀就能用。
- **放置**:共卡或分卡一个开关;共卡默认两边把显存让出去;还可以只起训练或只起生成做排障。
- **权重通路**:共卡、分卡、跨机房不是同一条线,增量模式不能和共卡一起开。
- **可插拔生成**:默认循环只负责并发和回收;多轮、工具、沙箱、已有 harness 都是一条生成函数加一条打分函数。

## 三、11 章,各自解决什么

下表是本解读的章表。**这里只回答「它存在是为了解决什么」**;展开讲解在各章,代码在哪见代码索引页。

| 主题 | 不这么做会怎样 | 做法一句话 | 详见 |
|---|---|---|---|
| 整体架构与一步训练的生命周期 | 训练、生成、数据各写一套:权重版本对不上,排障找错仓库 | 控制器一个文件顺序写;生成和训练是两组 Ray actor,样本走 Data Buffer | 01 章 |
| 放置与显存让出 | 两边各占一份卡不够用;共卡又不让显存就 OOM | 共卡或分卡一个开关;共卡默认两边 offload;两条只起一边的排障路径 | 02 章 |
| Megatron 直通训练 | 换训练框架要重写循环;包一层引擎又跟不上 Megatron fork | 没有引擎抽象,训练步就是 Megatron actor;损失、优势、蒸馏钩子挂在这一步 | 03 章 |
| SGLang 原生部署 | 抽象成多引擎公因子会丢掉路由、缓存和分离式部署 | 服务器模式加前缀透传;router、PD、外部引擎都是起服务的变体 | 04 章 |
| 权重通路 | 每步全量推权重,通信或写盘吃掉一步的大头 | 共卡走张量,分卡走 NCCL 或盘,跨机房走增量;增量不能和共卡一起开 | 05 章 |
| 可插拔数据生成 | 每种任务 fork 一个框架;黑盒 harness 重切词则训推 token 对不上 | 默认循环只做并发与回收;每条样本的生成是用户函数,agent 适配器只是便利层 | 06 章 |
| 长尾与完全异步 | 同步一步等最慢的那条,长尾 agent 让卡空转 | 后台工人跨步保持在飞轨迹,中止的组回到 buffer 再训 | 07 章 |
| 奖励、过滤与动态采样 | 打分慢堵住整步;过采样不中止就白占生成位 | 打分和组过滤是生成之后的闸门;过采样靠中止回收 | 08 章 |
| 训推一致、路由回放与低精度 | 两侧概率对不上,MoE 专家对不齐,训练发散 | 路由回放、权重核对、低精度各治一段 | 09 章 |
| 观测、复现、容错与调试 | RL 的错常常不报错;挂了接不回去 | 生成可回放、健康检查、trace 与剖析是一等工程,不是附加项 | 10 章 |
| 模型接入 | Megatron 还不认的架构接不进来 | 用 HF 模块替换 Megatron spec,再补权重映射 | 11 章 |

配置系统不单独成章,三种入口集中在本页第六节。

## 四、一步训练怎么串起来

控制器是提交作业的那个进程,循环写在 `train.py` 里。启动时先向 Ray 要卡,再起 **RolloutManager**(里面再起 SGLang 服务器和路由),再起 **训练 actor 组**(Megatron,需要时还有 critic)。先起生成侧,是因为有的作业用「每个 epoch 多少步」反推总步数,这个数要从数据源问出来。

一步里先让 RolloutManager 生成一批,拿到的是样本引用而不是把整批张量塞回控制器。需要让显存时,生成侧先把权重卸掉。然后训练组对这一批做一次 `async_train`:actor 在 offload 打开时会先醒过来、算完再睡。若开了 critic,先让 critic 训出价值,再交给 actor。训完把新权重建成生成侧能加载的形状推过去,下一步才敢用新权重生成。

共卡和分卡的差别主要落在「谁和谁挤一张卡」以及「权重怎么送」:共卡时生成和训练轮流占用同一批 GPU,默认两边都要把显存让出去,权重走张量;分卡时两边同时活着,权重走 NCCL 或共享盘,跨机房才走增量。完全异步并不改这条循环的骨架,它改的是生成函数内部:后台工人跨步保持在飞的轨迹,被中止的组回到 Data Buffer,而不是当成这步的训练样本。

## 六、怎么调它、怎么看它

各章「调参与观测」只写自己的参数,入口在这里说一次。

**三种入口,一个原则:改了要重新拉起整个作业。**

| 入口 | 长什么样 | 什么时候用 |
|---|---|---|
| Megatron 原样参数 | 直接写 `--tensor-model-parallel-size` 这类,slime 不改名 | 模型结构、并行、优化器、检查点 |
| SGLang 前缀参数 | 已安装版本支持的参数一律加 `--sglang-`,例如静态显存比例写成带此外缀的同名项 | 生成服务的显存、并行、缓存、分离式部署 |
| slime 自己的参数 | 定义在 `slime/utils/arguments.py`:卡怎么分、生成函数路径、权重模式、共卡开关 | RL 循环和资源布局 |

共卡开关打开时,未显式关掉的一侧会默认把显存让出去。只起训练或只起生成的两条排障路径,用来把「生成慢」和「训练慢」拆开。观测走统一的上报层(wandb 等),生成轨迹走 trace,跨角色耗时走剖析器,引擎挂没挂走健康检查(见 10 章)。

## 七、阅读顺序

主干是 01 → 02 → 03 → 04 → 05,读完就抓住了 slime 的主线:一步怎么串,卡怎么摆,训练为什么不包引擎,生成为什么只接 SGLang,权重怎么送过去。06 到 08 是这条主线上「样本从哪来」的三件事(生成函数、长尾、打分过滤),做 agentic 或过采样时再读;09 到 11 按需查阅。

**怎么读**:强化学习的算法本身在知识库里各有一篇,**本解读一概不讲算法是什么**,只讲 slime 怎么把它挂进 Megatron 训练步、怎么把一条 agent 执行收成可训样本。每一章都是短页:核心问题、解法、代价、和同类常见做法不一样的地方、调参与观测、常见误区。第四段只做能核到的对比,重点在 slime 自己。哪一句想展开,在对话里问。

和另外两份解读的分工也在这里说清。SGLang 内部的调度、缓存、PD 实现见 SGLang 解读,slime 的 04 章只写「RL 作业怎么把它起成服务、参数怎么透传」。Megatron 的并行与优化器见 Megatron-LM 解读,slime 的 03 章只写「后训练这一步怎么调用它」。推理引擎关心一条请求怎么服务好;slime 关心一步训练里训练和生成怎么共用或分用卡,以及样本函数怎么插进来。

## 八、术语表

| 术语 | 一句话 |
|---|---|
| Data Buffer | 生成和训练之间的样本桥,默认实现带一块可还回的 buffer |
| 直通 | 上游框架的参数原样进入 slime,不在中间再包一层引擎接口 |
| 共卡 | 训练和生成挤同一批 GPU,用一个开关打开,默认两边都要让显存 |
| RolloutManager | 生成侧的 Ray actor,负责起服务、调生成函数、交出训练引用 |
| Sample | 一条可训片段;一次执行拆成多段时,这些段要共用同一个 rollout 编号 |
| 自定义生成函数 | 只替换「这一条样本怎么跟服务器说话」,外层并发循环还在 |
| 生成函数路径 | 替换整段生成编排的钩子,完全异步走这条,而不是另写一个训练入口 |
| 前缀透传 | 把 SGLang 原参数加上固定前缀后交给 slime,安装版本支持什么就能开什么 |
| 增量同步 | 只把两次同步之间变了的权重写成盘上的差量,不能和共卡一起开 |
| 完全异步 | 后台工人跨训练步保持在飞轨迹,长尾不再卡住下一步 |
| 路由回放 | 生成时记下的 MoE 专家选择,训练时按同一路由重算 |
| 只起一边 | 排障时只拉训练或只拉生成,用来把两边的慢拆开 |
