# 奖励、过滤与动态采样

这一页回答一件事：字写完之后、训练开算之前，分数怎么打上、哪一组能留下、多取出来的怎么把槽位收回来。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过，「当前」与「默认」都指这组基准。

## 一、核心问题

生成侧交卷的是一串 token。训练侧要的是带着分数、组内还有差别的样本。这两件事不在同一拍：字可以很快写完，分可能还在远端规则或 HTTP 上排队；一组里全对或全错，优势算出来是一条平线，这一组白占一步。

闸门若漏了，坏的是**一步墙钟**和**有效样本**。打分慢，生成位被占着等分，整步过不去。组过滤没开，无信号的组照样进训练，损失有数、梯度没方向。过采样一次多取了好几组、却不在够数之后把还在飞的中止掉，多出来的请求继续占引擎并发，白占生成位。

所以真问题是：生成之后、训练之前必须有闸。分要打上，没信号的组要丢掉再补，多取的要靠中止把槽位还回去。

## 二、解法

默认生成函数在一组写完之后立刻打分，再拿组过滤决定留不留，凑够这一步题数就把还在飞的中止掉。完全异步那条工人路径同样尊重组过滤，被拒的组不计入这一步要的组数；工人本身是上一章的事。

**打分是生成之后的第一道闸。** 没给用户打分函数时，按奖励类型走内置规则：数学对错、DAPO 那套分、选择题、指令遵循、远端 HTTP，也可以先从盒子里抽出答案再打。给了用户函数，整段换掉。默认按条打；打开整组打分后，一组全写完才一起算，好让需要看整组的打分一次拿到所有回答。已经中止的样本不再打。用户函数也可以在生成里自己填分，闸门看到有分就不再调一次。

**组过滤是第二道闸。** 给一条函数路径，对刚打完分的一组说留还是丢。内置例子看组内分数标准差：几乎为 0 就丢，理由记成「零方差」加那个分数。丢了的组不进训练，在飞计数减一，循环继续取新组，直到留下的组数等于这一步要的题数。另有一档：候选已经不够填满这一步时，即使零方差也留下，免得再开一轮过采样空转。

**过采样是第三道闸，靠中止回收。** 一次从数据源取出的组数默认等于这一步题数；调大之后，过滤会扔掉一部分，仍有余量尽快凑够。不够就再取一轮，粒度始终是这个数，跟部分回收开没开无关。够数之后，还在飞的请求走中止：可以按请求取消，也可以整组服务清到空闲。中止的组不进训练。打开部分回收时，已经写出半截的组退回缓冲，下一步再捡；缓冲里先取谁，由缓冲过滤决定——默认弹出最先放进去的，也可以改成先弹出生成时权重最旧的，或换成用户函数。凑够之后还可以再跑一遍样本过滤，只改「这条算不算进损失」，不改优势归一化用不用它。需要看见被丢掉的组时，另挂一条「全体样本」钩子，训练批和候选批一起交给它。

## 三、代价

**第一笔是打分堵在生成位上。** 默认路径里，一条样本占着并发槽直到分打完。规则很快还好；远端 HTTP 慢、重试多，槽位和一步墙钟一起被拖住。整组打分更明显：最慢那条写完，整组才开始算分。

**第二笔是过滤让一步变长。** 丢掉的组已经付过生成和打分。题库里大量全对或全错时，可能连续丢好几组才凑够，过采样粒度越大，一次白烧越多。兜底留下零方差那一档能少一轮空取，但会把没信号的组放进训练。

**第三笔是中止有损耗。** 多取出来的请求不是免费预取：够数之后必须中止，引擎才把并发还给下一步。不中止，过采样等于长期多占一组生成位。部分回收保住题目，不保住已经吐出的 token；没开部分回收，半截直接丢掉。中止走整组服务时，要把每台引擎清到空闲才算完；按请求中止则只取消还挂着的那几条，两种不是同一个旋钮。

## 四、和同类大厂框架不一样的地方

对照栏只放 verl。两边都要在进训练前丢掉组内没差别的题，落点不同。

| 比什么 | slime | verl |
|---|---|---|
| 闸门在哪一段 | 默认生成函数里：写完立刻打分，组过滤随后，够数就中止多取的 | 生成 loop 和打分 loop 可分开；组过滤做在回放缓冲里，和超龄、失败并成淘汰理由 |
| 没信号怎么判 | 用户函数说了算；内置看组内分数标准差是不是几乎为 0 | 同组条数大于 1 且指定指标标准差为 0；缺指标字段直接报错 |
| 丢掉之后怎么补 | 在飞计数减一，继续按过采样粒度取新组；够数后中止剩余 | 淘汰与补题按训练器档位配矩阵，同步档分组过滤常按丢掉的组补两倍 |
| 多取出来的怎么收 | 过采样粒度大于这一步题数；收口靠中止，不靠缓冲丢超产 | 同步档分组过滤会另计「多出来被丢掉」；异步档走缓冲淘汰再精确补 |
| 打分和生成是否同槽 | 默认占着生成并发直到分回来；整组打分还要等整组写完 | 共卡的奖励模型只能在采样结束后算；分组过滤因此要求规则奖励，或奖励模型另开资源池 |

slime 拿「闸门写在生成收口上、过采样靠中止」换了实现短：不必再养一套淘汰补题矩阵。付出去的是：打分慢就堵住生成位；过采样忘记中止，多占的槽不会自己消失。

## 五、调参与观测

**这一页的参数全是启动配置，改了要重新拉起整个作业。** 闸门装在默认生成函数里，改路径或粒度都要整场重拉。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--rm-type` · 内置打分类型 | 启动 | 空 | 空会在真正打分时报未实现；`math` / `dapo` / `deepscaler` / `f1` / `gpqa` / `ifbench` / `remote_rm` / `random`，可加 `boxed_` 前缀先抽盒子 | 生成日志里第一条样本的 reward |
| `--custom-rm-path` · 用户打分函数 | 启动 | 空 | 有则整段换掉内置类型；按条调用签名是一条样本，整组打分时改成一批样本 | 同上；签名不对会在第一组报错 |
| `--group-rm` · 等整组写完再打分 | 启动 | 关 | 开：一组全写完才算分；评测路径直接拒绝 | 打分跨度是否覆盖整组 |
| `--rm-url` · 远端打分地址 | 启动 | 空 | 类型为远端时必填；失败最多重试 10 次，退避上限 30 秒 | 打分日志里的重试 |
| `--reward-key` · 分是字典时取哪一键 | 启动 | 空 | 打分返回字典时用它取出标量 | 过滤用的那个标量 |
| `--over-sampling-batch-size` · 一次取几组 | 启动 | 空则等于每步题数 | 必须大于等于每步题数；大了过滤有余量，中止也更多 | 一次提交的组数 |
| `--dynamic-sampling-filter-path` · 组过滤函数 | 启动 | 空 = 全留 | 内置零方差丢组；带兜底的那条在候选不够时留下 | `rollout/dynamic_filter/drop_*` |
| `--partial-rollout` · 中止半截退回缓冲 | 启动 | 关 | 开：动态采样里没写完的组回收；长回答少付一遍 | 中止日志里回收条数 |
| `--buffer-filter-path` · 缓冲里先取谁 | 启动 | 空 | 有则覆盖下面那条陈旧排序 | 下一步是否先拿到回收组 |
| `--buffer-sort-by-staleness` · 缓冲先取最旧权重 | 启动 | 关 | 开且没给缓冲函数：先弹出生成时权重最旧的组 | 回收组的出场顺序 |
| `--rollout-sample-filter-path` · 凑够后再改谁进损失 | 启动 | 空 | 直接改样本上的剔除标记；不决定优势归一化 | 训练侧参与损失的条数 |
| `--rollout-all-samples-process-path` · 连被过滤的组一起后处理 | 启动 | 空 | 看见全部候选和留下的那批 | 钩子是否跑到 |
| `--custom-reward-post-process-path` · 分打完之后的塑形 | 启动 | 空 | 默认走组内归一；本章只接到闸门之后，公式在训练章 | 训练侧看到的优势量级 |

**怎么看。** 一是生成日志里第一条和收口那条的分数。二是动态过滤丢掉计数：按理由累加，零方差会带上那个分数。三是中止之后是否还有请求占着引擎。四是提交作业的进程：卡在生成收口，多半是打分或过滤在补组，不是训练卡没动。

**典型配置。** 三套能直接抄走的起法，参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 数学题、组内对比、先把无信号组扔掉 | 奖励类型用数学；组过滤用零方差那条；过采样粒度大于每步题数 | 用多生成几组换掉全对全错进训练 |
| 远端打分、HTTP 不稳 | 类型用远端并给地址；不要开整组打分 | 用按条打分换「最慢那条拖住整组」；仍要接受重试堵住槽位 |
| 长回答、过滤会丢掉很多组 | 打开部分回收；过采样略大于每步题数；需要时用带兜底的组过滤 | 用半截回缓冲、少一轮空取，换掉反复重写长尾 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 字写完很久一步还不收口 | 打分是不是远端、是否整组打分 | 远端看重试；整组改回按条 |
| 一步特别长、有效样本却很干净 | 组过滤丢掉计数是否在涨 | 过采样加大，或换带兜底的过滤少空转 |
| 引擎并发一直满、训练还没开始 | 过采样是否大于每步题数、够数后中止是否发生 | 粒度先改回等于每步题数 |
| 启动后第一次打分就炸 | 奖励类型是否为空、用户打分签名是按条还是按组 | 空类型不会在启动时报；整组打分要批处理签名 |
| 评测打不开 | 是否开了整组打分 | 评测路径拒绝整组打分 |
| 回收的半截从不出现在下一步 | 部分回收关着，或缓冲过滤把它们挤到后面 | 打开部分回收；需要旧权重优先就开陈旧排序 |

## 六、常见误区

**以为过采样会自己把多出来的组丢掉。** 多取只是取数粒度。收口靠中止。把过采样当成「多生成、自动挑最好的留下」，引擎上会长期多占一组并发。

**以为组过滤会改分数。** 它只说留还是丢。分怎么变成优势，是训练章的塑形；样本过滤改的是进不进损失，也不改归一化那一笔。

**以为用户打分按条写一份就到处能用。** 打开整组打分后，同一条路径拿到的是一批样本。按条签名在第一组就会炸。评测集还可以给样本自己另挂一条打分路径，和训练那条不是同一个旋钮。

**以为缓冲过滤就是组过滤。** 组过滤发生在刚打完分的一组上；缓冲过滤发生在下一步从回收堆里取谁。名字都叫过滤，闸门差一步。

**以为类型为空等于不打分。** 空会在真正打分时报未实现。想跳过内置规则，要给用户打分函数，或在生成里自己把分填上。
