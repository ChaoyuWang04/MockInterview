# 长尾与完全异步

这一页回答一件事:同步一步要等最慢那条轨迹写完,完全异步把生成换成后台工人,在飞轨迹跨步保温,中止的组回到缓冲而不进训练。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

一批题目里,短回答早早就写完了,长尾还在往下吐。**默认同步生成里,这一步什么时候收口,由还没写完的那几条说了算。** 卡还整片占着,上面只剩零星几条在解码,并行度塌下来,算力空转。多轮 agent、工具调用、长思维链最容易把这条尾巴拉长:不是并发不够,是某一条自己的长度。

训练侧要的是完整的一批。循环仍然是「生成一批、再训练一批」两句阻塞调用,少一组就开不了算。所以空等落在生成收口上:工人已经闲了,循环还在等最慢那条交差。

把收口从「这一步发出去的都写完」改成「够一批就拿走」,空等立刻小了。代价是拿走的样本可能跨过一次换权重,中止的组也不能混进训练。

## 二、解法

不换循环,换生成函数。入口还是仓库根那份训练脚本,改的是生成函数路径。后台工人跨步常驻,循环骨架不动。

**默认同步是一步一池。** 这一步从数据源拿出若干组,并发写到够数为止,剩下没写完的中止,中止的组可以退回缓冲。下一步再从零起一批。长尾被付在这一步的墙上:够数之前,最慢那条还在写,训练侧一个字都干不了。

**完全异步是一个跨步不散的工人。** 第一次生成时起一条后台线程,里面跑事件循环;之后每一步复用同一个工人,完成队列因此是热的。工人按引擎并发上限维持在飞组数,每组仍走默认的「一组生成再打分」,每条样本怎么跟服务器说话可以整段换成用户函数,那是用户生成函数那一章的事。完成队列故意不设容量上限,反压写在循环里:完成的组已经攒满一个并发池,就先不再取新题,避免有界队列把事件循环堵死。

**循环这一步只从完成队列里舀。** 舀够这一步要的组数就返回,多出来的留着给下一步。组按样本编号排好再交给训练,保证同一步里顺序稳定。队列空了就短睡再问,大约每 30 秒打一行已收、已丢、队列剩余。

**中止的组不进训练。** 工人自己不听上层的暂停和换权重信号,每一条在飞生成自己短路,把状态标成中止。工人只做一件它自己的事:整组退回数据缓冲,下一步换完权重再捡起来。当前这一版没有把中止轨迹从断点接着写,退回去等于重开。动态过滤若开着,被拒的组不计入这一步要的组数,从热队列里再补,算法本身是过滤那一章的事。

工人停掉挂在进程退出上。评测模式直接拒绝:常驻工人和「评一轮就停」拧不到一起。

## 三、代价

**第一笔是样本会旧。** 工人跨步保温,完成队列里可能躺着上一步权重写出来的组。陈旧度按权重版本算,新鲜样本年龄记成 1,只上报均值和最大值,没有「超了就丢掉或卡住」的门禁。旧到什么程度,要自己看指标。

**第二笔是中止等于重开。** 退回缓冲保住了题目,没保住已经吐出的 token。长尾被切掉的那一段算力作废,下一步再付一遍。把中止当成断点续写,会对不上实现。

**第三笔是循环仍等整批。** 工人在后台跑,训练侧照样要凑齐这一步的组数才开训。队列一时舀不满,循环就短睡空转。完全异步消的是「最慢那条拖住整片卡」,不是「训练侧随到随训」。

**第四笔是评测和数据源有前提。** 评测函数路径若没单独指定,会跟着生成函数走,一评就炸。工人断言必须用全局数据集;关掉之后这条路径起不来。完成队列无界,反压靠「池子满了先别取新题」——训练侧若迟迟不舀,队列会在内存里堆着已经打完分的组。

## 四、和同类大厂框架不一样的地方

横向只拿字节的 verl 来衬 slime 自己把长尾从同步收口里拆开的那一笔,不是评哪家更好。

| 比什么 | slime | verl |
|---|---|---|
| 换哪一层 | 换生成函数,循环仍是取一批再训 | 换训练器档位,生成侧接口可以不动 |
| 训练侧等不等整批 | 等够这一步的组数才开训 | 分卡异步可把一批切成多次本地更新,凑够一份就训 |
| 长尾怎么处理 | 后台工人跨步保温;中止组回缓冲、当前不从断点续写 | 共卡异步可当场中断、下一步从已写出的 token 接着写 |
| 样本最多能旧多少 | 只报年龄,没有按版本丢掉或等待的门禁 | 默认最多跨 8 个版本,超了可丢可等,也能整道关掉 |
| 完成侧怎么刹住 | 完成队列无界,池子满了先不取新题 | 缓冲按太旧、无信号、失败淘汰整组,再精确补同样多的新题 |

slime 拿「循环一行不动、工人跨步保温」换掉同步长尾,同时不设版本门禁——没有门禁参数可配错,旧到什么程度要靠观测自己盯。verl 把提前量和陈旧上限拆开,付的是旋钮和档位。两边都不是第二套训练循环。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。** 启动方式是跑仓库根的训练脚本。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--rollout-function-path` · 生成函数 | 启动 | `slime.rollout.sglang_rollout.generate_rollout` | 换成 `slime.rollout.fully_async_rollout.generate_rollout_fully_async` 才走后台工人;循环骨架不变 | 生成管理器启动日志里导入的函数路径 |
| `--eval-function-path` · 评测生成函数 | 启动 | 空则抄生成函数路径 | 完全异步必须单独指回默认同步生成,否则评测直接报错 | 评测是否出现「不支持 evaluation」 |
| `--sglang-server-concurrency` · 单引擎并发上限 | 启动 | 512 | 工人在飞组数 = 它 × 引擎数 ÷ 每题几条回答,至少为 1;调大则队列更热、样本更可能跨步 | 工人启动日志;完成队列深度 |
| `--rollout-batch-size` · 每步舀多少组 | 启动 | 必填 | 只决定这一步从完成队列舀多少;多出来的留给下一步 | `fully-async rollout` 日志里的 target 与 collected |
| `--n-samples-per-prompt` · 每题几条回答 | 启动 | 1 | 参与在飞组数的除法;组长度必须对得上,中止退回时也按这个长度断言 | 缓冲追加失败的断言 |
| `--buffer-sort-by-staleness` · 缓冲先取最旧 | 启动 | 关 | 开:续跑时先捡生成 token 权重版本最老的组;显式缓冲过滤函数优先于它 | 缓冲弹出顺序 |
| `--buffer-filter-path` · 自定义缓冲过滤 | 启动 | 空 | 设了就覆盖「先取最旧」 | 数据源构造时加载的函数 |
| `--disable-rollout-global-dataset` · 关掉全局数据集 | 启动 | 默认用全局数据集 | 加上后完全异步断言失败,起不来 | 断言信息 |
| `--dynamic-sampling-filter-path` · 动态过滤 | 启动 | 空 | 开了则拒收的组不计入本步组数,从热队列再补;过滤算法见后一章 | `rollout/dynamic_filter/*` |

**怎么看。** 一是提交作业的进程:循环仍堵在「要这一批生成结果」那次远端调用上,不是另一套入口。二是生成管理器日志:`starting fully-async rollout worker`;每步 `target=`、`queue_warm=`、结束时的 `kept` / `dropped` / `queue_left`;卡住时每 30 秒一行 `collected`。三是陈旧度:路径名里带 `fully_async` 才算指标,看 `rollout/staleness/mean`、`max`、`unknown_count`。四是中止:完成队列里不该出现中止组,它们应回到缓冲长度里。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 回答长度均匀、一步里没有明显长尾 | 保持默认生成函数 | 用「每条都出自刚推过的权重」换掉异步那笔陈旧 |
| 多轮 agent / 长思维链,同步一步被最慢那条拖死 | 生成函数换成完全异步;若还要评测,评测函数指回默认同步生成 | 用跨步陈旧和中止重开,换掉长尾空转 |
| 缓冲里积了跨步组,希望先消化旧的 | 打开按陈旧度先取;不要同时塞自定义缓冲过滤 | 用「先续最旧」换一点顺序上的确定性,不改变有没有门禁 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 一步墙钟仍跟最慢那条绑在一起 | 生成函数是不是还停在默认 | 没换路径就是同步收口,工人不会起 |
| 换了路径一评测就报错 | 评测函数路径有没有单独指定 | 空则抄生成函数,完全异步拒绝评测模式 |
| 启动直接断言失败 | 全局数据集是不是被关掉了 | 必须开着 |
| 训练侧样本明显旧、曲线发飘 | `rollout/staleness/max` | 没有门禁,只能降并发或先取最旧;不要去找丢掉超龄组的开关 |
| 完成队列一直涨、训练迟迟不开 | 这一步要的组数、过滤拒收是否把有效组舀不满 | 过滤开着时被拒的不计数;队列无界会堆已经打完分的组 |
| 中止组出现在训练批里 | 工人回调有没有把中止组 `add_samples` 回去 | 中止只回缓冲,不进完成队列 |

## 六、常见误区

**以为仓库根还有一份异步训练脚本。** 没有。换的是生成函数路径,循环还是那一份。去根目录找另一份入口,是第一反应最容易错的地方。

**以为完全异步之后训练也不等整批。** 工人跨步保温,循环仍要舀够这一步的组数才开训。把「生成不停」读成「训练随到随取」,会低估一步墙钟。

**以为中止的组会进训练、或会从断点续写。** 工人把中止组退回缓冲,完成队列里没有它们。退回去当前是重开,不是把已写出的 token 留下。

**以为陈旧度有一道超龄闸。** 年龄只上报。打开「先取最旧」只改缓冲弹出顺序,不会丢掉超龄组,也不会让取样停下来等。

**以为评测会跟着完全异步一起跑。** 评测函数路径默认抄生成函数。不单独指回去,评测第一次调用就会被拒绝。

**以为完成队列有界、满了会堵住工人。** 队列故意无界,堵住的是「再取新题」。训练侧不舀,内存里堆的是已经打完分的组,不是事件循环被 `put` 卡死。
