# SGLang 原生部署

这一页回答一件事:生成侧怎么把推理引擎起成一组可被路由的 HTTP 服务,以及引擎参数怎么原样透过去。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

生成要吃独立的调度、前缀缓存和 HTTP,训练要吃自己的并行。把引擎当库函数塞进训练进程,两边都施展不开。反过来做成「多引擎最低公因子」,路由粘性、前缀缓存、预填充与解码分卡这些 SGLang 自己的能力会被抹平。

多轮 agent 把这个问题放大。一条轨迹下一轮的输入取决于上一轮,必须尽量打回同一台,前缀缓存才命中得上。若预填充和解码还绑在同一组卡上,decode 吞吐被 prefill 挤掉,长上下文的显存也分不开。坏的是**生成时延和卡利用率**,不是训练 loss 写错。

所以真问题是:服务必须按 SGLang 的拓扑起,参数必须原样进引擎,任务差别不能逼你再包一层后端。

## 二、解法

**只接这一家引擎,起成服务器,参数加前缀透传。** 听起来少了选择,换来的是路由、缓存、分离式部署都还能用。

入口先看要不要接外面已经起好的服务:给了地址就不占本地 GPU,只拉信息、登记进路由器。否则解析配置:一份 YAML、一条旧的预填充台数、或默认「一体组」。多模型时,从第二个模型起强制新开路由器,每个模型自己一台。

拓扑是组,不是引擎内部的调度器。默认一组 regular,预填充和解码在同一批卡上。打开分离,就变成预填充组加解码组,路由器同时开分离模式。再狠一档是编码器先行:先把编码器起完、拿到地址,再注入预填充或一体组,编码器自己不登记进路由器。占位组只占卡位、不起进程。

引擎进程起来之后,节点 0 才对外露出地址并登记;多节点里其余进程只参与计算。推测解码这类引擎能力走同一条前缀透传,slime 不另立开关。完全异步和中止请求是后几章的主场,起服务这一侧只保证路由器把健康检查让给生成侧的监视器。

## 三、代价

**第一笔是多一个路由器进程。** 请求先打路由器再打引擎。slime 起路由器时会关掉熔断,并把健康检查交给自己的监视器,避免瞬时 RDMA 超时把解码工人判死。路由器挂了,整组生成一起停。

**第二笔是配置必须自洽。** YAML 里各组卡数之和必须等于生成侧总卡数;YAML、旧的预填充台数、外部地址三者两两不能同时开。对不上就在校验或起组时直接断言,不会默默改拓扑。

**第三笔是外部引擎这条路变窄。** 不占本地卡,也就没有本地的睡醒、恢复、让出显存。引擎已经在别处,slime 只当客户端登记。

**第四笔是透传本身。** 前缀过去的字段原样进 ServerArgs,拼错、版本对不上,炸在引擎启动日志里,slime 不会替你翻译。组级覆盖比命令行后写,覆盖错了也是引擎先爆。

## 四、和同类大厂框架不一样的地方

对照只取大厂在大规模训练里真用的框架;这一页主对 verl。重点在 slime 自己怎么起服务,不评哪家更好。

| 比什么 | slime | verl |
|---|---|---|
| 接几家推理引擎 | 故意只接 SGLang,生成后端目录就这一家 | 生成侧有多家后端目录,副本、服务、路由要做成后端无关 |
| 参数怎么进引擎 | 引擎参数加前缀透传,组级 YAML 覆盖最后生效 | 公共配置加各后端自己的透传字典 |
| 服务怎么起 | 先分支外部引擎,再解析配置走分离或默认组 | 副本数由训练卡数除以三个并行度得出,不是单独配的台数 |
| 路由粒度 | 每个模型一台路由器,从第二个模型起强制新开 | 一层路由管整个服务池,粘性与最少在途是池内规则 |
| 分离式部署 | 预填充 / 解码分离和编码器先行都是同一套组配置 | 分离是副本内部拆组,且限制更多 |

slime 拿「不包第二家引擎」换回了 SGLang 的路由和分卡。这是一笔交易:换引擎要改这一层,不是改一个后端名。和 verl 比,少的是那层后端无关的副本状态机。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。**

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--rollout-num-gpus` · 生成侧总卡数 | 启动 | 空;共卡时若仍空则等于训练卡数 | 0:只起路由器不起本地引擎;必须和 YAML 里各组卡数之和一致 | 起组时的断言 |
| `--rollout-num-gpus-per-engine` · 每台引擎几张卡 | 启动 | 1 | 等于张量并行;开流水线时必须能被流水线度数整除 | 引擎启动参数里的并行度 |
| `--sglang-config` · 多组 / 多模型 YAML | 启动 | 空 | 有则按文件起组;不能和预填充台数、外部地址同时开 | 日志里每个模型的路由器 |
| `--prefill-num-servers` · 旧的分离写法 | 启动 | 空 | 有则拆成预填充组加解码组;预填充卡数 = 台数 × 每台卡数,其余给解码 | 路由器是否开分离 |
| `--rollout-external-engine-addrs` · 已有服务地址 | 启动 | 空 | 有则走外部引擎,不占本地 GPU | 探测到的 worker 类型清单 |
| `--sglang-router-ip` / `--sglang-router-port` · 复用已有路由器 | 启动 | 空则本机新开 | 第一个模型可复用;从第二个模型起仍强制新开 | 路由器地址日志 |
| `--sglang-router-request-timeout-secs` · 打路由器的超时 | 启动 | 14400 | 大了长轨迹不容易断,挂了发现得更晚 | 路由器参数日志 |
| `--sglang-server-concurrency` · 单服务并发 | 启动 | 512 | 大了排队短、显存峰值高 | 服务侧并发 |
| `--sglang-dp-size` · 数据并行 | 启动 | 引擎默认 | 大于 1 时必须同时打开数据并行注意力 | 校验断言 |
| `--sglang-pp-size` · 流水线并行 | 启动 | 1 | 大于 1 时每台引擎卡数必须能整除,张量并行被除出来 | 校验断言 |
| `--colocate` · 训练与生成共卡 | 启动 | 关 | 开:生成侧卡位从放置组开头算,不往后错开 | 放置与显存那一章 |
| 其余 `--sglang-*` · 引擎原样字段 | 启动 | 跟所装 SGLang | 透传进 ServerArgs;YAML 的 overrides 最后覆盖 | 引擎启动日志 |

**怎么看。** 一是提交作业的进程:卡在起服务还是第一次生成。二是「Launch router」那一行:地址、Prometheus 端口、是否开分离。三是引擎「Launch HttpServerEngineAdapter」或「Use external SGLang engine」。四是多模型时 `sglang_model_routers` 是否每个名字一台。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 单机先把生成服务跑通 | `--rollout-num-gpus` 等于可见卡数;不要 YAML、不要分离、不要外部地址 | 用一体组换最少旋钮,确认路由器和引擎都能登记 |
| 长上下文、希望预填充与解码分卡 | `--prefill-num-servers` 按预填充台数设,或改用 `--sglang-config` 写两组 | 用一份解码卡换 prefill 不再挤 decode;路由器必须开分离 |
| 引擎已经在另一组机器上 | `--rollout-external-engine-addrs` 填 `host:port`;不要再配 YAML 或预填充台数 | 用「本地不起引擎」换跨机房复用;睡醒和恢复都没有 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动卡在起路由器 | 进程 3 秒后是否还活着 | 断言失败说明路由器没起来,先看端口和依赖 |
| YAML 一起就断言 | 各组卡数之和是否等于 `--rollout-num-gpus` | 对不上不会自动改总数 |
| 同时给了 YAML 和预填充台数 | 启动校验 | 二者互斥,分离写进 YAML 的组类型 |
| 外部地址和 YAML 一起开 | 启动校验 | 外部路径不解析 YAML |
| 数据并行大于 1 直接退出 | 是否打开数据并行注意力 | 没开就起不来 |
| 多模型时请求打到错的模型 | 是不是还在用第一个模型的路由器 | 从第二个模型起是另一台 |
| 编码器起来了但路由里没有 | 编码器本来就不登记 | 地址是注入预填充 / 一体组,不是进路由器 |
| 引擎启动参数和命令行不一致 | YAML 的 overrides 是否后写覆盖 | 组级覆盖优先于前缀透传 |

## 六、常见误区

**以为仓库里还有第二家推理后端。** 生成后端目录只有 SGLang 这一家,全树没有另一家引擎的后端包。人们会这么以为,是因为同类框架把「可换引擎」当成默认。在 slime 里换引擎不是改一个名字。

**以为 YAML 和旧的预填充台数可以叠着用。** 解析配置时三条路互斥:YAML、预填充台数、默认一体组;外部地址更是在入口就分支走掉。叠着用会在校验阶段被拒,不是后者覆盖前者。

**以为编码器也会出现在路由器的工人列表里。** 登记函数对编码器直接返回。人们会这么以为,是因为其他组都是起完就登记。编码器的地址只进后续组的覆盖项。

**以为推测解码是 slime 的一章。** 它是引擎能力,这里只做前缀透传。去 slime 里找草稿模型的调度实现,找错仓库。

**以为副本数会像另一家那样被除出来。** slime 的台数来自总卡数除以每台卡数,再按组类型切开;没有「训练卡数 ÷ 三个并行度 = 副本数」那条公式。按那条公式估路由器池宽度,会估错。
