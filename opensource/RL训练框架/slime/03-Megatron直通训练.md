# Megatron 直通训练

这一页回答一件事:训练步为什么不包一层引擎,而是直接就是 Megatron 上的 actor;损失、优势、蒸馏和自定义钩子怎么挂在这一步上。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

后训练要换训练框架时,坏的通常不是吞吐,是**循环本身**。并行切法、谁手上有输出、优化器怎么建、检查点怎么写,每家都不一样。把这些写进循环,换一次框架就要连循环一起改;包一层「谁都能接」的引擎,循环是保住了,可引擎要跟着上游 fork 跑——上游一改并行或优化器,壳就裂。

slime 这条路上训练侧只认一家。问题因此变成:既然不换,还要不要再包一层?包了,跟 Megatron 的成本转嫁到适配层;不包,损失、优势、蒸馏就必须直接挂在这一家的训练步上,挂错位置,坏的是**可改性**——换损失像换框架一样重写循环。

## 二、解法

不换后端,也不再包一层引擎。训练进程就是 Megatron 的 actor:初始化走 Megatron 自己的并行与优化器,一步训练走它自己的前向反向。slime 只在这一步前后插钩子。

**参数原样进来。** 启动时先用 Megatron 的解析器把并行、优化器、检查点这些字段收进来,再并上 slime 自己的字段。训练后端这个开关目前只有一档,仓库里也没有第二套训练后端目录。

**损失不走注册表。** 切好的样本进训练步之后,先按配置算优势(需要时先让价值网络算出价值),再按损失类型分发:策略损失、监督微调损失、价值损失,或者一条用户给的函数路径。算法变体是这一步上的分支,不是另一套循环。

**蒸馏也挂在这一步。** 打开在线蒸馏时,要么生成侧已经把教师 logprob 写进样本,要么训练步里切到教师权重再前向一次;惩罚加在优势上,跟用哪一种优势估计正交。低精度若只是透传或挂钩子,主场在训推一致那一章。

![一次训练步就是 Megatron actor:样本引用进来后,可选地切到参考或教师做前向,再算优势、分发损失、走 Megatron 的前向反向;自定义损失和蒸馏都挂在这一步上,不另起引擎](/opensource/slime/03a-train-step-hooks.svg)

## 三、代价

三笔。

**第一笔是绑死一家。** 换训练框架等于重写训练步,没有「只换 worker」这条路。跟上 Megatron fork 是主动选择,不是暂时没做完。

**第二笔是钩子都挤在一步里。** 损失类型、优势估计、蒸馏、参考模型前向、自定义函数路径,全在同一段训练里分叉。钩子写砸了,循环帮不上忙;切错教师权重,优势就是错的。

**第三笔是 Megatron 的配置面直接露出来。** 并行度、优化器、检查点不是 slime 再包一层字段,是上游原样透传。改错一个并行开关,炸的是 Megatron 自己的校验,报错不一定长得像 slime。

## 四、和同类大厂框架不一样的地方

对照对象是 verl。它要把同一段循环接到多种并行完全不同的训练框架上,所以切在「一个微批怎么算损失」,往下外包给后端。

| 比什么 | slime | verl |
|---|---|---|
| 训练后端有几档 | 只有一档,开关的可选项也只有这一家 | 六个后端目录,靠注册表按模型类型、后端名、设备、厂商取类 |
| 这一刀切在哪 | 不切。训练步就是 Megatron actor,建模型、优化器、检查点都贴着这一家写 | 切在微批损失。往下建模型、包并行、优化器、存档全部外包 |
| 损失写在哪 | 训练步里的损失分发,没有独立算法注册表 | 微批与损失留在框架自己写的那一层 |
| 价值网络默认起不起 | 默认优势估计不会起;只有选中那一种需要它的算法才起 | 角色组装里 critic 是一等公民,能否起还看这个后端有没有注册价值模型 |
| 换框架要动什么 | 重写训练步 | 换后端类和启动命令,循环可以不动 |

slime 拿「不换、不包」换了跟上游的速度:Megatron 新能力进来,不用先改一层引擎接口。付出去的是通用性——要接另一家训练框架,没有现成的壳。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。** 作业入口仍是仓库根那份训练脚本;Megatron 原有的张量并行、流水线并行、专家并行、优化器与检查点字段走它自己的解析器,本表只列 slime 挂在训练步上的钩子。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--train-backend` · 训练后端 | 启动 | `megatron`,且可选项只有这一档 | 填别的名字会在预解析时报错 | 启动即报 |
| `--loss-type` · 损失分发 | 启动 | `policy_loss` | `sft_loss`:监督微调损失;`custom_loss`:走下面那条函数路径;价值损失由训 critic 时就地改,不在这个可选项里 | 训练日志里的损失名 |
| `--custom-loss-function-path` · 自定义损失 | 启动 | 空 | 损失类型为自定义时必须给,按路径加载 | 分发不到函数会在训练步报 |
| `--advantage-estimator` · 优势估计 | 启动 | `grpo` | `ppo` 才会起价值网络;其余几档不起 critic | 是否出现 critic 组 |
| `--disable-compute-advantages-and-returns` · 关掉优势计算 | 启动 | 默认会算 | 加上后不写优势与回报,给监督微调或自定义损失用 | 训练步是否还走优势那段 |
| `--custom-advantage-function-path` · 自定义优势 | 启动 | 空 | 设了就替换内置优势计算,仍要原地写出优势和回报 | 优势张量是否按你的函数出现 |
| `--use-kl-loss` · 把 KL 加进损失 | 启动 | 关 | 开:损失里多一项 KL,系数见下一行 | 损失分项 |
| `--kl-loss-coef` · 损失里的 KL 系数 | 启动 | 0 | 大于 0 才有这项 | 同上 |
| `--kl-coef` · 算优势前塑形奖励的 KL 系数 | 启动 | 0 | 作用在奖励上,不是损失项 | 优势尺度 |
| `--eps-clip` · 策略裁剪 | 启动 | 0.2 | 大了更新更猛 | 策略损失 |
| `--entropy-coef` · 熵系数 | 启动 | 0 | 大于 0 鼓励探索 | 熵分项 |
| `--use-opd` · 打开在线蒸馏 | 启动 | 关 | 开了必须同时指定类型 | 启动校验 |
| `--opd-type` · 教师 logprob 从哪来 | 启动 | 空 | `sglang`:生成侧教师服务写入样本;`megatron`:训练步切到教师权重前向 | 是否出现教师前向 |
| `--opd-teacher-load` · Megatron 教师检查点 | 启动 | 空 | 类型为 Megatron 时必填,且要是合法检查点目录 | 启动即报路径 |
| `--opd-kl-coef` · 蒸馏加在优势上的系数 | 启动 | 1.0 | 与优势估计正交,叠在已有优势上 | 优势是否被拉开 |
| `--ref-update-interval` · 每隔几步用 actor 覆盖参考模型 | 启动 | 空 = 不覆盖 | 设了且加载过参考权重才会备份 | 训练日志里的参考更新 |

**怎么看。** 一是启动校验:后端名、蒸馏类型、教师路径、损失类型与自定义路径是否配对。二是训练组日志:这一步有没有切到参考或教师、有没有价值网络、损失分项叫什么。三是 Megatron 自己的并行校验:并行开关配错时,报错来自上游,不一定带 slime 前缀。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 组内对比、先把训练步跑通 | 优势估计保持默认;不要开价值网络、不要开蒸馏 | 用最少的钩子换一次能算出策略损失的验证 |
| 必须上价值网络的算法 | 优势估计改成那一档需要 critic 的;不要再加一组卡,价值网络跟训练同一段放置组 | 用同一批卡上多一组进程、以及先训价值再训策略的时间,换 PPO 那条优势 |
| 在线蒸馏、教师与学生同结构 | 打开蒸馏;类型选 Megatron 并给教师检查点,或类型选生成侧教师服务 | 用一步里多一次教师前向(或生成侧多打一次教师),换叠在优势上的蒸馏信号 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动就报训练后端不认识 | 可选项是不是只写了这一家 | 基准上没有第二档,不是漏装 |
| 起了 actor 却没有 critic | 优势估计是不是那一档需要它的 | 默认不会起;不要按「有 actor 就有 critic」要卡 |
| 损失类型写成自定义却立刻失败 | 函数路径给了没有 | 分发是按类型加载路径,空路径不会有内置实现 |
| 打开蒸馏报必须指定类型 | 类型是空的 | 生成侧教师和 Megatron 教师是两条路,要显式选 |
| Megatron 类型蒸馏报检查点 | 教师路径是否带合法的步数文件 | 要的是 Megatron 检查点目录,不是 HuggingFace 权重目录 |
| 监督微调仍在算优势 | 优势计算有没有关掉 | 自定义损失和监督微调通常应关掉 |
| 并行开关改了但报错不像 slime | 看是不是 Megatron 自己的校验 | 透传字段由上游负责,先对并行组合 |

## 六、常见误区

**以为换训练后端只要改一个开关。** 开关的可选项只有一档。填别的名字过不了解析,仓库里也没有另一套训练目录可以接上。想换框架,要动的是训练步本身。

**以为默认会起价值网络。** 价值网络跟的是优势估计是不是那一种需要它的算法,启动后才会被写成是否使用 critic。按对称角色估算卡数,会多要一组。

**以为蒸馏是另一种优势估计。** 它叠在已有优势上。只改优势估计不会打开教师前向;打开蒸馏却不给类型或教师路径,会在启动校验失败,而不是默默关掉。

**以为自定义损失是算法注册表里的一条。** 没有注册表。类型指到自定义时,就是按路径加载一个函数,塞进 Megatron 训练步的损失分发。路径写错,失败点在训练步,不在启动选算法。

**把 Megatron 的并行字段当成 slime 再包的一层。** 它们走上游解析器,默认还会打开分布式优化器、按是否半精度决定是否用 BF16。低精度怎么和生成侧对齐,是另一章的事;这里改错,先对 Megatron 的报错。
