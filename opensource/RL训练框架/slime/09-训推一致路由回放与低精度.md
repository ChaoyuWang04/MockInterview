# 训推一致、路由回放与低精度

这一页回答一件事:同一段文字在生成侧和训练侧概率对不上时,怎么用路由回放、权重核对和低精度把比值拉回来。说法都在源码基准 `5bae5bb792`(tag `v0.3.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

强化学习每一步都要拿「生成时这条回答有多像」去除「训练时再看一遍有多像」。两侧不是同一套算子、不一定同一套精度,MoE 还可能选到不同专家。**概率对不上,重要性比值就失真**:裁剪看起来在干活,更新方向已经不是当前策略该走的方向。这件事常常不崩,曲线慢慢不对。

MoE 上更狠。生成时记下的专家集合,训练时若按自己的打分再选一遍,集合可以相同、列顺序却不同;低精度累加顺着列走,专家还没真正分叉,数值已经漂了。专家对不齐,训练会发散。

权重刚推完、生成侧其实还是旧参数,也会装成「同一份模型」。所以真问题不是再讲一遍损失怎么写,而是:同一段文字两侧概率对不上时,路由怎么录再放、推完怎么核对、低精度怎么插拔。

## 二、解法

三件套,各治一段。默认仍是训练侧重算旧策略概率;生成侧顺带给出的 logprob 要显式打开才进比值。

**第一件是路由回放。** 训练侧自己前向时,也可以把专家下标录下来,反向再按同一列取分。更狠的一档是生成侧把整条轨迹的专家张量带回来:形状是 token 行 × 层 × 每层取几个专家。训练步先按微批填进回放器,算 logprob 时正向弹出,真正训练时反向再弹一遍,弹完必须刚好用光。参考模型和教师那两次前向故意穿过去,不吃这份记录。价值网络那一组根本不打开回放。生成侧这一档会让引擎把专家选择写进回包;张量太大就落到共享盘,训练进程按微批预取,中止的样本必须把路由留在身上,不能写进这一步马上会删的目录。

**第二件是推完核对。** 生成管理器刚起来时,对每台引擎先拍一张快照、再把对照张量清掉。循环里第一次把训练权重推过去之后,再比一次。比的是「推完了两边一不一样」,不是怎么选路——选路是权重通路那一章。核对默认关。

**第三件是低精度怎么插。** 大规模 MoE 文档推荐的生产路径是训练侧保持 BF16,生成侧用带量化配置的 HuggingFace 检查点。推权重时,slime 读这份配置,把更新后的 BF16 再量化再送走,不重写引擎内部的数值核。生成侧 KV cache 用哪种低精度,加前缀透给引擎。训练侧真要走 FP8,走的是 Megatron 自己的格式和配方开关,Ray actor 默认会把块缩放用的环境变量写成开;参数收集那一档能省显存,但和常用的 CPU 优化器卸数拧着,文档标成实验。

捕获全是零的层会拒,避免整层都按专家 0 重放。整行缺失在限额内会警告并按专家 0 放;限额取 64 行与总行数除以 100 里较大的那个。流水线各段没把互斥捕获拼齐,最容易踩这一条。

## 三、代价

**第一笔是默认多一次训练侧前向。** 不用生成侧 logprob 时,旧策略概率在训练卡上重算。打开生成侧路由回放之后,这一次前向还要按录好的列取分,不能顺手把同一次前向的概率拿去当损失里的旧策略——条件更严。打开失配指标时,即使用了生成侧 logprob,训练引擎仍会再前向一次专门算指标。

**第二笔是路由张量的内存和盘。** 生成侧回放把专家选择从推理服务带到训练进程。不落盘就堆在主机内存;落盘就要所有生成节点和训练节点都能看见同一目录,还要按微批预取。完全异步再叠加落盘时,在飞样本会跨步,必须显式留下文件,否则下一步目录被清掉,续跑没有路由。

**第三笔是低精度把「看起来同一份权重」拆成两套数。** BF16 训、FP8 生成,推的时候多一次量化,比值对的是量化后的生成侧。两边都上 FP8,文档说有时能压低失配、拉高吞吐,但优化器和检查点仍有限制:保存时还要反量化回 BF16。把训练核改成和生成核逐比特一致,是对齐补丁和确定性那条窄路,不是默认作业。

**第四笔是核对只抽一次。** 它发生在作业开头那次推权重之后。后面每步仍按权重通路走,不会每步再比。开了核对却在引擎里找不到对照接口,失败点在 HTTP,不在选路工厂。

## 四、和同类大厂框架不一样的地方

横向只拿字节的 verl 来衬 slime 自己把概率、路由、精度拆开修的那一笔,不是评哪家更好。verl 成稿把「生成不停」写成缓冲与陈旧,训推 logprob 对不齐明确划给别章;本页只核两边仓库里能对上的格子。

| 比什么 | slime | verl |
|---|---|---|
| 默认旧策略概率从哪来 | 训练侧重算;生成侧 logprob 要显式打开才进比值 | 同步档训练侧重算;完全异步档成稿写明默认将就生成侧 logprob,对齐归别章 |
| MoE 专家怎么对齐 | 训练侧自录自放,或生成侧把专家张量带回来按列重放 | 本页未核到对等的路由回放入口 |
| 推完怎么验是不是同一份 | 作业开头对引擎拍快照,第一次推完再比 | 本页未核到对等的引擎对照接口 |
| 低精度怎么接到生成侧 | 量化配置跟 HuggingFace 检查点走,推权重时再量化;KV 低精度加前缀透传 | 文档把只量化生成、两端都上 FP8、全 BF16 写成失配从高到低的三档,实现细节在它自己的低精度页 |

slime 拿「默认重算、路由可录可放、量化跟检查点走」换的是:损失公式不用为精度分叉再写一套。这是一笔交易——专家张量没带回来或量化配置和生成侧检查点对不上,比值照样歪,循环帮不上忙。

## 五、调参与观测

**这一页的参数全是启动配置,改了要重新拉起整个作业。** 量化跟哪份检查点走、路由张量落哪块盘,都在启动时钉死。

| 参数 · 一句话中文说明 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `--use-rollout-logprobs` · 比值用生成侧 logprob | 启动 | 关 | 开:不再用训练侧重算的旧策略概率;不能和离策重要性采样同时开 | 损失里旧策略从哪一列取 |
| `--use-routing-replay` · 训练侧自录专家再放 | 启动 | 关 | 开:actor 进程带上环境变量,前向录、反向放;价值网络组不会开 | actor 环境变量;回放未用光会在训练步炸 |
| `--use-rollout-routing-replay` · 用生成侧带来的专家 | 启动 | 关 | 开:顺带打开上一行;引擎回包带专家选择;样本里必须有路由张量 | 引擎是否打开返回专家;训练步缺字段会报 |
| `--rollout-routed-experts-store-dir` · 专家张量落盘目录 | 启动 | 空 | 落盘钩子必填;所有相关节点要能看见 | 目录下按步号分子目录 |
| `--routing-replay-prefetch-microbatches` · 落盘预取几个微批 | 启动 | 1 | 不得为负;大了主机内存更高、训练线程少同步读盘 | 训练日志里的预取剖析 |
| `--keep-rollout-routed-experts-files` · 训完不删落盘 | 启动 | 关 | 开:这一步目录留下;完全异步加落盘时必须开 | 目录是否在步末被删 |
| `--get-mismatch-metrics` · 算训推失配指标 | 启动 | 关 | 开:必须同时给自定义重要性函数路径;即使用了生成侧 logprob 仍会多一次训练前向 | 指标日志;启动校验 |
| `--check-weight-update-equal` · 第一次推完核对权重 | 启动 | 关 | 开:管理器起来先快照再清空,循环第一次推完再比 | 引擎对照接口的返回 |
| `--hf-checkpoint` · 生成侧 HuggingFace 检查点 | 启动 | 空 | 里面的量化配置决定推权重时怎么再量化 | 检查点里的量化字段;生成侧精度 |
| `--fp8-format` · 训练侧 FP8 格式 | 启动,Megatron 透传 | 空 | 有则 TransformerEngine 层在 FP8 上下文里建;文档示例为 `e4m3` | 训练侧是否走 FP8 配方 |
| `--fp8-recipe` · 训练侧 FP8 配方 | 启动,Megatron 透传 | 空 | 文档示例为块量化;不重写 GEMM 内部 | 同上 |
| `--fp8-param-gather` · 训练权重以 FP8 存 | 启动,Megatron 透传 | 关 | 开:省显存,但和常用 CPU 优化器卸数冲突 | 启动或优化器报错 |
| `--sglang-kv-cache-dtype` · 生成侧 KV 精度 | 启动,加前缀透传 | 引擎默认 | 例如 `fp8_e4m3` 只改生成侧缓存容量,不动训练精度 | 引擎启动参数 |

**怎么看。** 一是损失里旧策略概率的来源:默认应是训练侧重算那一列;打开生成侧 logprob 才换成回包。二是路由:回放未按「正向一次、反向一次」用光会在训练步抛错;专家张量形状对不上层数和每层取几个,会在校验里拒。三是核对:只出现在作业开头那次推权重前后。四是精度:生成侧是否真吃到量化后的权重,看出去的检查点配置,不是训练侧保存的 BF16 目录。

**典型配置。** 三套能直接抄走的起法,参数名和默认值都来自上表。组合与推荐值是按语义推的起点,不是实测最优。

| 什么场景 | 在默认起法上加什么 | 拿什么换什么 |
|---|---|---|
| 稠密模型、先确认推完是同一份 | 打开第一次推完核对;不要开路由回放 | 用作业开头一次对照,换掉「权重通路走通了但引擎还是旧参数」这种哑巴错 |
| 大规模 MoE,生成和训练专家对不齐 | 打开生成侧路由回放,配上落盘目录;完全异步还要留下文件 | 用专家张量和预取内存,换掉列顺序不同导致的低精度累加漂移 |
| 训练要稳、生成要省显存 | HuggingFace 检查点指向带量化配置的那份,训练检查点仍走 BF16;需要时长上下文再给 KV 低精度 | 用推权重时多一次量化,换生成侧显存和带宽 |

| 症状 | 先查 | 然后 |
|---|---|---|
| 奖励还在涨,裁剪比例悄悄上升 | 有没有改用生成侧 logprob,两侧精度是否同一档 | 默认应重算;量化配置必须和生成侧检查点一致 |
| 训练步报路由回放没有用光 | 参考或教师前向是否误吃了记录、微批数是否变了 | 那两次前向应穿过去;弹完必须刚好 |
| 报专家张量全是零 | 流水线各段有没有把互斥捕获拼齐 | 拒的是整层专家 0,不是默默训下去 |
| 完全异步加落盘启动失败 | 有没有留下文件 | 在飞样本跨步,目录会被下一步清掉 |
| 打开失配指标立刻失败 | 自定义重要性函数路径给了没有 | 指标不是内置公式,空路径过不了解析 |
| 打开参数收集的 FP8 存法报优化器 | 是不是还在走 CPU 卸数 | 文档写明这两条拧着,不是漏装 |
| 核对打开但引擎报不认识接口 | 引擎是否暴露对照动作 | 失败在 HTTP,不是选路工厂 |

## 六、常见误区

**以为默认比值用的就是生成时那份 logprob。** 人们会这么以为,是因为回包里明明有。实际上默认仍在训练侧重算;生成侧那一份要显式打开。打开之后还不能和离策重要性采样同时设。

**以为权重核对就是选哪条通路。** 核对只问推完了两边一不一样。共卡走张量还是分卡走集合通信,是权重通路那一章;把核对开关当成选路,会在工厂里找不到对应分支。

**以为切词漂移也归这一章。** 黑盒 harness 事后再切一遍词,对不上的是 token 串,不是专家列,也不是精度。那是可插拔生成那一章的事。

**以为打开训练侧 FP8 就是推荐的生产路径。** 文档把 BF16 训加 FP8 生成写成稳定档;两端都上 FP8 标成实验。按「精度一致一定更稳」一上来就开训练侧 FP8,会先撞优化器和检查点限制。

**以为价值网络也会回放专家。** 注释写明不能给 critic 做路由回放。按对称角色给 critic 也开环境变量,代码根本不会写进去。
