源码基准:官方仓库 <https://github.com/verl-project/verl-omni>,分支 `main`,commit `b708218d5b62134ea75945a348d87f54c0c2fea2`,最近的发布 tag `v0.2.0`,核对日期 2026-09-20。全篇的「当前」「默认」都指这组基准;标了「官方数字」的来自官方文档,不是实测。它把 verl 钉死在 commit `fefb0802` 上(`pyproject.toml` 里的依赖声明),本页凡是说到 verl 的实现,指的都是那个版本。

## 一、VeRL-Omni 是什么

**VeRL-Omni** 是多模态生成模型的强化学习后训练框架,建在 verl 之上,起源于 verl 仓库里的多模态生成 RL 工作,后来独立成仓。

它要解决的问题和文本 RL 不是一回事。一次文本生成是一条 token 序列:动作是离散的,每一步的对数概率由模型直接给出,训练时重算一遍就行。而一次图像或视频生成是一条**去噪轨迹**——从纯噪声出发,一步一步把噪声减掉,最后解码成图。动作空间是连续的,每一步的对数概率要按噪声预测自己算出来;训练用的步数可以远少于推理用的步数;奖励既可以来自规则或外部服务,也可以来自看图打分的模型;复杂的视觉打分可能成为瓶颈。项目还覆盖 BAGEL、HunyuanImage 等统一理解与生成模型,以及另一类全模态模型,它本身是自回归的,却要吃图像、音频、视频的编码器输出。这几类模型的输入输出形态、算力特征和瓶颈都不一样,塞进同一套文本 RL 框架,批怎么凑、显存怎么算、哪一段该异步,全都对不上。

VeRL-Omni 的回答是**只换上面那一层,不重写下面那一层**。单控制器编程模型、分发协议、资源池与放置、权重通路、检查点引擎、回放缓冲,全部沿用 verl;它自己拥有的是扩散训练循环、模型接入层、扩散生成的服务化、多奖励打分,以及扩散特有的数值一致性手段。

一句话定位:**VeRL-Omni 拥有模型接入层、扩散训练循环、扩散 Rollout 与多奖励服务,把单控制器、分发协议、放置与权重通路交给 verl。**

顶层入口(包 `verl_omni`):

- 扩散训练的默认入口:按算法族分岔成策略梯度与直接偏好两条训练器线,是今天绝大多数配方走的路。
- 扩散训练的 V1 入口:另一个入口文件,用队列搬运轨迹,支持同步与分卡异步。**它不是默认**——开关默认关着,使用时要同时选择这个入口并打开开关;这一点和 verl 那边正好相反,verl 的 V1 已经是默认路径。
- 全模态训练入口:给自回归的全模态模型用,在线路径复用 verl 的 V1 训练能力,离线直接偏好另有训练器。
- 离线权重合并:训练结束后把分片权重合回能加载的形态。

代码组织上,主体全部在 `verl_omni/`(2404 KB、243 个文件)。从体量看,**模型接入层独占 32%**(781 KB,17 个模型与算法组合的包),训练循环与配置 25%,数据与奖励打分 20%,worker 与引擎层 15%。另有三块不解读的:测试(2038 KB)、文档(1188 KB,是本解读的主张来源)、容器与持续集成。

和 verl 的耦合有多深,可以量一下:`verl_omni/` 下 215 个 Python 文件,其中 85 个从 verl 导入东西,导入行约 328 行。**最能说明分工的一条**:全模态在线路径复用 verl 的 V1 训练能力,而扩散训练器的基类是本仓库自己写的。

## 二、六件招牌:先建立全局图景

```text
           VeRL-Omni:扩散与全模态模型的 RL 后训练
                              │ 组织并调用
        ┌─────────────────────┴─────────────────────┐
        │ [6] 扩散训练循环       全模态训练路径       │
        └─────────────────────┬─────────────────────┘
                              │ 使用相应组件
        ┌─────────────────────┴─────────────────────┐
        │ [1] 模型接入层:Rollout / 训练适配器        │
        │ [2] Rollout:批处理、提示词编码缓存         │
        │ [3] 训练引擎:不同能力的可选后端            │
        │ [4] 奖励服务:分数合成、条件性流式打分      │
        │ [5] 训推一致性:重算与 Rollout Correction   │
        └─────────────────────┬─────────────────────┘
                              │ 依赖
        verl:控制器/worker 分发、资源池、权重通路、检查点
        外部引擎与模型库:vLLM-Omni、Diffusers、VeOmni
        注:这是组件依赖图,一步训练的时序见 01 章。
```

一句话记忆:

- **模型接入层**:扩散模型的在线训练通常需要 Rollout 和训练两侧的适配器,按架构名与算法名注册;部分包只提供一侧;这是整个仓库最大的一块。
- **扩散 Rollout**:生成交给外部的全模态推理引擎,本仓库负责把去噪轨迹要的东西要回来;批处理有两种互斥的做法,提示词编码可以跨请求复用。
- **训练引擎**:两条训练后端可选,并行方式可组合;两边复用模型适配契约,但支持的模型、算法与并行能力不同。
- **奖励**:支持多个打分模型及分数合成,也支持符合条件的样本级流式打分与独立资源池;命名多奖励模型当前不走流式路径。
- **数值一致性**:Rollout 与训练侧的 log-prob 可能因执行路径和精度不同而出现偏差;默认要重算一趟,跳过它能省下一步里约 20% 的时间(官方数字),代价是引入离策偏差,再用两种手段兜住。
- **两条训练线**:扩散模型和全模态自回归模型的一步长得不一样,所以是两条训练器线——前者本仓库自己写,后者的在线路径复用 verl,离线直接偏好另有实现。

## 四、一步扩散 RL 怎么串起来

以在线扩散 Policy Gradient 为例:控制器取一批提示词,交给 **Rollout** 生成图像或视频,并返回训练所需的轨迹片段与条件信息;Rollout 侧的 log-prob 按配置返回,不要求保存全部生成步。

奖励阶段为每个样本提供分数。部分配置可以让打分与剩余 Rollout 重叠;命名多奖励模型当前不走这条流式路径。随后完成所需的旧策略、Reference Model 或 Teacher 前向,计算 Advantage,由 **Actor** 更新参数,再通过 verl 的权重通路同步给 Rollout。具体阶段见 01 章。

全模态在线路径的生成是自回归的,因此可复用 verl 的训练能力;离线 Direct Preference 则有自己的训练路径(09 章)。

异步程度的差别落在最后一段的时序上:默认是同步,控制器等这一批全部走完再开下一批;V1 的分卡异步可让另一组卡上的生成与训练重叠,权重按同步周期传递;缓冲不够时还能把与训练共卡的那几个生成副本临时借出去(08 章)。

## 六、怎么调它、怎么看它

各章「调参与观测」只写自己的参数,入口在这里说一次。

**三种入口,一个原则:改了要重新拉起整个作业的都是启动配置。**

| 入口 | 长什么样 | 什么时候用 |
|---|---|---|
| 训练器主配置 | 三份主配置文件各自按 defaults 逐块组合出组件配置;扩散一份、全模态两份(同步一份、另一条训练后端一份),全模态那两份还会去 verl 的配置包里找父配置 | 定一套固定的实验配置 |
| 命令行覆盖 | 配方脚本在启动命令后追加点分路径等号写法 | 单次实验调某几个值 |
| 配置数据类 | worker 与算法配置目录下的一组数据类 | 读代码时查一个字段的真实默认值 |

优先级从低到高是:主配置默认值 → 配方脚本 → 命令行覆盖。配置目录里带下划线前缀的四份文件是**组合结果的展开快照,自动生成、不是给人改的**;快照便于理解配置结构,最终取值仍应看本次启动合并配方与命令行后的配置。

上手前要知道的三个默认:扩散线默认走非 V1 的那个入口;全模态线默认是同步模式;Rollout 默认关闭逐步执行;支持整请求批处理的适配器可以打包,不支持时退回串行;两种批处理互斥。

**扩到多机没有单独的机制**,只是同一组旋钮换一组取值:拓扑变量、批大小怎么放大、生成与打分各占几张卡、分片配置、注意力后端。各章第五节给自己那几个参数的多机取值,本页不重复。

观测的四处:训练指标走统一上报层到外部看板;扩散专用的算力利用率按两个键报出来,口径和 verl 的一致;逐段耗时走剖析器;另有一个开关把训练状态接到外部的可观测服务。

## 七、阅读顺序

主干是 01 → 02 → 03 → 04,读完就抓住了这个项目的主线:它和 verl 怎么分层、一个模型怎么接进来、生成怎么服务化、训练怎么落到两条后端。05 与 06 是把主线用起来的两件事(算法怎么换、奖励怎么搭);07 与 08 是性能与稳定性的两段,07 讲跳过重算的代价,08 讲异步的代价,建议按这个顺序读;09 到 13 按需查阅。

**怎么读**:本站已有 verl 的解读,它是训练与 RL 领域的参照系,本解读每章第四段都和它对比。扩散模型、流匹配、多模态 RL 的算法本身在知识库里各有一篇——去噪轨迹怎么映射成决策过程、它和文本自回归 RL 的根本差别、几条路线各自在修什么,都在那里;**本解读一概不讲算法是什么**,只讲 VeRL-Omni 怎么把它插进去、怎么排布卡、怎么调。

和 verl 解读的分工:verl 那边关心的是一步训练里四个角色怎么共用一批卡、怎么交换权重和数据;**这边的重心是多模态这件事本身**——当生成从一条 token 序列换成一条去噪轨迹之后,哪些地方必须重做。凡是本页说「沿用 verl」的,想看底层实现去 verl 的解读;但**为了把多模态这条线讲通顺,少量重复是允许的**,不会为了避开重叠而把话说一半。

## 八、术语表

| 术语 | 一句话 |
|---|---|
| 去噪轨迹 | 一次图像或视频生成从纯噪声到成品经过的全部中间状态,RL 在它上面算概率和梯度 |
| 适配器对 | 在线扩散训练通常配套的两侧适配类,Rollout 与训练必须对同一份数据格式达成一致 |
| 注册键 | 适配器注册时用的两元组,由模型架构名和算法名组成,全模态训练侧改成架构名加阶段,Rollout 侧使用流水线名 |
| Stepwise Continuous Batching | 每轮从兼容的在途请求各取一个去噪步组成批,请求可以处于不同进度 |
| Request-level Batching | 把兼容请求组成一批共同走完生成循环,每个去噪步各执行一次批前向 |
| 编码缓存 | 把提示词编码的结果按调用参数做键缓存起来,跨请求复用 |
| 命名奖励模型 | 一次训练里可以挂多个、各自独立管理资源与生命周期的打分模型 |
| 异步奖励 | 样本级的流式打分,谁先生成完谁先打分,与剩余生成重叠 |
| 跳过重算 | 不再用训练图重算一遍旧策略的对数概率,直接复用生成侧给的值 |
| 重要性修正 | 用两侧对数概率之差的指数做权重,修正跳过重算带来的偏差 |
| 拒绝采样 | 把两侧差距超出设定区间的样本的损失清零,不让极端值进梯度 |
| V1 训练器 | 扩散线的第二套训练器,用队列搬运轨迹,当前不是默认 |
| 分卡异步 | 生成放在独立的一组卡上提前一批开跑,权重每若干步同步一次 |
| 借卡 | 回放缓冲样本不够时,把与训练共卡的生成副本临时交给生成用,一步最多切一次 |
| Teacher | 蒸馏用的冻结模型,提供额外预测;可复用 Actor worker,也可独立部署 |
| 扩散算法族 | Policy Gradient 与 Direct Preference;不要与扩散/全模态两类模型路径混淆 |
