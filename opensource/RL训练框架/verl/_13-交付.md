## 否定检索与范围限定

在基准上执行 `git grep -n 'MODEL_CONFIG_CONVERTER_REGISTRY\|ModelRegistry\|load_state_dict_to_megatron_gptmodel\|use_mbridge must' <commit> -- verl`。结果保留 registry 定义、utils/model.py 的旧使用点、weight_loader_registry 的引用,并明确给出当前 Engine:191 的断言。因此只写“当前默认 Engine 不能选无 Bridge 内置建模”,**没有**写“旧 converter 全树无人调用”。

HF 扩展“不必复制整份建模文件”是 `docs/advance/fsdp_extension.rst:33-36` 与 `verl/models/README.md:3-24` 的明确规范,不是由目录为空推导。不以 mcore 模型 Enum 统计支持数量,不声称任意 HF checkpoint 都能在线训练。

## 主线程应核的硬事实

1. 当前 Megatron Engine 强制 Bridge;默认 vanilla=false 对应 NVIDIA Megatron-Bridge。
2. NVIDIA Bridge 从 local_path 读取 HF pretrained,兼容 mbridge 从内存 hf_config 构造;独立配置路径不保证这两个分支等效。
3. fused 的 Skipping 日志不能否定此前 attention/多模态补丁。
4. registry 弃用段不等于当前模型全链路支持清单。
5. Megatron override_transformer_config 的 YAML 默认非空,不能写成空字典。
