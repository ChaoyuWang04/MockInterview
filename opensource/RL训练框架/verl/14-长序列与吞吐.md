# 长序列与吞吐

这一页回答一件事:长短回答混在同一批时,verl 怎么减少白算、减少等待,并让长序列的训练峰值显存可控。说法都在源码基准 `f3d9b56e78`(tag `v0.8.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

同样一批回答,样本数相等不代表各卡工作量相等。短回答补到最长回答的长度,会多算 padding;把长回答集中分给一个 rank,其他 rank 又得等它。即使这两处处理好了,单条长回答的激活仍可能放不下,输出层还会产生「token 数乘词表大小」的 logits,把显存峰值再次推高。

这几处都表现为吞吐低或 OOM,但堵在不同位置。**verl 的做法是沿着有效 token 的去向逐层处理:先决定交给谁,再决定一次算多少,最后决定哪些中间结果不必整块留下。**

## 二、解法

先把两件容易混淆的事分开。**packing 去掉样本之间的 padding,长度均衡改变样本分配。** 前者减少无效计算,后者让各个 rank 更接近同时结束;只做其中一件,另一种浪费仍会存在。下图用同一组示意样本把它们分开,不是实际吞吐测量。

![同一组长度为8、6、2、4的示意样本,去掉padding后有效长度总和不变,再把长短样本搭配给两个rank,每个rank的有效长度从14与6变成10与10;实际调度还考虑长度平方带来的计算量。](/opensource/verl/14a-pack-and-balance.svg)

默认训练流程先在控制器上估计样本工作量、重排分给 Actor 的数据,并保持各分区样本数相等。这里不只数 token,还把长度平方计入估计。进入引擎后,动态 micro-batch 再按 token 预算分组,检查每组不超预算、协调各 DP rank 的 micro-batch 数。模型输入则把有效 token 连起来,保留各样本边界,由变长 attention 处理,不会把不同回答当成一条能互相注意的长句。

单条样本仍太长时,再让多卡协作处理上下文。FSDP 路径接入 Ulysses:进入 attention 时交换序列与 head 的分片,出来后换回来。Megatron 路径还可按每个 packed micro-batch 动态选择 CP 大小:同一 DP×CP 平面先拿到相同 mini-batch,把长度交给 Megatron-Core 调度器,各 rank 在本地选中分给自己的样本,再按原样本编号收回结果。**动态 CP 改的是哪些卡一起处理这一批上下文,不只是改变一批里装几条回答。** 并行算法内部见对应训练框架解读。

最后收掉输出层的大张量。融合输出头把线性投影、目标 token 的 logprob 与 entropy 计算接在一起,只向训练逻辑返回需要的逐 token 结果。原生实现按 token 分块,反向时重算块内 logits;Triton 实现按词表分块计算与归约。二者都避免把整段的完整词表 logits 长期留给后面的算子,并不意味着词表上的计算消失了。

## 三、代价

**均衡需要调度,并行需要通信。** 工作量估计是近似值,相近 token 数不保证每个模型、每种长度下耗时相等。Ulysses 增加 attention 前后的交换;动态 CP 还要求整个 DP×CP 平面拥有相同输入,收尾需要汇集结果、恢复顺序。缩短最长 rank 的计算时间,不等于整步必然缩短。

**少留中间结果,要付重算或分块开销。** 输出融合减小显存峰值,但失去通用的完整 logits 接口;有些额外概率统计不能与它同时启用。变长输入还会增加张量形状的种类。为了减少编译与调优抖动,可以把 packed 长度再补齐到几个固定档位,这又会把部分 padding 计算买回来。要看相同有效 token 下的时间与显存,不能只看 OOM 消失了没有。

## 四、和同类框架不一样的地方

slime 与 ROLL 也在解决变长负载,区别主要是在哪一层作决定,不是谁有 packing、谁没有。

| 要办的事 | verl | slime | ROLL |
|---|---|---|---|
| 给 DP rank 分工作 | 默认控制器先按样本工作量均衡,引擎内再拆 micro-batch | 先全局打包成 micro-batch,再把这些 micro-batch 分给 DP rank | 在 Megatron 的 packing 工具中提供按工作量重组 micro-batch 的实现 |
| 让 micro-batch 大小跟长度走 | 按 token 预算拆分,并检查每组预算;长上下文还可进入 Megatron 动态 CP 分支 | 动态打包后对齐 micro-batch 总数,保证各 DP rank 执行次数一致 | packing 配置分别规定训练与前向预算,协调 DP 与流水线的 micro-batch 数 |

对 verl 的使用者,实际区别是要分清控制器均衡、引擎 micro-batch 与上下文并行这几个层次。第四节的对照没有建立速度排名,也不能据此把另一项目同名预算直接抄过来。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。下面是追加在总览所述训练启动命令后的 Hydra 覆盖;模型、数据与资源配置继续使用已跑通的作业配置。

| 参数与位置 | 默认 | 调了之后哪个指标往哪边变 | 怎么看 |
|---|---|---|---|
| `actor_rollout_ref.model.use_remove_padding` | `true` | 保留有效 token 的 packed 输入;关闭会恢复批内补齐,显存与无效计算可能增多 | 相同样本的训练时长、显存峰值 |
| `actor_rollout_ref.actor.use_dynamic_bsz` | `false` | 开启按 token 预算拆 micro-batch,每批样本数随长度变 | `timing_s/update_actor` 与实际 micro-batch 形状 |
| `actor_rollout_ref.actor.ppo_max_token_len_per_gpu` | `16384` | 动态拆批的每卡预算;提高通常减少拆批次数,也增加峰值显存 | Actor 显存峰值;长样本是否超过可用预算 |
| `actor_rollout_ref.rollout.log_prob_use_dynamic_bsz` · `actor_rollout_ref.rollout.log_prob_max_token_len_per_gpu` | 跟随 Actor 动态开关 · 跟随 Actor 预算 | 控制 Actor old logprob 前向,不是 Rollout 生成的并发;动态开关必须与 Actor 一致 | `timing_s/old_log_prob`;初始化断言 |
| `actor_rollout_ref.ref.log_prob_use_dynamic_bsz` · `actor_rollout_ref.ref.log_prob_max_token_len_per_gpu` | 跟随 Actor 动态开关 · 跟随 Actor 预算 | 调整 Reference 前向的拆批与显存,可单独设预算 | `timing_s/ref` 与 Reference 显存 |
| `actor_rollout_ref.actor.fsdp_config.ulysses_sequence_parallel_size` | `1` | 多卡分摊上下文激活,同时增加通信并减少独立 DP 分区数;要求 remove-padding | 长样本 OOM、训练时间、attention 通信 |
| `actor_rollout_ref.actor.megatron.context_parallel_size` · `actor_rollout_ref.actor.megatron.dynamic_context_parallel` | `1` · `false` | 静态 CP 拓扑与是否启用动态调度;后者可按 micro-batch 改 CP 分组 | 固定样本下的耗时与峰值;不支持组合会直接报错 |
| `actor_rollout_ref.actor.megatron.max_seqlen_per_dp_cp_rank` | `null` | 动态 CP 必填的正整数,表示每个 rank 的 packing 预算;不是整组总预算 | 调度器关于单序列所需 rank 数的报错 |
| `actor_rollout_ref.model.use_fused_kernels` · `actor_rollout_ref.model.fused_kernel_options.impl_backend` | `false` · `torch` | 开启融合输出头,减少完整 logits 的驻留;HF 路径可选 `torch`、`triton`、`liger`,Megatron 的融合实现用 Triton | 启动时的融合后端日志、峰值显存;Megatron 的禁用警告 |
| `actor_rollout_ref.actor.fsdp_config.entropy_from_logits_with_chunking` · `actor_rollout_ref.actor.fsdp_config.entropy_checkpointing` | `false` · `false` | 非融合路径分别分块算 entropy、反向重算 entropy;不会消掉模型已产出的 logits | entropy 阶段峰值与反向耗时 |
| `actor_rollout_ref.actor.fsdp_config.pad_to_length` · `actor_rollout_ref.actor.fsdp_config.pad_to_length_bucket` | `false` · `1024` | 把 packed 长度向上补齐到桶,减少形状种类,增加补齐计算;桶还会对齐 SP 大小 | 预热后的形状抖动、编译时间与每步时间 |

普通动态拆批的整组预算是每卡预算乘 SP/CP 大小,单条样本不能被这一层拆开。动态 CP 则直接使用自己的每 rank 预算。它要求支持相应调度器的 Megatron-Core,DP×CP 至少为 2 且为偶数;当前支持纯文本语言模型的 packed 输入,不支持 FP8、value model、多模态、蒸馏与虚拟流水线。若 Reference 也采用该路径,要给它对应的配置。

**观测先看分配,再看计算。** `global_seqlen/minmax_diff` 记录均衡前的长度总和差距,`global_seqlen/balanced_min` 与 `global_seqlen/balanced_max` 记录均衡后的两端;它们统计的是长度,不是预测 FLOPs 或真实耗时。然后对照 `timing_s/update_actor`、`timing_s/old_log_prob` 与 worker 的 `perf/max_memory_allocated_gb`、`perf/max_memory_reserved_gb`。显存项是设备记录的峰值,不要自动当成本阶段独占显存;更细的归因见 16 章。

**典型配置**:

| 场景 | 追加哪些覆盖 | 拿什么换什么 |
|---|---|---|
| 单机多卡 CUDA、已支持的 Qwen/Llama 文本模型,回答长短差异大,单样本不超过 4096 token | `actor_rollout_ref.actor.use_dynamic_bsz=true actor_rollout_ref.actor.ppo_max_token_len_per_gpu=4096 actor_rollout_ref.model.use_remove_padding=true` | 用更多或更少条样本组成 micro-batch,减少固定条数造成的峰值波动;预算小会增加拆批 |
| 单机高速互联 CUDA 卡、同类文本模型,FSDP 下单卡上下文激活成为瓶颈;卡数及 attention head 数可被 2 整除 | `actor_rollout_ref.actor.use_dynamic_bsz=true actor_rollout_ref.actor.ppo_max_token_len_per_gpu=4096 actor_rollout_ref.actor.fsdp_config.ulysses_sequence_parallel_size=2 actor_rollout_ref.model.use_remove_padding=true actor_rollout_ref.model.use_fused_kernels=true` | 用跨卡通信和输出头分块计算换显存;先保证单样本不超过 8192 token,再核对实际峰值 |
| 已跑通的 Megatron 文本作业、至少 4 张可用于 CP 的高速互联 CUDA 卡,静态 CP4 packed 预算为 16384 token | `actor_rollout_ref.actor.use_dynamic_bsz=true actor_rollout_ref.actor.ppo_max_token_len_per_gpu=4096 actor_rollout_ref.actor.megatron.context_parallel_size=4 actor_rollout_ref.actor.megatron.dynamic_context_parallel=true actor_rollout_ref.actor.megatron.max_seqlen_per_dp_cp_rank=4096` | 保持每 rank 预算,让不同长度的 micro-batch 使用适合的 CP 分组;增加调度与结果归并成本 |

组合与推荐值是按语义推的起点,不是实测最优。

**症状 → 先查 → 然后**:

| 症状 | 先查 | 然后 |
|---|---|---|
| 多数卡先结束,总被少数卡拖住 | 均衡后的长度两端、样本长度分布与阶段耗时 | 区分分配不均和模型计算差异;不要先提高全局 batch |
| 打开动态 batch 后,最长样本仍报预算不足 | 单样本长度是否超过每卡预算乘 SP/CP | 在显存允许下增预算,或增加上下文并行;只减少样本条数不能拆短单样本 |
| attention 已跑过,算概率时 OOM | 输出头 logits 与 entropy 的峰值 | 先试融合输出头;需完整 logits 时改用 entropy 分块或重算 |
| 开了融合仍看不到显存下降 | 实际后端与禁用警告,峰值是否发生在输出头以外 | Megatron 的非 packed、value model 或 MTP 会关闭融合;按真正峰值位置处理 |
| packed 长度变化时耗时反复尖峰 | 预热后是否仍出现编译或 kernel 调优 | FSDP 可试长度分桶,同时检查补齐计算是否抵消收益 |

## 六、常见误区

**把动态 batch 的 token 预算理解成最长生成长度。** 名字里都有长度,但前者管训练或 logprob 一次装多少 token,后者决定数据本身。普通动态拆批不会切开单条样本;预算太小会报错,不是自动缩短回答。

**看到 packing 就认为跨卡已经均衡。** packing 图看起来更紧凑,容易让人以为卡利用率也一定均匀。它只去掉 padding;默认控制器的均衡与引擎拆批另有步骤,而均衡日志本身又不是耗时预测。

**把融合输出头和分块 entropy 当成同一个开关。** 都会影响显存,但后者接到的输入已经是完整 logits,只减少后续 entropy 的临时结果。前者从线性投影就开始分块或融合;需要完整词表统计时,必须检查兼容性。

**看到 TiledMLP 配置就以为已接通。** 基准里确实有实现和 `tiled_mlp.enabled` 字段,但默认 V1 FSDP 的模型补丁调用没有传入启用值,补丁入口默认关闭。不能把它写进这一版可直接使用的省显存配方,更不能据此预估容量。
