## 07｜算法怎么插进来

两张注册表与主循环中额外分支的解释成立，07a 保留。

1. **多轮会话不等于多条输出。** 末段计算 GRPO 再广播的特殊处理针对同一会话返回多个 AgentLoopOutput 的路径。内置 ToolAgentLoop 将多轮 token 串放进一个输出，不能说所有多轮任务都按“每段各算／只算末段”处理。建议将末尾误区限定为多输出轨迹路径，并补一句普通工具会话仍可返回一条完整轨迹。
2. **GSPO 表格中的权重方向需要纠正。** `seq-mean-token-mean` 先对每条序列的有效 token 取平均，再在序列间平均，不能据此说“短回答的梯度占比被压低”。改为“降低长度直接决定样本权重的影响”，不承诺任意任务的稳定性。
3. 两个算法名称并不单独决定 Reference 是否启用，KL 配置才是相关条件；“角色启用”也不等于新增独立进程。正文与 07a 图注统一即可。图中熵项改为“非零时加入熵正则”，避免误称只有非零才计算熵。

依据：`verl/trainer/ppo/v1/utils.py:148-222`；`verl/experimental/agent_loop/tool_agent_loop.py:120-213`；`verl/trainer/ppo/core_algos.py:1170-1205`；`verl/trainer/ppo/utils.py:70-112`；`verl/trainer/ppo/v1/trainer_base.py:1831-1848`。

## 08｜训练等生成等多久

同步、共卡异步、独立 one-step-off 实验路径都真实存在，问题在于把它们画成统一的递进尺度。

1. **拆开实现入口和机制比较。** 前两种属于 V1 模式；实验性的 one-step-off 使用独立训练器。不能把三者写成同一启动开关的三个档位，或暗示异步程度越高，样本年龄就按固定顺序增长。保留一章，在图和段首标明入口即可。
2. **08b 应重画。** 预热一个批次是样本预算，陈旧度八个版本是年龄界限，不能共用“训练步”长度轴。建议改成“允许提前生产多少／允许样本旧多久”两列，把 VeRL、slime、ROLL 分别填入对应控制方式；没有硬界限时直接注明，不用箭头长度伪装可比数值。
3. 08a 的流水线示意可保留，明确为稳态示意，仍有权重同步和边界等待。“生成永不停”改为“生成与训练可以重叠”。低阈值可能丢掉提前生成的旧组、降低预热收益，不必断言必然每步整批丢弃或原地打转。
4. 与 09 统一 wait 的含义：避免因陈旧度主动丢弃，不保证失败、过滤等情况下所有样本都保留。

依据：`verl/trainer/ppo/v1/trainer_colocate_async.py`；`verl/experimental/one_step_off_policy/ray_trainer.py:315-408`；`verl/trainer/ppo/v1/replay_buffer.py:510-615`。

## 09｜生成不停

生成池、缓冲区、训练消费者的主线正确；两张图用途明确，但陈旧度图的案例与策略需要一起修正。

1. **wait 不是“一条都不丢”。** 它根据 pending/running 组的年龄暂停推进；失败和过滤仍可淘汰样本。已经完成的组不靠 wait 等它跑完。正文、08 回指与 09b 一起改。
2. **09b 的时间案例不符合默认 drop 条件。** 示例从第 5 步提交，到第 13 步取用，按图中年龄算法已超过默认 8；不能同时表现成默认策略接受训练。建议用同一个明确超阈值的候选演示 drop 拒绝，另画仍在途的组解释 wait 等待，避免混成同一条时序。提交年龄与 token 使用的权重版本衡量不同量，不能直接相等，也不应说完全无关联。
3. **空阈值不提供有限的版本年龄保证。** 并发数限制同时在途的数量，不能给某条长期未完成轨迹的陈旧度提供硬上限。删除“仍有上限，只是不知道”的推论。
4. **队列满时存在两层机制。** fully-async 的监控会因队列达到阈值暂停生产；非阻塞 put 在溢出时仍可能丢旧项。不能用后者断言“队列没有背压”。将正常节流与溢出兜底分开讲。
5. **ROLL 的禁止共卡结论须限定 agentic 路径。** 不能由该路径的断言推出整个 ROLL 项目都禁止异步共卡；RLVR 路径采取警告等不同处理。
6. **调优建议区分慢请求与积压。** 已完成样本排队变旧时，再给生成侧加卡可能加重积压。建议先看在途延迟还是已完成队列增长，再决定优化生成或提高训练消费能力。
7. “四次优化器更新后同步”改为“四个训练子循环后同步”；每个子循环内部仍可有多次优化器更新。“训练不再等”改为“不必等待整批生成，仍需等够可用的小批”。这些一句话即可修正，不展开参数枝节。

依据：`verl/trainer/ppo/v1/replay_buffer.py:510-615`；`verl/trainer/ppo/v1/trainer_base.py:533-614,1948-1995`；`verl/experimental/fully_async_policy/message_queue.py:30-88`；`verl/experimental/fully_async_policy/fully_async_rollouter.py:1135-1170`；ROLL `roll/pipeline/agentic/agentic_pipeline.py:894`；`roll/pipeline/rlvr/rlvr_config.py:228-245`（共卡警告）。09a 保留缓冲结构，明确条目是题组及其状态，不把组与单条回答混用。

## 10｜多轮会话与工具调用

逐轨迹协程、工具等待、训练 mask 与 token 拼接主线成立。10a 的两种时序使用一致的工作时长，清楚解释跨轨迹并行，建议保留。

1. **middle 截断写反。** 实现保留头尾、截掉中间；参数表“头尾一起砍”必须改正。
2. **10b 加适用范围。** 去掉旧边界 token 再拼接是某些模型族的处理；基础实现可直接拼接。图注明“需要边界修正的模型示例”，不要讲成每次拼接的统一动作。图仍有真实信息，无须删除。
3. request ID 用于尽量保持服务亲和性，不能保证后续每轮永远落在同一后端；换成“尽量回到原服务”。训练 mask 是这里关注的关键差异，不宜称训练与推理“唯一实质区别”。两处均属轻量措辞修正。

依据：`verl/experimental/agent_loop/tool_agent_loop.py:245-300,450-513`；`verl/utils/tokenizer/continuous_token.py:190-223,365-419,620-646`；`verl/workers/rollout/llm_server.py:57-98`。
