# 训推不一致

同一段 token 交给 rollout 和 actor,为什么会得到不同的 logprob,这种差异该在计算端还是损失端处理。说法都在源码基准 `f3d9b56e78`(tag `v0.8.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

回答由 rollout 采样,更新由 actor 完成。即使刚同步过权重,两边也可能使用不同精度、不同 kernel 和不同批次布局;MoE 还可能因数值扰动选中不同专家。此时 actor 对已经生成的 token 重算概率,得到的未必是生成时的概率。

**权重版本相同,不等于概率相同。** 如果把 actor 重算的概率直接当作采样概率,损失中的概率比值就混入了训推差异。异步样本陈旧也会造成概率偏差,但陈旧度怎么限制归 09 章;本章关心拿到这批 token 后如何测量和处理差异。

另一个容易混进来的问题是复现:相同配置再跑一次,样本顺序与 reward 曲线能否重复。它与训推一致有关,却不是同一指标——两套计算各自稳定地输出不同概率,也可以完全可复现。

## 二、解法

verl 把处理位置分开:**计算端尽量缩小差异,损失端显式处理剩余偏差,复现端固定执行条件。**

默认 V1 会保留生成时的 logprob,再让 actor 对同一批 token 重算一遍。后者作为这一批更新的固定锚点,不随本批 mini-batch 更新而改写。重要性采样 IS 用「锚点概率除以采样概率」得到权重,可按 token 计算,也可把整段有效 token 的概率比相乘,让整条回答共用一个权重。接着截断过大的权重,或用拒绝采样 RS 把越界部分从训练 mask 中排除。这里的 RS 是处理已生成的数据,不是要求 rollout 重新生成。

![同一批 token 在 rollout、更新前 actor 和更新中 actor 三处产生概率;固定锚点与采样概率决定 IS 和 RS,更新中概率与固定锚点决定策略比值,两条路径在损失处汇合。](/opensource/verl/12a-probability-paths.svg)

计算端有不同的落点。**QAT 让训练前向也经历量化误差**,训练仍保留可更新的高精度参数,交给 rollout 时再导出真实低精度权重。FSDP 路线替换适用的 Linear 层并处理量化 scale,Megatron 路线通过 ModelOpt 完成转换与导出。仅给 rollout 开 FP8,改变的是生成侧精度,不能据此认定训练侧已经做了对齐。

**专家路由重放固定的是专家选择。** 一种方式记录 actor 重算概率时的路由,更新时照着走;另一种方式从 rollout 带回路由,让训练沿生成时的专家选择走。前者针对 actor 重算与更新之间的差异,后者才把生成侧纳入路由约束。它们不会把所有算子变成同一实现。

确定性则覆盖随机种子、请求到副本的路由、推理批次影响以及训练算子。这里有一条实际边界:本基准的官方完整复现路径要求旧训练入口和单轮 vLLM rollout,默认 V1 按完成情况收集数据,不能只打开确定性开关就承诺两次训练逐位相同。

## 三、代价

**修正要付出重算与有效样本的代价。** 固定 actor 锚点需要额外前向;截断权重控制极端贡献,也改变了未经截断的 IS 估计。RS 越严格,留下的训练 token 越少。因此偏差指标下降与训练质量改善必须分别观察,不能把过滤后的平稳曲线当成恢复完全同策。

**低精度对齐增加一条需要维护的计算与导出链。** 假量化范围、scale、跳过的层和 rollout 量化配置要匹配;路由重放还要传递逐 token、逐层的专家索引。它们都是有条件的机制,不是给任意模型换一个 dtype 就完成。

**复现会限制并发与执行选择。** 推理批次不变性未覆盖的模型可能需要串行生成,确定性算子也可能牺牲性能。作业重复性、两侧概率误差、最终 reward 和端到端速度应分别验收,源码接通不等于这几项都改善。

## 四、和同类框架不一样的地方

与智谱系 slime 的 Megatron 损失实现相比,两者都能比较训练概率和采样概率,再将截断后的重要性权重乘到策略损失上。区别在处理位置:verl 的默认 V1 先在控制器上用固定锚点计算修正权重和 mask,再交给 worker 的损失入口;slime 的这条路径在 Megatron 损失函数内调用修正函数,并允许替换该函数。

这让 verl 的同一批修正结果可以沿公共数据通路交给不同训练引擎,也要求检查所选损失是否实际使用传入的权重。它不是「开了修正,所有算法就自动等价」的保证;本章核实的默认策略损失会消费该权重,其他算法的公式与适配边界见 07 章。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

以下点分路径写在训练启动命令的 Hydra 覆盖项中。先在已能运行的模型、数据和 GPU 配置上追加,不单独构成完整训练命令。

| 参数与位置 | 默认 | 调了之后的影响 | 怎么看 |
|---|---|---|---|
| `actor_rollout_ref.rollout.calculate_log_probs` | `true` | 保留采样概率,是训推对照与 IS 的输入;关闭后缺少对照依据 | 批数据中的 `rollout_log_probs` 与 `rollout_corr/` 指标 |
| `algorithm.rollout_correction.rollout_is` | YAML 为 `null` | `token` 按 token 加权;`sequence` 将整段有效 token 比值累乘,长回答可能更易出现极端权重 | `rollout_corr/rollout_is_ratio_fraction_high`、`rollout_corr/rollout_is_eff_sample_size` |
| `algorithm.rollout_correction.rollout_is_threshold` | `2.0` | 单值是权重上限;更小会压低大权重贡献;`lower_upper` 双界形式会把界外权重置零,不是夹到边界 | `rollout_corr/rollout_is_mean`、双界时的 `rollout_corr/rollout_is_oob_ratio` |
| `algorithm.rollout_correction.rollout_rs` / `rollout_rs_threshold` | 均为 `null` | 前者开启后必须显式给阈值;越严格通常排除越多有效 token | `rollout_corr/rollout_rs_masked_fraction`、`rollout_corr/rollout_rs_seq_masked_fraction` |
| `algorithm.rollout_correction.bypass_mode` | `false` | V1 置真会直接用采样概率作旧概率并跳过控制器修正;不自动接通专用 bypass 损失 | 对照 `actor.policy_loss.loss_mode` 与实际损失指标,不要据此推断 RS 生效 |
| `actor_rollout_ref.actor.fsdp_config.qat.enable` / `mode` | `false` / `w4a16` | 启用训练假量化与低精度导出;`w4a4` 在 FSDP 配置中标为实验性 | QAT 层替换日志、rollout 的 `QAT quantization config injected` 日志及概率偏差 |
| `actor_rollout_ref.actor.fsdp_config.qat.group_size` / `quantization_config_path` | `16` / `null` | 后者启用 QAT 时必须提供有效 JSON;不能只启用训练侧而漏掉 rollout 配置 | 缺路径会报错;不整除组大小的 Linear 会打印跳过警告 |
| `actor_rollout_ref.actor.megatron.router_replay.mode` | `disabled` | `R2` 记录 actor 重算路由供更新使用;`R3` 使用 rollout 路由 | 缺 `routed_experts` 会报错;核对生成、重算与更新阶段的数据 |
| `actor_rollout_ref.rollout.enable_rollout_routing_replay` | `false` | 为生成侧路由返回提供数据;vLLM 路线检查版本至少 `0.22.0` | 启动版本检查、返回的 `routed_experts` |
| `actor_rollout_ref.rollout.full_determinism` / `seed` | `false` / `42` | 固定请求 seed 与副本路由等条件,不能单独保证完整训练复现 | 相同配置两次运行逐步比对生成 token、批次与 reward |
| `actor_rollout_ref.actor.fsdp_config.full_determinism` | `false` | 启用确定性算子配置;无法提供确定性实现时允许告警 | worker 告警与两次运行对照 |
| `trainer.use_v1` | `true` | 官方完整确定性路径要求 `false`,会切换训练入口 | 启动入口与单轮 vLLM 限制;这是独立复现实验,不是 V1 修正参数 |

默认 IS 和 RS 都未启用,但只要两侧 logprob 到齐,控制器仍计算偏差指标。先看 `rollout_corr/k3_kl` 与 `rollout_corr/log_ppl_abs_diff`,再看权重超界比例和过滤比例。`rollout_corr/kl` 是采样估计,不能把单步出现负值直接判成计算错误;也别把这些指标与相对 Reference 的 KL 混用。有效样本量指标是归一化的权重集中度指标,不是剩余样本条数。

量化配置随 actor 侧插值给 rollout,排除层的匹配方式则依赖训练后端。

| 配置位置 | 默认 | 影响与观测 |
|---|---|---|
| `actor_rollout_ref.actor.fsdp_config.qat.ignore_patterns` | `[lm_head, embed_tokens, 're:.*mlp.gate$']` | 支持子串与 `re:` 正则,匹配层保留原精度;核对 QAT 替换日志 |
| `actor_rollout_ref.actor.megatron.qat.ignore_patterns` | `[lm_head, '*mlp.gate']` | 使用 glob,不要照搬 FSDP 正则;核对 ModelOpt 配置与导出层范围 |

| 场景 | 在已有作业上追加的配置 | 拿什么换什么 |
|---|---|---|
| 已跑通的单机 dense 模型,先测概率差异 | `actor_rollout_ref.rollout.calculate_log_probs=true`、`algorithm.rollout_correction.bypass_mode=false`、`algorithm.rollout_correction.rollout_is=null`、`algorithm.rollout_correction.rollout_rs=null` | 保留 actor 重算开销,先取得未修正的差异基线 |
| 同一模型与 GPU 布局,验证 token 级截断 IS | 上一行改为 `algorithm.rollout_correction.rollout_is=token`、`algorithm.rollout_correction.rollout_is_threshold=2.0` | 限制极端权重贡献,对比 reward 与权重超界比例;不预设质量一定改善 |
| 已跑通的 Megatron MoE,先固定 actor 内部路由 | 保留 `algorithm.rollout_correction.bypass_mode=false`,追加 `actor_rollout_ref.actor.megatron.router_replay.mode=R2` | 保留 old logprob 前向并传递路由索引,隔离重算与更新之间的专家选择变化 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 修正开了却看不到权重指标 | 采样 logprob 是否返回、IS 是否仍为 `null`、是否打开 bypass | 用未修正基线确认数据齐全,再只改 IS |
| 长回答的权重频繁超界 | 是否用了 `sequence`,有效长度是否增长 | 对比 token 档,不要先无限抬高阈值 |
| 曲线更平稳但学习停滞 | RS 排除比例和 IS 有效样本量 | 先放宽过滤或回到基线,确认是否丢掉了主要训练信号 |
| QAT 启动成功但概率差仍大 | 跳过层、量化 JSON、scale 与后端是否匹配 | 固定同一批 token 做两侧对照,不要用正常启动代替数值检查 |
| 路由重放缺索引 | R2 是否跳过了重算,R3 是否有 rollout 返回路由 | 修复数据来源与对齐,不要用空索引绕过错误 |
| 固定 seed 仍复现不了 | 是否仍用 V1、是否多轮工具调用、是否出现确定性告警 | 按官方单轮 vLLM 与旧入口条件做独立复现验证 |

## 六、常见误区

**看见配置类默认 sequence,就以为默认已经有 IS。** Python 配置类确实给了这个值,但标准训练入口加载的 YAML 明确覆盖为 `null`。排障要看合成后的启动配置,否则会把只有偏差观测的运行当成已修正实验。

**把 bypass 当成免费加速开关。** 名字容易让人以为只是省一次前向。V1 实际还跳过控制器上的 IS 和 RS;旧入口中把专用损失一起改好的辅助函数,没有在 V1 这条路径调用。因此只改这一项,不能声称保留了原来的修正语义。

**看到同一批 MoE token,就认为重放任一路由都一样。** R2 的记录源是 actor 重算,R3 的记录源是 rollout;跳过前者的前向却要求它提供索引,会直接缺数据。先确定要约束哪两个阶段,再选记录源。

**看到确定性开关名字里的 full,就把告警当成无关紧要。** 底层使用允许告警的确定性检查,而批次收集、外部工具和推理后端还有各自边界。需要的是一次符合边界的重复运行对照,不是日志里出现了开关名。
