# 12 训推不一致：交付与证据

## 基准与范围

verl `f3d9b56e789c39a06c4b87cc367bae02bac9102b`, tag `v0.8.0`, 2026-09-22。源码只读 `/tmp/verl-base`。slime 比较只读固定提交 `5bae5bb7928d65906e24e99f5b5d3f99a4daaf93` 的 git show,不以工作树为依据。

主旨：同一批 token 的采样概率、固定 actor 锚点、更新中概率有不同职责；IS/RS、QAT/路由重放、完整复现各处理不同层次。不能把修正说成恢复完全同策，也不能把确定性说成训推逐位相同。

阅读范围：docs/06-开源解读流程.md、docs/00-START.md、01 样板、07/08/09 边界与登记表；V1 控制器、公共 loss 入口、rollout correction helper、QAT 与 ModelOpt、Megatron router replay、V1 worker/rollout 接线、确定性与低精度官方 docs。QAT 算子和 FP8 引擎细节归相应引擎/知识库，本章不展开。

## 否定检索与边界

- 全快照 `rg -n apply_bypass_mode /tmp/verl-base/verl`：定义在 helper，调用仅 `verl/trainer/ppo/ray_trainer.py:1579` 与 `verl/experimental/separation/ray_trainer.py:514`。V1 无此调用。再搜 V1 的 bypass_mode，仅复制概率与跳过 correction 分支；公共 loss 仍按 actor.policy_loss.loss_mode 查表。不把专用 bypass loss 自动接线的旧入口行为搬到 V1。
- 默认关闭断言来自完整配置检索与 YAML 有效值：rollout_is / rollout_rs null，full_determinism false，QAT enable false，router replay disabled。Python 类 IS 默认 sequence 单独列明。
- 全确定性不作全框架保证：官方 docs 明确限定，底层 warn_only 也不构成每个算子确定的强制证明。
- QAT/路由重放只缩小其覆盖的数值或离散选择差异；不声称 KL 必定归零、质量一定改善或推理一定加速。
- 07 负责算法/损失注册与公式，09 负责样本陈旧与调度，05 负责权重传输；12 仅负责差异发生后各机制的实际作用位置。

## 硬事实核验清单

1. 默认 YAML 的 IS 是 null，不能照配置类写 sequence。
2. V1 默认修正使用固定 old actor / rollout 比值；当前 actor / old actor 是另一条比例。
3. V1 bypass 不调用自动改 loss 的 helper，不承诺 RS/TIS 等同旧入口。
4. R2 记录源是 actor 重算，R3 是 rollout；R3 还有因果行对齐，并非复制所有行无条件使用。
5. 完整确定性官方要求 V0 + 单轮 vLLM，底层检查 warn_only；复现不等于两侧概率一致。
