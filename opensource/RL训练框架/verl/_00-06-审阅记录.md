## 03｜训练引擎抽象与六个后端

**判断：选题与主要机制正确，抽象边界和共卡描述需要修正。**

**必须改 A：不能写“建模、并行、优化器、剪梯度、存档全部外包，VeRL 一行不写”。** VeRL 自己的 engine adapters 中有建模、FSDP 包装、优化器与 scheduler 组装、梯度裁剪、checkpoint 对接；后端内部也参与微批处理。不是一条横线把“VeRL 代码”和“上游代码”分开。

建议改为三层：训练循环/worker 提供角色与批次编排 → VeRL engine adapter 实现统一生命周期并适配后端 → PyTorch/FSDP、Megatron 等提供底层能力。03a 仍保留分层图，但应画这三层；不把接口收窄成唯一一个“微批怎么算 loss”函数。

依据：`verl/workers/engine/base.py:30-180`；`verl/workers/engine/fsdp/transformer_impl.py:207-233`、`verl/workers/engine/fsdp/transformer_impl.py:385-479`、`verl/workers/engine/fsdp/transformer_impl.py:496-526`、`verl/workers/engine/fsdp/transformer_impl.py:724-825`；`verl/workers/engine_workers.py:242-315`。

**必须改 B：“Critic 不共卡”与默认拓扑相反。** Critic 使用 TrainingWorker 类型，不等于它独占 GPU/进程。默认与 Actor 在同一 global pool 中合成共置 worker。直接改这一句，并与新 01 图保持一致即可。

依据：`verl/trainer/ppo/v1/trainer_base.py:280-330`、`verl/trainer/ppo/v1/trainer_base.py:788-848`。

**应同步 C：后端数量不要作为不等口径的能力比较。** 本文已明确“六个目录不是六条都能走通的路”，这段可保留；但 03b 图又按目录/策略/单文件混合比较数量。改成“覆盖哪些引擎家族、如何适配”即可，无须纠缠精确目录数。Reference 强制 CPU offload 的叙述限定 FSDP 路径，不能推广到全部后端。

**图的结论：** 03a 有必要但边界须改；03b 是表格型比较，可保留为简短 Markdown 表，不必强求第二张 SVG。图中的后端名称用 FSDP，避免把它只写成“分片数据并行”而失去项目对应关系。

## 04｜把推理引擎当成可换权重的服务

**判断：副本—服务—路由的主旨合格，生命周期的两处事实必须修正。**

**必须改 A：abort 不是必然丢弃整条轨迹。** 正文开头说换权重前请求全部作废、旧权重 token 不能混入新样本；V1 异步客户端实际累积已生成的 token 与 logprob，再携带前缀重试，轨迹可以跨权重版本。应区分“停止本次正在运行的请求”和“丢弃已有轨迹”。同步模式也不必画成每步都走同一套中断准入流程。

依据：`verl/workers/rollout/llm_server.py:171-189`、`verl/workers/rollout/llm_server.py:281-348`。

**必须改 B：04b 把睡眠→半唤醒箭头标为“推完新权重”，顺序不准确。** 应先恢复接收权重所需的内存，再更新权重，最后恢复 KV cache。正文虽然有正确描述，图必须对齐。浅睡统一画成“只放缓存”也过度：SGLang adapter 路径保留 base weights，vLLM level-1 仍涉及权重解除映射与恢复。入门图用“按后端策略保留或卸载权重”即可，不必展开全部细节。

## 05｜权重通路

**判断：全量/分片/增量三层主线很好，仍有几处不能保留的事实概括。**

**必须改 A：NaN 加载机制属于 SGLang 这条路径，不是两家统一实现。** SGLang 自定义 loader 将稀疏补丁解码并通过 masked copy/load_weights 应用；vLLM adapter 解码成 CheckpointWeightPatch，调用其 checkpoint patch 接口。两者共同点是使用 checkpoint 坐标与引擎原生映射，并不等于都临时修改 copy_。

修法：共同原理保留一段；NaN 方案标注“以 SGLang 为例”，另用一句解释 vLLM 的 patch 接口。05a 概念图可以保留，但“同一个加载器跳过空洞”应标注示例范围。

依据：`verl/workers/rollout/sglang_rollout/delta_loader.py:60-109`；`verl/workers/rollout/vllm_rollout/delta_weight_transfer.py:135-200`。

**必须改 B：比较段说两家共卡限制相反，实际上文内已经写成同一种限制。** slime 禁止 delta+colocate，VeRL 本文讨论的 delta 配置也是训练/生成分离；不能据此得出“砍掉相反的一半”。删除该结论，保留真实区别：slime 的磁盘补丁路径与 VeRL 的通信/内存补丁路径。

交叉依据：slime 基准 `slime/utils/arguments.py:2098-2110`；VeRL `docs/advance/delta_weight_sync.md:7-24`。不要把 rollout worker 到引擎的同 GPU IPC 与 trainer/rollout 是否共卡混为一谈。

**应改 C：稀疏收益保留为特定实测，不能写成普遍保证。** 官方有对应实验，因此数字不是凭空编造；但“后训练绝大多数字节不变”需带 BF16、学习率和测试配置前提。“接收侧峰值与模型多大无关”改为“不额外保留完整模型镜像，临时空间由桶与解码张量决定”。SGLang 的 `_decode_one` 仍会构造当前参数形状的张量。

**应改 D：hybrid_engine 不能写成所有路径的总开关。** 第一章已修，05 参数表还在用旧概括；同步口径即可。流水线并行的禁止也应限定具体后端/导出路径，不泛化到全部 engine。

**图的结论：** 05a 最有教学价值：不同切分、共同坐标、只传变化位置。示意的九个变化格子与右侧 5/4 分配能对应，不需要为了版式重画。05b 可保留或改短表，修与正文相同的范围问题。

## 06｜放置与显存

**判断：池子、共置与显存交接的主线成立；显存图把独立状态合成一个开关，必须修正。**

**必须改 A：参数 offload 不是参数、梯度、优化器状态的统一开关。** 06b 图用同一紫块代表三类状态，下排仅声明打开参数 offload，却把整块一起移走。优化器 offload 是独立配置，梯度也有生命周期；打开一个开关不能证明三份状态同时离卡。

修法：最简单是把图限定为“模型参数与 Rollout 权重/KV cache 的交接”，去掉优化器与梯度的共同归属；或分别画参数与优化器状态，并标明两个开关。时间顺序保留，但“唯一共存时刻”“整程固定峰值”改成可能出现重叠峰值的区间，不能保证启动成功后换权重就无显存问题。

依据：`verl/workers/engine/base.py:303-339` 的 BaseEngineCtx；`verl/workers/engine/fsdp/transformer_impl.py:159-164`、`verl/workers/engine/fsdp/transformer_impl.py:977-1040`；`verl/workers/engine_workers.py:768-828`。

**必须改 B：“Actor/Critic 共用进程，所以分别调 offload 没意义”不成立。** 两个角色使用各自引擎与配置，卸载 Critic 不会卸掉 Actor，但可以减少同一 GPU 上的总占用。共用进程不意味着配置绑定。正文相应症状表需直接改正。

依据：`verl/trainer/ppo/v1/trainer_base.py:250-330`；`verl/workers/engine/base.py:303-339`。

**必须改 C：区分训练引擎自动上下文与 Rollout 的显式睡醒。** 文字“两套定时器、控制器一句话不用说”及 06c “没人下令”过头。训练引擎可在上下文中自动装卸，但控制器仍通过生命周期钩子调用 sleep 和 update_weights。06c 若只比较训练 engine 参数装卸，应在行名里明确该范围。

依据：`verl/trainer/ppo/v1/trainer_sync.py:20-44`；`verl/workers/engine/base.py:303-339`。

**需收紧的一项比较：** slime actor 的 sleep 调用 torch_memory_saver.pause，wake 调用 resume；仅凭调用方不能推出“完全不拷贝”。当前读到的是外部包的接口，不是其内部实现。保留“通过 torch_memory_saver 管理内存”，删去无证据的零拷贝结论即可，不必为入门教材增加外部库专章。

**图的结论：** 06a 有效，按需角色与默认角色的图例需一致；06b 必须改上述内存归属；06c 改显式/自动控制范围和无证据比较即可。其“价值网络能否单独放”统一为“Critic 能否单独放”。章节数量和三张图的选题本身均不用推翻。
