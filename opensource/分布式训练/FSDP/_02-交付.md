## 一、分组规则与入口

| 断言 | 出处 | 节 |
|---|---|---|
| 每次调用 `fully_shard` 构成一个通信组,组内参数一次 all-gather、梯度一次 reduce-scatter;没有按字节算的自动攒批,边界完全由包了哪些模块决定 | `docs/source/distributed.fsdp.fully_shard.md:58-67` | 一、二 |
| 同一条规则在入口 docstring 里复述:分组是一等公民,组 = 本模块参数减去已被子模块调用认领走的;应当自底向上调用;一般**不要**只在最外层根模块上调 | `_fully_shard/_fully_shard.py:133-143` | 一、二 |
| 只包根模块 = 一次 all-gather 全部参数、一次 reduce-scatter 全部梯度,两次巨大的阻塞通信、零重叠,「almost never what you want」 | `docs/source/distributed.fsdp.fully_shard.md:75-83` | 一 |
| 逐子模块包之后 `m2`、`m3` 各成一组,剩下的 `a`、`d` 组成根组 | 同上 `:85-89` | 二 |
| 组的大小由「包哪些模块」控制:包得细 = 组小、更易重叠(文档自己类比 DDP 的小桶),包得粗 = 组大;没有自动攒批 | 同上 `:129-133` | 二、四 |
| 组的形成是一次深度优先遍历:不可组合的模块不进,已带 FSDP 状态的子模块不再往下走(注释原文 `nested fully_shard module`) | `_fully_shard/_fsdp_init.py:276-325` | 二 |
| 组的参数 = 受管模块直属参数的去重并集;buffer 一并收集;标量参数(零维)被拒 | `_fully_shard/_fsdp_init.py:328-366` | 二、备 |

## 二、一个组持有什么

| 断言 | 出处 | 节 |
|---|---|---|
| 组持有:参数对象列表、所属模块元组、网格信息与前向后网格信息、设备、混合精度与 offload 策略、训练态、分片态、模块全名 | `_fully_shard/_fsdp_param_group.py:159-198` | 二、备 |
| 组还持有自己的通信实现与 all-gather 输出缓冲,以及归约相关的开关:是否归约、HSDP 是否跨组 all-reduce、反向后是否重分片、归约因子、归约输入缓冲上限、反向是否凑齐 | 同上 `:200-252` | 三、五、备 |
| 组持有在途状态:all-gather 结果、归约完成事件、前向后重分片事件、HSDP 的部分归约输出与 all-reduce 状态 | 同上 `:254-275` | 备 |
| 组内可训练参数的原始精度必须唯一、归约精度必须唯一,否则断言失败(注释说明「要放宽就得按归约精度各发一次 reduce-scatter」) | 同上 `:278-308` | 三、五、六 |
| 组的分片态三值:分片、前向后分片到小网格、完整;状态转换以组为单位整体进行 | 同上 `:886-914` | 备 |
| 组的一次 all-gather:先把组内所有参数的本地分片拷进一块连续缓冲区,输出缓冲大小 = 组内分片元素总数 × world size,然后发一次集合通信 | `_fully_shard/_fsdp_collectives.py:325-378` | 二 |
| 组的一次 reduce-scatter:组内梯度先拼成一块输入缓冲,再发一次 | `_fully_shard/_fsdp_collectives.py:578, 642, 664, 823-830` | 二 |
| world size 为 1 时不发集合通信,直接用本地分片构造完整参数 | `_fully_shard/_fsdp_param_group.py:402-418, 447-470` | 备 |
| 组的参数到模块的映射刻意不去重,以支持共享模块与组内共享参数 | 同上 `:1119-1147` | 备 |
| 反向的 post_backward 由一个 autograd 函数触发,在前向进入这一组时注册一次 | 同上 `:926-942, 1150-1167` | 三 |
| 归约的进程组默认与 all-gather 共用分片进程组,除非显式给 reduce-scatter 单开一个 | 同上 `:997-1047` | 备 |

## 三、根、调用顺序与校验

| 断言 | 出处 | 节 |
|---|---|---|
| 根由「第一个跑前向的状态」认下;认定时遍历自己这棵子树,把其中别的状态标为非根 | `_fully_shard/_fsdp_state.py:171-202` | 六 |
| 认定为根之后,若重分片粒度是自动的(入口传 `None`),把本状态各组的前向后网格信息置空,即根组前向后不重分片 | 同上 `:203-207` | 六 |
| 因此根模块上不调入口时,没有任何状态能在遍历里把各层标成非根:每个层跑前向时各自认一次根,各自拿到「前向后不重分片」 | 由 `:171-207` 与 `:289-325` 两段合起来得到(`_pre_forward` 每次进入都会走一次根前置逻辑,而根前置逻辑第一步就是懒初始化) | 六 |
| 同一个参数落进两个组 → `ValueError`,报文直接建议用 `fully_shard([module_a, module_b])` 并组 | 同上 `:217-230` | 三、五、六 |
| 子模块先于根跑前向 → `RuntimeError`,要求先走根模块的前向 | 同上 `:190-196` | 五 |
| 模块全名在根的懒初始化里写进组;一个组对应多个模块时,名字用逗号接起来 | 同上 `:255-287` | 五 |
| 共享通信上下文、组序号与组总数在懒初始化里统一分发给所有状态 | 同上 `:232-253` | 备 |
| 懒初始化是幂等的,并在这里做 meta 设备、CPU offload、归约缓冲上限三项校验 | `_fully_shard/_fsdp_param_group.py:310-328, 1067-1116` | 备 |

## 四、一次收一组模块(列表形式)

| 断言 | 出处 | 节 |
|---|---|---|
| 列表形式的动机:主前向只跑组里一部分模块,其余在同一轮里稍后调用;分块算损失是那个动机场景 | `_fully_shard/_fully_shard.py:145-150` | 二 |
| 代价一:每次独立的按块调用各自注册一个 post_backward autograd 节点,N 块 = 该组 N 次 reduce-scatter | 同上 `:151-153` | 三、六 |

| 组里有模块整轮没跑时,由根的后置前向补齐 | 同上 `:369-384` | 备 |
| 前向进入时若该组已处于前向态,跳过重复注册反向节点 | `_fully_shard/_fsdp_param_group.py:558-576` | 备 |
| 前向或反向抛异常后,这一轮状态未定义,要在根上重置 | `_fully_shard/_fully_shard.py:159-167` | 备(01 章主场) |

## 七、留给主线程的两处

1. **01 章第四节写的是「通信边界一个按字节划,一个按模块划」,而 Megatron 的阈值口径是参数元素个数,不是字节**(`distributed_data_parallel_config.py:52-56` 的 docstring 原文是 "Maximum number of parameters in each bucket")。02 章按核到的口径写成「元素个数」。两章的措辞是否统一,由主线程定。
2. **「只在根模块上调一次」这件事,01 章第六节已经写了一整段,而它是 02 章的核心问题。** 02 章没有重复 01 的句子,并把 01 没有的两面补上(它不出声、以及漏掉根上那一次会让每层各自成根)。是否把 01 那一段压成一句回指,由主线程定。
