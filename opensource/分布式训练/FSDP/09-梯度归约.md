# 梯度归约

这一页回答:多个 microbatch 的梯度什么时候合起来,才能少通信、又不把显存和更新尺度搞错。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

**梯度累积只更新一次,不代表只通信一次**。 如果每个 microbatch 的反向都走默认路径,它们各自完成梯度归约,最后才一起交给优化器。microbatch 越多,同一组梯度形状就越反复经过通信链路。

最直觉的做法是把归约推迟到最后。但反向刚算出的梯度是完整形状,推迟归约就得先把它留下。于是省下的通信又变成显存压力。通用梯度累积与分片原理见知识库的 ZeRO、并行策略篇;这里只看 FSDP2 怎样安排这笔交换。

## 二、解法

普通全分片路径先做 reduce-scatter:各卡的梯度归约后,每张卡只留下与自己参数对应的分片。HSDP 还要再做 all-reduce,把不同副本中对应的分片同步好。分片维与复制维怎么摆,见 07 章。

FSDP2 把这两步的开关拆开。**完全推迟归约**,就先累积完整梯度,最后一次反向才做通信。**HSDP 只推迟 all-reduce**,则每次仍做 reduce-scatter,把累积量压成分片大小,最后再跨副本同步。后者保留了一部分通信,换来更小的累积梯度。

![一个分片规模为 2 的 HSDP 参数组累积 3 个 microbatch 时,每次同步执行 3 次 reduce-scatter 和 3 次 all-reduce,完全推迟只在最后执行各 1 次但中间保存完整梯度,只推迟 all-reduce 则执行 3 次 reduce-scatter 和 1 次 all-reduce并保存半份梯度](/opensource/FSDP/09a-accumulation-paths.svg)

归约还要回答“除以多少”。默认得到数据并行范围内的平均梯度;HSDP 的分母包含分片规模与复制规模。实现会把这个除法放进 collective,或拆成归约前后的缩放,避免把全部除法都拖到大规模求和之后。**这只处理 rank 之间的平均,不替训练循环决定 microbatch 的权重**。

## 三、代价

完全停归约时,参数仍可以退回分片,**梯度却要按完整形状累积**。不能看到参数已经释放,就以为累积状态也只剩本地分片。HSDP 的折中方案可以缩小这部分梯度驻留,代价是每个 microbatch 仍要 reduce-scatter。

通信少了也不保证每步更快:原来能藏在反向计算里的通信,可能集中成最后一次反向的尾巴。要同时看整步时间与显存峰值,而不是只数 collective。

条件分支还会影响哪些参数得到梯度。不同 rank 使用的参数不同时,参与归约的列表可能不一致。FSDP2 可以给已参与该组生命周期、但本次没有梯度的可训练参数补零,让 collective 的形状对齐;代价是这些位置也要随组传输。这不是把任意不同的模块调用顺序自动变成合法分布式程序。

## 四、和同类常见做法不一样的地方

对照限定为 Megatron-LM 的 DDP 与分布式优化器梯度路径,不包含其另有的全分片实现。

| 比较维度 | FSDP2 | Megatron-LM |
|---|---|---|
| 暂停梯度同步 | 在分片模块上显式设置同步状态 | DDP的暂停同步上下文把bucket标记为非最后一个microbatch |
| 何时恢复同步 | 设置持续生效,训练循环要在最后一次恢复 | 退出上下文恢复原标记 |
| 如何得到平均梯度 | 按归约类型与除法因子选择内置平均、预乘求和或单独缩放 | 默认在collective前缩放梯度,再做求和 |

两边都要区分底层求和算子和最终平均语义;profiler中看到SUM,不代表模型收到未平均的梯度。

## 五、调参与观测

这些是分片后模块上的运行期方法,应在对应 microbatch 的前反向开始前安排好;同步状态与“是否最后一次反向”各管一件事。

| 方法 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `set_requires_gradient_sync(value, recurse=True)` | 根或目标 FSDP 模块 | 同步开启 | `False` 同时停 reduce-scatter 与 HSDP all-reduce,留下完整梯度;`True` 恢复两者 | 中间 microbatch 的归约事件与显存 |
| `set_requires_all_reduce(value, recurse=True)` | HSDP 模块 | 开启 | 保持梯度同步开启时,设 `False` 只停 all-reduce,累积 reduce-scatter 后的分片 | reduce-scatter 仍在,all-reduce 延后 |
| `set_is_last_backward(value)` | 根 FSDP 模块 | `True` | 控制反向结束时等待在途归约与清理预取状态,不负责停 collective | 最后一次反向前恢复 `True` |
| `set_gradient_divide_factor(factor)` | 要修改的各个 FSDP 模块,不递归 | 内部为 `None`,按数据并行规模平均 | 自定义总除数,改变最终梯度尺度;HSDP 不会再自动额外除一次复制规模 | 同一输入下对照参考梯度与 norm |
| `set_force_sum_reduction_for_comms(enable)` | 要修改的各个 FSDP 模块,不递归 | `False`;MTIA 强制启用 | collective 只用 SUM,所需平均改由前后缩放完成 | 同时查 collective 与缩放,不能只看 SUM |
| `set_reduce_scatter_unused_params(value, recurse=True)` | 有条件参数使用的模块 | `False` | `True` 对本轮未得梯度的可训练参数补零参与归约,减少 rank 间列表不一致 | 比较各 rank 使用参数与 collective 形状 |

下面以每个 rank 吃等量样本、累积 3 个 microbatch 为例。每个 microbatch 的平均 loss 再除以 3,全部反向完成后才做一次 optimizer step;不在中间清梯度。样本或 token 数不等时,应按训练目标另算权重。

| 场景 | 怎么设 | 拿什么换什么 |
|---|---|---|
| 普通全分片,完整梯度累积放得下 | 前 2 次在根设 `set_requires_gradient_sync(False)`;最后一次设 `True` | 用完整梯度驻留换中间归约全部省去 |
| HSDP,完整梯度太大,主要想少做跨副本通信 | 保持 `set_requires_gradient_sync(True)`,前 2 次设 `set_requires_all_reduce(False)`,最后设 `True` | 每次仍做 reduce-scatter,用分片累积换少做 all-reduce |
| 多模态分支使同组参数在各 rank 使用不同 | 对相关模块设 `set_reduce_scatter_unused_params(True)`,同时保持一致的通信组调用顺序 | 零梯度通信换 collective 列表对齐 |

前两套都可在根模块把前 2 次的 `set_is_last_backward(False)`、最后一次的 `set_is_last_backward(True)` 与上述同步安排配合使用。它不替代同步开关。

组合与推荐值是按语义推的起点,不是实测最优。

用 `torch.profiler` 的 `FSDP::post_backward_accumulate`、`FSDP::post_backward_reduce` 对齐反向阶段,再看实际 reduce-scatter/all-reduce 事件;同时记录峰值显存与完整 optimizer step 耗时。要验证梯度尺度,用同一组样本比较“分 microbatch 累积”与参考大 batch 的梯度,容许浮点归约顺序带来的误差。

| 症状 | 先查 | 然后 |
|---|---|---|
| 累积越多,loss 或梯度尺度越不对 | loss 是否按 microbatch 权重归一化,是否重复设置了总除数 | 先用等量样本小例对照参考梯度 |
| 已设非最后反向,仍每次有通信 | 是否只改了 `set_is_last_backward` | 按目标选择全停同步或只停 HSDP all-reduce |
| 停同步后 OOM | 完整梯度是否跨 microbatch 留存 | HSDP 可试只停 all-reduce;否则恢复逐次同步 |
| 最后反向后各副本更新不一致 | all-reduce 或总同步是否忘记恢复 | 最后一次前恢复对应开关,完成归约后再更新 |
| 条件分支后出现 collective mismatch | 各 rank 是参数无梯度,还是整组调用顺序不同 | 前者核对补零开关,后者先修通信生命周期 |

## 六、常见误区

**“最后一次”标记就是停同步开关。** 名字很像 microbatch 的总开关,实际它管尾部等待与状态清理。只改它,reduce-scatter 仍会按同步设置执行。

**HSDP 先关总同步,再打开 all-reduce,以为保留了其中一半。** 总同步关闭时,反向会在归约前返回;单开 all-reduce 不能越过它。折中路线是总同步开着,只关 all-reduce。反过来,调用总同步 setter 也会同时覆盖 all-reduce 状态,所以调用顺序要明确。

**只在根模块改除数,以为所有层一起改了。** 同步 setter 默认递归,除数 setter 却只改当前模块所管理的组。需要整个模型同一尺度时,逐个设置相关 FSDP 模块,不要把两类接口的递归习惯混用。

**默认平均已经包含累积次数。** FSDP 知道参与通信的 rank,并不知道这些 microbatch 各代表多少样本或 token。把 microbatch 数翻倍却不调整 loss 权重,得到的可能是更大的梯度,不是同一个大 batch 的平均。
