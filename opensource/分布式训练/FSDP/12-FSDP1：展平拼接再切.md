# FSDP1：展平拼接再切

这一页回答:旧实现为何先把参数拼成一根长条,以及这个选择怎样影响包装、冻结参数和 checkpoint。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

**模型按参数计算,通信却适合处理成组的连续数据。** 一组里既有矩阵也有向量,若让每个小参数各管一次分片与通信,调度会很零碎。FSDP1 把这组数据收进一根长条,由一个句柄统一管理。

难点随之出现:长条按 rank 等分,切口不必落在原参数之间。某张卡可能拿到一个参数的全部、另一个参数的一部分,还有一些参数完全不在本卡。计算、优化器和保存模型仍然需要认得原参数,实现就得维护“原参数在哪里”和“现在数据是否完整”这两层关系。

## 二、解法

FSDP1 的包装模块负责前后向入口,**长条参数负责存数据,长条句柄负责变形和搬运**。每个有受管参数的包装实例建立自己的长条:参数先展平拼接,再沿这一维切给各 rank。手动嵌套包装或自动包装策略,决定哪些模块归同一根长条。

计算前先 all-gather 完整长条,再按记下的形状和偏移把它还原成各参数的视图,原模块照常运行。完整分片策略下,非根组前向后释放完整存储,反向需要时再凑齐;根组保留完整存储以便紧接着反向。反向产生的长条梯度经 reduce-scatter 回到本地分片,供优化器更新。

![三个各有 8 个 FP32 元素的参数先拼成 24 元素长条,再由 2 个 rank 各拿 12 个元素,中间参数跨越切口;启用原参数视图后,rank 0 看到 A 的全部、B 的前半和空的 C,底层仍是同一段长条存储](/opensource/FSDP/12a-flat-boundary.svg)

保留原参数对象的选项改变的是**用户和优化器看到谁**,不是底层还展不展平。开启后,原参数对象还在,它的数据指向长条上的视图;完整态恢复原形状,分片态则可能是部分一维数据或空张量。这样可以按原参数分别设优化器超参数,但不能把对象还在误当作完整数据也一直在。

## 三、代价

**包装边界同时成为数据管理边界。** 包得太大,一次要还原的完整长条就大;包得太细,通信和 hook 调度又变碎。这里不是再选一种数学分片算法,而是在决定一根长条管多少参数。

冻结也受到这根长条约束。默认不保留原参数对象时,同一个实例管理的参数要么全冻结、要么全可训练。保留原参数对象后允许混合,但梯度内存可能高于只看可训练参数量的预期。支持混合不等于冻结区域的所有梯度存储开销都自动消失。

保存模型还要选择哪一种形态:原名下的完整参数、本地长条分片,或者原名下的参数分片。当前旧实现生成后一种时,会先还原完整参数,再按原参数切分输出。**训练态的长条分片与导出的逐参数分片不是同一布局**,不能因为都叫“分片”就认为保存一定不需要转换。具体读写与优化器状态处理见 11 章。

## 四、和同类常见做法不一样的地方

Megatron-LM 的 DDP 与分布式优化器路径同样使用连续 buffer,也保存参数在 buffer 里的区间,并让优化器处理参数分片。因此“把数据放连续”并不是 FSDP1 独有的选择。

FSDP1 更直接地把这根长条做成内部参数对象,让句柄在本地分片和完整存储之间切换,并在模块计算时装回参数视图。Megatron 的上述路径则围绕参数/梯度 buffer、bucket 与优化器分片管理这些范围。两边都维护映射,区别是映射附着在哪个对象以及谁驱动生命周期,不能把展平理解成原参数名字永久丢失。

## 五、调参与观测

包装和参数暴露方式在构造 FSDP1 时确定;state dict 类型在保存/加载前选择。这里使用 `torch.distributed.fsdp.FullyShardedDataParallel` 的别名 `FSDP`,各项 API 的迁移对应见 13 章。

| 参数或接口 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `auto_wrap_policy` | `FSDP(model, ...)` | `None`,不自动递归包装子模块 | 传 `ModuleWrapPolicy({BlockClass})` 按指定类包装,缩小每根长条范围 | 打印包装后的模块树,确认边界 |
| `size_based_auto_wrap_policy` 的 `min_num_params` | 构造包装策略,再传给 FSDP | `100000000` 个元素,不是字节 | 降低阈值可能产生更多包装实例,减小单组但增加调度 | 对照模块树、完整参数峰值与通信次数 |
| `use_orig_params` | FSDP 构造参数 | `False` | `True` 暴露原参数对象,允许逐参数超参数与混合冻结;底层仍展平 | 对照 `named_parameters()` 和分片态形状 |
| `sharding_strategy` | FSDP 构造参数 | 未指定时多 rank 用 `ShardingStrategy.FULL_SHARD`;单 rank 转为 `NO_SHARD` | 决定何时释放完整参数与是否分片,不改变本章“先展平”的主线 | profiler 的 all-gather 与参数驻留 |
| `FSDP.state_dict_type(...)` | 保存或加载前的上下文 | `StateDictType.FULL_STATE_DICT` | 选择下表三种形态;该接口已标记弃用,现有代码识别用,新流程见 11 章 | 检查键名、张量类型及保存时峰值 |

| state dict 类型 | 输出主要形态 | 为何需要转换 |
|---|---|---|
| `FULL_STATE_DICT` | 原参数名与完整形状 | 从长条分片聚合,恢复原参数视图并保留输出 |
| `LOCAL_STATE_DICT` | 本地展平分片,带分片元数据 | 保留训练长条布局;不是普通未包装模型的逐参数文件 |
| `SHARDED_STATE_DICT` | 原参数名下的分片张量 | 先还原长条及原参数,再导出逐参数分片;可用 ShardedTensor 或相应 DTensor 路径 |

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 旧训练栈中按 transformer block 控制聚合大小 | 用 `FSDP(model, auto_wrap_policy=ModuleWrapPolicy({BlockClass}))`,其中类替换成模型实际 block 类 | 更多包装边界换较小的单次完整参数驻留 |
| optimizer 要分别设置 bias/weight 超参数,或同组混合冻结 | 在上述构造中加 `use_orig_params=True`,包装完成后再按原参数建 optimizer | 保留参数身份与配置粒度,接受视图管理和可能更高的梯度内存 |
| 既有代码需要导出给普通未包装模型 | 用完整 state dict 形态,按 11 章安排 CPU offload 与 rank 0 输出 | 通用原名形态换聚合与保存内存,不直接拿本地长条文件加载 |

组合与推荐值是按语义推的起点,不是实测最优。

打印模型回答“包了哪些模块”,`named_parameters()` 回答“优化器会看到哪些对象”。需要核完整参数形状时用 `FSDP.summon_full_params(...)`,不要拿训练间隙的一维局部分片判定模型结构损坏。profiling 可从 `FullyShardedDataParallel.forward` 对齐包装入口,再看 all-gather、reduce-scatter 与显存。

| 症状 | 先查 | 然后 |
|---|---|---|
| 包装时提示 `requires_grad` 不一致 | 同一实例是否混合冻结且 `use_orig_params=False` | 按训练性拆开包装,或明确选择原参数模式并检查内存 |
| 开原参数模式后某参数大小为 0 | 本 rank 的长条区间是否覆盖该参数 | 在完整参数上下文核对,不要按空张量判断参数被删除 |
| 只有根包装,计算前显存突然升高 | 是否整个模型成为一根长条 | 按 block 核对包装边界,再量完整训练步峰值 |
| 分片保存仍触发 all-gather | 用的是逐参数分片形态还是本地长条形态 | 接受必要转换,按 11 章安排保存资源 |

## 六、常见误区

**保留原参数就等于禁用展平。** 名字让人容易把它理解成另一套分片算法;它实际保留的是对象身份,数据仍是长条的视图。依赖原二维形状的代码,不能随时在分片态读取本地数据。

**旧实现完全不能混合冻结参数。** 很多错误提示来自默认模式的统一训练性检查。开启原参数模式后可以混合,但还要评估梯度存储,不能只拿可训练参数占比预测峰值。

**内部参数叫长条,导出文件就只能有长条名字。** 完整与逐参数分片的 state dict hooks 会恢复原参数名并去掉包装前缀。先分清查看的是训练中的参数枚举,还是选定形态后的 state dict。

**checkpoint 写着分片,就等于直接存本卡数据。** 本地展平分片与逐参数分片的切口不同,后者需要转换。把保存时间突然变长都归因于磁盘,会漏掉保存前的聚合和重排。
