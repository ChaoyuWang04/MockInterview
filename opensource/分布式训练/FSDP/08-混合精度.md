# 混合精度:模块级的那一刀

这一页回答一件事:怎样让计算和参数通信吃到低精度的收益,又不把优化器更新和梯度归约绑死在同一种精度上。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

模型分片后放得下了,每步仍可能花很多时间在矩阵计算和参数 all-gather 上。只给算子套自动混合精度,并不会让 FSDP 聚合的参数自动变小;直接把整个模型转成低精度,又把优化器手里那份参数一起降了精度。

**计算时用什么精度,长期更新时保留什么精度,需要分开**。梯度归约还有自己的取舍:低精度传得少,但跨卡相加的舍入误差也随之进入训练。混合精度与 loss scaling 的通用原理见知识库《预训练流程》;这里讲 FSDP 在哪里做转换。

## 二、解法

最自然的办法是保留原始精度的参数,用之前临时转成低精度。FSDP 本来就常驻一份分片参数、临时聚合一份计算参数,因此**常驻的那份直接承担优化器更新,不用为混合精度再添一份高精度主参数**。

转换落在模块边界:浮点输入进入模块时转成计算精度,参数在 all-gather 之前转换,所以参数通信也受益;前向和反向使用计算参数,供反向保存的激活也能保持低精度。梯度则可以在归约前升精度,归约后转回原始参数精度交给优化器。模块内部仍可能有自己使用高精度累加的算子,模块策略不等于强制所有中间值同一种精度。

## 三、代价

升精度归约会增大梯度通信缓冲和传输量,但不会把参数 all-gather 一并升回去。收益与成本分属两条通信路径,不能看见计算用了低精度,就按同一个比例估算整步通信或总显存。

模块边界也成为精度契约。相邻模块若采用不同策略,输出和下一个模块的输入必须接得上;切出更多边界可能增加转换。低精度激活和参数带来的数值变化仍需用 loss 与验证指标检查,分片实现不替模型保证收敛。参数存储如何切换见 04 章,梯度累积与归约调度见 09 章。

## 四、和同类大厂框架不一样的地方

对照 Megatron-LM 的常规模型混合精度包装与梯度缓冲路径,不概括它另外的FSDP后端。

| 比较维度 | FSDP2 | Megatron-LM |
|---|---|---|
| 计算精度的转换边界 | 各分片模块分别声明计算和输出精度,沿临时参数聚合生命周期转换 | 常规包装先把模型转成低精度,在pipeline入口转换输入、出口按需升回精度 |
| 梯度归约精度 | 可独立于计算精度选择 | 梯度缓冲另有选项决定是否用高精度归约 |
| 优化器更新用的参数 | 直接更新原始精度分片,这份常驻参数就是更新用的那份 | 常规模型参数已转低精度,更新侧的精度管理由优化器路径承担,不能只看模型dtype判断 |

两边都能分开计算与归约精度。本章的重点是FSDP复用原始分片参数进行更新,而不是宣称只有它支持混合精度。

## 五、调参与观测

在训练代码调用 `fully_shard(module, mp_policy=...)` 时传入精度策略 `MixedPrecisionPolicy`。它是构造时的不可变配置;要换策略,重新构造分片模型与对应训练作业,不要直接改内部状态。

| 参数 | 在哪调 | 默认 | 调后影响与怎么看 |
|---|---|---|---|
| `param_dtype` | `MixedPrecisionPolicy` | `None`,沿用原参数 dtype | 改为低精度会改变完整参数、计算与参数 AG 的 dtype;在模块计算内部查权重 dtype,结合 profiler 看 AG 与计算耗时 |
| `reduce_dtype` | 同上 | `None`,使用计算产生的梯度 dtype | 设 `torch.float32` 可提高归约精度,代价是相对低精度归约更多通信与缓冲;查归约缓冲 dtype、RS 耗时与 loss 曲线 |
| `output_dtype` | 同上 | `None`,不额外转换输出 | 显式转换浮点输出以衔接下游;查模块输出 dtype 与 profiler 的 `FSDP::cast_forward_outputs` |
| `cast_forward_inputs` | 同上 | `True` | 配合非空 `param_dtype` 转换浮点输入;关掉后由调用方保证兼容,查输入 dtype 与 `FSDP::cast_forward_inputs` |

**先看清观测位置**。反向结束后,分片参数及其梯度的 dtype 是更新侧的读数,不能拿它证明计算或归约用了什么精度。需要区分模块内部输入/权重、输出、归约缓冲和更新侧参数。FSDP 已给输入与输出转换加了上述 profiler 标记;通信时间用 profiler 看,数值效果用固定数据与相同训练预算对照。

以下都假设模型原始参数是 `torch.float32`,已初始化进程组,并按 02 章逐层分片;把表中的调用用于各层,根模块最后处理,优化器在分片后创建。

| 场景 | 怎么配 | 拿什么换什么 |
|---|---|---|
| 支持 BF16 的 GPU,先核数值的 Transformer 训练 | `fully_shard(layer, mp_policy=MixedPrecisionPolicy(param_dtype=torch.bfloat16, reduce_dtype=torch.float32))` | 计算与 AG 用 BF16,保留 FP32 归约;以更大的梯度通信换归约精度,也是配图实例 |
| 同类硬件,已通过低精度数值对照且梯度通信明显暴露 | `fully_shard(layer, mp_policy=MixedPrecisionPolicy(param_dtype=torch.bfloat16))` | 归约跟随 BF16,继续缩小通信;接受归约舍入变化并监测验证指标 |
| 在相同模型上定位混合精度引入的差异 | `fully_shard(layer, mp_policy=MixedPrecisionPolicy())` | 沿用原始 FP32,作为更高计算与通信开销的对照组 |

组合与推荐值是按语义推的起点,不是实测最优。

| 症状 | 先查 | 然后 |
|---|---|---|
| 设了低精度计算,归约仍比预想慢 | `reduce_dtype` 是否显式设成 FP32,profiler 中 RS 是否暴露 | 数值允许时对照低精度归约,不要为此改参数原始 dtype |
| 某层出现输入与权重 dtype 不匹配 | 这一层是否关了输入转换,上游是否转换了输出 | 在模块边界补齐契约,检查实际张量而非只看根模块策略 |
| 以为保留了 FP32 更新,实际参数仍是 BF16 | 是否在分片之前就把模型整体转成 BF16 | 从原始 FP32 参数构造混合精度作业;策略不会凭空恢复已丢掉的精度 |
| 换 FP16 后出现零梯度或非有限梯度 | loss scaling 是否由训练循环显式管理,异常在计算还是归约产生 | 先定位数值源头;按知识库流程处理缩放与溢出,别只调归约 dtype |

## 六、常见误区

**看到 `reduce_dtype=None` 就以为是 FP32**。因为更新侧梯度最后确实可能是 FP32,只在 `backward()` 后打印它很容易得出这个结论。实际留空会沿用计算梯度的 dtype;想要 FP32 归约必须明确指定。

**把 BF16 和 FP16 当成只换名字的配方**。二者都是低精度,但数值范围不同。BF16 通常不需要 FP16 那套 loss scaling,也不意味着不会出现 NaN;FP16 的缩放仍由训练循环负责。FSDP 的 `MixedPrecisionPolicy` 只声明 dtype 与边界转换,不会自动替你缩放 loss 或跳过更新。

**沿用 FSDP1 的整份混精配置**。旧配置 `MixedPrecision` 还管 buffer dtype、是否保留低精度梯度和根模块输入转换,字段看起来相近却不是同一个对象。`ShardedGradScaler` 也要显式在训练循环里调用,不能因为导入了它就以为缩放已启用;两代字段迁移见 13 章。
