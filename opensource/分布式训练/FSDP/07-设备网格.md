# mesh:分到哪一层为止

这一页回答一件事:分片应该铺满所有卡,还是只铺在通信最快的一组卡里。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

模型从单机搬到多机,最自然的做法是继续把所有卡排成一组。常驻分片更小了,但每个通信组的参数 all-gather 也开始跨节点;节点间链路慢时,前后向就会反复等参数。加卡省下的显存,可能换成更长的每步时间。

这里要决定的不是再切哪一层模型,而是**每次凑齐参数,究竟要找哪些卡**。DP、TP、EP 的通用分工见知识库「并行策略」,本章只看 FSDP 怎样划这条边界。

## 二、解法

FSDP 用设备网格把卡排成逻辑上的行和列,每个方向对应一组参与通信的 rank。默认的一维网格沿唯一方向分片;二维 HSDP 则让每一行独立分片,同一列保留相同分片的副本。参数只在行内凑齐,梯度除了行内 reduce-scatter,还要在列间同步,才能让副本更新一致。

**小组足以装下模型,就有机会把反复发生的参数聚合留在快链路内**。下图把每一行放在同一个节点上;这是显式安排 rank 的结果,网格本身不会替你发现网络拓扑。

![8 张卡按 2 行 4 列排列,行内 4 张卡各持参数的四分之一并做参数聚合与梯度分片,列间相同分片的副本同步梯度;若将 8 张卡排成一维,参数聚合也会跨节点](/opensource/FSDP/07a-mesh-boundaries.svg)

与 TP 或 EP 组合时,逻辑网格还可以包含模型并行方向。FSDP 只接管指定的数据并行方向,保留参数已有的其他分布。因而「凑齐」是补回 FSDP 切掉的部分,不是把 TP 或 EP 也撤掉。已有模型并行的参数如何接入,有子网格与完整命名网格两条路径,入口要求见第五节。

还有一个边界情况:完全不切参数,只复制。源码另有复用 FSDP 参数组与 hooks 的纯复制入口,让这套运行机制也能服务复制式数据并行;它不是普通 DDP 的默认实现。

## 三、代价

缩小分片范围会增加每卡常驻的参数、梯度与优化器状态。图中共有 8 张卡,但每行只有 4 张参与分片,均匀分片时每卡留的是 1/4,而不是 1/8。**这里的 N 是分片维大小,不是整个作业的卡数**。叠加模型并行后,还要先区分模型并行本来分给本卡的部分。

跨节点通信也没有消失。HSDP 仍要沿复制方向同步梯度,只是参数聚合不必再走这个方向。是否更快取决于节点内外的带宽、分组大小和计算时间;本章不承诺换成二维就一定提速。前向后保留多少参数属于 06 章,梯度通信如何执行属于 09 章。

组合的代价则是分布必须事先对齐。网格的 rank 排布、维名和参数的 DTensor 分布不能各说各话;能写出一张高维网格,不代表任意模型与 TP、EP 组合都已得到支持。

## 四、和同类常见做法不一样的地方

Megatron-LM 在基准 fb6a123a09 中,按各并行度与 rank 排列顺序生成训练所需的进程组,并为普通参数与专家参数分别生成拓扑。它把「哪些卡一起工作」放在训练框架的并行初始化中统筹。

FSDP 接收的是调用方交来的网格,再从中取出分片与复制的通信范围。这让模块可以接到已有的模型并行布局上,但调用方也要保证参数已经按那套布局分布好。区别在于拓扑由谁组织,不是谁能随意组合更多并行方式。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数或入口 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `mesh` | `fully_shard` 调用 | `None`,按默认进程组大小建一维网格 | 改变分片参与者;不传 `dp_mesh_dims` 时,二维按第 0 维复制、第 1 维分片 | 打印 `mesh.mesh`、`mesh.get_coordinate()` 与各维进程组 |
| `mesh_shape`、`mesh_dim_names` | `init_device_mesh` | 形状必填,维名默认 `None`;HSDP 二维网格要求有维名 | 形状决定各轴大小;维名供切子网格或指定 DP 轴使用 | 核对每个 rank 的网格内容一致,再核对 rank 到物理节点的映射 |
| `dp_mesh_dims` | `fully_shard` 调用 | `None` | 用 `DataParallelMeshDims` 指明完整网格里哪些轴归 FSDP 管,适合已分布的 DTensor 参数 | 查看 `param.device_mesh` 与 `param.placements`,确认其他并行轴保留 |
| `shard`、`replicate` | `DataParallelMeshDims` | 均为 `None`,至少指定一个 | 分别选分片轴、复制轴;多个轴名会各自展平成一个通信方向 | 按所选分片轴大小的乘积算 N,不要拿完整网格大小代入 |
| `replicate` | `torch.distributed._composable.replicate_with_fsdp` 的独立入口 | 网格默认是一维全局复制网格 | 复用 FSDP 运行机制但不切参数,每卡参数驻留更大 | 参数 placement 为 `Replicate()`;不要与另一模块中的同名入口混用 |

命名 DP 轴的路径要求参数预先成为**同一张完整网格上的 DTensor**,且接入前选中的 DP 轴是 `Replicate()`。这里的完整网格包括所需的 TP、EP 等方向,不含 PP;不要一边传完整网格的维名,一边只给参数配置 TP 子网格。传统子网格路径则从参数已有的 TP/EP DTensor 分布与传入的 DP 网格组成布局。两条路径都必须满足各自的分布约束。

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单机 8 张 CUDA GPU,仅数据并行分片 | `init_device_mesh("cuda", (8,), mesh_dim_names=("shard",))`,逐层与根模块使用同一 `mesh` | 8 卡均匀分片,参数聚合覆盖全机 |
| 2 节点各 4 张 CUDA GPU,节点内快、节点间慢,4 卡分片能装下模型 | 保证 rank 0–3、4–7 分别在同一节点;用 `init_device_mesh("cuda", (2, 4), mesh_dim_names=("replicate", "shard"))` 作为 `mesh` | 每卡常驻 1/4 而非 1/8,换取参数聚合留在节点内;节点间仍同步梯度 |
| 已有 4 路 DP × 2 路 TP 的 CUDA 作业,参数已在完整网格上分布 | 完整网格命名为 `("dp", "tp")`,传 `mesh=world_mesh` 与 `dp_mesh_dims=DataParallelMeshDims(shard="dp")`;接入前参数在 DP 轴为 `Replicate()` | 保留 TP 分布,再沿 DP 轴分片;需先确认模型的 TP 路径可用 |

组合与推荐值是按语义推的起点,不是实测最优。

观测先看**参与者**,再看耗时。打印网格与参数的本地形状 `param.to_local().shape`,确认谁持有同一分片;再用 profiler 区分参数 all-gather 与复制轴的梯度 all-reduce。只看全作业 NCCL 总耗时,无法判断是哪一个方向拖慢了迭代。

| 症状 | 先查 | 然后 |
|---|---|---|
| 改二维后仍在跨节点聚合参数 | 分片轴实际包含哪些 rank,这些 rank 在哪台机器 | 修正 rank 排布或网格,维名叫 `shard` 不会自动绑定节点内链路 |
| 8 卡 HSDP 的常驻分片比预计大 | 是否把 2 × 4 的总卡数误当成 N | 按分片轴 4 卡重算,再判断显存是否足以采用 HSDP |
| 加上 `dp_mesh_dims` 后初始化报普通张量或 mesh 不匹配 | 参数是否已经是同一完整网格上的 DTensor | 对齐预分布与入口,不要只补维名 |
| 建网格或首次通信挂住 | 各 rank 是否构造了相同网格、是否进入相同调用 | 先统一 rank 列表与调用顺序,再排查网络 |

## 六、常见误区

**按名字猜方向**。看到网格维名写着分片和复制,容易以为顺序随意。未传 `dp_mesh_dims` 的二维入口按轴位置解释:第 0 维复制、第 1 维分片;换名字不能换语义。先确认形状与 rank 分组,再起名字。

**以为 all-gather 后拿回了整个模型参数**。在纯 FSDP 下这个直觉成立,搬到 TP/EP 组合后却会把本地形状看错。FSDP 撤回的是自己的分片,已有模型并行分布仍在,应该对照接入前的 DTensor 分布检查。

**把两个 `replicate` 当成同一个东西**。它们都做复制式数据并行,名字也一样,但普通 composable `replicate` 内部构建 `DistributedDataParallel`,本章的 `replicate_with_fsdp` 复用 FSDP 参数组。看调用名无法确认路径,要核对 import 来源;也不要从纯复制入口推导 FSDP 默认不分片。
