## 二、一句话核心

FSDP 解决的是**一张卡装不下模型**:把参数、梯度、优化器状态按数据并行的卡数切开,算之前把要用的那一段临时拼回来,算完立刻扔掉。

代码花在哪(只算 `.py`,不含测试):

| 部分 | 行数 | 说明 |
|---|---|---|
| `torch/distributed/fsdp/_fully_shard/` | 6107 | FSDP2,9 个文件 |
| `torch/distributed/fsdp/*.py` | 15018 | FSDP1,21 个文件 |
| 合计 | 21125 | 整个 fsdp 包 |

**最值得记住的一个对比**:FSDP2 用 6107 行做到了 FSDP1 用 15018 行做的事,而且两者今天并存在同一个包里、由同一个 `__init__.py` 导出,`__all__` 里明写 `# FSDP1` 与 `# FSDP2` 两组(`fsdp/__init__.py:33-72`)。

## 三、主张清单

采集自官方文档、RFC 与源码里的设计理由注释。每条标出处。

| # | 主张 | 出处 |
|---|---|---|
| 1 | 按参数逐个在 dim-0 切,取代 flat parameter;目标是 fp8 all-gather、冻结与非冻结同组、无通信的 sharded state dict、给编译留口子 | RFC「[RFC] Per-Parameter-Sharding FSDP」,pytorch/pytorch#114299 |
| 2 | 用户契约七条:初始化时把参数原地换成 DTensor;前后向的 hook 负责 all-gather 与释放;优化器必须吃 DTensor 参数;要走 `model(input)` 不走 `model.forward(input)`;自底向上包;`type(model)` 被原地 union 成 FSDP 子类;参数的完整名不变 | `docs/source/distributed.fsdp.fully_shard.md:14-56` |
| 3 | 每次调用分片入口构成一个**通信组**;组内参数一次 all-gather、梯度一次 reduce-scatter;**没有按字节算的自动攒批**,组边界完全由你包了哪些模块决定 | 同上 `:58-67` |
| 4 | 只包根模块 = 两次巨大的阻塞通信、零重叠,「几乎不会是你想要的」 | 同上 `:80-83` |
| 5 | 前向:all-gather 走独立流,靠 CPU 领先 GPU 让下一个组的 all-gather 与当前组的计算重叠;领先不够时可以手动把预取提前一个 hook | 同上 `:85-110` |
| 6 | 反向:额外**显式**预取下一个组的 all-gather,reduce-scatter 再走一条独立流,不需要额外配置 | 同上 `:112-129` |
| 7 | 与 FSDP1 的四处不同:①DTensor 逐参数分片 vs flat 展平拼接再切;②换了一套多流显存管理,不用 `record_stream`,因此不必像 FSDP1 那样阻塞 CPU;③开放手动预取与调度 API;④不直接提供 full state dict,要自己用 DTensor 接口或走 DCP | 同上 `:139-165` |
| 8 | 模块级混合精度而非 op 级:低精度激活存给反向,高低精度转换只发生在模块边界;FSDP 本来就常驻高精度分片参数,所以优化器不需要额外的主权重副本 | `_fully_shard/_fsdp_api.py:14-22` |
| 9 | FSDP 眼里有五种张量:原始参数、分片参数、all-gather 输入、all-gather 输出、完整参数;中间留了 pre/post-all-gather 变换的口子,量化扩展可以有多个输入输出(量化数据加 scale) | `_fully_shard/_fsdp_param.py:66-92`,[Note: FSDP tensors] |
| 10 | 完整参数要反复释放和分配,而 autograd 可能存了它的引用或视图,所以用**改存储大小**来实现释放,以保住别名关系;完整参数对象只构造一次,之后一律原地写 | 同上 `:93-101`,[Note: FSDP and autograd] |
| 11 | 隐式前向预取要让下一个组的拷入与当前组的 all-gather 重叠,为此单开一条拷入流,并让下一个组负责释放上一个组的输出 | `_fully_shard/_fsdp_param_group.py:63-71`,[Note: Overlapping all-gather copy-in and all-gather] |
| 12 | 分片入口可以一次收一组模块,用于分块算损失那类「主前向只跑一半、另一半按块反复调」的写法;代价是每次独立调用各自注册一个反向节点,N 块就是 N 次 reduce-scatter | `_fully_shard/_fully_shard.py:141-160` |
| 13 | 前向或反向抛异常后,每轮迭代的状态处于未定义状态,要重跑必须先在根模块上重置 | 同上 `:161-169` |

## 四、候选章表(带把握程度)

把握:**高** = 有官方文档或 RFC 背书且读过入口代码;**中** = 读了目录与类清单、关键函数;**低** = 只看过体量与符号名。

| 章 | 名 | 这一章的核心问题(哪个场景下哪个指标会坏) | 把握 |
|---|---|---|---|
| 01 | 一次迭代的形状 | 参数加梯度加优化器状态装不下一张卡:直接 OOM,连第一步都跑不起来 | 高 |
| 02 | 通信组:包在哪里决定一切 | 只包根模块:通信退化成两次巨大的阻塞操作,零重叠,显存峰值等于整个模型 | 高 |
| 03 | 重叠:三条流与预取 | CPU 领先 GPU 不够多时(层小、host 端开销大),all-gather 暴露在关键路径上,吞吐掉一截 | 高 |
| 04 | 参数的五种形态 | 完整参数必须反复释放才省得下显存,而 autograd 存了它的视图:释放就崩 | 高 |
| 05 | 初始化:先切开再填数 | 模型大到完整实例化一份就爆内存,或者初始化要等几十分钟才开始第一步 | 中 |
| 06 | 拿什么换显存 | 前向后立刻重分片省显存但反向要重来一次 all-gather;不重分片省通信但显存顶不住 | 高 |
| 07 | mesh:分到哪一层为止 | 跨节点全局分片时 all-gather 走慢链路;模型不大却切到几百张卡,通信占比压过计算 | 中 |
| 08 | 混合精度:模块级的那一刀 | 低精度算得快但梯度归约会掉精度;按 op 自动转换则省不到通信量 | 高 |
| 09 | 梯度归约 | 梯度累积时每个微批都归约一次,白白多出几倍通信;低精度下求和还会溢出 | 中 |
| 10 | 通信原语可替换 | 通信缓冲每次现分配,显存碎片与抖动;默认路径走不到硬件的最优 all-gather | 中 |
| 11 | 断点:存下来还要读得回去 | 存断点时把参数全量聚合到一张卡:爆显存;换了并行度之后旧断点读不回来 | 高 |
| 12 | FSDP1:flat parameter 那一套 | 展平拼接再切之后,「这张卡上到底是哪几个参数的哪一段」说不清,冻结参数、换并行度、存分片断点全都别扭 | 中 |
| 13 | 迁移与共存 | 同一个训练框架里两套 API 都活着,默认走的还是老那套:排障时先要知道自己在哪一套上 | 高 |

## 六、已定口径与待查

**已定(2026-09-20 用户拍板,序章过门时一并给的)**:

1. **参照项目一事不争。**各章第四段只做合理对比——和同类常见做法、和旧实现不一样的地方,能核到的才写,核不动就不写。页头不回指任何别的项目,只用一句话定位本章要解决的问题。重点放在把 FSDP 自己讲透。
2. **每章至少一张图,需要时 2–3 张,不得泛滥。**这是派章时对子 Agent 的硬要求,写进派章提示词。注意它与 06 现行的「每章最多两张;这是上限不是配额,零张也是合法答案」相左——**以本条为准**,是否把它改进 06 变成全库规则,用户另行决定。画之前仍要过 06 的「这件事有形状吗」那一关:够不到判据的,换一个角度找到有形状的那一面再画,不要拿装饰凑数。
3. **第五段开头不用 06 的那句模板。**06 给的是「这一页的参数全是启动配置,改了要重新拉起整个作业」,这话在 FSDP 上是错的:新实现有一整套可以在两轮之间改的方法。**各章自己写一句准确的开场,不要跨章复用同一句**(复用会被 lint 当成跨章重复,而它不在白名单里)。
4. **第四段的对比对象定为 Megatron-LM**(2026-09-20 用户拍板,那时它的序章刚成稿)。它的基准快照在 `/tmp/megatron-base`,基准 commit `fb6a123a09f524a2abfca81a78b6478358ca77e0`,最近发布 tag `core_v0.19.2`,22 MB。**关于它的每一条断言都必须在那份快照上核过,核不动就不写**;`opensource/分布式训练/Megatron-LM/` 是另一条线的在建工作,只读不改,它的序章只用来定位、不当事实来源。**重点仍在 FSDP 自己这一边**:第四段是对比,不是并排介绍两个框架,更不写谁比谁好。
   - 各章最相关的对比面:02 与 03 看 `megatron/core/distributed/`(连续缓冲区、按字节分桶、两个重叠开关);04 看 `param_and_grad_buffer.py` 与 `optimizer/distrib_optimizer.py`(连续缓冲区加偏移量 vs 逐参数分布式张量);05 看 `tensor_parallel/layers.py` 与模块规格装配(按并行度直接建,不存在「先完整实例化再切」)。
   - **已核过、可直接引用的几条**:它的数据并行默认只把梯度铺进连续缓冲区并按桶归约,参数与优化器状态每卡各一整份(`distributed/distributed_data_parallel.py:87-107`);分布式优化器默认关(`distributed/distributed_data_parallel_config.py:33`),开了之后把优化器状态沿数据并行维切片(`optimizer/distrib_optimizer.py:113-118`),更新完再聚合参数,可与下一次前向重叠(`optimizer/distrib_optimizer.py:3202-3232`);桶大小是一个可调阈值(`distributed/distributed_data_parallel_config.py:52`);它是标准的包装写法,把模型存成自己的子模块(`distributed/data_parallel_base.py:11-22`);它自己另有两条全分片路线(`distributed/fsdp/`、`distributed/torch_fully_sharded_data_parallel.py`)。
   - **01 章的第四段已于 2026-09-20 按这条改写**,原先写的是与老一代和纯数据并行的对比;改写后的版本是各章第四段的写法样板。
   - **派发时给过一条错口径,已纠正**:我在 02–05 的派章提示词里写 Megatron 是「按字节分桶」,02 章去核之后报回来说不对——阈值数的是**参数元素个数**,默认 `max(40000000, 1000000 × dp_size)` 个元素(`distributed/distributed_data_parallel_config.py:52-56`、`distributed_data_parallel.py:131-137`)。01 章第四段里我写的「按字节划」已改成「按容量划(数的是参数个数,不是字节)」。**教训**:派发提示词里给的事实同样要先核,子 agent 会当前提用;守则的口径是「核出别的就写核到的」,这次子 agent 处理对了。
   - **另一条已核实的 Megatron 事实,后面几章可直接引用**:梯度归约重叠默认关,而这个开关一关,桶容量阈值会被直接置空、整块缓冲区退化成一个桶;不是第一个流水段的模型块也一样被置空(`distributed/distributed_data_parallel.py:135-137,176-177`)。所以「Megatron 默认按桶重叠」这个印象是错的,**它默认既不分桶也不重叠**。
