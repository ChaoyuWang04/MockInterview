# 初始化:先切开再填数

这一页回答一件事:一份单卡装不下的模型,第一个模型对象是怎么建出来的。说法都在源码基准 `217579124a`(main,仓库自报 `2.15.0a0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

分片是训练循环里的事。可在循环开始之前,你得先有一个模型对象——而按最自然的写法,建这个对象就是把全部参数原原本本地造出来一遍,每个进程各造一份。模型一大,进程刚起来就死在这一行:还没来得及切,就已经装不下了。

退到主机内存里建并不解决问题,只是换了个地方装不下。同一台机器上的每个进程各造一整份,主机内存先顶不住;就算顶得住,随机初始化和主机到卡的搬运也要按完整一份的量,每个进程各做一遍。源码注释把取舍写得很直白:FSDP 宁可自己负责把参数搬上卡,图的就是初始化更简单也更快。老一代那条路上还专门留了一句警告,提醒你不指定设备的话,切分这一步会落在主机内存上做,比在卡上慢。

这两种坏法都发生在第一步之前。日志停在模型构造那几行,profiler 还没开始记,看上去像卡死。

## 二、解法

把顺序倒过来:**先决定每张卡该拿哪一段,再让每张卡只为自己那一段分配内存、写初值。**

第一步,在一个只记形状、不分配数据的设备上把模型搭出来。模块结构、参数对象、形状和精度全都在,就是没有任何字节——模型再大,这一步也几乎不占内存。

第二步,照常自底向上调分片入口。它对这类参数网开一面:搬设备那一步直接跳过,让它们留在原地。切分照常做,因为切分本来就是纯形状运算——切成几段、本卡拿第几段、按哪一维切、补多少对齐,全都只需要形状和网格。这一步走完,每张卡手上已经是一个说得清「本卡持有哪一段」的分布式张量,只是这一段还没有数据。

第三步才是填数:在已经切好的参数上分配内存、写初值。分配的是本卡那一段的大小,完整形状始终只是写在张量身上的一条元数据,从头到尾没有被兑现成真实内存。

**分片初始化需要协调随机数**:在受支持的 DTensor 随机操作中,框架按分片位置设置随机数流偏移,操作后再推进各 rank 的状态。各 rank 应设置一致的种子并执行一致的初始化流程;这不等于任意设备、随机算子或自定义初始化都与普通单卡逐元素相同。

![三条初始化路线的对照图,左边一列是三条路线都必须做的四件事(搭出结构与参数对象、定下本卡持有哪一段、为本卡那一段分配内存、写入初值),右边三列分别是先切开再填数、先造好再切开、生来就是切好的三条路线,每一格标出这条路线把这件事排在第几步并画出此刻卡上有多少数据:第一条路线前两步都是空心虚框表示只有形状没有字节,第二条路线的写入初值那一格是一整条紫色的完整参数,第三条路线的四件事合成一格,一上来就是一小段实心的本卡分片](/opensource/FSDP/05a-three-init-orders.svg)

## 三、代价

**填数是你的活,框架只负责查**。分片入口不分配也不写初值;它只在第一次前向时检查一遍,发现还有参数停在那个不分配数据的设备上就报错,并在错误信息里直接写出该调哪两个方法。换句话说,建模型那一步犯的错,要到第一次前向才暴露。

**每个模块都得能单独重来一遍**。填数是按模块逐个调「重新初始化我自己这几个参数」来做的,而且约定是只管自己、不碰子模块。PyTorch 自带的层都有这个方法;自己写的层、从论文仓库里抄来的层经常把初值写死在构造函数里,这条路上就用不了,得补。

**依赖数值的初始化要往后挪**。放弃了构造函数里的初值,也就放弃了那里能做的一切:按别的参数算出来的初值、按数据统计量定下来的初值,在这一步都还没有材料。上游把这种情况当成正常用法处理——首轮那次内部初始化被特意做成可以重复执行的,允许你在分片之后、第一次前向之前再改参数、再注册参数。

**缓冲区不在保护范围里**。分片入口管的是参数:搬设备的时候顺手把缓冲区一起搬走,但不切它们,首轮那次检查也只数参数。于是留在不分配数据的设备上的缓冲区不会被拦下来,要到真正用到它的那一步才炸,报的还是一个跟初始化看不出关系的错。

**搬到主机内存那条路要连着改**。开了这条路之后,分片参数必须落在主机内存上,填数那一步就得填到主机内存而不是卡上;这一条同样是首轮才检查。

## 四、和同类常见做法不一样的地方

对比对象仍取 Megatron-LM。同一个问题——第一份模型对象怎么来——两边走的不是一条路。下面每条都核在它 2026-09-20 主干的那份代码上,基准 fb6a123a09。

**一个先不造,一个根本不造整份**。Megatron 的并行层在构造函数里就把本卡该拿的尺寸算出来,直接按这个尺寸分配,而且直接分配在当前卡上;流水段则决定这张卡建几层。这条 GPU TP 并行层路径直接创建本地权重分片;它也有下文所述先建 CPU master weight 的另一条路径。代价是模型必须用它那套并行层写出来,尺寸怎么算和并行度绑死在一起,换个并行度就是换一组对象。

**随机数两边都得特殊处理,处理的位置不同**。那边在初始化并行层权重时分叉出一份独立的随机数状态,让同一个张量的不同分片各抽各的;这边把偏移算进分布式张量,每张卡去取整条随机数流上属于自己那一段。前者使用并行随机数状态,后者由 DTensor 协调分片位置与随机数偏移;一致性需在所用初始化路径上核对。

**想让初值与并行度无关,那边要付一次完整实例化**。Megatron 另外留了一条在主机上初始化的路:每个进程各自把完整权重造出来、初始化好,再切下自己那一块。注释写得很直白,就是「在所有进程上建出主权重,再分发对应的那一块」。这正是这一章要绕开的那件事,而它换来的是初值不随并行度变化。

**它自己那两条全分片路线,一条先造后切,一条根本不碰这件事**。Megatron 自带一套全分片实现,同样支持不分配数据的设备,但顺序和这边正相反:包每一个分片单元之前,先把这个单元的参数在卡上造出来、调一次重新初始化,然后才切。原因写在注释里——某些第三方层的重新初始化会把参数对象整个换掉,所以必须让分片看到最终那一批对象。于是它的峰值是「一个单元的完整参数」,而不是零。另一条路线直接调这边的分片入口,它接手的是一个已经按并行度建好、已经躺在卡上的模型,不分配数据的设备那条线在它这里根本用不上。

## 五、调参与观测

这一页几乎没有旋钮。起模型是一段有固定顺序的代码——在哪个设备上建、什么时候切、什么时候填数——顺序对不对靠第一次前向的几处检查兜底,而不是靠开关。所以下面三张表分别是:分片入口里和初始化有关的那几个参数、这条路上你要亲手做的几个动作,以及老一代用来做同一件事的三个构造参数。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `mesh` | 分片入口 | 不传就按当前默认进程组的大小现搭一张一维网格;进程组还没初始化时顺手初始化一次 | 网格的设备类型加当前卡号决定参数被搬到哪里,也决定切给哪些卡 | 打印参数,网格与切法写在它身上 |
| `ignored_params` | 分片入口 | `None` | 列进去的参数不切、初始化时不搬设备、反向不归约;一个模块的参数全被列进去、它自己没有缓冲区、子模块也全被排除时,这个模块整个从管辖范围里摘掉 | 打印这些参数,它们仍是普通张量 |
| `offload_policy` | 分片入口 | 不 offload | 开了之后分片参数必须在主机内存上,填数那一步要填到主机内存 | 首轮前向检查,不对就报错并列出参数名 |
| `dp_mesh_dims` | 分片入口 | `None` | 把传进去的网格当成整张并行网格,按维名挑出数据并行那几维;给了它就不再按一维或二维校验 | 维名对不上会直接报错;详见 07 章 |

这条路上你要亲手做的几件事:

| 动作 | 怎么做 | 什么时候 |
|---|---|---|
| 各 rank 对齐随机数 | 每个 rank 各调一次 `torch.manual_seed()`,种子相同 | 建模型之前 |
| 在不分配数据的设备上建模型 | 用 `with torch.device("meta"):` 包住模型构造,或用模块自己的设备参数 | 分片之前 |
| 给分片后的参数分配本卡那一段 | `model.to_empty(device=...)` | 分片之后 |
| 写初值 | 逐个模块调 `reset_parameters()`,或自己写一个按模块类型分派的初始化函数 | `to_empty` 之后 |
| 改成从已有权重起 | 跳过上面两步,用分布式checkpoint接口把分片权重直接读进来 | 分片之后;详见 11 章 |

老一代用三个构造参数做同一件事,它们在新实现里一个都没有:

| 老一代的参数 | 它做什么 | 新实现里怎么办 |
|---|---|---|
| `param_init_fn` | 包装时对每个停在无数据设备上的模块调一次,由你按模块类型分派;不给就退回去调模块自己的 `reset_parameters()` | 没有。分片之后自己遍历模块调 |
| `device_id` | 指定初始化与切分在哪张卡上做;不给就在主机内存上切,而且会警告 | 没有。设备由网格的设备类型加当前卡号算出来 |
| `sync_module_states` | 构造时从 0 号 rank 把参数与缓冲区广播一遍,代价是构造函数里多一趟通信 | 没有。靠各 rank 同一个种子,或者从checkpoint读 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 从零开始训,模型单卡装不下 | 在不分配数据的设备上建模型,自底向上分片,`to_empty` 到本卡,逐模块调 `reset_parameters()` | 峰值只到切开之后的那一份,换来的是每个模块都必须有能单独重来一遍的初始化方法 |
| 接着已有权重训,模型单卡装不下 | 前两步同上,第三步换成用分布式checkpoint接口直接读分片权重 | 连随机初始化都省了,由兼容的加载路径按目标网格恢复,不要求保存时和加载时分片方式完全相同 |
| 模型单卡装得下,只想起得快一点 | 照常在卡上建模型再分片,`mesh` 与其余参数全默认 | 少两道手续,换来的是初始化峰值等于完整一份 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:起到哪一步了——分片之后、填数之前打印任意一个参数,它的设备类型应该还是那个不分配数据的,填完之后才变成卡。初值对不对——在受控输入与相同初始化流程下核对聚合参数或输出,不要仅凭各 rank 的局部 loss 判断。显存对不对——填完数那一刻的显存应该约等于参数总量除以分片维的大小,明显高出说明有模块没走这条路,多半是它在构造函数里就把数据分配了。

| 症状 | 先查 | 然后 |
|---|---|---|
| 首轮前向报参数还停在无数据设备上,并把参数名列了出来 | 这些参数属于哪些模块 | 给这些模块补一个只初始化自己那几个参数的方法,或者在填数那一步手工处理 |
| 报某个模块没有可调用的重新初始化方法 | 这个模块是不是自己写的,初值是不是写在构造函数里 | 补一个 `reset_parameters()`,只管自己不碰子模块 |
| 填完就跑,loss 从第一步起就是噪声,而且一个错都不报 | 是不是只分配了内存,没写初值 | `to_empty` 之后补上初始化那一步 |
| 相同初始化流程下,聚合参数或相同输入的输出不符合预期 | 各 rank 的种子、初始化顺序和随机操作是否受支持 | 修正初始化流程;不同训练样本的局部 loss 本来就可能不同 |
| 报某个参数已经被另一个组管着 | 是不是共享权重,比如词表嵌入与输出投影绑在一起 | 把这两个模块放进同一次分片调用 |
| 报不支持零维参数 | 有没有把某个可学习系数写成了标量 | 改成长度为 1 的一维参数 |
| 报不支持没实现前向的容器 | 是不是直接在 `nn.ModuleList` 或 `nn.ModuleDict` 上调了分片入口 | 改成调它里面的模块,或者调包着它的那个模块 |
| 开了 offload 之后首轮报参数不在主机内存 | 填数那一步填到哪去了 | 填到主机内存 |

## 六、常见误区

**以为分片入口会顺手把模型建出来**。它只换参数的身份,不分配也不填数。在不分配数据的设备上建完模型、调完分片就直接进训练循环,是这条路上第一种翻法——而报错要等到第一次前向,那时候你已经过了数据加载、优化器构造好几步,回头找原因容易找偏。

**以为分配了内存就是填了数**。错误信息里写的是两件事:先分配,再初始化。只做前一半不会有任何抱怨,因为首轮那次检查只看参数还在不在那个不分配数据的设备上,不看里面是什么。于是训练照跑,loss 从第一步起就是噪声,你多半要到看曲线时才开始怀疑权重。**这条路上最贵的错是不报错的那一种。**

**以为每个模块都有能单独重来一遍的初始化方法**。PyTorch 自带的层有,而且严格只管自己那几个参数。自己写的层、从论文仓库里抄来的层十有八九把初值写在构造函数里,在不分配数据的设备上建出来就是一片未定义内存。填数那一步逐个模块调过去,碰到没有这个方法的会直接报错——它至少会报,比上一条好。

**以为各卡的初值会自动对齐**。FSDP2 没有构造时广播完整参数的开关。老一代有一个从 0 号 rank 广播的开关,新实现连这个开关都没了。分片参数各卡各一段、各抽各的,靠的是各 rank 的随机数状态本来就同步。第一次在分片参数上抽随机数时底下确实还有一层兜底,会把 0 号 rank 的状态广播一遍,但它同时会警告说这个兜底是要去掉的,让你自己在每个 rank 上设同一个种子。

**以为缓冲区跟着一起处理了**。分片入口把缓冲区搬设备,但不切它们;首轮那次检查也只数参数,不数缓冲区。掩码、位置编码那几张常量表留在不分配数据的设备上不会被拦,要到真正用到的那一步才炸,报的是一个和初始化看不出关系的错。

**以为绑在一起的权重会被自动处理**。词表嵌入和输出投影共享一份权重是常见写法,两个模块被分进两次不同的分片调用就会出事;该怎么办是 02 章的事。放在这里说是因为它的形状和这一章别的坑一模一样:错犯在建模型那一步,报在第一次前向,中间隔着好几步。
