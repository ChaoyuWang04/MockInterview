# FSDP 总览

源码基准:官方仓库 <https://github.com/pytorch/pytorch>,分支 `main`,commit `217579124a28a51d623935fa5e414a6e93d3488a`,最近的正式发布 tag `v2.14.0`(仓库自报版本 `2.15.0a0`),核对日期 2026-09-20。全篇的「当前」「默认」都指这组基准。FSDP 不是独立仓库,源码是 pytorch 仓里的 `torch/distributed/fsdp/`。

## 一、FSDP 是什么

**FSDP**(Fully Sharded Data Parallel)是 PyTorch 自带的数据并行分片实现。它解决的问题只有一个:**一张卡装不下**——参数、梯度、优化器状态三样加起来,训练一个稍大的模型就放不进单卡显存。

它的办法直白得近乎粗暴:**把这三样沿分片维切开,均匀分片时每张卡只常驻自己那 1/N;真要算某一段的时候,临时把那一段的完整参数拼回来,在启用前向后重分片时,算完释放完整参数。**代价是引入参数的 all-gather,并用 reduce-scatter 归约梯度;前向后释放完整参数的组,反向前还要再做一次 all-gather。所以 FSDP 的核心工程问题是:**尽量让通信与计算重叠**,以及**让临时拼出来的那份完整参数尽可能短命**。

它和另外两种并行切的不是同一刀:张量并行切的是单个算子内部,流水并行切的是层与层之间,而 FSDP 切的是**同一份权重在数据并行维上的那些副本**——本来每张卡存一份一模一样的权重,现在每张卡只存一段。所以它能和前两者叠着用,而不是二选一。

顶层入口只有两个,而且**今天都活着**:

- `torch.distributed.fsdp.fully_shard`:新实现的入口,是个函数,原地改造传进去的模块,不包一层。
- `torch.distributed.fsdp.FullyShardedDataParallel`:旧实现的入口,是个类,把模块包起来。

两者由同一个 `torch/distributed/fsdp/__init__.py` 导出,`__all__` 里明写 `# FSDP1` 与 `# FSDP2` 两组。**上游没有让哪一套退场**,官方文档的说法是「如果你在用 FSDP1,考虑迁移到 FSDP2」,并给了迁移指南。

代码花在哪(只算 `.py`,不含测试):整个 fsdp 包 21125 行,其中新实现 6107 行、旧实现 15018 行。新实现的包内代码更少,部分能力由 DTensor 等外围子系统承担;两代 API 的支持范围也并不完全相同。

紧挨着它、但本解读不展开的两块:DTensor(34633 行)是新实现表示分片参数的类型,DCP(14486 行)是存取checkpoint的统一入口。它们各自够格另开一份解读,这里只写 FSDP 拿它们做什么。

## 二、6 个招牌:先建立全局图景

```text
                    一张卡装不下:参数 + 梯度 + 优化器状态
                                    │
              [1] 按参数逐个在 dim-0 切:每张卡常驻 1/N,类型是 DTensor
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
   [2] 通信组                  [3] 通信与计算重叠            [4] 存储改写
   包在哪里决定通信粒度          计算流 / AG 流 / RS 流      完整参数要反复释放
   收多少参数;组边界            下一组的通信盖在            又不能和 autograd
   全靠你自底向上包出来         这一组的计算底下            存的视图打架
        │                           │                           │
        └───────────────────────────┼───────────────────────────┘
                                    ▼
              [5] mesh:分片铺到哪一层为止 —— 全局、只在节点内、或和别的并行叠着
                                    │
                                    ▼
              [6] 原位改造与 hooks:保留模块结构,在计算边界切换参数形态
```

一句话记忆:

- **逐参数分片**:默认把每个参数各自在第 0 维切给各张卡,切完的东西是 DTensor,「这张卡上有哪个参数的哪一段」是可以直说的。旧实现先把一组参数展平拼成一根长条再切,这句话就说不出来了。
- **通信组**:通常一次分片调用圈定一批参数,一起 all-gather、一起 reduce-scatter。**没有按字节自动攒批这回事**,组边界完全由你包了哪些模块决定。
- **通信与计算重叠**:计算、all-gather、reduce-scatter 分流调度,为重叠创造条件。前向靠 CPU 跑在 GPU 前面自然重叠,反向则显式预取下一组。
- **存储改写**:临时拼出来的完整参数必须反复释放,可 autograd 可能存着它的视图;所以释放走的是改存储大小,而不是换对象,别名关系才保得住。
- **mesh**:一维就是全局分片,二维就是组内分片、组间复制,还能作为更大的设备网格里的一个维度和别的并行叠着用。
- **原位改造与 hooks**:FSDP2 保留原模块结构与参数完整名,通过 hooks 在计算边界聚合和释放参数。

## 四、一次迭代怎么串起来

以默认前向后重分片的非根组为例:**all-gather → 前向 → 释放完整参数 → all-gather → 反向 → reduce-scatter**。根组默认保留前向聚合后的参数,不必反向再聚合。下图画非根组间的计算与通信重叠,不包含根组。

![四个非根通信组的示意时间线:前向与反向各有四次 all-gather,计算等待本组参数就绪;反向的 all-gather 与 reduce-scatter 在共享通信通道上交错排队,并与计算重叠。图中不表示实际耗时和总显存](/opensource/FSDP/00a-one-iteration-three-streams.svg)

**前向**:每个组的前置 hook 发起自己的 all-gather,等它完成再算这个组。因为 CPU 通常跑在 GPU 前面,当前组还在算的时候,下一个组的 hook 已经把它的 all-gather 发到通信流上了——这就是默认路径形成重叠的方式,实际能隐藏多少通信仍取决于计算长度与 CPU 提前量。CPU 领先不够时,可以把预取手动提前到当前组的前置 hook 里。

**反向**:顺序倒过来,而且多做两件事——**显式**预取下一个组的 all-gather,以及把 reduce-scatter 放到第三条流上。这些工作可以提前提交,但不同 CUDA 流不等于网络并发:默认 all-gather 与 reduce-scatter 共用 communicator,二者在网络上串行,同时争取与计算重叠。

**显存**:分片参数常驻,完整参数按组临时驻留;预取越早、保留越久,同时占用的参数显存越多。整步峰值还包括梯度、优化器状态、激活和通信缓冲。组边界、预取与重分片的取舍分别见 02、03、06 章。

**梯度**:反向算出来的是完整形状的梯度,打散之后每张卡只留自己那 1/N,和分片参数对得上,优化器直接在分片上更新,不需要额外的主权重副本。

## 六、怎么调它、怎么看它

各章「调参与观测」只写自己的参数,入口在这里说一次。

**两套实现的可调面形状完全不同,这是上手时最容易撞的一件事。**

| 实现 | 配置长什么样 | 什么时候改 |
|---|---|---|
| 新实现 | 入口函数的 7 个具名参数(网格、重分片粒度、分片放置函数、混合精度策略、offload 策略、忽略参数集、网格维名),外加分片模块上的 23 个方法 | 前者在分片时指定;后者按各接口约定控制运行期行为 |
| 旧实现 | 包装类构造函数的一长串参数,加上类方法设置的checkpoint类型与配置对象 | 分片策略等在构造时定;梯度累积等也有运行期控制 |

**新实现提供了更细的显式控制**:可以控制梯度归约、重分片与预取。旧实现也有运行期接口,例如用上下文管理器控制梯度累积;两者的控制粒度和使用方式不同。

观测的三处:通信与计算有没有真重叠,看 profiler 里三条流的时间线,这是唯一可靠的判据;显存是不是按预期释放,结合参数驻留、梯度、优化器状态、激活与通信缓冲检查峰值;分片形状对不对,直接打印参数,新实现下它本身就是带分布信息的分布式张量。

## 七、阅读顺序

主干是 01 → 02 → 03 → 04 → 05,读完就抓住了 FSDP 的主线:切成什么、一次凑多少、怎么藏起通信、怎么安全地扔掉、怎么让它起得来。06 与 07 是把这条主线调到具体集群上的两件事(拿什么换显存、铺到哪一层),显存或通信成为瓶颈时读。08 到 11 按需查阅,其中 11 章在你第一次存checkpoint之前就该读——存错了要重训。

**12 与 13 是另一条线**:如果你手上的训练框架默认走的是旧实现,从 13 章倒着读回 12 章,比顺着读快。

**怎么读**:本解读**不讲分片这件事本身的原理**——按阶段切分优化器状态、梯度和参数的那套思路,以及数据并行、张量并行、流水并行怎么配合,知识库里各有一篇,这里只写 PyTorch 这套实现是怎么落地的、和常见做法差在哪、怎么调。每一章都是短页:核心问题、解法、代价、和同类常见做法不一样的地方、调参与观测、常见误区。哪一句想展开,在对话里问。

和训练框架解读的分工:verl 那类框架关心的是一步训练里几个角色怎么共用一批卡、权重怎么在训练侧与推理侧之间倒;FSDP 关心的是**单个模型在一组数据并行的卡上怎么放得下、算得动**。训练框架把 FSDP 当成一个可选的训练后端直接用,所以那边只写「怎么把它接进来」,接进来之后的事在这里。

## 八、术语表

| 术语 | 一句话 |
|---|---|
| 分片参数 | 切开之后常驻在本卡上的那一段,新实现里它的类型是 DTensor |
| 完整参数 | all-gather 后用于计算的参数,按重分片策略释放或保留 |
| all-gather | 把各卡的分片凑成完整参数的那次通信 |
| reduce-scatter | 把完整形状的梯度归约并打散回各卡的那次通信 |
| 通信组 | 一起进行 all-gather 与梯度 reduce-scatter 的一批参数 |
| DTensor | 带分布信息的张量类型,新实现用它表示分片参数 |
| 设备网格 | 卡的逻辑排布,一维是全局分片,二维是组内分片加组间复制 |
| 重分片粒度 | 前向结束后把完整参数退回到什么程度:全退、不退,或退到一个更小的范围 |
| 预取 | 提前把下一个组的凑齐动作发到通信流上,好让它被当前计算盖住 |
| 长条句柄 | 旧实现的核心对象,管一组参数展平拼接后的那根一维长条 |
| 包装策略 | 旧实现里决定哪些模块各自成为一根长条的规则 |
| sharded checkpoint | 各 rank 保存分片状态的 checkpoint;FSDP2 生成分片 state_dict 无需聚合完整参数,不代表整个保存过程零通信 |
| 对称内存 | 一种让各卡互相直接寻址的显存分配方式,新实现把它作为通信缓冲的一个可选来源 |
