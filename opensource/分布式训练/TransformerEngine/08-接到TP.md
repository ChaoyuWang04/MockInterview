# 接到 TP:切法与 Userbuffers

这一页回答一件事:线性层怎么按列或按行接到张量并行,以及集合通信怎么盖进矩阵乘,而不是串在关键路径上。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

多卡把一层线性切进张量并行之后,最常见的两种骨折不是「切不动」,而是**切法和通信时机都错了**。

切法错:列切该在输入上先做 all-gather、行切该在输出上做 reduce-scatter(或 all-reduce),序列并行还要把序列维也摊开。切反了,形状对不上,或者每张卡都在算一份完整矩阵。序列并行关着、张量并行开着,通信仍在,只是序列维没切,激活显存先爆。

通信错:all-gather 或 reduce-scatter 和矩阵乘串着跑。通信占满关键路径,Tensor Core 空等。多卡越大,空等越明显——算力账单看起来像「核没开」,其实核在等网。

本库不发明张量并行。它只在线性层(以及融合的归一化加线性、归一化加 MLP)上提供切法和通信重叠。注意力的上下文并行是另一章的事;分组线性层明确不管集合通信。

所以这一章的问题是:**这一层按列切还是按行切,通信有没有盖进矩阵乘。**

## 二、解法

切法只有三种取值:不切、列切、行切。列切把输出特征按张量并行世界大小整除切开,前向若开了序列并行,要先把各卡上的输入片 gather 齐再乘;行切把输入特征切开,前向乘完后若开了序列并行就 reduce-scatter,否则做 all-reduce。序列并行默认关;世界大小为 1 时即使用户打开也当关。切分发生在建层时改权重宽高,不是前向里临时切。

通信重叠另走一条路。先在进程里初始化一份用户缓冲通信器,按一层里各次矩阵乘的名字(查询键值、投影、第一段全连接、第二段全连接,以及各自的前向、输入梯度、权重梯度)建缓冲。列切且序列并行时,前向可以把输入 all-gather 盖进矩阵乘;行切且序列并行时,前向可以把输出 reduce-scatter 盖进矩阵乘。反向对称:行切重叠输出梯度的 all-gather,列切可以重叠输入梯度的 reduce-scatter,或用体积通信把输入 all-gather 盖进输入梯度、把输入梯度 reduce-scatter 盖进权重梯度。任何一条重叠开关要生效,必须先完成那次初始化,并且给这一层一个缓冲名;没初始化就建层会直接断言。

![上排列切与行切:列切切开输出特征、前向先 gather 输入再乘;行切切开输入特征、乘完再 reduce-scatter 或 all-reduce。下排同一条列切前向:红框是 all-gather 与矩阵乘串行,绿框是用户缓冲把通信盖进矩阵乘](/opensource/TransformerEngine/08a-tp-cut-and-ub-overlap.svg)

融合层只是把同一套开关接到对应的那一次矩阵乘上:归一化加线性的列切前向用查询键值那条缓冲,行切用投影;归一化加 MLP 的第一段全连接走列切重叠,第二段走行切重叠。体积重叠只给列切的反向。另一条可选后端用厂商的多卡矩阵乘库做 all-gather / reduce-scatter 重叠,不支持体积重叠和外部重叠,会改走环交换并把对应的权重梯度体积重叠关掉。

**为什么实际不吃亏。** 训练引擎仍负责进程组和切哪些层;本库只在这一层里把该做的集合通信接到矩阵乘上。不打开重叠,列切前向就走普通的第一维 gather,行切走普通的 reduce-scatter 或 all-reduce,语义不变,只是通信暴露在关键路径上。

## 三、代价

**重叠不是默认。** 切分模式默认不切,序列并行默认关,所有重叠开关默认关。只换积木、不传切分、不初始化用户缓冲,这一层就是单卡线性层。

**重叠绑死切法和序列并行。** 列切才认前向 all-gather 重叠和反向 reduce-scatter / 体积重叠;行切才认前向 reduce-scatter 重叠和反向 all-gather 重叠。序列并行关着,这些开关写了也不生效。

**初始化只能一次,销毁才允许再来。** 通信器已经在就再调一次会报错。编译图可能把缓冲是不是八位烤进常量,销毁时会重置编译器,免得下次用另一套量化模式读到旧值。

**设备要支持组播,否则走用户缓冲后端会直接失败**,除非启动时跳过组播改走进程间共享。另一条多卡矩阵乘后端在组播不可用时会自己退到非组播算法,不走这条断言。

**配对约束。** 管道式重叠只给 reduce-scatter,不给 all-gather。原子矩阵乘只认八位。查询键值前向和投影前向、第一段和第二段全连接,若一侧用原子加环交换,另一侧必须同一套,否则块顺序对不上。体积和外部重叠,多卡矩阵乘后端直接拒绝。

**分组线性层打开重叠会立刻失败。** 专家侧的集合通信在分发与合并里做,不在这一层。

**形状是整除。** 列切要求输出特征能被世界大小整除,行切要求输入特征能被整除;除不尽建层就失败。序列并行下输出的序列维会按列切放大、按行切缩小,和切法反了形状对不上。

## 四、和同类算子库不一样的地方

本页只比线性层上的切分怎么接到张量并行、通信怎么盖进矩阵乘。Apex 核在主干 8a6508aa;FlashAttention 没有单独镜像。两者都不是张量并行重叠库,表里那两列不是漏写接口。Megatron 是把本库接进去的宿主,不进对等列,也不在本页重讲张量并行本身。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 线性层怎么切 | 建层时列切或行切,改权重宽高;序列并行改前向 gather / scatter | 融合稠密层没有列切行切,也不做序列并行集合通信 | 不是线性层库,没有切分 |
| 通信怎么盖进矩阵乘 | 先初始化用户缓冲,再按层名把 all-gather / reduce-scatter 交给矩阵乘;可选多卡矩阵乘后端 | 没有用户缓冲,也没有通信与矩阵乘重叠入口 | 不是通信重叠库 |
| 谁负责进程组 | 调用方传入张量并行组;本库只在这一层里做该做的集合通信 | 不管张量并行组 | 不适用 |
| 专家侧 | 分组线性层拒绝重叠开关,集合通信留给分发与合并 | 没有分组专家入口 | 不适用 |

注意力上的上下文并行见 06 章,不是本页的切法。

## 五、调参与观测

这一页的参数是线性层上的切分模式和用户缓冲重叠,改了要重建模块并重新初始化用户缓冲;矩阵乘精度见 04 章,融合层怎么接到同一套开关见 05 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `parallel_mode` | 线性层 / 融合层构造 | `None`,不通信 | `column` 切输出特征;`row` 切输入特征 | 权重宽高是否已按世界大小整除 |
| `sequence_parallel` | 同上 | `False`;世界大小为 1 时强制关 | 列切前向 gather 输入,行切前向 reduce-scatter | 激活的序列维是否按世界大小缩放 |
| `tp_group` / `tp_size` | 同上 | 组空则用 `tp_size`,默认 1 | 决定切几份;组空且大于 1 时必须在前向前补组 | 各卡权重形状是否一致 |
| `initialize_ub` | 建层前调一次 | 不调则重叠全关 | 按层名建用户缓冲;已初始化再调会报错 | 日志里张量并行域个数与全局秩 |
| `quantization_modes` | 初始化用户缓冲 | 不传则回落到已废弃的 `use_fp8` | 每种量化模式各建一套通信器 | `get_ub` 按八位开关取对应套 |
| `ub_overlap_ag` | 线性层 / 融合层构造 | `False` | 列切前向盖 all-gather,行切反向盖 all-gather | 前向是否还走普通第一维 gather |
| `ub_overlap_rs` | 同上 | `False` | 行切前向盖 reduce-scatter | 前向是否还走串行 reduce-scatter |
| `ub_overlap_rs_dgrad` | 同上 | `False` | 列切反向把 reduce-scatter 盖进输入梯度 | 与体积重叠互斥,体积那两条会被关掉 |
| `ub_bulk_dgrad` / `ub_bulk_wgrad` | 同上 | `False` | 列切反向体积重叠;多卡矩阵乘后端会改走 reduce-scatter 重叠并关掉体积 | 反向时间线是否仍串行 |
| `ub_name` | 同上 | `None` | 必须能拼出前向 / 输入梯度 / 权重梯度三套缓冲名 | 打开任意重叠却名为空会断言 |
| `with_cublasmp` | 初始化用户缓冲 | `False` | 改用多卡矩阵乘库做重叠;体积和外部方法直接拒绝 | 需编译打开对应宏 |
| `destroy_ub` | 作业结束或重配前 | 无 | 清通信器并重置编译器常量 | 之后才能再次初始化 |
| `UB_SKIPMC` | 环境变量 | 未设当 0 | 组播不支持时改走进程间共享,否则用户缓冲后端失败 | 初始化是否还报组播 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 多卡列切投影前的线性,先把语义跑通 | 切分模式列切,序列并行打开,张量并行组传入,不调用户缓冲初始化 | 形状和集合通信正确;通信仍串在矩阵乘前面 |
| 同一层要把 all-gather 盖进前向矩阵乘 | 建层前初始化用户缓冲,形状用整网序列乘批次、隐层,列切加序列并行,打开 all-gather 重叠并给缓冲名 | 通信进矩阵乘;换来的是初始化只能一次、设备要组播或显式跳过 |
| 行切输出投影,前向 reduce-scatter 重叠 | 行切加序列并行,打开 reduce-scatter 重叠,缓冲名对投影前向 | 输出侧通信进核;切法写列切则开关不生效 |
| 编译进多卡矩阵乘重叠 | 初始化时打开多卡矩阵乘后端,不要用体积方法 | 少一条体积路径;对应权重梯度重叠被关掉 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:切没切对,看权重宽高和输出序列维,不要只看「已经传入张量并行组」;重叠有没有真开,看前向还走不走普通第一维 gather,以及初始化日志里的张量并行域;组播失败,看是用户缓冲后端断言还是已经改走另一条后端。

| 症状 | 先查 | 然后 |
|---|---|---|
| 多卡线性层形状对不上 | 切分是列还是行,输出/输入特征能否整除 | 列切改输出特征,行切改输入特征,建层时就会 `divide` |
| 换成积木,多卡仍在等通信 | 重叠开关、是否先初始化、缓冲名、序列并行是否开 | 先初始化再建模;列切配 all-gather 重叠,行切配 reduce-scatter 重叠 |
| 建层直接断言用户缓冲 | 初始化有没有调、缓冲名是不是空 | 作业入口先初始化;名字必须能拼出前向那一条 |
| 初始化报组播不支持 | 设备/驱动是否支持组播,是否走用户缓冲后端 | 设跳过组播,或改用多卡矩阵乘后端 |
| 第二次初始化失败 | 通信器是否还活着 | 先销毁再初始化 |
| 分组线性层一开重叠就失败 | 是不是把稠密层的重叠抄到了专家层 | 专家侧不要开;集合通信放分发与合并 |

## 六、常见误区

**「切分模式写了列切,为什么还是单卡形状」——世界大小仍是 1。** 组没传入、大小默认 1,列切除以 1,权重宽高不变。看起来像没切,其实切法生效了,只是切成一份。

**打开重叠却不先初始化。** 任意一条重叠在建层时检查通信器,没初始化直接断言。这不是前向里才暴露的慢,是构造期就会炸。

**列切上打开 reduce-scatter 重叠,以为「有开关就会盖」。** 行切才认前向 reduce-scatter;列切认的是前向 all-gather。写反了开关被条件吞掉,前向仍走串行集合通信。

**序列并行关着却指望重叠。** 所有重叠条件都乘上序列并行。只开张量并行、关序列并行,通信还在(行切 all-reduce),只是没有用户缓冲这条路径。

**把用户缓冲当成量化开关。** 量化模式只决定通信器按八位还是非八位各建一套;没套前向上下文,矩阵乘精度仍走 01 / 04 章那套全局开关。重叠开了不等于低精度开了。

**分组线性层跟着稠密层抄重叠。** 04 章已经写过分组层不管集合通信;这里再抄一次会立刻失败,不是「专家多所以更需要重叠」。
