# Transformer Engine 总览

源码基准:官方仓库 <https://github.com/NVIDIA/TransformerEngine>,分支 `main`,commit `f0b6e7179baf5be6fc9ee32a4197c92dc590f58c`,最近的正式发布 tag `v2.19.0`(仓库自报版本 `2.21.0-dev0`),核对日期 2026-09-21。全篇的「当前」「默认」都指这组基准。

## 一、Transformer Engine 是什么

**Transformer Engine**(TE)是 NVIDIA 的 Transformer 层加速库。它解决的问题只有一个:**一层要在 GPU 上又快又不散**——矩阵乘要吃到 Tensor Core,激活和权重还不能因为换成 8 位或 4 位就把训练打崩。

它的办法也直白:**不要自己拼 kernel,不要自己管 scale。** 把 Linear、LayerNorm、Attention、MoE 收成可以换进去的积木;前向外面套一层类似 AMP 的 autocast,库在里面维护缩放因子和 amax;Hopper / Ada / Blackwell 走 FP8,Blackwell 再往下还能走 MXFP8 和 NVFP4。

它和另外两件事切的不是同一刀:Megatron 切的是**模型怎么铺到多卡**,FSDP 切的是**同一份权重在数据并行维上怎么切开**,TE 切的是**这一层内部用什么精度、哪几个算子融在一起、GEMM 怎么把通信盖住**。所以训练框架把它当后端接进来,而不是二选一。

顶层入口按框架分成两套,接到同一份 C++ 核:

- `import transformer_engine.pytorch as te`:PyTorch 模块 + `te.autocast`。
- `import transformer_engine.jax as te` 与 `transformer_engine.jax.flax`:JAX / Flax 模块 + 同一套配方对象。

还有一条框架无关的 C++ API,给别的库嵌 FP8 用。本解读以 PyTorch 为主线,JAX 的绑定契约单独一章,不把每一层再讲一遍。

代码花在哪(解释本体,不含测试):`transformer_engine/` 约 10.4 MB,其中 `common/`(C++/CUDA)4.5 MB、`pytorch/` 4.3 MB、`jax/` 1.7 MB、`debug/` 0.15 MB。**核比前端还重**,这个数字本身就是这份解读要解释的东西——Python 模块是在选路,真正干活的是下面那层。

紧挨着它、但本解读不展开的两块:并行策略(张量 / 流水 / 数据 / 专家)归 Megatron 或 FSDP 的解读;通用的 FP8、混合精度、FlashAttention、MoE 路由思想在知识库各有一篇,这里只写这个库怎么落地。

## 二、6 个招牌:先建立全局图景

```text
                    一层 Transformer:要快,还不能把训练打崩
                                    │
              [1] autocast + 配方:打开量化,选定 scale 怎么算
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
   [2] 积木                       [3] 量化张量                 [4] 后端
   Linear / LN+Linear             行、列两份用法               Attention 多后端
   LN+MLP / GroupedLinear         amax 与 extra_state          GEMM 走 Tensor Core
        │                           │                           │
        └───────────────────────────┼───────────────────────────┘
                                    ▼
              [5] 接到并行:Linear 上的 TP/SP 切法 + Userbuffers 把通信盖进 GEMM
                                    │
                                    ▼
              [6] 两套前端:PyTorch 模块 / JAX flax,同一份 C++
```

一句话记忆:

- **autocast + 配方**:量化不是模块上的一个 dtype 开关,是前向外面的上下文加上一份 recipe。默认配方按设备选:能跑 MXFP8 就 MXFP8,否则退到 current scaling 或 DelayedScaling。
- **积木**:先换 Linear / LayerNorm,再换 Attention,再换成融合的 LayerNormLinear / LayerNormMLP,或直接用现成的 TransformerLayer。官方 Getting Started 就是这条阶梯。
- **量化张量**:一份张量常常要同时准备行访问和列访问;scale 与 amax 历史走 `._extra_state`,断点漏了它,续训就会跳。
- **后端**:Attention 按硬件和输入自动挑 fused / Flash / 回退;GEMM 按配方走到对应精度的 Tensor Core。选错的代价不是「慢一点」,是显存爆或根本没走快路径。
- **接到并行**:TE 不发明张量并行。它在 Linear 上提供切法,再用 Userbuffers 让 TP 的通信和 GEMM 重叠。
- **两套前端**:PyTorch 与 JAX 共用 C++ 核,契约不同——JAX 必须在 autocast 里初始化,才会有量化 collection。

## 三、12 章,各自解决什么

下表是本解读的章表。**这里只回答「它存在是为了解决什么」**;展开讲解在各章,代码在哪见代码索引页。

| 主题 | 不这么做会怎样 | 做法一句话 | 详见 |
|---|---|---|---|
| 一次前向的形状 | 换成 TE 模块却不包前向 autocast,或把反向也包进去:没走低精度,状态机失败 | 积木换进去,前向套 autocast,反向在外面;配方和量化状态在这一跳里接上 | 01 章 |
| 量化配方 | 配方与硬件或激活分布不匹配:Tensor Core 空转,或 scale 跟不上、loss 发散 | 按设备选 delayed / current / block / MXFP8 / NVFP4,scale 的粒度与来源写在 recipe 里 | 02 章 |
| 量化张量与 extra state | 断点没带上 scale / amax,或没在量化上下文里建权重:续训跳点 | 行/列两份用法的张量对象,元数据走 extra_state;建权重可只留量化副本 | 03 章 |
| Linear 与 GEMM | GEMM 没走到对应精度的 Tensor Core;MoE 不用 grouped 就变成多次小 GEMM | Linear / GroupedLinear 把量化、转置、GEMM 收成一次前向 | 04 章 |
| Norm 与融合层 | LN 和 Linear 拆开:多卡时 launch 与中间激活把吞吐打掉 | LayerNorm / RMSNorm,以及 LN+Linear、LN+MLP 的融合模块 | 05 章 |
| Attention:后端与上下文并行 | 后端选错或长序列不开 CP:显存爆或比 Flash 还慢;mask 极性用错则算反 | 自动选 fused / Flash / 回退;长序列在注意力上切一刀;线性注意力变体走同一套入口 | 06 章 |
| MoE:路由、permute、grouped GEMM | token 不重排、router 不融合:expert 计算被搬运和启动开销淹没 | permute / unpermute、融合 router、GroupedLinear 一次打一群专家 | 07 章 |
| 接到 TP:切法与 Userbuffers | Linear 的 TP/SP 切错,或通信和 GEMM 串行:算力空等 | 列切/行切与序列并行落在 Linear 上;Userbuffers 把 AG/RS 盖进 GEMM | 08 章 |
| 激活 CPU offload | 长序列或大微批激活放不下,只能砍批量 | 上下文里把指定激活卸到主机,用完再取回 | 09 章 |
| 算子融合器 | 模块级融合粒度不够,自定义层走不到融合核 | `te.ops` 把可融合算子排成一条管线,前反向可以融成不同的组 | 10 章 |
| JAX 绑定 | 没在 autocast 里 init:没有量化 collection;sharding 对不上 | 同一份 C++ 核,Flax 模块与 collection 契约 | 11 章 |
| Debug | FP8 不收敛时没有层内统计,只能猜 | 按层看 amax、scale 和统计,分布式下也能收 | 12 章 |

## 四、一次前向怎么串起来

一次训练步里,TE 只接管**层内**这一段。进程组、流水线调度、优化器分片都在外面。

前向:进入 autocast → 每个 TE 模块按当前配方把输入和权重量化(或直接用已经量化的副本)→ Norm / Linear / Attention / MLP 走到对应核 → 离开 autocast。官方写明:**autocast 必须在反向开始前退出**。

反向:梯度在高精度或配方规定的反向格式里算;需要 amax 归约时,归约发生在 autocast 退出那一刻。同一模块在一次 autocast 里调两次,后一次会盖掉前一次的 amax,这是不支持的。

显存:量化张量比 BF16 小,但常常要同时留行、列两份布局给三种 GEMM(前向一次、反向两次)用;融合层省的是中间激活和 launch,不是把这份布局账抹掉。峰值仍然是「量化权重 + 这一层还活着的激活 + 可能的转置副本」。

接到多卡时,Linear 按列切或行切做张量并行,激活还可以沿序列再切一刀;真正让通信不暴露的,是 Userbuffers 把 all-gather / reduce-scatter 排到 GEMM 底下。那是 08 章的事,01 章只需要知道:**没初始化 Userbuffers,TE 照样能算,只是通信会排在 GEMM 外面。**

## 六、怎么调它、怎么看它

各章「调参与观测」只写自己的参数,入口在这里说一次。

**先选配方,再换模块,最后才谈并行重叠。** 模块换进去但 autocast 没开,走的仍是较高精度的融合核;Userbuffers 没初始化,TP 仍然正确,只是通信不重叠。

| 旋钮 | 长什么样 | 什么时候改 |
|---|---|---|
| 配方 | `DelayedScaling` / `Float8CurrentScaling` / `Float8BlockScaling` / `MXFP8BlockScaling` / `NVFP4BlockScaling`,传给 autocast | 训练开始前定;编译区域里必须显式传入,不能靠默认工厂 |
| autocast | 前向上下文;`calibrating` 可在未量化时先采集 amax | 每步前向;反向开始前退出 |
| 积木替换 | Linear、融合层、TransformerLayer、Attention | 建模型时定 |
| 量化初始化 | `quantized_model_init` | 建模型时;优化器已有主权重或推理时打开 |
| TP / Userbuffers | Linear 的切法参数 + `initialize_ub` | 进程组建好之后、第一次前向之前 |
| 环境变量 | 构建期 `NVTE_FRAMEWORK`、`NVTE_CUDA_ARCHS`;运行期后端开关见官方 envvars 页 | 安装或排障;比 API 更容易变 |

观测的三处:有没有真走低精度,看模块是否在 autocast 里、配方是否被当前设备支持;Attention 走了哪条后端,开 `NVTE_DEBUG=1` 看日志;通信有没有被 GEMM 盖住,看 profiler 里 Userbuffers 那条流,而不是看「初始化成功」四个字。

## 七、阅读顺序

主干是 01 → 02 → 03 → 04 → 05,读完就抓住 TE 的主线:前向怎么套、配方怎么选、张量怎么活、GEMM 和融合层怎么把一层跑起来。06 与 07 是注意力和 MoE 两条专线,做长序列或专家模型时读。08 在你真的把 TE Linear 接到张量并行之后再读——没接 TP 时 Userbuffers 帮不上忙。09、10、12 按需。11 只给 JAX 用户。

**怎么读**:本解读**不讲 FP8 格式本身、不讲混合精度思想、不讲 FlashAttention 或 MoE 路由是什么**——那些在知识库。这里只写这个库怎么把它们收成积木、和常见做法差在哪、怎么调。每一章都是短页:核心问题、解法、代价、和同类大厂框架不一样的地方、调参与观测、常见误区。哪一句想展开,在对话里问。

和训练框架解读的分工:Megatron 关心五维并行和一次 iteration 怎么排,它把 TE 当成低精度与融合的后端接进来;FSDP 关心参数怎么切开。两边都只应写「怎么把 TE 接进来」。接进来之后,层内发生的事在这里。各章第四段的对等列是 Apex 与 FlashAttention,不是这两个引擎。

## 八、术语表

| 术语 | 一句话 |
|---|---|
| 配方 / recipe | 一次训练用哪套量化规则:格式、scale 从哪来、切多细 |
| DelayedScaling | 用上一迭代的 scale,本步再记 amax 历史 |
| current scaling | 这一步当场算 amax 再量化 |
| MXFP8 | Blackwell 上的微缩放 FP8 块量化 |
| NVFP4 | Blackwell 上的 4 位块量化 |
| autocast | 打开低精度的前向上下文,退出时做 amax 归约 |
| extra_state | 模块状态字典里的量化元数据,断点必须带着 |
| 行用法 / 列用法 | 同一份量化张量按 GEMM 访问方向准备的两种布局 |
| Userbuffers | 把 TP 的 all-gather / reduce-scatter 与 GEMM 重叠的通信缓冲 |
| GroupedLinear | 一次打一组不同 token 数的专家 GEMM |
| TransformerLayer | 官方现成的一层,内部已接好 Norm、Attention、MLP |
