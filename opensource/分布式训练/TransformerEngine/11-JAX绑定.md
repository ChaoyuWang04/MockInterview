# JAX 绑定

这一页回答一件事:同一套 C++ 核接到 JAX 时,初始化契约和切分声明差在哪,以及为什么没在量化上下文里 init 就没有量化 collection。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

PyTorch 侧可以先建模块、再在前向外套量化上下文。JAX 侧照抄这套习惯,最常见的结果不是走较高精度,而是**量化 collection 根本没有被建出来**。Flax 的变量只能在 init 时登记;量化元数据是一份 Flax collection,不是前向临时算出来的。init 时全局配方是空的,积木只会生成一份空的量化器集合,apply 时再套上下文也补不回来。

第二件事是切分。多卡不是「JAX 网格在、积木就会跟着切」。绑定把逻辑轴映射到网格轴的那张表,读的是量化上下文里塞进去的切分资源。网格轴名字和资源对不上,或者张量并行与张量序列并行同时开,断言直接炸,多卡数值立刻错。

所以这一章的问题不是线性层、注意力、专家怎么算(那是 04、06、07 章),而是:**JAX 怎么接到同一套 C++,谁在 init 时把量化 collection 写进变量树,切分轴谁来声明。**

## 二、解法

入口先加载 JAX 扩展动态库,再导出量化上下文、切分资源和 Flax 积木。积木不是另一套算法:稠密、归一化、注意力的 Python 入口把张量、量化器集合交给同一套 C++ 扩展。

量化上下文做三件事。打开时把全局配方写进去,并检查当前设备支不支持这份配方;顺手把切分资源挂到线程全局。关掉时把配方和切分资源还原。配方不传则用延迟缩放。注意:这个绑定里,上下文默认是关着的,不显式打开就等于没开。

Flax 积木在前向里向基类要一份量化器集合。基类读全局配方:有配方就按配方建元数据,延迟缩放会在指定 collection 里登记缩放和绝对值最大值历史;没配方就走空配置,不登记那些变量。官方上手因此要求:**init 必须包在打开的量化上下文里**,apply 也在同一类上下文里跑,变量树里才会有那份 collection。

切分是另一份契约。切分资源声明数据并行、张量并行、张量序列并行、完全分片数据并行、流水线、上下文并行、专家并行各对应网格哪一根轴。量化上下文进去时把这份资源设成全局;扩展逻辑轴规则、以及按逻辑轴加切分约束,都读这张表。张量并行和张量序列并行不能同时开。没有物理网格时,映射表是空的,单卡不必硬填。

![左右两列对照:左列灰框是 PyTorch,先建模块不必包量化上下文,前向再套上才打开低精度;右列紫框是 JAX,init 必须在打开的量化上下文里,才会在变量树里登记量化 collection,只包 apply 补不回来;下方黄条写切分资源也是这份上下文带进去的,轴对不上多卡直接错](/opensource/TransformerEngine/11a-jax-init-inside-autocast.svg)

**为什么实际不吃亏。** 用户代码仍是 Flax 的 init 加 apply,没有第二套训练循环。同一套 C++ 核,差的是变量树和切分声明必须在上下文里一次对齐。旧的八位上下文名字标了废弃,公开入口就是这一份量化上下文。

## 三、代价

**init 漏包,collection 永不出现。** 这不是「前向走较高精度还能训」,是变量树缺一块,apply 对不上、断点也对不上。

**上下文默认关着。** 包了但忘了打开,全局配方仍是空的,效果和没包一样。

**切分资源是全局的。** 多卡必须在上下文里传入,并与真实网格轴同名。扩展现成一层的逻辑轴规则之前,也必须先把切分资源设上。稠密积木则要自己把权重和偏置的轴写对。

**延迟缩放在 JAX 上更窄。** 绝对值最大值算法只认最大和最近一次;缩放因子算法必须空着;跨卡归约绝对值最大值必须开着。其它字段会断言。

**重算策略按点积原语过滤的,会漏掉本库的矩阵乘。** 本库的矩阵乘不总走框架那条点积原语,要用绑定提供的、把本库矩阵乘也算进去的策略,或干脆不按原语过滤。

**扩展逻辑轴规则目前只覆盖单卡、数据并行和一维张量并行。** 更复杂的切法不要指望这一条辅助函数代劳。

## 四、和同类算子库不一样的地方

本页只比 JAX 怎么接到同一套 C++、初始化契约差在哪。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| JAX 绑定 | 有独立的 JAX 入口、Flax 积木、量化上下文和切分资源,接到同一套 C++ | 本页未核到 JAX 绑定 | 本页未核到 JAX 版 Transformer Engine 绑定 |
| 初始化 | 必须在打开的量化上下文里 init,才会有量化 collection | 没有这套 Flax collection 契约 | 没有这套 Flax collection 契约 |
| 切分声明 | 量化上下文带切分资源,逻辑轴映射到网格轴;两套张量并行不能同时开 | 不是本库这张切分资源表 | 不是本库这张切分资源表 |
| 漏套会怎样 | init 漏套则没有量化 collection;只套 apply 补不回来 | 不适用:没有这条 JAX 绑定 | 不适用:没有这条 JAX 绑定 |

Apex 的断言核在主干 8a6508aa。FlashAttention 只写本库快照里没有这条 JAX 绑定。两者都不是「同一套 C++ 再挂一条 JAX 前端」的积木库,表里那两列不是漏写接口。Megatron 是宿主,不进对等列。

## 五、调参与观测

这一页的参数是 JAX 量化上下文、切分资源和 Flax 积木怎么初始化,改了要重新 init 再 apply;配方怎么算 scale 见 02 章,线性、注意力、专家内部见 04、06、07 章。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `autocast` 的 `enabled` | JAX 量化上下文 | `False` | 打开才把全局配方写进去;关掉则配方仍空 | init 后变量树有没有 `fp8_metas` |
| `recipe` | JAX 量化上下文 | 不传则 `DelayedScaling()` | 决定元数据长什么样;设备不支持会在进入时断言 | 02 章;JAX 延迟缩放还限制绝对值最大值算法和归约 |
| `mesh_resource` | JAX 量化上下文 | `None` | 声明各并行轴对应网格哪一根;不传则切分映射读不到资源 | 多卡切分是否与网格轴同名 |
| `NVTE_FP8_COLLECTION_NAME` | 量化配置常量 | `"fp8_metas"` | delayed 配方把 scale 和 amax 历史登记进这个 Flax collection | params 里有没有这一支 |
| `update_collections` | 训练步里合并变量 | 无,要自己调 | 把新 collection 合进原树,同名键以新的为准 | 量化元数据有没有写回 |
| `fp8_autocast` | 旧入口 | 转调 `autocast` | 废弃,新代码不要用 | 运行时弃用警告 |
| `MeshResource` 各轴 | 切分资源 | 全 `None` | 数据、张量、张量序列、完全分片、流水线、上下文、专家各一根轴;张量与张量序列不能同时开 | 进上下文时断言,或切分对不齐 |
| `extend_logical_axis_rules` | 现成一层 | 在已有 Flax 规则上追加本库逻辑轴 | 调用前必须已通过量化上下文设好切分资源 | 规则表是否含本库那几根逻辑轴 |
| Flax 积木 | `transformer_engine.jax.flax` | 稠密、归一化、融合层、点积注意力、多头、现成一层 | Python 侧接到同一套 C++;量化器集合由基类按全局配方生成 | init 是否在打开的上下文里 |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| 单卡把官方 JAX 上手跑通 | 打开量化上下文,配方显式传入,先 init 再 apply,都包在里面 | 变量树里有量化 collection;还没接多卡切分 |
| 多卡数据并行加一维张量并行 | 网格轴名写进切分资源,量化上下文带进去;现成一层先扩展逻辑轴规则再 pjit init | 切分跟积木走;轴名写错或两套张量并行同时开会断言 |
| 只换稠密和归一化、自己写注意力 | 仍然在打开的上下文里 init;稠密自己填权重轴,不要调现成一层那条扩展规则 | 改动面小;注意力切分不会自动补 |
| 重算要保住本库矩阵乘 | 用绑定提供的、把本库矩阵乘和点积都算进去的策略 | 不会把本库 GEMM 漏出重算范围;换来的是不能再用只认点积原语的策略 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:量化 collection 有没有,看 init 之后变量树,不要看「模块已经换成 Flax 积木」;切分对不对,看切分资源轴名是否与网格一致,进上下文有没有断言;配方是否真开,看上下文的打开标志,默认是关着的。

| 症状 | 先查 | 然后 |
|---|---|---|
| 前向没有量化 collection | 模型是不是在打开的量化上下文里 init 的 | init 也包进去并打开;不要只包 apply |
| 包了上下文仍然没有 collection | `enabled` 是不是还停在默认关 | 显式打开;不传配方则走延迟缩放 |
| 多卡一跑就断言或数值错 | 切分资源轴名、是否同时开了张量并行和张量序列并行 | 轴名改成与网格一致;两套里只留一套 |
| 扩展逻辑轴规则时报切分资源未设 | 有没有先走进带切分资源的量化上下文 | 先包上下文再扩展规则 |
| 重算把本库矩阵乘漏掉 | 策略是不是只过滤点积原语 | 换成绑定提供的策略 |

## 六、常见误区

**「PyTorch 可以先建再套,JAX 一样。」——不一样。** Flax 变量在 init 时定型。没在打开的上下文里 init,量化 collection 不会出现。这不是风格,是变量树契约。

**包了上下文但没打开。** 这个绑定默认关着。关着时全局配方是空的,积木走空配置,不登记 delayed 那套元数据。

**以为切分跟着 JAX 网格走。** 积木读的是量化上下文里的切分资源。网格在、资源空,多卡照样切不对。

**继续用旧的八位上下文名字。** 它只是转调新入口并打废弃警告。新代码走量化上下文。

**用只认点积原语的重算策略。** 本库矩阵乘不总走那条原语,看起来像「重算没生效」,其实是过滤条件把核漏掉了。
