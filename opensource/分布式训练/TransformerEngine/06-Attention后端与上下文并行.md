# Attention:后端、上下文并行、变体

这一页回答一件事:注意力核怎么被挑出来,长序列不切上下文并行会怎样,以及掩码真值从 1.7 起代表屏蔽。说法都在源码基准 `f0b6e717`(tag `v2.19.0`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

点积注意力换进库里之后,最常见的两种炸法不是公式写错,而是**核走错了,或序列太长却还当单卡完整算**。

核走错:三条路径都能跑——融合核、外面那套 Flash、以及未融合的原生 softmax。库先按环境和形状过滤,再按卡代给一个偏好。Hopper 以前 Flash 更常赢;Hopper 及以后融合核排在前面。你关掉 Flash、或形状把融合核筛掉,就会落到未融合路径:注意力分数整张进显存,比 Flash 还慢,也更容易爆。

序列太长却不开上下文并行:每张卡仍要握住完整 KV。长度一上去,显存先爆;就算勉强放下,未融合核更是按平方涨。开了并行却用未融合核,这条路直接被关掉——并行不是「切了就能随便走哪条核」。

掩码还有第三种骨折。从 1.7 起,真表示这一位被屏蔽、假才参与计算。仍按旧极性填填充位,注意力会算反:该看的被抹掉,该挡的反而进 softmax。

所以这一章的问题不是「注意力是什么」,而是:**这条前向到底走进哪条核、长序列有没有按上下文切开、掩码真值有没有用反。**

## 二、解法

先让库自己挑核,再在需要时把序列切开。

**挑核。** 点积注意力入口把形状、精度、掩码、是否在训练、有没有开上下文并行收成一份参数,交给选择函数。三条开关默认都开。过滤完之后,若融合和 Flash 同时还活着:计算能力到 Hopper 就把 Flash 关掉,留下融合;更早的卡反过来,Flash 留下、融合让位。只剩未融合时才走原生 softmax。调试日志会打出「还能用谁、最后用了谁」——不要用肉眼猜。

**切开。** 上下文并行把每条序列切到一组卡上。默认通信是点对点:环形交换 KV 块,可以和计算重叠。也可以先全收集完整 KV 再算(不能重叠),或把头打散、把整段 QKV 收回来(类似 Ulysses),或组内全到全、组间再点对点。因果掩码下对角与反对角负载不均,默认把两端对调再分。约束写死:每条序列长度必须能被并行度乘 2 整除。未融合核不支持这条切法。八位注意力加上下文并行时,Flash 也会被关掉,只留融合核;自定义配方这条切法还没接上,会直接报错而不是默默算错。

![长序列先按上下文并行切到两张卡上交换 KV,再按环境和卡代过滤三条核:Hopper 及以上融合优先,未融合核在开了上下文并行时直接丢掉](/opensource/TransformerEngine/06a-attn-backend-cp.svg)

**为什么实际不吃亏。** 日常训练不必手写选核。形状合法时 Hopper 上融合核已经比外调 Flash 更合适;真要对比,再关某一条开关。长序列的显存账靠切开,不靠把未融合 softmax 硬撑大。

**线性注意力变体。** 库里另有一套实验性模块:门控 delta 及其二代、以及门控 delta 乘积。它们走 cuDNN 前端的线性递推,不进上面三条点积核,也不走上下文并行那套切法。门控张量类型和形状对不上会直接报错。当实验特性用,不要当成点积注意力的第四条后端。

## 三、代价

**过滤比偏好更硬。** 开了并行、八位、非标准 softmax、交叉注意力的因果、或带偏置,Flash 或融合核可能整段被禁用。看起来「默认都开着」,实际只剩未融合。

**切开有整除和掩码限制。** 长度补不到并行度乘 2,进不去。右对齐因果、交叉注意力因果、带偏置的若干组合,融合和 Flash 都会拒绝并行。

**点对点以外的通信更贵。** 全收集拿完整 KV,显存和等待都回去了。全到全改的是头和序列的分布,不是免费的切分。

**掩码极性从 1.7 起与旧习惯相反。** 填充位填成真,有效位填成假。沿用 1.7 以前的真值表,填充位置会进计算。

**确定性要花钱。** Flash 默认非确定;要确定须够新的版本并关掉允许非确定算法的开关。融合核若干子路径在确定模式下会被禁用。

**线性变体是实验接口。** 与点积注意力的量化、并行、选核不是同一条栈;混用会让你以为「注意力已经切过了」,其实递推仍在单卡完整状态上。

## 四、和同类算子库不一样的地方

本页只比注意力走哪条核、长序列怎么切。

| | 本库 | Apex | FlashAttention |
|---|---|---|---|
| 注意力核从哪来 | 自己挑:融合、外调 Flash、未融合 softmax 三条,按环境和卡代过滤再偏好 | 公开入口没有注意力 | 你直接调它的核,没有「再挑融合或未融合」这层 |
| 长序列怎么切 | 点积注意力上设上下文并行组;未融合核不支持;八位时 Flash 也不走这条 | 无 | 本库切完可以再调它;它自己不是训练层上的上下文并行入口 |
| 掩码真值 | 1.7 起真表示屏蔽 | 无注意力,不适用 | 本库调用时跟本库统一后的极性,不要按调用方旧习惯反填 |
| 关掉某一条会怎样 | 环境变量可整段关掉 Flash 或融合,落到下一条还能用的核 | 不适用 | 本库把总开关关掉就不再走它,不是卸载 pip 包 |

Apex 没有注意力,表里那一列不是漏写。宿主训练引擎怎么代劳套上下文,不进本列。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

| 参数 | 在哪调 | 默认 | 调了之后 | 怎么看 |
|---|---|---|---|---|
| `NVTE_FLASH_ATTN` | 环境变量 | `1` | 设 `0` 整段关掉 Flash 路径 | 点积注意力调试日志里 Selected backend |
| `NVTE_FLASH_ATTN_V2` / `V3` / `V4` | 环境变量 | 均为 `1` | 只关某一代 Flash | 日志里 Flash 版本号;Hopper 上若融合也活着仍会丢掉 Flash |
| `NVTE_FUSED_ATTN` | 环境变量 | `1` | 设 `0` 关掉融合核 | 日志;Hopper 上关了它才会把偏好让给 Flash |
| `NVTE_UNFUSED_ATTN` | 环境变量 | `1` | 设 `0` 禁止原生 softmax 兜底 | 三条都不够格时前向失败,而不是默默变慢 |
| `NVTE_FUSED_ATTN_USE_FAv2_BWD` | 环境变量 | `0` | 设 `1` 时融合前向、反向改走 flash-attn v2 | 反向耗时是否突然像 Flash |
| `NVTE_ALLOW_NONDETERMINISTIC_ALGO` | 环境变量 | 允许非确定 | 设 `0` 且 Flash≥2.4.1 才要确定行为 | 同输入多次前向是否位级一致 |
| `NVTE_DEBUG` / `NVTE_DEBUG_LEVEL` | 环境变量 | `0` | 打开后点积注意力打过滤原因和最终核 | 不要靠猜当前走了哪条 |
| `set_context_parallel_group` | 点积注意力 / 多头注意力 | 不设则并行度 1 | 传入进程组、全局 rank、流和通信类型 | 前向里并行度是否大于 1 |
| `cp_comm_type` | 上面那个接口 | `p2p` | `all_gather` 先收集完整 KV;`a2a` 打散头;`a2a+p2p` 要两组进程组 | 通信是否与计算重叠 |
| `attn_mask_type` / `attention_mask` | 前向 | 无填充则不用掩码张量 | 真 = 屏蔽。1.7 起与旧填充掩码相反 | 填充位是否还在注意力分数里 |
| 门控 delta 三个模块 | 建层,线性注意力包 | 实验性,默认不用 | 不进三条点积核,需 float32 门控 | 走的是 cuDNN 线性递推,不是 Selected backend |

**典型配置**:

| 场景 | 怎么起 | 拿什么换什么 |
|---|---|---|
| Hopper 训练,短序列,确认走融合核 | 点积注意力,三条 `NVTE_*_ATTN` 保持默认 1,开 `NVTE_DEBUG=1` 与 `NVTE_DEBUG_LEVEL=1` 看 Selected backend | 零胶水;换来的是日志噪声,确认后应关掉调试 |
| 长序列,两卡上下文并行 | `set_context_parallel_group` 通信类型留 `p2p`,序列长度补到并行度乘 2 的倍数,不要关融合核 | 每卡 KV 变短;换来的是环形换块,且未融合核不可用 |
| 故意对比 Flash | Hopper 上设 `NVTE_FUSED_ATTN=0` 且保持 `NVTE_FLASH_ATTN=1`,短序列、不开上下文并行 | 让偏好让位;八位加并行时这条对比无效,Flash 会被过滤掉 |
| 线性递推实验 | 用 `GatedDeltaNetAttention`,不要设上下文并行组 | 换点积为线性状态;与三条核、掩码极性都不是同一套契约 |

组合与推荐值是按语义推的起点,不是实测最优。

**观测三处**:当前核看调试日志的 Available / Selected,不要看 pip 里有没有 flash-attn;并行有没有真开,看进程组是否设上以及长度是否整除;掩码看填充位对应的真值,不要沿用 1.7 以前的包含语义。

| 症状 | 先查 | 然后 |
|---|---|---|
| 换了点积注意力,比 Flash 还慢或显存爆 | 日志是否落到 Unfused;是否该开上下文并行却没开 | 打开调试;不够格的形状先改;长序列补齐并设并行组 |
| Hopper 上死活走 Flash | 是不是把融合核环境变量关了;融合核是否被形状过滤 | 恢复 `NVTE_FUSED_ATTN=1`;看过滤原因而不是强行指定 Flash |
| 开了并行立刻失败或落到未融合 | 长度是否能被并行度乘 2 整除;掩码/偏置/八位是否把核滤光 | 补长度;八位并行只留融合;自定义配方先关并行 |
| loss 从换掩码那次开始反 | 填充位是不是仍填成真表示「有效」 | 改成真 = 屏蔽,与 1.7 起 README 一致 |
| 门控 delta 前向类型错误 | 门控是否 float32、形状是否跟头数对齐 | 不要把点积的 QKV 布局和掩码直接套上去 |

## 六、常见误区

**「装了 flash-attn,就一定会走 Flash。」** Hopper 及以上只要融合核也合格,选择函数会把 Flash 关掉。总开关默认开着,不等于最终选中。

**「关掉 Flash 就能逼出融合核。」** 融合核也可能被形状、掩码、并行组合滤掉,然后落到未融合。三条都要看日志,不要只拨一个开关。

**「长序列开张量并行就等于切开了上下文。」** 张量并行切的是头和通道,KV 序列长度还在。上下文并行才切序列。两套不是同一个进程组。

**「未融合核也能拿来做上下文并行兜底。」** 选择函数直接禁用。并行开着只剩未融合,就是失败,不是慢一点。

**「掩码真值还是 1.7 以前那种,真表示这个位置要算。」** 从 1.7 起全框架统一为真 = 屏蔽。旧脚本原样搬过来,填充位会进注意力。

**「线性注意力变体是第四条点积后端。」** 它们是另一套实验模块,不进选择函数,也不走上下文并行切法。
