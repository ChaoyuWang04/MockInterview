## 重要模块覆盖与正文取舍

- FP8 storage helpers实际处理Float8/MXFP8/grouped tensor和量化主参数分片,不是只做dtype cast: `fp8_utils.py:105-329,374-380,432-700,705-727`;scale与amax处理依TE版本分支。NVFP4 shard量化委托TE并保留FP32主参数语义: `fp4_utils.py:135-174`。
- TE recipe wrapper `extensions/transformer_engine.py:135-451` 区分训练/验证recipe与初始化存储;`TransformerEngineMixedPrecision.md:25-48` 明示训练存储默认BF16及与graph/recompute未验证的限制。训练侧不继承推理优化后端的自动存储继承例外。
- TE模块适配覆盖Linear/LayerNormLinear/Attention/GroupedLinear及RNG;正文只取量化context入口。`extensions/kitchen.py:1-33` 为未公开扩展stub,不写成当前可直接使用的公开实现。
- 融合目录已盘点: bias GELU/GEGLU/SwiGLU与weighted activation、bias/dropout/add、softmax、LayerNorm、vocab-parallel cross entropy、routing map padding和indices转换、MLA YaRN RoPE、mHC kernel。核心示例完整读取bias GELU/dropout,另读softmax/LayerNorm条件。其他目录成员已确认入口和用途,不宣称逐个kernel全部逐行审过。它们属于不同shape/模块路径,不能声称一个总开关全启用。
- `jit.py` 选择编译装饰器;不是由CUDA graph自动完成fusion。
- local runner记录/捕获/重放与参数匹配 `cuda_graphs.py:1679-1815,1987-2158`;TE捕获组织、PP顺序、额外warmup与版本分支 `:2613-2777,2836-2892`。不把每个microbatch的graph数简化成一张全模型图。
- Core full wrapper有training/validation独立graph和reset;shared memory pool优化不等于不占额外显存,构造函数裸默认与实际训练传入值不同,正文使用配置最终默认。
- CUDA graph配置归一化旧full和旧full_iteration分开处理;文档有dev-only paged stash配方,正文未将其无条件推荐为任意MoE的整轮capture方法。offload/recompute约束交11章,本章不声称全不兼容或全兼容。
- batch-invariant kernel `transformer/custom_layers/batch_invariant_kernels.py:1811-1875`: native workspace限制或Triton/DeepGEMM替代,并patch部分归约;`transformer/moe/batch_invariant.py:13-123` 固定rank/top-k加法顺序。`TransformerConfig:3620-3695` 有特定MXFP8专家组合与融合冲突,故正文只列基础条件加“等”,不声称所有状态只能BF16。推理引擎 `core/inference/` 不在本系列范围。

## 图的编码与数字证据

12a使用同一条GEMM→bias→GELU→GEMM示意链,来自 `MLP.forward` 的FC1/activation/FC2边界。不是实际trace或保证kernel数量。低精度仅画4个值的payload:4×16/8=8 B、4×8/8=4 B、4×4/8=2 B;显式排除scale与padding,FP4打包对应 `fp4_utils.py:70-77`。四个矩形表示四个元素,宽度按payload比例,不编码耗时或全模型显存。

fusion行把bias/GELU放在同一区域,中间值显存往返是机制示意;实际编译kernel数量依后端。graph行保持相同操作节点,由4个示意launch改为一次replay提交该区域;不声称整轮训练只有一次CPU调用。图未把fusion与低精度自动叠加,三行分别说明优化位置。
