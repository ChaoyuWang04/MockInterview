# 模型层与混合架构

这一页回答一个问题:怎样在同一训练接口下组织 attention、MLP 与状态空间层,又不把更换模型容器误认为架构没有变化。说法都在源码基准 `fb6a123a09`(tag `core_v0.19.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

标准 GPT 的一层通常同时包含 attention 与 MLP。如果希望独立安排 attention、Mamba、GDN 和专家层,继续把所有变化塞进同一种完整 Transformer block,层数、流水线切分和旧权重的位置就容易混在一起。

Megatron 的 HybridModel 把层的计数单位改成**一个 layer family 的位置**。这让异构序列可以明确表达,也带来一个必须先解决的问题:新列表里的第几层,究竟对应旧模型的哪一部分。

## 二、解法

**pattern 先决定计算顺序,再决定每个位置的层类型。** 标准 GPT block 中的 attention 与 MLP 可以拆成相邻的两个 Hybrid layer。因此模型名字变了、层数翻倍了,仍可能保留原来的计算顺序;反过来,插入一个状态空间层,即使 hidden size 不变,也已经改变计算。

![两个 GPT block 的 attention 与 MLP 分别对应四个 Hybrid layer,插入 Mamba 后新增位置没有原 GPT 权重来源](/opensource/Megatron-LM/14a-hybrid-layer-families.svg)

**模型外壳保留训练需要的接口。** HybridModel 组织 embedding、本地 decoder 和输出层,接收 token 或外部提供的 embedding;末端有 labels 时返回 loss,否则返回 logits,非末端继续传递 hidden states。内部先选择当前流水线段,再按各位置独立的配置构造层。Mamba 层也保持输入输出的 hidden-state 形状,由自己的 mixer 完成序列计算。具体构件如何装配见 08 章。

**多模态组合发生在另一层。** 例如 LLaVA 路径先把视觉或音频特征投影到语言模型空间,与文本 embedding 合并,同时对齐 labels 和 loss mask,再交给语言模型。语言 decoder 可以选 GPT 或 Hybrid;这不等于把图像编码器写成 Hybrid pattern 的一个符号。

## 三、代价

**所有按层编号的配置都要重新核对。** 原来属于同一个 GPT block 的 attention 和 MLP 现在占不同位置,逐层列表、checkpoint 映射和 PP 切分都要使用新口径。层数相同也不意味着计算量相同,异构层的耗时可能不同。

**可表达的架构多于可从 GPT 自动加载的架构。** 当前加载器可以把匹配的 GPT attention 与 MLP 权重送到 Hybrid 的对应位置;插入的 Mamba 保留新初始化,不能被解释为从旧 attention 自动转换而来。保架构迁移仍需对比固定输入上的 logits,新增层则需要单独验证训练效果。

**统一接口没有消除构件限制。** pattern 解析会拒绝标准 attention 与 MLA 系列 attention 混在同一模型的组合,层实现也有自己的依赖与并行约束。实验 attention 的算法留在 15 章,本章只说明它们从哪里进入模型。

## 四、和同类常见做法不一样的地方

PyTorch FSDP可以管理给定模型的分片,HybridModel则负责定义模型内部的层序列。对本章而言,有意义的差别是“保持已有结构”与“重新组织计算结构”各自需要检查什么。

| 对比维度 | PyTorch FSDP的模型外接入 | Megatron HybridModel |
|---|---|---|
| 模型结构从哪里来 | 调用方提供模型,分片围绕其模块安排 | 有序pattern选择attention、MLP、Mamba等layer family |
| 层数变化意味着什么 | 分片管理范围不替模型定义层的语义 | GPT block拆成多个Hybrid位置会改变计数,计算顺序仍可保持 |
| 复用旧权重的前提 | 仍需模型自身具有兼容的参数与恢复关系 | 兼容映射识别GPT权重来源,插入的新层可能保留新初始化 |

因此保架构迁移应验证固定输入输出,新增层则需验证新架构的训练效果。两种目标都不能由“已经能分片运行”替代。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

**在哪调。** 以下使用传统 `pretrain_hybrid.py` CLI 路径。该 builder 的 `--spec` 要导入静态 `ModuleSpec`,不是工厂函数;配置容器的 builder 是另一条入口。直接使用 Core 时,调用者还须让配置中的层数与主 pattern 一致。

| 参数 | 默认 | 调整的作用 | 怎么看 |
|---|---|---|---|
| `--hybrid-layer-pattern` | 无 | 指定有序层序列;CLI 从主 pattern 推导层数,忽略分隔符和 MTP 后缀,覆盖原 `--num-layers` | 启动后的总层数、各类型数量和实际层列表 |
| `--spec` | 无;本章 CLI 训练路径必须提供 | 选择 Hybrid stack 各 layer family 的具体实现 | builder 的规格类型检查与构造结果 |
| `--pipeline-model-parallel-size` | `1` | 与 pattern 中的流水线分段共同决定本 rank 的层;显式段数须能被 PP 大小整除 | 各 stage 的层类型与参数量,不要只看层数均分 |
| `--load`、`--ckpt-format` | 加载路径无;格式 `torch_dist` | 有源模型元数据时,支持从 GPT checkpoint 自动加载到兼容 Hybrid 架构;也支持 Megatron-FSDP 的 `fsdp_dtensor` | GPT→Hybrid 配对日志及缺失/多余权重 |
| `--finetune`、`--no-load-optim` | 均关 | 前者选择重新开始 iteration 等训练进度;自动 GPT→Hybrid 路径若要优化器也全新开始,还需后者 | 恢复后的 iteration 与 optimizer 状态 |

**pattern 怎么读。** 每个层符号占一个位置,分界符本身不占层。

| 符号 | 当前含义 |
|---|---|
| `M`、`G` | Mamba、GDN 家族 |
| `*`、`+`、`D` | 标准 self-attention、MLA、DSA |
| `C`、`H`、`W` | DSv4 attention 的压缩、重压缩和仅滑窗变体 |
| `-`、`E` | 稠密 MLP、MoE |
| 竖线分隔符、`/` | 前者分流水线段;后者引入 MTP 模板,每段模板对应一个预测深度,各模板须相同 |

流水线分隔符写作 `|`,例如 `*-|*-` 显式指定两个段;它不占层数。

**配置起点**:以下沿用一个已可运行的、2 个 block 的稠密 GPT/Transformer Engine BF16 配方,使用支持 BF16 的 GPU,保持宽度、attention 结构、位置编码和词表等设置。共同改用 `pretrain_hybrid.py`,移除旧 `--num-layers`,设置 `--spec megatron.core.models.hybrid.hybrid_layer_specs hybrid_stack_spec`。pattern 始终用单引号包住,避免 shell 展开。

| 场景 | 增量设置 | 代价与前提 |
|---|---|---|
| 验证保架构的权重迁移 | `--hybrid-layer-pattern '*-*-' --load /path/to/gpt-checkpoints --finetune --no-load-optim --save /path/to/new-hybrid-run` | 主 decoder 为4层;这里明确只继承模型权重,训练进度与优化器重新开始,先对比固定输入的 logits |
| 将相同顺序放入2个流水线段 | 在首组改为 `--hybrid-layer-pattern '*-*-' --pipeline-model-parallel-size 2` | 使用至少2张GPU,本例无显式段界时按层均分;删除旧PP/VPP布局开关,避免两套布局定义冲突 |
| 从头验证含Mamba的新架构 | `--hybrid-layer-pattern 'M*-M*-' --save /path/to/new-mixed-run`,不设置旧checkpoint加载路径 | 主 decoder 为6层,需要Mamba依赖与适配的层配置;新增计算不保证速度或质量收益 |

组合与推荐值是按语义推的起点,不是实测最优。

**看哪里。** CLI builder 会输出本地层的参数量。加载 GPT checkpoint 时,日志说明多少 GPT 层映射到 attention/MLP 位置,多少新层保留初始化。自动转换允许匹配数量的标准 attention 与单一类型的稠密或 MoE MLP,可插入 Mamba,但不接受 MTP 后缀及其他不兼容 layer family。若继续加载 `torch_dist` 的 optimizer,源状态还需 model-space 格式;反向将 Hybrid checkpoint 直接载入非 Hybrid 模型会报错。完整状态搬运机制见 13 章。

| 症状 | 先查 | 然后 |
|---|---|---|
| 改入口后层数翻倍 | 是否把一个 GPT block 拆为 attention 与 MLP 两层 | 对齐计算顺序和权重来源,不要为了匹配数字删掉一半层 |
| pattern 能构建却不能加载 GPT 权重 | layer family、attention/MLP 数量、MTP 与源模型元数据 | 区分保架构迁移和新架构初始化,不要跳过校验硬载 |
| PP 后某 stage 明显更慢 | 各段的层类型、参数量与执行时间 | 调整段边界,不要假设每个符号成本一样 |
| 多模态接入后 loss 位置错位 | 合并后的 embedding、labels 和 loss mask 长度 | 核对模型适配层的占位展开,不要只修改语言模型层数 |

## 六、常见误区

**「文档符号表就是全部支持类型。」** 当前迁移指南的简表没有列全 MLA 与 DSv4 变体;实际解析器包含更多符号。但解析器识别某个符号,也不意味着 GPT 自动转换能为它提供权重。

**「加载没报错,插入的新层也继承了预训练能力。」** 自动加载可以保留 Mamba 的新初始化,因此成功读取 checkpoint 只说明已有权重找到了位置。应查看新初始化层的警告,并把这个结果当作新架构的训练起点。

**「加一个分界符等于增加一层。」** 流水线与 MTP 分隔符只是结构标记。MTP 模板中的层属于额外预测分支,主 decoder 的层数只数首个分隔部分里的层符号;直接数整个字符串会把两种深度混为一谈。
