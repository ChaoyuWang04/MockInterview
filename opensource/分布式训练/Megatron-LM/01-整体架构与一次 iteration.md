# 整体架构与一次 iteration

这一页回答一个问题:参考训练入口怎样把 Core 的能力组织成一次 iteration,自己写训练循环时又能复用哪些部分。说法都在源码基准 `fb6a123a09`(tag `core_v0.19.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

并行维度决定一份模型分布在哪些卡上,global batch 与 microbatch 则决定一次更新如何拆成多轮前反向。两套划分必须对上,否则要么启动失败,要么执行方式与预想不同。

![常规配置下先由总卡数和 TP、PP、CP 算出 DP,再由 global batch、microbatch size 与 DP 算出 microbatch 数;PP 改变时局部调度改变,固定 global batch 的全局样本数不变](/opensource/Megatron-LM/01a-the-two-divisions.svg)

图只讲没有额外权重分片轴、固定 global batch 的常规路径。特殊并行轴和动态 batch 交给对应实现处理,不影响这里要抓住的关系:先确定参与切分 batch 的数据并行范围,再计算一次更新要执行多少个 microbatch。

## 二、解法

参考入口把一次训练组织成三个阶段。

**启动:把配置变成可执行的训练状态。** 参数先经过校验与派生,然后初始化分布式环境与进程组、构造模型和优化器、恢复 checkpoint,并准备数据迭代器。参考层负责衔接这些动作,Core 提供并行状态、microbatch 计算器、模型构件与执行能力。

**一次 iteration:调度完成后才能更新。** 先清理梯度,再由调度器驱动数据读取和各个 microbatch 的前向、反向。开启梯度通信 overlap 时,部分归约在反向期间已经发起;进入参数更新前仍须完成相应同步与梯度处理。随后优化器更新参数,参考循环推进学习率和训练进度。更新被跳过时,相应状态也要按实际结果处理。

**步与步之间:决定是否评估、保存或退出。** 日志、评估与 checkpoint 编排由参考循环负责,它们不是每个 microbatch 都执行的步骤。满足保存或退出条件时才进入对应分支。

模型的组织方式也会影响这条主线:流水线调度收到的是本 rank 持有的 model chunk 列表。不开交错式流水线时通常只有一个 chunk;开启后,同一 rank 可以持有多个 chunk。

![构造入口生成本 rank 的一个或多个 model chunk;每个 chunk 按配置选择精度包装与数据并行包装,包装用嵌套框表示](/opensource/Megatron-LM/01b-one-function-many-chunks.svg)

当前 GPT 参考入口通过配置容器与 builder 构造模型,仓库也保留 model provider 回调路径。图强调两条路径共同交付的模型结构,不要求读者记住每个构造函数。

## 三、代价

**复用参考层会带入它的状态约定。** 参数、计时器、tokenizer 等由参考层统一管理。选择性调用其中的辅助函数时,要满足相应初始化前提;直接使用 Core 的组件,则按该组件要求提供配置和进程组,不必无条件复制参考层的全部单例。

**启动本身有成本。** 编译辅助代码、建组、装配模型、读 checkpoint 和准备数据都可能耗时。应把启动时间与稳定训练步的耗时分开观察。

**并行划分改变局部执行。** PP 增大后,每个 rank 的层数、microbatch 数和通信次序会变化。固定模型、序列长度与 global batch 时,全局每步处理的样本数并没有因此增加;收益来自这些局部变化能否更好地使用硬件。

## 四、和同类常见做法不一样的地方

**可组合的库之外,还提供参考循环。** PyTorch FSDP 主要提供模型分片接口,DeepSpeed 提供训练引擎,通常由调用方组织外层循环。Megatron Core 同样可以由外部循环驱动,而 Megatron-LM 还提供一套现成编排。比较时要分清库与参考入口,不能把参考循环当成使用 Core 的必要条件。

**模型切分与调度相互配合。** 参考入口构造本 rank 所需的 model chunk,调度器按这个列表安排前反向。精度和数据并行包装由配置决定,并不是所有模型都固定经过两层包装。

**第三方可以按需复用两层。** verl 主要复用 Core;slime 除了 Core,还复用参考层的参数、模型构造和 checkpoint 辅助函数。采用自己的循环,不等于参考层其余代码全部失去用途。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

**在哪调。** 参考入口通常使用 CLI,部分参数从配置类生成,再转换成运行配置。`--yaml-cfg` 是实验性独立路径,使用嵌套结构与单独校验,不能简单当成 CLI 同名键的文件版。直接接 Core 时,用配置对象与初始化接口提供所需信息。

| 参数 | 默认 | 调整的作用 | 怎么看 |
|---|---|---|---|
| `--micro-batch-size` | 必须指定 | 单个 microbatch 的样本数;影响激活显存和一次更新的 microbatch 数 | 峰值显存、每步耗时 |
| `--global-batch-size` | 未指定时由 microbatch size 与 DP 派生 | 一次更新的总样本数;常规固定批量路径按 DP 和 microbatch size 计算 microbatch 数 | 日志中的 `global batch size` |
| `--train-iters` / `--train-samples` | 无 | 按步数或样本数设置训练长度 | `iteration x/y` 与训练进度 |
| `--save` / `--load` | 无 | 指定 checkpoint 保存和恢复位置 | 启动及存档日志 |
| `--save-interval` | 无 | 周期存档间隔 | 存档频率和对应耗时 |
| `--ckpt-format` | `torch_dist` | 选择存档格式;重新分片恢复还取决于模型与状态支持 | 恢复日志,详见 13 章 |
| `--async-save` | 关 | 部分落盘工作异步执行;不代表快照创建和退出收尾完全不等待 | 存档步与相邻步耗时 |
| `--exit-interval` / `--exit-duration-in-mins` | 无 | 到达步数或时间边界时有序退出 | 退出原因与最后 checkpoint |
| `--exit-signal-handler` | 关 | 处理可捕获的终止信号,按配置保存并退出 | 需有可用存档目录及足够收尾时间 |
| `--log-interval` / `--log-throughput` | 100 / 关 | 日志频率与吞吐输出 | 训练日志 |
| `--eval-interval` / `--eval-iters` | 无 / 100 | 评估频率与长度 | 评估耗时和 loss |
| `--manual-gc` / `--manual-gc-interval` | 关 / 0 | 手动组织 GC;非零间隔才额外按训练步触发,还存在评估边界处理 | 耗时波动 |
| `--rerun-mode` | `validate_results` | 控制结果校验和重跑策略 | 重跑与异常日志,详见 17 章 |

**配置起点**:以下是已有模型配方上的增量配置,不是完整训练命令。模型尺寸、卡型、数据与并行度沿用已核对的配方。

| 场景 | 增量设置 | 代价与前提 |
|---|---|---|
| 调试参考训练链路 | `--log-interval 1 --log-throughput`,用较短训练长度 | 日志更密;需要续跑时仍要配置存档 |
| 长时间训练 | 指定 `--save`、`--save-interval`,按格式支持启用 `--async-save` | 增加存储与保存开销,需检查异步任务结果 |
| 可提前通知的抢占 | 在存档配置上加 `--exit-signal-handler`,必要时指定时间边界 | 调度器须留出执行与保存时间;不能保证节点失联或强制杀进程时保存成功 |

**看哪里。** 启动阶段分开看建组、模型与优化器构造、checkpoint 恢复、数据准备。稳定训练阶段,固定模型、序列长度和 global batch 后比较 `elapsed time per iteration (ms)`、tokens/s 和吞吐;每 GPU 吞吐需开启相应日志。跳步与数值异常用于定位训练是否正常,完整监控见 17 章。

| 症状 | 先查 | 然后 |
|---|---|---|
| 启动报整除错误 | rank 划分还是 batch 划分不合法 | 对齐总卡数、并行度、global batch 和 microbatch size |
| 改并行度后变慢 | 比较的模型和每步工作量是否相同 | 再看各 rank 的计算、通信和流水线 bubble |
| 自写循环调用辅助函数失败 | 出错函数属于 Core 还是参考层,依赖哪些状态 | 只补该路径所需初始化,不要默认全部重写 |
| 退出后没有可恢复 checkpoint | 是否启用保存、是否收到可处理信号、收尾是否完成 | 检查目录、日志与调度器宽限时间 |

## 六、常见误区

**「自己写循环就不能用参考层。」** 容易把外层编排与辅助函数当成不可拆的一整块。实际上可以选择性复用,代价是满足被调用函数的配置和状态约定。

**「PP 增大,microbatch 数翻倍,全局工作量也翻倍。」** 只盯着局部调度会得出这个结论。固定 global batch 时,DP 数和每个 rank 持有的层数也在变化,全局样本数保持不变。

**「不开交错式流水线就拿到单个模型对象。」** 物理上只有一个 chunk,并不意味着接口返回单个对象;参考实现也会把它组织成长度为 1 的列表。按调度接口约定接入即可。

**「CPU 初始化和两层包装是必经步骤。」** 一张简化图容易留下这种印象。初始化设备与 dtype 受配置控制,精度包装和 DDP/FSDP 包装也要分别看启用条件。

**「异步存档意味着随时退出都安全。」** 异步只把部分保存工作移出主路径,退出前仍需完成必要收尾。周期存档、信号处理与实际恢复验证各有作用。
