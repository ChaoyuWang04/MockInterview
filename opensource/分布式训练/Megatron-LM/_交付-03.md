# 03 章交付:张量并行与序列切分

基准 `/tmp/megatron-base`,commit `fb6a123a09f524a2abfca81a78b6478358ca77e0`,tag `core_v0.19.2`。2026-09-22 返工;只修改 03 正文、两张 SVG 与本文件,未改共享底稿/99/源码,未 commit。

主旨:TP、SP、CP 的收益与代价取决于哪些张量保持分片,以及交换发生在计算链的哪里。

## 图的数字、箭头与编码

- 03a:三行是同一标准稠密块的前向主路径,非时间轴;7格是区域压缩,LayerNorm/dropout合并为逐token区域,不声称它们在真实执行中都先于attention。绿色为TP分片计算,灰色为TP复制区域,黄色为SP切分区域,紫色标通信。两次TP all-reduce或两组all-gather/reduce-scatter来自上述layers与spec。CP行以默认P2P ring为例,只有attention额外CP通信,原有TP/SP通信仍然存在;不涵盖MoE、Mamba、GTP、推理融合。横线表示数据向后流,没有时间/带宽编码。通信字节相当只指常见collective分解,不声称次数/耗时相同。
- 03b:3卡6段是演示规模;分配162534来自Mamba代码示例。作者假设第k段权重为k,连续配对得到3/7/11,首尾得到7/7/7;与真实causal FLOPs存在简化,明确不推11:7耗时比。条形统一24px/单位,长度72/168/264px;原图76/178/280并不严格成比例,本轮同时修正。颜色只表示rank0/1/2,上排6个等宽框表示等长序列分段。
