# Transformer 构件与装配

这一页回答一个问题:同一套 Transformer 骨架怎样换用不同的 attention、MLP 与归一化实现,而不必为每种组合重写整层。说法都在源码基准 `fb6a123a09`(tag `core_v0.19.2`)上核过,「当前」与「默认」都指这组基准。

## 一、核心问题

模型变化不只发生在层数和宽度上。attention 可能换成 MLA,归一化可能独立执行或融合进线性层,MLP 也可能由不同实现提供。如果这些选择都写死在层的构造函数里,增加一种组合就得修改框架内部,而且容易漏掉输入输出、进程组或 checkpoint 的约定。

Megatron 把“选择谁来实现”与“这一层怎样组织计算”分开。它提供的是有固定接口的装配位置,不是任意模块之间都能自动接线。

## 二、解法

**配置定尺寸与行为,规格定构件。** TransformerConfig 保存层数、宽度、head 数等信息;ModuleSpec 则描述要构造的类、构造参数和子模块规格。GPT 的规格工厂根据后端和模型配置选择 norm、attention、线性层与 MLP 的实现,再把它们交给层构造器。

![配置和后端工厂生成嵌套规格,TransformerBlock 为本 stage 的各层分别创建实例,每层再按规格构造 attention 与 MLP](/opensource/Megatron-LM/08a-spec-to-layer-block.svg)

**层负责接线,构件负责完成自己的接口。** 一层把归一化、attention、残差相加和 MLP 串起来。attention 内部还可以继续指定投影与核心 attention 实现。某些位置收到的是函数或 builder,因此装配并不要求每个节点都包装成一个 ModuleSpec。例如 MLP 的 builder 会接收配置和进程组,归一化也通过自己的构造接口创建。

**block 管本地的层列表。** 传入同一种 layer spec 时,block 按本 stage 应有的层数逐个实例化;也可以直接接收逐层不同的规格列表。重复的是构造说明,不是同一个层对象。普通执行路径按列表调用各层,末尾是否加最终归一化则由模型与 stage 的位置决定。

MLA 接在 self-attention 位置,但带有自己的投影和归一化规格、专用配置字段。MTP 则是另一层装配:在归一化与融合投影外再包一个内部模型层,由独立的 MTP block 组织。两者都复用构件接口,但不是随便替换类名就完成接入。

## 三、代价

**替换实现必须满足调用契约。** attention 会接收 mask、位置信息、推理上下文等输入;线性层或 MLP 还可能返回输出与独立 bias。只保证张量最后一维相同不够,构造参数、返回结构和进程组也要匹配。

**融合改变模块树的外观。** 某个 norm 位置看起来是恒等操作,不一定表示没有归一化:标准 Transformer Engine 规格可以把它融合到后续投影。checkpoint 的参数名因此可能需要映射,切换实现时不能只比较模块数量。

**可组合不等于所有组合都支持。** 配置会检查维度整除等约束,构件还有各自限制;自定义规格也须接入分片 checkpoint 的状态描述。重算与计算优化如何包住这些构件,分别在 11、12 章展开。

## 四、和同类常见做法不一样的地方

**这里的接口介入模型内部的装配。** PyTorch FSDP 的概括性职责是给模型增加状态分片与通信;本章的规格系统则决定 attention、MLP 和 norm 由谁实现、怎样组成层。理解这一区别,就能分清“替换模型构件”和“给模型加分片能力”分别要改哪一层。

Megatron 也不是只有一条装配入口:通用 layer spec、逐层 block spec 和面向不同模型的 builder 可以并存。选择可复用的那一级接口,比把整个 Transformer 层复制出来更容易保留框架既有约定。

## 五、调参与观测

这一页的参数全是启动配置,改了要重新拉起整个作业。

**在哪调。** 参考 GPT 入口由 CLI 转换配置,再选择默认规格;直接使用 Core 时可显式传入配置、spec 与进程组。自定义 `--spec` 使用 Python 模块路径和导出符号。当前配置容器路径的 `GPTModelBuilder` 支持调用工厂取得规格;传统 `gpt_builder` 路径直接把导入对象传给模型,两条入口不能混用工厂约定。

| 参数 | 默认 | 调整的作用 | 怎么看 |
|---|---|---|---|
| `--num-layers`、`--hidden-size`、`--num-attention-heads` | CLI 无可用模型默认,由配方指定 | 决定模型规模与构件尺寸,影响显存和计算量;本地层数还受 PP 布局影响 | 最终配置、各 rank 的层列表和参数形状 |
| `--transformer-impl` | `transformer_engine` | 选择默认构件实现路线;`local` 使用 Core 本地实现,但不代表所有外部依赖都消失 | 实例中的投影、norm 和 attention 类 |
| `--normalization` | 普通 Transformer 配置为 `LayerNorm` | 选择归一化类型,不是单纯性能开关;MLA 专用配置的类默认另为 `RMSNorm`,参考入口应核对最终值 | 独立 norm 或融合投影的配置与权重 |
| `--qk-layernorm` | 关 | 为适用的 attention 加入 Q/K 归一化,改变计算与参数结构 | Q/K norm 构件及加载兼容性 |
| `--multi-latent-attention` | 关 | 选择 MLA 配置与构件;还需配套 latent/head 维度及模型配方 | attention 实例与投影形状 |
| `--mtp-num-layers` | 无 | 正数启用额外 MTP 深度,增加计算和训练目标;位置与模型支持需同时满足 | MTP block 与对应 loss |
| `--spec` | 无,走默认选择 | 导入自定义规格或工厂,按所用入口的契约替换构件;不是自动适配任意 PyTorch 模块 | 构造错误中的 `when instantiating` 类名,以及实际模型树 |

**配置起点**:以下是已有可运行的普通稠密 GPT 配方上的增量,使用支持该配方精度的 GPU。先保持层数、宽度、数据与并行布局一致,不混入 MLA、MTP 或量化变化。

| 场景 | 增量设置 | 代价与前提 |
|---|---|---|
| 查看默认加速构件如何装配 | `--transformer-impl transformer_engine` | 依赖匹配的 Transformer Engine 环境;norm 可能融合在投影内 |
| 对照本地构件结构 | `--transformer-impl local` | 执行实现和性能可能变化;检查配方所需算子依赖与 checkpoint 映射 |
| 从头训练时验证 Q/K norm 变体 | 在首组加 `--qk-layernorm` | 增加归一化构件,属于架构变化;不能直接假定旧 checkpoint 等价兼容 |

组合与推荐值是按语义推的起点,不是实测最优。

**看哪里。** 先核对最终配置,再看构造完成的模型树:本 rank 有哪些 layer、attention 和 MLP 的具体类型是什么、norm 是独立模块还是融合在投影里。自定义规格发生构造错误时,装配函数会把正在实例化的类名补进异常。结构匹配后再核对 checkpoint 的键和张量形状,最后用小规模前反向检查接口;只看到模型成功创建,还不能认定训练语义相同。

| 症状 | 先查 | 然后 |
|---|---|---|
| 自定义类构造时报未知参数 | 所在位置的 builder 接口,实际收到的配置/进程组/层编号 | 适配该位置的契约,不要删掉外层传参来掩盖不匹配 |
| 同样层数,某 rank 的层列表更短 | PP/VPP 布局与当前 stage | 对照本地层数和全局层偏移,不要把模型分布误判为漏层 |
| 切换实现后找不到独立 norm | 后端是否使用融合 norm+linear | 看融合模块权重及状态字典映射 |
| 自定义 attention 能创建却在前向报错 | 输入关键字、返回结构、mask 与 packed 输入支持 | 按 attention 契约逐项核对,不只比较 hidden size |
| 打开 MLA/MTP 后旧权重不匹配 | 构件类型、投影尺寸与新增模块 | 使用相应模型配方和转换/初始化策略,不要当成透明性能切换 |

## 六、常见误区

**「spec 复制几次,权重就共享几次。」** block 的规格列表确实可以引用同一份说明,但构造循环会分别调用 builder,产生独立实例。共享权重需要另有明确实现;MTP 的重复层模式也有自己的专门分支。

**「配置里写了后端,自定义 spec 就会自动随它改变。」** 默认规格工厂会读取配置选择实现,但自定义规格若已经指定某个具体类,装配函数会按这份指定去构造。要换实现,应检查工厂是否使用了该配置。

**「换成同形状模块就兼容。」** Transformer 的构件契约还包括 bias 的返回方式、进程组和状态保存。形状正确只通过了其中一项,剩下的问题可能到反向或恢复 checkpoint 时才暴露。
