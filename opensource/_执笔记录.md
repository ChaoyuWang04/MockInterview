## 依据与局限

- **Claude**:会话记录 `~/.claude/projects/*interviewprep*/` 里的 `Write` 与 `Edit` 调用;提交带 `Co-Authored-By: Claude` 署名。
- **Codex**:会话记录 `~/.codex/sessions/`、`~/.codex/archived_sessions/` 里的补丁与写文件调用;提交信息为英文的 `docs: complete…` 一类,多次提交已核到是 Codex 会话执行的 `git commit`。
- **Grok**:经 Hermes 运行,默认模型 `grok-4.6`。子 Agent 的实况记录在 `~/.hermes/cache/delegation/live/`,逐条记有 `write_file` 与 `patch`;提交信息为中文的 `feat(opensource): X 章成稿`。
- **推断的部分**:Hermes 主会话存在 `~/.hermes/state.db`,本次没有读取,所以 Grok 那几个项目的 00、01 章以及收尾章只能按「06 规定序章与 01 章由主线程亲写」推断,标为中等把握。
- 用 shell 批量改的文件(sed、Python 脚本)只能靠启发式识别,可能漏记小改,不影响各章主笔的判断。
