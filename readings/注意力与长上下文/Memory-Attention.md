# Memory Attention：拿掉 value 投影，用「key + 按 token 查表的记忆」拼出 value

<!-- release-date: 2026-09-23 -->

**本文依据**：`Memory Attention`，arXiv 2609.28399v1（[cs.LG] 23 Sep 2026），12 页。作者 Jiale Kang，封面只给个人邮箱与 GitHub 仓库链接，没有写机构。截至核验 arXiv 只有 v1。文中数字都标 PDF 页码；标「我们的解释」「我们粗算」的段落不是论文原话，标「外部补充」的段落不来自本文。

## 一句话

标准注意力的 value 由隐状态乘一个专门的投影矩阵 $W_V$ 得到。这篇论文把 $W_V$ 整个删掉，改成 $V = K + \mathrm{Norm}(E[s])$：上下文信息借用已经算好的 key，token 自身的信息从每层一张「按 token 编号查的表」里取（PDF p. 1、p. 4）。推理时归一化可以提前烤进表里，value 的构造只剩一次查表和一次加法（PDF p. 5）。查表地址只取决于 token 编号和层号，所以表可以放到 CPU 内存、提前预取（PDF p. 5）。在同样的训练 token 数下，5 组对照里 MA 的困惑度与下游平均分都更好，但按表 2 算，参数量也是对照的约 1.6–3 倍，论文自己承认分不开「结构的功劳」和「参数变多的功劳」（PDF p. 2、p. 7）。

## 读前几个词

- **Q、K、V（query、key、value）**：注意力里的三组向量。query 和 key 做内积决定「看谁、看多少」，value 是「被看的那个位置交出来的内容」。标准做法三者都从当前隐状态各乘一个线性投影得到（PDF p. 2 式 1）。
- **value 投影（$W_V$）**：把隐状态变成 value 的那个 $d \times d_v$ 矩阵。本文要换掉的就是它。
- **Token memory（token 记忆表）**：每层一张 $N \times d_v$ 的可学习表，$N$ 是词表大小。给一个 token 编号，取出一行向量（PDF p. 3 式 7）。和输入词嵌入是同一种东西，只是每层各有一张、专门喂给 value。
- **查表式扩容（lookup-based capacity）**：用嵌入表增加参数，不按比例增加矩阵乘。Value Embedding、DeepEmbed、Per-Layer Embeddings（PLE）、STEM、Engram 都属于这一类（PDF p. 1）。
- **MHA / GQA / MQA**：多头、分组查询、多查询注意力。区别是多少个 query 头共用一组 key/value 头。本文在三者上都做了对照（PDF p. 12 表 6）。
- **Offload（卸载）与 prefetch（预取）**：把参数放到 CPU 内存，用到之前提前搬回 GPU，让搬运时间藏在计算背后。
- **NIAH（Needle in a Haystack，大海捞针）**：在长文本里埋一条信息，看模型能不能找回来。

## 一、矛盾：查表扩容一直是「外挂」，能不能替掉一块现有计算

在算力和显存都有限的前提下，让模型更好，一条路是查表扩容：多挂几张嵌入表，参数上去了，矩阵乘不跟着上去（PDF p. 1）。论文点名的前作做法各不相同：

| 前作 | 查表的键 | 查到的东西去哪 | 原有计算是否保留 |
|---|---|---|---|
| Value Embedding | 当前 token | 与投影出的 value 按 $\lambda$ 混合（PDF p. 3 式 3） | 保留 $W_V$ |
| PLE（Per-Layer Embeddings） | 当前 token | 经隐状态门控后加进残差更新（PDF p. 3 式 4–5） | 全部保留 |
| Engram | 局部 n-gram 的哈希 | 经上下文门控融合（PDF p. 3 式 6） | 全部保留 |
| Memory Attention | 当前 token | 直接加到 key 上当 value（PDF p. 4 式 8） | 删掉 $W_V$ |

前三者都是在原有计算之外「再加一条」。论文要问的是互补的一件事：显式记忆能不能替换掉一部分现有计算，而不只是补充它（PDF p. 1）。

注意力是自然的试验场。把注意力看成按内容寻址的存储器：query–key 决定取什么，value 提供被取的内容（PDF p. 1–2）。作者的假设是：value 里有一部分内容是 token 自身的、跨上下文可复用的，可以直接存成表；剩下依赖上下文的部分，key 里已经有了，不必再单独投影一次（PDF p. 2）。

**我们的解释。** 这就是整篇的主要矛盾：value 投影每个 token 每层都要做一次稠密矩阵乘，但它产出的内容里，有多少真的需要「这次上下文」才能算出来？如果答案是「不多」，那这次矩阵乘就可以换成一次查表，而查表的容量可以做得远比 $W_V$ 大。

Engram 的查表与预取已在 Engram 一篇里详细写过；本篇只关心 MA 与它的差别：MA 的表以单个 token 为键，且替换而不是补充一条通路。

## 三、核心设计：$V = K + \mathrm{Norm}(E[s])$

### 旧做法

标准自注意力从隐状态 $X$ 算三组投影（PDF p. 2 式 1）：

$$
Q = XW_Q,\quad K = XW_K,\quad V = XW_V
$$

单头输出是 $\mathrm{softmax}(QK^\top/\sqrt{d_k} + C)\,V$，$C$ 是因果掩码（PDF p. 3 式 2）。三者都来自当前隐状态。

### 新做法：先查表，再归一化，再加到 key 上

设序列的 token 编号为 $s = (s_1, \ldots, s_T)$。每个 MA 层有一张表 $E \in \mathbb{R}^{N \times d_v}$，$d_v = H_{KV} d_h$ 是所有 key/value 头拼起来的总维度（PDF p. 3）。先取出这段序列对应的行，再做归一化：

$$
M = \mathrm{Norm}(E[s]) \in \mathbb{R}^{T \times d_v}
$$

这里的 Norm 是 RMSNorm，在每个 key/value 头内部对每个 token 的向量单独做（PDF p. 3 式 7）。然后（PDF p. 4 式 8）：

$$
Q = XW_Q,\quad K = XW_K,\quad V = K + M
$$

读法：$K$ 这一项是「当前上下文与前面各层计算的结果」，因为隐状态本身已经累积了这些信息；$M$ 这一项是「这个 token 在这一层的固定档案」，同一层里同一个 token 在任何位置、任何上下文取到的都是同一行（PDF p. 3–4）。不同层各有一张表，所以同一个 token 在不同深度可以存不同的东西（PDF p. 2）。

和 Value Embedding 的关键差别有两条（PDF p. 2、p. 4）：

1. Value Embedding 在投影出的 value 旁边再混入一份嵌入；MA 把独立的 $W_V$ 删了。
2. MA 复用 key，并让 $W_K$ 和记忆表联合学习，一起去承担构造 value 的任务。

### 和 RoPE 的先后顺序

用旋转位置编码时，旋转只作用于打分用的 query 与 key，value 用的是旋转之前的 key（PDF p. 4 式 9）：

$$
Q_R = \mathrm{RoPE}(Q),\quad K_R = \mathrm{RoPE}(K),\quad V = K + M
$$

之后 $Q_R$、$K_R$、$V$ 交给原来的注意力算子，权重和聚合规则一概不动（PDF p. 4）。**我们的推断**：这意味着 FlashAttention 这类现成算子可以直接用，改动只在进算子之前；推理测试的环境里确实列了 FlashAttention 2.8.3（PDF p. 9），但论文没有专门说明算子如何接入。

### 在 GQA / MQA 里怎么对齐

记忆表的宽度等于 $d_v$，所以跟着 key/value 头数走：隐藏维 1,024 的骨干上，MHA、GQA、MQA 的表宽分别是 1,024、512、256（PDF p. 12）。共享同一个 key/value 头的那几个 query 头，也共享这份记忆贡献（PDF p. 12）。

**我们的解释。** 这带来一个直接后果：KV 头越少，每层记忆表越窄，MA 加出来的参数越少。下面第八节表 2 里 MHA、GQA、MQA 的参数量从 1,135M 降到 526M，正是这个原因。

### 可迁移启发

如果某个投影产出的内容里，有相当一部分只取决于 token 身份，就可以考虑拆成「复用一路已有的上下文表示 + 一张按 token 查的表」。这招的前提是有一路现成的、维度对得上的上下文表示可借；MA 借的是 key，所以要求 key 与 value 维度相同（PDF p. 3）。

## 四、为什么敢复用 key：和 MLA 的对照

论文用 MLA（Multi-head Latent Attention，多头潜在注意力；外部补充：它由 DeepSeek-V2 提出，本文没有给出处）给复用 key 找了一个理由（PDF p. 4）。MLA 从一份压缩的潜在表示 $C$ 同时得到 key 和 value：$K = CW_K$，$V = CW_V$（式 10）。按结合律，key 映射可以并进 query 一侧，value 映射可以挪到聚合之后（式 11–12）：

$$
A_{\mathrm{MLA}} = \mathrm{softmax}\!\left(\frac{(QW_K^\top)\,C^\top}{\sqrt{d_k}}\right),\qquad
O_{\mathrm{MLA}} = (A_{\mathrm{MLA}}\,C)\,W_V
$$

也就是说，MLA 的注意力本质上是直接在同一份共享表示 $C$ 上取内容，再用 $W_V$ 变换取回来的东西。

把被聚合的共享表示记作 $Z$：MLA 里 $Z = C$，MA 里 $Z = K$（旋转前）。两者输出分别是（PDF p. 4 式 13–15）：

$$
O_{\mathrm{MLA}} = (A_{\mathrm{MLA}} Z_{\mathrm{MLA}})\,W_V,\qquad
O_{\mathrm{MA}} = A_{\mathrm{MA}} Z_{\mathrm{MA}} + A_{\mathrm{MA}} M
$$

共同点：都用一份共享的上下文表示同时支撑打分和取内容。差别：MLA 取回后乘一个学到的线性映射；MA 直接聚合 key，再用同一组注意力权重加上一份聚合后的记忆（PDF p. 4）。论文特意声明，这只是功能角色上的对照，不代表两者表示、维度或权重相同，MA 也不是 MLA 的代数等价改写（PDF p. 4）。

**我们的解释。** 这一节是动机论证，不是证明。它说明「用同一份表示既打分又当内容」在 MLA 里已经行得通，所以 MA 删掉 $W_V$ 不是凭空冒险。但 MLA 在聚合后还有 $W_V$ 做变换，MA 连这个都没有，最后只剩输出投影 $W_O$ 来消化。记忆项虽然每条固定，聚合后的贡献仍随注意力权重变化（PDF p. 4），这是它不退化成「每个位置加个常数」的原因。

## 五、成本账：参数变多，算术变少

先把单张表的账算清。下表对应 PDF p. 5 Table 1，只统计 $L$ 个被替换层里构造 value 的部分；key 投影等共享部分不计，查表开销与内存访问也不计，推理一栏只算新处理的 token（PDF p. 5）：

| 项目 | Standard | MA |
|---|---|---|
| value 怎么来 | $XW_V$ | $K + \bar{E}[s]$ |
| 可训练参数 | $Ldd_v$ | $L(Nd_v + p_{\mathrm{norm}})$ |
| 推理时存储的参数 | $Ldd_v$ | $LNd_v$ |
| 在线构造 value 的 FLOPs | $\approx 2LSdd_v$ | $LSd_v$ |

$S$ 是新处理的 token 数：prefill 时 $S = BT$，单步 decode 时 $S = B$；$p_{\mathrm{norm}}$ 是每层归一化参数数（PDF p. 5）。

### 参数：$N > d$ 时一定变多

标准 value 投影每层 $d \times d_v$，MA 换成 $N \times d_v$ 的表。词表 $N$ 远大于隐藏维 $d$ 时，参数容量和总存储都增加；多出来的容量靠查表访问，不靠稠密投影（PDF p. 5）。

**我们粗算。** 推理测试用的模型 $d = 2{,}048$、词表 32,000（PDF p. 9），每层表的参数是 $W_V$ 的 $32{,}000 / 2{,}048 \approx 15.6$ 倍。

### 训练：算术少了，但别读成「训练更快」

标准 value 投影前向加两路梯度约 $6LSdd_v$ FLOPs；MA 只剩归一化、加法和对访问到的表项做梯度累加，量级 $O(LSd_v)$（PDF p. 5）。论文随即给出三条限定：不含优化器更新、梯度缓冲初始化和内存访问；查表本身也不意味着梯度或优化器状态是稀疏存储的（PDF p. 5）。

**我们的解释。** 最后一条很要紧。AdamW 默认给每个参数都存两份状态，表有多大，优化器状态就有多大，每步更新也要扫全表，除非实现专门做了稀疏更新。论文没有写它的实现是否做了稀疏更新。

### 推理：把归一化烤进表里

推理时表和归一化参数都固定了。归一化是逐行独立做的，所以可以提前对全表算一遍（PDF p. 5 式 16）：

$$
\bar{E}[i] = \mathrm{Norm}(E[i]),\quad i = 1, \ldots, N
$$

在线构造 value 就只剩 $V = K + \bar{E}[s]$，一次查表加一次逐元素加法（PDF p. 5 式 17）。省下的算术约为（PDF p. 5 式 18）：

$$
\Delta F_V \approx LSd_v(2d - 1)
$$

全模型的 FLOPs 降幅是它除以「未变部分 $F_{\mathrm{common}}$ 加上原来的 $2LSdd_v$」（PDF p. 5 式 19）。论文没有代入具体数字，并提醒算术减少不直接决定延迟，延迟还取决于内存访问、kernel 执行和同步（PDF p. 5）。

**我们粗算。** 对推理测试那个 24 层、$d = d_v = 2{,}048$ 的模型，$W_V$ 共约 100.7M 参数（这正好对上第八节表 4 里 MA-Offload 比 Standard 少的那部分 GPU 参数）。按每参数 2 FLOPs，每个 token 省约 0.2 GFLOPs；整模型 1,364M 参数对应每 token 约 2.7 GFLOPs 的矩阵乘，降幅量级约 7%，还没算注意力打分本身。这是粗略量级，不是论文数字。

## 六、MA-Offload：地址只看 token 编号，所以能提前搬

烤好的表不必留在 GPU。它的查表地址只取决于 token 编号和层号，在对应层的隐状态算出来之前就能确定要哪几行；MA-Offload 把表放在 CPU 内存，提前把需要的向量预取到 GPU，让检索和传输与模型计算重叠（PDF p. 5）。

这和 Engram 能预取的理由是同一条（PDF p. 3）：寻址不依赖隐状态。

账怎么算（PDF p. 6）：

- 移出 GPU 的参数字节数是 $P_{\mathrm{offloaded}} = b_w L N d_v$（式 20），$b_w$ 是每个元素的字节数。总参数量和算术都不变，GPU 上仍需要临时的查表与传输缓冲。
- 不做缓存与去重时，处理 $S$ 个新 token 的主机到设备传输量是 $D_{\mathrm{Offload}} = b_w L S d_v$（式 21）。
- 有常规 KV cache 时，历史 value 已缓存，每步 decode 只为新 token 取记忆，即每步 $b_w L B d_v$ 字节。

**我们粗算。** 代入推理测试的模型（BF16 下 $b_w = 2$、$L = 24$、$d_v = 2{,}048$），batch 8 的单步 decode 约 0.75 MiB；而 batch 8、长度 2,048 的 prefill 若不去重，约 1.5 GiB，已是整张表 3,000 MiB 的一半。decode 这点流量很轻，prefill 的流量不小，去重与缓存会是实际实现的关键。论文的公式明确标注了「不含缓存与去重」，但没写原型实现是否做了去重。

论文自己的结论很克制：MA-Offload 减少的是 GPU 上的参数驻留，历史 KV cache 照样保留；延迟代价取决于 CPU 查表性能、传输带宽、同步和可重叠的余量；因此它不保证总显存占用或延迟下降（PDF p. 6）。

## 七、MA-Recall：只存 key，value 现场拼（未实测）

加法结构还带来一个可能：历史 value 可以由历史 key 与 token 编号重建（PDF p. 6 式 22）：

$$
V_{1:T} = K_{1:T} + \bar{E}[s_{1:T}]
$$

这样就不必长期缓存 value。论文把它叫 MA-Recall，并明说它只是分析，不在本文的推理测量里（PDF p. 6、p. 8）。

难点在于打分要的是旋转后的 key，重建 value 要的是旋转前的 key。论文给了两条路：缓存旋转后的 key，用逆旋转还原；或者缓存旋转前的 key，用时再旋转。两条都要把位置变换的开销算进实测；两种都存则要额外缓存（PDF p. 6）。

账（PDF p. 6）：

- 常规 KV cache 占 $2b_c LBTd_v$ 字节；每个历史位置只留一份 key，降到 $b_c LBTd_v$，这一项省 50%。不含 token 编号、位置元数据、临时重建缓冲和额外的位置 key 存储。
- 代价：每步 decode 每条序列要重建 $R$ 个位置的 value，约 $LBRd_v$ 次加法（不含位置变换）；全因果注意力 $R = T$。表若也卸载到 CPU，传输量是 $D_{\mathrm{Recall}} = b_w L B R d_v$（式 23）。
- 分块重建可以避免在 GPU 上一次性物化整段 value 历史。

**我们的解释。** 这是拿「每步都要重新查全部历史 token 的表」换「少存一半 KV」。对全注意力、长上下文、表又放在 CPU 的情况，每步要搬的量随 $T$ 线性增长，几乎肯定成为瓶颈；它更可能在滑动窗口、稀疏注意力这类 $R \ll T$ 的模式下划算。论文本身也说实际收益取决于注意力模式、缓存表示、放置和重建实现（PDF p. 6）。

## 八、实验怎么证明

### 设置

所有模型在 H800 上用 flash-linear-attention 框架训练，骨干是注意力块加门控 MLP，带 RoPE 和 RMSNorm（PDF p. 7）。默认预训练设置（PDF p. 11–12 表 5）：

| 项目 | 取值 |
|---|---|
| 数据 | FineWeb-10BT |
| 优化器 | AdamW，峰值学习率 $3 \times 10^{-4}$，$\epsilon = 10^{-15}$ |
| 调度 | 前 1,024 步热身，余弦衰减到峰值的 10% |
| 全局 batch / 序列长度 | 256 条 / 2,048 |
| 训练步数 | 20,480 |
| 梯度裁剪 | 1.0 |
| 随机种子 | 42，同一骨干内 Standard 与 MA 相同 |

隐藏维 1,024 的骨干配置（PDF p. 12 表 6）：

| 配置 | 层数 | query 头 | KV 头 | KV 头维 | 总 KV 维 $d_v$ |
|---|---:|---:|---:|---:|---:|
| MHA | 24 | 16 | 16 | 64 | 1,024 |
| GQA | 24 | 16 | 8 | 64 | 512 |
| MQA | 24 | 4 | 1 | 256 | 256 |

RoPE base 10,000，RMSNorm $\epsilon = 10^{-6}$，输入嵌入与输出头不共享（PDF p. 12）。评测用 lm-evaluation-harness 零样本；平均分是 7 个准确率的不加权平均，不含困惑度（PDF p. 7）。

读表还要知道三件事：

1. **正文只点名了 3 组，表里有 5 组。** 正文说「三个配置」，给了小 MHA、GQA、大 MHA 的平均分增幅（PDF p. 7）。按表算，MQA 只涨 0.23 点，是 5 组里最小的；Gate 涨 1.48 点，是最大的。这两个差值是我们用表算的。
2. **「Gate」骨干没有定义。** 附录表 6 只列了 MHA、GQA、MQA 三种配置（PDF p. 12），正文与附录都没说明 Gate 是什么结构。从参数差看（Memory 比 Standard 多约 762M，与 MHA 那对的约 762M 相同），它的 KV 总维应与 MHA 同为 1,024，这是我们的推断。
3. **参数不对等是最大的混杂因素。** MHA 那对 Memory 是 Standard 的约 3 倍参数，GQA 约 2.1 倍，MQA 约 1.6 倍，大模型约 2.1 倍。表注只说参数量含记忆表、每对之内不相等；正文两处声明，这些结果支持的是「MA 这个组合设计在该预算下有效」，不能把结构的贡献与参数容量增加的贡献分开（PDF p. 2、p. 7）。论文没有做「同参数量」或「Value Embedding 加同样大的表」这类对照。

**我们的解释。** 一个有意思的旁证是：参数增幅最小的 MQA 提升也最小，增幅大的 MHA、Gate 提升更大。这和「多数收益来自多出来的表容量」是同一方向，但只有 5 个点，不足以下结论。

**我们粗算，核对参数列。** 以词表 32,000 计，小 MHA 每层表 $32{,}000 \times 1{,}024$，24 层约 786M，减去删掉的 $W_V$ 约 25M，373M 变成约 1,134M，与表中 1,135M 对得上；GQA、MQA 同法得约 730M、526M。论文只在推理测试一节写了词表 32,000（PDF p. 9），小模型的词表没有单独写明，这里的一致性是我们的核对。

### 训练效率：同 loss 少用多少 token

![Figure 2 前两格是隐藏维 1,024 与 2,048 两档的训练 loss 曲线，在图示的 token 区间内 MA（绿）一直低于 baseline（蓝），末端差分别为 0.058 与 0.026，差距在大模型上更小。](/readings/Memory-Attention/figure2-loss-curves.png)

原图出自 PDF p. 8 Figure 2 的前两格。第三格训练 TFLOPs 只有两个数，写在下文；后三格是推理的参数与延迟，已转成下文表 4。两条曲线的横轴分别从约 2.5B、5B token 画起，前面的训练段没有画出（读自图）。

论文把 token 效率定义为达到同一目标 loss $\ell$ 时两边所需 token 数之比（PDF p. 8 式 24）：

$$
\rho_{\mathrm{token}}(\ell) = \frac{n_{\mathrm{Standard}}(\ell)}{n_{\mathrm{MA}}(\ell)}
$$

在图上所取的工作点，隐藏维 1,024 与 2,048 两档分别是 1.42 倍与 1.16 倍，即约少用 29.6% 与 13.8% 的训练 token（PDF p. 8）。论文强调这是 token 效率，不是墙钟训练速度，且比较的模型带着额外的记忆参数（PDF p. 7–8）。目标 loss 取在哪个值，论文没有写明。

Figure 2 第三格是需要特别指出的地方：图上隐藏维 2,048 那档 MA 的训练 TFLOPs 是 934，baseline 是 525，标注为「1.78× computational cost」（PDF p. 8 Figure 2）。图注只说「其余格子报告训练 FLOPs」，正文没有解释这个数的统计口径，也没有讨论它为什么与论文第 3.3 节「value 构造算术减少」方向相反。

**我们的解释。** 第五节的算术账刻意排除了优化器更新与内存访问；而 MA 的可训练参数约是 baseline 的 2.08 倍。如果这里的 TFLOPs 是按参数量线性估算、或包含优化器对全表的更新，就会出现这种反向结果；不过 1.78 并不等于 2.08，说明它也不是单纯与总参数量成正比。这只是可能的解释，原文没有给口径。无论哪种口径，都不能把 MA 读成「训练更省算力」。

### 推理：延迟基本打平，GPU 参数存储可以更少

测试环境：单张 H800、BF16、PyTorch 2.9.1（CUDA 12.6）、FlashAttention 2.8.3（PDF p. 9）。模型 24 层、隐藏维 2,048、32 个 query 头与 32 个 KV 头，门控 MLP 中间维 5,632，词表 32,000，输入嵌入与输出头不共享（PDF p. 9）。参考负载是 batch 8、prefill 长度 2,048，以及带 2,048 长历史的单步 decode（PDF p. 9）。MA-Offload 的卸载分组在 prefill 是每组 1 层、decode 是每组 4 层，两阶段预取深度都是 4（PDF p. 9）。三种配置都保留常规 KV cache，不含 MA-Recall（PDF p. 8）。

下表转自 PDF p. 9 Table 4（参数存储按 BF16，不含 KV cache、激活和传输缓冲）：

| 配置 | Prefill（ms） | Decode（ms） | GPU 参数（M） | CPU 参数（M） | 总参数（M） | GPU 存储（MiB） | CPU 存储（MiB） |
|---|---:|---:|---:|---:|---:|---:|---:|
| Standard | 90.970 | 17.636 | 1,364.298 | 0.000 | 1,364.298 | 2,602.38 | 0.00 |
| MA | 88.202 | 17.788 | 2,836.498 | 0.000 | 2,836.498 | 5,410.38 | 0.00 |
| MA-Offload | 90.686 | 17.189 | 1,263.634 | 1,572.864 | 2,836.498 | 2,410.38 | 3,000.00 |

论文的读法（PDF p. 9）：

- **MA 放 GPU**：prefill 从 90.970 降到 88.202 ms（3.04%），decode 从 17.636 升到 17.788 ms（0.86%）。总参数约为 Standard 的 2.08 倍，前向延迟基本持平。算术减少并不一致地变成延迟减少，内存访问与执行开销仍然要紧。
- **MA-Offload**：1,572.864M 表参数移到 CPU，BF16 下 3,000 MiB。GPU 参数存储从 MA 的 5,410.38 MiB 降到 2,410.38 MiB，减少 55.45%；比 Standard 还少 192 MiB（7.38%），因为删掉了 value 投影。延迟 prefill 90.686 ms、decode 17.189 ms，比 Standard 分别低 0.31% 和 2.53%（PDF p. 9）。

测量口径很窄（PDF p. 9）：只计模型前向（含输入嵌入、各层、最终 RMSNorm、输出头），prefill 在每个位置都算 logits；MA-Offload 计入前向中的检索与传输；不计表初始化、归一化折叠、decode 前缀构造、采样，以及 token 编号从 GPU 到 CPU 的传输，测量前 token 编号已在两端就绪。所以这不是端到端服务延迟。参数存储也不等于总显存或峰值显存。

![Figure 3 显示 batch 从 8 扫到 64、长度从 2K 扫到 16K 时，Baseline、MA、MA Offload 三条 prefill 延迟曲线几乎重合并随 batch 与长度一起上升，而 decode 延迟几乎不随 batch 与长度变化、都在 17–18 ms 附近，MA Offload 在 batch 32、64 略高。](/readings/Memory-Attention/figure3-latency-scaling.png)

原图出自 PDF p. 10 Figure 3：左两格固定长度 2K 扫 batch，右两格固定 batch 8 扫长度；点是中位数，误差棒是各轮最小到最大（PDF p. 10）。图上三条线在 prefill 几乎叠在一起，batch 64 时约 0.7 s、长度 16K 时约 1.3 s；decode 各点都在 17–18 ms 附近，从 batch 8 到 64、从 2K 到 16K 几乎不涨，MA Offload 在 batch 32、64 略高于另两条（读自图）。正文没有逐点讨论这张图。

论文对这些小差异的定性是：它们是报告工作点上的测量，不是跨负载的一致加速；合计计时混合了投影计算减少、内存访问、传输和调度的影响，不能说明通信没有成本，也没有单独量化重叠的贡献；实现是原型，查表、缓冲和传输调度的进一步优化没有评测（PDF p. 9–10）。

**我们的解释。** 这张表最有价值的一格不是延迟，而是「总参数 2.08 倍、GPU 参数存储反而少 7.38%」。在这个 1.4B 规模上，参数本身只有约 2.5 GiB，与参考负载下的 KV cache 同一量级（我们粗算：$2 \times 24 \times 8 \times 2{,}048 \times 2{,}048 \times 2$ 字节约 3 GiB），还没算激活，卸掉 3,000 MiB 表的意义有限；真正能体现 offload 价值的，是表远大于 GPU 剩余空间的场景，而那样的规模论文没测。

## 可迁移启发

1. **先问哪块计算的产出其实只依赖 token 身份。** 那一块就有机会换成查表。MA 找到的是 value 投影，要验证类似改造，最关键的对照是「同参数量」，这正是本文缺的一格。
2. **替换比外挂多一层收益，也多一层风险。** 外挂（Value Embedding、PLE、Engram）不删原通路，最坏只是白加参数；替换删了 $W_V$，就要靠联合训练让 $W_K$ 同时服务打分和内容。本文 5 组都没翻车，但规模很小。
3. **寻址不依赖隐状态，是能卸载的根本前提。** 设计新的记忆模块时，把「键只由输入 token 决定」当作硬约束，就能换来预取和 CPU 放置；一旦键依赖隐状态，这条路就断了。Engram 与 MA 用的是同一个前提。
4. **推理时能提前算的，都烤进表里。** 固定的逐行归一化折进表是零成本的推理优化，任何「查表后接逐行固定变换」的结构都可以照做。
5. **加法结构让缓存可以「只存一半」，但要算清重建账。** MA-Recall 的思路迁移到别处时，先估 $R$：只有在每步真正要重建的历史位置远小于全长时，省下的缓存才不会被重复查表和传输吃掉。
6. **读这类论文先对参数列。** 「同 token 数下全面更好」配上 1.6–3 倍参数，结论就要打折。token 效率、算术 FLOPs、训练 TFLOPs、前向延迟、GPU 参数存储是五本不同的账，本文每本都给了一个数，彼此不能互相替代。

## 关键词回看

- **Memory Attention（MA）**：$V = K + \mathrm{Norm}(E[s])$，删掉 $W_V$，value 由 key 与每层一张 token 记忆表相加构成。
- **token 记忆表**：每层 $N \times d_v$，宽度随 KV 头数走；同层同 token 取同一行，不同层各自独立。
- **RoPE 之前取 key**：value 用旋转前的 key，打分用旋转后的 key，注意力算子不变。
- **归一化折叠**：推理时 $\bar{E}[i] = \mathrm{Norm}(E[i])$，在线只剩查表加加法。
- **MA-Offload**：地址只看 token 编号与层号，表放 CPU、提前预取；GPU 参数存储比 MA 少 55.45%，比 Standard 少 7.38%。
- **MA-Recall**：只存 key、现场重建 value，KV cache 这一项省 50%，代价是每步重复查表；未实测。
- **token 效率**：同 loss 所需 token 数之比，1.42 倍与 1.16 倍；不是墙钟速度。
- **与 MLA 的对照**：都用一份共享表示同时打分与取内容；MLA 取回后乘 $W_V$，MA 直接加记忆。只是动机类比，不是等价。
