# TALM：少样本工具演示，靠自博弈把语言模型接上 API

<!-- release-date: 2022-05-24 -->

**本文依据**：`TALM: Tool Augmented Language Models`，arXiv 2205.12255v1（2022-05-24），6 页 A4。作者 Aaron Parisi、Yao Zhao、Noah Fiedel，Google。本地 PDF 为 `readings/_src/Agent 训练与工具使用/TALM.pdf`（pdfinfo：6 页，A4，`pdfTeX-1.40.21`，CreationDate 2022-05-25）。首发日取 arXiv v1 提交日 24 May 2022；订正不回写。文中数字紧跟 `(PDF p. N)`；图里才有的趋势不估成精确表。标「外部补充」的段落不来自本文。

## 一句话

语言模型再大，也记不住训练之后才变的天气、日历和私有状态。TALM 只做两件事：用纯文本接口让模型生成工具调用并读回结果；再用「对了才进训练集」的迭代自博弈，从极少标注的工具轨迹把这条能力刷起来。同样规模下，接上工具的模型明显超过不接工具的 LM；更小的 TALM 也能超过更大的闭卷 LM。

## 一、矛盾：缩放和检索都解不了「训练时不在场」的事

Transformer 语言模型随规模变强，论文点名 T5、GPT-3、PaLM，以及 SuperGLUE、BIG-bench 这类基准（PDF p. 1）。缩放有代价：存、传、部署都笨，训练和推理对很多团队贵到做不起（PDF p. 1）。

更硬的限制不是贵，是**记不住不该记、记不住会变的东西**：

1. 会编出错答案。
2. 世界知识一直在变，昨天的训练数据今天可能作废。
3. 大模型会记住训练数据，带来不想要的后果（PDF p. 1）。

检索能减轻对规模的依赖。论文把 REALM、RETRO、RAG 归到这一路，并提到给 LM 接计算器能提升数学推理（PDF p. 1）。但检索仍默认对着一份相对固定的语料。天气、个人日历、会改状态的 API，都不在预训练快照里。Say Can 把语言模型接到环境，但模型主要是**收查询的一方**；TALM 反过来：模型自己生成工具输入，再盯着工具输出写任务答案（PDF p. 2）。

贡献两条（PDF p. 2）：

- 用 text-to-text API 给语言模型接工具。
- 用迭代自博弈，从很少的带工具标注例子，把工具数据集和模型表现一起滚起来。

## 二、接口：调用就是再生成一段字

骨干是预训练 T5，微调、推理、评测都用它；规模取 base、large、XL，对应后文图里的 220M、770M、3000M（PDF p. 3 图 5）。架构上 Seq2Seq、从左到右 LM、prefix LM 都能做；作者选 Seq2Seq，因为中等规模微调表现好（PDF p. 2）。

旧问题：工具不是可微层，不能塞进反向传播。新设计：全部走文本。流程按图 2 画成（PDF p. 2）：

```mermaid
flowchart LR
    A[任务输入] --> B[生成工具输入]
    B --> C["写出分隔符 |result"]
    C --> D[调用外部工具]
    D --> E[把工具结果拼回序列]
    E --> F[继续生成任务输出]
```

抽象模板和天气例子原样是（PDF p. 2 图 3）：

```text
task input |tool-call tool input |result tool output |output task output

how hot will it get in NYC today?
|weather lookup region=NYC
|result precipitation chance: 10, high temp: 20c, low-temp: 12c
|output today's high will be 20C
```

模型同时学两件事：何时、怎样调工具；拿到结果后怎样写答案（PDF p. 2）。分隔符是触发器，不是新模块。

**可迁移启发**：先把工具收成「字符串进、字符串出」，再谈强化学习或可微检索。2022 年这篇已经把后来常见的 tool token / function call 写成最朴素的 Seq2Seq。

## 三、自博弈：没有轨迹就自己滚轨迹

新工具往往几乎没有「输入 → 工具调用 → 工具结果 → 答案」的完整示范，但任务级监督很多：输入–目标对，外加自动对错指标（PDF p. 2）。作者从 Decision Transformer 借思路，把「模型跟工具 API 交互」叫 self-play，不是模型互相对打（PDF p. 2）。

算法 1 的因果链（PDF p. 2–3）：

| 步骤 | 做什么 |
|---|---|
| 起步 | 任务集 $T=\{x_i,y_i\}$；很小的工具轨迹集 $D=\{x_j,t_j,r_j,y_j\}$ |
| 每轮 | 在 $D$ 上微调：同时最大化 $P_\theta(t_j\mid x_j)$ 和 $P_\theta(y_j\mid x_j,t_j,r_j)$ |
| 探索 | 对 $T$ 里每条，采样最多 $N=600$ 条工具轨迹 |
| 过滤 | 生成答案与目标的差距小于阈值 $th$，才把这条轨迹并进 $D$ |

探索用温度 $1.0$、top-$k=40$ 的随机采样；评测用 4-beam，只出一条（PDF p. 3）。作者把它写成带二元奖励的政策梯度特例，并提到与 expert iteration 的亲戚关系；当前任务是单跳，但可以扩成多跳 MDP（PDF p. 3）。

**代价/边界**：过滤靠「答案对了」，不保证工具调用语义正确——检索碰巧翻到含答案的片段、公式碰巧算出对的数，都会进 $D$。论文没有报告被拒轨迹的比例，也没有分析错误调用如何污染后续轮次。

**可迁移启发**：缺工具标注时，用任务级对错当二值奖励，比先雇人标完整 trace 更便宜。前提是评测能自动判对；开放生成、没有金标准时这条管线会停住。

## 四、知识任务：闭卷记百科，不如让 220M 去搜

Natural Questions 约 30 万训练例。作者用 short answer，去掉布尔题以免乱猜抬分；对照是闭卷 LM（PDF p. 3）。NQ 自带维基「oracle」片段，TALM **不把片段直接喂进模型**，而是拿它们建 BM25 索引，当检索工具用（PDF p. 3）。

图 4 的格式对照（PDF p. 3）：普通 NQ 是「问题 + 短答案」；工具序列则是 `|question … |search … |result … |output …`。

图 5 设定：从 **150 条**工具示范起步，自博弈 **两轮**。正文写死的结论是：即便 220M 的 base TALM 也超过 3B 的 XL LM；TALM 的 base 与 XL 差距，小于 TALM 与同规模 LM 的差距。作者猜想规模曲线上的噪声来自低数据微调（PDF p. 3）。图本身没有印出精确 F1，本文不估点。

**收益**：知识密集型任务上，更小的模型从检索工具获利更大（PDF p. 3）。**边界**：索引只覆盖 NQ oracle 片段的并集，不是开放网络；「能搜」仍限于这份冻结语料，直到 3.4 节换成公开搜索引擎。

## 五、推理任务：公式对了约七成，模型负责写公式

MathQA 约 3 万训练例：题面、众包公式、选择题文本答案（PDF p. 3）。工具是一个执行公式并核对数值的 solver。按这个 solver，约 **70%** 公式能对上对应答案，与 Hendrycks 等对 MATH 的观察同类；对不上的来自错公式或非法答案（PDF p. 4）。

起步集：在公式有效的训练子集里随机抽 **10%**，约 **2k** 条（PDF p. 4）。图 6 例子（PDF p. 3–4）：

```text
|question If Lily’s test scores are 85 , 88 and 95 …
|formula Divide(Add(85, Add(88, 95)), 3)
|result 89.3333333333
|output 89.33
```

图 7 同样只给趋势：TALM 在 220M / 770M / 3000M 上都明显高于不接工具的 LM，纵轴是 solver-match（PDF p. 4）。精确点值图上未标，不写入正文。

**边界**：指标是 solver-match，不是「公式在数学上唯一正确」。70% 公式噪声会进训练；模型学的是「写出 solver 能跑通且对上文本答案的公式」。

## 六、消融：一轮就跳，三轮还在涨

图 1 把知识（NQ F1）和推理（MathQA solver-match）画在同一套自博弈轮次上，横轴 0–3 轮，系列是 TALM / LM 的 base、large、xl（PDF p. 1）。正文对应结论（PDF p. 4）：

- 只在起步工具集上训，不如再做一轮自博弈。
- 三轮内表现继续升。
- 220M 到 3B 都成立。

图 1 曲线没有印精确坐标，不估。LM 曲线在图例里出现，机制上它们没有工具轨迹可滚，正文也没有单独解释 LM 为何随 round 变化；这一点原文没写清。

## 七、分布外：换工具、换数量级，闭卷 LM 当场露馅

知识侧：把 BM25 Wiki 换成公开搜索引擎。问 `What is wordle?`，LM 答 `a word generator`；TALM 答成在线猜五字母单词、六次机会的游戏（PDF p. 4 图 8）。这是定性例子，不是准确率表。

数学侧：大数运算，训练数据缺、非增强 LM 也差。`535 miles per hour` 开 `2450 miles`：LM 给 `8.5`，TALM 给 `4.58`（PDF p. 5 图 9）。$2450/535\approx 4.58$，TALM 走的是计算器，不是心算。

**可迁移启发**：分布外不一定要换模型，先换工具后端。同一套 text-to-text 协议，索引可以从 BM25 换成搜索引擎，solver 可以换成任意解释器。

## 八、结论、没写什么、附录

结论把两件事捆在一起：text-to-text 工具接口 + 迭代自博弈，让探索新工具和新任务不必先砸标注；更小的增强模型可以超过更大的裸 LM（PDF p. 5）。

原文没写、本文也不补的缺口：

- 没有代码仓、没有超参表（学习率、步数、batch）。
- 没有 NQ / MathQA 的精确指标表，只有图 1、5、7 的趋势和图注设定。
- 没有延迟、调用次数、失败重试、多跳工具。
- 没有与 REALM / RAG / RETRO 的同设定对照，相关工作只定位。
- 阈值 $th$ 的具体形式（字符串相等还是数值容差）只写了符号。
