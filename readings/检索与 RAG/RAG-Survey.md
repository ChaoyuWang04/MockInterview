# 大模型时代的 RAG：先承认 Naive 流水线会漏、会编、会复读，再决定要不要拆成模块

<!-- release-date: 2023-12-18 -->

**本文依据**：`Retrieval-Augmented Generation for Large Language Models: A Survey`，arXiv:2312.10997v5 [cs.CL] 27 Mar 2024，Letter，21 页。第一作者 Yunfan Gao，封面机构行 **a** 为 Tongji University（Shanghai Research Institute for Intelligent Autonomous Systems）；**b** 为 Fudan University；**c** 为 Tongji University College of Design and Innovation。通讯 Haofen Wang。页眉印 `arXiv:2312.10997v5`，封面未印会议名。封面与摘要自称 survey。文中数字均标 PDF 页码；标「外部补充」的段落不来自本文。资源页脚注指向 `https://github.com/Tongji-KGLLM/RAG-Survey`（PDF p. 1）。

## 一句话

大模型会幻觉、知识过期、推理说不清出处。RAG 用外部库补非参数记忆，和参数里的知识拼在一起（PDF p. 1）。这篇综述不是再发明一个框架名，而是把 LLM 时代一百多篇工作收成一张地图：范式切成 **Naive RAG / Advanced RAG / Modular RAG**；技术切成检索、生成、增强过程三块；评测切成检索质量、生成质量，以及噪声鲁棒、拒答、信息整合、反事实鲁棒四项能力（PDF p. 1–2、p. 12–14）。它解决的是 **ChatGPT 之后 RAG 长得很快、却没有一张能对照的轨迹图。**

## 这张地图切了几刀

轴本身是这篇综述的主要贡献，比表 I 里堆了多少方法名重要。

**第一刀：按流水线怎么长，而不是按发表年堆目录。** 图 3 把范式写成三代（PDF p. 2–5）：

| 范式 | 骨架 | 作者怎么定位 |
|---|---|---|
| Naive RAG | 索引 → 检索 → 生成，Retrieve-Read | ChatGPT 普及后最早的做法 |
| Advanced RAG | 仍是链式，在检索前、检索后加优化 | 专门补 Naive 的漏检、噪声、过长上下文 |
| Modular RAG | 可换模块、可改编排；一次检索不再是默认 | 迭代、递归、自适应检索；可接微调与强化学习 |

三代不是互相作废。Modular 继承前两代原则，只是不再被「先取再读」锁死（PDF p. 4）。

**第二刀：按组件，而不是按「是不是 RAG」。** 贡献列表把核心技术钉成检索、生成、增强（PDF p. 2）。第 III–V 节按这三块写；图 1 的技术树再横切预训练 / 微调 / 推理三个介入时机（PDF p. 2）。ChatGPT 之后研究先扎在推理阶段的 ICL；随后才更多和微调缠在一起，预训练侧的检索增强也没有停（PDF p. 1–2）。

**第三刀：RAG 对微调、对提示工程，用两维象限而不是胜负表。** 图 4：外部知识需求 × 模型改造需求（PDF p. 5–7）。提示工程两边都低；微调偏改模型、少靠外库；Naive RAG 几乎不改模型；Modular 越来越和微调叠在一起。作者转述 Ovadia 等人：无监督微调有一点用，但 RAG 在「训练见过的旧知识」和「全新知识」上都更稳；LLM 很难靠无监督微调学会新事实（PDF p. 5，[28]）。二者不互斥，可以多轮交替（PDF p. 5）。

**第四刀：评测不再只报下游任务分数。** 第 VI 节先列任务与数据集，再把目标拆成检索质量与生成质量，再加三个质量分（上下文相关、答案忠实、答案相关）和四项能力（PDF p. 12–14）。作者明说：表 III 里的 Accuracy、EM、BLEU 等仍是传统指标，**还不是成熟、统一的 RAG 量化方案**（PDF p. 13）。

把三代摊开（机制示意，根据 PDF p. 4 图 3 重画，不是实测时间轴）：

## 每一区里有什么

### Naive RAG：Retrieve-Read 为什么便宜，也为什么会塌

图 2 的三步（PDF p. 3）：文档切块、向量入库；查询用同一套编码器取 Top-$k$；问题和块拼进提示，让 LLM 生成。对话历史可以塞进提示做多轮。模型既可以动用参数知识，也可以被要求只根据文档答（PDF p. 3）。

作者列的失败模式要分开记，后面两代是对着这些长的（PDF p. 3）：

- 检索：精度和召回都不稳，取到错块、漏关键块。
- 生成：幻觉（生成内容文档撑不住）、跑题、毒性或偏见。
- 增强：拼不齐、多源重复、风格不统一；复杂问题单次检索上下文不够。
- 更刺的一条：生成器过度依赖增强文本，**只会复读检索结果，不再综合。**

可迁移：上线前先问失败会落在这四类的哪一类，再决定是改切块、改查询，还是改「要不要检索」。

### Advanced RAG：不拆链，只在链的两端打补丁

检索前：优化索引（粒度、结构、元数据、对齐、混合检索）和优化查询（改写、变换、扩展等）（PDF p. 4）。检索后：重排，把最相关的挪到提示两端；压缩上下文，避免把整库塞进 LLM（PDF p. 4）。LlamaIndex、LangChain、HayStack 被写成这一层的工程落点（PDF p. 4）。

共识大致是：Lost in the Middle 已经说明，人一样，模型也更盯长上下文的头尾（第 IV 节引用 [98]，PDF p. 10）。还在打架的是：切多大块。固定 token 数（文中举例 100、256、512）大块噪声多、贵；小块语义不完整；递归切分和滑窗仍难在语义完整与长度之间取齐，于是有 Small2Big：用句子检索，把前后句当大上下文送给 LLM（PDF p. 8）。

### Modular RAG：模块和编排都变成一等对象

新模块（PDF p. 4–5）：Search（搜索引擎、数据库、知识图谱，可用 LLM 写的代码或查询语言）；RAG-Fusion（多查询并行向量检索再重排）；Memory（无界记忆池、迭代自增强）；Routing（摘要、特定库、多路合并）；Predict（LLM 直接生成上下文，减检索噪声）；Task Adapter（零样本自动取提示、少样本造任务检索器）。

新编排不只是换零件（PDF p. 5）：Rewrite-Retrieve-Read；Generate-Read（用生成顶替检索）；Recite-Read（从权重里「背」）；HyDE 用假想文档做答案对答案的嵌入相似；DSP；ITER-RETGEN 的 Retrieve-Read 循环；FLARE 与 Self-RAG 按场景决定要不要检索。作者判断：灵活架构更容易接微调或强化学习，例如只微调检索器、只微调生成器、或两端协同（PDF p. 5）。

### 检索源与粒度：外部库不是唯一非参数记忆

数据形态从纯文本扩到半结构化（PDF）和结构化（知识图谱），再扩到 **LLM 自己生成的内容**（PDF p. 5–7）。半结构化的两个坑写得很具体：切块可能把表切断；表会干扰语义相似（PDF p. 7）。结构化更准，但要建、要验、要维护（PDF p. 7）。LLM 自生成一侧：SKR 先判问题是否已知再决定检索；GenRead 发现模型生成的上下文有时更常含正确答案，因为更贴因果语言模型的预训练目标；Selfmem 用选择器把输出当成对偶问题，喂回自己（PDF p. 7）。

文本粒度从细到粗：Token、Phrase、Sentence、Proposition、Chunk、Document。DenseX 把命题定义成自包含的原子事实（PDF p. 8）。图谱侧是实体、三元组、子图。粒度也可随下游改，例如推荐里的 Item ID（PDF p. 8）。粗粒度理论上信息多，也更容易夹冗余、干扰下游（PDF p. 7）；细粒度检索负担大，还不保证语义完整。表 I 用检索源、数据类型、粒度、增强阶段、检索过程（Once / Iterative / Adaptive / Recursive 等）把几十个方法摊平（PDF p. 6），正文不当目录念。

查询侧的主矛盾：Naive 直接拿用户原句检索。原句常常写不清；术语和缩写会歧义，文中例子是「LLM」究竟是大语言模型还是法学硕士（PDF p. 8）。扩展（多查询、子问题、CoVe 校验）、变换（改写、HyDE、Step-back）、路由（元数据过滤、语义路由）都是在补这一刀（PDF p. 8–9）。嵌入没有万能答案：稀疏（BM25）和稠密（BERT 系）特征不同，可以互补；领域词表差得远时要微调嵌入；也可用 LLM 当监督信号训检索器（LSR、PROMPTAGATOR、REPLUG 的 KL）（PDF p. 9）。改不动模型时就外挂适配器：UPRISE、AAR、PRCA、BGM 的 Seq2Seq 桥、PKG 用指令微调直接顶替检索器（PDF p. 9–10）。

### 生成：取回来之后先减肥，再考虑微调 LLM

不要把检索结果原样倒进生成器（PDF p. 10）。重排既是增强也是过滤。压缩：LLMLingua / LongLLMLingua 用小模型删不重要 token；PRCA 训抽取器；RECOMP 用对比学习训冷凝器。Filter-Reranker：小模型过滤、大模型重排难样本（PDF p. 10）。Chatlaw 让模型先自评法条再生成（PDF p. 10）。

微调 LLM 的理由写了三条：补领域；改输入输出格式与文风；用 RL 对齐人或对齐检索器。RA-DIT 用 KL 对齐检索器与生成器的打分（PDF p. 10）。没有 GPT-4 级模型时，蒸馏是作者写下的退路（PDF p. 10）。

### 增强过程：一次检索不够时，环怎么转

图 5 三种（PDF p. 11）：

- **迭代**：按当前查询和已生成文本反复搜。ITER-RETGEN 把「检索增强生成」和「生成增强检索」拧在一起（PDF p. 11）。代价是语义断裂和无关信息累积。
- **递归**：按上次结果改写查询。IRCoT 用思维链引导检索再反写思维链；ToC 用澄清树拆含混处。层次索引上的先摘要再入篇，和图谱上的多跳，常被一起用（PDF p. 11）。
- **自适应**：模型自己决定何时检索、检索什么。FLARE 看生成词概率跌破阈值再检索；Self-RAG 用 retrieve / critic 两类 reflection token，不必另训分类器或 NLI（PDF p. 11–12）。WebGPT 用特殊 token 调搜索引擎，是同一类「主动判断」的前作（PDF p. 11）。

### 任务、评测、工具：地图的第四象限

核心任务仍是问答（单跳 / 多跳、选择题、领域、长答案），并扩到信息抽取、对话、代码搜索等。表 II 按任务列数据集（PDF p. 13）。摘要口径是 **26 项任务、近 50 个数据集**（PDF p. 2）。

历史评测多半套下游指标：问答用 EM、F1；事实核查用 Accuracy；BLEU、ROUGE 也常见（PDF p. 12）。作者认为缺的是 RAG 自身特性。检索质量用 Hit Rate、MRR、NDCG；生成质量按有无标签分成忠实 / 相关 / 无害，或正确性（PDF p. 12）。

三个质量分和四项能力（PDF p. 12）：

| 质量分 | 问的是什么 |
|---|---|
| 上下文相关性 | 取来的上下文是否准、是否少废话 |
| 答案忠实性 | 生成是否贴上下文、是否自相矛盾 |
| 答案相关性 | 是否在回答这个问题 |

| 能力 | 问的是什么 |
|---|---|
| 噪声鲁棒 | 相关但没实质信息的文档会不会带偏 |
| 拒答 | 文档不够时会不会闭嘴 |
| 信息整合 | 会不会跨多文档拼复杂问题 |
| 反事实鲁棒 | 明知文档有错时会不会跟着错 |

上下文相关与噪声鲁棒偏检索；其余偏生成（PDF p. 12）。表 III 把 Accuracy 几乎划到所有列，EM 主要落在拒答，R-Rate 落在反事实；作者提醒这些仍是传统度量（PDF p. 13–14）。

基准与工具（表 IV，PDF p. 15）：RGB、RECALL、CRUD 是基准（†）；RAGAS、ARES、TruLens 是工具（‡），后三者用 LLM 当裁判打质量分，部分格子是自定义指标（\*）。CRUD 还覆盖创造性生成、知识密集问答、纠错、摘要。

## 作者认为缺什么

第 VII 节是作者判断，和前面综述到的事实分开。

**RAG 对超长上下文。** 文中写当时 LLM 已能轻松处理超过 20 万 token 的上下文（脚注指向 Kimi，PDF p. 14）。整篇文档塞进提示之后，会有人问还要不要 RAG。作者的回答是：一次性超长上下文会拖推理速度；分块按需仍更省；检索过程可回溯原文，纯长上下文仍是黑盒。反过来，超长上下文让 RAG 有机会做必须读大量材料的综合题。**超长上下文下的新 RAG 方法被写成未来趋势之一**（PDF p. 14）。

**鲁棒性。** 噪声和矛盾检索会直接砸质量。文中转述那句比喻：错误信息有时比没有信息更糟（PDF p. 14）。Cuconasu 等人的结果被点名：加入无关文档竟能把准确率抬高超过 30%，和「噪声一定降质」的直觉相反（PDF p. 14）。这是转述，不是本篇新实验。

**混合。** RAG 与微调如何串、如何交替、如何端到端，参数记忆和非参数记忆如何一起用，仍是开放题（PDF p. 14–15）。CRAG 训轻量评估器，按置信度触发不同检索动作，被当成「把带功能的小模型嵌进 RAG」的例子（PDF p. 15）。

**Scaling。** LLM 的缩放定律是否搬得动 RAG 还不清楚。RETRO++ 开了头，但 RAG 模型参数量仍落后 LLM。有没有 Inverse Scaling（更小反而更好）值得查（PDF p. 15）。

**生产。** 检索效率、大库召回、防泄露文档来源或元数据，被写成工程题（PDF p. 15）。生态上 LangChain、LlamaIndex 先占 API 面；Flowise 偏低代码；HayStack、Meltano、Cohere Coral 被点名；Weaviate Verba、Amazon Kendra 代表传统软件与云厂商入场。三条专业化方向：定制、简化、面向生产（PDF p. 15–16）。作者判断：工具栈在收束成底座，但「一个打通的综合平台」还没有（PDF p. 16）。

**多模态。** 已越出文本问答：图像（RA-CM3、BLIP-2、Visualize Before You Write）、音频视频（GSS、UEOP、Vid2Seq）、代码（RBPS）、结构化知识（CoK）（PDF p. 16）。结论把 Naive / Advanced / Modular 再复述一遍，并说评测方法必须跟着应用面变（PDF p. 16–17）。

## 这张地图指向哪些值得单独读

正文不写待办。下面几篇是地图上的下一站，只收本 PDF 参考文献里印了 arXiv 编号的。本方向已经成文的 Lewis RAG、Atlas、DPR、Lost-in-the-Middle 不重复挂。

- Self-RAG，arXiv:2310.11511。自适应检索这一区的代表：reflection token 让模型自己决定何时检索、如何批评（PDF p. 5、p. 11–12）。
- Active Retrieval / FLARE，arXiv:2305.06983。用生成置信度触发检索，和 Self-RAG 构成自适应这一刀的另一侧（PDF p. 5、p. 11）。
- ITER-RETGEN，arXiv:2305.15294。迭代检索：生成与检索互相当上下文（PDF p. 5、p. 11）。
- RA-DIT，arXiv:2310.01352。检索器与生成器双指令微调，是「RAG 对微调」从象限讨论落到一篇方法（PDF p. 5、p. 10）。
- REPLUG，arXiv:2301.12652。黑盒 LLM 当监督、用 KL 训检索器，代表改不动生成器时怎么对齐（PDF p. 9）。
- HyDE，arXiv:2212.10496。查询变换：假想答案对真实文档做嵌入相似，而不是问题对文档（PDF p. 5、p. 9）。
- RGB，arXiv:2309.01431。专门打四项能力的基准，评测区不能只停在 EM/F1（PDF p. 14）。
- RAGAS，arXiv:2309.15217。用 LLM 裁判打上下文相关、忠实、答案相关，是工具侧下一站（PDF p. 14）。
- Fine-tuning or retrieval?，arXiv:2312.05934。作者用来支撑「无监督微调打不过 RAG、也难注入新事实」的那篇对照（PDF p. 5）。
- The Power of Noise，arXiv:2401.14887。鲁棒性讨论里「无关文档反而抬点」的刺，用来防止把噪声鲁棒写成常识（PDF p. 14）。

RETRO 在参考文献 [5] 印的是 ICML 会议条目、未印 arXiv，这里不编造编号。

## 可迁移启发

- 先定位失败是检索、生成、增强还是「过度复读」，再选 Naive 补丁还是换 Modular 编排。
- 查询原句不是检索查询。改写、拆子问题、HyDE、路由，往往比换一个更大的嵌入模型便宜。
- 取回的块默认有毒。重排、压缩、让模型先批评再答，应写成默认后处理，而不是进阶技巧。
- 一次检索只覆盖单跳事实题。多跳、长答案、含混问题要先选迭代 / 递归 / 自适应，而不是加 $k$。
- 超长上下文没有取消 RAG：速度、可引用、按需仍在。评测不要只报下游 EM，至少要能说清拒答和反事实。

## 关键词回看

Naive / Advanced / Modular RAG；Retrieve-Read；检索 / 生成 / 增强过程；迭代、递归、自适应检索；参数记忆与非参数记忆；RAG 对微调；上下文相关、答案忠实、答案相关；噪声鲁棒、拒答、信息整合、反事实鲁棒。
